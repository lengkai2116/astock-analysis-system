# 方案390 JUD多因子决策引擎集成 — Final Report

## What Was Built

方案390将JUD（现状判定）从if-else规则链升级为多因子决策引擎。L1-L5组件（维度适配、可靠性评估、共识聚合、冲突矩阵、多因子仲裁）此前已独立实现但未接入status_engine主流程。本次工作完成了三件事：

1. **实现L6 advice_engine.py** — 动态仓位模型，含波动率调整、盈亏比调整、距防守位调整
2. **集成L1-L5到status_engine** — evaluate()通过`jud_engine_version`配置开关切换新旧管线
3. **新增输出字段** — final_score、semantic_type、reliability_summary、consensus_detail

## Architecture

### 新管线数据流（v390模式）

```
dim_results + tags
  → L1 convert_to_factors()     → dims_factor (11维因子)
  → L2 reliability_assessor     → reliability (0-1/维度)
  → L3 consensus_engine.compute → consensus (族级去相关+可靠性加权)
  → L4 conflict_matrix.detect   → conflict (15条规则+4种语义)
  → L5 factor_arbiter.arbitrate  → final_score + opportunity_state
  → L6 advice_engine.compute    → advice_params (动态仓位+止损/目标)
```

### 版本切换

`config/status_engine.yaml` 中 `jud_engine_version: "v390"` 控制新旧管线切换。`status_engine.evaluate()` 根据此值调用 `_aggregate_v390()`（新）或 `_aggregate()`（旧）。一键回滚：改为 `"legacy"` 即可。

## Usage

切换新管线：
```yaml
# config/status_engine.yaml
jud_engine_version: "v390"   # 新管线
# jud_engine_version: "legacy"  # 回滚到旧管线
```

重启后端生效（yaml配置带lru_cache）。

- [lesson] advice_builder.py（631行）仍被strategy_analyze.py和cross_validate.py live使用，不能直接删除。advice_generator.py（零引用）已安全删除
