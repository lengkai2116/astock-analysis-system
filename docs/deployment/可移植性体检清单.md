## 二、密钥明文（必改，安全）

| 项目根 `.env` | `DEEPSEEK_API_KEY`、`TUSHARE_TOKEN`、`SECRET_KEY`、`LLM_WIKI_API_TOKEN` 等 | ✅ **正确位置**（已被 .gitignore 忽略） |

## 三、环境变量注入面（迁移时保持一致的契约）

来源 = 项目根 `.env` + 启动器注入，键名如下（值不进文档）：

```
TUSHARE_TOKEN  SECRET_KEY  CORS_ORIGIN  AUTH_TOKEN
DEEPSEEK_API_KEY  DEEPSEEK_BASE_URL  DEEPSEEK_MODEL  LLM_PROVIDER  LLM_WIKI_API_TOKEN
DATABASE_URL  FLASK_ENV  DATA_DIR
CN_10Y_BOND_YIELD  QMT_ENABLED  QMT_ACCOUNT_ID
DATA_DAEMON_RUNNING=1   （data_daemon.py 自设，防止 API 进程抢采集）
```

- **DATA_DIR**：数据根目录（含全部 SQLite 分库），是迁移最关键的单一变量
- **REDIS_URL**（已废弃并移除）：旧 Gunicorn 多 worker + SocketIO 广播设计的遗留，全仓零消费方（现为单进程直接广播 + TTLCache 内存缓存），已从 `.env` / `docker-compose.yml` / 启动器 plist 清出
- 迁移建议：以 `.env.example` 为准，补齐 `DATA_DIR`/`DATABASE_URL` 平台默认值说明

## 四、平台启动器切换点

| 职责 | 当前（macOS 本机） | 迁移目标 |
|------|--------------------|----------|
| 采集 daemon 看守 | 登录项 `start_daemon.sh`（Terminal scripts，while 循环 + 单实例 + ulimit） | Linux：`astock-daemon.service`（`Restart=always`）；Windows：NSSM 服务或计划任务 |
| daemon 手动启动 | `start.command` | systemd `systemctl start` / 服务 |
| API 服务 | `run.py --port 5001`（Flask/SocketIO） | Linux：`astock-api.service`（Gunicorn 1-4 workers × gevent）；Windows：NSSM |
| 日志轮转 | launchd `com.stock.analyzer.logrotate`（每天 3:00） | Linux：systemd timer 或 cron；Windows：计划任务 |
| 数据一致性检查/日终同步 | daemon 内置（30s 循环 + 15:30 窗口 + 补采） | **随 daemon 走，无需额外配置** |

> 看守职责迁移后可移交给系统服务管理器（KeepAlive / Restart=always），`start_daemon.sh` 的 while 循环降级为手动兜底。

## 六、数据目录与存储依赖

- `DATA_DIR`（默认 `data/` 项目内，L22 硬编码待改）下为 **SQLite 分库（WAL）**：
  `market_cache.db` / `financial_cache.db` / `history_cache.db` / `compute_cache.db` / `snapshot_cache.db` / `app.db` 等
- 数据量级约 2-5 GB（daily_cache 640 万行 / factor_cache 1044 万行），随交易日增长
- 已有 WAL 治理与保留策略（374 号方案）
- **迁移建议**：数据目录与代码目录分离（独立数据盘/卷）；SQLite 不支持跨网络共享写，云上唯一 daemon 为写者，本地/其他机器只读副本或 API
