## 二、BUG清单

### F-01（HIGH）：筹码成本结构全部为空

**位置**：dim4 evaluate() 行5799-5817

**现象**：`cost_concentration=""`, `cost_asr=None`, `cost_cyqkl=None`, `cost_profit_ratio=None`, `cost_structure="筹码数据不足"`

**根因分析（跨环节追踪）**：

**数据流全链路**：
```
data_daemon.py RAW-2（行2382-2384）
  → ChipDistributionEstimator.get_tags(df)    # 计算筹码特征
  → features['chip'] = {k:v ... if k in ('chip_position','chip_concentration','asr','cyqkl')}
  → cache_pre_feat(code, trade_date, features)  # 写入pre_feat_cache
      ↓
status_engine._load_tags() → 扁平化 → tags dict
      ↓
dim4.evaluate(tags=...) → 读取 tags.get('asr') / tags.get('cyqkl') / tags.get('profit_ratio')
```

**逐层排查**：

| 层级 | 问题 | 详情 |
|------|------|------|
| **ChipDistributionEstimator.get_tags()** | `asr`计算了但未输出 | 行183：`asr_est = chip_dist.std() / (chip_dist.mean() + 1e-9)` 计算了数值，但仅用于分类判定（concentrating/stable/dispersing），未写入`tags['asr']` |
| **ChipDistributionEstimator.get_tags()** | `cyqkl`完全未实现 | `ChipIndicators`类有`_calculate_cyqkl()`方法，但`get_tags()`未调用 |
| **ChipDistributionEstimator.get_tags()** | `profit_ratio`完全未实现 | `ChipIndicators`类有`_calculate_profit_ratio()`方法，但`get_tags()`未调用 |
| **data_daemon.py RAW-2** | 筛选条件包含这三个key | 行2384：`if k in ('chip_position','chip_concentration','asr','cyqkl')` — daemon已预留，但get_tags()未产出 |
| **pre_feat_cache** | 三个字段均不存在 | `asr`/`cyqkl`/`profit_ratio`（数值）均无 |
| **dim4 evaluate()** | 假设tags中有数值字段 | `float(tags.get('asr'))` → None → `cost_asr=None` |

**注意**：pre_feat_cache中存在`profit_ratio`字段，但值为`'in_peak'`（string，来自chip_position），不是数值百分比。`float('in_peak')`抛异常→被except吞掉→None。

**问题环节**：RAW-2（特征提取），`ChipDistributionEstimator.get_tags()`有计算能力但输出不完整。

**影响**：`cost_structure="筹码数据不足"`→dim8跳过→"因为"段缺少筹码成本信息

**修复方案**：

~~方案B（dim4 evaluate()自行计算）~~ → **确认采用方案A（修复get_tags()输出）**

具体修改点：

| 序号 | 修改文件 | 修改位置 | 修改内容 |
|------|---------|---------|---------|
| 1 | `app/data/chip_distribution_service.py` | `ChipDistributionEstimator.get_tags()` 行183后 | 将已计算的`asr_est`写入`tags['asr'] = round(asr_est, 2)` |
| 2 | `app/data/chip_distribution_service.py` | `ChipDistributionEstimator.get_tags()` 行189后 | 调用`ChipIndicators.calculate_all_indicators()`计算cyqkl/profit_ratio，写入tags |
| 3 | — | `data_daemon.py` | 无需修改（筛选条件行2384已包含`asr`/`cyqkl`） |
| 4 | — | `dim4 evaluate()` | 无需修改（已从tags读取，字段补全后自动生效） |

**注意**：pre_feat_cache中已存在的`profit_ratio`字段值为`'in_peak'`（string，来自chip_position），方案A写入数值后将覆盖该string值，dim4 evaluate()的`float()`转换将正常工作。

**工时**：0.5天

### F-02（MEDIUM）：retail_institution与fund_flow逻辑矛盾

**位置**：行5827-5835

**现象**：`fund_flow=强流入`但`retail_institution=散户与机构博弈中性`

**根因**：代码逻辑仅在`mfp=='building'` AND `'inflow' in fund_flow_raw`时判定为"机构买入"。lifting阶段即使资金强流入也落入else→"中性"。

**影响**：dim8读取时发现资金强流入但机构中性，逻辑矛盾。

**修复方案**：扩展条件，raising/lifting阶段+资金强流入也应判定为"机构参与拉升"。

**工时**：0.5天

---

### F-03（MEDIUM）：judgment.overall_direction与light不一致

**位置**：行5925-5928

**现象**：`overall_direction=0`（中性），`light=green`（看多）

**根因**：`overall_direction`仅在building/raising时为1，distributing时为-1，其他（包括lifting）为0。但light=green在building/raising/lifting时都为green。

**影响**：dim_adapter读取direction和light时产生矛盾信号。

**修复方案**：将`raising`和`lifting`统一处理，overall_direction=1。

**工时**：0.5天

### F-04（LOW）：signal_evidence包含空值

### F-05（LOW）：pde_vote_ratio被截断

## 四、代码质量优化（建议项，可延后）

### Q-01：bare except过多（64个）

大量`except Exception: pass`静默吞掉错误。与用户要求的"区分管道故障/正常结论"原则相悖。

**建议**：分批替换为具体异常类型（`TypeError/ValueError/KeyError`），保留关键路径的debug日志。

**工时**：1天（建议延后到398号方案STG仓储统一处理）

### Q-02：ABC抽象基类未使用

5个ABC类（`UniverseSelectionModel/AlphaModel/PortfolioConstructionModel/RiskManagementModel/ExecutionModel`）定义了抽象接口，但实现类仅用于dim4内部。pipeline架构过度设计。

**建议**：如无外部调用者，可简化为普通类。

**工时**：0.5天（建议延后）

### Q-03：evaluate()中try/except+pass静默降级

CrowdingFactor等组件异常被静默吞掉→输出默认值→无法区分"计算失败"和"正常无数据"。

**建议**：在398号方案OutputSemanticController中统一处理。

**工时**：延后到398号
