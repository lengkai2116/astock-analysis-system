## 二、阶段引擎核心（PhaseDetectionEngine.compute_tags，312/412 号）

输出 `main_force_phase / phase_confidence / price_position / trend_alignment / fund_flow / phase_conflict / phase_vote_ratio`。

- **7 维阶段向量**（控盘度维度批次 3 未接）：chip 筹码形态、fund 资金流向、stage 量价四阶段、asr ASR、trend 趋势斜率、ssrp 主力成本锚（443 补传 cost_ext）、chan 缠论买点。
- **加权共识 `_consensus`**：维度权重 `_DIM_WEIGHTS = {chip:3.0, fund:3.0, stage:2.5, asr:2.0, trend:1.5, ssrp:2.5, chan:2.0}`；阶段总分=Σ 维度强度×权重×环境因子（情绪 climax 买入证据×0.7、热点板块 washing×0.7）；冲突阈值 gap<0.08（325 档案校准）→ 置信度×0.6；**确认门槛：top 阶段支持者（该阶段强度>0.25 的维度数）≥2**，不足则降级次高，仍不足→unknown_no_evidence；置信度=top 总分/总分和；capital_nature 机构+0.05/游资×0.8。
- **涨停交叉校验 `_limit_up_cross_check`**（298 号）：pct_chg>9.5% 时——building+低位+非巨量→确认 building；building+高位→distributing；lifting+高位+巨量+次日低开→distributing；distributing+低位+缩量→building。⚠️ **规则3"次日低开"死逻辑**（§四-7）。

### 3.1 judgment

### 3.2 audit 条件（5 条）

5. 资金×价格无危险背离：risk≠危险 ⚠️ 恒"无"（fund_price_divergence 数据不足时，§四-2）

### ❌1（**464-6**）crowding 融资分项恒死：`calc_margin_ratio` 列名错位
- **现状**：`CrowdingFactor.calc_margin_ratio`（dim4:5112-5178）余额列白名单 `('marge_balance','融资余额','marge','balance')`、流通市值白名单 `('circ_mv','流通市值','circulating_mv','mv')`；而 margin_cache 实际列为 Tushare margin_detail 原样（**rzye/rqye/rzmje/rqje**，data_daemon:858 仅删 name/rqchl），流通市值根本不在 margin_cache（在 daily_basic_cache）。
- **实证**：茅台/万科 `calc_margin_ratio => None`，evidence 恒"融资数据不可用"，`valid_signals` 恒 2（换手+波动）。
- **影响**：HIGH_CROWDING 需 high≥2 且 valid≥2——融资恒 False → **HIGH/LOW_CROWDING 实际不可达，拥挤度三态退化为恒 MODERATE(0.5)**；`judgment.continuous_value = 1-0.5` **恒 0.5**（与 dim2 chanlun_strength 恒 0.5 同类病）；audit「拥挤度合理」恒 satisfied（MODERATE 非 HIGH/unknown）。另注释"至少满足 2/3 条件"与实现 `high_count>=2 and valid_signals>=2`（融资死后实际 2/2 制）不符。
- **建议处置**：对齐 rzye（融资余额）+ 流通市值取 daily_basic_df（或 data_context 传 circ_mv）；同时订正实现为 3 维制（换手/波动维独立有效信号）。
- **分类**：数据层/口径（445 冻结边界内可改，前端数据获取错误属 444 事实层）。

### ❌2（**464-7**）evaluate 静默吞异常 → 输出退化无告警
- **现状**：`PhaseDetectionEngine.compute_tags` 与 `CrowdingFactor.evaluate` 两处调用均包 `try/except: pass`（evaluate 主体）。
- **实证**：锁环境下 **PhaseDetectionEngine 整体未生效**（茅台 phase 落 tags 兜底"出货期（高位派发）"，detail 非"PhaseDetector分析（置信度xx）"）、**crowding 输出 unknown**（默认值）——异常被静默吞掉，输出退化无日志（430 §7.4-3 静默吞异常同类）。
- **影响**：连带 fund_flow 恒"中性（无明确资金流向）"、audit「资金流向」恒 False、fund_price_divergence 恒"数据不足"（需资金方向非 neutral 才产结论）。
- **建议处置**：异常改 `logger.warning`（或保留 debug + 输出降级标记 data_warning），勿静默回退默认值。
- **分类**：健壮性/可观测性。

### ⚠️3（**464-8**）fund_flow 双源枚举不对称：tags 侧永不产 `5d_outflow`
- **现状**：depth 组 `MainForceScorer.get_tags`（chip_strategy.py:1097-1125）打分单向——`_score_moneyflow ≥2→5d_inflow / ≥1→mixed / else none`，**永不产 5d_outflow**；`5d_outflow` 唯一由 evaluate 内 PhaseDetectionEngine 覆盖路径产出（dim4:5845-5858）。`_assess_fund_flow`（dim4:5661-5665）本身只认 5d_inflow/5d_outflow 两枚举。
- **影响**：覆盖路径一旦失效（见 ❌2）→ 全市场无"强流出"输出；retail_institution 组合判定（mfp×ff）也受影响，易落"中性"。
- **建议处置**：tags 侧补 5d_outflow 判定（对称打分）或明确"引擎覆盖为唯一权威源"并同步 _assess_fund_flow。
- **分类**：数据层/口径。

### ⚠️4（**464-9**）`_analyze_fund_flow` 未用 data_context.moneyflow_df
- **现状**：`_analyze_fund_flow`（dim4:982-1006）用 `self._get_dm().get_cached_moneyflow(ts_code)`（ECM 直读），未用 dim1 已注入的 `data_context.moneyflow_df`——同源无正确性影响，但 daemon 写锁时 ECM 读失败 → compute_tags 整体异常 → 静默降级（❌2 实证即此路径）。
- **建议处置**：compute_tags 增传 moneyflow_df，`_analyze_fund_flow` 优先用 data_context 版本（与 dim2/443 同构接线）。
- **分类**：接线/健壮性。

### ⚠️5（**464-10**）cost_ext 条件性失效（456 融资成本投票少触发）

### ⚠️7（**464-12**，待拍板·判定逻辑）涨停交叉校验"次日低开"：注释矛盾 + 覆盖范围偏窄（**非死逻辑**，2026-09-21 复核修正）
- **现状**：`_limit_up_cross_check`（dim4:1232-1302）入口要求当天涨停（pct_chg>9.5 提前 return）；`next_day_low_open` 检查 `pc_2>9.5`（df.iloc[-2] 涨停）且 `df.iloc[-1].open < df.iloc[-2].close×0.97`（次日低开3%+）。
- **复核结论（修正此前"互斥不可达"误判）**：**可达**——连续双涨停 + 第二日低开高走（低开≥3% 后拉涨停）时 next_day_low_open=True，规则3（lifting+高位+巨量+次日低开→distributing）可触发。例：df.iloc[-2] 收盘 10（涨停）、df.iloc[-1] 开盘 9.6 收盘 11（涨停）→ pc_2>9.5 ✓、pct_chg>9.5 ✓、9.6<9.7 ✓。
- **真问题**：① 注释两行自相矛盾（"latest 是当天涨停日" vs "涨停日在 df.iloc[-2]"）——语义混乱；② 覆盖范围偏窄：next_day_low_open 仅在 df.iloc[-1] 也是涨停日（入口条件）时才可能评估，**单涨停 + 次日低开不涨停**的场景反而漏检（与 298 号"次日低开"意图可能不符）。
- **建议**：核对 298 号规则本意——若意图为"涨停次日低开"（单涨停场景），当前实现漏检，需调整判定窗口；若接受"仅双涨停场景"，则订正注释消除矛盾。
- **分类**：判定逻辑（445 冻结边界，须用户拍板）。

### ⚠️8（**464-13**，待拍板·判定逻辑）audit「主力阶段」不看置信度

- **分类**：判定逻辑（须拍板）。

### ⚠️9（**464-14**，待拍板·判定逻辑）audit「资金流向」判定枚举死档 + **漏 `strong_out`**
- **现状**：audit 条件 2 `level in ('very_strong','strong','medium','weak')`；实现只产 `strong/strong_out/none`——`very_strong/medium/weak` 是死枚举。
- **⚠️ 复核补充（比死枚举更实际）**：判定集**漏 `strong_out`**——实现产出的"强流出"（`level='strong_out'`，来自 `_assess_fund_flow` 或 PhaseEngine 覆盖）不在判定集 → **资金强流出时 audit「资金流向」恒 False**（强流入 strong 满足、强流出反而不满足，不对称）。
- **建议**：判定集补 `strong_out`（或改按 direction 判定 inflow/outflow 两态），同时清理死枚举。
- **分类**：判定逻辑（须拍板）。

### ⚠️10（**464-15**，待拍板·口径）`_dim_fund` 的 net_lg_5d 单位错配
- **现状**：`strength = min(1.0, abs(net_lg_5d)/1e8)`（dim4:511-520）；net_lg_5d 单位**万元**（fund_5d_ext 聚合 moneyflow 万元列），按"元/亿"除 → strength≈0（茅台 -16037万→0.0002）。
- **影响**：fund_flow=mixed 时 `_dim_fund` 返回 {}（不投票）影响有限；但 5d_inflow 时 lifting 只取 0.3 下限，**投票强度恒被低估**。
- **建议**：÷1e4（万元→亿）或按万元归一。
- **分类**：口径（445 边界内可改，属数据层单位错误）。

### ⚠️11（**464-16**，待开实施号·输出有效性）`_assess_signal` 映射缺 `third_sell`（三卖被吞）
- **现状**：`_assess_signal` 的 sm 映射 `{'first_buy','second_buy','third_buy','first_sell','second_sell'}`——**缺 `third_sell`**；而 buy_sell_point 值域含 third_sell（`get_chanlun_tags` 卖点优先级 second_sell > **third_sell** > first_sell > first_sell_p，chanlun_strategy.py:2704-2725）。
