# 369 — COL环节四项问题修订方案

> **目标**：修复COL环节审查中发现的4个问题，确保采集环节的数据完整性、分库一致性和采集有效性。

---

## 一、问题根因分析

### 问题1：margin_cache 主库和分库均为0行

**根因**：`_batch_margin(today)` 传入当天日期，非交易日（周末/节假日）时 Tushare `margin_detail` API 返回空数据。

```python
# data_daemon.py:1117
today = datetime.now().strftime('%Y%m%d')  # 非交易日如 20260823
# data_daemon.py:1186
added = _batch_margin(today)  # API 对非交易日返回 0 行
```

**证据**：
- 周六 `pro.margin_detail(trade_date='20260823')` → 0行
- 周五 `pro.margin_detail(trade_date='20260821')` → 1998行
- daemon 日志反复出现"空表，触发补采...→ 补采 0 条"

**影响**：融资融券数据始终为空，JUD-1 门禁层无法获取 margin 数据做主力在场判定。

### 问题2：balancesheet_cache/cashflow_cache/forecast_cache 为空

**根因**：`_run_financial_sync` 中调用了 `_batch_balancesheet`/`_batch_cashflow`/`_batch_forecast`，但 `run_integrity_check` 的完整性检查列表中**不包含这3张表**，导致空表时不会自动触发补采。

**证据**：
- `_run_financial_sync` 在 daemon 后台线程中运行（`data_daemon.py:1654`）
- `run_integrity_check` 的检查列表（`data_daemon.py:1139-1258`）不含 balancesheet/cashflow/forecast
- 即使 `_run_financial_sync` 被调用，如果 API 返回空数据也不会重试

**影响**：3张财务表始终为空，JUD 环节无法获取资产负债表/现金流/业绩预告数据。

### 问题3：factor_cache 日期异常（EPOCH 1970-01-01）

**根因**：`factor_precompute.py` 中因子计算返回的 Series 使用整数索引（RangeIndex 0,1,2...），而非日期索引。`_batch_cache_factor_series` 将整数0作为 `trade_date` 写入，SQLite 将其转为 `1970-01-01`。

**状态**：✅ 代码已修复（368号方案阶段0），数据已清空待重跑。

### 问题4：market_cache.db 数据滞后主库3天

**根因**：分库写入通过 `_insert_from_df` 中的 `sharding_manager.execute_batch_insert()` 执行，失败时仅记录 DEBUG 级别日志（被 `_DedupLogFilter` 吞掉）。实际写入失败的异常被静默忽略。

**证据**：
- 主库 daily_cache 最新 2026-08-21，分库最新 2026-08-18
- 分库 cached_at 显示批量数据在 2026-08-18T20:13 写入（初始迁移），后续 COL 写入未同步
- `_insert_from_df` 第151-152行：`except Exception as e: logger.debug(f"分库写入失败（非致命）: {table}, {e}")`

**影响**：分库数据与主库不一致，RAW-1/RAW-2/RAW-3 从分库读取时数据不完整。

## 二、修订方案

### 修订1：margin_cache 非交易日降级（🔴 高优）

**文件**：`data_daemon.py` `_batch_margin` + `run_integrity_check`

**改动**：
1. `_batch_margin` 增加非交易日降级逻辑：当传入日期的 API 返回空数据时，自动回退到 `daily_cache` 中的最新交易日
2. `run_integrity_check` 中 margin 检查改为：空表时使用最新交易日而非当天

```python
def _batch_margin(trade_date: str) -> int:
    """全市场融资融券个股明细 — 支持非交易日降级"""
    _ensure_pd()
    import tushare as ts
    pro = ts.pro_api()
    raw = _ts(pro.margin_detail, trade_date=trade_date)
    if raw is None or raw.empty:
        # 非交易日降级：使用 daily_cache 中的最新交易日
        try:
            latest = _ecm.conn.execute(
                "SELECT MAX(trade_date) FROM daily_cache"
            ).fetchone()[0]
            if latest and latest != trade_date:
                raw = _ts(pro.margin_detail, trade_date=latest.replace('-', ''))
        except Exception:
            pass
    if raw is None or raw.empty:
        return 0
    # ... 后续逻辑不变
```

**改动**：在完整性检查中新增3张财务表的空表检查

# 在 adj_factor 检查之后追加
for table, label, fn in [

### 修订4：分库写入失败提升为 WARNING（🔴 高优）

**文件**：`enhanced_cache_manager.py` `_insert_from_df`

**改动**：分库写入失败的日志级别从 DEBUG 提升为 WARNING，确保异常可见

```python
# 第151-152行
except Exception as e:
    logger.warning(f"分库写入失败: {table}, {e}")  # 原为 logger.debug
```

**同时**：分库 daily_cache 缺少 `pre_close` 和 `change` 列（Tushare API 返回但表结构无），需要 ALTER TABLE 补齐，或在 `_validate_and_fix_data_format` 中过滤不存在的列。

**补充改动**：`_insert_from_df` 中增加列过滤，忽略分库表中不存在的列

```python
# 在分库写入前增加列过滤
try:
    from app.data.sharding_manager import sharding_manager
    db_name = sharding_manager.get_db_for_table(table)
    if db_name:
        # 检查分库表的列，过滤不存在的列
        shard_cols = {row[1] for row in sharding_manager.execute_query(
            table, f"PRAGMA table_info({table})")}
        if shard_cols:
            keep = [c for c in cols if c in shard_cols]
            if len(keep) < len(cols):
                shard_rows = [tuple(r[c] for c in keep) for _, r in df.iterrows()]
                shard_col_list = ', '.join(f'"{c}"' for c in keep)
                shard_placeholders = ', '.join(['?' for _ in keep])
                sharding_manager.execute_batch_insert(
                    table, f"INSERT OR REPLACE INTO {table} ({shard_col_list}) VALUES ({shard_placeholders})", shard_rows)
            else:
                sharding_manager.execute_batch_insert(table, f"INSERT OR REPLACE INTO {table} ({col_list}) VALUES ({placeholders})", rows)
except Exception as e:
    logger.warning(f"分库写入失败: {table}, {e}")
```
