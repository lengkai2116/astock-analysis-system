## 1. 页面结构概览

策略模板是**策略类后台管理的核心枢纽页面**，职责清晰界定为：

- ✅ **是**：系统策略管理平台（11个领域策略 + S1-S7 浏览/查看规格/复制为自建）
- ✅ **是**：Vibe自建策略管理平台（自然语言→AI生成→预览→保存/编辑/删除）
- ✅ **是**：选股系统 L3 的 Vibe 自建策略数据源（`vibe_strategies` localStorage 跨页同步）
- ❌ **不是**：因子组合管理场所（由因子管理页直接对接到选股系统 L3）
- ❌ **不是**：AI策略管理场所（由 AI 多角色投研页独立管理）

### 1.3 数据流

```
策略模板页
  │
  ├─ 系统策略 (Tab: 系统策略)
  │   ├─ GET /api/v2/strategy/templates → 11个系统策略列表 → 卡片/表格渲染
  │   ├─ GET /api/v2/strategy/templates/{id} → 单个策略详情 → 6区段详情面板
  │   ├─ POST /api/v2/strategy/templates/{id}/clone → 复制为自建策略
  │   └─ GET /api/v2/strategy/system-list → 简要列表 → 选股系统L3同步
  │
  ├─ Vibe自建策略 (Tab: Vibe自建)
  │   ├─ POST /api/v2/strategy/generate → AI自然语言→策略代码/参数
  │   ├─ POST /api/v2/strategy/templates → 保存自建策略
  │   ├─ PUT /api/v2/strategy/templates/{id} → 更新自建策略
  │   └─ DELETE /api/v2/strategy/templates/{id} → 删除自建策略
  │
  └─ 选股系统 L3 (外部消费者)
      └─ localStorage `vibe_strategies` key → 原型阶段跨页模拟同步
          └─ [Phase 1] GET /api/v2/strategy/system-list → 正式同步
```

## 6. 已知差异（Discrepancies）

### D1: 11个系统策略全部硬编码且后端领域模型不匹配 [P0]

原型 `SYSTEM_STRATEGIES` 数组（L316-549）包含11个A股领域策略（量价/缠论/筹码/达尔文/S1-S7），每个含完整规格（id/cat/params/inputs/output/wiki/code）。

**后端事实：** `backend/app/routes/strategy.py` 的 `GET /api/v2/strategy/templates` 返回的5个通用模板（均线交叉/RSI均值回归/布林带/MACD/KDJ）**与原型结构完全不同**：
- 原型: 11个策略（中文名/中文描述/A股专用参数/标签体系/枚举输出）
- 后端: 5个模板（英文名/通用描述/通用参数/Mustache模板代码）

**影响：** 这是策略模板页最核心的差异。即使后端路由已就绪，也无法对接原型——领域模型完全不同。

**Phase 0 任务：** 将11个系统策略的数据模型从原型前端迁移到后端（作为配置文件或数据库种子）。

### D2: Vibe Coding AI生成仅前端Mock [P0]

`generateMockStrategy()`（L876-889）返回固定模板的JavaScript硬编码对象，`params` 固定为 `{period: 14, threshold: 30, holding_days: 5}`，`code` 为固定注释+伪代码结构。

**后端服务已就绪：** `backend/app/services/ai_strategy_generator.py` 实现了AI策略生成服务（支持DeepSeek/LM Studio/Mock模式），包含7种指标识别模式。
**路由缺失：** `POST /api/v2/strategy/generate` 无对应路由实现。

**优先级：** P0 — 挂载生成路由 + 前端接入API

### D3: 复制系统策略为纯前端操作 [P0]

`copyToVibe()`（L1011-1036）直接从 `SYSTEM_STRATEGIES` 数组复制对象属性到 `vibeStrategies` 数组，无后端调用。

**后端无对应端点：** `POST /api/v2/strategy/templates/{id}/clone` 完全未实现。

**优先级：** P0 — 实现clone端点 + 前端接入

### D4: Vibe策略CRUD仅localStorage [P0]

`loadVibeStrategies()` / `saveVibeStrategies()`（L566-571）全部操作 `localStorage.getItem/setItem`。页面刷新不影响同一浏览器，但跨设备/无痕模式/缓存清除全部丢失。

**后端路由已就绪：** `POST/PUT/DELETE /api/v2/strategy/templates` 在 `route/strategy.py` 中完整实现（基于SQLAlchemy+StrategyTemplate模型）。

**优先级：** P0 — 接入后端API替代localStorage

### D5: 详情面板从内存数组读取 [P0]

`selectCard()`（L689-783）从前端 `SYSTEM_STRATEGIES` + `vibeStrategies` 内存数组逐项查找。6区段（概览/参数/输入/输出/wiki/代码）全部从内存对象中读取字段拼接HTML。

**后端路由已就绪：** `GET /api/v2/strategy/templates/{id}` 在 `route/strategy.py` 中已实现（返回 strategy.to_dict()），但返回结构与原型所需结构不同（见D1）。

**当前状态：** screener.html L3 中系统策略列表为空（仅有Vibe自建从localStorage读取）。

**依赖端点：** `GET /api/v2/strategy/system-list`（S8）未实现。

#171 §2.8 中标注为 "❌ 未实现" 的端点，用于选股系统L3获取系统策略简要列表。原型阶段无替代方案。

### D8: 参数调整无后端持久化 [P1]

详情面板参数range slider调整后仅存储在DOM中（`.param-val` 文本和 `input[type=range]` 的 `value` 属性），刷新页面后复位至原始值。系统策略滑块为disabled状态无此问题，仅Vibe自建策略可调。
