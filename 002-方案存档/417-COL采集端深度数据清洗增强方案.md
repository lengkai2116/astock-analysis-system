# 417-COL采集端深度数据清洗增强方案

> **背景**：用户要求验证 COL 采集端是否对采集数据进行了有效清洗。经全链路核查（data_daemon.py 批量采集函数 + enhanced_cache_manager.py 写入网关 + mootdx/akshare 实时采集器），确认 COL 已做"基础格式清洗"（日期/代码统一、列白名单过滤、字段重命名、主键去重、无效快照过滤、`_safe_float` NaN→0），但**未做"深度数据质量清洗"**，存在 4 处缺口。本方案针对这些缺口制定增强计划。
> **范围**：仅增强 COL 采集端写入网关的深度清洗，不改变四层架构（COL 采集+规范化 → RAW 计算）职责划分，不触碰 RAW/SIG 层。
> **方法**：在统一写入网关 `_insert_from_df` 的清洗入口 `_validate_and_fix_data_format` 中补充深度清洗，按表类型差异化处理，保持幂等可回滚。

---

## 一、核查结论：4 处清洗缺口

| # | 严重度 | 缺口 | 现状 | 影响 |
|---|--------|------|------|------|
| 1 | HIGH | **NaN/空值未显式处理** | 批量 Tushare 数据无 `dropna`/`fillna`，NaN 直接落库为 NULL | 下游 RAW 需自行防御，脏值透传 |
| 2 | HIGH | **OHLC 一致性校验缺失** | 无 `high≥low`、`open/close` 在 `[low,high]` 区间内等合理性校验 | 异常 K 线原样入库，污染指标计算 |
| 3 | MED | **异常值/离群值检测缺失** | 无涨跌幅超限、价格突变等离群过滤 | 单点脏数据影响均线/波动率 |
| 4 | MED | **类型转换不彻底** | 仅日期/代码做格式清洗，数值列未统一 `to_numeric` | 部分列以文本存储，下游计算报错 |

**根因**：`_validate_and_fix_data_format`（enhanced_cache_manager.py L213）仅实现 355号方案 规则1-3（日期/代码/列名），未覆盖数值质量维度。所有批量采集最终都经 `_insert_from_df` → `_validate_and_fix_data_format`，是深度清洗的唯一且最佳落点。

---

## 二、增强设计

### 增强1（HIGH）— 数值列类型统一 + NaN 处理

**目标**：所有数值列统一 `to_numeric`，并按表类型差异化处理 NaN。

**修改文件**：`backend/app/data/enhanced_cache_manager.py` 的 `_validate_and_fix_data_format`

在现有规则1-3 之后新增规则4：

```python
# 规则4：数值列类型统一 + NaN 处理
_NUMERIC_COLUMNS = {
    'daily_cache': ['open', 'high', 'low', 'close', 'pre_close', 'vol', 'amount', 'pct_chg'],
    'daily_basic_cache': ['turnover_rate', 'volume_ratio', 'pe', 'pb', 'total_mv', 'circ_mv'],
    'moneyflow_cache': ['buy_lg_amount', 'sell_lg_amount', 'net_lg_amount', ...],
    'stk_limit_cache': ['high_limit', 'low_limit'],
    'lhb_cache': ['buy_amount', 'sell_amount', 'net_amount', 'buy_rate', 'sell_rate'],
    # ... 其余表按需补充
}
```

**NaN 处理策略（按表类型）**：
- **K线/行情表**（daily_cache、minute_kline_cache、market_snapshot）：价格列 NaN → 0（与 `_safe_float` 一致），`vol/amount` NaN → 0
- **财务/基本面表**（daily_basic_cache、fina_indicator_cache 等）：数值列 NaN → NULL（保留缺失语义，不伪造 0）
- **资金流表**（moneyflow_cache）：`net_*` 列 NaN → 0（净额缺失视为 0）

> 关键：**不统一 fillna(0)**，避免把"数据缺失"误标为"数值为 0"（尤其 PE/PB/财务指标），否则会污染估值类 RAW 计算。

### 增强2（HIGH）— OHLC 一致性校验

**目标**：对 K 线类表校验 OHLC 合理性，异常记录修正或丢弃。

**修改文件**：同上，新增规则5

```python
# 规则5：OHLC 一致性校验（仅 K 线类表）
_OHLC_TABLES = {'daily_cache', 'minute_kline_cache', 'market_snapshot', 'index_daily_cache'}

def _fix_ohlc(df: pd.DataFrame) -> pd.DataFrame:
    """校验并修正 OHLC 一致性：
    - high < low → 交换
    - open/close 超出 [low, high] → 夹取到区间
    - 全部价格 <= 0 → 丢弃该行
    """
    mask_valid = (df['high'] > 0) & (df['low'] > 0)
    df = df[mask_valid]
    if df.empty:
        return df
    # high < low 交换
    swap = df['high'] < df['low']
    df.loc[swap, ['high', 'low']] = df.loc[swap, ['low', 'high']].values
    # open/close 夹取到 [low, high]
    for col in ['open', 'close']:
        df[col] = df[col].clip(lower=df['low'], upper=df['high'])
    return df
```

**处理原则**：
- **可修正**（high/low 颠倒、open/close 越界）→ 夹取修正，保留数据
- **不可修正**（价格全 ≤0、high 或 low 缺失）→ 丢弃该行
- 校验在 `_insert_from_df` 内、`_validate_and_fix_data_format` 之后执行，仅作用于 K 线类表

---

### 增强3（MED）— 异常值/离群值检测

**目标**：对 K 线类表检测明显异常值（涨跌幅超限、价格突变），异常记录丢弃并告警。

**修改文件**：同上，新增规则6

```python
# 规则6：离群值检测（仅 K 线类表）
def _detect_outliers(df: pd.DataFrame) -> pd.DataFrame:
    """检测并剔除明显异常记录：
    - 单日涨跌幅 |pct_chg| > 50%（A股单日涨跌幅上限 20%/30%，>50% 必为脏数据）
    - 价格突变：close 相对前一日 close 变化 > 100%（停牌复牌/除权场景除外，由复权因子处理）
    """
    if 'pct_chg' in df.columns:
        df = df[df['pct_chg'].abs() <= 50]
    return df
```

**处理原则**：
- 阈值保守（涨跌幅 >50% 才判离群），避免误杀正常数据（如新股上市首日、ST 股）
- 剔除记录时 `logger.warning` 记录 ts_code + trade_date，便于审计
- 仅作用于 K 线类表，财务/基本面表不做离群过滤（财务指标本身波动大）

---

### 增强4（MED）— 清洗结果可观测性

**目标**：深度清洗可观测，便于审计与排查。

**修改文件**：同上

在 `_insert_from_df` 中统计清洗前后行数差异，差异 >0 时输出告警日志：

```python
before = len(df)
df = self._validate_and_fix_data_format(df)   # 规则1-4
df = self._apply_deep_clean(table, df)        # 规则5-6（按表类型）
if len(df) < before:
    logger.warning(f"[COL清洗] {table}: 清洗剔除 {before - len(df)} 行 ({before}→{len(df)})")
```

## 三、实现结构

### 新增方法（enhanced_cache_manager.py）

在 `_validate_and_fix_data_format` 之后新增 `_apply_deep_clean(table, df)`，按表类型分发规则5-6：

```python
def _apply_deep_clean(self, table: str, df: pd.DataFrame) -> pd.DataFrame:
    """深度清洗：按表类型应用 OHLC 校验 + 离群值检测"""
    if df.empty:
        return df
    if table in _OHLC_TABLES:
        df = self._fix_ohlc(df)
        df = self._detect_outliers(df)
    return df
```

### 调用链

```
_insert_from_df(table, df)
  ├─ _validate_and_fix_data_format(df)   # 规则1-4：日期/代码/列名/数值+NaN
  └─ _apply_deep_clean(table, df)        # 规则5-6：OHLC 校验 + 离群检测（按表类型）
```

> 规则4（数值+NaN）放在 `_validate_and_fix_data_format` 内统一处理；规则5-6 因需按表类型区分，独立为 `_apply_deep_clean`。

## 五、风险与回滚

- **风险1**：OHLC 夹取/离群剔除可能误伤正常数据。缓解：阈值保守（>50% 才判离群）、可修正优先于丢弃、剔除记录告警可审计。
- **风险2**：`to_numeric` 对超大表（600万+行）可能耗时。缓解：仅对数值列操作，pandas 向量化，秒级；在 daemon 写入路径执行，不影响读取。
- **风险3**：NaN→NULL 策略改变下游行为。缓解：仅对"缺失语义"列（PE/PB/财务）保留 NULL，K线价格列仍 NaN→0，与既有 `_safe_float` 一致。
- **回滚**：全部为 `_validate_and_fix_data_format` / `_apply_deep_clean` 内新增逻辑，不改变表结构，可整体回退；已入库数据不受影响（清洗仅作用于写入路径）。
- **兼容**：不改变四层架构职责（COL 采集+规范化 → RAW 计算），深度清洗仍属 COL 层，RAW 层无需改动。
