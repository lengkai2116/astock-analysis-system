# 352 — 332-337 架构落地修订方案（8项差距修复）

## 一、背景

351号核查报告 + 332-337 架构对照，发现 8 项差距（G1-G8）。本方案按优先级排序，制定修订方案和执行计划。

## 二、差距清单与修订方案

### G2 [P0] diagnose 的 operation_advice 未传 L1 共识（高）

**现状**（cross_validate.py:505）：
```python
unified = build_operation_advice(ts_code, _dims, [], _df, tags=tags)
# 缺少 consensus=_l1_consensus, dirs=_l1_dirs
```

**设计依据**：332号§5.6"实时操作建议不能独立于生产环节另算"；336号§2"消双口径"

**修订方案**：
在 cross_validate.py:505 调用前，获取 L1 九维共识和 dirs，传入 advice_builder：

```python
# cross_validate.py:505 附近，调用 build_operation_advice 前新增：
try:
    _sv = self._get_status_verdict(ts_code)
    if _sv:
        _l1_consensus = {
            'consensus_rate': _sv.get('consensus_rate', 0),
            'bullish_votes': _sv.get('bullish_dims', 0),
            'bearish_votes': _sv.get('bearish_dims', 0),
            'direction': _sv.get('direction', 'neutral'),
            '_source': 'nine_dim',
        }
        _l1_dirs = []
        for _d in json.loads(_sv.get('dim_states', '{}')).values():
            _light = _d.get('light', 'yellow')
            _l1_dirs.append(1 if _light == 'green' else (-1 if _light == 'red' else 0))
    else:
        _l1_consensus = None
        _l1_dirs = None
except Exception:
    _l1_consensus = None
    _l1_dirs = None

unified = build_operation_advice(ts_code, _dims, [], _df, tags=tags,
                                  consensus=_l1_consensus, dirs=_l1_dirs)
```

**改动范围**：cross_validate.py 1 处
**依赖**：advice_builder.py 的 `consensus`/`dirs` 参数（已存在）
**风险**：低（_get_status_verdict 已在同函数中调用，复用同一缓存）
**验收**：兴齐眼药弹窗/个股页仓位一致（均为 0.6 或均为同一值）

### G3 [P1] diagnose 的 _arb 仲裁仍用五维共识（中）

**现状**（cross_validate.py:438-444）：
```python
consensus, voting_detail = self._compute_consensus(tags, adjusted_votes)  # 五维标签投票
_arb = arbitrate(tags, gate=gate, consensus=consensus)  # 用五维共识仲裁
```

**设计依据**：336号§2"消双口径：弹窗摘要/个股页/快照全部读同一 L2 输出共识"

**修订方案**：
将 _arb 的 consensus 从五维标签投票改为 L1 九维推导。_get_status_verdict 在 diagnose 中已调用（cross_validate.py:538），可复用其 consensus。

具体步骤：
1. 将 `_get_status_verdict(ts_code)` 的调用从 Step F（:538）提前到 Step C 之后（:438 附近）
2. _arb 调用时传入 L1 九维 consensus：
   ```python
   _l1_consensus_for_arb = {'direction': _sv.get('direction', 'neutral'),
                              'consensus_rate': _sv.get('consensus_rate', 0)}
   _arb = arbitrate(tags, gate=gate, consensus=_l1_consensus_for_arb)
   ```
3. 标签投票 consensus 保留，仅用于 voting_detail 展示（弹窗投票明细）

**改动范围**：cross_validate.py 1 处（_arb 的 consensus 参数）
**依赖**：_get_status_verdict（已存在）
**风险**：中（改变 diagnose 的 opportunity_state 计算路径，需验证全市场状态分布变化）
**验收**：弹窗 opportunity_state 与 status_snapshot 一致率显著提升

### G1 [P1] right_side_confirm 未作为 L1 独立维度（中）

**现状**：status_engine._build_dimensions 11 维不含 right_side_confirm，仅由 arbiter P0-P6 消费标签。

**设计依据**：332号§5.5"闸门2→成为 L1 信号确认维度核心输入"；336号§5"right_side_confirm 改为 L1 信号确认维输出"

**修订方案**：
在 status_engine._build_dimensions 中新增 `signal_confirm` 维度，但 **不参与共识计票**（332号"不允许参与九维平均"）。

新增维度定义：
```python
# _build_dimensions 末尾，11维之后追加（不入 _DIM_ORDER）
rsc = str(tags.get('right_side_confirm', ''))
bsp = str(tags.get('buy_sell_point', ''))
if rsc == '否决':
    put('signal_confirm', '否决', 0.7,
        [f'right_side_confirm=否决', f'buy_sell_point={bsp}'])
elif rsc == '强确认':
    put('signal_confirm', '强确认', 0.8,
        [f'right_side_confirm=强确认'])
elif rsc == '基础确认':
    put('signal_confirm', '基础确认', 0.6,
        [f'right_side_confirm=基础确认'])
else:
    put('signal_confirm', '未确认', 0.5,
        [f'right_side_confirm={rsc or "无"}'])
```

关键：`signal_confirm` 不加入 `_DIM_ORDER`，consensus_rate 计算不遍历该维度。它仅用于：
- dim_states 输出（前端九维灯中显示"信号确认"维度）
- _build_verdict / 七维模板第①维的状态来源
- arbiter P0-P6 仍从标签消费（不变）

**改动范围**：status_engine.py 1 处（_build_dimensions 新增维度）+ config/status_engine.yaml（dimension_weights 不加 signal_confirm）
**依赖**：无
**风险**：低（维度仅输出到 dim_states，不影响共识计算和仲裁）
**验收**：status_snapshot.dim_states 中包含 signal_confirm 维度（状态+证据+红绿灯）

### G4 [P2] conflict[:6] 截断丢弃 deep_valuation 规则（中）

**现状**（status_engine.py:455）：
```python
'conflict_evidence': conflict[:6]
```
_aggregate 自身生成 6 条冲突规则，arbiter 追加的 deep_valuation 在第 7+ 位被截断。

**设计依据**：336号§4.2 要求 6 条规则全部输出

**修订方案**：
将截断逻辑改为：先截断 _aggregate 自身的规则到 4 条，再追加 arbiter 的规则（不受截断限制），总计不超过 8 条。

```python
# status_engine.py:455 附近
_core_conflicts = conflict[:4]   # _aggregate 自身检测的核心冲突（保留前4条）
_arb_conflicts = arb.get('conflict_evidence', [])  # arbiter 检测的冲突（deep_valuation等）
all_conflicts = _core_conflicts + _arb_conflicts
'conflict_evidence': all_conflicts[:8],  # 总计不超过8条
```

**改动范围**：status_engine.py 1 处
**依赖**：无
**风险**：低
**验收**：deep_valuation+强确认 冲突证据出现在 status_snapshot.conflict_evidence 中

### G6 [P2] advice_builder L0c 阈值硬编码 12%（中）

**现状**（advice_builder.py:222）：`if _dist > 12`

**设计依据**：334号 生命周期阈值从 signal_registry.yaml 读取

**修订方案**：
将硬编码 12% 改为从 signal_registry.yaml 读取：

```python
# advice_builder.py:222 附近
from app.services.status_config import get_signal_registry
_registry = get_signal_registry().get('signals', {})
# 取所有信号的 extended.dist_pct 最大值作为统一阈值
_extended_pct = 0
for _sig_cfg in _registry.values():
    _ext = (_sig_cfg.get('lifecycle') or {}).get('extended') or {}
    _pct = _ext.get('dist_pct', 0)
    if _pct > _extended_pct:
        _extended_pct = _pct
_extended_pct = _extended_pct * 100 if _extended_pct <= 1 else _extended_pct  # 兼容 0.12 和 12
if _dist > _extended_pct and state in ('enter', 'light'):
    state = 'wait'
```

**改动范围**：advice_builder.py 1 处
**依赖**：signal_registry.yaml（已存在）
**风险**：低
**验收**：yaml 中 lifecycle.extended.dist_pct 变更后，advice_builder 同步生效

### G7 [P3] 多空打平共识率公式偏差（低）

**现状**（status_engine.py:400）：bull=bear=3 时 consensus_rate=0.5

**设计依据**：336号§2.2"多空打平→tie标记"

**修订方案**：
多空打平时 consensus_rate 设为 0.0（无优势方向），direction='neutral'。

```python
# status_engine.py:400 附近
if bull == bear and bull > 0:
    consensus_rate = 0.0  # 多空打平，无优势方向
    direction = 'neutral'
elif bull + bear > 0:
    consensus_rate = round(max(bull, bear) / (bull + bear), 3)
    direction = 'bullish' if bull > bear else 'bearish'
else:
    consensus_rate = 0.0
    direction = 'neutral'
```

**改动范围**：status_engine.py 1 处
**依赖**：无
**风险**：极低（多空打平场景罕见，且 direction='neutral' 本身已标识）
**验收**：全市场快照中 bull==bears 的股票 consensus_rate=0.0
