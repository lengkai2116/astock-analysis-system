## 一、背景与目标

431 §018 确认 `dim2_structure_engine.py` 是缠论框架的**整份 vendored 副本**（4 区块 ~3800 行：chanlun_config / chanlun_level_validator / trend_structure_detector / chanlun_strategy）。其中 `chanlun_level_validator.py` framework 份已于 2026-09-14 删除（零消费方）；剩余 **chanlun_config / chanlun_strategy / trend_structure_detector 三组双份均 live**。

**目标**：eliminate dim2 内联副本，dim2 改为 import framework 共享底座——符合 SIG dim1-dim8 规划（dim3/dim5/dim6 均为 import framework 模式，dim2 是唯一内联 vendored 异类）；缠论能力全局单一代码源；**同时修复第一步审计发现的 dim2 内联版功能退化**（背驰检测失效、快速模式被删）。

## 六、环境说明（daemon 运行中）

- framework `analyze()` 回迁后对**带 `ts_code` 的 df** 读预计算 MACD 表（`_load_precomputed_macd`，411 Phase 5 设计意图）。daemon 进程内调用走同一 ECM 单例（无自锁，读自己预计算写入的表）；**独立 pytest 进程**调用时与 daemon 跨进程抢锁 → 挂起（环境阻塞，同 431 §018 性质）。
- 处置：`test_chanlun_verification.py` 加 autouse fixture mock `_load_precomputed_macd` 恒返回 `{}`（合成数据验证缠论逻辑，不验证预计算读取；真实预计算读取由 data_daemon 冒烟覆盖）。**该 mock 只在测试进程生效，不影响生产**。
- 若需跑 framework 缠论的真实预计算读取用例：关停 daemon（用户授权）或沙盒双切（`TEST_DATA_DIR`）。
