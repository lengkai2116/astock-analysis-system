# 信号强度评分体系重构方案

## 一、背景与问题

### 1.1 问题背景

机会地图（`_ui-prototype/opportunity-treemap.html`）的方块大小由 `signal_strength`（信号强度，0-10 分）决定，经实证发现评分体系存在四个层次的问题：

**问题 1：评分离散扎堆，无法拉开方块差异**

当前公式（`data_daemon.py:_compute_signal_strength`）：

```
基础分 = 主力阶段 5 档（building 7.0 / lifting 6.0 / washing 5.5 / distributing 2.0 / unknown 3.0）
       + 估值调整（±1.5 / ±1.0 / 0）
       + 趋势调整（±1.0 / 0）
最终 = 基础分 × 置信度系数（0.8 / 0.9 / 1.0 三档） × 环境系数（0.7 / 0.85 / 0.9 / 1.0）
```

实证分布（`treemap_snapshot` 5578 只，2026-08-02 实测）：

| 分数段 | 股票数 | 占比 |
|--------|-------|------|
| 8-10 分 | 20 只 | 0.4% |
| 6-8 分 | 1136 只 | 20.4% |
| 4-6 分 | 3822 只 | 68.5% |
| 2-4 分 | 553 只 | 9.9% |
| 0-2 分 | 47 只 | 0.8% |

同分扎堆严重（6.8 分 362 只 / 5.6 分 756 只 / 4.8 分 787 只），高分（8-10 分）仅 20 只。方块面积差异被"离散输入 + 开方感知（面积差 7.7 倍只感知 2.8 倍）+ 递归切分/minSize 压制"三重削弱，视觉上无法识别高信号强度股票。

**问题 2：标签内部同质化，差异被抹平**

"状态 → 固定分"是分类而非测量：

- `building` 一律 +2.0，但低价建仓（price_position=low_zone）与高价建仓（high_zone）同分
- `volume_price_fit=healthy` 内部，price_trend 2% 与 8% 一视同仁
- 置信度 0.9 与 0.4 的建仓同分

大量标签统一评分导致组合空间锁死，分数相同的股票背后可能是完全不同的信号画像。

**问题 3：信号组合效应丢失**

- 独立加总无法体现同向信号的协同（多标签确认应 1+1>2）
- 负向信号叠加（出货 + 资金流出 + 量价背离）应产生远超线性的风险结果，线性减分表达不了"风险开关"语义

**问题 4（v2 新增）：引擎已算出连续强度，评分层却视而不见，重新"状态赋分"**

引擎实证（2026-08-02 核查）：

| 引擎 | 已算出的连续量 | 落库后被离散成 | 连续量去向 |
|------|--------------|--------------|-----------|
| PhaseDetectionEngine（五源投票） | `phase_confidence` 0-1（5 源 4 一致 = 0.8，phase_detector.py:440-469） | 无（独立标签，但被评分按 3 档打折） | 连续值丢弃 |
| `_add_vp_simple_tags`（量价） | price_trend、vol_trend 连续值（data_daemon.py:1680-1693） | healthy/diverging/neutral 三态 | 连续值丢弃 |
| PhaseDetection 价格位置 | pos_ratio 0-1（phase_detector.py:142-151） | low/mid/high_zone | 连续值丢弃 |
| VolumePrice 模式检测 | 模式 confidence（volume_price_strategy.py:1987） | pattern_signal 状态 | confidence 丢弃 |

**核心结论**：评分体系应当**消费引擎已有的连续强度（置信度/偏离度/连续量），而非给离散状态重新赋分**。v1 的"状态→固定分 + 乘性修正"本质仍是拍脑袋赋分，差异是人为设计出来的；正确做法是让差异从"信号源含义本身"自然长出——方向来自状态标签（分类语义），强度来自引擎连续量（测量语义），两者正交。

### 1.2 设计目标

机会质量由**两个独立维度正交表达**：

| 维度 | 表达 | 语义 |
|------|------|------|
| 方块大小 | signal_strength（重构后） | 信号强弱与确认程度（定量、连续） |
| 方块颜色 | opportunity_type 健康度（HOLD_COLORS） | 机会类型与健康度（定性、分类） |

两者都好的股票（大方块 + 对颜色）= 高质量机会。**signal_strength 不负责回答"该不该关注"（那是颜色的职责），只回答"这个信号有多强、多确定"**，但保留方向性（见 §二）。

### 1.3 目标分布

| 分数段（百分制） | 现占比（十分制折算） | 目标占比 |
|--------|--------|---------|
| 90-100 | 0.4% | ~8-12% |
| 70-90 | 20.4% | ~30% |
| 40-70 | 68.5% | ~40% |
| <40 | 10.7% | ~15% |

高分不再稀有、中间段不再一坨、低分有梯度，方块大小自然拉开层次。

## 二、核心决策

### 2.1 决策一：保留方向性（带方向双向投票）

**结论：signal_strength 必须保留方向性，不能做成纯强度。**

决定性证据：signal_strength 是 L4 共识的**方向性票源**，不止管方块大小。全局改成纯强度后，放量出货股（方向为空）会拿高分 → L4 共识投票将其误判为多头票（`cross_validate.py:54`：`>=7 → +1, <=4 → -1`），扭曲共识结论。

信号源双向投票：正向信号加分、负向信号减分。副作用可控：危险股（红）天然低分小块，符合"大块 = 偏正面"的视觉直觉。

### 2.2 决策二：百分制展示

**结论：进制不是拉开差异的关键，公式连续性与输入分辨率才是；但百分制更适合展示。**

- 离散输入下，100 分制只是 8→80、7→70，照样扎堆；必须让**连续型数据（置信度、量价数值、估值偏离度）直接进入公式**
- 百分制收益：感知精度高（89 vs 81 直观可感）、无 UI 小数截断（现 `toFixed(1)`）、整数即表达精细差异
- 采用百分制需同步迁移 5 处消费方阈值（见 §五）

### 2.3 决策三：三层评分结构（v2 修订语义）

```
信号强度(0-100) = 基础层（方向 × 引擎连续强度，消费引擎数值而非状态赋分）
               + 协同层（同族去相关 → 跨族加权共识 → 状态依赖权重 → 组合语义识别）
               − 风险层（负向证据叠加 → 惩罚/封顶/否决，非对称）
```

三层架构不变（看基础、看协同、看风险），**每层的计分方式在 v2 中重构**：基础层消费引擎连续强度、协同层做加权共识而非数量累加、风险层用负向证据强度而非固定减分。

## 三、三层评分结构详细规则

### 3.1 基础层：方向 × 引擎连续强度（v2 全面替换 v1 的"状态赋分"）

#### 3.1.0 核心原则：方向来自状态，强度来自引擎数值

每个信号源的贡献拆成两个正交分量：

```
信号源贡献 = 方向 dir（∈ {+1, 0, −1}，来自状态标签，分类语义）
           × 强度 strength（∈ [0, 1]，来自引擎连续量，测量语义）
```

- **方向**回答"这个信号偏多还是偏空"——由状态标签决定（lifting=+1、distributing=−1、neutral=0）
- **强度**回答"这个信号多确定/多强烈"——由引擎连续量决定（五源投票置信度、量价数值、偏离度幅度）
- **二者正交**：高置信出货 = 方向 −1 × 强度 0.9 = 强负信号（大而红，危险醒目）；低置信建仓 = 方向 +1 × 强度 0.4 = 弱正信号（小而绿，待确认）——差异从信号源含义自然长出，无需人工系数

#### 3.1.1 数据通道：引擎连续量透出（前置改造，v2 新增；主力阶段部分依赖 312 号修复）

当前引擎连续量**未落库**（price_trend/vol_trend/pos_ratio/主力阶段投票明细），评分层拿不到。需在引擎输出/标签层透出以下连续量（新增标签或扩展字段，见 §六）：

> **上游依赖**：`phase_confidence` 的连续化与 `phase_vote_ratio` 明细由 **312号（主力阶段判定修复方案，8 维度加权共识体系）** 产出——312 将五源投票从"等权票数制"升级为"8 维度加权连续强度共识"，phase_confidence 由 5 个离散档变为连续 0-1。本方案在 312 完成后实施，直接消费其连续输出。

| 连续量 | 来源 | 现状 | 透出方式 |
|--------|------|------|---------|
| phase_confidence | 主力阶段判定（312号 8 维度加权共识） | ✅ 已落库但仅 5 档离散 | **312 修复后连续 0-1，直接消费** |
| phase_vote_ratio | 主力阶段判定（312号） | ❌ 未落库 | 312 输出 8 维度投票明细（JSON） |
| phase_conflict | 主力阶段判定（312号） | ❌ 未落库 | 312 输出分歧标记 + conflict_detail |
| 主力投票明细（各源方向一致性） | `_vote_decision` votes | ❌ 未落库 | 由 312 的 phase_vote_ratio 取代 |
| pos_ratio（120 日价格分位） | `_price_position_analysis` | ❌ 离散成 low/mid/high | 引擎输出连续 pos_ratio |
| price_trend / vol_trend（量价连续值） | `_add_vp_simple_tags` | ❌ 离散成三态 | 计算处保留连续值输出 |
| 资金净流入强度 | `_analyze_fund_flow`（net_lg_amount 5 日累计） | ❌ 离散成 inflow/outflow | 输出连续净流入强度（归一化） |
| 估值偏离度 | ValuationEngine | ✅ 已落库（valuation_deviation REAL） | 直接消费 |
| 筹码 ASR | ChipDistribution | ❌ 仅 chip_concentration 状态 | 透出 asr 连续值 |
| 缠论买点置信度 | ChanlunAnalyzer | ❌ 仅 buy_sell_point 状态 | 透出买点级别/置信度 |

#### 3.1.2 各信号源方向与强度定义

| 信号源 | 方向 dir（状态） | 强度 strength（引擎连续量） |
|--------|-----------------|----------------------------|
| 主力阶段 | lifting +1 / building +1 / washing 0 / distributing −1 / unknown 0 | **phase_confidence 连续 0-1（312号 8 维度加权共识产出；washing 占比从 57.8% 回落后方向分布改善）** |
| 趋势一致 | up_aligned +1 / down_aligned −1 / mixed、no_trend 0 | 三周期斜率强度（short/mid/long 同向数/3，连续 0-1） |
| 量价配合 | healthy +1 / diverging −1 / neutral 0 | 量价健康度（price_trend/vol_trend 连续映射，健康程度 0-1） |
| 价格位置 | low_zone +1 / high_zone −1 / mid 0 | pos_ratio 偏移度（越极端强度越高，|pos_ratio−0.5|×2） |
| 估值 | low/extreme_low +1 / high/extreme_high −1 / fair 0 | 偏离度幅度（min(1, |valuation_deviation|/30)） |
| 资金流向 | 5d_inflow +1 / 5d_outflow −1 / 其余 0 | 净流入强度（5 日累计净额归一化 0-1） |
| 筹码 | concentrating +1 / dispersing −1 / stable 0 | ASR 连续值（区间映射 0-1） |
| 缠论买点 | first_buy/third_buy +1 / first_sell/second_sell −1 / 其余 0 | 买点置信度（缠论级别/结构确认度） |
| 财务健康 | pass 0 / suspicious 0 / fail → 触发风险层 | —（财务是否决门，不参与正向强度） |

#### 3.1.3 基础层聚合

```
基础分 = Σ( dirᵢ × strengthᵢ × wᵢ )        # wᵢ 为信号源族权重（见 3.2.2）
理论范围 ≈ −(Σw) ~ +(Σw)
```

方向与强度正交后，基础分天然连续：同方向下，强度越高分越高；强度相同下，方向决定正负。**不再有"状态→固定分"的离散台阶**。

### 3.2 协同层：去相关 → 加权共识 → 状态依赖 → 组合语义（v2 全面替换 v1 的"数量累加"）

v1 按"同向信号数量 n"给非线性奖励，问题是：①信号源权重不同却一视同仁；②同族信号（资金/筹码/主力都测"主力行为"）被重复计数；③组合含义不同却同分；④情绪环境对信号可信度的影响没有体现。v2 按四步处理：

#### 3.2.1 第一步：同族去相关合并

信号源先按"测度对象"归族，同族内先合并成一个证据，**避免重复计数**：

| 族 | 成员 | 合并方式 |
|----|------|---------|
| **主力行为族** | main_force_phase / trend_alignment / fund_flow / chip_concentration | 同向时只计一个证据：`主力证据 = 方向 × max(各族强度)`；反向时取主信号方向 |
| **价格价值族** | price_position / valuation_level | 同向合并（位置低 + 低估 = 一个"价值底部证据"） |
| **独立族** | volume_price_fit / buy_sell_point / fina_health | 各自独立，不合并 |

合并后得到**相互独立的证据族**：主力、价值、量价、缠论、财务（≤5 族），跨族才算"多指标共识"。

#### 3.2.2 第二步：跨族加权共识（替代数量累加）

```
共识分 = Σ( wᵢ × dirᵢ × strengthᵢ ) / Σ wᵢ      # wᵢ = 族权重
```

族权重 wᵢ ∝ 该族的**独立性与可靠性**（v1 拍脑袋系数替换为有依据的权重）：

| 族 | 权重依据 | wᵢ（草案） |
|----|---------|:---:|
| 主力行为族 | 五源投票引擎，可靠性最高 | 3 |
| 价格价值族 | 估值偏离度为连续量，可量化 | 2 |
| 量价族 | 量价连续值，与主力部分重叠 | 1.5 |
| 缠论族 | 单源信号，独立性强 | 1.5 |
| 财务族 | 是否决门，不参与共识加权 | — |

共识分 ∈ [−1, +1]，连续。**强信号主导、弱信号微调**——两个 0.9 强度同向 vs 两个 0.4 强度同向，共识分自然不同（这正是 v1 数量累加做不到的）。

#### 3.2.3 第三步：状态依赖权重（知识库《量价形态与情绪周期融合框架》动态权重矩阵）

情绪周期（sentiment_phase）作为**状态变量**改变族权重，而非简单环境乘子：

| 情绪阶段 | 主力/价值族 | 量价/缠论族 | 说明 |
|---------|:---:|:---:|------|
| 复苏 recovery | 1.0 | 1.0 | 正常 |
| 冰点 ice | 1.0 | 0.7（只保留超跌信号） | 买入信号降权 |
| 高潮 climax | **0.5** | **0.5** | 买入信号权重减半（诱多风险） |
| 退潮 ebb | **0.3** | **0**（买入信号清零） | 系统风险压制 |

依据：《量价形态与情绪周期融合框架》"高潮期买入信号权重减半、退潮期买入信号权重清零"。

#### 3.2.4 第四步：组合语义识别（不同组合含义不同）

同向信号数量相同、组合含义不同——识别组合类型，附加语义修正：

| 组合类型 | 判定条件 | 语义修正 |
|---------|---------|---------|
| **确认型** | 主力族 + 独立族 ≥2 同向（如建仓+放量健康+资金流入） | ×1.15（多源确认，机会可信） |
| **初现型** | 仅主力族正向，独立族无同向 | ×1.0（信号刚出现，等确认） |
| **追高警示型** | 拉升 + 情绪高潮 + 高位（pos_ratio>0.7） | ×0.6（追高风险，压分） |
| **矛盾型** | 同族内方向冲突（如主力建仓但资金流出） | ×0.7（证据打架，降级） |

设计依据：307号§3.1.7 证据计数 + 知识库《多指标共识机制》信号隔离与分层思想。

### 3.3 风险层：负向证据强度驱动封顶/否决（框架保留，v2 用证据强度替代固定减分）

负向信号不按线性减分，而是"组合触发风险门"；v2 中负向证据同样用"方向 × 强度"（高置信出货 = 强负证据，更快触发风险门）：

| 负向证据组合 | 处理 |
|---------|------|
| 出货 + 资金流出（同向负证据 ≥2） | 负向共识 ×1.5（负向证据同样有叠加放大） |
| 出货 + 流出 + 量价背离 + 缠论卖点（负证据 ≥3 且强度均值 > 0.6） | **直接封顶 ≤20** |
| fina_health = fail | **单独封顶 ≤30**（一票否决候选） |
| 情绪退潮 + 负证据 ≥2 | 额外 ×0.7（环境风险叠加） |

**为什么非对称**：正向信号是"锦上添花"（该奖励），负向信号是"风险开关"（该否决）。财务暴雷 + 主力出货的股票，即使趋势向上、情绪高涨，机会质量也应被压死——线性减分表达不了这个语义。

### 3.4 映射与输出

```
总分 = clamp( 100 × 共识分 × 状态权重 × 组合语义修正 , 0, 100 )   # 各分量见 §3.2/§3.3
输出 = round(总分)    # 0-100 整数，写入 signal_strength
```

**v2 与 v1 的本质差异**：v1 是"固定系数加分/减分 → 映射"，差异靠人工系数设计；v2 是"方向×引擎强度 → 加权共识 → 状态修正 → 组合修正"，差异从信号源含义与引擎测量自然长出——每个分数对应"信号有多强、多少独立证据、什么环境、什么组合形态"。

## 四、面积公式适配（前端）

信号强度由 0-10 改为 0-100 后，面积公式 `value = Math.pow(Math.max(0, signalStrength - 2), 2.5) * 1.5 + 10`（`opportunity-treemap.html:951`）必须同步适配，否则全部方块退化为最小面积。

**适配公式（候选）**：

```
方案 1（保持指数放大形状）：
  value = Math.pow(Math.max(0, (ss100 - 20) / 10), 2.5) * 1.5 + 10
  # ss100=100 → 281；ss100=40 → 18.5；与十分制原公式形状一致

方案 2（归一化百分制，更平滑）：
  value = 10 + Math.pow(ss100 / 100, 2.5) * 300
  # ss100=100 → 310；ss100=80 → 10+0.572×300 ≈ 182；ss100=50 → 63
```

**建议**：实施时两种公式各验证一次全市场分布，选择层级感更明显者。面积公式改动仅限 `buildTreeData` 机会模式分支（:951），不影响 market/value 模式与 `sizeMode` 逻辑。

## 七、验证方案（v2 增加引擎对照验证；联动 312 号修复）

> **前置条件**：312 号（主力阶段判定修复）批次 1 完成后，washing 占比回落（57.8% → 目标 25-35%）、phase_confidence 连续化——本方案验证在 312 修复后的数据上进行。

1. **分布验证**：全市场重算后直方图——目标 90-100 占比 ~8-12%、无同分扎堆（同分数股票 ≤ 2%）、<40 分占比 ~15%
2. **引擎对照验证（v2 新增）**：评分应与引擎连续量单调相关——①与 phase_confidence 的相关性（高置信阶段 → 高分，312 连续化后 ρ 应显著提升）；②与 valuation_deviation 的单调性（低估 → 高分）；③同分数股票的信号画像应相似（反向验证：抽查同分股票，其主力/量价/估值组合应一致）
3. **典型样本对比**（人工抽验）：
   - 低价高置信建仓+多族确认 → 预期 85-95；高价低置信建仓+单族 → 预期 55-65
   - 危险组合（出货+流出+背离+卖点）→ 预期 ≤20；财务 fail → 预期 ≤30
   - 追高警示（拉升+高潮+高位）→ 预期被 ×0.6 压低
   - phase_conflict 股票 → 评分被置信度打折影响（风险层素材）
4. **消费方回归**：L4 共识投票、操作建议分级、自选库自动升级、雷达排序在阈值迁移后输出合理
5. **前端视觉**：方块大小层级感明显，高分股可一眼识别
