# 统一阶段判定引擎设计

## 一、定位

取代当前 MainForceScorer 的等权评分逻辑。核心变化：**先判定阶段，再输出标签**，不算总分。

## 二、五源融合架构

```
统一阶段判定引擎 (PhaseDetectionEngine)
  │
  ├── 输入1: TradingPhaseDetector → 基于 OHLCV 的初步阶段判定
  │     (已有，chip_strategy_impl.py:21)
  ├── 输入2: MainForceScorer(资金流向维度) → 大单净额+连续性
  │     (已有，chip_strategy.py — 移除总分逻辑)
  ├── 输入3: StageDetector → 量价四阶段判定
  │     (已有，volume_price_strategy.py:1983)
  ├── 输入4: ChipDistributionService → 筹码分布(ASR/SSRP/CYQKL)
  │     (已有，chip_distribution_service.py)
  └── 输入5: VolumePriceStrategy(趋势部分) → 趋势强度+量价模式
        (已有，volume_price_strategy.py:3963)

  融合规则:
  ├── ≥3 个来源判定同一阶段 → 确认，置信度 = 一致数/5
  ├── 2 个一致 + 2 个不一致 → 可疑，输出分歧原因
  └── 全部不一致 → unknown
  
  输出标签:
    main_force_phase: building | washing | lifting | distributing | unknown
    phase_confidence: 0.0-1.0
    price_position: low_zone | mid_zone | high_zone
    trend_direction: up | down | sideways
```

## 三、阶段判定步骤

```
Step 1: 价格位置判定
  - 近120日价格区间分位 → price_position
  - 均线排列(MA5/MA20/MA60) → ma_alignment

Step 2: 量能模式识别
  - 5日/20日/60日均量对比
  - 量比趋势、量价协调性

Step 3: 资金流向分析
  - 5日大单净额方向及连续性 → fund_flow
  - 散户反向指标

Step 4: 筹码分布确认
  - ASR(浮筹比例)、SSRP偏离度、CYQKL → chip_concentration
  - **ASR 量化阈值规则**（来源：LLM Wiki "ASR指标"概念）：

    ```python
    if ASR > 90 and ASR_trend_30d == 'declining':
        投票给 lifting（高位浮筹区持续回落=脱离高浮筹区，拉升启动）
    elif ASR < 15 and 当前价在筹码主峰±10%内:
        投票给 building（浮筹极少+价格在集中区=筹码锁定在建仓范围）
    elif ASR < 15 and 当前价 > 筹码主峰 × 1.2:
        投票给 lifting（浮筹极少+有显著浮盈=拉升途中）
    elif ASR > 30 or ASR_trend_30d == 'rising_sharply':
        投票给 distributing（浮筹快速增加=筹码扩散，出货迹象）
    ```

  - **筹码主峰位置辅助判定**（来源：LLM Wiki "主力操盘四阶段"概念）：

    读取 ChipDistributionService 输出的 CYQKL 数据，获取当前筹码主峰位置和次峰位置：

    ```python
    peak_price = chip_data['main_peak']      # 筹码主峰对应价格
    sub_peak_price = chip_data.get('sub_peak', None)  # 筹码次峰（如有）
    
    if current_price < peak_price * 1.15:
        主峰状态 = 'price_at_peak'    # 价格在主峰附近
    elif current_price > peak_price * 1.2:
        主峰状态 = 'price_above_peak'  # 价格已远离主峰
    else:
        主峰状态 = 'price_near_peak'
    
    # 辅助判定：
    if 主峰状态 == 'price_at_peak' and ASR < 15:
        筹码倾向 = building（低位密集+浮筹少=建仓）
    elif 主峰状态 == 'price_above_peak' and ASR < 15:
        筹码倾向 = lifting（有浮盈+筹码不散=拉升）
    elif sub_peak_price and 主峰状态 == 'price_above_peak':
        筹码倾向 = distributing（出现次峰+价格远离主峰=筹码转移）
    ```

    ASR 阈值规则和主峰位置判定**不额外增加投票源**，而是作为 Step 5 阶段判定中筹码维度投票时的内部细化依据——即输入4（ChipDistributionService）在输出投票时，依据上述规则选择投票给具体哪个阶段，而非笼统输出 chip_concentration 趋势。

Step 5: 阶段判定（五源投票 + 涨停交叉校验）

  基础判定（五源投票）：
  ┌────────────┬─────────────────────────────────────┐
  │ 阶段        │ 判定条件                              │
  ├────────────┼─────────────────────────────────────┤
  │ building   │ 低位+放量+资金流入+价格震荡             │
  │ washing    │ 低位+缩量+资金脉冲+价格区间收窄         │
  │ lifting    │ 中高位+放量+多头排列+资金持续流入       │
  │ distributing│ 高位+放量滞涨+资金流出/散户大量买入    │
  │ unknown    │ 以上均不匹配                           │
  └────────────┴─────────────────────────────────────┘

  **涨停类型交叉校验**（来源：LLM Wiki "涨停板不同阶段含义"概念）：
  当当日出现涨停（涨幅 ≥ 9.9%）时，对基础判定的结果进行二次校验：

  ```python
  # 仅在 Step 5 初判阶段后进行，不独立产生投票
  低位涨停 = 涨停前位于 price_position == 'low_zone' 或近60日价格区间下30%
  高位涨停 = 涨停前位于 price_position == 'high_zone'
  巨量    = 当日成交量 > 60日均量 × 2
  次日低开 = 次日开盘价 < 当日收盘价 × 0.97  # 需盘后次日数据补充

  if 初判阶段 == 'building' and 低位涨停 and not 巨量:
      阶段 ← 'building'（确认：拔高建仓，符合 building 特征）
  elif 初判阶段 == 'building' and 高位涨停:
      阶段 ← 'distributing'（修正：高位涨停建仓不典型，可能实为出货）
  elif 初判阶段 == 'lifting' and 高位涨停 and 巨量 and 次日低开:
      阶段 ← 'distributing'（修正：放量涨停次日低开=诱多出货）
  elif 初判阶段 == 'distributing' and 低位涨停 and 缩量:
      阶段 ← 'building' or 'washing'（修正：低位缩量涨停不像是出货）
  # 不满足上述条件时，维持初判阶段不变
  ```

  > 涨停校验仅在当日触发时生效。五源投票的初判结果仍然输出，涨停校验修改的是最终输出的 `main_force_phase`。该机制约影响 10%-15% 有涨停的个股（日频），核心价值是减少 building 和 distributing 在极端行情下的误判。
```

## 四、输出标签清单

| 标签名 | 类型 | 说明 |
|--------|------|------|
| `main_force_phase` | 枚举 | 主力阶段 |
| `phase_confidence` | 浮点数 | 0-1 |
| `price_position` | 枚举 | 价格区间位置 |
| `trend_direction` | 枚举 | 趋势方向 |
| `fund_flow` | 枚举 | 大单资金流向 |

## 五、实施要点

- **改造 MainForceScorer**：移除等权总分逻辑，保留各维度的独立判断能力 `_score_moneyflow()` / `_score_volume_price()` 等，每个维度独立输出置信度
- 位置：`backend/app/opportunity_atlas/phase_detector.py`
- 计算时机：盘后预计算
- 异常处理：某个信号源不可用时（如无 moneyflow 数据），自动降级为剩余信号源判定
