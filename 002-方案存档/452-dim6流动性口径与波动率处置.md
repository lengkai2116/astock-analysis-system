# 452 号 — dim6 流动性口径与波动率处置

## 一、问题确认（445 §6.3 dim6 两条偏差，代码级已核）

**445 §6.3 dim6** 登记两条判读偏差：

1. **波动率当风险源** —— 引擎 `_assess_risk_level` / `_list_risk_factors` 把 `volatility_level=='high'` 计入 risk_sources / risk_factors（升 risk_level、进 audit「波动率」条件）。
   **KB 权威《风险定义（纳兰达版）》**：「纳兰达认为波动性是机会而非风险，金融理论认为波动性是风险」——体系采纳前者，**高波动不应计入风险源**；ATR/波动分位仅作参考信息。

2. **流动性口径不符** —— 原实现用「换手率<1%」当流动性风险源（`_assess_risk_level` 读 `tags['turnover_rate']<1` 升 risk_level）。
   **KB 权威《量化财务门槛/风险剔除逻辑体系》**：「日均成交额>5000万元 + 流通市值>30亿元」双门槛。换手率低≠成交枯竭（蓝筹也可低换手），口径不符。

> 448号已处置 dim6 PIERS（造假升 L0a 硬否决 / E 高杠杆维度 / audit 假检查）；**波动率/流动性两条未在 448 处置**，本号承接。

## 二、修复方案（用户拍板：波动率从风险源摘除 + 流动性改双门槛）

### 2.1 波动率从风险源摘除（KB：波动是机会而非风险）

- `_assess_risk_level`／`_list_risk_factors` **移除 `volatility_level=='high'` 判据**：高风险源计数、风险因子、audit「波动率」条件均不再含高波动。
- 波动信息**仅作参考输出**（不参与判定）：`_calc_volatility` 保留，`status_description.volatility_*` 继续暴露 ATR%/波动分位；`_risk_plain` 白话仍可呈现「高波动」作为环境描述（**不是风险源**）。

### 2.2 流动性改 KB 双门槛（成交额<5000万 / 流通市值<30亿 → 触发）

- 新增模块常量：
  - `_LIQUIDITY_MIN_AVG_AMOUNT_WAN = 5000.0`（日均成交额 5000 万元）
  - `_LIQUIDITY_MIN_CIRC_MV_WAN = 300000.0`（流通市值 30 亿元 = 30×10000 万元）
- 新增**纯函数 `_assess_liquidity(df, basic_df, tags)`** 返回 `{'triggered','avg_amount_wan','circ_mv_wan','detail'}`：
  - `avg = df['amount'].astype(float).tail(20).mean()/10`（**千元→万元**，332号单位）
  - `circ_mv_wan = basic_df['circ_mv'].iloc[-1]`（万元）
  - `avg<5000` 或 `circ<300000` → triggered；任一数据来源不足 → **不触发**（保守，无数据不惩罚，不误伤正常股）。
- **数据来源（data_context 链路）**：dim1 预加载 `daily_basic_df`（流通市值）+ 既有 `daily_df`（成交额）；`evaluate` 取 `(data_context or {}).get('daily_basic_df')` 传入，回退空 `None`（不触发 DB 兜底查询）。
- `_assess_risk_level(tags, liquidity_info=None)` / `_list_risk_factors(tags, liquidity_info=None)` **签名新增 `liquidity_info` 参数**（默认 None）：`liq_high = bool(liquidity_info and liquidity_info.get('triggered'))` → 计入 high_count / 生成「流动性」风险因子。
- **契约/audit**：
  - `status_description` 新增 `liquidity_risk` / `liquidity_detail` / `liquidity_avg_amount_wan` / `liquidity_circ_mv_wan`。
  - audit「波动率」条件**替换为「流动性」**：`satisfied = not triggered`，`threshold='日均成交额>5000万且流通市值>30亿'`，`actual=liquidity_detail`。

### 2.3 SIG/JUD 边界合规（约束：不改 status_engine L0b）

- 本号只在 **SIG 侧**改分析结论/现状描述（波动率摘除 + 流动性双门槛），**产条件不产否决**；L0 硬否决（含 `_apply_l0` 的 `low_liquidity` 换手率<1% 软风险 / 仓位系数 0.7）仍归 **JUD 层 StatusEngine**，**不在本号 scope**。
- 因此 `test_321_s4_snapshot.test_l0_low_liquidity_soft_risk`（测 JUD `_apply_l0` 换手率软风险）**不改不动**，回归通过即证边界未破坏。

## 三、影响评估（445 约束：不破坏判定基准）

- **波动率**：原「高波动」会升高 risk_level/risk_factors/audit 不满足；现不再升——高波动股 risk_level 回落（仅当存在其它风险源才升），audit「波动率」消失、改「流动性」。**纯摘除，无副作用**。
- **流动性**：由「换手率<1%」改为「成交额<5000万 / 流通市值<30亿」。触发面变化（换手低但成交额大→不再触发；成交额枯竭→触发）。新增判断会**影响 risk_level 计数**，从而可能改 `judgment.light`——但 SIG/JUD 边界下灯色最终由 JUD 消费，SIG 侧只是如实产条件。
- **数据缺失兜底**：daily_df 或 daily_basic_df 缺任一 → 流动性不触发（保守中性），存量无 daily_basic_df 的调用不崩、不误标。
- 448号 PIERS、JUD L0b 逻辑**零改动**。
