# 321 — 机会图谱跨维仲裁与结论收敛方案

> **背景**：2026-08-08 对个股机会弹窗进行全面核查（26-08-08 沟通纪要 001/003），实证机会图谱存在 **4 类矛盾输出**。根因定位为**架构形态问题**：4 条平行维度链各自独立计算、独立产标签、并列展示，缺跨维串联仲裁层。本方案提出**结论收敛层（机会状态机）+ 显式仲裁优先级表**，从计算层根治矛盾，同时保留各维度链主体功能。
>
> **约束**：①仅存档，不修改代码（实施待用户确认）；②Windows + macOS 双平台长期部署为背景约束，本方案全部在单进程计算层内完成，不引入多进程/多写共享（避免重蹈 239/240/243 号 PG+Redis+Gunicorn 覆辙）；③各维度链（潜力/时机/阶段/共识）判定逻辑保持独立完整，收敛的是"结论"，不是"事实"。

## 一、问题定义（实证）

### 1.1 四条平行维度链

```
┌─ 链A 潜力链：7维截面百分位+IC加权 → signal_strength(0-100)  [慢变量·月度]  potential_engine.py
├─ 链B 时机链：闸门2(一票否决+基础+增强) → right_side_confirm  [快变量·日线]  data_daemon.py:_check_right_side_confirm
├─ 链C 阶段链：8维加权共识 → main_force_phase                 [中变量·周级]  phase_detector.py
└─ 链D 共识链：L4 12+3票源+情绪加权 → consensus/verdict/advice  [混合变量]    cross_validate.py
        ↓ 四链输出并列落入 opportunity_tags_cache / treemap_snapshot / 弹窗
        无优先级、无互斥、无一致性校验 → 矛盾输出
```

### 1.2 四类矛盾实证（5583 只，2026-08-08）

| # | 矛盾 | 数量 | 性质 | 根因 |
|---|------|------|------|------|
| T1 | 右侧否决 + 主力建仓 building | **305** | 假矛盾(时间尺度)+展示无解释 | 链B与链C独立判定、并列展示；"主力建仓"(慢)与"短线否决"(快)本可共存 |
| T2 | 右侧否决 + 看多型机会类型(building_watch/steady_rise等) | **490** | 真矛盾 | `_classify_opportunity_type` 规则树不消费 right_side_confirm |
| T3 | 右侧否决 + L4 看多共识(看多票>看空票) | **522** | 真矛盾 | `_build_verdict` 未被 rsc 否决覆盖；L4 中 rsc 仅 1 票，可被多票压过 |
| T4 | 操作建议"右侧否决" + max_position_ratio>0 | 部分 | 真矛盾(数值) | `_build_operation_advice` 否决只覆盖 label，仓位未归零 |

### 1.3 结构根因

1. **缺"结论收敛层"**：计算层只有"维度计算"，没有"跨维仲裁"这一级。L4 是链内投票，不是跨链裁决；
2. **缺"显式判定优先级"**：否决>高估>看空>未确认 的优先级隐式散落各函数（rsc 覆盖 advice、gate 覆盖仓位），无统一仲裁表；
3. **缺"时间尺度解释"**：快慢变量矛盾（T1 类）在展示层无解释（313 号 C5/C6 未落地）。

## 二、方案总览：收敛结论、保留事实

```
现状：4 链独立 → 并列输出 → 消费端自行拼接（矛盾暴露）
目标：4 链独立 → 仲裁层统一裁决 → 单一结论 opportunity_state → 消费端单一引用（矛盾消除）

P4 各引擎（4链判定逻辑不变） → 标签库（59 标签原貌保留）
                                      │
                 ┌────────────────────▼────────────────────┐
                 │  新增：仲裁层（机会状态机，P4.5 管道环节）  │
                 │  输入：4 链全部标签 + 门禁                  │
                 │  输出：opportunity_state + state_evidence  │
                 │  规则：显式仲裁优先级表（§三）              │
                 └────────────────────┬────────────────────┘
                                      │
   opportunity_state → 快照 → API → 前端颜色/建议/弹窗（单一引用）
   原始标签 → 画像/筛选/策略分析（继续消费维度数据）
```

**核心原则**：
- **收敛结论**：颜色、操作建议、verdict、机会类型、仓位上限——全部从 `opportunity_state` 派生，天然一致；
- **保留事实**：59 种标签、7 维画像、4 链原始判定全部保留，供画像/筛选/策略分析使用；
- **不越红线**：仲裁在计算层（P4.5），不在调用层实时计算，符合 292 号四层架构红线。

## 三、核心设计：机会状态机 + 显式仲裁优先级表

### 3.1 状态枚举（单一输出）

| 状态 | 语义 | 颜色 | 对应现有时机色 |
|------|------|------|--------------|
| `enter` | 可入场 | 🟦 蓝（共识≥70% 深蓝） | 强确认 |
| `light` | 可轻仓 | 🟨 黄 | 基础确认 |
| `wait` | 等待 | ⬜ 灰 | 未确认 |
| `avoid` | 回避 | 🟫 棕 | 否决 |

### 3.2 显式仲裁优先级表（本方案核心）

**从上到下逐级判定，命中即止**（优先级：硬否决 > 硬风险 > 软否决 > 方向 > 时机 > 默认）：

| 优先级 | 条件 | 判定 | 覆盖范围 |
|:---:|------|------|---------|
| **P0 硬否决** | `right_side_confirm='否决'`（缠论卖点/量价背离/预跌形态） | **avoid** | 覆盖一切（无论潜力多高/共识多强） |
| **P1 硬风险** | `gate.hard_risks` 含 `event_negative`（监管立案） | **avoid** | 覆盖一切 |
| **P2 深度高估** | `gate.valuation='deep'`（PE分位>90 或 dev<-20） | **avoid** | 覆盖一切 |
| **P3 强看空** | L4 `direction='bearish'` 且 `consensus_rate≥0.65` | **avoid** | 覆盖时机 |
| **P4 未确认** | `right_side_confirm='未确认'` | **wait** | 覆盖潜力 |
| **P5 可轻仓** | `right_side_confirm='基础确认'` 且 L4 非强看空 | **light** | 按共识细分 |
| **P6 可入场** | `right_side_confirm='强确认'` 且 L4 `direction='bullish'` 且 `consensus_rate≥0.55` | **enter** | 共识≥70% 深蓝 |
| **P7 默认** | 其余（基础确认+L4中性/分歧） | **light** 或 **wait** | 按 L4 方向 |

### 3.3 状态派生（所有消费点统一引用）

```
opportunity_state 决定：
├─ 颜色（前端方块 + 弹窗时机行）——不再单独映射 right_side_confirm
├─ operation_advice：
│   ├─ avoid → action='not_recommended'，label='回避：{触发依据}'，max_position_ratio=0（修 T4）
│   ├─ wait → action='hold'，label='等待：右侧信号未确认'，max_ratio=按共识但≤0.2
│   ├─ light → action='hold/add_position'，label='可轻仓：基础确认'，max_ratio=按共识×0.5
│   └─ enter → action='build_position'，label='可入场：右侧确认+共识'，max_ratio=按共识（强确认+0.1）
├─ verdict（交叉验证）：统一附加状态语义（修 T3）——"★ {状态}：{依据摘要}"
├─ 机会类型（修 T2）：avoid 时机会类型降级为"回避·仅观察"（原始类型保留在 detail 字段）
└─ 风险提示：state_evidence 生成对应风险文案
```

### 3.4 时间尺度解释（修 T1，展示层）

- `opportunity_state`（快变量）与七维画像（含阶段链慢变量）**明确分区**展示；
- 弹窗对"状态=avoid + 画像trend=建仓🟡"组合，自动附加解释条："⚠ 主力阶段显示建仓（慢变量），但短线时机出现否决信号（快变量），当前以时机为准"；
- 解释条文案由 `state_evidence` 驱动（哪些标签导致 avoid），不硬编码。

| 风险 | 概率 | 缓解 |

**回滚**：S1-S4 为后端新增/改造，可逐阶段 git revert；前端 S5 兜底逻辑保证旧数据可展示。所有阶段独立提交。
