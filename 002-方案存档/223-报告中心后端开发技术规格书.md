## 1. 页面定位

报告中心是**全系统报告的统一存档检索中心**，不直接生成报告。它接收来自5个上游模块的存档数据，提供搜索/筛选/查看/下载/删除功能。

### 1.1 数据流方向

| 方向 | 说明 |
|:-----|:------|
| **数据流入** | 各模块主动推送（自动或手动保存）到报告中心 |
| **用户操作** | 搜索 → 筛选 → 查看详情（弹窗）→ 下载 / 删除 |
| **数据流出** | JSON文件下载 → 本地留存 |

### 1.2 报告类型体系（5种）

| 标识 | 显示名称 | 来源模块 | 触发方式 | 后端类型映射（当前v2→v3） |
|:-----|:---------|:---------|:---------|:--------------------------|
| `strategy` | 策略存档 | indicator-ide | 用户手动保存 | `single_stock` → 改名 |
| `analysis` | 分析报告 | ai-analysis | 用户手动保存 | `research` → 改名 |
| `backtest` | 回测报告 | backtest | 自动归档 | `backtest` → 保留 |
| `diagnosis` | 诊断报告 | playback | 自动生成 | **新增** |
| `sandbox` | 测试报告 | strategy-sandbox | 自动归档 | **新增** |

> **已移除类型：** `research`（研究报告）——系统中无此类型产出模块

### 3.3 后端就绪度评估：~60%

**就绪分析：** 报告中心是已审计页面中**后端就绪度较高**的页面——核心CRUD端点（列表/详情/删除）已全部实现，服务层（ReportGenerator/AIStrategyGenerator/ResearchPipeline）全部就绪。唯一缺口是：
1. 路由前缀v2→v3变更（纯机械修改）
2. 报告类型枚举从3种扩展到5种
3. 新增上游模块写入端点（POST）
4. 文件系统→数据库迁移（生产需求，原型期文件存储可先用）

与复盘中心（~0%）、策略沙箱（~20%）完全不同——报告中心后端**不需要从零构建**，大部分工作是**路由迁移+类型对齐**。

    total_score: Optional[int]           # 综合评分（0-100）
    pnl_pct: Optional[float]             # 盈亏百分比
    summary: str                         # 摘要（80字以内）
    
    # 下载状态
    downloaded: bool = False             # 是否已下载
    file_size: Optional[int] = None      # 文件大小（字节）
    
    # 完整内容

    format: str = "markdown"             # 内容格式
    
    # 类型特有数据（可选）
