# 347 — 标签历史归档实施

## 一、背景

346 号 §3.4（二期内容）：opportunity_tags_cache 无历史保留，P4 写标签时全量覆盖——无法跨日核查标签变化，L1.5 时间序列核查与 daily_change_summary（299 号自选监控 Part B）不可行。

## 二、现状

- **P4 写标签**：`_precompute_l2_labels`（data_daemon.py:1573）遍历全部活跃股 → `ECM.write_tags(code, tags)` 逐只 INSERT OR REPLACE INTO opportunity_tags_cache
- **覆盖机制**：同 (ts_code, tag_name) 的行被替换——历史标签丢失

## 三、实施内容

### 3.1 新增 `tag_history` 表（ECM._init_tables）

```sql
CREATE TABLE IF NOT EXISTS tag_history (
    ts_code TEXT, tag_name TEXT, tag_group TEXT, tag_value TEXT,
    confidence REAL, evidence TEXT, source TEXT, updated_at TEXT,
    PRIMARY KEY (ts_code, tag_name, updated_at)
)
```

复合主键：同股票同标签同日期覆盖（幂等），不同日期保留历史。

### 3.2 `write_tags` 同步归档（ECM.write_tags）

在 `with self._write_lock:` 内，每条标签 INSERT OR REPLACE INTO opportunity_tags_cache 后同步 INSERT OR REPLACE INTO tag_history——同一 commit 内，无额外锁开销。

### 3.3 读取网关

- **ECM `get_tag_history()`**：只读方法（ts_code/tag_name/start_date/end_date 过滤，ORDER BY updated_at, ts_code, tag_name）
- **DataManager `get_tag_history()`**：调用层只读网关（292 合规：routes/services 禁止直查 tag_history 表）

## 四、292 红线合规性

- ✅ 写入仅 ECM write_tags（P4 调用，daemon 采集层内）
- ✅ 读取经 DataManager 网关（调用层只读）
- ✅ 同一 _write_lock 保护，无新增并发风险
- ✅ 幂等复合主键，重复构建不累积

## 五、验证结果

| 项 | 结果 |
|---|---|
| 归档 | 3 只股票 × 83 标签 = 249 条 ✅ |
| 幂等 | 同日同标签再次写入仍 1 行（最终值覆盖）✅ |
| 网关读取 | DataManager 000001.SZ 83 条 ✅；过滤（tag_name/start_date）✅ |
| 测试 | 18 passed（s4/s2/chip）✅ |

## 六、效果

- **L1.5 跨日标签核查**：tag_history 每日随 P4 写标签自动归档，支撑标签突变检测（1 日跳变 2 档以上标记核查）
- **daily_change_summary**（299 号自选监控 Part B）：日度变化比较数据就绪
- **存储代价**：每日 5571 只 × 83 标签 ≈ 46 万行 × ~100B ≈ 4.6MB/日（可控）
