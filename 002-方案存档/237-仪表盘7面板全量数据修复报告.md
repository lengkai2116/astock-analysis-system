# 仪表盘7面板全量数据修复报告

## 问题概述

用户反馈仪表盘大量数据面板为空或显示错误数据，要求**启动浏览器自查**。经浏览器验证确认，7个数据面板中仅2个工作（四大指数、AI雷达），其余5个（成交额柱状图、资金流向、行业板块涨跌幅、行业板块资金流入、涨幅前十、策略信号汇总）全部失效。

## 根因分析

### 1. 后端代码修改后未重启 Flask 进程（最主要原因）

- `dashboard_service.py` 的 5 项修复于 08:11 写入磁盘
- Flask 进程（PID 4525）于 08:12 启动，加载的是**旧代码**
- 后端日志显示所有仪表盘端点返回 503（数据源不可用）
- 直接 curl 127.0.0.1:5001 验证不存在，因 sandbox 限制

### 2. 前端/后端字段名不匹配

| 位置 | 前端期望 | 后端返回 | 影响 |
|------|---------|---------|------|
| `loadSectorChanges()` | `d.data.length` | `d.data.sectors` | 行业板块涨跌幅图空白 |
| `loadSectorChanges()` | `v.pct_chg` | `v.change_pct` | 涨跌%显示为0 |
| `loadVolumeChart()` | `d.data` 为数组 | `d.data.days` 为数组 | 成交额柱状图不渲染 |
| `renderGainers()` | `s.pct_chg` | `s.change_pct` | 涨幅表显示为0.00% |
| `applySignals()` | `s.bullish` | `s.bullish_count` | 策略信号全"--" |
| `applySignals()` | `s.chanlun` | `s.chanlun_signal` | 缠论信号不显示 |
| `applySignals()` | `s.highconf` | `s.high_confidence`（对象） | 高置信度不显示 |
| `applySignals()` | `s.resonance`（字符串） | `s.resonance{label, detail}` | 共振信号显示"[object Object]" |

### 3. 数据同步管道整体断裂

- `DataManager` 缺少 `sync_daily_data_range()` / `sync_daily_basic()` / `sync_moneyflow()` / `sync_index_data()` / `sync_adj_factor()` 5个方法
- `RuleScheduler.register_daily_eval` 收到意外 `date` 关键字参数
- DuckDB 被 PID 5203 持有锁，备份库（`stock_cache.db.backup`）0 记录
- DB 最新交易日仅到 **2026-05-28**

### 4. Tushare 数据源问题

- `TushareProvider()` 在 `app_context` 外创建时，`_load_token()` 的 DB 回退路径静默失败 → `pro=None`
- Tushare `industry` API 返回"请指定正确的接口名"错误
- AKShare `get_sector_rankings()` HTTP 调用被沙盒屏蔽

## 修复内容

### 后端修复（`backend/app/services/dashboard_service.py`）

#### 全局：3处 `signal_summary` 字段名对齐

```
bullish_count  →  bullish
bearish_count  →  bearish
chanlun_signal →  chanlun
chip_signal    →  chip
high_confidence(对象) → highconf(字符串)
resonance(对象)       → resonance(字符串)
```

涉及方法：
1. `get_dashboard_summary()` 的 DB 降级路径（line 441-449）
2. `_screening_to_dashboard_summary()` 模拟数据路径（line 877-885）
3. `_aggregate_screening_results()` 真实聚合路径（line 1021-1029）

### 前端修复（`_ui-prototype/dashboard.html`）

1. **`loadSectorChanges()`:363-369** — `d.data.length` → `d.data.sectors?.length`，`v.pct_chg` → `v.change_pct`
2. **`loadVolumeChart()`:288** — `d.data.reverse()` → `d.data.days.slice().reverse()`
3. **`renderGainers()`:464** — `s.pct_chg` → `s.change_pct || s.pct_chg`
4. **后端重启** — `preview_stop` + `preview_start` 使代码生效

## 剩余问题

### P0 - 数据同步（阻塞6月/7月行情数据）

- DataManager 缺失 `sync_daily_data_range` 等5个方法
- RuleScheduler `daily_eval_job()` 收到意外 `date` 参数
- DuckDB 锁冲突（需 kill PID 5203）

### P1 - 数据质量

- 行业板块涨跌幅仅有6个行业（需更多 stock.industry 非空记录）
- 涨幅榜仅6只股票（DB daily_data 仅部分股票有数据）
- Tushare moneyflow 的行业映射无数据返回

### P2 - 前端优化

- `moneyflow ERR: signal timed out` 警告（不影响渲染）
- `"<!DOCTYPE"...` JSON 解析错误（某个端点返回 HTML 而非 JSON）

## 恢复数据同步建议

1. 修复 `DataManager` 添加 `sync_daily_data_range` 等方法
2. 修复 `RuleScheduler.register_daily_eval` 移除 `date` 参数或添加 `**kwargs`
3. Kill DuckDB PID 5203 释放锁
4. 调用 `POST /api/v3/system/schedule/sync-now` 触发完整数据同步
5. 验证 DB 中出现 6月/7月 daily_data
