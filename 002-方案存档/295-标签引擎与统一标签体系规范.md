# 标签引擎与统一标签体系规范

## 一、定位

所有策略引擎不再按管线划分，统一产出标签。标签进入统一标签池，供前端 Treemap 标签筛选、L4 个股诊断等消费。**标签是各引擎和前端之间的唯一接口。**

## 二、标签数据结构

```python
{
  "tag_name": "main_force_phase",     # 标签名（snake_case）
  "tag_group": "quality",             # 所属分组：direction/position/quality/environment
  "value": "building",                # 标签值（枚举 or 数值）
  "confidence": 0.82,                 # 置信度 0-1
  "evidence": [                       # 证据列表
    "TradingPhaseDetector -> building",
    "资金流向 -> 连续5日净流入",
  ],
  "source_engine": "PhaseDetection",  # 产出引擎
  "updated_at": "2026-07-23 17:30:00" # 计算时间
}
```

**signal_strength 计算逻辑**（在 P0.4 L2标注层中实现，约30行）：

```
基础分（0-10）：
  main_force_phase = building  → 7.0
                   = washing   → 5.5
                   = lifting   → 6.0
                   = distributing → 2.0
                   = unknown   → 3.0（退到估值维度）
  + valuation_level = extreme_low → +1.5
                    = low        → +1.0
                    = fair       → 0.0
                    = high       → -1.0
                    = extreme_high → -2.0
  + trend_alignment = up_aligned  → +1.0
                    = down_aligned → -1.0
  ⇒ 基础分范围控制在 0-10

置信度调整（×0.8 ~ ×1.0）：
  phase_confidence < 0.6 → ×0.8
  phase_confidence 0.6-0.8 → ×0.9
  phase_confidence > 0.8 → ×1.0

环境调整（×0.7 ~ ×1.0）：
  sentiment_phase = ebb → ×0.7
                  = climax → ×0.85
                  = recovery → ×1.0
                  = ice → ×0.9

signal_strength = 基础分 × 置信度调整 × 环境调整
```

**signal_strength 不是预测指标，而是现状聚合指标。** 它只回答"当前可见信号有多强"，不回答"未来会涨多少"。

## 四、冲突核查（标签间关系）

### 4.1 需关注的逻辑矛盾

| 矛盾关系 | 表现 | 含义 | L4仲裁处理 |
|---------|------|------|-----------|
| `main_force_phase: distributing` + `trend_alignment: up_aligned` | 主力出货但趋势向上 | 诱多风险 | 标记为矛盾信号，降低综合可信度 |
| `valuation_level: low/extreme_low` + `fina_health: fail` | 低估但财务可疑 | 价值陷阱 | 标记为"价值陷阱警告"，建议人工核实 |
| `upward_driver: emotion_driven` + `catalyst_event: lhb` | 情绪驱动+龙虎榜 | 游资炒作 | 标注为短线机会，附加"快进快出"提示 |
| `main_force_phase: building` + `fund_flow: 5d_outflow` | 建仓阶段但资金流出 | 阶段判定与资金流向矛盾 | 降低phase_confidence，标记为"可疑" |

### 4.2 正共振关系（双重确认）

| 共振关系 | 含义 | L4处理 |
|---------|------|--------|
| `buy_sell_point: buy_3` + `pattern_signal: breakout` | 缠论三买+形态突破 | 提升信号强度，标记为"共振确认" |
| `main_force_phase: building` + `fund_flow: 5d_inflow` + `trend_alignment: up_aligned` | 建仓+资金流入+趋势向上 | 三重确认，最高优先级 |
| `valuation_level: low/extreme_low` + `dividend_yield: >3%` | 低估+高股息 | 价值型机会，吸引长线资金 |

**结论**：不存在定义性冲突（两个标签描述同一件事但标准不同），但存在逻辑性矛盾。这些矛盾不是bug，而是L4仲裁层的信息输入来源。

每个新建引擎必须实现：

```python
class BaseTagEngine(ABC):
    @abstractmethod
    def compute_tags(self, ts_code: str, df: pd.DataFrame) -> list[dict]:
        """返回该引擎产出的所有标签"""
        pass
```

现有引擎（缠论/量价/筹码/BOCIASI 等）改造，在其现有输出基础上附加标签字段即可，不需要重写。改造方式见 301 号方案。

## 五、标签存储与查询

标签写入 `opportunity_tags_cache` 表：

```sql
CREATE TABLE opportunity_tags_cache (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts_code TEXT NOT NULL,
    tag_name TEXT NOT NULL,
    tag_group TEXT NOT NULL,
    tag_value TEXT NOT NULL,
    confidence REAL DEFAULT 1.0,
    evidence TEXT,       -- JSON array
    source TEXT,
    updated_at TEXT,
    UNIQUE(ts_code, tag_name, updated_at)
);
CREATE INDEX idx_tags_ts_code ON opportunity_tags_cache(ts_code);
CREATE INDEX idx_tags_name ON opportunity_tags_cache(tag_name, tag_value);
```

查询示例：

```sql
-- 查询所有"主力建仓+估值偏低"的股票
SELECT a.ts_code FROM opportunity_tags_cache a
JOIN opportunity_tags_cache b ON a.ts_code = b.ts_code
WHERE a.tag_name = 'main_force_phase' AND a.tag_value = 'building'
  AND b.tag_name = 'valuation_level' AND b.tag_value IN ('low', 'extreme_low')
  AND a.updated_at = '2026-07-23' AND b.updated_at = '2026-07-23';
```

### 6.2 对外展示名命名规范

- **长度**：不超过6个中文字符（悬停浮窗空间有限）
- **emoji前缀**：统一在代码层维护映射表，前端读取渲染
- **无术语**：禁止直接暴露 `main_force_phase`、`valuation_deviation` 等内部名
- **状态指示**：如无信号（`none`/`unknown`）不在展示中显示

### 6.3 筛选栏展示规则
