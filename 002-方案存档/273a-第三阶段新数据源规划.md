# 第三阶段新数据源接入规划

## 概述

272号方案§8.3 定义了三个阶段的数据完善路径。前两个阶段（Phase 0/1/2）聚焦于现有数据的优化和暴露，第三阶段需要**新增外部数据源**来填补关键维度空缺。

需要接入的三个数据领域：

| 领域 | 当前状态 | 所需数据 | 用途 |
|------|---------|---------|------|
| **情绪四阶段** | ❌ 仅有BOCIASI快慢线，缺市场级情绪指标 | 涨停家数/连板高度/炸板率 | 九层框架§7.10.1 |
| **财务排雷** | ❌ 无ROCE/速动比率/现金流检查 | 财报指标数据 | 九层框架§7.10.3 |
| **收益驱动** | ❌ 无收益分解管道 | 分钟级K线/收益分解 | 九层框架§7.8（暂缓） |

---

## 一、情绪四阶段数据接入

### 需求分析

当前 BOCIASI 快慢线可输出 BUY/WATCH/NEUTRAL/BEARISH 信号，但无法对应到"冰点/复苏/高潮/退潮"四阶段。四阶段定位需要全市场级别的核心阶梯数据。

### 所需数据

| 数据项 | 说明 | 来源建议 |
|--------|------|---------|
| 涨停家数 | 当日涨停股票数量（非ST） | Tushare `stk_limit` / AKShare `stock_zt_pool_em` |
| 跌停家数 | 当日跌停股票数量 | 同上 |
| 连板高度 | 当前最高连板数 | 需从涨停数据中计算 |
| 封板率 | 涨停封板成功比例 | 需计算 |
| 炸板率 | 涨停后开板比例 | 需计算 |
| 涨跌比 | 上涨家数/下跌家数 | Tushare daily 全市场聚合 |

### 实现路径

```
数据采集 → 全市场聚合 → 情绪指标计算 → 四阶段映射 → 注入 snapshot
```

1. **数据采集**：`akshare_collector.py` 中已有 `stock_zt_pool_em` 定时采集（Thread 5），可直接扩展
2. **全市场聚合**：新增 `MarketSentimentAggregator` 服务，聚合涨停数据计算指标
3. **四阶段映射**：

| 四阶段 | 判定条件 |
|--------|---------|
| 冰点期 | 涨停家数<20 且 空间龙头<3板 且 炸板率>60% |
| 复苏期 | 涨停家数20-50 且 空间龙头>3板 |
| 高潮期 | 涨停家数>80 且 连板晋级率高 且 封板率>75% |
| 退潮期 | 空间龙头断板 且 炸板率暴增 且 亏钱效应扩散 |

### 预估工作量

| 阶段 | 工作项 | 工作量 |
|------|--------|--------|
| 1 | 涨停数据采集扩展 | 小（现有管道扩展） |
| 2 | MarketSentimentAggregator | 中（~150行） |
| 3 | 前端展示情绪阶段 | 小 |

## 二、财务排雷数据接入

### 需求分析

九层框架§7.10.3 需要输出财务排雷结论（ROCE>15%、速动比率>0.8、经营现金流为正），当前系统有 `daily_basic` 但主要是行情数据，缺少完整财务指标。

### 所需数据

| 数据项 | 说明 | 来源建议 |
|--------|------|---------|
| ROCE | 已动用资本回报率 | Tushare `fina_indicator` 或 `fina_vip` |
| 速动比率 | (流动资产-存货)/流动负债 | Tushare `fina_indicator` |
| 经营现金流 | 经营活动现金流量净额 | Tushare `fina_vip` |
| 资产负债率 | 总负债/总资产 | Tushare `fina_indicator` |
| 大股东质押比例 | 质押股数/总股本 | Tushare `stk_holdernumber` |

### 实现路径

```
财报数据采集 → 指标计算 → 排雷规则引擎 → 排雷结论 → 注入 snapshot
```

1. **数据采集**：通过 Tushare `fina_indicator` 接口（需5000积分，当前已有）
2. **指标计算**：
   - ROCE = EBIT / (总资产 - 流动负债)
   - 速动比率 = (流动资产 - 存货) / 流动负债
3. **排雷规则引擎**（`chip_pre_filter.py:825-880` 已有雏形，可复用）：

| 检查项 | 通过标准 | 严重等级 |
|--------|---------|---------|
| ROCE | > 15%（连续3年） | 🔴 硬性 |
| 速动比率 | > 0.8 | 🔴 硬性 |
| 经营现金流 | 近3年至少2年为正 | 🟡 建议 |
| 资产负债率（非金融） | < 70% | 🟡 建议 |
| 大股东质押 | < 50% | 🟡 建议 |

### 预估工作量

| 阶段 | 工作项 | 工作量 |
|------|--------|--------|
| 1 | 财务数据采集管道 | 中（~200行，含Tushare配置） |
| 2 | 排雷规则引擎 | 小（复用 chip_pre_filter 逻辑） |
| 3 | 结论注入 snapshot | 小 |

## 三、收益驱动（暂缓）

收益驱动维度需要分钟级K线数据做收益分解（隔夜/温和/极端），当前系统无此数据管道，且工程量较大。

**建议**：在完成前两个数据源接入后，评估用户需求再决定是否启动。

---

## 四、实施顺序

```
第1优先：情绪四阶段（价值最高、用户感知最强）
  ↓
第2优先：财务排雷（数据成本低、规则清晰）
  ↓
第3优先：评估收益驱动需求（暂缓）
```

| 步骤 | 内容 | 前置 | 建议周期 |
|------|------|------|---------|
| 1a | 涨停数据采集扩展 | 无 | 1天 |
| 1b | MarketSentimentAggregator 实现 | 1a | 2天 |
| 1c | snapshot 集成 | 1b | 1天 |
| 2a | fina_indicator 数据采集 | 无 | 1天 |
| 2b | 排雷规则引擎搭建 | 2a | 1天 |
| 2c | snapshot 集成 | 2b | 1天 |

## 五、与现有系统的关系

| 方面 | 说明 |
|------|------|
| **数据结构** | 新增数据写入 `snapshot.sentiment` 和 `snapshot.risk` 区块，不修改现有字段 |
| **回滚** | 每个数据源独立接入，可单独回滚 |
| **前端** | 情绪阶段和排雷结论由 DeepSeek 在九层描述中体现，无需专门的前端卡片 |
