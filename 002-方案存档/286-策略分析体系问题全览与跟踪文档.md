## 二、整体工作流全景

### 2.1 个股策略分析请求流

```
前端请求 (POST /api/v3/strategy/analyze)
  │
  ├─ L1 风控检查 (DarwinRiskFilter)                  ← 可选
  │
  ├─ SignalComputationService.compute_for_stock()      ← 串行，实时
  │   ├─ 加载K线 + 扩展数据 (daily_basic/moneyflow/index/margin/...)
  │   ├─ 价格位置计算：乖离率/历史分位/BOLL带宽/均线粘合
  │   ├─ [L2] 筹码主力分析           ├─ [L3] 缠论走势分析
  │   ├─ [L3] 因子评分信号           ├─ [L3] 量价分析
  │   ├─ [L3] BOCIASI快线+慢线       ├─ 周线方向约束
  │   ├─ Vibe策略                    ├─ 新闻情绪修正
  │   └─ VAP支撑阻力 + 中枢强度
  │
  ├─ 组装五维格式 (chanlun/volume_price/chip/emotion/factor+vibe)
  ├─ [可选] Kronos推理 / DeepSeek九层描述
  └─ 返回 JSON
```

### 2.2 Data Daemon 策略信号预计算流

```
日终同步完成 → _run_precompute() (data_daemon.py:1213)
  ├─ 指标预计算 → indicator_ma/macd/other 宽表
  ├─ 策略信号预计算 → strategy_signals 表（无消费者，见 P1）
  ├─ [兜底] 全部失败 → _write_factor_signals() (简易因子信号)
  └─ PRESET_COMBOS因子预计算 → factor_cache
```

### 2.3 板块策略现状

```
当前无独立板块策略分析流程。"板块分析"散落四处：
1. Dashboard板块涨跌幅排行 → AKShare > DuckDB个股聚合
2. Dashboard板块资金流向排行 → DuckDB > Tushare
3. 五维卡4"情绪环境" → 仅显示股票行业名+个股涨跌幅
4. SectorRotationModel → 用个股收益率冒充板块数据（代码注释承认简化模型）
```

## 五、讨论决策记录

### 2026-07-21 讨论结论

**P1 性质确认**：
- 所有策略数据源均为盘后数据（daily_cache/moneyflow_cache等），15:30 后全部就绪 ✅
- Daemon的策略信号预计算(`_run_precompute`第二部分)不属于系统原始规划，是无主代码
- 全市场预计算耗时：5000只×~0.8s/只≈66分钟(单线程)，18小时窗口绰绰有余
- 选股L3的z-score归一化需要跨候选股统计分布，**不适用预计算**，保持实时

**渠道统一决策（P10）**：
- ✅ 统一核心计算层 `UnifiedStrategyCore`，两条渠道共用
- ❌ `_adjust_score_with_context` **直接剔除**（选股仅提供候选参考，个股多维+DeepSeek已覆盖）
- ✅ 选股L3因子评分迁移到 `FactorRegistry`，废弃 `_FACTOR_COMPUTERS`
- ✅ 选股L3丢弃筹码维度（L2已完成）和BOCIASI慢线
- ✅ z-score归一化+加权评分保留在选股适配器中，实时计算

**工作方式约定**：
- 286号文件为**总纲**，仅做问题摘要和交叉索引
- 每个问题逐一讨论细化后，分别建立独立专项方案存档（`28x-*.md`）
- 本文件标记各问题对应的专项方案编号
