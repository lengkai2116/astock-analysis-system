# 机会图谱三地图筛选功能修复方案

> **背景**：2026-08-07 核查发现机会图谱页面搜索框下的标签按钮（全部/低估/高成长/高股息/白马股…）大部分无效或语义错配，且三张地图共用同一套按钮与数据，未按地图区分（详见 `001-沟通记录/26-08-07沟通纪要.md` 001）。本方案将核查结果整理为问题清单与修复建议，基于**真实数据**重构三地图各自的筛选功能，给出前端与后端两侧的配置设计。**本方案仅存档，不修改任何代码。**

---

## 一、问题清单（基于真实数据实证）

### P0 级：按钮无效 / 语义错配（用户直接可见，最影响体验）

| # | 问题 | 实证证据 | 影响 |
|---|------|---------|------|
| P0-1 | **16 个标签按钮点击后恒为空**：高成长、北向增持、MACD金叉、涨停、科创板、创业板、沪深300、中证500、次新股、社保重仓、汇金持股、基金重仓、券商金股、高质押、ST、龙虎榜 | 前端 `_deriveTags()`（opportunity-treemap.html:701-721）只生成 7 个中文标签（低估/高股息/破净/主力建仓/资金流入/白马股/放量突破），上述 16 个无任何生成逻辑；实证模拟对线上 4995 只全量数据命中数 = 0 | 用户点击后地图清空/无变化，误以为功能损坏 |
| P0-2 | **「白马股」语义严重错配**：把"价格处于区间低位"当成白马股 | `_deriveTags` 用 `price_position === 'low_zone'` 推导白马股，实证命中 **3409 只（占全市场 68%）**，与本义（优质蓝筹）完全不符 | 价值地图/机会地图点击"白马股"得到 3400+ 只，完全失真 |
| P0-3 | **三地图共用同一套按钮与数据，未按地图区分** | 前端 `loadMarketData()` 仅请求 `mode=market`（:728），`setMode()`（:1490）只切换渲染逻辑**不重新拉数据**；30s 轮询（:1810）也只刷新 market。三地图展示同一份快照数据、同一套 21 个标签按钮 | 与 295/296 号方案"按模式分区"设计意图不符，价值/机会地图的筛选无意义 |

### P1 级：架构/配置缺口

| # | 问题 | 实证证据 | 影响 |
|---|------|---------|------|
| P1-1 | **前端中文标签与后端英文标签体系不对接** | 后端 `query_tags`（opportunity_atlas.py:66-96）走**英文键**（`main_force_phase:building` 等），实测 `mode=opportunity&tags=main_force_phase:building` 返回 1069 只；但前端标签是中文且**从不携带 tags 参数请求后端**，过滤纯在前端内存完成 | 后端 opportunity/value 模式的标签过滤路径（`_collect_ts_codes`）形同虚设，两端语义割裂 |
| P1-2 | **标签生成与按钮不对称** | `_deriveTags` 生成了"主力建仓/资金流入"两个标签，但 ALL_TAGS 按钮栏无对应按钮；而按钮栏 16 个标签无生成逻辑 | 用户无法使用本可用的标签，可用的按钮却空转 |
| P1-3 | **与 295/296 号方案设计偏离** | 295 号 §6.3 设计筛选栏为 15 个英文标签（ma_alignment/buy_sell_point/valuation_level/dividend_yield…）+6 折叠；296 号能力三设计预设场景「价值低估/主力跟庄/短线催化/做T机会」。前端实际为另一套 21 个中文标签 | 方案与实现脱节，后续维护无基准 |

### P2 级：遗留/低优

| # | 问题 | 实证证据 | 影响 |
|---|------|---------|------|
| P2-1 | 「放量突破」按钮为近似替代 | 映射自 `right_side_confirm='强确认'`（实证 315 只），非真实放量突破信号（快照表无 volume/price 突破字段） | 名称与语义不符，但数据非空，暂可用 |
| P2-2 | mock 数据残留 | `STOCK_DEFS`（:611-683，含 tags 数组的硬编码股票）仅定义处引用 1 次、0 处调用 | 死代码，易误导后续维护者 |

## 三、三地图筛选功能设计（前端+后端配置）

### 3.1 设计原则

1. **每个按钮必须映射到后端真实存在的字段**（上表 ✅ 项），杜绝空按钮与臆造标签；
2. **按地图模式分区**：市场/机会/价值三张地图各自持有专属标签按钮组（复用现有 `_applyModeControls` 的 `.mode-market-only`/`.mode-opportunity-only`/`.mode-value-only` 显隐机制，:1483-1488）；
3. **前端过滤 + 后端标签参数双通道**：前端默认对已下发快照做内存过滤（4995 只，性能无忧）；同时后端保留并完善英文 tags 参数路径，供机会/价值模式精确查询（可下沉为服务端过滤）；
4. **预设场景按钮保留**（价值低估/主力跟庄/短线催化/做T机会），其标签组合全部改为真实字段映射。

**定位**：回答"今天市场发生什么"——看涨跌分布、资金流向、活跃度。

### 4.1 标签按钮分组配置（核心改动）

将现有单一 `ALL_TAGS`（21 个中文标签）重构为**按模式分组的配置对象**：

// 替换现有 ALL_TAGS（:602-607）——按地图模式分组的真实标签按钮
const MODE_TAG_GROUPS = {

### 4.2 渲染与过滤逻辑改造

1. **`initTags()`（:809-827）**：按 `currentMode` 从 `MODE_TAG_GROUPS` 渲染对应按钮组；`setMode()` 切换时重新渲染（+`🏠 全部` 恒在首位）。
2. **`getFilteredStocks()`（:954-960）**：过滤逻辑从 `s.tags.includes(中文)` 改为**按 `key`+`values` 匹配真实字段**（`s[key]` 或 `s.tags[key]`），支持特殊规则（`__gt3__`/`__lt1__` 走数值比较）。
3. **`_deriveTags()`（:701-721）**：可删除（不再需要中文标签数组推导），或保留仅用于浮窗展示；过滤完全基于真实字段。
4. **`applyPreset()`（:937-943）**：预设组合改为 3.5 节真实映射（键值对数组，非中文标签数组）。
5. **`_applyModeControls`（:1483-1488）**：已具备按模式显隐机制，标签按钮组随模式切换重渲染即天然分区，无需改显隐逻辑。

### 4.3 搜索框与「全部」按钮

- 搜索框（:897-918）保持不变（已有效）。
- 「🏠 全部」按钮保留，点击清空当前地图的筛选。

## 五、后端配置设计

### 5.1 treemap API 标签参数完善（opportunity_atlas.py）

现有 `_collect_ts_codes()`（:66-96）已支持英文 tags 参数（`k:v,k:v` 逗号分隔、AND 语义、query_tags 实现）。**无需新增接口**，只需：

1. **前端开始携带 tags 参数**（机会/价值模式）：`/treemap?mode=opportunity&tags=main_force_phase:building,lifting` —— 打通前端按钮与后端 query_tags 路径（解决 P1-1）；
2. **value 模式数值条件支持**：`dividend_yield:>3`、`pb:<1` 属于快照表列数值比较，query_tags 走的是 opportunity_tags_cache 字符串匹配，无法直接处理。处理方案二选一：
   - **方案A（推荐，零后端改动）**：value 模式继续走前端内存过滤（前端已持有快照全字段，`:>3`/`:<1` 在前端比较），仅机会/市场模式可选走后端 tags；
   - **方案B（后端增强）**：`_collect_ts_codes` 增加对 `__gt3__`/`__lt1__` 特殊标记的数值过滤分支（直接 SQL 过滤快照表），工作量约 15 行。
3. **快照表字段补齐**（如选方案B/服务端过滤）：`treemap_snapshot` 表当前**无** `style_exposure`/`catalyst_event`/`time_rhythm` 列（在 opportunity_tags_cache 中）。若需后端直接过滤这些标签，需在 `get_treemap_snapshot_items()`（enhanced_cache_manager.py:2210）组装时 JOIN 标签表补齐；前端内存过滤则无需此步。

### 5.2 后端标签过滤实现示意（方案B，可选）

## 七、风险与说明

1. **覆盖率差异**：`fina_health` 中 suspicious 占 70%（3871/5533），"财务健康"按钮仅 1153 只属真实分布，非 bug；
2. **`sentiment_phase`/`capital_nature` 不可用**（全 climax / 全 unknown），本方案未采用，若后续补数据可扩展；
