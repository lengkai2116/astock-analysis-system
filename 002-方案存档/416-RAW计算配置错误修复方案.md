# 416-RAW计算配置错误修复方案

> **背景**：用户要求核对 415号方案（RAW 环节原始数据加工明细）中对应明细的计算配置是否正确。经运行时核查（FactorRegistry 因子解析 + 主库/分库表结构直查 + 实际落库数据），发现 **5 处错误配置**，本方案针对这些缺口制定修复计划。
> **范围**：仅修复 RAW 计算配置错误，不改变 RAW 架构与既有已落地修复。
> **方法**：先核查实际落地状态（已确认 5 处缺口），再逐项修复。

---

## 一、核查结论：5 处错误配置

| # | 严重度 | 环节 | 问题 | 实际状态 |
|---|--------|------|------|---------|
| 1 | HIGH | RAW-3 | `VOL_RATIO_20` 因子类不存在 → "20日换手率" 死映射 | 静默不预计算 |
| 2 | HIGH | RAW-3 | `VOLATILITY_20` 名称冲突 → academic 版覆盖 a_stock 版 | 用错因子版本 |
| 3 | HIGH | RAW-1 | `indicator_other` 表缺 BBI/ENE/九转列（414号R5 未落地实际库） | 整组静默丢弃 |
| 4 | MED | RAW-1 | `indicator_ma` 表缺 ma120/ma250 列（414号P1.2 未落地实际库） | 值被过滤丢弃 |
| 5 | MED | 前置 | `market_stats_cache` 表不存在（414号R8 未落地实际库） | 持久化失败 |

**根因**：`_init_tables()` 的 DDL 用 `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ADD COLUMN`，但实际库表结构为历史遗留（早于 414号 修复），且 daemon 当前未运行，迁移逻辑未触发；`_insert_from_df` 对分库缺列采用"过滤后写入"策略，静默丢弃新列不报错。

---

## 二、修复项

### 修复1（HIGH）— 补建 `VOL_RATIO_20` 因子类

**目标**：使 `FACTOR_NAME_MAP['20日换手率']='VOL_RATIO_20'` 映射生效，"20日换手率" 进入预计算。

**修改文件**：`backend/app/factors/builtin/a_stock.py`

在 `VOL_RATIO_10` 之后新增 `VOL_RATIO_20` 类，与既有 `VOL_RATIO_5/10` 同构（20日量比 = 当前成交量 / 20日均量）：

```python
class VOL_RATIO_20(BaseFactor):
    """20日量比"""
    name = "VOL_RATIO_20"
    name_cn = "20日换手率"
    category = "volume"
    subcategory = "volume_momentum"
    description = "当前成交量与20日平均成交量的比值"
    formula = "VOL_RATIO = Volume / MA(Volume, 20)"
    source = "A-Stock"
    source_detail = "A股常用因子"

    params = [FactorParam("period", 20, "int", 10, 60, "平均周期")]

    def calculate(self, data: pd.DataFrame) -> pd.Series:
        period = self.get_param("period")
        vol_ma = data['vol'].rolling(window=period).mean()
        return data['vol'] / vol_ma.replace(0, np.nan)
```

> 注：`name_cn` 沿用映射中文名"20日换手率"以保持语义一致；计算逻辑与 VOL_RATIO_5/10 同构（量比口径）。

**验证**：`get_factor_registry().get_factor_class('VOL_RATIO_20') is not None`；重启 daemon 后 `factor_cache` 出现 `VOL_RATIO_20` 因子。

---

### 修复2（HIGH）— 解决 `VOLATILITY_20` 名称冲突

**目标**：使 `VOLATILITY_20` 解析到 A股版（`a_stock.VOLATILITY_20`，source="A-Stock"），而非 academic 版。

**根因**：`a_stock.py` 与 `academic.py` 均定义 `name="VOLATILITY_20"`，registry 按 `os.listdir` 顺序加载，academic 后加载覆盖 a_stock 版。

**修改文件**：`backend/app/factors/builtin/academic.py`

将 `ACADEMIC_VOLATILITY_20` 的 `name` 改为唯一名 `"ACADEMIC_VOLATILITY_20"`（与类名一致），消除与 a_stock 版的冲突：

```python
class ACADEMIC_VOLATILITY_20(BaseFactor):
    """20日波动率（学术版）"""
    name = "ACADEMIC_VOLATILITY_20"   # 原 "VOLATILITY_20"，改为唯一名避免覆盖 a_stock 版
    name_cn = "20日波动率（学术）"
    ...
```

**理由**：`FACTOR_NAME_MAP` 将"20日波动率/低波因子"映射到 `VOLATILITY_20`，语义上应取 A股常用版（source="A-Stock"）。academic 版作为独立学术因子保留，但不再占用 `VOLATILITY_20` 名称。

**验证**：`get_factor_registry().get_factor_class('VOLATILITY_20').__module__` 含 `a_stock`；`VOLATILITY_20` 的 `source` 为 `"A-Stock"`。

---

### 修复3（HIGH）— `indicator_other` 表补 BBI/ENE/九转列

**目标**：主库 `stock_cache.db` 与分库 `compute_cache.db` 的 `indicator_other` 表补齐 `bbi/ene_upper/ene_lower/nine_buy/nine_sell` 列，使 `cache_indicators_wide` 的 `other_cols` 子集判断通过，BBI/ENE/九转正常落库。

**修改文件**：新增迁移脚本 `backend/scripts/migrate_indicator_columns.py`（或复用 `migration.py` 的 `migrate_table_structure`）

对主库 + 分库执行幂等 `ALTER TABLE ADD COLUMN`：

```python
# indicator_other 补列
for _col in ['bbi', 'ene_upper', 'ene_lower', 'nine_buy', 'nine_sell']:
    ALTER TABLE indicator_other ADD COLUMN {_col} REAL   # 已存在则跳过
```

**验证**：`PRAGMA table_info(indicator_other)` 主库/分库均含 5 个新列；`get_indicators_wide` 的 SELECT 不再报 `no such column: bbi`。

---

### 修复4（MED）— `indicator_ma` 表补 ma120/ma250 列

**目标**：主库 + 分库 `indicator_ma` 表补齐 `ma120/ma250` 列，使 MA120/MA250 预计算值正常落库。

**修改文件**：同上迁移脚本

```python
# indicator_ma 补列
for _col in ['ma120', 'ma250']:
    ALTER TABLE indicator_ma ADD COLUMN {_col} REAL   # 已存在则跳过
```

**验证**：`PRAGMA table_info(indicator_ma)` 主库/分库均含 `ma120/ma250`；`get_indicators_wide` 的 SELECT 不再报 `no such column: ma120`。

---

### 修复5（MED）— 创建 `market_stats_cache` 表

**目标**：主库 `stock_cache.db` 创建 `market_stats_cache` 表，使 `cache_market_stats` 持久化成功，daemon 重启后可恢复市场级统计。

**修改文件**：同上迁移脚本

```python
CREATE TABLE IF NOT EXISTS market_stats_cache (
    stat_date TEXT PRIMARY KEY,
    ma20_ratio REAL, turnover_percentile REAL, limit_ratio REAL,
    rsi_percentile REAL, erp_percentile REAL, margin_trend REAL,
    pe_percentile REAL,
    cached_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)
```

**验证**：`SELECT name FROM sqlite_master WHERE name='market_stats_cache'` 存在；`cache_market_stats` 写入成功。

## 三、迁移脚本设计（修复3/4/5 统一）

新增 `backend/scripts/migrate_indicator_columns.py`，幂等执行：

1. **主库** `data/duckdb/stock_cache.db`：
   - `indicator_ma` 补 `ma120/ma250`
   - `indicator_other` 补 `bbi/ene_upper/ene_lower/nine_buy/nine_sell`
   - 创建 `market_stats_cache`
2. **分库** `data/duckdb/compute_cache.db`：
   - `indicator_ma` 补 `ma120/ma250`
   - `indicator_other` 补 `bbi/ene_upper/ene_lower/nine_buy/nine_sell`

> 分库表结构由 `_insert_from_df` 从主库 SQL 自动建表，但**已存在**的分库表不会自动补列，需脚本显式 ALTER。脚本对所有列用 `PRAGMA table_info` 检查存在性，幂等可重复执行。

## 五、风险与回滚

- **风险**：迁移脚本对 600 万+ 行大表 `ALTER TABLE ADD COLUMN` 可能耗时（SQLite 加列不重写数据，仅改 schema，通常秒级）。建议在 daemon 停止时执行。
- **回滚**：新增列可保留（不影响既有数据）；`VOL_RATIO_20` 因子类与 `academic.py` 改名均为纯新增/改名，可安全回退。
- **兼容**：`get_indicators_wide` 的 SELECT 已含新列，补列后不再触发异常回退，符合红线 #3（读预计算产物）。
