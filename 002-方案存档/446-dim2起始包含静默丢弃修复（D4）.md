# 446 号 D4 — dim2 起始包含对静默丢弃

## 一、问题确认（445 §6.1 dim2 偏差 D4，代码级已核）

**知识库权威**（外部 wiki《缠论走势结构量化系统配置指南》L41-42）：
> "是否跳过前两根K线包含——大多数实现跳过（从第三根开始判断），但**跳过可能导致起始位置识别不完整，建议不跳过**"

**引擎现状缺陷**（`chanlun_strategy.py:KLineMerger._merge_once` L280-306，修复前）：
```python
result = [klines[0]]        # 直接以第一根为起点
direction = None
for i in range(1, len(klines)):
    current = klines[i]
    prev = result[-1]
    if KLineMerger.is_contained(prev, current):
        if direction is not None:    # ← 只有 direction 已确定才合并
            ... 合并 ...
        # ← direction is None 时：既不合并不 append → 该 K 线被静默丢弃
    else:
        if direction is None:
            ...确定 direction...
        result.append(current)
```

**矛盾机制（实证）**：当**起始两根 K 线 `klines[0]` 与 `klines[1]` 有包含关系**时 → 进入 `if is_contained` 分支，但 `direction is None`，**既不合并也不保留 → `klines[1]` 被静默丢弃**。因 `result[-1]` 恒为 `klines[0]`，之后所有与第一根仍有包含的 K 线也都被丢弃，直到出现不包含的一根才建立 direction——**起始位置识别不完整**，正违反知识库「不跳过前两根」。

> 注：引擎确实"从第 2 根开始判断"（未像多数实现那样直接跳过前两根），但 `direction is None` 守卫使起始包含对**被丢弃而非合并**——这是 445 抓到的更深一层，未见于 362/359（它们仅核对"从第几根开始判断"判 ✅）。

## 二、修复方案（用户拍板 2026-09-17：修复起始包含合并）

`_merge_once` 中：当 `direction is None` 且起始两根包含时，**先按与 else 分支相同的锚定规则确定方向，再合并**（而非丢弃）：

```python
if KLineMerger.is_contained(prev, current):
    if direction is None:
        # 446号D4：起始包含且方向未定——先确定方向再合并，禁止静默丢弃
        if current.high > prev.high:
            direction = 'up'
        elif current.high < prev.high:
            direction = 'down'
        else:
            direction = 'up' if current.low >= prev.low else 'down'
    if direction == 'up':
        new_high = max(prev.high, current.high)
        new_low = max(prev.low, current.low)
    else:
        new_high = min(prev.high, current.high)
        new_low = min(prev.low, current.low)
    merged = KLine(idx=prev.idx, ...)
    result[-1] = merged
```

- 方向锚定规则与 `else`（不包含起方向）分支完全一致，语义统一、无新算法。
- 消除了 `direction is None` 时起始包含对的静默丢弃，起始 K 线被正确合并保留。
- **非起始部分合并逻辑完全不变**（direction 已定后的行为与修复前相同）；起始不包含/单根等路径也原样保留。

## 三、影响评估（445 约束：不破坏分析引擎判定逻辑/阈值/窗口）

- **判定语义变化**：仅影响**起始位置**的 K 线合并——原来是丢弃（丢失 1-3 根起始 K 线），现在是合并保留。对齐知识库「不跳过前两根」（起始识别完整）。
- **阈值/计数/算法不变**：合并规则（up=max/max、down=min/min）不变；`merge_depth`、分型 0.5%、笔/段/中枢判定不动。
- **尾部/主体笔序列**：不受影响（direction 已定后的行为一致）。
- **消费链**：KLineMerger.merge 供 ChanlunAnalyzer（RAW data_daemon + SIG dim2）共用，修复对齐两路径的起始识别。
