### 1.2 页面加载流程

```
页面加载（默认显示空状态）
  │
  ├─ 用户点击「⚡ 执行筛选」
  │    └→ POST /api/v3/screener/run
  │         └→ 返回 pipeline_counts + results[]
  │              ├→ 更新 Pipeline横条通过数
  │              ├→ 渲染筛选结果表
  │              └→ 缓存结果供详情弹窗复用
  │
  ├─ 用户勾选/取消策略
  │    └→ 前端局部状态更新（无后端调用）
  │
  ├─ 用户调整权重
  │    └→ 前端权重计算（adjWeight）+ 归一化逻辑
  │
  ├─ 用户点击详情弹窗
  │    └→ 复用 run 结果中该股票的 strategy_detail
  │
  ├─ 用户点击「+ 创建新策略」(Vibe Coding)
  │    └→ POST /api/v3/llm/generate-strategy
  │         └→ 返回 AI 生成的策略代码
  │
  └─ 页面加载时并行获取
       ├→ GET /api/v3/factors/combinations
       │     └→ 动态渲染因子组合复选框
       └→ GET /api/v3/strategies/vibe
             └→ 动态渲染Vibe Coding策略卡片（**须从策略模板同步**）
```

## 2. API端点技术规格

### 2.1 `POST /api/v3/screener/run` — 执行完整Pipeline筛选

**用途:** 执行 L1→L2→L3 全流程筛选
**所属区块:** 全部三层
**优先级:** P0
**HTTP方法:** POST

#### 请求参数

```json
{
  "params": {
    "layers": ["l1", "l2", "l3"],
    "strategy_checks": {
      "chanlun": true,
      "volume_price": true,
      "factor": true,
      "vibe": false
    },
    "vibe_strategies": [                   // 勾选的Vibe策略（从策略模板动态同步）
      {"id": "vibe_002", "name": "业绩超预期+MACD金叉"},
      {"id": "vibe_005", "name": "我的短线策略"}
    ],
    "factor_combinations": [
      {"id": "combo_001", "name": "经典动量组合"},
      {"id": "combo_002", "name": "量价突破组合"},
      {"id": "combo_005", "name": "我的短线策略"}
    ],
    "weight_config": {
      "chanlun": 35,
      "volume_price": 30,
      "factor": 25,
      "vibe": 10
    },
    "min_score": 30,
    "vibe_prompt": null
  }
}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
|:-----|:-----|:-----|:-----|:------|
| `params.layers` | string[] | 否 | `["l1","l2","l3"]` | 执行层序 |
| `params.strategy_checks.chanlun` | boolean | 否 | true | 是否启用缠论策略 |
| `params.strategy_checks.volume_price` | boolean | 否 | true | 是否启用量价策略 |
| `params.strategy_checks.factor` | boolean | 否 | true | 是否启用多因子评分 |
| `params.strategy_checks.vibe` | boolean | 否 | false | 是否启用Vibe Coding策略 |
| `params.strategy_checks.vibe` | boolean | 否 | false | 是否启用Vibe Coding策略 |
| `params.vibe_strategies[]` | array | 否 | [] | 勾选的Vibe策略列表（**须从策略模板动态同步**），每项含`id` + `name` |
| `params.factor_combinations[]` | array | 否 | [] | 选中的因子组合ID列表（**须从因子管理动态同步**）|
| `params.weight_config` | object | 否 | {} | 策略权重配置（需归一化到100%） |
| `params.min_score` | int | 否 | 30 | 最低通过阈值 |
| `params.vibe_prompt` | string/null | 否 | null | Vibe Coding自然语言描述（启用Vibe时必填） |

| 字段 | 类型 | 说明 | 前端使用 |
|:-----|:-----|:------|:---------|
| `run_id` | string | 本次运行ID | — |
| `pipeline_counts.l1_passed` | int | L1通过数 | Pipeline横条 `4,650 只` |
| `pipeline_counts.l2_passed` | int | L2通过数 | Pipeline横条 `1,240 只` |
| `pipeline_counts.l3_passed` | int | L3通过数 | Pipeline横条 `23 只` |
| `results[].ts_code` | string | 股票代码 | 结果表+列 |
| `results[].name` | string | 股票名称 | 结果表+列 |
| `results[].price` | number | 最新价 | 结果表 `¥12.34` |
| `results[].score` | int | 综合评分(0-100) | 结果表评分列，渲染为`tag-bullish/watch/neutral` |
| `results[].grade` | string | 评级代码 | 映射为评级文字 |
| `results[].grade_label` | string | 评级文字 | 结果表评级列 |
| `results[].triggers` | string[] | 触发信号标签 | 结果表触发信号列 |
| `results[].in_watchlist` | boolean | 是否已在自选 | ⭐/☆ 标记 |
| `results[].strategy_detail` | object | 各策略细分评分 | 详情弹窗渲染 |
| `results[].reasons` | string[] | 选股理由列表 | 详情弹窗渲染 |

#### 评分等级映射

| 分数区间 | `grade` | `grade_label` | tag类名 |
|:---------|:--------|:--------------|:--------|
| 85-100 | S | 🔥 强烈推荐 | `tag-bullish` (#EF4444) |
| 75-84 | A | ✅ 推荐 | `tag-bullish` (#EF4444) |
| 65-74 | B | 👀 关注 | `tag-watch` (#F59E0B) |
| 50-64 | C | ⚠️ 谨慎 | `tag-watch` (#F59E0B) |
| <50 | D | ❌ 回避 | `tag-neutral` (#94A3B8) |

#### 综合评分计算规则

```
综合评分 = min_score_threshold (30) + 加权分数

加权分数 = weight_chanlun × chanlun_wscore
          + weight_vp × vp_wscore
          + weight_factor × factor_wscore
          + weight_vibe × vibe_wscore

其中 weight_xxx 为前端传送的权重配置（需归一化到100%）
     xxx_wscore 为各策略引擎输出的归一化分数(0-100)
```

#### 因子组合评分规则（C方案）

```
factor_wscore = sum(组合_i.评分 × 组合_i.权重) / sum(组合_i.权重)
                  组合权重见因子管理配置
                  未勾选的组合不参与计算
```

#### 数据来源

- L1: 后端 `screener.py` 风险层（`chanlun_strategy.py` / `volume_price_strategy.py` / `FactorRegistry`）
- L2: 主力识别层（筹码/ASR/资金流）
- L3: 策略验证层（多策略共振评分）

#### 更新频率

用户触发，每次点击「执行筛选」实时计算

#### 缓存策略

- 结果缓存至下次筛选或过期（默认TTL 30分钟）
- 缓存key: `screener:run:{run_id}`

#### 降级方案

- 单层失败（如L2因数据源不可用）：跳过该层，返回其他层结果 + 标注"L2数据暂缺"
- 全不可用：返回 `data: null` + `message: "Screener引擎暂不可用"`

**用途:** 保存用户自定义权重配置
**优先级:** P2
**HTTP方法:** POST

```json
{
  "status": "active",
  "weights": {
    "chanlun": 35,
    "volume_price": 30,
    "factor": 25,
    "vibe": 10
  },
  "auto_normalize": true
}
```

#### 响应格式

```json
{
  "code": 0,
  "data": {
    "saved": true,
    "normalized_weights": {
      "chanlun": 35,
      "volume_price": 30,
      "factor": 25,
      "vibe": 10
    }
  }
}
```

**权重归一化逻辑（后端实现）：**

```
如果 auto_normalize == true && sum(weights) != 100
  → 按比例缩放至总和100%
  例: {缠论:50, 量价:20, 因子:20, Vibe:20} → sum=110
  → 归一化: {缠论:45, 量价:18, 因子:18, Vibe:18} → sum=99 ≈ 100
```

> **数据关联：** 当用户在Vibe Coding弹窗中创建新策略（→ `POST /api/v3/llm/generate-strategy` 并点击"+ 添加策略"）时，策略应保存到策略模板的后端数据库。选股系统 L3 通过 `GET /api/v3/strategies/vibe` 动态读取，新增的策略才可在后续筛选中被勾选。此流程与因子组合的"因子管理→选股系统"双向同步关系一致。

#### 数据来源

策略模板（strategy-templates）页面的后端策略库，需确保：
- Vibe Coding生成的自建策略自动入库
- 用户从策略模板删除的策略，选股系统不可见
- 不允许硬编码Mock策略名称（与166号§4.1.1因子组合规则同等约束）

#### 更新频率

每次页面加载时获取（或缓存至策略模板变更后失效）

#### 缓存策略

- TTL: 5分钟
- Redis key: `strategies:vibe`

#### 降级方案

- 策略模板不可用 → 返回最近一次缓存
- 无缓存 → 返回空数组，前端隐藏Vibe Coding区域，显示"Vibe策略暂不可用"

### 2.8 `POST /api/v3/llm/generate-strategy` — Vibe Coding策略生成

**用途:** 用户输入自然语言描述，AI生成策略代码
**所属区块:** 右栏Vibe Coding创建弹窗
**优先级:** P2
**HTTP方法:** POST

#### 请求参数

```json
{
  "prompt": "选出业绩预告超预期且MACD刚刚金叉的股票",
  "language": "python",
  "max_tokens": 1024
}
```

| 字段 | 类型 | 必填 | 说明 |
|:-----|:-----|:-----|:------|
| `prompt` | string | ✅ | 自然语言策略描述 |
| `language` | string | 否 | 目标语言，默认python |
| `max_tokens` | int | 否 | 生成代码最大长度 |

#### 响应格式

```json
{
  "code": 0,
  "data": {
    "code": "def custom_strategy(data):\n    \"\"\"\n    选出业绩预告超预期且MACD刚刚金叉的股票\n    \"\"\"\n    score = 0\n    # MACD金叉检测\n    if data[\"macd_diff\"].iloc[-1] > data[\"macd_dea\"].iloc[-1]:\n        score += 40\n    # 业绩预增检测\n    if data[\"yoy_profit\"].iloc[-1] > 50:\n        score += 30\n    return score",
    "language": "python",
    "generated_at": "2026-06-30 15:32:00",
    "tokens_used": 256
  }
}
```

| 字段 | 说明 | 原型引用 |
|:-----|:------|:---------|
| `code` | AI生成的策略代码 | L358-371 `vibe-code-area` 显示区域 |
| `language` | 代码语言 | L359 |
| `generated_at` | 生成时间 | — |

#### 数据来源

DeepSeek LLM（接入174号方案LLM Wiki能力），后端需实现 LLM 调用 → 策略代码生成管道

#### 策略保存流程

```
用户输入描述 → 点击「🤖 AI 生成」
    ↓ POST /api/v3/llm/generate-strategy
    ↓ 返回代码
用户输入策略名称 → 点击「+ 添加策略」
    ↓ 前端：添加到 Vibe Coding 卡片列表
    ↓ 本地存储或 POST /api/v3/strategies （保存到策略模板）
    ↓ 提示：已保存到策略模板 → 用户自建策略
```

## 6. 错误处理矩阵

| 故障场景 | 受影响区块 | 前端表现 | 后端降级 |
|:---------|:----------|:---------|:---------|
| Screener引擎无输出 | 全部 | 空状态保持不变，显示提示 | HTTP 200 + `results: []` |
| L1通过为0 | Pipeline横条 | 显示"0 只" | 正常返回，空列表 |
| 因子管理不可用 | 左栏因子组合 | 隐藏组合区+"因子配置暂不可用" | `combinations: []` |
| LLM不可用 | Vibe Coding生成 | "🎯 AI暂不可用"降级提示 | HTTP 503 |
| 用户权重未归一化 | 中栏 | 前端js自动归一化（请求前） | 后端二次归一化校验 |
| 单只股票数据异常 | 结果表 | 该行标记"数据异常"灰显 | 该股票跳过不参与排序 |
| 结果超过1000只 | 结果表 | 分页或虚拟滚动（原型未实现） | `limited: true` + `total_count` |
