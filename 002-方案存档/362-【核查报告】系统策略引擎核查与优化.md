## 四、问题详细根因分析

### 问题1：缠论中枢100%无输出（5/5股票）

**严重度**：🔴 高

**现象**：ChanlunAnalyzer.analyze() 在5只不同行业股票上全部未产出中枢数据。

**根因**：`min_width` 绝对值门槛过高 + 配置未透传

**具体位置**：chanlun_strategy.py 第2157行 + 第1154行

```python
# 第2157行：创建中枢查找器时，min_width 未传入
self.bi_zs_finder = BiZhongshuFinder(
    min_bi_count=self.config.get('min_bi_count', 3),
    # ← min_width 未传入！使用默认值
)

# 第1154行：BiZhongshuFinder 默认值
def __init__(self, ..., min_width=0.5):
    # min_width = 0.5元（绝对价格差，非百分比）
```

**中枢生成的完整链路**（chanlun_strategy.py 第2184-2229行）：

```
analyze() → _preprocess(df) → kline_merger.merge() → filter_limit_klines()
  → fractal_detector.detect() → stroke_builder.build()
  → bi_zs_finder.find() → 中枢输出
```

**中枢被过滤的两个断点**：

| 断点位置 | 过滤条件 | 说明 |
|---------|---------|------|
| 第2188行 | `overlap_low > overlap_high` | 三笔无重叠区间 → 跳过 |
| 第1194行 | `high - low < self.min_width`（< 0.5元） | 重叠宽度不够 → 跳过 |

**以000001.SZ为例**：现价11.40元，min_width=0.5元意味着三笔重叠区间宽度必须≥0.5元（占价格4.4%）。银行股低波动行情下，笔的高低点差异很小，重叠区间宽度很可能<0.5元，全部被过滤。

**其他加剧因素**：
- `fx_check='strict'`（第315行）要求分型中间K线**同时**满足high和low条件，比`totally`更严格，进一步减少分型数量
- 涨跌停过滤（第267行）可能移除部分K线
- 分型不足时（第2209行 `len(fractals) < 4`）直接返回error
- 笔不足时（第2225行 `len(strokes) < 3`）直接返回error

**影响**：结构位置维度的"价格vs中枢"子维度在当前配置下**完全不可用**。

**修复方向**：
1. 增加`min_width`参数支持百分比阈值（如`min_width_pct=0.02`即2%），使低价股也能正常生成中枢
2. 在配置中透传`min_width`参数，允许用户根据股票类型调整
3. 降低`fx_check`严格度（从strict改为totally）

### 问题2：支撑阻力resistance低于现价（2/5股票）

**严重度**：🔴 高

**根因**：`min(hi60, ma60)` 逻辑在上涨趋势中必然失效

**具体位置**：advice_builder.py 第99-101行

```python
resistance = hi60                    # 第99行：60日高点
if hi60 is not None and ma60 is not None:
    resistance = min(hi60, ma60)     # 第101行：取两者较小值
```

**逻辑缺陷分析**：

| 场景 | hi60 | ma60 | 现价 | resistance | 是否合理 |
|------|------|------|------|-----------|---------|
| 上涨趋势（000001.SZ） | 11.66 | 10.91 | 11.40 | **10.91** | ❌ 低于现价 |
| 下跌趋势（000858.SZ） | 85.11 | 85.11 | 72.09 | 85.11 | ✅ 高于现价 |
| 横盘震荡（601318.SH） | 54.34 | 54.34 | 52.14 | 54.34 | ✅ 高于现价 |

**规律**：当股票处于**上涨趋势**（现价>ma60）时，`min(hi60, ma60)` 取ma60，但ma60<现价，导致阻力位低于现价。

**影响链路**：

```
resistance < price
  → dist_to_resistance_pct 为负值（第123行）
  → risk_reward = abs(负/负) = 正值（虚假盈亏比，第124行）
  → advice_builder.py:195 主决策入口 rr<1 降级逻辑可能被绕过
  → status_engine.py:592 盈亏比门禁失真
```

**支撑位回退保护**（已有）：

```python
# 第113-115行：支撑位有回退保护
if support is not None and price is not None and support >= price:
    support = lo60  # 近端位高于现价时回退60日低点
```

**阻力位缺少类似保护**（bug所在）：

**修复方向**：

```python
# 当前（缺陷）
resistance = min(hi60, ma60)

# 修复：ma60<现价时ma60是支撑不是阻力
if ma60 is not None and ma60 > price:
    resistance = min(hi60, ma60)  # ma60>现价时取较小者（更贴近的阻力）
else:
    resistance = hi60  # ma60<现价时直接取60日高点
```

**调用方影响**：
- `advice_builder.py:195` — 主决策入口，rr<1 时将 state 降级为 wait
- `status_engine.py:592-593` — 盈亏比门禁，rr<rr_gate 时降级
- 两处都依赖 resistance 代表"现价上方的压力位"，resistance < price 时逻辑全部失效

### 问题3：factor_cache测试路径错误

**严重度**：🟡 中

**现象**：测试脚本连接 `factor_cache.db` 失败（no such table）。

**根因**：factor_cache表定义在 `stock_cache.db`（ECM的主数据库，enhanced_cache_manager.py:559）中，但测试脚本尝试连接独立的 `factor_cache.db` 文件。

**修复方向**：测试脚本应通过 `ecm.db_path` 连接正确的数据库。

### 问题4：筹码asr/cyqkl字段全部为None（5/5股票）

**严重度**：🟡 中

**现象**：pre_feat_cache中chip组的asr和cyqkl字段全部为None。

**根因**：两层字段映射断裂

**第一层断裂**（data_daemon.py:2520-2527）：

```python
chip_tags = cde.get_tags(df)          # ChipDistributionEstimator.get_tags()
features['chip'] = {k: v for k, v in (chip_tags or {}).items()
    if k in ('chip_position', 'chip_concentration', 'asr', 'cyqkl')}
# ↑ asr/cyqkl 在 get_tags() 的返回值中不存在！
```

`ChipDistributionEstimator.get_tags()`（chip_distribution_service.py:165-192）**只返回chip_position和chip_concentration**，不计算asr和cyqkl。白名单中的asr/cyqkl永远匹配不到。

**第二层断裂**（data_daemon.py:2541-2556）：

```python
_depth.update(extract_chip_deep_tags(code))  # 这里确实能算出 asr/cyqkl
features['depth'] = {
    'hold_float_ratio': _depth.get('hold_float_ratio'),
    'turnover_rate': _depth.get('turnover_rate'),
    # ... 仅8个字段，asr/cyqkl 被排除在外
}
```

`extract_chip_deep_tags()` 通过 `ChipIndicators.calculate_all_indicators()` **确实能算出asr和cyqkl**，但depth组的输出白名单硬编码了8个字段，**asr/cyqkl不在其中**。

**结果**：asr/cyqkl在chip组中因get_tags()不返回而为空，在depth组中因白名单排除而被丢弃。

**修复方向**：
- **方案A**：在chip组中改为调用 `ChipIndicators.calculate_all_indicators()` 计算真正的asr/cyqkl
- **方案B**：在depth组的白名单中补上asr/cyqkl字段

## 六、验证结论

| 维度 | 代码核查结论 | 模拟验证结论 | 一致性 |
|------|------------|------------|:------:|
| 价格vs中枢 | 计算精度高（B+ 85%） | 100%无输出 | ❌ 不一致 |
| 价格vs均线 | 计算精度高（B 80%） | 5/5正常 | ✅ 一致 |
| 价格vs支撑阻力 | 质量不足（D 45%） | 2/5异常 | ✅ 一致 |
| 价格vs筹码 | 计算质量高（B 78%） | asr/cyqkl缺失 | ⚠️ 部分一致 |
| 价格vs指标 | 计算精度高（B- 75%） | RSI可用，MACD/KDJ缺失 | ⚠️ 部分一致 |

**关键发现**：
1. **代码核查与模拟验证存在不一致**——缠论中枢在代码层面"有完整实现"（B+级），但在实际运行中100%无输出。这说明**代码能力≠运行能力**，必须通过模拟验证才能发现真实问题。
2. **支撑阻力的D级评分完全印证**——不仅是"无统一输出"，更存在计算逻辑本身的bug。
3. **质量评估必须以模拟验证为准**，代码级核查只能确认"有没有"，不能确认"好不好"。

> "缠论数据的计算，采用逐Bar方式进行计算，根据当前Bar变化，计算并合并缠论K线，再计算分型、笔、线段、中枢、走势段、背驰、买卖点数据；再根据下一根K线数据，更新以上缠论数据。"
>
> "这种计算方式，可以很方便实现增量更新，process_klines方法可以一直喂数据，内部会判断，已处理的不会重新计算。"

### 7.2 LLM Wiki精度提升研究

基于[[缠论走势结构量化系统配置指南]]、[[缠论中枢量化]]、[[K线包含处理的量化实现]]、[[缠论量化参数设置指南]]、[[缠论中枢量化]]。

#### 当前系统配置 vs Wiki推荐配置

| 配置项 | 当前值 | Wiki推荐值 | 差异 | 影响 |
|--------|--------|-----------|------|------|
| fx_check | strict | 短线totally/中长线strict | 短线过严 | 分型过滤过多 |
| fractal_threshold_pct | 0 | 0.5% | 未过滤弱势分形 | 噪声分型多 |
| min_klines | 6 | 短线3/中长线5 | 短线偏高 | 笔频率偏低 |
| min_width | 0.5元（绝对值） | **应为百分比（2%）** | 🔴 绝对值不适用 | 中枢全被过滤 |
| 背驰方法 | 仅面积法 | 面积法+力度法双验证 | 缺力度法 | 信号可靠性不足 |
| 级别递归 | 无 | 30min/5min/1min三级 | 🔴 缺失 | 无法多周期联立 |
| 参数平原 | 无 | PBO<0.3+CSCV验证 | 🔴 未验证 | 参数稳健性未知 |

#### Wiki推荐的精度提升7项措施

**措施1：分型识别优化**
- 短线fx_check改为`totally`（更宽松，减少漏判）
- 增加fractal_threshold_pct=0.5%（过滤弱势分形）

**措施2：笔划分优化**
- 短线min_klines=3（宽笔）+ min_amplitude_pct=0.01（1%振幅过滤）
- 成笔后确认K线数=3（当前未实现）

**措施3：中枢参数优化**
- min_width从绝对值0.5元改为百分比（如0.02即2%），适配不同价位
- 保留最新三个中枢状态动态跟踪
