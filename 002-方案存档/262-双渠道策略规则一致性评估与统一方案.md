# 双渠道策略规则一致性评估与统一方案（修订版）

> 对应沟通记录：2026-07-11 第2轮 — 策略架构澄清与全方案修订
> 参考知识库：LLM Wiki — 筹码分布分析（主力视角）、K线形态跨策略融合框架、风险剔除逻辑体系

---

## 一、策略架构总纲

### 1.1 核心理念

> **策略后台的设定目标是真实有效，不能为了方便核算而进行简化。**

这意味着所有策略规则必须忠实于其原本的逻辑，不能因为性能或实现便利而裁剪。渠道一（选股系统）和渠道二（个股策略分析）共享同一套策略规则引擎，区别仅在于输出方式——排序评分 vs 现状解读。

### 1.2 双渠道定位

| 维度 | **渠道一：选股系统（Screener）** | **渠道二：策略分析（Strategy Analyze）** |
|:-----|:-------------------------------|:----------------------------------------|
| **功用** | **筛选** — 从全市场快速选出有机会的股票 | **解读** — 对具体股票分析当前处于什么状态 |
| **输出形态** | 数值评分 + 等级，用于排序 | 现状描述 + 证据链，用于理解 |
| **性能要求** | 批量化（千只级，秒级响应） | 深度化（单只，可接受秒级延迟） |
| **策略选择** | 用户可选参与哪些策略（L1~L3全部可配置） | 用户可选参与哪些策略（同一套选项） |

### 1.3 策略分类体系（修正后）

根据用户确认，策略的整体类别为 **三层四类**：

```
┌─────────────────────────────────────────────────────────┐
│                    L1：风控策略                           │
│   DarwinRiskFilter — 风险排查（硬性否决规则体系）        │
│   · ST/PT剔除、流动性过滤、连续亏损过滤、高估值过滤     │
│   · 大盘环境熔断检查                                     │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│              L2：主力筹码策略                              │
│   结合资金流向 + 筹码分布 + 主力行为的一个统一策略        │
│   · 大单资金流向（主力买卖力度、连续性、占比）            │
│   · 筹码分布计算（ASR/CYQKL/SSRP/筹码峰/成本分布）       │
│   · 股东户数集中度                                        │
│   · 主力操盘四阶段识别（建仓/洗盘/拉升/出货）            │
│   · 散户反向指标                                          │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│              L3：系列策略                                  │
│                                                          │
│   ① 缠论                                                │
│      K线包含处理 → 分型 → 笔 → 线段 → 中枢 → 买卖点    │
│                                                          │
│   ② 量价                                                │
│      四阶段分析链：阶段检测 → 量态分析 → 量价关系 → 信号 │
│                                                          │
│   ③ 因子组合（多个小型因子组合构成）                    │
│      · 动量类：MOM_20、REV_5                             │
│      · 情绪类：（原BOCIASI归入此类，作为因子组合之一）   │
│      · 质量类：ROE、毛利率、资产负债率                   │
│      · 波动类：ATR、VOLATILITY_20                        │
│      · 资金类：大单净买入、换手率变化                     │
│      · 其他预设组合共12组（PRESET_COMBOS）               │
│                                                          │
│   ④ Vibe策略（多种策略，包括用户自建）                 │
│      · 系统预设Vibe策略（趋势通道、情绪周期等）          │
│      · 用户AI生成策略（生产环境持续扩展）                 │
└─────────────────────────────────────────────────────────┘
```

### 1.4 统一原则

**渠道不统一，规则要统一。** 两个渠道的同一策略使用相同的计算规则，只是输出方式不同：

| 策略 | 渠道一输出 | 渠道二输出 |
|:-----|:----------|:----------|
| L1 风控 | 是否通过（通过/不通过） | 未通过原因说明 |
| L2 主力筹码 | 0-10分 | 主力阶段 + 筹码结构 + 证据链 |
| L3 缠论 | 0-10分 | B/S点 + 级别 + 置信度 + 建议 |
| L3 量价 | 0-10分 | 量价关系 + 阶段 + 信号 |
| L3 因子组合 | 0-10分（组合加权） | 各因子值 + 解读 |
| L3 Vibe | 加分（0-5分） | AI生成策略分析文本 |

**所有策略在两个渠道中均可由用户选择是否参与**（选股系统中通过权重滑条和勾选框，策略分析中通过策略开关面板）。

## 二、策略规则一致性评估

以下逐一对比每个策略在两个渠道中的计算规则是否一致。

### 2.1 L1 风控策略（Risk Control）

| 对比项 | 渠道一 | 渠道二 |
|:-------|:-------|:-------|
| **位置** | `screener.py:24` `DarwinRiskFilter.filter()` | —（渠道二目前无独立L1，需补充） |
| **风控类** | `DarwinRiskFilter` + `MultiLevelRiskControl` + `FinancialRiskFilter` | 无对应调用 |
| **规则** | ST过滤、流动性过滤、连续亏损、高估值、大盘环境熔断 | 无 |

**结论：渠道二缺少L1层。** 用户在渠道二分析个股时，应该也能看到该股是否通过了风控排查。需要将L1风控引入渠道二，作为个股分析的"安全前置检查"。

---

### 2.2 L2 主力筹码策略（Main Force + Chip — 统一策略）

> 知识库参考：LLM Wiki `筹码分布分析（主力视角）` 页面将资金流向与筹码分布定位为同一分析体系的两个维度，强调"交叉比对比法"——通过比对主力买卖超、法人筹码、股价走势来判断主导力量。

| 对比项 | 渠道一 L2 | 渠道二 |
|:-------|:----------|:-------|
| **位置** | `chip_strategy.py:379` `MainForceScorer` | `pipeline.py:83` `ChipDistributionStrategy` |
| **类名语义** | "主力评分"（MainForce） | "筹码分布"（ChipDistribution） |
| **资金流向分析** | ✅ `_score_moneyflow()` 大单净额/连续性/占比 | ❌ 仅作为阶段判定的辅助信号 |
| **筹码分布计算** | ❌ 不使用 `ChipDistributionService` | ✅ 核心 — ASR/CYQKL/SSRP/筹码峰 |
| **集中度分析** | ✅ `_score_concentration()` 股东户数 | ❌ 不单独计算集中度 |
| **散户反向指标** | ✅ `_score_retail_contrarian()` | ❌ 无 |
| **主力阶段识别** | ✅ `identify_phase()` → 建仓/洗盘/拉升/出货/中性 | ✅ `TradingPhaseDetector.detect()` → 建仓/洗盘/拉升/出货/下跌 |
| **信号生成** | ❌ 不打信号，仅评分 | ✅ S_BUY/S_SELL等6种信号 |

**关键问题：渠道一 L2 测量的是"主力行为评分"（资金面），渠道二测量的是"筹码结构分析"（成本面）。两者度量的是主力行为的两个不同侧面，但根据用户的构想，它们应该统一为同一个"主力筹码策略"——既分析资金流向，也分析筹码分布。**

L2的完整形态应该同时包含：
- 资金流向维度（大单净额/连续性/占比）
- 筹码分布维度（ASR/SSRP/筹码峰/集中度）
- 主力阶段识别（统一后的阶段判定引擎）
- 散户反向指标

### 2.3 L3 缠论（Chanlun）

| 对比项 | 渠道一 L3 | 渠道二 |
|:-------|:----------|:-------|
| **位置** | `screener_strategy_integration.py:65` `_compute_chanlun_score()` | `signal_computation_service.py:450` `_compute_chanlun_signal()` |
| **底层引擎** | 仅 `ChanlunAnalyzer` | `ChanlunAnalyzer` + **`ChanlunScorer`** |
| **分析维度** | 5项：买点(3类)、趋势、中枢数 | **11项**：买卖点(6类)、价格距离、背离、多中枢冲突、段笔矛盾、扩张中枢、趋势、中枢数 |
| **后处理** | 自定义轻量计分 → 0-10 | `ChanlunScorer.score()` → 0-100 → 信号翻译 |
| **价格距离评估** | ❌ 无 | ✅ 跌破买点扣分 |
| **背离评估** | ❌ 无 | ✅ ±10~15分 |
| **冲突检测** | ❌ 无 | ✅ 多中枢/段笔矛盾/扩张 |

**结论：规则不一致。** 渠道一自实现了简化版评分，没有复用 `ChanlunScorer` 的完整维度（价格距离、背离、冲突检测都是缠论的重要判定要素）。这违反了"真实有效"原则——为了简化而裁剪了规则。

---

### 2.4 L3 量价（Volume/Price）

| 对比项 | 渠道一 L3 | 渠道二 |
|:-------|:----------|:-------|
| **位置** | `screener_strategy_integration.py:127` | `signal_computation_service.py:1425` |
| **核心引擎** | `VolumePriceStrategy.analyze()` ✅ | `VolumePriceStrategy.analyze()` ✅ |
| **market_env参数** | **None**（market_mult恒为1.0，永不降权） | **Dict**（POOR→0.70, UNKNOWN→0.85） |
| **cycle_weights** | 无 | 有，execution≥0.3时再×0.85 |

**结论：核心引擎相同，但渠道一缺少市场环境参数的传递**，导致大盘低迷时渠道一的量价评分不降权，产生虚假高分信号。

**注意**：渠道一 L2 内的 `_score_volume_price()`（`chip_strategy.py:514`）是一个50行的轻量启发式评分，它属于 L2 主力筹码策略的量价子维度，不属于 L3 量价策略。L2 内部的主力量价判断可以保持轻量（因为是快速筛选的一部分），但 L3 量价必须调用完整的 `VolumePriceStrategy`。

### 2.5 L3 因子组合（Factor Combos）

> 知识库参考：LLM Wiki `A股市场异象因子` 页面指出因子体系包含大量经过验证的异象因子，可以作为因子组合的扩展来源。

| 对比项 | 渠道一 L3 | 渠道二 |
|:-------|:----------|:-------|
| **位置** | `screener_strategy_integration.py:295` `_compute_factor_score()` | `signal_computation_service.py:1066` `_compute_factor_signal()` |
| **因子来源** | `PRESET_COMBOS`（12组合，34命名因子） | `FactorRegistry`（通过注册表查找因子类） |
| **实现覆盖率** | 34因子中**仅9个有内联实现**（26%），其余25个退化为中性5.0分 | 5个注册因子全部真实计算（100%） |
| **计算方式** | 9个 `_FACTOR_COMPUTERS` 内联函数（numpy/pandas） | `FactorCalculator` 代理到 `builtin/*.py` 类方法 |
| **组合支持** | ✅ 12预设组合 + 自定义权重 | ❌ 无组合概念，5因子等权 |
| **情绪因子** | 无专门实现 | `_compute_bociasi_signal()` 独立于因子体系外 |
| **归一化** | 0-10分制，组合内加权 → 等权平均 | 0-1分制，固定权重加权 |
| **动态权重** | ❌ 无 | ✅ `StateDependentFactorWeight` |
| **性能** | PRESET_COMBOS加载 + 内联计算 ≈ 秒级 | registry查找 + 类实例化 ≈ 毫秒级 |

**这是规则最不统一的策略。** 具体问题：

1. **渠道一的UI展示12个组合34个因子，但70%不参与计算** — UI与引擎严重脱节，用户选择了组合但发现评分无变化
2. **渠道二的情绪分析（BOCIASI）独立于因子体系** — 根据用户确认，**情绪策略应该是因子组合中的一个**，不应独立存在
3. **两个渠道的因子计算引擎完全不同** — 一个用内联函数，一个用注册表类。无法保证同一因子输出同一结果

## 三、统一方案（修订版）

### 3.1 Phase 0：策略分类整理（文档级，1天）

**目标**：确认三层四类的策略架构，同步更新代码组织和文档。

| 层级 | 策略 | 类/模块 | 说明 |
|:-----|:-----|:--------|:-----|
| L1 | 风控策略 | `DarwinRiskFilter` + `MultiLevelRiskControl` + `FinancialRiskFilter` | 硬性否决规则，不输出评分，只输出通过/不通过 |
| L2 | 主力筹码策略 | `MainForceScorer` + `ChipDistributionService` + `TradingPhaseDetector` 统一 | 合并资金流向与筹码分布为一个策略 |
| L3 | 缠论 | `ChanlunAnalyzer` + `ChanlunScorer` | 两个渠道共用完整11维度评分 |
| L3 | 量价 | `VolumePriceStrategy` | 四阶段分析链，统一market_env参数 |
| L3 | 因子组合 | `FactorRegistry` + `PRESET_COMBOS` 打通 | 因子组合包括情绪类、动量类、质量类等 |
| L3 | Vibe | `strategy_template_v2` | 两个渠道均可执行/解读 |

---

### 3.2 Phase 1：缠论规则统一（🟡 P1，~1天）

**目标**：渠道一使用与渠道二相同的`ChanlunScorer`完整评分。

**方案**：
- `_compute_chanlun_score()` 改为调用 `ChanlunScorer.score()`（0-100分），然后缩放到0-10分
- 渠道二保持现有0-100+signal_label不变
- 保证两个渠道对同一股票的买卖点判定、价格距离评估、背离检测、冲突检测结果完全一致

**影响**：渠道一从5维度扩展到11维度，评分更精确。在简化版下得高分的股票如果存在价格距离过大或中枢冲突，纠正后分数可能下降。

---

### 3.3 Phase 2：量价参数对齐（🟢 P2，~0.5天）

**目标**：渠道一 L3 的量价分析使用与渠道二相同的市场环境参数。

**方案**：
- `_compute_volume_price_score()` 调用 `VolumePriceStrategy.analyze()` 时传入 `market_env` 参数
- `market_env` 从 `_compute_index_condition()` 获取大盘状态（与渠道二对齐）
- L2内的 `_score_volume_price()` 轻量版保留（属于主力筹码策略的价量子维度，不属于L3量价策略）

---

### 3.4 Phase 3：L2 主力筹码策略统一（🔴 P0，~3天）

**目标**：将渠道一的 "主力行为评分" 与渠道二的 "筹码分布分析" 融合为统一的 **L2主力筹码策略**。

**方案**：

统一后的 L2 主力筹码策略包含 **5个维度**：

| 维度 | 数据源 | 计算方式 | 分值 |
|:-----|:-------|:---------|:----|
| A. 资金流向 | `moneyflow_cache` 大单净额/连续性/占比 | `_score_moneyflow()`（复用现有） | 0-3 |
| B. 筹码分布 | `ChipDistributionService` chip_bins/ASR/SSRP | `ChipIndicators`（复用渠道二） | 0-3 |
| C. 集中度 | `stk_holder_cache` 股东户数变化 | `_score_concentration()`（复用现有） | 0-2 |
| D. 散户反向 | `moneyflow_cache` 散户净买卖 | `_score_retail_contrarian()`（复用现有） | 0-2 |
| E. 主力阶段 | 综合 A+B+C+D 判定 | `TradingPhaseDetector`（统一引擎） | 标签输出 |

**渠道输出差异**：
- 渠道一：A+B+C+D → 0-10分（排序用）+ E阶段标签
- 渠道二：A+B+C+D → 各维度指标值 + E阶段 + 证据链 + 信号建议

---

### 3.5 Phase 4：因子组合体系统一（🔴 P0，~3天）

**目标**：打通 `PRESET_COMBOS` 与 `FactorRegistry`，建立一个统一因子计算层。

**方案**：

```
PRESET_COMBOS (12组合，含情绪组合)
    │  定义：{组合ID, 因子列表[n:name, w:weight]}
    │
    ▼
FactorRegistry (统一因子注册表)
    │  注册：因子名 → 因子类（含compute()方法）
    │  扩展：从现有5个扩展至覆盖所有PRESET_COMBOS中可实现的因子
    │
    ├──→ 渠道一：组合→查注册表→逐因子计算→加权→0-10分
    └──→ 渠道二：查注册表→逐因子计算→因子值+解读
```

**关键技术决策**：

| 问题 | 方案 |
|:-----|:------|
| 情绪因子（原BOCIASI） | 作为因子组合中的一个组合（如"情绪组合"），通过 `FactorRegistry` 计算，不独立存在 |
| 因子覆盖率 | 以 `PRESET_COMBOS` 为基准，逐步实现所有可计算的因子，**不允许中性5.0分占位** |
| 计算引擎 | 统一使用 `FactorRegistry` 注册表模式（类方法），淘汰 `_FACTOR_COMPUTERS` 内联函数 |
| 归一化 | 统一0-10分制 |
| 动态权重 | 引入 `StateDependentFactorWeight`（从渠道二迁移） |

**需实现的因子类型**（PRESET_COMBOS中当前未实现的25个）：
- 情绪类：原BOCIASI快线4指标（放量确认/价格强势/短期动量/波动活跃）、BOCIASI慢线
- 质量类：ROE、毛利率、资产负债率、EPS
- 估值类：市盈率倒数(EP)、市净率倒数(BP)、股息率
- 资金类：大单净买入、换手率变化
- 学术因子：市场因子、规模因子等（通过因子注册表扩展）

---

### 3.6 Phase 5：Vibe 策略引入渠道二（🟡 P2，~1天）

**目标**：渠道二也能执行Vibe策略，输出形式为策略分析文本。

**方案**：
- 渠道二新增Vibe策略调用，复用已有的 `_execute_single_strategy()` 引擎
- 输出形式：将策略执行结果转化为现状解读文本（而不是加分）
- 用户通过策略开关面板选择是否启用Vibe策略分析

---

### 3.7 Phase 6：L1风控引入渠道二（🟢 P3，~0.5天）

**目标**：渠道二个股分析时能看到风控检查结果。

**方案**：
- 渠道二分析个股前调用 `DarwinRiskFilter.filter()` 
- 输出：风控是否通过 + 未通过的具体原因

## 四、统一评分体系设计（渠道一）

> 目标：为渠道一的最终结果合理性提供依据，确保不同策略的评分能在同一尺度下加权组合。

### 4.1 L3 评分架构

```
单只股票 = L1通过 → L2评分 → L3综合评分

L3综合评分 = f(缠论评分, 量价评分, 因子组合评分, Vibe加分)
              │         │         │           │
              │         │         │           └─ 加分项（0-5，可选启用）
              │         │         │
              │         │         └─ 因子组合加权（组合内因子加权→组合间等权）
              │         │
              │         └─ 量价评分（含大盘环境降权）
              │
              └─ 缠论评分（含价格距离/背离/冲突检测调整）

分值范围：0-10分（每个子策略独立归一化）
综合公式：综合 = Σ(score_i × weight_i) / Σ(weight_i)
```

### 4.2 各个策略的评分映射

| 策略 | 原始分值 | 映射到0-10 | 说明 |
|:-----|:---------|:-----------|:-----|
| 缠论 | 0-100（`ChanlunScorer`） | ÷10 | 完整11维度评分 |
| 量价 | 0-10（`VolumePriceStrategy` 信心度） | 等比例 | 含大盘环境降权 |
| 因子组合 | 0-10（各因子加权平均） | 等比例 | 每个因子0-10，组合内加权 |
| Vibe | 0-5（加分） | 直接加分 | 不归一化，作为额外加分 |

### 4.3 z-score归一化保留

当前渠道一使用的 z-score 归一化（将各策略原始分转换为标准分后再加权）应当保留，因为它解决了不同策略分值分布差异大的问题（例如缠论评分集中在3-7分，而因子评分集中在5-6分）。

统一后的流程：
1. 计算各策略原始分（0-10）
2. z-score归一化（消除量纲差异）
3. 加权求和
4. 截断至[0,10]

### 5.2 策略变化对评价标准的影响

| 变化类型 | 影响范围 | 是否需要调整评价标准 |
|:---------|:---------|:-------------------|
| **缠论评分扩展**（5维→11维） | 影响缠论评分分值分布（更分散） | ⚠️ 需要。z-score归一化可吸收部分影响，但回测的历史评分与新评分不可直接比较 |
| **量价加入market_env** | 大盘低迷时评分降低 | ⚠️ 需要。历史回测需重新计算量价评分，大盘熊市期的信号胜率可能变化 |
| **L2主力筹码统一**（资金+筹码合并） | 影响L2评分逻辑 | ⚠️ 需要。L2→L3的`_phase_timing_bonus()`依赖L2阶段判定，统一L2后阶段判定的回测结果会变化 |
| **因子组合补充实现**（25个因子中性分→真实分） | 因子评分区分度大幅提升 | ✅ 正面影响。当前中性5.0分的因子获得真实分后，回测的信号区分度应有所提升 |
| **Vibe引入渠道二** | 新增策略维度 | ✅ 不影响现有评价标准。作为可选启用项 |
| **L1风控引入渠道二** | 新增风控前置检查 | ✅ 不影响评分。仅作为阻塞式检查 |
| **权重场景化**（动态权重） | 综合评分计算方式变化 | ⚠️ 需要。历史回测需引入大盘状态判定逻辑，回测结果与当前固定权重的结果不可直接比较 |

### 5.3 建议的回测策略

1. **增量回测而非全量重跑**：修改后的策略只对新产生的信号进行回测验证，历史回测结果保留但标注"旧版规则"
2. **引入版本化策略标记**：每个策略输出附带版本号（如 `chanlun_v1` → `chanlun_v2`），回测结果可以与版本挂钩
3. **建立策略变更影响评估流程**：任何策略规则变更 → 影响评估 → 回测验证 → 更新评价基准
4. **A/B对比测试**：新旧规则并行运行一段时间，对比评分分布和信号胜率，验证改进效果后再全量切换
