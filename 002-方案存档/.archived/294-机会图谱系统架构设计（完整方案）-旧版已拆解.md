# 机会图谱系统架构设计（完整方案）

> **范式转变**：从「选股系统」(Stock Screener) 到「机会图谱」(Opportunity Atlas)
>
> 这并不是名字的改变，而是系统**核心目标**和**呈现范式**的根本转变：
> - 选股系统回答「哪些股票好？」—— 输出一个排序列表
> - 机会图谱回答「**今天市场上，机会在哪里、风险在哪里**」—— 输出一张可缩放、可导航、可交互的**机会全景地图**
>
> **机会图谱的本质是一张地图，地图的核心能力是缩放和导航，而不是把全世界的每一条街道都列出来。**

---

## 一、核心理念与设计哲学

### 1.1 最大问题回顾

| 问题 | 当前表现 | 根因 |
|------|---------|------|
| **机会模糊** | 推荐了股票，用户不知道是什么类型的机会、什么时间维度 | 无机会分类，无周期标定 |
| **估值盲区** | 纯技术评分，完全不涉及估值 | 只有价格维度，没有价值维度 |
| **操作模糊** | 用户不知道什么价格买、什么价格卖、持有多久 | 无操作建议体系 |
| **缺乏连续性** | 每天推荐不同股票，没有长期跟踪 | 无标的库机制，每天独立筛选 |

### 1.2 五大设计原则

**原则一：从「排序」到「分类」**

```
当前:   5000只 → 过滤 → 评分 → 排序 → 前N只（一维排序）
新范式: 5000只 → 分类 → 分层 → 标定 → 机会图谱（多维分类）
```

系统不再试图回答「哪只最好」—— 这是一个伪命题。因为不同类型的机会无法在单一尺度上比较。一只短线技术突破票和一只长线低估值票，没有可比性。正确的方式是**把每一类机会分门别类呈现给用户，让用户自己根据需求选择**。

**原则二：从「单次筛选」到「持续跟踪」**

```
当前:   每天独立跑全市场筛选 → 每天一个新名单
新范式: 标的库(长期维护) + 每日增量更新 + 状态变化提示
```

放弃"每天从头筛一遍"的思维。改为维护一个**动态标的库**，每天对新股做候选入池评估，对池中股票做状态更新和操作建议。标的库是持续性跟踪的载体，而 Treemap 市场地图是全市场探索的入口，两者构成机会图谱的核心交互：**地图上发现→标的库里跟踪**。

**原则三：从「黑盒评分」到「透明诊断」**

```
当前:   分数 7.5 → 用户只知道"好"但不知道为什么好
新范式: 多维雷达图 + 阶段判定 + 关键证据链 → 用户能理解并信任
```

每个机会必须附带完整的**证据链**：为什么是这个阶段？有哪些指标支持？风险点是什么？用户不仅要看到结论，还要能看到得出结论的过程。

**原则四：从「固定策略」到「可扩展策略框架」**

```
当前:   系统预设固定策略，用户无法自定义
新范式: 基础引擎(固定) + 因子组合(用户自选) + Vibe策略(用户自建)
        ↓
        三者按管线融合，产出最终机会评分
```

Factor 组合和 Vibe 策略不是"某个管线的组成部分"，而是**叠加在所有管线之上的用户自定义增强层**：

- **Factor 组合**：用户从 FactorRegistry 中挑选因子 + 自定义权重，形成组合，挂载到任意管线
- **Vibe 策略**：用户用自然语言描述策略 → LLM 生成可执行代码，挂载到任意管线
- 两者的设计目的相同：**在预设引擎之外，给用户留一个自建策略的窗口**

**原则五：从「列表」到「地图」**

```
当前:   列表形式展示筛选结果 → 用户逐行浏览
新范式: Treemap 矩形树图 → 一眼感知全市场机会分布
        ↓
        地图的核心能力是「缩放」和「导航」，而非逐条列出
        
        三种地图模式（行业分组）:
        市场地图: 大小=市值, 颜色=涨跌幅
        机会地图: 大小=机会评分, 颜色=持有周期(蓝绿橙红)
        价值地图: 大小=前收盘价(行业内), 颜色=估值偏离度
        
        交互方式:
        多标签 AND 筛选 | 预设场景快捷入口 | 悬停四行标签摘要
```

机会图谱的前台展示遵循**「信息分层，按需下钻」**原则。后台对前置过滤后的全量股票进行计算（L2-L3 约 4800 只），但前台**只展示三层**：

| 定位 | 展示范围 | 展示方式 | 核心理念 |
|------|---------|---------|---------|
| **我的标的**（家） | 标的库 20-100 只 | 列表/看板 + 变更提示 | 连续跟踪，关注变化 |
| **新机会窗口**（发现） | 管线推荐 3-5 只/管线 | 卡片 + "加入标的库"按钮 | 有限推荐，不被淹没 |
| **市场总览**（地图） | 全市场 Treemap | 矩形树图 + 双模式切换 | 一眼感知分布，缩放导航后详见个股 |

**不展示全部 5000 只股票的机会信息**。全量计算是后台能力，前台通过地图聚合和搜索来访问。

## 四、L2 — 股票属性多维标注层（★★★★★ 全新设计）

这是机会图谱的**根基**。每只股票不再是"一个代码"，而是带有一组结构化标签的**实体**。

### 4.0 前置过滤层：不可逆风险剔除

在进入任何标注和计算之前，先执行一道窄口径的**前置过滤**。与当前 L1 的四条规则不同，此过滤仅剔除**有确定性本金永久损失风险的股票**，不做估值或流动性判断。

#### 过滤标准

| 规则 | 标准 | 数据来源 | 理由 |
|------|------|---------|------|
| **R1: ST/*ST/退市** | 股票名称含 `*ST`、`ST`、`退市`、`SST` | Stock ORM / stock_list 缓存 | 已被交易所特殊处理，存在退市风险 |
| **R2: 面值退市风险** | 连续 10 个交易日收盘价 < 1 元 | `daily_cache.close` | A股面值退市规则（连续20日<1元即触发） |
| **R3: 市值退市风险** | 连续 10 个交易日收盘总市值 < 3 亿元 | `daily_cache.close` × 总股本 | A股市值退市规则（连续20日<3亿即触发） |

#### 过滤效果

| 指标 | 数值 |
|------|------|
| 当前 A 股 ST/*ST 数量 | ~150-200 只 |
| 面值<1元股数量 | ~10-30 只（动态） |
| 市值<3亿股数量 | ~30-50 只（动态） |
| **合计剔除** | **约 200-250 只（占全市场 4-5%）** |
| **剩余可计算标的** | **约 4800 只** |

**对比当前 DarwinRiskFilter 的 24.8% 剔除率**，本过滤口径窄得多——仅剔除有确定性退市风险的股票，不碰 PE、换手率、市值等"可逆风险"。

#### 被剔除股票的处理

```
被 R1/R2/R3 命中的股票:
  1. 不进入 L2 标注管线（跳过计算）
  2. 不进入 L3 策略管线（不评分）
  3. 不在 Treemap 中展示（不可见）
  4. 不在标的库出现
  5. 仅在个股搜索中可查（输入代码时提示"该股因XX原因已过滤"）
```

#### 不纳入此过滤的风险类型（保持标签化处理）

| 风险 | 为什么不剔除 | 处理方式 |
|------|------------|---------|
| PE>300 | 成长股高PE是常态，不是风险 | 标签化：标记为`high_valuation` |
| 换手率<1% | 低流动性不等于退市风险 | 标签化：标记为`low_liquidity` |
| 连续亏损 | 亏损企业可能反转（困境反转策略） | 标签化：标记为`negative_profit` |
| 市值<30亿 | 小盘股也有机会 | 标签化：标记为`micro_cap` |
| 高负债率 | 杠杆经营是行业特性 | 标签化：标记为`high_debt` |

```
每只股票在L2层产出:

  "name": "平安银行",
  
  // ── A. 基础画像 ──
  "category": "head_blue_chip",     // 一级分类
  "market_cap_level": "large",      // 市值规模
  "industry": "银行",
  "industry_group": "金融",
  
  // ── B. 风险标签 ──

### 4.2 一级分类（L0 → L2 整合）

取消原来独立的 L0，将分类逻辑融入 L2 标注：

| 类别 | 判定标准 | 预期数量 | 典型策略适用 |
|------|---------|---------|------------|
| **头部蓝筹** | 市值>500亿，行业前3 | ~300只 | 价值型(长线)、波段操作 |
| **成长型** | 营收增长>20%，市值50-500亿 | ~500只 | 趋势型(中线)、事件型 |
| **周期型** | 强周期行业(有色/化工/钢铁/煤炭/航运) | ~400只 | 趋势型(中线)、估值修复 |
| **微小盘** | 市值<50亿 | ~3000只 | 事件型(短线)、技术型(超短) |
| **困境反转** | 利润为负但边际改善，有催化剂 | ~200只 | 事件型(长线左侧) |
| **稳定收息** | 股息率>3%，连续3年派息 | ~200只 | 价值型(长线收息) |
| **主题概念** | 当前热门概念关联度高 | ~300只 | 事件型(短线) |
| **待分类** | 以上均不匹配 | ~100只 | — |

**关键决策**：微小盘占全市场 60%，但多数不适合做为主要投资标的。机会图谱默认**不将微小盘纳入主力管线**，仅在事件型管线中按"催化剂触发"方式出现。这解决了「L2 把微小盘活跃票当成主力票」的根本问题。

### 4.3 风险标签体系（L2 标注层）

L2 的**前置过滤层（§4.0）**已剔除 ST/退市/面值退市/市值退市等不可逆风险股。进入此环节的股票，其余风险**不再剔除，而是打标签**：

| 标签 | 定义 | 影响方式 |
|------|------|---------|
| `low_liquidity` | 20日换手率<1% | 进入策略管线时显示"流动性警告" |
| `high_valuation` | PE分位>90%+非金融 | 价值型管线降低权重 |
| `loss_micro` | PE为负+市值<30亿+换手<3% | 仅在事件型管线中出现 |
| `negative_profit` | 连续2年净利润为负 | 基本面标记，不阻断 |
| `high_debt` | 资产负债率>80% | 风险提示标记 |
| `pledge_risk` | 大股东质押比例高 | 风险提示标记 |

**新增规则：任何策略管线在消费 L2 标签时自行决定是否处理带风险的股票**。风险和机会的判断从"系统决定"变为"管线和用户共同决定"。

### 4.4 估值定位子系统（完全新增）

#### 估值方法链

```
对于每只股票，按以下优先级计算估值:
  1. PE历史分位法 (优先)
     - 计算近5年(或上市以来)的PE-TTM分位
     - <20% → 低估 | 20-50% → 偏低 | 50-80% → 合理 | >80% → 高估
     
  2. 行业对比法 (PE/PB相对行业中位数)
     - PE/行业PE_median < 0.7 → 显著折价，警惕价值陷阱
     - PE/行业PE_median 0.7-1.3 → 行业合理
     - PE/行业PE_median > 1.3 → 溢价
     
  3. PB-ROE框架 (周期股/金融股)
     - PB和ROE的回归关系
     - 当前PB相对合理PB的偏离度
     
  4. DCF参考 (长线价值股)
     - 简单DCF模型(FCFF折现)
     - 产出合理市值区间
```

## 四A、信息架构与前端展示（四层级模型）

### 4A.1 核心设计理念

机会图谱的前端展示遵循**「信息分层，按需下钻」**原则。这与后台全量计算（L1-L3 覆盖所有 5000 只）形成对比：

> **后台（全量计算，保证覆盖）**: L2 标注覆盖约 4800 只（经 §4.0 前置过滤剔除 ST/退市等约 200 只），L3 管线全部评分
>
> **前台（分层展示，防止过载）**: 只展示三类信息——用户在跟踪的（标的库）、新出现的（管线发现）、用户主动搜索的（个股查询）

### 4A.3 层级一详解：Treemap 市场总览与交互设计

#### 设计目标

**「一目了然地回答：今天市场上，机会在哪里、风险在哪里。」**

Treemap 不是"推荐股票"，而是**地图导航**——告诉用户从哪个方向开始探索。这是机会图谱和传统选股系统的根本区别。

所有三种模式共享同一套行业分组结构（申万一级行业），外层是行业板块容器，内层是个股方块。**切换模式时行业分组不变，变的只有方块大小和颜色的映射规则。**

#### 三种地图模式

> 注：覆盖范围为经 §4.0 前置过滤后的全部约 4800 只股票。ST/*ST/退市/面值退市/市值退市股不在 Treemap 中出现。

##### 📊 模式一：市场地图

| 要素 | 规则 | 说明 |
|------|------|------|
| **外层分组** | 申万一级行业 | 按行业板块分组，板块间有颜色边框区分 |
| **方块大小** | **流通市值**（行业内比较） | 行业内市值越大的公司方块越大 |
| **方块颜色** | **涨跌幅** | 红=跌、绿=涨，颜色越深幅度越大 |
| **用户视角** | "今天市场怎么样？" | 看哪个板块在涨跌、哪个板块在活跃 |

##### 🎯 模式二：机会地图

| 要素 | 规则 | 说明 |
|------|------|------|
| **外层分组** | 申万一级行业（不变） | 行业分组和市场地图完全一致 |
| **方块大小** | **机会评分**（行业内比较） | 评分越高的股票方块越大，**高分小盘股自动放大** |
| **方块颜色** | **机会类型（按持有周期）** | 见下方颜色映射表 |
| **用户视角** | "每个板块里机会在哪、是什么类型的？" | 一眼看出哪儿有机会、能持有多久 |

**机会地图颜色映射**（从用户需求出发，不使用术语）：

```
🔵 蓝色 = 长线机会（适合持有6个月以上）
  — 如：估值偏低+财务健康的优质公司
  — 用户理解："这只票便宜质量好，买了放着"

🟢 绿色 = 中线机会（适合持有1-6个月）
  — 如：主力建仓/洗盘末期+趋势向上
  — 用户理解："主力在建仓，跟一段趋势"

🟠 橙色 = 短线机会（适合持有1-4周）
  — 如：有催化剂+放量突破
  — 用户理解："有利好要来了，短线博一把"

🔴 红色 = 超短/做T机会（适合1-5天）
  — 如：缠论买点+波动率够大
  — 用户理解："有底仓可以做个T，快进快出"

⬜ 灰色 = 无明确信号（暂不关注）

颜色深浅 = 置信度（深蓝=确定性强的长线机会，浅蓝=可能是长线但不明确）

通俗类比:
  🔵蓝(长线) ≈ 定期存款，放着不动
  🟢绿(中线) ≈ 跟一个项目，需要盯一盯
  🟠橙(短线) ≈ 赶一趟航班，卡准时间上下
  🔴红(超短) ≈ 抢个红包，手快有手慢无
```

##### 💎 模式三：价值地图

| 要素 | 规则 | 说明 |
|------|------|------|
| **外层分组** | 申万一级行业（不变） | 行业分组完全一致 |
| **方块大小** | **前收盘价**（行业内比较） | 行业内价格越高的股票方块越大（同行业价格可比） |
| **方块颜色** | **估值偏离度** | 绿=低估、灰=合理、红=高估，颜色越深偏离越大 |
| **用户视角** | "在每个板块里，哪些贵了哪些便宜了？" | 发现板块内的价值洼地 |

**价值地图颜色映射**：

```
偏离度 = (当前价 - 合理估值中轴) / 合理估值中轴

🟢 深绿 → 深度低估（偏离度 < -20%）
🟢 浅绿 → 低估（偏离度 -20% ~ -10%）
⬜ 灰色 → 估值合理（偏离度 -10% ~ +10%）
🔴 浅红 → 偏高估（偏离度 +10% ~ +20%）
🔴 深红 → 高估/泡沫（偏离度 > +20%）
```

合理估值区间的计算方法见 §4.4——综合 PE/PB/PS 历史分位 + 行业对比 + PB-ROE 框架，对不同类型股票使用不同的估值锚。

##### 模式切换的效果

```
切换模式时:
  行业分组（外层结构）→ 不变，便于用户定位
  方块大小 → 重新计算（ECharts 动画过渡约 300ms）
  方块颜色 → 重新映射（标签/说明同步更新）
```

#### 交互行为

| 交互 | 行为 | 数据来源 |
|------|------|---------|
| 悬停 (Hover) | 显示四行标签摘要浮窗 | L2 标注 + L3 评分聚合 |
| 点击 (Click) | 打开 L4 个股诊断弹窗 | L4 诊断引擎 |
| 双击/滚轮 | 缩放进入板块视图 | ECharts 原生 |
| 模式切换 | 一键切换市场/机会/价值地图 | 重算大小和颜色映射 |

#### 悬停浮窗：四行标签摘要

```

┌─ 西藏矿业 ─────────────────────────┐

四行标签（方向/位置/质量/环境）是对机会的标准化描述，用户无需了解任何策略术语即可理解。

#### 标签筛选栏：多标签 AND 组合

Treemap 上方有一排标签筛选按钮，支持多标签 AND 组合筛选：

```
[ 📊 全市场(4800) ]  [主力建仓(42) ✕] [估值偏低(156) ✕]  [+选择标签▾]

```

交互逻辑：
- 点击标签 → Treemap 只高亮带此标签的股票，其余变灰
- 多标签同时选中 → AND 交集
- 标签按钮右侧显示当前满足此标签的股票数量（动态更新）
- 再次点击标签 → 取消高亮
- "全市场"按钮 → 清除所有筛选

#### 预设场景：四组标签组合快捷入口

原来的四条管线在此转化为**四组预设的标签组合**，作为用户的推荐入口：

```
预设场景        包含的标签条件                对应原来管线
────────        ───────────                 ───────────
📋 价值低估   = {估值偏低 + 财务健康 + ROCE≥15%}  → 价值型管线
📋 主力跟庄   = {主力建仓 + 资金流入 + 趋势向上}   → 趋势型管线
📋 短线催化   = {有催化剂 + 量价突破 + 情绪复苏}   → 事件型管线
📋 做T机会    = {有底仓 + 缠论买点 + 波动率>2%}    → 技术型管线
```

用户点击"📋 价值低估" → 系统自动勾选 {估值偏低 + 财务健康 + ROCE≥15%} 三个标签 → Treemap 高亮同时满足三条件的股票。效果和用户手动勾选这三个标签完全一致。

用户也可以在预设场景基础上微调（添加或删除标签），从而实现个性化。

#### 盘中实时能力

| 场景 | 数据 | 更新方式 | 频次 |
|------|------|---------|------|
| 盘中价格 | 东财 HTTP 实时行情 | 前端轮询 | 30s |
| 机会信号 | 盘前预计算（日频） | 被动展示 | 每日盘前刷新 |
| 实时提示 | 右下角显示数据时间戳 | 自动 | 每次更新 |

默认模式：**盘后/盘前默认展示机会地图**（盘前就绪的静态机会数据）；**盘中自动保留用户当前选择的模式**，价格颜色 30s 轮询刷新。

### 4A.4 四层级与原有六层模型的关系

```
原有六层模型（数据/计算层）:
  L1 数据底座 → L2 属性标注 → L3 标签引擎(各引擎产出标签) + L3+ 自定义策略 → L4 交叉诊断 → L5 全景总览

四层级展示模型（呈现层）:
  层级一「市场总览」: L5 全景总览的 Treemap 实现形式 + L3 标签筛选栏
  层级二「标的库看板」: L5 全景总览的列表/看板实现形式
  层级三「预设场景+标签筛选」: L3 标签引擎输出 + L3+ 自定义策略叠加后的发现入口
  层级四「个股搜索诊断」: L4 诊断引擎的按需调用
```

**六层模型是系统的计算架构，四层级是用户的信息架构。** 两者不矛盾——六层回答了"系统怎么运作"，四层级回答了"用户怎么看"。六层的数据最终按照四层级的信息架构呈现给用户。

### 5.0 策略引擎与标签体系总览

机会图谱的策略来源分为三个层次，但**策略引擎不再按"管线"划分，而是统一产出标签**：

```
┌─────────────────────────────────────────────────────────────────┐
│  层次一：五大基础引擎（系统预设，固定不变）                      │
│                                                                   │
│   1. DarwinRisk 标签化 → 风险标签（原L1，改造为不阻断的标签系统） │

## 五A、L3+ — 用户自定义策略层（★★★★★ 核心新增）

### 5A.1 设计定位

Factor 组合和 Vibe 策略**不是某个管线的组成部分**，而是**叠加在所有四根管线之上的用户自定义增强层**。它们的角色是"让用户在基础引擎之上加入自己的判断"，而非替代基础引擎。

| 维度 | Factor 组合 | Vibe 策略 |
|------|-----------|----------|
| 关联模块 | 因子管理模块（FactorRegistry） | 策略模板模块（strategy_templates_v2） |
| 构成方式 | 从因子注册表挑选因子+自定义权重 | 自然语言描述 → LLM 生成可执行代码 |
| 灵活性 | 限于 FactorRegistry 已有因子 | 理论上无限（可生成新计算逻辑） |
| 可扩展性 | 用户可注册新因子到 FactorRegistry | 用户可反复迭代描述直到满意 |
| 可解释性 | 高（每个因子透明可见） | 中低（LLM 生成的代码不透明） |
| 可靠性 | 高（因子经过回测验证） | 中低（LLM 可能生成错误逻辑） |
| 用户门槛 | 低（勾选+拖拽权重） | 中（需写策略描述+审查生成代码） |

### 5A.2 Factor 组合的管线归属

每个 Factor 组合在创建时必须指定它**属于哪条管线**：

```json
{
  "id": "c1",
  "name": "深度价值组合",
  "pipeline": "value",                    // ← 管线归属: value/trend/event/technical
  "pipeline_auto_assign": true,           // ← 是否自动分配（根据因子类型猜测）
  "factors": [
    {"name": "PE_PERCENTILE_5Y", "weight": 0.4},
    {"name": "DIVIDEND_YIELD", "weight": 0.3},
    {"name": "ROE", "weight": 0.3}
  ],
  "status": "active",
  "created_at": "2026-07-23",
  "usage_count": 5,
  "last_score_avg": 68.5                  // 历史平均表现
}
```

一条管线可以挂载多个 Factor 组合，系统取其加权平均作为 Factor 贡献分。

### 5A.3 FactorRegistry 新建因子清单

当前 FactorRegistry **缺少估值类和质量类因子**，导致价值型管线即使有引擎，Factor 也无法提供支持。需要新增以下因子：

| 因子名 | 类别 | 数据源 | 用途 | 管线归属 |
|--------|------|--------|------|---------|
| `PE_PERCENTILE_5Y` | 估值 | daily_basic.pe_ttm | PE近5年分位 | value |
| `PB_PERCENTILE_5Y` | 估值 | daily_basic.pb | PB近5年分位 | value |
| `PS_PERCENTILE_5Y` | 估值 | daily_basic.ps | PS近5年分位 | value |
| `DIVIDEND_YIELD` | 估值 | cashflow/分红 | 股息率 | value |
| `ROE` | 质量 | fina_indicator.roe | ROE | value |
| `DEBT_RATIO` | 质量 | fina_indicator | 资产负债率（反向） | value |
| `REVENUE_GROWTH` | 质量 | income | 营收增长率 | value |
| `PROFIT_GROWTH` | 质量 | income | 净利润增长率 | value |
| `INSTITUTIONAL_BUY_5D` | 资金 | moneyflow | 机构5日净买入 | trend, event |
| `CONCEPT_HEAT` | 情绪 | concept | 所属概念热度排名 | event |
| `EMOTION_EXTREME` | 情绪 | BOCIASI | 情绪极值信号 | event, technical |

### 5A.4 Vibe 策略的管线归属与分级管理

每个 Vibe 策略创建时指定归属管线：

```json
{
  "id": "vibe_001",
  "name": "业绩超预期+MACD金叉",
  "pipeline": "event",                    // 管线归属
  "level": "trial",                       // sandbox(预览) / trial(试用) / trusted(已验证)
  "code": "def evaluate(df): ...",        // LLM 生成的执行代码
  "natural_language": "业绩预告净利润同比增长>50%且MACD金叉",
  "source": "llm_v1",
  "status": "active",
  "win_rate": null,                       // 试用期无胜率数据
  "trial_start": "2026-07-23",
  "auto_promote_after": 30                // 试用30日且胜率>55%自动升级到trusted
}
```

#### Vibe 分级管理

| 级别 | 含义 | 权重上限 | 自动启用 | 上線条件 |
|------|------|---------|---------|---------|
| `trusted` | 经过验证的可靠策略 | 20%（占总分） | 是 | 已通过回测 + 实盘观察N日 + 胜率>X% |
| `trial` | 正在试用的策略 | 10%（占总分） | 否（默认不启用） | 已通过沙箱回测 |
| `sandbox` | 刚生成的策略 | 0%（仅预览信号） | 否（仅展示） | 仅生成，需用户审查后手动升级 |

#### Vibe 沙箱→灰度→上線流程

```
用户写描述 → LLM生成策略代码
  ↓
沙箱回测（在历史数据上验证表现）──→ 失败 → 提示用户修改描述
  ↓ 通过
预览信号（在最新数据上生成信号，对比基础引擎输出）
  ↓ 用户审查确认
灰度上线（标记为 trial，不影响综合评分，仅展示信号）
  ↓ 观察N个交易日，记录胜率
胜率达标(>55%) → 自动升级 trusted，正式参与评分
胜率不达标 → 提醒用户"该Vibe策略表现不佳，建议修改或停用"
```

### 5A.5 Fator/Vibe 变更对标的库的影响

用户会持续新增/修改/删除 Factor 组合和 Vibe 策略。**标的库的评分不能完全依赖 Factor/Vibe，因为策略是可变的**。

解决方案：**标的库评分分层存储**

```json
{
  "ts_code": "000001.SZ",
  "library_score": {
    // 下层：基础引擎评分（不变，仅依赖L2数据）
    "base_value_score": 7.2,
    "base_trend_score": 5.0,
    "base_event_score": 3.0,
    "base_technical_score": 6.5,
    
    // 上层：用户自定义策略加分（可变，依赖当前Factor/Vibe配置）
    "factor_boost": 0.5,
    "vibe_boost": -0.2,
    
    // 最终得分
    "composite_score": 7.0
  }
}
```

**当用户修改 Factor/Vibe 配置时的处理**：
- 基础引擎评分不变（无需重算）
- 仅重新计算 factor_boost 和 vibe_boost
- 生成新的 composite_score
- 如果 composite_score 大幅下降（>2分），标记为"*策略变更* 建议重新评估此标的"

**标的库分级受 Factor/Vibe 影响规则**：

| 标的库等级 | Factor/Vibe 影响方式 |
|-----------|-------------------|
| ⭐⭐⭐ 核心持仓 | 基础引擎评分主导，Factor/Vibe 只影响操作建议，不影响入库/出库 |
| ⭐⭐ 重点观察 | 基础引擎评分 + Factor/Vibe 共同决定 |
| ⭐ 潜力扫描 | Factor/Vibe 可以主导入库（用户自定义策略发现的机会） |

## 六、L4 — 个股深度诊断层 + 交叉验证仲裁层（全新增）

### 6.0 交叉验证仲裁层（L4 内部）

这是确保各管线结果一致性的核心机制。当前系统中各策略独立计算且互相不通信的问题，在这里解决。

#### 仲裁规则

```
规则1: 趋势型说建仓 + 事件型说有利好 + 技术型说有买点
       → ★ 强三重确认信号，建议优先建仓

规则2: 趋势型说建仓 + 事件型无信号 + 技术型说有买点
       → ✓ 中等确认，建议建仓

规则3: 趋势型说拉升中段 + 技术型说超买
       → ⚠ 风险提示：拉升中段且超买，建议持有不追

规则4: 趋势型说出货 + 事件型有利好
       → ✗ 矛盾信号：利好出货是典型陷阱，建议观察

规则5: 趋势型说无主力 + 事件型无信号 + 技术型说有买点
       → ℹ 技术信号但无主力配合：仅做T，不建议新仓位

规则6: BOCIASI 情绪过热 + 任一做多管线
       → ⚠ 情绪过热抑制做多信号：降低仓位建议

规则7: 价值型说低估 + 趋势型说建仓
       → ★ 价值+趋势双确认：长期仓位+中期仓位均可建

规则8: 价值型说高估 + 技术型说有买点
       → ✗ 矛盾信号：高估下的买点风险大，建议不参与或极轻仓
```

#### 仲裁输出

### 6.2 操作建议生成规则

机会图谱的核心产出是**操作建议**，而非评分。操作建议分为五类：

| 操作类型 | 含义 | 适用场景 |
|---------|------|---------|
| **建仓** | 建议开始买入 | 新发现的机会，处于建仓期或低估 |
| **加仓** | 建议增加仓位 | 已有持仓，机会确认加强 |
| **持有** | 建议不动 | 逻辑未变，耐心等待 |
| **减仓** | 建议降低仓位 | 目标接近，或风险上升 |
| **做T** | 建议利用波动降低成本 | 标的优质但短期波动大 |
| **止损** | 建议清仓退出 | 条件被破坏，逻辑不成立 |
| **观察** | 暂时不做操作 | 出现信号但不充分，继续跟踪 |

#### 入库/出库规则

| 操作 | 触发条件 |
|------|---------|
| **入库** | 管线评分 > 阈值(默认6.0) 且 非带阻断标签 |
| **升级** | 持续跟踪>5日 + 信号增强 = 从⭐→⭐⭐ |
| **出库通知** | 信号消失/条件破坏 = 移入历史记录 |

## 八、运行流程 — 每日完整链路

### 8.1 日间流程

```
时间        动作                                    产出
───         ────                                    ────
盘前(8-9点)  data_daemon 数据采集                    全市场日线+基础数据就绪
盘前(9点)   L2 标注计算                              5000只股票多维标签
盘前(9:15)  四管线并行扫描 + L3+ Factor/Vibe 叠加    各管线候选列表 + 用户自定义增强分
盘前(9:25)  标的库更新(入/出/升级/降级) + 交叉验证   更新后的标的库 + 一致性检查
盘中(9:30-15:00) 实时行情更新                         标的库内股票实时价格监控
盘中触发    L3 阶段变更检测 + L3+ 策略信号重算        标的状态变化通知
盘后(15:30) data_daemon 日终同步+全量预计算            新数据就绪
```

当标的库中某只股票的状态变化时，系统主动通知用户：

### 8.3 用户操作记录与反馈闭环

```
用户操作 → 系统记录 → 预测 → 验证 → 反馈到模型

例如:
  1. 系统推荐建仓平安银行@11.5
  2. 用户记录"已建仓500股@11.5"
  3. 系统记录该操作
  4. 一个月后平安银行涨到12.8
  5. 系统计算: 推荐准确 ✓ 回报率 +11.3%
  6. 反馈到L3评分模型: 类似信号权重适当提升
  
  或:
  1. 系统推荐建仓西藏矿业@28.5
  2. 用户已建仓
  3. 跌破止损24.5
  4. 系统触发"止损提醒"
  5. 系统计算: 该笔推荐失败
  6. 分析失败原因: 碳酸锂价格暴跌超预期
  7. 反馈到风险模型: 增加原材料价格波动风险标签
```

| **Greenblatt 神奇公式** | 高质量(ROIC)+低估值(EBIT/EV)的二维筛选 | 价值型管线：估值质量+财务质量双维评分 |
| **Howard Marks 周期理论** | 识别市场所处阶段比预测更重要 | 阶段判定引擎：先判定阶段再评分 |
| **缠论「走势终完美」** | 任何趋势都有完成的结构 | 趋势型管线包含走势结构分析 |
| **桥水投资原则** | 系统化决策+透明原因+持续反馈 | 证据链透明+操作记录反馈闭环 |
| **主动投资组合管理** | 信息比率=超额收益/跟踪误差 | 标的库提供可跟踪的基准 |
| **Carbon Collective** | 问「股票在做什么」而非「股票是什么」 | 从静态分类到动态行为识别 |
| **Morningstar 股票评级** | 公允价值区间+星级评级 | 估值区间+安全边际+建议持仓 |
| **Wind 行业树** | 多维度交叉数据呈现 | L2 多维标注+四管线并行 |

## 十二、关键决策记录

| 编号 | 决策 | 选择 | 替代方案 | 理由 |
|------|------|------|---------|------|
| D1 | 管线结构 | 四管线并行 | 三层串行过滤 | 避免"一层不准全链失效"问题 |
| D2 | 主力识别 | 阶段判定→评分 | 等权评分→排序 | 阶段判定优先，不同阶段采用不同评分标准 |
| D3 | 风险处理 | 标签化(不剔除) | 规则过滤剔除 | 不替用户做决策，提供信息让用户自决 |
| D4 | 标的库范围 | 仅纳入管线输出 | 全市场候选+入库 | 避免淹没在5000只中 |
| D5 | 操作周期 | 管线自带周期标签 | 统一周期输出 | 不同管线自然对应不同周期 |
| D6 | 微小盘处理 | 仅出现在事件型管线 | 在所有管线中出现 | 微小盘多数不适合作为主要投资标的 |
| D7 | 估值方法 | 多方法链(按优先级) | 单一估值方法 | 不同行业适用不同方法 |
| D8 | 旧系统兼容 | 增量替换，路由共存 | 一刀切替换 | 前端改造量小，逐步过渡 |
| D9 | Factor 定位 | 跨管线用户自定义增强层 | 作为单独管线 | Factor 本质是用户可以组合的因子集合，不限定在某一条管线 |
| D10 | Vibe 定位 | 跨管线用户自定义增强层，分级管理(sandbox/trial/trusted) | 作为单独策略类型 | Vibe 是 LLM 生成的个性化策略，质量不确定，需要通过分级控制风险 |
| D11 | 标的库评分 | 双分层：基础引擎评分(不变)+Factor/Vibe加成(可变) | 单层混合评分 | 用户会频繁修改Factor/Vibe配置，如果混在一起每次都需要全面重算，且可能导致标的库剧烈震荡 |
| D12 | 信息架构 | 四层级展示（市场总览→标的库→管线发现→个股搜索） | 单一列表展示 | 机会图谱本质是地图不是列表，用户需要缩放导航能力而非逐行浏览；四层级对应不同使用场景 |
| D13 | Treemap 方块大小 | 机会地图模式下由**评分**决定而非市值 | 固定由市值决定 | 确保评分高的小盘股不会被淹没 |
| D14 | 前置过滤 | ST/*ST/退市/面值退市/市值退市——约200只，窄口径剔除 | 全部标签化不剔除 | 有确定性本金永久损失风险的股票不应进入任何计算管线或展示；口径必须窄，不误伤正常标的 |
| D15 | 管线→标签引擎 | 引擎统一产出标签，四条管线改为四组预设场景（标签组合快捷入口） | 引擎按管线分配 | 同一引擎（如缠论）对长线和短线有不同的识别逻辑和数据需求；改为标签后引擎只需产出标签，不由引擎决定管线归属 |
| D16 | Treemap 机会地图颜色 | 颜色=持有周期（蓝=长线、绿=中线、橙=短线、红=超短/做T、灰=无信号） | 颜色=策略类型（价值/趋势/事件/技术） | 用户不需要理解策略术语；"长线/中线/短线/超短"是自然语言，零学习成本 |
| D17 | 价值地图大小 | 前收盘价（行业内比较） | 流通市值 | 用户对价格敏感，行业内价格可比性强；配合估值颜色可直观看出"贵不贵" |
| D18 | 标签筛选交互 | 多标签 AND 组合过滤 Treemap + 预设场景按钮 | 固定四条管线推荐列表 | 用户灵活度最大，可自由组合任意标签；预设场景作为"新手引导" |

## 十三、最终效果对比

| 维度 | 当前选股系统 | 新机会图谱 |
|------|------------|-----------|
| **输出内容** | 评分排序列表 | 机会全景地图（Treemap + 标的库看板 + 管线发现卡） |
| **信息架构** | 单一列表展示 | **四层级展示**：市场总览(地图)→标的库(连续跟踪)→管线发现(新机会)→个股搜索(按需查询) |
| **对用户的帮助** | 低(只知道哪只可能好) | 高(知道是什么、为什么、怎么做) |
| **机会连续性** | 无(每天新列表) | 有(标的库+状态变更跟踪) |
| **风险控制** | 规则剔除(一刀切，24.8%剔除率) | **双层风控**: 前置过滤(窄口径，4-5%，仅退市风险) + 标签化(可逆风险，不下架) |
| **主力识别** | 等权评分(出货期也可能高分) | **多源阶段判定引擎**（5个独立来源交叉验证，仅建仓/洗盘期推荐） |
| **估值维度** | 无 | 估值分位+行业对比+合理区间（完全新建） |
| **策略构成** | 预设固定策略 | 基础引擎(固定) + Factor组合(用户自选) + Vibe策略(用户自建)，全部统一产出标签 |
| **引擎与管线关系** | 引擎按管线划分（每个引擎属于一条管线） | **标签引擎架构**：引擎统一产出标签→标签池→前端标签筛选，不限定管线归属 |
| **用户自定义** | 无 | Factor组合(可引用任意标签做加权) + Vibe策略(可计算任意标签) |
| **策略扩展性** | 不支持的无法扩展 | FactorRegistry可注册新因子，Vibe可LLM生成新策略，新引擎只需产出新标签 |
| **用户机会发现方式** | 查看四条管线的推荐列表 | **Treemap 标签筛选**：多标签 AND 组合 + 预设场景快捷入口，灵活度最高 |
| **策略变更影响** | — | 标的库评分分层（基础不变+用户层重算），防止剧烈震荡 |
| **管线一致性** | 各策略独立计算不通信 | 交叉验证仲裁层（8条仲裁规则） |
| **操作指导** | 无 | 建仓/加仓/持有/做T/止损全流程建议 |
| **用户反馈** | 无 | 操作记录→验证→模型优化闭环 |
