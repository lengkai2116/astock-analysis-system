## 一、只读实证（2026-09-26，库在 `data/duckdb/` 分库）

### ① lhb_cache（system_cache.db）— 主因是**口径**，非采集缺口

- 覆盖：去重 **680** 只 / **1459** 行 / 日期 **2026-08-18 ~ 2026-09-24**（≈1 个月）；每日上榜 **50–70** 只。
- QA 规则：`lhb_cache: check_mode='nonempty'`（`stg_quality.py:89`）→ **只要非空即过，不校验覆盖率** → **QA 不报此项**。
- 482 的「覆盖过低」实际来自 **dim1 门禁**：`lhb_df` 在 `optional` 契约内，某股无上榜记录 → `get_cached_lhb` 返空 → 计入 `missing_tables` → `quality_level='degraded'`（8 股中 7 只）。这也正是 461-14 修复后实测 `completeness=0.9565`（=22/23）的那 1 个 missing。
- 消费端核实：`event_monitor._detect_longhubang`（:481）只取该股**最近一条**（`sort_values('trade_date', desc).iloc[0]`）→ **1 个月深度对当前消费足够**。
- **定性**：**「稀疏事件表被当作应载契约」的口径问题**（与 441 号「指数不存在股东人数却被判素材缺失」同类）。真正可选的是「加深历史」，而非「修覆盖」。
- ⚠️ 佐证：龙虎榜天然稀疏（全市场仅 ~680 只/月上榜），**「7/8 只无数据」是正常现象**，不是缺陷。

| 60min | **1** | 1,589 | — |

60min 唯一归属 `300649.SZ`。**生产链路实证**：

- **实时分钟产出只有 1min**：`mootdx_collector._MINUTE_AGG_FREQ='1min'`（5s 快照自聚合，:890）。
- **全市场 1min 历史回填已成死路径**：`_batch_backfill_minute_kline`（Tushare `pro_bar freq='1min'` 逐只，:6813）的**唯一调用者** `_run_minute_backfill`（:6895）已在 414 号 R20 因「移除 v1 Tushare 回填，仅保留 v2 mootdx」被**注释停用**（:2531-2534）。现存 1min 全市场数据为停用前的遗留。
- **5/15/30/60min 聚合无全市场链路**：`minute_backfill.aggregate_minute`（1min→5min→15/30/60）仅被 `run_backfill_all` 调用，而 `run_backfill_all` 由 `_run_minute_backfill_v2` → `_check_watchlist_minute`（:2410）驱动，**只覆盖「自选股」**；实测 `data/app.db` 的 `watchlist` **仅 1 条** → 只有 1 只股有 5/15/30/60min。
- 消费端：dim1 载入 `hourly_df` → dim2 457 `data_context['hourly_df']`（`dim2_structure_engine.py:128`）；缺失时 W+D 降级（**457 设计内可降级**，不阻塞主链）。
- **定性**：**真缺口**——全市场 60min 多周期级联实际退化为「周线+日线」。但 **1min 已有全市场数据（5211 只）** → 补 60min 可**本地聚合（CPU-only，零 API）**，成本低。

### ③ margin_cache（market_cache.db）— **真缺陷（部分入库 + 口径结构性错误）**

每日覆盖（`COUNT(DISTINCT ts_code)`）：

| trade_date | 覆盖 | 说明 |
|---|---|---|
| 2026-09-24 | **2002** | ⚠️ 仅 ≈45% |
| 2026-09-23 | 4451 | 正常 |
| 2026-09-22 | 4450 | 正常 |
| 2026-09-21 | 4448 | 正常 |
| … | 4443–4448 | 正常 |

`daily_cache` 当日 `COUNT(*)`=**5592**（含指数）。

- **问题 a（采集）**：09-24 部分入库（2002 vs 常态 4451）且**未回补**。根因——`run_integrity_check` 对 margin **只做「`MAX(trade_date)` 滞后 ≤7 天」检查**（:1974-1998），`margin_cache` **不在带行数阈值的 `checks` 列表内**（:1931-1935 只含 daily/basic/moneyflow/stk_limit/lhb）→「最新日已存在但行数不全」**永不触发补采**。
- **问题 b（口径）**：QA 规则 `margin_cache: rows_ratio=0.95`，基准 `N=daily_cache COUNT(*)`（`stg_quality.daily_base`，:311）→ 阈值 `int(5592×0.95)=5312`；而 margin 理论最大覆盖 ≈**4451**（融资融券标的集）→ **5312 永远不可能达到，此项结构性恒失败**（`stg_quality.py:83`）。
- **定性**：**真缺陷**（补采 + 校验口径修正），且口径错误会让 QA 永久告警。

### ④ indicator_ma（compute_cache.db）— **主因口径（分母含指数）+ 残余新股缺 MA（阈值内正常）**

- 覆盖：09-24 = **5510**（前几日 5508–5510 稳定）。QA：`rows_ratio=0.99`，原基准 `int(5592×0.99)=5536` → `5510 < 5536` → 报 `5510/5536（99% < 99%）`。
- **核对（更正初判）**：`daily_cache@09-24` 全部 **5592** 个代码中，指数仅 **36** 个——
  `000001.SH / 000300.SH / 399001.SZ / 399006.SZ / 899050.BJ`（5 宽基，含 2 个 `000xxx.SH`）
  + **31** 个 `8010xx/8017xx/8018xx/8019xx.SI`（申万一级行业指数）。**个股 = 5556**。
- 无 `indicator_ma` 的代码实为 **82** 个 = 36 指数 + **46 只真实个股**；46 只经核**全为新股/次新**
  （`daily_cache` 数据天数 1–55 天、首见日 2026-07~09，如 `920025.BJ` 仅 1 天、`601091.SH` 4 天）——
  历史不足（MA5/MA20/MA60 窗口未满）→ 不产 indicator_ma，**属正常边界，非缺陷**。
- **结论**：QA 报错为**口径问题**（分母 5592 含 36 指数，且 `5510/5536` 被展示为「99% < 99%」的边界假失败）；
  按个股宇宙 5556 计，`5510/5556 = 99.17% ≥ 99%` → **通过**（残余 46 新股在 1% 容差内）。
  ⚠️ 更正：初判「缺的 82 个全是指数」不成立（ORDER BY 使指数排前致误读）——另 46 只为新股，非指数。
- **定性**：**口径问题（假失败）**，修口径即消除；残余 46 只为新股正常缺失，不补。

### ③ 补充实证（源侧 + 假期因素）

- `_batch_margin('20260924')` 回补后仍 **2002** 条；直接调源 `provider.get_margin_detail` 对照：
  `20260924 → 2002 行（仅 `exchange={'SH': 2002}`）`、`20260923 → 4451 行（SH 2002/SZ 2106/BJ 343）`
  → **缺口精确为深市 2106 + 北交所 343，沪市 2002 齐**。
- **第二源交叉验证**：深交所官方接口（AKShare `stock_margin_detail_szse`）`20260924 → 0 行`、
  `20260923 → 2106 行`（与库中 SZ 数**完全一致**）→ 两条独立源一致确认**源侧未发布**，非本地采集缺陷。
- **机制性解释（2026-09-26 补充，用户提供假期信息 + 系统日历核实）**：系统日历确认 **09-25(五)/09-26(六)/09-27(日) 为假期**，
  09-24 为节前最后交易日，下一交易日 = **09-28(一)**。上交所当日发布（09-24 SH 已到）；深/北交所**次一交易日**发布，
  09-24 的发布窗口（09-25）恰逢假期 → **顺延至节后首个交易日（09-28）**。
  佐证：margin_cache 全部 **83 个交易日**（2026-06-01~09-24）中，**仅 09-24** 出现「SH 有 / SZ·BJ 无」。
  → 属**发布机制 + 假期顺延**，非缺陷；节后 daemon 巡检（新增的行数完整性检查）会自动补齐。
- 同理：`daily_cache` 最新 = 09-24 也**正常**（09-25 起放假无交易），非「源侧滞后」。
- 故 ③a 的处置重点在**检出与自动重试**（已具备，日志实证见下），③b 的 QA 基准口径错误则必须修（见下）。
  **日志实证（daemon 重启后首轮巡检）**：
  ```
  10:33:37 [融资融券] 最新 2026-09-24，滞后 2 天 ✅
  10:33:37 [融资融券] 最新 2026-09-24 行数不足 2002/4451（<90%），回补...
  10:33:37   → 回补 2002 条        # 源仍只返回沪市 2002，无净增；节后将自动收敛
  ```

## 三、处置决定与实施（2026-09-26 用户拍板：**口径层 + 采集层全实施**；② 采**日终本地聚合落库**）

### A. 口径层（已实施）

1. **统一「个股宇宙」SSOT**：新增 `backend/app/data/market_universe.py`（`BROAD_INDEX_CODES` + `SW_INDEX_CODES` + `is_index_code()` + `stock_only_sql()`），为唯一定义。
   - `stg_quality.daily_base` / `WriteGateway._daily_base`：分母改为**仅个股**（`stock_only_sql` 谓词）。
   - `data_daemon`：438 号常量迁入该模块（保留同名导入兼容 `scripts/_441_*`）；`_get_active_codes`、RPS 股票池改用 `is_index_code`（后者原内联条件**漏 399 段**，致 `399001.SZ/399006.SZ` 宽基被误纳入 RPS 池，一并修正）。
   - `stg_quality.QUALITY_RULES['margin_cache']` 增 `baseline:'self'` + 新 `_baseline_rows()`：以表自身近 20 日峰值为基准（`0.95×4451`），替代 `daily_cache` 全量锚。无历史时不误报。
2. **① dim1 契约**：`lhb_df` **从 `optional` 移出**（与 QA `lhb_cache: nonempty` 一致），仍加载进 `data_context` 供 dim4/dim6 消费。
   - 连带：dim1 契约基数 **23 → 22**（461-14 的测试断言已同步为 21/22）。

### B. 采集层（已实施）

3. **③ margin**：`run_integrity_check` 在「滞后未超阈值」分支内增**最新交易日行数完整性**检查（行数 < 近 20 日峰值的 90% → 触发 `_batch_margin` 回补）。
   - ⚠️ 回补后仍 2002：双源（Tushare + 深交所官网）确认 09-24 **深/北交所未发布**——上交所当日发布（SH 已到），深/北交所次一交易日发布，09-24 的发布窗口 09-25 恰逢假期 → 顺延至 **09-28**。属发布机制 + 假期顺延，**非缺陷**；机制已可检出（日志实证见 §一），节后自动收敛。`daily_cache` 最新=09-24 同理正常。
4. **② 60min**：`minute_backfill.aggregate_1min_to_60min()`（1min 本地聚合 → 60min，零 API，幂等）+ `_cache_to_ecm` 补 `trade_date`（原聚合结果无 trade_date，落 NULL 致按日检索/去重失效）；`data_daemon` 新增 `_check_minute_60min()`（以「最新 1min 交易日 60min 覆盖」为闸门，只聚合缺失股）并挂入日终同步。
