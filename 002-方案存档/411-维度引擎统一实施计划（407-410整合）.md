# 411号 — 维度引擎统一实施计划（407-410号方案整合）

---

## 一、整合背景

407-410号方案分别覆盖维度引擎改造的不同方面，存在以下需要整合的问题：

| 方案 | 覆盖范围 | 状态 |
|------|---------|------|
| 407号 | 旧路径剔除 + dim4/dim5 RAW迁移 | 待实施 |
| 408号 | dim1重构（已废弃） | 被409号取代 |
| 409号 | dim1数据质量门禁层改造 | 待实施 |
| 410号 | dim2-dim7 RAW前置计算审计与迁移 | 待实施 |

**需要整合的原因**：

1. **408号被409号取代**：408号的调用顺序设计（dim1移到最后）在409号中被修正（dim1必须排第一），408号不再独立实施
2. **407与410存在冲突**：407建议5说"dim7保持现状"，410审计发现dim7存在可迁移的RAW违规；407建议3说"dim2/dim3保持现状"，410发现dim2/dim3存在MA/MACD/RSI重复计算
3. **407与410存在重叠**：dim4/dim5的RAW迁移在两个方案中都有覆盖，410范围更广
4. **409与410有依赖**：409的dim1数据准备层改造影响410的dim2-dim7数据获取方式
5. **407与409有依赖**：407的旧路径剔除影响409的dim1调用位置

### 冲突解决原则

| 冲突 | 解决方式 |
|------|---------|
| 407建议5（dim7保持现状）vs 410 Phase 6（dim7 RAW迁移） | **以410为准** — 407未做逐行审计，410审计证明dim7存在PE/PB/PS分位等标准公式的3处重复计算 |
| 407建议3（dim2/dim3保持现状）vs 410 Phase 1（改读预计算表） | **两者不矛盾** — 407说"分析逻辑不能完全预计算"（正确），410说"分析逻辑内部的标准指标改读已有预计算表"（补充优化） |
| 407建议4（dim1保持现状）vs 409（dim1重构） | **以409为准** — 407基于"dim1是纯分析引擎"的旧认知，409重新定义dim1为数据质量门禁层，dim1不再保留任何原有分析功能，全部迁移到JUD |
| 407 dim4/dim5 RAW vs 410 dim4/dim5/dim6/dim7/dim3 RAW | **以410为准** — 410覆盖范围是407的超集 |

## 二、统一数据分层定义

| 层 | 代号 | 定义 | 产出 |
|---|------|------|------|
| **COL** | 采集层 | 外部数据源采集 | 原始行情/财务/资金数据（原料数据） |
| **RAW** | 加工层 | **简单数学公式加工**（非分析类单纯计算加工） | 指标（MA/MACD/RSI/BOLL/SSRP/ATR等，加工数据） |
| **SIG** | 分析层 | 策略分析（提取STG存储层的原料数据和加工数据） | 半成品（信号/判定/评分） |
| **JUD** | 判定层 | 判定整合和操作建议 | 成品 |
| **OUT** | 成品仓 | 存储供前端消费 | 最终输出 |

> 注：本定义需同步更新到353号方案§二。

### 3.4 跨Phase协同规则

Phase 5（改读预计算表）和Phase 6（data_context改造）对dim4存在**交叉改动**——dim4的evaluate()既要改MA读取方式（Phase 5），又要加data_context参数（Phase 6）。**对dim4必须按Phase 5先、Phase 6后的顺序串行执行**，避免同一文件的并发改动冲突。dim2/dim3/dim5/dim6/dim7无此约束（Phase 5和Phase 6在这些引擎上不重叠）。

**Phase 5与Phase 2-4的并行说明**：Phase 5改读预计算表是dim引擎内部的指标获取方式变更（通过DataAwareMixin/ECM访问indicator_ma/macd/other），不经过data_context。Phase 2-4改造的是dim1的职责和data_context传递机制。两者改动维度不同，无代码冲突，可以并行执行。

### 3.5 降级策略（来自409号§5.6）

dim1数据门禁失败时的端到端降级路径：

```

  │
  ├── dim1返回：data_context=None + status_quality标注"数据未经门禁校验"
  │
  ├── dim2-dim7：回退到独立SQLite查询（data_context参数为None时触发回退路径）
  │
  ├── dim_adapter：signal因子使用默认值
  │     ├── direction=0（中性）
  │     ├── strength=0.5（默认）
  │     └── reliability=0.5（中等）
  │
  ├── dim8：signal_confirm降级到tags.right_side_confirm（RAW预计算标签）
  │
  └── 最终输出：标注"data_quality":"degraded"
```

**降级原则**：不中断、可追踪、可恢复。下次daemon运行时重新触发dim1门禁，数据恢复后自动升级。

### 3.5.3 dim1在engine_map中的位置变更

**旧结构**（当前）：dim1在engine_map循环中与其他引擎一起执行（status_engine.py L222-243），7个引擎统一接口。

**新结构**（Phase 3完成后）：dim1从engine_map循环中移出，改为status_engine中的独立预处理步骤：

```python
# 新流程
def _build_dim_engine_results(self, tags, signals, dims, lifecycle):
    # Step 1: dim1数据门禁（独立调用，非engine_map循环）
    dim1_result = self._run_dim1_gate(ts_code, tags, lifecycle)
    data_context = dim1_result.get('data_context')

    # Step 2: dim2-dim7执行（engine_map仅含6个引擎）
    results = {'signal': dim1_result}
    for dim_name, (module_path, class_name) in engine_map.items():
        engine = instantiate(module_path, class_name)
        results[dim_name] = engine.evaluate(dims, tags, signals, lifecycle,
                                            data_context=data_context)
    return results
```

### 3.6 边界案例处理规则（来自410号§4.2）

以下6处计算属于"RAW和SIG耦合"——分析逻辑中用到标准指标值，但指标值本身应改读预计算表。**处理规则：保留分析逻辑不变，仅将指标值的数据来源从raw重算改为读预计算表**。

| # | 引擎 | 位置 | 分析逻辑（保留SIG） | 指标值来源（改读RAW） |
|---|------|------|-------------------|---------------------|
| 1 | dim4 | MainForceScorer.identify_phase() | RSI背驰检测+阶段分配规则 | RSI值改从`indicator_other`读取 |
| 2 | dim4 | MainForceScorer._score_volume_price() | MA对齐分析+量价评分 | MA值改从`indicator_ma`读取 |
| 3 | dim4 | ChipScorer._calculate_v2_score() | 筹码评分逻辑 | MA值改从`indicator_ma`读取 |
| 4 | dim5 | _bociasi_quickline() | BOCI快线信号判断 | MA5改从`indicator_ma`读取，量比改读预计算 |
| 5 | dim5 | _time_rhythm() | 盘整节奏分类 | MA20/std20改读`indicator_ma`+`indicator_other` |
| 6 | dim7 | _fina_health() | ROE/ROCE阈值判断(>6%/>15%) | ROE/ROCE原始值改读预计算 |

**实施要求**：Phase 5/6改造这6处时，必须保留其分析逻辑分支结构，仅替换数据获取方式。不得删除分析条件或改变阈值判断逻辑。
