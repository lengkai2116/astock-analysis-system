# 392 — SIG环节系统架构与能力说明

> **文档定位**：本文档基于系统代码实际实现倒推编制，描述SIG（策略信号）环节的真实架构、运行流程、8引擎能力及输出，反映2026-09-17代码审计后的系统现状。

---

## 一、SIG环节定位

SIG是数据管道第5步（COL→RAW→SIG→JUD→OUT），负责**股票现状描述**——将原始行情数据转化为结构化的多维度分析结论。

**核心职责**：
1. 7个维度引擎独立分析，输出`{status_description, judgment, audit}`
2. 1个总结引擎整合7维结果，输出红绿灯+共识率
3. 生成三份产物：`signal_json`（5引擎信号）+ `seven_dim_json`（七维描述）+ `dim_results_json`（维度预计算供JUD消费）

**设计原则**：
- 每个引擎独立运行，无引擎间依赖
- 统一接口 `evaluate(dims, tags, signals, lifecycle) → {status_description, judgment, audit}`
- 失败降级：单引擎异常不影响其他引擎

## 二、管道执行流程

### 2.1 执行入口

```
data_daemon.py _run_daily_pipeline()
  → _run_pipeline_step(today, 'SIG', _sig_build, codes)
    → _precompute_strategy_signals(codes)
```

**前置条件**：SIG步骤状态≠done
**重试机制**：失败后最多重试3次（retry_count<3 → pending重入）
**幂等锁**：`mark_step_running()` 防止并发tick重复执行

### 2.2 执行步骤

```
_prewarm_weekly_cache(codes)                    1. 周线缓存预热
  → UnifiedStrategyCore.compute_batch(codes,    2. 5引擎信号并行计算
      max_workers=4)
  → for code in codes:                          3. 逐只7引擎维度预计算
      _se_engine._load_tags(code)                 → pre_feat_cache读标签
      _se_engine._load_signals(code)              → strategy_signal_detail读信号
      _se_engine._signal_lifecycle(code)          → 计算生命周期
      _se_engine._build_dim_engine_results()      → 7引擎evaluate()
      generate_seven_dim_from_signals()           → 七维描述生成
  → _batch_write_signal_detail(rows)            4. 批量写入
```

### 2.3 写入机制

- **独立短连接**：非daemon共享conn，`busy_timeout=10s`
- **批量事务**：`executemany` + 单次commit（2026-08-16死锁根治方案）
- **写入SQL**：`INSERT OR REPLACE INTO strategy_signal_detail`

### 2.4 降级路径

| 故障场景 | 降级策略 |
|----------|----------|
| 单引擎异常 | `results[dim_name] = None`，其他引擎继续 |
| dim_results全空 | status_engine.evaluate()返回None |
| SIG全量失败 | `_write_factor_signals(codes)` 回退因子信号 |
| dim_results预计算失败 | SIG仍写入signal_json+seven_dim_json，dim_results_json=None |
| 周线缓存预热失败 | 不影响主流程（warning日志） |

## 四、各引擎详细能力

### 4.1 Dim1 信号确认引擎

**职责**：判定当前信号处于生命周期的哪个阶段，评估信号质量和共振程度。

**分析流程**：
1. 7类信号属性分类：`right_confirmed`（右侧确认）/ `right_emerging`（右侧初现）/ `trend_running`（趋势运行）/ `left_probing`（左侧试探）/ `risk_warning`（风险警示）/ `neutral`（中性）/ `exit`（退出）
2. 5维度共振评分：结构/量价/资金/情绪/估值各维度是否支持信号方向
3. 衰减检测：信号持续天数、是否验证（3日不破）、衰减分数
4. 生命周期阶段：初期（1-3天）→ 中期（4-12天）→ 已延伸（>12天）

**输出字段**：
- `status_description`：attribute, strength, maintenance, lifecycle_days, lifecycle_stage, verified, decay_detail, evidence(4条), plain
- `judgment`：attribute{code,light}, strength{level,light}, maintenance{status,light}, overall_light, overall_direction, continuous_value
- `audit`：按属性分类的conditions（3-5条）

**evidence**：4条结构化证据（信号类型、强度、衰减、风险交互）

### 4.2 Dim2 结构位置引擎

**职责**：基于缠论理论分析股票的技术结构位置，判断当前处于趋势的哪个阶段。

**核心算法**：
1. **缠论全栈**：分型识别→笔划分→线段构建→中枢识别→背驰检测→买卖点标注
2. **多级别联立**：日线+周线+月线三级别趋势一致性分析
3. **123法则**：趋势结构突破确认（1-趋势线突破，2-回测不破，3-创新高/低）
4. **支撑阻力位**：基于中枢上下沿+MA+前高低点计算

**输出字段**：
- `status_description`：vs_zhongshu(完整dict), vs_ma(完整dict), vs_sr(完整dict), chanlun_phase, chanlun_strength, chanlun_strength_components, buy_sell_points_detail, divergence_type, level_trends, level_cross_score, trend_structure_signal, evidence(7个子evidence), plain
- `judgment`：overall_direction, overall_light, continuous_value, structure, light
- `audit`：级别验证、趋势方向、中枢数量、背驰检测

**evidence**：7个子系统独立evidence（chanlun_direction/phase/strength/buy_sell/divergence/level/trend_structure）

### 4.3 Dim3 量价健康引擎

**职责**：分析成交量与价格的配合关系，判断量价健康度和趋势持续性。

**核心算法**：
1. **量价四阶段链**：吸筹→拉升→派发→下跌
2. **9种VP-形态**：价涨量增/价涨量缩/价跌量增/价跌量缩等
3. **背离检测**：MACD顶底背离+量价背离
4. **50+种K线形态**：头肩/双底/三角/旗形等
5. **状态机方向判定**：BUY/SELL/HOLD/WATCH四态
6. **多周期一致性**：日线+周线趋势是否一致
7. **R乘数仓位管理**：基于盈亏比的仓位建议

**输出字段**：
- `status_description`：stage_name, state_machine_direction/confidence/label, resonance_score, multi_timeframe_consistency, entry_zone, target_zone, fake_breakout, supply_demand, vol_ratio, divergence, evidence, risk_notes, plain
- `judgment`：vp_state, light, overall_light, overall_direction, continuous_value
- `audit`：阶段判定、量价配合、背离检测、多周期一致性

### 4.4 Dim4 资金筹码引擎

**职责**：分析主力资金行为和筹码分布，判断资金阶段和筹码健康度。

**核心算法**：
1. **8维度加权共识**：筹码形态+资金流向+量价阶段+ASR+趋势+SSRP+缠论+涨停交叉
2. **TradingPhaseDetector**：五阶段检测（吸筹/建仓/拉升/派发/下跌）
3. **ChipDistributionEstimator**：筹码分布估算
4. **筹码因子**：SSRP/ASR/集中度/获利比/CYQKL/RSI
5. **PDE冲突检测**：阶段判定内部矛盾检测

**输出字段**：
- `status_description`：phase, phase_confidence, fund_flow, pde_conflict, pde_price_position, retail_institution, pde_vote_ratio, cost_concentration, crowding/level/score, evidence(7个子evidence), plain
- `judgment`：phase, direction, light, overall_light, overall_direction, continuous_value
- `audit`：五源共识、阶段确认、数据充足性、冲突检测

### 4.5 Dim5 情绪环境引擎

**职责**：评估市场情绪温度和所处阶段，为均值回归策略提供方向信号。

**设计要点（均值回归）**：
- 冰点(ice) = 反转看多机会（恐慌创造低估）
- 积极(positive) = 过热看空风险（亢奋追涨危险）
- 与直觉相反，需特别注意

**核心算法**：
1. **三层面评估**：市场层（BOCIASI四象限）+ 板块层（热度排名）+ 个股层（情绪标签）
2. **BOCIASI快线**：4指标融合（涨跌停比/融资变化/量价背离/波动率）
3. **BOCIASI慢线**：ERP（股权风险溢价）
4. **情绪温度**：7维度加权（涨跌停/融资/量价/波动/PE/换手/北向）
5. **时间节奏**：BOLL带宽判断变盘窗口

**输出字段**：26个（market_phase, temperature, bociasi_quadrant, sector_heat, stock_emotion, evidence(3层), plain等）

### 4.6 Dim6 风险边界引擎

**职责**：量化风险等级，提供支撑阻力位、盈亏比、波动率等风控参数。

**核心算法**：
1. **5级风险判定**：极低/低/中/高/极高
2. **几何化支撑阻力**：MA20+近20日低点取高者（近端结构位）
3. **盈亏比计算**：(目标价-现价)/(现价-止损位)
4. **ATR波动率**：14日ATR百分比+历史分位数
5. **事件监控**：EventMonitor检测监管/财务/市场事件
6. **失效条件**：基于支撑位和事件构建

**输出字段**：22个（risk_level, support_price, resistance_price, rr_value, atr_pct, volatility_percentile, invalidation, risk_evidence, plain等）

### 4.7 Dim7 估值引擎

**职责**：多锚点加权合成估值，判断当前估值水平和财务质量。

**核心算法**：
1. **四锚加权**：PB锚+PE锚+FCF锚+股息率锚，按行业分类加权
2. **财务质量评分**：ROCE/ROE检测
3. **7维潜力评分**：增长/盈利/估值/质量/动量/情绪/资金
4. **截面百分位**：PE/PB/PS在5年历史中的百分位

**输出字段**：20个（composite_rating, valuation_level, pe_percentile_5y, potential_score, valuation_evidence, plain等）

### 4.8 Dim8 状态总结引擎

**职责**：纯整理输出——读取dim1-dim7结果，组装八维红绿灯、共识率、状态条。

**不产生判定**，仅汇总展示。

**输出字段**：status_bar, eight_dim_summary, consensus_rate, conflict_count, conflicts, text, plain

## 五、引擎注册与调度

### 5.1 注册表

```python
engine_map = {
    'signal':       ('dim1_signal_engine', 'Dim1SignalEngine'),
    'structure':    ('dim2_structure_engine', 'Dim2StructureEngine'),
    'volume_price': ('dim3_vp_engine', 'Dim3VPEngine'),
    'chip_fund':    ('dim4_chip_fund_engine', 'Dim4ChipFundEngine'),
    'emotion':      ('dim5_emotion_engine', 'Dim5EmotionEngine'),
    'risk':         ('dim6_risk_engine', 'Dim6RiskEngine'),
    'valuation':    ('dim7_valuation_engine', 'Dim7ValuationEngine'),
}
```

- dim8不在engine_map中，在StatusEngine.evaluate()中单独调用
- 使用`importlib.import_module`动态导入

### 5.2 引擎间依赖

**无显式依赖**——各引擎独立运行，dim8通过`lifecycle['dim_results']`消费其他引擎结果。

### 5.3 数据依赖关系

```
dim1 ← tags(pre_feat_cache) + lifecycle(strategy_signal_detail)
dim2 ← daily_cache(OHLCV) + minute_kline_cache(周月线)
dim3 ← daily_cache + daily_basic_cache(换手率)
dim4 ← daily_cache + daily_basic_cache + moneyflow_cache + pre_feat_cache
dim5 ← daily_cache + daily_basic_cache + margin_cache + sentiment_pool_cache + pre_feat_cache
dim6 ← daily_cache + pre_feat_cache + DataManager(事件)
dim7 ← daily_basic_cache + fina_indicator + income + balancesheet + cashflow + pre_feat_cache
dim8 ← dim1-dim7输出
```

## 七、SIG→JUD接口

### 7.1 v390管线接口

**适配层**：`dim_adapter.py convert_to_factors(dim_results, tags)`

**输出格式**：13维因子，每个维度`{direction: -1/0/1, strength: float, evidence: list[str]}`

| 维度 | direction映射来源 | strength来源 |
|------|------------------|-------------|
| signal | SIGNAL_CODE_DIRECTION(right_confirmed→+1) | 固定0.5 |
| structure | judgment.overall_direction + buy_sell增强 | chanlun_strength+level_cross+continuous_value加权 |
| vp | state_machine_direction(BUY→+1) | sm_confidence×0.7+resonance×0.3 |
| chip_fund | judgment.phase→DIM_DIRECTION映射 | phase_confidence |
| emotion | _EMOTION_DIRECTION(ice→+1, positive→-1) | temperature距中性距离 |
| risk | risk_level+rr_value组合 | rr_value/3归一化 |
| valuation | composite_rating(≥0.5→+1) | cr+deviation加权 |
| time/finance/event/factor/position/signal_confirm | 从tags降级 | 默认0.5 |

### 7.2 未被JUD消费的字段

| 字段类别 | 说明 |
|----------|------|
| status_description.plain | 仅前端展示 |
| audit.conditions | 引擎自检用 |
| dim5旧兼容字段(market/sector/stock等) | 向后兼容 |
| dim8.eight_dim_summary | 前端红绿灯展示 |
