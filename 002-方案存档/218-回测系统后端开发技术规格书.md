## 1. 页面结构概览

回测系统用于验证组合策略机制在不同股票/不同历史时期上的有效性。核心回答三个问题：组合策略历史表现如何？哪些策略拖后腿？回测结果可信吗？

### 1.1 布局结构

```
┌─ page-header ────────────────────────────────────────────────────┐
│ 📉 回测系统 · 横截面回测 v2 · 组合策略引擎 · 多维验证走廊         │
├─ backtest-layout (grid: 320px + 1fr) ────────────────────────────┤
│ ┌─ 左侧配置面板(7区块) ─┬─ 右侧结果面板(9区域) ──────────────────┐ │
│ │ ① 策略组合            │ ① 绩效概览(5+X指标)                    │ │
│ │ ② 策略参数            │ ② 权益曲线+回撤(±1σ+基准切换)         │ │
│ │ ③ 回测模式(3-tier)   │ ③ 横截面多维矩阵(4判据×K股票)         │ │
│ │   判据多选(5项)        │ ④ 策略贡献度诊断(横截面平均)           │ │
│ │ ④ 标的范围(选股弹窗)  │ ⑤ 稳健性验证走廊(4判据卡片)            │ │
│ │ ⑤ 基准选择(7指数多选) │ ⑥ 情境分析(4市场状态切片)             │ │
│ │ ⑥ 日期/资金            │ ⑦ 交易明细(多股可筛选)                 │ │
│ │ ⑦ 高级选项(折叠)      │ ⑧ 参数优化与应用(三态切换)            │ │
│ └─────────────────────────│ ⑨ 修订建议(4类故障定位)              │ │
│                            └────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────┘
```

### 1.3 配置→结果数据流

```
配置面板 → 点击[开始回测]
  ├→ 验证配置(策略/参数/模式/标的/资金)
  │   快速模式: 1只股票, 仅基础回测, 无判据
  │   标准模式: 20~30只股票, 全4判据, ~15-25min(异步)
  │   深度模式: 30只, 全4判据+参数平原全量, ~40-50min(异步)
  ├→ POST /api/v3/backtest/strategy-run
  │   ↓ 返回 task_id
  ├→ 显示异步进度面板
  │   └→ 轮询 GET /api/v3/backtest/strategy-run/progress?task_id=xxx
  │       6阶段: 加载策略配置→读取数据→逐日期运行→横截面聚合→多维走廊→完成
  ├→ 完成后: GET /api/v3/backtest/strategy-run/result?task_id=xxx
  │   ↓ 渲染9区域结果
  └→ 可选: 切换基准 → GET /api/v3/backtest/benchmark/{code} 更新曲线
```

### 1.4 回测引擎信号数据流

```
indicator-ide策略配置(默认来源)
    ↓ sync/独立覆盖
回测配置面板: 策略组合(4激活+3禁用) + 权重 + 参数 + 标的(1-30只) + 模式
    ↓ POST /api/v3/backtest/strategy-run
后端横截面执行引擎:
  for ts_code in ts_codes (并行, 线程池):
    for date in [start_date, end_date]:  (每日回滚防前视偏差)
      → 各策略 analyze(date_slice)          (缠论/量价/筹码/多因子/BOCIASI)
      → UPFEngine → ConflictArbiter → UIDFEngine
      → backtest_v2.execute(signal)          (信号→交易执行)
    → SingleStockResult (绩效指标+交易明细+策略信号)
  横截面聚合:
    中位数/IQR(四分位距)/通过率/正收益占比
  多维验证走廊:
    4判据×K股票多维矩阵
    → 走步前推: walk_forward_consistency()
    → CSCV/PBO: cscv_validator.pbo()
    → 参数平原: optimizer.parameter_plateau()
    → 蒙特卡洛: monte_carlo_significance()
  → CrossSectionalResult
```

## 4. 缓存策略

| 端点 | 缓存Key | TTL | 策略 | 备注 |
|:-----|:--------|:----|:-----|:------|
| `GET indicator-config/{ts_code}` | `backtest:indicator_config:{ts_code}` | 5min | 短TTL | indicator-ide配置变更后清除 |
| `POST strategy-run` | — | 无 | 不缓存 | 写操作，结果按task_id存储 |
| `GET strategy-run/progress` | — | 无 | 不缓存 | 实时进度 |
| `GET strategy-run/result` | `backtest:result:{task_id}` | task生命周期 | 按task写入 | 完成后保留2h |
| `GET benchmark/{code}` | `backtest:benchmark:{code}:{dates}` | 1h | 长TTL | 基准指数数据相对稳定 |
| `POST optimize` | `backtest:optimize:{task_id}` | task生命周期 | 按task写入 | — |
| `GET optimize/snapshots` | `backtest:snapshots:{ts_code}` | 持久化 | 需DB写入 | 快照需永久保存 |

**特殊规则：**
- 标准/深度模式回测是**异步任务**（耗时15-50min），`_task_store` 使用内存字典 + Redis后备
- 单次回测产生约500KB-2MB数据（全量结果含逐日权益曲线+32行交易明细+全矩阵+建议文本）
- 任务完成后保留2h，超时自动清理；用户可通过"保存配置"触发持久化
- 并发上限：同时运行最多3个深度回测或5个标准回测

## 6. 已知差异（Discrepancies）

### D1: 结果面板9区域全Mock [P0]

`generateAllResults()`（L905-965）使用 `Math.random()` 动态生成所有9区域数据：
- 绩效指标：12只股票随机返回值→中位数/IQR计算
- 权益曲线：72个月 `randf(-40000, 80000)` 随机漫步
- 多维矩阵：随机分布🟢60%/🟡25%/🔴15%
- 策略贡献度/走廊/情境/修订建议：固定Mock
- 交易明细：4只股票×32行交叉生成

**优先级：** P0 — 全部需要 B4 端点替换

### D2: 进度模拟setTimeout [P1]

`runBacktest()`（L839-892）使用 6 阶段 `setTimeout` 模拟异步回测进度。每阶段根据 tier 参数动态计算 ETA（快速1000ms/标准2000ms/深度2600ms）。

**优先级：** P1 — 替换为 B3 实时轮询

### D3: 股票数据库51只硬编码 [P1]

`_btMockStocks`（L615-633）包含 51 只硬编码股票数据（代码+名称），`_selectedStocks` 数组无持久化。

**优先级：** P1 — 替换为 `GET /api/v3/chart/stock-list`（已有后端端点）

### D4: 策略列表硬编码（含P1/P2状态标签） [P1]

`_strategies` 数组（L638-647）硬编码 8 个策略条目（含 `status` 字段："✅已实现"/"⏳P1"/"⏳待实施"）。

**优先级：** P1 — 需从后端动态获取策略可用状态

### D5: 参数优化1.5s spinner模拟 [P1]

**优先级：** P1 — 替换为 B8 端点

"保存"按钮（L409: `showToast('💾 配置已保存')`）无实际持久化。回测配置面板的7区块参数全在内存变量中，页面刷新全部丢失。

### D7: "完成后通知"Toast-only [P2]

**优先级：** P2

### D8: 选股弹窗确认后Mock [P1]

`confirmStockSelection()`（L812-819）仅更新 `#scopeCount` 显示计数，不触发任何实际回测范围变更。`_selectedStocks` 数组页刷新即丢失。

**优先级：** P1

### D9: ECharts权益曲线全Mock [P1]

`initChart()`（L1213-1285）使用 `randf()` 生成中位数曲线、±1σ置信带、基准曲线、回撤曲线全部72个月数据。基准切换 `switchBenchmark()` 仅占位（无实际函数体）。

### D10: 前后端回测引擎分离 [架构]

当前后端存在 `backtest_v2.py` 回测引擎（含CSCV/走步前推等能力），但前端backtest.html原型完全独立开发，**两者尚未对接**。后端回测引擎的信号输出格式与前端9区域展示需要适配层。

**优先级：** P0 — 架构级任务，Phase 1 核心前提
