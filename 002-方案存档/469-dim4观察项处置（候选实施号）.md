## 一、逐项处置与实施记录

### 观察项 1：`retail_institution` 与 `phase` 不同源（一致性风险）——✅ 已实施
- **代码现状**：`_assess_retail_institution(tags)`（dim4）读 **tags** 的 `main_force_phase`/`fund_flow`；而 evaluate 的 `phase_info` 可能被 `PhaseDetectionEngine` 覆盖。两者重算结果与 tags 不一致时，`status_description['retail_institution']` 与 `['phase']` 自相矛盾。
- **改动**：
  1. `_assess_retail_institution(phase, fund_flow)` 签名改由 evaluate 传「当前生效的」phase/fund_flow（覆盖后取覆盖值、否则取 tags 值），不再自读 tags。
  2. evaluate 内新增 `_retail_phase`/`_retail_flow` 追踪变量（初始 tags 值，随 PhaseDetectionEngine 覆盖更新），覆盖块后统一调用。
- **实证**：8 股全链路——600036 出货期↔retail「主力出货」、拉升期股↔「中性」、688981 建仓期兜底↔「中性」，retail 与 phase 完全同源无矛盾。

### 观察项 2：`fund_price_divergence` 兜底路径无中性态——✅ 已实施
- **代码现状**：仅 `PhaseDetectionEngine` 失效时走 df 斜率兜底 `price_direction = 'up' if _s5 > 0.01 else 'down'`——5 日变化 ≤1%（平盘/微涨/微跌）一律判 `'down'`，与引擎的 up/down/mixed/no_trend 三态不对称。
- **改动**：兜底改三态 `'up' if _s5>0.01 else ('down' if _s5<-0.01 else 'no_trend')`——|变化|≤1% 判 no_trend，`_assess_fund_price_divergence` 的 `pd not in ('up','down')` → 数据不足 分支天然兼容（不再误判平盘为背离）。

### 观察项 3：`judgment.direction` 与 `fund_flow` 同值重复——保持现状（用户拍板 3留）
- **判断**：`direction` 是结构化键、归 JUD 消费；`detail` 是文案层供 dim8 叙事——**两层非冗余**，符合 437 去重原则的真实意图。保留。

### 观察项 4：`_flatten_pre_feat` 同名键覆盖风险——保持现状（用户拍板 4留）
- **判断**：`price_position`/`trend_alignment` 双组覆盖，2026-09-18 实测两组合值一致，非故障；加固成本高收益低。保留观察。
