# 385 — 维度6（风险边界）策略引擎升级方案

> **背景**：基于377号SOP阶段〇深度审查，对dim6风险边界引擎（2058行）进行全面代码阅读、Bug识别、输出规则审查、知识库对标，编制系统性升级路径。
>
> **核心原则**（358号§1.1 + 360号§5.1）：
> - **纯描述维度**：只描述风险现状，不生成买卖信号
> - **多源风险聚合**：财务/事件/波动率/盈亏比/流动性等多维度风险
> - **SIG环节定位**：输出风险现状描述数据，判定结论由JUD环节做出

---

## 一、引擎架构概览

### 1.1 引擎文件

| 项目 | 内容 |
|------|------|
| 引擎文件 | `dim6_risk_engine.py`（2058行） |
| 整合源文件 | risk_boundary_builder.py(382行) + advice_builder._geometric() + event_monitor.py(925行) + cscv_validator.py(307行) + eagle_sword_resonance.py(399行) |
| 核心组件 | Dim6RiskEngine / EventMonitor(20事件检测) / CSCVValidator(PBO过拟合检测) / EagleSwordResonance(鹰眼大宝剑共振) |
| 顶层函数 | calc_geometric() / _calc_volatility() / _assess_risk_level() / _list_risk_factors() / _assess_rr() / _build_invalidation() / _risk_plain() |
| 分析框架 | 多源风险聚合 + 几何化距离(支撑/阻力/盈亏比) + 波动率(ATR/历史分位) + 20类事件监控 + 鹰眼大宝剑双系统共振 |
| 数据来源 | daily_cache(OHLCV) + daily_basic_cache(PE/MV) + pre_feat_cache(tags: risk_level/volatility_level/fina_health/catalyst_event等) + forecast_cache + fina_indicator + income + cashflow + balancesheet + lhb_cache + margin_cache + stk_holder_cache + concept_cache |
| 输出对象 | status_description（现状描述）+ judgment（灯色判定）+ audit（条件稽核） |

### 1.2 组件调用链

```
Dim6RiskEngine.evaluate(dims, tags, lifecycle)
  ├─ _assess_risk_level(dims, l0, tags)        ← 5源风险聚合
  ├─ _list_risk_factors(tags, dims, l0)         ← 风险因素枚举
  ├─ EventMonitor.compute_tags(ts_code)          ← 20类事件检测
  │   ├─ A: earnings_surprise/confirm/report_date/dividend/fraud_sign
  │   ├─ B: share_float/pledge_risk/holder_reduce/underwater_ipo/buyback/incentive
  │   ├─ C: regulatory/delist_risk/st_warning/goodwill_risk
  │   ├─ D: longhubang/limit_move/holder_concentration/margin_risk
  │   └─ E: breakout/concept_heat
  ├─ calc_geometric(df)                          ← 几何化指标
  ├─ _assess_rr(geo)                             ← 盈亏比评估
  ├─ _calc_volatility(df, tags)                  ← 波动率计算
  ├─ _build_invalidation(support, tags, dims)    ← 失效条件
  └─ _risk_plain(level, factors, geo, rr, vol, invalidation) ← 白话描述
```

## 二、现状问题清单

### 2.1 架构Bug（导致功能缺失或不正确）

| # | 问题 | 严重度 | 根因 | 影响 |
|---|------|--------|------|------|
| **B1** | `_assess_risk_level()`从`dims.get('risk')`读取风险等级，而dims['risk']由StatusEngine从dim6输出生成→**循环依赖** | **高** | evaluate() L1955: `_assess_risk_level(dims, l0, tags)` → L232: `dim_risk = str(dims.get('risk', {}).get('state', ''))` → 如果StatusEngine先调dim6，dims['risk']为空 | 首次调用时风险等级判定可能不准确 |
| **B2** | `CSCVValidator`类(214行)在evaluate()中**完全未使用**→死代码 | **中** | CSCVValidator仅在模块级函数compute_cscv_pbo()中使用，evaluate()不调用 | 214行代码不参与dim6输出，浪费维护成本 |
| **B3** | `EventMonitor()`无参数实例化，`_dm=None`→依赖DataAwareMixin回退 | **中** | evaluate() L1961: `monitor = EventMonitor()` 未传入data_manager | 可能导致部分事件检测因数据不可用而静默失败 |
| **B4** | status_description**无evidence字段**→与dim2/dim3/dim5标准不符 | **中** | evaluate() L2001-2012: 输出仅含risk_level/risk_factors/support_resistance等，无evidence证据链 | JUD环节缺少判定依据 |
| **B5** | 20类事件检测中**6类因数据表未入库而永久返回未检测到** | **中** | B1-B6(share_float/pledge_risk/holder_reduce/underwater_ipo/buyback/incentive)的检测方法直接返回`{"detected": False}` | 资本运作风险完全缺失 |
| **B6** | `_list_risk_factors()`与`_assess_risk_level()`**风险源不完全对齐** | **低** | _assess_risk_level检查turnover_rate<1.0，但_list_risk_factors未检查；_list_risk_factors检查profit_ratio>=0.8，但_assess_risk_level未检查 | 风险等级和风险因素列表不一致 |
| **B7** | `_detect_regulatory()`检查`reason_category`字段→sentiment_pool_cache**无此列** | **低** | L679: `reason = str(df_stock.iloc[0].get('reason_category', ''))` → sentiment_pool_cache表结构中无reason_category列 | 监管事件检测始终返回未检测到 |
| **B8** | `calc_geometric()`中`dist_to_prev_high_pct`**未在status_description中输出** | **低** | L181计算了dist_to_prev_high_pct，L2006输出了该字段，但status_description的消费者可能未读取 | 距前高百分比数据未被充分利用 |
