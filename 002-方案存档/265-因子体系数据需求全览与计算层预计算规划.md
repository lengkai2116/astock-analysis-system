# 因子体系数据需求全览与计算层预计算规划（修正版）

> 本方案对系统中 **两套独立的因子体系** 进行全量数据需求梳理：
> 1. **FactorRegistry**（`factors/builtin/`）：257个注册因子，全部仅需OHLCV
> 2. **PRESET_COMBOS**（`routes/factors.py`）：12组合42个命名因子，供选股系统L3用户选择
> 
> 识别数据缺口，规划计算层预计算需求。

---

## 八、实施路线图

### Phase 0: 验证现有缓存消费（~0.5天）

- 确认 chart.py 的 `indicator_cache` 读取路径生效
- 确认 `SignalComputationService` 的 `factor_cache` 读取路径生效
- 验证 `_run_precompute()` 策略信号写入 `strategy_signals` 表（当前表不存在）
- **前置条件：D3 分钟补齐完成（分钟K线用于30min/60min级别指标）**

### Phase 1: PRESET_COMBOS 18因子实现（~2天）

- 批A: EP + 股息率 → 注册到 `_FACTOR_COMPUTERS`
- 批B: ROE + 增长率 → 注册
- 批C: 大单净买入 + 资金流向强度 → 注册
- 批D: 换手率变化 + 资产负债率 → 注册

### Phase 2: Fama-French 因子体系（~2天）

- 全市场每日市值/BM 分组 → 计算 SMB/HML 因子值
- 整合盈利因子 RMW 和投资因子 CMA
- 注册到 `_FACTOR_COMPUTERS`

### Phase 3: 日终全量预计算管道（~1天）

- 将 PRESET_COMBOS 每日因子值写入 `factor_cache`
- data_daemon `_run_precompute()` 扩展至全量因子
- 创建缺失的 `strategy_signals` 表并写入

### Phase 4: 消费端迁移（~1天）

- `_compute_factor_score()` 改为优先读 `factor_cache`
- 迁移 `StateDependentFactorWeight` 到渠道一
