## 〇、数据源

`daily_df`（data_context 优先，dim1 供）+ `tags`（pre_feat 扁平化）+ `PatternEngine`（app/engine/patterns/engine.py，**独立形态体系**）+ `data_context['relative_strength']`（dim1 统一供给，460 号）。

**⚠ 两套形态体系并行（467 后关键事实）**：
- `pattern`/`pattern_score` ← **PatternEngine**（Bullish/Bearish/BlackHorse/State 四检测器，P-3- 黑马型，10 分制聚合）——**与 467 无关**（467 只动 EnhancedPatternDetector + `_add_vp_simple_tags`）。
- `kline_pattern`（pre_feat volume_price 组）← `EnhancedPatternDetector.detect_all` + 467 均线过滤——**不被 dim3 evaluate 读取**。
- 实证佐证：000002 `pattern='缩量洗盘后放量, W底放量突破, 缩量挖坑后放量'`（PatternEngine）vs `kline_pattern='地量后倍量启动'`（EnhancedPatternDetector）——**同名不同源，勿混淆**。

## 六、存疑点（2026-09-20 实证发现，待逐项确认，未改代码）

### 六-1 ⚠ `judgment.state` 与 `health_score` 档位矛盾（4/8 只）
实证：000001（state=中性/yellow，但 hs=8/10 强健康）、000002（中性/9/10 强健康）、688981（中性/7/10 健康）、600036（中性/7/10 健康）。根因：hs 聚合 7 因子（量能/均线/筹码/RSI/RPS/形态偏差均可推高），而 vp_state 仅由 volume_price_fit 单键决定 → **两把尺子不同源**。464 §二 未记录此矛盾。待确认：dim8/JUD 消费哪个为准？是否需让 score 与 state 语义对齐（如中性态 hs 上限或档位降级）？

### 六-2 ⚠ `pattern`（PatternEngine）与 `kline_pattern`（EnhancedPatternDetector）双形态体系并存
实证：000002 pattern='缩量洗盘后放量, W底放量突破…'（PatternEngine）vs pre_feat kline_pattern='地量后倍量启动'（EnhancedPatternDetector+467 过滤）；600036 pattern='高位量价背离, 价跌量缩'（PatternEngine 含背离类形态）但 divergence='无背离信号'（framework 标签）。**形态结论双源并行，且 pattern 内"背离"与 divergence 键语义冲突**。待确认：dim8 归集时两体系如何取舍？（437-A 字段级映射需明确 pattern 与 kline_pattern 是否同槽）

### 六-3 ⚠ `granville` 与 `vp_state` 粒度不一致
实证：600519/601318 vp_state=强健康（framework 单日标签）但 granville=回探缩量（5 日区间回调+缩量）——**同一股票"强健康"与"回调缩量"并存**，因 vp_state 用单日、granville 用 5 日窗口。逻辑上可解释（单日健康+5 日回调）但话术上易困惑。待确认：是否接受（粒度差异说明）还是需要窗口对齐？

### 六-4 ⚠ `plain` 与 `judgment` 话术一致性
实证：000001 plain='量价关系中性…（健康度8/10，强健康）'——plain 内"中性"与"强健康"并存（同 六-1 根因）。plain 是 dim8 主文字素材（464 §十一），此矛盾会直接进现状描述。待确认：与 六-1 一并处置。

### 六-5 🔍 `300750` 量价八准则放量下跌但 hs=6/10 健康
实证：300750 granville=放量下跌（audit 条件 6 不满足，confidence 仅 0.33）但 hs=6/10（健康）——负面形态未显著拉低 hs（因 dp 只认 diverging 标签，granville 负面不参与 hs 计算）。**granville 已入 audit 但不入 hs 评分**，两处权重不对称。待确认：是否符合设计（audit 负责门禁、hs 负责评分）？
