# ECM 持久表完整设计方案与日终同步路线

## 一、设计原则

1. **所有可归档的历史数据 → ECM SQLite WAL 持久存储**
2. **盘中实时数据 → InMemoryStateStore（不持久）**
3. **日终（15:30）统一触发 Tushare 集采 → 写入 ECM**
4. **Tushare 5000 积分全覆盖，不新增外部依赖**

## 三、日终同步路线

### 3.1 当前日终调度结构（不动）

```
15:30 CronTrigger
  └─ run_daily_sync()
       ├─ 读 data_types 配置
       ├─ 循环 _sync_by_type(type)
       │    ├─ daily       → dm.sync_daily_data()
       │    ├─ basic       → dm.sync_daily_basic_data()
       │    ├─ moneyflow   → dm.sync_moneyflow_data()
       │    ├─ index       → dm.sync_index_daily_data()
       │    └─ adj_factor  → dm.sync_adj_factor_data()
       ├─ 写 sync_log
       └─ 盘后清理链
```

### 3.2 新增注册方式（不改调度器）

在 `scheduler_config` 的 `data_types` 数组中追加新类型名，调度器已有循环遍历逻辑，只需在 `_sync_by_type()` 中加 else-if 分支。

新增的一行默认配置：

```python
"data_types": [
    "daily", "basic", "moneyflow", "index", "adj_factor",
    "minute_kline",         # 分钟K线（Tushare + mootdx）
    "fina_indicator",        # 财务指标
    "income",               # 利润表
    "balancesheet",         # 资产负债表
    "cashflow",             # 现金流量表
    "forecast",             # 业绩预告
    "margin",               # 融资融券
    "stk_limit",            # 涨跌停
    "lhb",                  # 龙虎榜
    "top10_holders",        # 前十大股东
    "stk_holder",           # 股东人数
]
```

### 3.3 每个类型的采集策略

| 类型 | 采集范围 | 频率 | Tushare 限流影响 |
|------|---------|------|----------------|
| fina_indicator | 全市场×最新4季 | 季度 | 每次调用返回~5000行，1次API |
| income | 同上 | 季度 | 同上 |
| balancesheet | 同上 | 季度 | 同上 |
| cashflow | 同上 | 季度 | 同上 |
| forecast | 当日有预告的 | 日 | 1次API |
| margin | 当日融资融券 | 日 | 1次API |
| stk_limit | 当日涨跌停价 | 日 | 1次API |
| lhb | 当日龙虎榜 | 日 | 1次API |
| top10_holders | 指定股票 | 按需 | 逐只查询 |
| stk_holder | 指定股票 | 按需 | 逐只查询 |
| concept | 全量 | 月度 | 1次API |
| index_member | 全量指数 | 月度 | 按指数各1次 |

**注**：Tushare 总量限流 200 次/分钟，财务类调用极低频，新加入的 12 个类型在日终 15:30 一轮触发约 <30 次 API 调用，完全在限额内。

## 四、分钟K线专项（minute_kline_cache）

分钟K线与其他数据类型不同——它是一个**双通道写入**的表：

```
通道A（历史，30天）:
  Tushare stk_mins
    │ 限流 1 次/分钟，后台线程逐只回填
    │ 覆盖范围：自选股 → 活跃股 → 全市场（缓慢推进）
    ▼
  minute_kline_cache (INSERT OR REPLACE)

通道B（实盘，今日）:
  mootdx L1 快照（5s）
    │ 内存窗口聚合 1min bar
    │ open=首笔, high/low=区间极值, close=末笔, volume=累计
    ▼
  InMemoryStateStore.minute_kline[]
    │ 每1分钟批量写入
    ▼
  minute_kline_cache (INSERT OR REPLACE)
```

日终同步只需处理**通道A**（历史回填）。通道B由 mootdx 采集线程实时写入，日终清理即可。

## 五、实施阶段

### Phase 1：分钟K线实盘聚合（0.5 天）
- mootdx 采集线程中加入 1min 窗口聚合逻辑
- 写入 InMemoryStateStore + `minute_kline_cache` 表
- 修复 `/api/minute/<ts_code>` 读取路径

### Phase 2：12 表建表 + ECM 方法（1 天）
- `_init_tables()` 中增加 12 条 CREATE TABLE
- ECM 中增加 `cache_xxx_data()` 和 `get_cached_xxx()` 方法
- DataManager 中增加 `sync_xxx_data()` 方法（复用 TushareProvider 已有方法）

### Phase 3：日终调度注册（0.5 天）
- `_sync_by_type()` 增加 12 个 else-if 分支
- 默认配置 `data_types` 追加新类型
- 测试日终调度执行 + sync_log 记录

### Phase 4：分钟K线历史回填（1 天）
- 后台线程 `_catch_up_minute_kline()` 
- 每分钟从 Tushare stk_mins 获取 1 只股票的近 30 天数据
- 写入 `minute_kline_cache`
- 按自选股 → 活跃股 → 全市场渐进覆盖

### Phase 5：E07/E10 改造（1 天）
- E07 个股行情：从 Tushare 直调 → 优先读 ECM 缓存
- E10 个股资金流向：从 Tushare 直调 → 优先读 `moneyflow_cache`
- 缓存未命中才回退 Tushare 直调
