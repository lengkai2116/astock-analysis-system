# 策略引擎改造详细方案

补充 295-301 号方案未覆盖的策略引擎改造项，重点解决"看似有但实际不能用"的引擎缺口。

## 一、BOCIASI 改造：sentiment_phase 情绪阶段判定引擎（改造已有 MarketSentimentService，非新建）

### 1.1 问题

现有 BociasiQuickLine 输出 BUY/WATCH/NEUTRAL/BEARISH 四态，但我们需要 ice/recovery/climax/ebb 情绪周期四阶段。两者分类体系不同，不能直接映射。

此外，**已有 `MarketSentimentService`**（`market_sentiment_service.py:16`）基于涨停池数据实现了四阶段映射（ice/recovery/high/ebb/neutral），但：
- 使用 `high` 而非 `climax`（与标签体系不一致）
- 缺少炸板率指标
- 缺少`neutral`状态与`ebb`状态之间的区分阈值

### 1.2 方案

**改造 `MarketSentimentService`**，替代新建 `SentimentPhaseEngine`（避免重复造轮子）。改造内容：

1. 增加炸板率计算（接入东财 HTTP API 快照数据，日频用近似值替代）
2. 将阶段名称 `high` 改为 `climax`，与 295号标签体系对齐
3. 调整阈值算法，消除 `neutral` 模糊区间：
   - 满足 `ice` 条件 → ice
   - 满足 `ebb` 条件 → ebb（原 `neutral` 状态中可以区分出 ebb）
   - 两者都不满足时走 recovery/climax 判定
4. BociasiQuickLine/SlowLine 保留为辅助确认通道

改造后的 `MarketSentimentService.get_sentiment_phase()` 直接产出标准化标签：

```
| 阶段 | 判定条件 | 操作含义 |
|------|---------|---------|
| `ice` 冰点 | 涨停家数 < 20 + 空间龙头 < 3板 + 炸板率 > 60% | 不宜卖出，关注潜在反转 |
| `recovery` 复苏 | 指数企稳 + 涨停家数回升 + 龙头打出高度 | 可积极参与但仓位不宜过重 |
| `climax` 高潮 | 涨停家数 > 80 + 连板晋级率高 + 资金亢奋 | 减仓时机，非建仓时机 |
| `ebb` 退潮 | 空间龙头断板 + 亏钱效应扩散 + 炸板率暴增 | 大幅减仓，回避追高 |
```

### 1.3 数据依赖

- `daily_cache`：计算涨停家数（涨幅 > 9.9%），已有
- 连板高度：从 daily_cache 连续涨停天数推导，已有
- 炸板率：可通过东财 HTTP API 快照数据计算盘中炸板统计；日频**近似方案**定义如下：

```python
def _estimate_daily_sealing_rate(df: pd.DataFrame) -> float:
    """基于 daily_cache 的日频封板率近似值"""
    if df is None or df.empty:
        return 0.0
    # 条件1: 盘中触涨停（high >= prev_close * 1.099, 非科创板/北交所简化）
    touched_limit = (df['high'] >= df['prev_close'] * 1.099).sum()
    if touched_limit == 0:
        return 100.0
    # 条件2: 收盘封住涨停（close >= prev_close * 1.099）
    sealed_limit = (df['close'] >= df['prev_close'] * 1.099).sum()
    return round(sealed_limit / touched_limit * 100, 1)
```

> 日频近似方案仅用于盘后预计算。盘中实时炸板率通过东财 HTTP API snapshot 数据（`in_memory_state_store._snapshot`）计算精准值。

## 二、SectorRotation 重写：sector_heat 板块热度引擎（重写）

### 2.1 问题

现有 `SectorRotationModel` 代码自陈"由于缺少实时全市场板块指数数据"，实际只是个股收益率自指。核心数据缺失，不可用于生产。

### 2.2 方案

采用"缠中说禅板块强弱指标"法，**不需要外部板块指数数据**，直接从板块内个股状态聚合：

```
对每个申万一级行业:
  1. 取该行业下全部个股列表
  2. 统计各股的 MA5 > MA20（女上位=上涨）或 MA5 < MA20（男上位=下跌）
  3. 板块强弱值 = (女上位数量 - 男上位数量) / 板块总股数
  4. 对所有板块的强弱值排序
  5. top_10(前10名) / top_20(11-20名) / normal(21-40名) / none(40名以外)
```

### 2.3 数据依赖

- `Stock.industry`：行业分类，已有
- `daily_cache`：MA5/MA20 计算，已有
- **不需要任何外部板块指数数据**

> **⚠ 红线合规说明**：`Stock.industry` 通过 SQLAlchemy ORM (`Stock.query.get()`) 访问，**未经过 DataManager 网关**（Red Line 5 违规）。本方案在重写 `SectorRotationModel` 时，同步新增 DataManager 行业数据封装接口，使引擎的行业数据获取走 DataManager 网关。
>
> **实施方式**（在 `backend/app/data/__init__.py` DataManager 中新增两个方法）：
> ```python
> def get_stock_industry(self, ts_code: str) -> str | None:
>     """通过 DataManager 返回股票行业分类（申万一级），符合 Red Line 5"""
>     from app.models.stock import Stock
>     stock = self.session.query(Stock).filter(Stock.ts_code == ts_code).first()
>     return stock.industry if stock else None
> 
> def get_stock_industry_batch(self, ts_codes: list[str]) -> dict[str, str | None]:
>     """批量查询行业分类，减少 ORM 查询次数"""
>     from app.models.stock import Stock
>     stocks = self.session.query(Stock.ts_code, Stock.industry).filter(
>         Stock.ts_code.in_(ts_codes)
>     ).all()
>     return {s.ts_code: s.industry for s in stocks}
> ```
> **重写后 `SectorRotationModel` 的行业获取改为 `self.dm.get_stock_industry_batch(ts_codes)`，不再直读 ORM。**
>
> 此修改覆盖面广但改动量小（仅新增 2 个 DataManager 方法 + 引擎入口改 1 处），纳入 P0.6 工序一同实施。

## 三、收益分解引擎：upward_driver 上涨驱动力判定（新建）

### 3.1 问题

全新标签，无引擎覆盖。

### 3.2 方案

基于 Wiki 的"收益分解（隔夜-温和-极端）"框架，通过收益结构分解反向判断上涨驱动力：

```
对最近 20 个交易日:

1. 每日收益分解:
   隔夜收益 = (今日开盘 / 昨日收盘) - 1
   日内收益 = (今日收盘 / 今日开盘) - 1
   极端收益阈值 = 取日内收益的 ±3%（如果超过则为极端）

2. 统计占比:
   极端收益占比 = sum(|极端收益|) / sum(|日涨幅|)
   隔夜收益占比 = sum(|隔夜收益|) / sum(|日涨幅|)

3. 判定:
   info_driven(信息驱动): 隔夜收益占比 > 40% 且 极端收益占比 < 30%
     → 上涨由隔夜信息驱动，可持续
   emotion_driven(情绪驱动): 极端收益占比 > 40% 且 隔夜收益占比 < 20%
     → 上涨由日内情绪驱动，随时反转
   mixed(混合): 两者占比接近
   no_upward: 最近 20 日未上涨
```

### 3.3 数据依赖

- `daily_cache`：open/close 即可，已有

### 3.4 涉及文件

- 新建：`backend/app/opportunity_atlas/upward_driver_engine.py`（~80行）
- 归入 P2.1 EventMonitor 同一批实施

## 四、时间节奏引擎：time_rhythm 变盘窗口判定（新建）

### 4.1 问题

全新标签，无引擎覆盖。

### 4.2 方案

基于 BOLL 带宽变化 + 中枢横盘时长双重判定：

```
对最近 60 日:

1. BOLL 带宽趋势（从 indicator_other 读取 BOLL 指标）:
   带宽 = (上轨 - 下轨) / 中轨
   计算带宽最近 30 日的趋势(斜率):
    斜率 < -0.01（持续收缩 > 20日）→ 临近变盘信号

2. 中枢横盘时长（从 ChanlunAnalyzer 读取当前中枢）:
   读取最后中枢的形成时间和持续跨度
   日线级别中枢经验性跨度 1-6 个月
   接近 6 个月 → 临近变盘信号

3. 判定:
   approaching_turn: (BOLL收缩信号) OR (中枢接近级别上限)
   early_consolidation: 刚进入盘整(< 10 日)
   mid_consolidation: 盘整中段
   unknown: 无明显特征
```

### 4.3 数据依赖

- `indicator_other`：BOLL 上轨/下轨/中轨（已有预计算）
- `ChanlunAnalyzer` 输出中的中枢持续时间字段

### 5.1 gap_type — 缺口类型检测（补强）

```python
def _detect_gap_type(self, df, lookback=10):
    """检测最近缺口类型"""
    for i in range(-lookback, 0):
        prev_high = df['high'].iloc[i-1]
        prev_low = df['low'].iloc[i-1]
        cur_open = df['open'].iloc[i]
        cur_close = df['close'].iloc[i]
        cur_volume = df['vol'].iloc[i]
        avg_volume = df['vol'].iloc[max(0,i-20):i].mean()
        
        if cur_open > prev_high * 1.005:  # 向上跳空 > 0.5%
            gap_type = self._classify_gap(df, i, cur_open, cur_volume, avg_volume)
            # → common / breakaway / runaway / exhaustion
```

`_classify_gap` 子方法按 Wiki「缺口分析」定义的三日原则和位置判定。

## 七、MainForceScorer 补强：capital_nature 未上榜辅助判定

### 7.1 问题

`capital_nature` 对未上龙虎榜的股票一律输出 `unknown`。这是数据源限制，但可以通过资金流向数据做辅助推断。

### 7.2 方案

在 `MainForceScorer` 中新增阈值法：

```python
def _infer_capital_nature_no_lhb(self, symbol):
    """无 LHB 数据时，通过大单流向辅助推断"""
    mf = self.dm.get_cached_moneyflow(symbol, ...)
    if mf.empty: return 'unknown'
    
    big_order_ratio = (buy_lg + buy_elg) / (buy_lg + buy_elg + buy_sm + buy_md)
    if big_order_ratio > 0.4:
        return '疑似机构'  # 大单主导
    elif big_order_ratio < 0.15:
        return '疑似散户'  # 散单主导
    else:
        return 'unknown'
```

置信度设为 0.3（仅供参考）。LHB 数据有则用 LHB 判定（置信度 0.7+）。
