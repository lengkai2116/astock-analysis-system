# 估值体系统一修复方案（valuation_level 主导）

> **背景**：2026-08-07 核查发现常润股份（603201.SH）机会弹窗"估值定位=偏低"与"风险提示=估值偏高"直接矛盾，全市场量化存在 **447 只正向冲突**（level=low/extreme_low 但 PE 分位>60%）+ **160 只反向冲突**。深入分析确认：`valuation_level`（四锚综合，更合理）与 `pe_percentile_5y`（PE 历史分位）是两个独立估值度量，展示层未统一。本方案按分析结论（详见 `001-沟通记录/26-08-07沟通纪要.md` 008）将估值体系统一为 **valuation_level 主导**。**本方案仅存档，后续按 R1-R5 实施。**

---

## 一、问题根因

| 展示位置 | 使用的度量 | 冲突表现 |
|---------|-----------|---------|
| 💎 估值定位 / 标签摘要 | `valuation_level`（四锚综合：PB/收益/现金流/修正/股债差 × 行业权重 + PB-ROE 质量修正 + 截面百分位分档） | level=low → "偏低" |
| ⚠️ 风险提示 | `_evaluate_gate` 用 `pe_percentile_5y` 分位 + deviation（316 号分级） | pe 分位 86.5 → "估值偏高（PE 分位 80-90%）" |

**根因**：316 号 P1 门禁分级（`_evaluate_gate`，cross_validate.py:366-395）用连续偏离度（PE 分位 + deviation）独立于 valuation_level 判定，导致两套口径并存。而 valuation_level 已集成 PE/PB/现金流/成长多锚与质量修正，**对盈利下滑导致 PE 虚高的股票能正确识别为"资产便宜"**（实证：PE 分位>80 中被判低估的 246 只里 61% PB 分位也 <40）。

---

## 二、修复方案（valuation_level 主导）

### 修复原则

1. **估值高低结论统一由 `valuation_level` 输出**（估值定位、标签摘要、风险提示、L4 门禁）；
2. **pe_percentile_5y / valuation_deviation 降为佐证**：仅用于说明"PE 贵在何处"，不再单独触发"估值偏高"结论；
3. **矛盾场景转化为有效信息**：level 低（低估）但 PE 分位高 → 按 **EPS 方向 × PB 分位** 数据驱动分叉（盈利下滑/困境反转机会/估值收缩），而非"需核实"推诿；
4. **深度高估硬否决保留**：仅当 `valuation_level ∈ (high, extreme_high)` 且 PE 分位>90%（双信号共振）时触发 deep 级不推荐——避免误伤合理偏贵股。

### R1：`_evaluate_gate` 估值分级改 valuation_level 主导（cross_validate.py:382-393）

```python
# 修复前：pe_pct/dev 独立判定（与 valuation_level 冲突的根源）
if (pe_pct is not None and pe_pct > 90) or (dev is not None and dev < -20): lv = 'deep'
elif (pe_pct is not None and pe_pct > 80) or (dev is not None and dev < -12): lv = 'moderate'
elif (pe_pct is not None and pe_pct > 60) or (dev is not None and dev < -6): lv = 'mild'

# 修复后：valuation_level 主导，PE 分位仅作深度细分
lv = 'none'
level = tags.get('valuation_level', '')
if level in ('extreme_high', 'high'):
    if pe_pct is not None and pe_pct > 90:   # 双信号共振 → 深度高估
        lv = 'deep'
    elif pe_pct is not None and pe_pct > 80:
        lv = 'moderate'
    elif pe_pct is not None and pe_pct > 60:
        lv = 'mild'
    else:
        lv = 'mild'   # level 高但 PE 分位低（相对市场贵）→ 轻度标注，不硬否决
# level ∈ (fair/low/extreme_low)：估值不构成风险，不进入估值分级（PE 分位高=盈利下滑信号，归 R2 处理）
```

### R2：`_build_risk_warnings` 估值风险提示与 level 对齐（cross_validate.py:990-1001）

> **2026-08-07 修订**：原"盈利下滑"单一归因文案（58.8% vs 全市场 48.3%，仅高 10.5pp）过度绝对，"需核实"推诿对用户无意义（无核查条件）。改为**数据驱动四场景分叉**（EPS 方向 × PB 分位），实证基础：447 冲突股 EPS 同比下滑 58.8%、EPS 增长组 47% PB 分位<40（困境反转特征）、EPS 增长/下滑组近60日涨幅几乎相同（PE 高位源于盈利基数变化非股价涨）。

```python
# 修复前：val_lv（gate 判定，PE 分位驱动）直接输出"估值偏高"
# 修复后：估值风险提示以 valuation_level 为准；level 低但 PE 分位高 → 数据驱动分叉
#   eps_yoy: EPS 同比（income_cache.basic_eps 同月跨年，_eps_yoy() 计算）
#   pb_pct:  PB 近5年分位（快照 tags 已透出）
val_lv = gate.get('valuation', 'none')
_level = tags.get('valuation_level', '')
_pe_pct = tags.get('pe_percentile_5y', '')
if val_lv == 'deep':
    warnings.append({'type': 'valuation', 'content': '深度高估（估值等级高估 + PE 历史分位 >90%），估值泡沫风险，暂不介入'})
elif val_lv == 'moderate':
    warnings.append({'type': 'valuation', 'content': '估值偏高（估值等级偏高 + PE 分位 80-90%），安全边际有限，仓位减半'})
elif val_lv == 'mild':
    warnings.append({'type': 'valuation', 'content': '估值略偏高（估值等级偏高），注意追高风险'})
# 矛盾场景：估值等级低估/合理，但 PE 分位偏高 → 按 EPS 方向 × PB 分位分叉
elif _level in ('low', 'extreme_low', 'fair') and _pe_pct and float(_pe_pct) > 60:
    if eps_yoy is None:
        pass   # 无 EPS 数据：不输出（避免无依据输出）
    elif eps_yoy < 0:
        warnings.append({'type': 'valuation', 'content': '盈利下滑，PE 高位源于盈利萎缩，注意基本面风险'})
    elif pb_pct is not None and pb_pct < 40:
        warnings.append({'type': 'valuation', 'content': '盈利改善中且资产端便宜（PB 近5年低分位），属周期底部/困境反转特征——PE 高源于盈利基数低，注意盈利持续性'})
    else:
        warnings.append({'type': 'valuation', 'content': '盈利增长，但 PE 处历史高位——已计入较多增长预期，若盈利增速回落，估值有收缩风险'})
```

**四场景决策矩阵**：

| 场景 | 条件 | 输出 |
|------|------|------|
| 盈利下滑 | EPS 同比<0 | "盈利下滑，PE 高位源于盈利萎缩，注意基本面风险" |
| 困境反转（机会） | EPS>0 + PB 分位<40 | "盈利改善中且资产端便宜（PB 近5年低分位），属周期底部/困境反转特征——注意盈利持续性" |
| 估值收缩 | EPS>0 + PB 分位≥40 | "盈利增长，但 PE 处历史高位——已计入较多增长预期，若增速回落估值有收缩风险" |
| 无数据 | EPS 缺失 | 不输出（避免无依据） |

### R3：`_build_operation_advice` 门禁 deep 只对 level 高估生效（cross_validate.py:851-854）

```python
# 修复前：val_lv == 'deep' → not_recommended（PE 分位>90 即可触发，与 level 无关）
# 修复后：deep 已由 R1 保证仅 level ∈ (high, extreme_high) 时产生，此处分支逻辑不变，
#         但需确认 hard 风险与 deep 的优先级保持（负面事件 > 深度高估）
```

> R1 修复后，`_evaluate_gate` 返回的 'deep' 已隐含 valuation_level 高估前置条件，`_build_operation_advice` 的 :851-854 分支无需改动（行为自动对齐）；`_build_trade_plan` 的 risk_notes（:915-918）同理受益。

- diagnose 异步返回的 `risk_warnings` 经 R2 修复后与估值定位同源，弹窗自动消除矛盾。

## 四、风险与说明

1. **门禁收紧影响**：deep 硬否决从"PE 分位>90 单独触发"改为"level 高估 + PE 分位>90 共振触发"，会减少深度高估否决数量——经 315 号验证 high 股 PE 分位均值 72.1%，level=high 且 PE>90 的股票占比小，影响可控；316 号矛盾率 20%（设计内深度高估）会进一步下降；
2. **矛盾场景分叉严谨性**：EPS 方向 × PB 分位四场景均有真实数据支撑（实证 447 只全部落入四场景），且"困境反转"场景明确标注"注意盈利持续性"（盈利刚恢复不代表持续），不构成机会误导；无 EPS 数据时不输出，杜绝无依据提示；
3. **L4 门禁语义**：`valuation_level` 是行业中性化截面分位（相对市场），deep 双信号共振保证"绝对贵 + 相对贵"同时成立才硬否决，符合 315 号 §3.2 语义分离设计；
4. **回滚**：R1-R3 均为 cross_validate.py 局部修改，git 单文件可回滚。

---

## 五、结论

本方案将估值高低结论统一收敛到 **valuation_level（四锚综合，更合理）**，PE 分位降为佐证与深度细分；对"level 低但 PE 分位高"的矛盾场景按 **EPS 方向 × PB 分位** 数据驱动四场景输出（盈利下滑/困境反转机会/估值收缩/无数据不输出），将 447+160 只冲突股转化为有效信息而非推诿。修复范围集中在 cross_validate.py（R1-R3，含新增 `_eps_yoy()`），前端零改动。**2026-08-07 已按修订版实施完成（R1-R5，详见 §六）。**
