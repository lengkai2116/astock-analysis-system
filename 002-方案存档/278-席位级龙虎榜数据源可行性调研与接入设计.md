# 席位级龙虎榜数据源可行性调研与接入设计

> 目标：在不修改代码的前提下，调研系统中现有数据源是否支持席位级龙虎榜数据采集，
> 并设计存储结构、调用规则和集成方案。

---

## 一、调研结论：可行，有 2 条路径

| 路径 | 数据源 | 接入难度 | 数据精度 | 推荐度 |
|------|--------|:--------:|:--------:|:------:|
| **路径A** | AKShare `stock_lhb_jgmm_em`（机构买卖明细） | 低 | 机构级统计（非逐笔） | ⭐⭐⭐ 推荐 |
| **路径B** | Tushare `top_inst`（营业部/机构席位明细） | 中 | 逐席位明细 | ⭐ 备选 |

**推荐路径A**，理由：
- AKShare >= 1.14.0 已安装，无需新增依赖
- 现有 `akshare_collector.py` Thread 5 已有 1800s 间隔的 LHB 采集基础设施
- 现有 `akshare_provider.py` 已有数据源注册和健康检查
- 采集的数据直接对应"机构 vs 营业部"的判别需求

## 二、路径A：AKShare `stock_lhb_jgmm_em` 详细分析

### 2.1 API 规格

| 项目 | 内容 |
|------|------|
| **接口** | `ak.stock_lhb_jgmm_em(symbol, start_date, end_date)` |
| **参数** | `symbol`: 股票代码（如 "600696"），非可选 |
| **返回** | DataFrame，含逐机构席位买卖明细 |
| **频次** | 日级（盘后即可获取全天数据） |

### 2.2 返回列结构（预期）

| AKShare 列名 | 含义 | 用于假机构识别 |
|-------------|------|:------------:|
| `代码` | 股票代码 | — |
| `名称` | 股票名称 | — |
| `交易日期` | 交易日期 | — |
| **`买方营业部`** | 买入营业部/机构名称 | ✅ **核心字段**：区分机构专用 vs 普通营业部 |
| **`买方金额`** | 该营业部买入金额 | ✅ 计算买入占比 |
| **`买方排名`** | 买入金额排名 | ✅ 判断是否主力 |
| **`卖方营业部`** | 卖出营业部/机构名称 | ✅ 核心字段 |
| **`卖方金额`** | 该营业部卖出金额 | ✅ 计算卖出占比 |
| **`卖方排名`** | 卖出金额排名 | ✅ |
| `上榜原因` | 龙虎榜上榜原因类型 | ⚠️ 参考 |
| `简介` | 营业部/机构简介 | 🔵 辅助（含"机构专用"标识信息） |

> 注：具体列名以 AKShare 实际返回为准。各版本间列名可能有差异。`stock_lhb_jgmm_em` 返回每只股票当日的所有买卖营业部明细，含机构专用席位和普通营业部席位。

### 2.3 与假机构识别需求的对齐

知识库定义的真假机构四维判别：

| 维度 | 当前实现（聚合数据买入占比） | 路径A实现的席位级增强 |
|------|:---------------------------:|:--------------------:|
| 买入位置（低位/高位） | ✅ 已有 price_pos 计算 | ✅ 不变 |
| 买入金额占比 | ⚠️ 用总买入占比推测 | ✅ **按席位拆分**，可识别"一机构买入30%" vs "全部机构合计买入30%" |
| **席位名称** | ❌ 无数据 | ✅ **新增**：判断"机构专用" vs "某营业部冒充" |
| 分时特征 | ❌ 无分钟级 LHB | ❌ 仍不支持（需分钟级龙虎榜，无此数据源） |

### 2.4 局限性

1. **按股票查询**：`stock_lhb_jgmm_em` 需要指定 `symbol` 参数，不能全市场一键获取。需要先通过 `lhb_cache` 获取当日上榜股票列表，再逐只查询。
2. **无分钟级分时**：只有日级汇总，无法实现知识库定义的"一波拉涨停"波形检测。
3. **数据时效性**：AKShare 的东方财富源通常 15:00-15:30 更新当天数据。

## 三、路径B：Tushare `top_inst` 详细分析

### 3.1 API 规格

| 项目 | 内容 |
|------|------|
| **接口** | `pro.top_inst(trade_date='YYYYMMDD')` |
| **参数** | `trade_date`: 交易日期 |
| **返回** | DataFrame，逐席位明细 |

### 3.2 已知列结构

| Tushare 列名 | 含义 | 类型 |
|-------------|------|------|
| `trade_date` | 交易日期 | str |
| `ts_code` | 股票代码 | str |
| `exalter` | **营业部名称** | str |
| `buy` | 买入金额 | float |
| `buy_rate` | 买入占比 | float |
| `sell` | 卖出金额 | float |
| `sell_rate` | 卖出占比 | float |
| `net_buy` | 净买入 | float |
| `side` | 买卖方向（买入/卖出） | str |

### 3.3 优缺点

**优点：**
- 按 `trade_date` 全市场一次获取，无需逐股查询
- `exalter`（营业部名称）字段可直接用于"机构专用"名称匹配
- `buy_rate` / `sell_rate` 占比字段是假机构识别的直接输入

**缺点：**
- 当前 `tushare_provider.py` 完全未实现此 API
- 部分 Tushare 账号需要更高积分才能访问 `top_inst`
- 需要额外在 data_daemon 中增加日终同步

## 四、推荐方案设计：AKShare 路径A

### 4.1 存储设计

#### 4.1.1 ECM 表结构（新增 `lhb_detail_cache`）

```sql
CREATE TABLE IF NOT EXISTS lhb_detail_cache (
    ts_code         TEXT,           -- 股票代码
    trade_date      TEXT,           -- 交易日期
    seat_name       TEXT,           -- 席位/营业部名称（核心字段）
    seat_type       TEXT DEFAULT '',-- 席位类型：'institution'(机构)/'brokerage'(营业部)/'unknown'
    buy_amount      REAL DEFAULT 0, -- 买入金额（该席位）
    sell_amount     REAL DEFAULT 0, -- 卖出金额（该席位）
    net_amount      REAL DEFAULT 0, -- 净额
    buy_rank        INTEGER DEFAULT 0,  -- 买入排名
    sell_rank       INTEGER DEFAULT 0,  -- 卖出排名
    reason_category TEXT DEFAULT '', -- 上榜原因
    side            TEXT DEFAULT '', -- 主要方向：'buy'/'sell'/'both'
    data_source     TEXT DEFAULT 'akshare', -- 'akshare'/'tushare'
    cached_at       TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (ts_code, trade_date, seat_name)
);

CREATE INDEX IF NOT EXISTS idx_lhb_detail_ts ON lhb_detail_cache(ts_code, trade_date);
CREATE INDEX IF NOT EXISTS idx_lhb_detail_date ON lhb_detail_cache(trade_date);
```

**设计要点：**
- `seat_type` 从 `seat_name` 中推断：包含"机构专用"、"机构"字样的标为 `institution`
- `side` 从买入/卖出金额对比推断
- 不放在 `as_*` 表空间（此为新建正式表，非遗留兼容）
- `PRIMARY KEY (ts_code, trade_date, seat_name)` 支持同一天同一席位多笔记录

#### 4.1.2 InMemoryStateStore 扩展

```python
# 新增龙虎榜席位级数据槽（覆盖式）
self._lhb_detail: Dict[str, List[Dict]] = {}  # {ts_code: [seat_records]}

def update_lhb_detail(self, ts_code: str, records: List[Dict]):
    with self._lock:
        self._lhb_detail[ts_code] = [dict(r) for r in records]

def get_lhb_detail(self, ts_code: str = None) -> List[Dict]:
    with self._lock:
        if ts_code:
            return [dict(r) for r in self._lhb_detail.get(ts_code, [])]
        # 全量展平
        result = []
        for records in self._lhb_detail.values():
            result.extend(dict(r) for r in records)
        return result
```

#### 4.1.3 数据流

```
采集层 (akshare_collector.py)
  │  ① 从 lhb_cache 获取当日上榜股票列表
  │  ② 逐只调用 ak.stock_lhb_jgmm_em(symbol, today, today)
  │  ③ 解析席位级别数据
  ▼
存储层 ┌──────────────────────────────────────────┐
       │  InMemoryStateStore._lhb_detail (盘中)   │
       │  ECM lhb_detail_cache (持久化)            │
       └──────────────────────────────────────────┘
  │  DataManager.get_lhb_detail(ts_code)
  ▼
消费层 ┌──────────────────────────────────────────┐
       │  chip_strategy._detect_fake_institution  │
       │  新增：席位名称 → seat_type 判别         │
       │  新增：机构vs营业部买卖方向对比           │
       └──────────────────────────────────────────┘
```

### 4.2 调用规则

#### 4.2.1 采集频率

| 时机 | 方式 | 说明 |
|------|------|------|
| 盘中（30min） | AKShare 采集器 Thread 5 扩展 | 沿用现有 `_collect_lhb_and_news` 的 1800s 间隔 |
| 盘后（15:30） | Tushare data_daemon 扩展（可选） | 后续若实现路径B可追加 |

#### 4.2.2 消费接口

在 `DataManager` 中新增：

```python
def get_lhb_detail(self, ts_code: str) -> pd.DataFrame:
    """获取股票席位级龙虎榜明细
    
    优先级：
      1. InMemoryStateStore (盘中最新)
      2. ECM lhb_detail_cache (盘后持久化)
    """
    # 先查内存
    records = mem_store.get_lhb_detail(ts_code)
    if records:
        return pd.DataFrame(records)
    # 回退到 ECM
    return self.cache.get_cached_lhb_detail(ts_code)
```

#### 4.2.3 席位类型推断规则

```python
def _classify_seat(seat_name: str) -> str:
    """根据席位名称推断类型
    
    机构特征词：机构专用、基金、券商自营、社保、QFII
    营业部特征词：证券营业部、分公司、事业部
    """
    seat_lower = seat_name.lower()
    # 机构特征
    if any(kw in seat_lower for kw in ['机构专用', '基金', '自营', '社保', 'qfii']):
        return 'institution'
    # 营业部特征（默认）
    return 'brokerage'
```

### 4.3 假机构识别增强逻辑

在现有 `_detect_fake_institution` 基础上增加席位级维度：

```python
# 新增判断：席位名称级识别
detail = get_lhb_detail(symbol)
if detail is not None and not detail.empty:
    # 按席位分类汇总
    inst_buy = detail[detail['seat_type'] == 'institution']['buy_amount'].sum()
    broker_buy = detail[detail['seat_type'] == 'brokerage']['buy_amount'].sum()
    total_buy = inst_buy + broker_buy
    
    if total_buy > 0:
        inst_ratio = inst_buy / total_buy
        # 机构买入占比 < 20% 且 买入额较大 → 可能是"假机构"（营业部冒充）
        if inst_ratio < 0.2 and total_buy > 1e7:
            suspected = True
            reason = f"机构买入仅占{inst_ratio:.0%}，主要是营业部买入"
```

### 5.3 采集器集成方式（详细）

在 `_collect_lhb_and_news` 中，在现有 `stock_lhb_detail_em` 之后追加：

```
1. 从今日已采集的 lhb 列表获取上榜 ts_code 列表
2. 如果内存中没有或者为空，跳过（数据尚未就绪）
3. 对每个 ts_code：
   a. 调用 ak.stock_lhb_jgmm_em(ts_code, today, today)
   b. 解析返回的席位级数据（买方/卖方营业部名称 + 金额）
   c. 写入 mem_store.update_lhb_detail(ts_code, records)
4. 统一写入 ecm.cache_lhb_detail_data(all_records)
```

### 5.4 时序安全

- 采集间隔 1800s（30min），LHB 数据每日只变化一次，不存在并发覆盖问题
- `lhb_cache` 的采集（stock-level）优先于 `lhb_detail_cache`（seat-level），因为前者提供全上榜名单
- 若 `lhb_cache` 今日为空（非交易日/数据延迟），`lhb_detail_cache` 采集自动跳过

## 六、与全局数据体系的对齐检查

### 6.1 五层架构合规性

```
采集层 (akshare_collector)          → 纯采集，不关心谁读
存储层 (ECM + InMemoryStateStore)   → 原始数据存储
计算层 (chip_strategy)              → 只读存储层，不直连数据源
调用层 (DataManager)                → 只读不写
使用层 (前端/API)                   → 消费数据
```

✅ 新增数据完全遵循五层架构，采集层不知道消费层。

### 6.2 与现有 19 张活跃表的关系

| 关系 | 表名 | 说明 |
|------|------|------|
| ✅ 新增独立表 | `lhb_detail_cache` | 不与任何已有表冲突 |
| ✅ 依赖现有表 | `lhb_cache` | 采集时需要 `lhb_cache` 获取上榜股票名单 |
| ⚠️ 重复范围 | `as_lhb_detail` | 现有表为股票级聚合，新表为席位级明细，不重复 |
