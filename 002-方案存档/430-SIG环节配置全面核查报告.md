### 2.2 【P0，配置失效诱发的行为级缺陷】`_ext_threshold` 兜底不触发 → `enter`/`light` 被误降级

**代码事实**（两处**逐字相同**，仅缩进层级不同）：

`backend/app/opportunity_atlas/advice_builder.py:223-236`：

```python
                # 334号 + 352号G6：生命周期阈值从 signal_registry.yaml 读取
                try:
                    from app.services.status_config import get_signal_registry
                    _reg = get_signal_registry().get('signals', {})            # L226 → {}
                    _max_ext_pct = 0                                          # L227
                    for _sig_cfg in _reg.values():                            # L228 → 不进入
                        _ext = (_sig_cfg.get('lifecycle') or {}).get('extended') or {}
                        _pct = _ext.get('dist_pct', 0)
                        if _pct > _max_ext_pct:
                            _max_ext_pct = _pct
                    _ext_threshold = _max_ext_pct * 100 if _max_ext_pct <= 1 else _max_ext_pct  # L233 → 0*100 = 0
                except Exception:
                    _ext_threshold = 12  # 兜底默认值                            # L235 → 不触发
                if _dist > _ext_threshold and state in ('enter', 'light'):        # L236 → 0 < _dist 恒真
                    state = 'wait'
                    state_reason = f'信号已延伸（距突破位+{_dist:.0f}%），只可持有、不新开仓（L0c）'
```

`backend/app/opportunity_atlas/advice_engine.py:575-587` 为同构代码（`_ext_threshold` 兜底同样位于 `except` 分支内）。

**缺陷机理**：空注册表下 `_reg = {}` → 循环不执行 → `_max_ext_pct` 保持初值 `0` → `0 <= 1` 成立 → `_ext_threshold = 0 * 100 = 0`。**全过程不抛异常，故 `except` 分支（兜底 `12`）永不执行。**

**行为后果**：`_dist > 0`（现价高于信号价）即为真 → **任何正收益状态的 bullish 信号都会被降级**：

| 输入状态 | 期望（阈值 =12 时） | 实际（阈值 =0 时） |
|---|---|---|
| `_dist = +5%`，`state='enter'` | 保持 `enter` | **→ `wait`**，理由"信号已延伸（距突破位+5%）" |
| `_dist = +11%`，`state='light'` | 保持 `light` | **→ `wait`** |
| `_dist = -3%`，`state='enter'` | 保持 `enter` | 保持 `enter`（负值不触发） |

**模块间自相矛盾**：同一语义在 `status_engine.py:484-486` 算出的是 **12.0**（代码默认值，与注册表数值一致），在建议层却算出 **0**。即 SIG 内部"信号阶段判定"与"建议降级判定"使用了**两个不同阈值**，且后者恒为 0。

> **注**：旧版记录的"`except: _ext_threshold = 12` 被注释掉"表述**不准确**——该行是**有效代码**，但位于 `except` 分支内；由于空注册表不抛异常，其效果等同于不存在。核心结论（`_ext_threshold = 0`）经运行时探针确认成立。
