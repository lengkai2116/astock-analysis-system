## 附2：标签体系双体系共用核查（2026-08-13）

> 核查结论：同一套标签体系（opportunity_tags_cache 83 标签，P4 预计算单一事实源）**同时被机会图谱与个股策略分析两套体系使用**，存在 3 处实质问题。

### 双体系消费链路

```
                    opportunity_tags_cache（83 标签，P4 预计算，单一事实源）
                                    │
          ┌─────────────────────────┴─────────────────────────┐
          ▼                                                   ▼
   ① 机会图谱体系                                         ② 个股策略分析体系
   ─────────────                                         ─────────────
   routes/opportunity_atlas.py                           routes/strategy_analyze.py
   ├─ treemap: get_tags_batch(全量)                      ├─ 标签基线 _build_tag_baseline
   │   → 方块大小(signal_strength)/颜色(opportunity_state)│   → 七维红绿灯(tags_summary)
   │   → 潜力/七维画像/右侧确认                           ├─ 深度字段恢复(S0.5)
   └─ diagnose 弹窗: L4CrossValidator                    │   → chip_peak/asr/support_resistance
       ├─ _evaluate_gate(tags) → 门禁                    ├─ arbitrate(signals) → 仲裁
       ├─ _compute_consensus(tags) → L4 投票             └─ build_operation_advice(tags)
       ├─ arbitrate(tags, gate, consensus)                 → 止损/目标/情景/失效
       │   → opportunity_state
       └─ build_operation_advice(_dims, tags)
           → 止损/仓位/summary
```

两套体系共享同一标签库，且各自调用 `build_operation_advice` + `arbitrate`——符合 322/323 号"双端同源"设计意图，但实现存在差异。

### 3 处实质问题（实测 300759/301119/000066）

**问题 1：共识率双口径 —— 弹窗虚高 vs 个股页真实**

| 股票 | 弹窗 diagnose 共识 | 个股页 analyze 共识 |
|------|:---:|:---:|
| 301119 | **100%**（1.0） | **67%** |
| 300759 | **90%**（0.9） | **67%** |
| 000066 | 78% | 一致（回避） |

- 根因：弹窗 diagnose（`cross_validate.py:362-373`）用标签**轻量推导五维方向** `_dims` 后计算共识（多按看多映射→虚高）；个股页 analyze 用**真实五维信号**（chanlun/volume_price/chip/emotion/factor 实际方向）计算（真实值）
- 同一股票两个入口看到不同共识率，用户无法判断可信度

**问题 2：止损/仓位双轨未收口（300759 实测）**

| 字段 | 弹窗 diagnose | 个股页 analyze |
|------|:---:|:---:|
| 止损 | `close < 40.71`（顶层字段有值） | `None`（仅 executable 内 `close < 40.71`） |
| 仓位 | 0.6 | 0.3 |

- 止损：弹窗顶层字段有值，个股页顶层 `stop_loss` 为 None——**字段结构不同**，前端两个入口渲染路径不同
- 仓位：弹窗 0.6（BUY 满仓上限）vs 个股页 0.3（低置信度降级后）——323 号方案明确要消除的"执行层双轨"**未完全收口**：个股页走了低置信度降级（confidence='中'→max_pct 压到 0.3），弹窗侧未同步该降级逻辑

**问题 3：标签矛盾未暴露（300759 实证）**

- 300759：`risk_level=HIGH` + `state_label=下降`（缠论趋势向下）+ `profit_ratio=0.99`（获利盘 99% 高位）+ `main_force_presence=none`
- 但两套体系均输出 enter/可入场（因 `right_side_confirm=强确认` + 共识看多）
- 根因：arbiter 硬合成掩盖冲突维度，两套体系都看不到冲突证据——"可入场"掩盖了 HIGH 风险

### 问题定性

| 问题 | 严重度 | 性质 |
|------|:---:|------|
| 共识率双口径（100% vs 67%） | 🔴 高 | 两套体系对同一标签推导共识的**算法不同**（标签轻量推导 vs 真实五维） |
| 仓位双轨（0.6 vs 0.3） | 🔴 高 | 323 号"执行层双轨"**未完全收口**——降级逻辑只在个股页 |
| 顶层字段结构不一致（stop_loss None vs 有值） | 🟡 中 | 同一 operation_advice 双入口字段形态不同 |
| 标签矛盾未暴露（HIGH 风险却可入场） | 🟡 中 | arbiter 硬合成掩盖冲突，非双体系问题但被双体系共同放大 |

### 修复建议（待决策，未实施）

1. 弹窗 diagnose 的 operation_advice 改为完全复用个股页同源输出（含低置信度降级），消除仓位双轨
2. 共识率统一用真实五维推导（弹窗侧 `_dims` 改为真实信号方向），消除共识虚高
3. 顶层字段结构对齐（stop_loss 字段形态统一，双入口渲染路径一致）
4. 冲突维度暴露：arbiter 输出保留 evidence 冲突列表（如"缠论下降 vs 趋势向上"），前端风险边界展示
