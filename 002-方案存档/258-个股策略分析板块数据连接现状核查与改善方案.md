# 个股策略分析板块数据连接现状核查与全量改善方案

## 1. 背景与范围

本方案在 **258号方案 v1.0**（后端数据管道审计）基础上，纳入 **2026-07-09 第二轮核查**（前端K线页面9项操作端口深入审计）的全部发现，形成覆盖全栈的统一实施路线图。

### 1.1 核查范围

| 轮次 | 覆盖范围 | 发现数量 | 对应文档章节 |
|------|---------|:-------:|:-----------:|
| 第一轮 | 后端数据管道：ECM表结构、data_daemon调度、5维策略数据依赖 | 4项(P0~P3) | §3.1 |
| 第二轮 | 前端K线页面：9项操作端口与界面数据连接 | 9项 | §3.2 |

### 1.2 核心结论

**后端数据管道基本完整可用**（ECM SQLite WAL + data_daemon日终批量同步链路畅通），有4项结构性缺口需补齐。

**前端 `indicator-ide.html` 页面当前几乎完全运行在闭包模拟数据上**——这是系统生产化的最大阻塞点。L1094-1201 生成750根随机K线（起始日期2023-06），所有指标计算（MA/BOLL/BBI/ENE/九转/MACD/KDJ/RSI/DMI/WR/VR/SAR/DMA/OBV）均基于此mock数据。真实API调用仅用于"股票搜索"和"右侧行情面板"。

## 3. 全部核查发现（15项）

### 3.1 后端数据管道缺口（第一轮）

| 编号 | 优先级 | 问题 | 影响面 |
|:----:|:-----:|------|-------|
| **B1** | 🔴 P0 | 财务数据未纳入 data_daemon 日终同步（fina_indicator_cache/income_cache/balancesheet_cache/cashflow_cache 四表有定义无调度） | BOCIASI慢线无PE、因子估值类不可用 |
| **B2** | 🟡 P1 | 数据源降级对上游无显式反馈（扩展数据 try/except 静默跳过，前端无"数据暂缺"提示） | 数据缺省时用户以为是分析结果 |
| **B3** | 🟡 P1 | factors/builtin/ 因子族未联通 SignalComputationService | 因子维度不产生有效信号 |
| **B4** | 🟡 P2 | 板块资金流向缺持久化聚合层（moneyflow_cache 逐股逐日，缺 industry GROUP BY） | sector-moneyflow 仪表盘为空 |
| **B5** | 🟢 P2 | 完整性检查未覆盖 lhb_cache + 财务类表 | 龙虎榜缺失不自动修复 |
| **B6** | 🟢 P3 | signals/indicators/evaluation 目录结构不完整，SignalGenerator未被使用 | 代码冗余 |

### 3.2 前端K线页面数据连接缺口（第二轮）

| 编号 | 优先级 | 问题 | 严重程度 |
|:----:|:-----:|------|:--------:|
| **F1** | 🔴 P0 | 自选股选择下拉调用已移除端点 `GET /api/v3/phase3/watchlist`（404），回退硬编码mock | 自选股功能无法使用 |
| **F2** | 🔴 P0 | "+非自选"添加调用已移除端点 `POST /api/v3/phase3/watchlist`（404），只走本地缓存未写数据库 | 添加自选实际不生效 |

| **F8** | 🟡 P1 | 成交量数据为mock随机数，ECharts dataZoom start:86仅显示14%区间 | 成交量不可信 |
| **F9** | 🟠 P2 | `syncFromScreener()` 为空壳函数，仅弹Toast提示 | 策略同步不生效 |

## 4. 实施路线图（8个Phase）

### 实施原则
1. **依赖优先**：上游有依赖的Phase不可跳跃
2. **最小改动**：每Phase改动量控制在50-200行，单次可验证
3. **可回滚**：每Phase完成后验证，出问题仅回滚当前Phase
4. **逐步替换**：Phase 2~6 逐步将mock数据替换为真实API数据，每一Phase替换一组关联功能

### Phase 1 — 后端补齐分钟K线数据通道（F7前置）

**目标**：为周期切换提供真实分钟级数据

**现状**：`chart.py:L68-92` 将 `1m/5m/15m/30m/60m` 全部降级为 `period='D'`

**方案**：分钟级有两种可选路线（需在实施时确认）：

**路线A（推荐）**：ECM已有 `minute_kline_cache` 表（`enhanced_cache_manager.py:L260-266`），但无数据填充。利用 daemon 或路由层从 mootdx TCP / AKShare 逐日填充此表。

**路线B**：从日线降采样模拟分钟线（精度不足，仅作为备选）。

| 步骤 | 文件 | 修改内容 | 预计行数 |
|:----:|------|---------|:--------:|
| 1.1 | `backend/app/data/__init__.py` | 新增 `sync_minute_kline(ts_code, freq)` 方法，先从 mootdx 实时源获取，缺省时从 AKShare 补充 | ~30 |
| 1.2 | `backend/app/routes/chart.py` | 修改 `_get_kline_data()` 分钟分支：从 `minute_kline_cache` 取数而非直接降级D | ~20 |
| 1.3 | `backend/data_daemon.py` | 日终同步后增加可选分钟线预缓存任务（后台低优，仅缓存最近5日） | ~20 |

**验证标准**：`GET /api/v3/chart/kline/000762.SZ?period=60m` 返回含 `open/high/low/close/volume` 的60分钟K线数组（>= 20根）。
