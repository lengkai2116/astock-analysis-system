## 二、问题一：缠论结构图不显示

### 2.1 现状

`_ui-prototype/indicator-ide.html:2650-2687`，`loadChanlunCharts()` 函数：

```javascript
fetch('/api/v3/chanlun/chart?ts_code='+...+'&period=long')
  .then(function(html){
    longBody.innerHTML = '<iframe srcdoc="'+html.replace(/"/g,'&quot;').replace(/\n/g,' ')+'"></iframe>';
  });
```

后端返回完整的 HTML 页面（含 `<h2>`、`<svg>`、`<script>`、`<style>` 等标签）。

### 2.2 根因：三层问题

**问题 2.2.1 — srcdoc 转义不完整（★★★ 最高影响）**

`html.replace(/"/g,'&quot;')` 仅转义了双引号，遗漏了：

| 字符 | 问题 | 示例 |
|:-----|:-----|:------|
| `&` | 未转 `&amp;` | HTML 实体和 URL 中的 `&` 会被解析为 HTML 实体开始 |
| `'` | 单引号未处理 | 属性值内的单引号会提前闭合 srcdoc 属性 |
| `<` | 理论上 JS 拼接无害，但若嵌入脚本则可能被 CSP 拦截 | iframe srcdoc 中内联脚本执行受限 |
| 换行 | `\n→空格` 会破坏 `<script>` 内的字符串字面量 JS | 代码中的多行字符串断裂 |

**修复方案**：放弃手写转义，使用 `URL.createObjectURL` 替代 srcdoc：

```javascript
.then(function(html){
    var blob = new Blob([html], {type: 'text/html;charset=utf-8'});
    var url = URL.createObjectURL(blob);
    longBody.innerHTML = '<iframe src="'+url+'" style="width:100%;height:600px;border:none;"></iframe>';
})
```

或使用更安全的 `srcdoc` 方案——通过 `encodeURIComponent` 编码：

```javascript
.then(function(html){
    longBody.innerHTML = '<iframe srcdoc="'+encodeURIComponent(html).replace(/%22/g,'&quot;')+'"></iframe>';
})
```

**推荐使用 Blob URL**：性能好、无转义问题、iframe 权限完整。

---

**问题 2.2.2 — 60分钟图误判逻辑（★★ 中影响）**

```javascript
if(html.indexOf('</h2>')<200){
    shortBody.innerHTML = '<iframe srcdoc="...">';
} else {
    shortBody.innerHTML = '短期数据不足（需要更多分钟K线）';
}
```

`</h2>` 在成功返回的 HTML 中的位置不固定。如果 `<head>` 部分较长，`</h2>` 可能出现在 200 字符之后，导致成功的 HTML 被误判为"数据不足"。

**修复方案**：改为检查 HTTP Content-Type 或 HTML 头部特征：

```javascript
.then(function(html){
    // 成功响应：后端返回完整 HTML 页面，以 <!DOCTYPE 开头
    if(html.trim().startsWith('<!DOCTYPE') || html.trim().startsWith('<html')){
        shortBody.innerHTML = '<iframe srcdoc="...">';
    } else {
        // 错误响应：后端返回 <h2>错误信息</h2>
        shortBody.innerHTML = '<div class="cl-placeholder">短期数据不足</div>';
    }
})
```

---

**问题 2.2.3 — 新股日线数据不足（★ 低影响）**

`301448.SZ` 2022 年上市，累计 K 线可能不足 60 条（`ChanlunAnalyzer.min_klines` 默认要求）。

后端 `chanlun_chart()`（`strategy_analyze.py:1000-1008`）已有处理：
- `df is None or df.empty` → 503
- `result` 含 `error` → 500

前端应分别处理这两个 case，目前仅通过 `catch` 统一处理为"数据暂不可用"。问题不大，但可优化用户体验（告知用户具体是数据不足还是系统错误）。

## 三、问题二："数据不足以生成现状描述"占位文本

### 3.1 现状

前端 `renderStockStatus()`（`indicator-ide.html:3216-3255`）的渲染逻辑：

```javascript
function renderStockStatus(dimensions, availability, deepseekText){
    if(deepseekText && deepseekText.length > 10){
        // 正常渲染 DeepSeek 九层文本
    } else {
        // fallback → 显示"数据不足以生成现状描述"
        dsBody.innerHTML = dimensions.chanlun && dimensions.chanlun.deepseek_text 
            || '数据不足以生成现状描述';
    }
}
```

但 `deepseekText` 来自 `analysisData.deepseek_text`（`indicator-ide.html:3189`），而 287 号方案 v2.3 已将此字段从 E12 响应中移除。

### 3.2 根因

**问题 3.2.1 — 前端未调用独立 DeepSeek 端点（★★★）**

287 号方案 §十明确将 DeepSeek 从 E12 中分离为独立端点 `POST /api/v3/strategy/deepseek`。
E12 响应中不再包含 `deepseek_text`，仅包含 `deepseek_available: true/false`。

前端应新增：

```javascript
function loadDeepseekText(tsCode){
    return fetch('/api/v3/strategy/deepseek?ts_code='+encodeURIComponent(tsCode))
        .then(function(r){ return r.json(); })
        .then(function(res){
            if(res.code === 0 && res.data && res.data.deepseek_text){
                deepseekText = res.data.deepseek_text;
                renderStockStatus(dims, availability, deepseekText);
            }
        });
}
```

调用时机：E12 响应返回且 `deepseek_available === true` 时调用。

**问题 3.2.2 — 287号方案"零改动选项"未执行（★★）**

287 号方案 §十 L644 约定：

> **零强制改动选项**：若暂时不改前端，E12 返回中 `deepseek_text` 字段设为空字符串、`deepseek_available` 设为 `false`，前端展示和现有行为完全不变。

当前 E12 响应（`strategy_analyze.py:600-612`）**仅包含 `deepseek_available`**，缺少 `deepseek_text: ''` 字段。前端 `analysisData.deepseek_text` 读取到 `undefined`。

**修复方案**：在 E12 响应中加入：
```python
response['data']['deepseek_text'] = ''  # 287号§十零改动选项
```

### 3.3 执行顺序建议

1. **短期**：后端 E12 响应加回 `deepseek_text: ''`（使前端 prototype 不报 undefined，仍显示占位）
2. **中期**：前端新增独立 DeepSeek 端点调用（解决"数据不足以生成现状描述"问题本身）

## 四、问题三：实操建议三场景话术机械

### 4.1 现状

`indicator-ide.html:3338-3376`，`renderActionPlan()` 函数：

```javascript
function renderActionPlan(analysisData, verificationData){
    var support = levels.support || '--';
    var resistance = levels.resistance || '--';

    // 情景A：趋势延续 — 完全固定模板
    stepsA.innerHTML = [
      '① 当前价附近建仓 30% 底仓',
      '② 放量突破'+resistance+'加仓至 50%',
      '③ 持有至目标位减仓 50%...',
      '④ 跌破'+support+'全部离场',
    ];

    // 情景B、C 同理...
}
```

三个场景的话术模板完全硬编码，仅嵌入了 `support`/`resistance` 两个数值。不依赖策略方向、置信度、缠论结构、市场状态等任何分析结果。

### 4.2 根因

**纯前端 UI 层固有问题**：该函数是前端 prototype 的展示逻辑，自始至终未与后端策略信号建立数据绑定。

### 4.3 修复方向（不涉及后端改动）

**方案 A（推荐）：后端生成场景话术（结构化输出）**

后端 `strategy_analyze.py` 的 E12 响应中，新增 `action_plan` 字段，由 `UnifiedStrategyCore` 或 `StatusOutputService` 根据实际策略信号生成：

```json
{
    "action_plan": {
        "scenario_a": {
            "title": "趋势延续",
            "steps": ["当前价附近建仓30%底仓", "放量突破XX加仓至50%", ...],
            "condition": "方向看涨且置信度>0.6"
        },
        "scenario_b": {
            "title": "冲高回落",
            "steps": [...],
            "condition": "放量冲高回落信号"
        },
        "scenario_c": {
            "title": "破位下行",
            "steps": [...],
            "condition": "跌破支撑位"
        }
    }
}
```

**方案 B（轻量）：前端根据策略方向微调话术**

现有前端的逻辑上增加方向判断：

```javascript
var trend = dimensions.factor && dimensions.factor.trend || '';
if(trend === 'bullish'){
    // 看涨 → 情景A偏积极
} else if(trend === 'bearish'){
    // 看跌 → 情景C提前预警
} else {
    // 中性 → 维持当前模板
}
```

**方案 C（暂缓）：不做改动，等 Vue 迁移时一次性重构**

> 当前是 HTML prototype 层面的问题。如果后续要迁移到 Vue，可在 Vue 组件中直接从 state 驱动话术模板。

### 4.4 建议

推荐**方案 A（后端结构化输出）** + **方案 C（Vue 迁移时统一实现）** 组合：
- 当前不修改前端（prototype 即将迁移）
- 后端先新增 `action_plan` 响应字段
- Vue 新前端直接从响应数据渲染三维场景话术
