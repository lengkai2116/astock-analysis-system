# 543｜日终完成保障（第 1–3 项）与耗时优化分析

## 一、背景

2026-10-23 用户追问：昨日日终为何停、停了之后系统有无修复机制保证当日日终有效完成，而非每日补采。只读盘点结论（见沟通记录 §047 前置）：既有 `_recover_stale_running` / 断点续算 / 完整性巡检 / 历史 QA 巡检 / QA 失败告警均**不覆盖 `pending` 静默停摆**，也没有「日终未完成」硬校验。用户拍板开 543 号，先落地第 1–3 项。

## 二、实施内容

### 2.1 管道停滞看门狗（第 1 项）

`backend/data_daemon.py`：

- 新增 `_check_pipeline_stall()`，主循环每 30s tick 调用。
- 以最新数据日 `pipeline_status` 的**状态指纹**（`(step_id, status)` 全集）判断进展：
  - 指纹变化 → 重置计时；
  - 连续 **90 分钟**指纹不变且未全部 `done` → `ERROR` + `monitor.create_alert` + `AlertNotifier`；
  - 告警 **30 分钟冷却**，避免刷屏。
- 与 `_recover_stale_running`（只处理 `running` 超 4h）互补：本项专门覆盖 `pending` 卡死。
- 新增统一告警出口 `_pipeline_alert()`（日志 + monitor + AlertNotifier）。

### 2.2 日终完成硬校验（第 2 项）

- 新增 `_check_eod_completion()`，每日 **08:30 后**首次 tick 执行一次。
- 取 `daily_cache` 最近两个交易日，校验**前一交易日** `QA-CHECK` 是否 `done`。
- 未完成：告警（`EOD_INCOMPLETE`）；若该日期 == 最新数据日，自动调用 `_drive_pipeline()` 续跑；若已早于最新数据日，只告警并提示人工回补（避免误推进/覆盖）。
- 结果缓存在 `_EOD_CHECK_STATE`，每日只执行一次。

### 2.3 启动步骤注册自检（第 3 项）

- `backend/app/data/enhanced_cache_manager.py` 新增模块级 `PIPELINE_STEPS`（18 项），作为**单一来源**；`ensure_pipeline_steps()` 改为遍历该常量。
- `backend/data_daemon.py` 新增 `_self_check_pipeline_registration()`，启动时在 `_drive_pipeline()` 之前执行：
  - 最新数据日无记录 → 正常初始化；
  - 有记录但缺少 `PIPELINE_STEPS` 中的步骤 → 告警 `PIPELINE_STEP_MISSING` 并补登记；
  - 存在未知步骤（白名单 `OUT-MARKET-CHECK`）→ WARN。
- 与 542 的运行时缺行兜底互补：542 保运行不卡死，543 在启动时暴露注册不一致。

## 三、验证

- `py_compile` 三文件通过。
- 新增 `backend/tests/test_543_eod_guard.py`（5 用例）：看门狗触发/进展重置、日终校验告警+续跑、QA done 跳过、自检缺失步骤告警+补登记。
- `pytest`：**5 passed**。

### 4.2 优化候选（按收益排序）

| 优先级 | 对象 | 方案 | 预期 | 风险/前提 |
|---|---|---|---|---|
| P0 | RAW-2（2h） | ① 单只 profiling 拆分 DB 读/特征计算/筹码引擎；② 批量预取当日 daily_basic/moneyflow/limit 到内存；③ 进程池（worker 只算、主进程批量写） | 2h → 30–40min | 需先 profiling；写回单点化，避免 SQLite 并发写 |
| P1 | SIG（74min） | ① 今天日志显示大量 `dim1通知daemon补采: precompute_raw`，按只写 sync_requests → **批量化**（每 100 只或 60s 合并）；② 进程池 + 预取；③ 跳过停牌/无当日数据股票 | 74min → 30–40min | dim1 唯一入口约束不变；需确认批量通知不丢补采 |
| P1 | JUD（42min） | 逐股 ORM/DB 往返改批量查询；status/treemap 构建合并 | 42min → 15–20min | 需保证快照字段契约不变 |
| P2 | COL-7（26min） | 财务数据季度更新，降频（每周/仅新报告期）或前移到 15:30–18:00 空窗 | 关键路径 −26min | 财务新鲜度要求需拍板 |
| P2 | COL-6（12min） | 概念板块降频/增量 | 关键路径 −12min | 板块变更频率需确认 |
| P2 | 关键路径重排 | 15:30–18:00 先跑 COL-7、RAW-2E 等非当日依赖步骤；18:00 后只跑当日行情链 | 关键路径 −30min 左右 | 需确认各步骤对「当日数据」的真实依赖 |
| P3 | 部署 | 云主机 7×24（已有部署规划） | 消除跨夜/关机 | 涉及成本与运维，需单独拍板 |

**结论**：当前最大单点是 RAW-2（约 2h），其次是 SIG（74min）、JUD（42min）。建议下一步先做 RAW-2 + SIG 的**只读 profiling**（单只耗时拆分、DB 往返次数、dim1 通知次数），再决定进程池/批量预取的组合；不要先盲目上多进程。

## 五、遗留

2. 日终硬校验的自动续跑只覆盖「未完成日 == 最新数据日」；更早日期仍需人工回补（10-21 未回补）。
3. 耗时优化仅完成分析，未改算法；需另开号实施。
4. 15:30–18:00 空窗利用与云主机 7×24 需业务/部署拍板。
