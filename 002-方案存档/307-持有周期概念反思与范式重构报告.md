# 持有周期概念反思与三元条件驱动框架

## 一、问题的回溯

### 1.1 最初的问题

306号方案（持有周期判定方案，状态分类法）试图将持有周期从"前端伪计算"升级为"服务端规则引擎产出"，采用了三层次状态分类框架（背景判定→状态分类→时间修正）。但在实际执行过程中，发现了一个更深层的问题——"持有周期"这个概念本身存在根本性的范式矛盾。

### 1.2 第一次纠正尝试：从"持有周期"到"机会窗口期"

在第一次讨论中，我们将 `hold_period_days` 的解释从"持满多久"改为"决策窗口期——你有多长时间来做出买入决策"。看似解决了问题，但经过进一步的反思，认识到这个修正本质上只是换了一个名字——无论叫"持有天数"还是"窗口期"，只要输出的是一个时间数值，就还是在预测。

### 1.3 第二次纠正——彻底的范式转换

**根本解决方案：把"时间"从系统输出中完全删除。不做任何形式的时间预测。取而代之的是三个字："看条件"。**

## 二、核心矛盾梳理

### 2.1 "持有周期"本质上是在预测

306号方案的规则树输出如下：

```
value_bottom   → hold_period='长线机会', hold_period_days='6月+'
main_upsurge   → hold_period='短线机会', hold_period_days='1-4周'
```

这行的话外之音是："你入场吧，然后持满这么久"——这就是预测。

这与系统遵循的核心原则直接矛盾：

- **右侧交易原则**——入场是基于"股票已经出现了明显的抬升信号"，而不是基于对未来涨跌的预测
- **UIDF（统一投资决策框架）**——"从"预测"到"分类与应对"，每类预设操作规则，而不是预设时间
- **系统的底层设计原则**——"减少对未来的预测，避免靠猜投资"

### 2.2 一个具体的矛盾场景

用户举了一个非常现实的例子：

> 我们判定一个策略是长期的，然后入场建仓了，两天后出现了非常好的出货机会，我们不卖因为这个策略是长期的。

这在实际交易中是荒谬的——没有哪个现有交易系统或交易者会这样做。这个矛盾的根源在于："机会识别"和"持有期限"被绑在了一起，而它们本质上是两个独立维度的信息。

### 2.3 "周期"应该发生在机会之后，而不是提前设定

用户的核心认知得到了确认：

> 周期实际应该是在机会之后发生的，入场购买了股票，基于股票现状不是最好的出货阶段那就需要持有，这才是周期。

背后的逻辑链是：

1. **入场**——基于右侧信号（趋势确认、放量突破、技术形态确认、优质低估标的识别等）
2. **持仓**——不是被动持满一段时间，而是**每日检查：入场时的前提条件是否还成立？**
3. **退出**——条件不再成立 → 退出，不论过了多久

**持有周期不是一个事先设定的值，而是每天监控后的后验结果。"持有了多久"是事后总结的数据，不是先验的约束。**

### 2.4 时间驱动 vs 条件驱动的范式比较

| 维度 | ❌ 时间驱动（旧范式） | ✅ 条件驱动（新范式） |
|------|-------------------|--------------------|
| 范式本质 | 分类后预测时间 | 分类后监控条件 |
| 输出 | "持有 6 个月" | "当估值回归到 fair 时退出" |
| 两天后出出货信号 | 因为是长线所以不卖（荒谬） | 条件触发→退出（正确） |
| 持满预设时间但条件没变化 | 按计划卖（可能错过上涨） | 条件没变→继续持有（正确） |
| 预测性质 | ✅ 有（预测了"6个月内会怎样"） | ❌ 无 |
| 用户看到的 | 一个数字（焦虑、不敢违背） | 一组条件（理解、可执行） |
| 与右侧交易兼容性 | ❌ 不兼容 | ✅ 完全兼容 |
| 与 UIDF 对齐 | ❌ 部分对齐 | ✅ 完全对齐（分类与应对） |

## 三、新框架：三元条件驱动

系统输出的核心应该是三个东西，**没有一个跟时间有关**。

### 3.1 第一元：多维机会画像（opportunity_profile）

**描述这只股票当前处于什么状态、机会的本质是什么。** 第一元不输出单一类型标签，而是输出**七维机会画像**——每个维度独立判定、并列呈现，机会类型仅作为画像的速览摘要。

#### 3.1.1 范式修正：从"机会类型"到"多维机会画像"

**问题诊断**：最初的 15 种机会类型采用 if-elif 逐层筛选（决策树式归约），它的设计目标是"从多维输入归约出一个唯一结论"。这是**分类器**的思维，不是**画像**的思维。逐层筛选必然丢失信息：

```
示例股票同时满足：
  main_force_phase = building      ← 趋势维度：主力建仓
  fina_health      = pass          ← 风险维度：财务健康
  valuation_level  = low           ← 价值维度：低估
  fund_flow        = 5d_outflow    ← 资金维度：资金在流出 ⚠️
  sentiment_phase  = climax        ← 情绪维度：市场高潮 ⚠️
  sector_heat      = top_10        ← 环境维度：热点板块
  catalyst_event   = none          ← 事件维度：无催化
  volume_price_fit = poor          ← 量价维度：量价背离 ⚠️
```

当前系统会命中 R2 → `value_bottom`，**趋势、资金流出、情绪高潮、量价背离这 4 个维度的信息在呈现层全部消失**。用户只看到"估值底部"四个字——但一个**资金在流出、情绪在高潮、量价在背离**的"价值底部"，与资金流入、情绪复苏、量价健康的"价值底部"，是两个完全不同的机会。把它们都标成同一个 `value_bottom`，用户无法区分，也无法信任。

**关键判断**：问题不在数据层，在呈现层。系统并不缺多维信息——每只股票在 `opportunity_tags_cache` 中已经拥有完整的 43 个标签值。问题出在"判定层把多维信息压缩成单一标签"这个动作上——是呈现方式消灭了信息，不是数据缺失。

**核心原则**：逐层筛选（if-elif 优先级决议）在**第二元（入场）和第三元（退出）**中是合理的——做买卖决策时需要唯一结论（买/不买/卖/不卖）。但**第一元（描述机会）不应该做归约**——描述应该并列展示所有维度。**用"画像"代替"分类"，是"多标签并列"代替"单标签归约"，逻辑完全不同。**

#### 3.1.2 七维画像设计

借鉴知识库 **"道天地将法"五维框架**（道=大盘、天=题材、地=量价、将=主力、法=纪律）与 **"多维度股票现状分析"七步法**，结合现有标签体系，设计七个独立维度：

| 维度 | 回答用户的问题 | 使用的现有标签 | 输出状态 |
|------|--------------|---------------|---------|
| 🛡️ **风险** | 这股票安全吗？ | `fina_health`, `main_force_phase` | 安全 / 警戒 / 危险 |
| 💰 **价值** | 便宜还是贵？ | `valuation_level`, `dividend_yield`, `pe_percentile_5y` | 低估 / 合理 / 高估 |
| 📈 **趋势** | 主力在干嘛？ | `main_force_phase`, `trend_alignment`, `phase_confidence` | 建仓 / 洗盘 / 拉升 / 出货 / 不明 |
| 📊 **量价** | 量价配合吗？ | `volume_price_fit`, `volatility_level` | 健康 / 背离 / 放量 / 缩量 |
| 💸 **资金** | 有没有主力关注？ | `fund_flow`, `chip_concentration`, `capital_nature` | 流入 / 流出 / 集中 / 分散 |
| 🌡️ **情绪** | 市场环境如何？ | `sentiment_phase`, `sector_heat` | 冰点 / 复苏 / 高潮 / 退潮 |
| ⚡ **事件** | 有催化剂吗？ | `catalyst_event`, `catalyst_impact` | 有（正向/负向）/ 无 |

**每一维独立判定，互不遮蔽。** 以上面的示例股票，七维画像输出：

```
风险:    🟢 安全（fina=pass）
价值:    🟢 低估（val=low）
趋势:    🟡 建仓（building, 置信度0.6）
量价:    🔴 背离（volume_price_fit=poor）⚠️
资金:    🔴 流出（fund_flow=5d_outflow）⚠️
情绪:    🔴 高潮（sentiment=climax）⚠️
事件:    ⚪ 无催化
```

用户一眼就能看到：这是一个"低估+建仓"的好机会，但同时存在量价背离、资金流出、情绪高潮三个风险点。机会的真实全貌被完整呈现，用户基于全部信息做判断，而不是被一个标签误导。

#### 3.1.3 机会类型：画像的速览摘要

15 种机会类型仍然存在价值——它是画像的**速览**（"这个股票整体属于价值类机会"），但不再承载全部信息。用户先看类型获得第一印象，再看七维画像获得完整认知，最后结合入场/退出条件做决策。

| 类型标识 | 描述文本 | 含义 |
|---------|---------|------|
| `value_bottom` | "估值底部，基本面优质" | 估值处于低位，财务健康，下行风险有限 |
| `building_watch` | "主力建仓观察" | 主力资金开始介入，趋势尚未确认 |
| `build_high` | "建仓在高位，矛盾信号" | 主力在建仓但估值已高，需谨慎 |
| `main_upsurge` | "趋势加速，动量充分" | 拉升阶段，情绪高潮，板块热点 |
| `steady_rise` | "慢牛上涨" | 温和拉升，非热点板块 |
| `lifting_general` | "拉升阶段" | 拉升基线，无特殊特征 |
| `wash_hot` | "洗盘热点，关注突破" | 洗盘阶段，热点板块 |
| `wash_general` | "洗盘整理" | 洗盘基线，等待方向 |
| `danger_zone` | "出货已确认，风险区域" | 出货+财务风险或高估值 |
| `danger_overval` | "出货+高估，风险区域" | 出货阶段+估值过高 |
| `dividend_play` | "高股息收益" | 高股息率，收益安全垫 |
| `event_driven` | "事件催化，快进快出" | 催化剂事件驱动 |
| `event_watch` | "事件观察" | 有催化剂但未放量 |
| `cold_value` | "冷门价值" | 财务健康+冷门+合理估值 |
| `quality_unknown` | "优质不明" | 财务健康+低估但阶段不明 |
| `no_signal` | "无明确信号" | 信息不足，不做判断 |
| `sentiment_ice/climax/ebb` | 情绪兜底系列 | 规则树未命中时的情绪基调 |
| `default` | "一般机会" | 以上均不匹配时的兜底 |

**设计原则**：

- 描述性文本替代"长线/中线/短线"等暗示时间的词汇
- 每种类型只说"现在是什么状态"，不说"将要持续多久"
- 文本本身就已经告诉了用户：这只股票为什么值得关注（或为什么不应关注）
- **机会类型是速览，七维画像才是完整信息**

#### 3.1.4 15+ 种机会类型的判定逻辑详解

机会类型判定是一个**五层递进的逐层筛选**过程（风险 → 价值 → 趋势 → 事件 → 兜底），由 `_classify_hold_status()` 规则树（data_daemon.py:1836-1919）实现。以下按五大类逐一讲解每种类型的判定标签组合与真实数据分布。

##### 第一大类：🛑 风险类（优先级最高，一旦命中即定案）

**`danger_zone` — 危险区**

市场情景：主力正在大规模出货，且公司财务状况已恶化（财务造假风险或经营风险）——"双重危险"状态，系统里最需要回避的股票。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `distributing`（出货阶段） | PhaseDetectionEngine |
| `fina_health` | `fail`（财务不健康） | FinancialRiskFilter |

现实含义：既在出货又在暴雷，没有任何持有理由。系统输出"不持有"，是唯一一个"无条件回避"的判定，不会被任何其他类型信号覆盖。当前数据库 `distributing` 598 只（9.7%）、`fina_health=fail` 561 只，两者交集即此类（预计几十只）。

**`danger_overval` — 出货+高估**

市场情景：主力在出货阶段，同时估值已处高位——主力正把高估的筹码派发给市场，追高者面临高位接盘风险。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `distributing` | PhaseDetectionEngine |
| `valuation_level` | `high` 或 `extreme_high` | ValuationEngine |

现实含义：与 `danger_zone` 的区别是财务面未暴雷，但"出货+高估"本身就是卖出信号。当前 `valuation_level=high` 2518 只、`extreme_high` 50 只，与 598 只 `distributing` 的交集构成此类（当前样本 4 只，占比极小，符合市场常态）。

##### 第二大类：🟢 价值类（基本面主导，最安全的机会）

**`value_bottom` — 价值底部区**

市场情景：系统最理想的状态之一。主力建仓 + 财务健康 + 估值低位三者共振——"好公司 + 便宜价格 + 聪明钱正在进场"，安全边际最高的机会类型。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `building`（建仓） | PhaseDetectionEngine |
| `fina_health` | `pass`（财务健康） | FinancialRiskFilter |
| `valuation_level` | `low` 或 `extreme_low` | ValuationEngine |
| （增强可选）`price_position` | `low_zone` | PhaseDetectionEngine |
| （增强可选）`trend_alignment` | `up_aligned` | PhaseDetectionEngine |
| （增强可选）`chip_concentration` | `concentrating` | ChipDistributionService |

现实含义：当前 `fina_health=pass` 仅 376 只（6.8%）——财务健康本身就是稀缺品；再叠加 building（2663只）+ 低估（1750只），三者交集预计几十只，正是"稀缺的优质机会"。**注意**：此类型只说明"机会存在"，入场仍需右侧确认（见 3.2 entry_signals）。

**`cold_value` — 冷门价值**

市场情景：财务健康、估值合理（或低估）、板块毫无热度——无人问津的好公司。因为没有热点资金炒作，往往被市场遗忘，但基本面提供安全垫。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `fina_health` | `pass` | FinancialRiskFilter |
| `sector_heat` | `none` 或 `normal`（冷门板块） | SectorRotationModel |
| `valuation_level` | `fair`、`low` 或 `extreme_low` | ValuationEngine |

现实含义：当前 `sector_heat=none` 4945 只、`normal` 706 只——大部分股票板块热度不高，说明 A 股热点高度集中。与 `value_bottom` 的区别：`cold_value` 不需要主力建仓信号，只要"财务健康+冷门+不贵"即可，是价值投资思路的兜底型机会。

**`dividend_play` — 高股息策略**

市场情景：股息率超过 3% 的股票。无论股价如何波动，分红本身提供收益保障，适合追求稳定现金流的长期持有逻辑——"防守型机会"。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `dividend_yield` | 数值 > 3（%） | ValuationEngine |

现实含义：当前股息率 >3% 约 608 只。此判定只用了一个标签——因为股息率本身是"高信息密度"的复合指标（股价+分红政策共同决定）。它被放在 R11 位置，意味着只有未被阶段类规则捕获的股票才会落入此类，实际规模几十只。

**`quality_unknown` — 优质不明**

市场情景：财务健康且估值低，但主力阶段信号不明确或不可靠——"公司质量没问题、价格也便宜，但没人知道它接下来会怎样"。机会存在但方向未定。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `fina_health` | `pass` | FinancialRiskFilter |
| `valuation_level` | `low` 或 `extreme_low` | ValuationEngine |

现实含义：规则树中的"骑跨"类型——不管主力阶段是什么，只要财务健康+低估即捕获（building 的会在更早的 R2 被 value_bottom 截走，剩下的大多是 washing 或阶段不明的股票）。放宽此条件后，候选约 177 只，实际落入此类的估计几十只。它给"基本面好但阶段模糊"的股票明确归类，而非落入"无信号"。

##### 第三大类：🟡 趋势类（主力阶段主导，机会的主体）

**`building_watch` — 主力建仓观察区**

市场情景：主力正在建仓，但既不是"价值底部区"（估值不够低或财务不够好），也不是"建仓在高位"（估值没有过高）——中性的建仓状态，有聪明钱进场但安全边际一般，需要观察后续演变。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `building` | PhaseDetectionEngine |
| （隐含）`fina_health` | 非 pass（被 R2 过滤后） | — |
| （隐含）`valuation_level` | 非 low/extreme_low（被 R2 过滤）且非 high/extreme_high（被 R3 过滤） | — |

现实含义：`building` 2663 只（43.4%）是 A 股最常见阶段，扣掉 R2/R3 捕获的，`building_watch` 是其中最大的主体（当前样本 14 只，全量运行后预计占全市场 15-25%）。"温和关注"级机会：不急着入场，等右侧信号。

**`build_high` — 建仓在高位（矛盾信号）**

市场情景：有趣且常见的矛盾状态——主力在建仓，但股价已涨得估值很高。说明主力可能在高位建仓博取更高弹性（成长股常见），也可能是诱多陷阱（养套杀）。信号自相矛盾，需谨慎对待。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `building` | PhaseDetectionEngine |
| `valuation_level` | `high` 或 `extreme_high` | ValuationEngine |

现实含义：当前样本 11 只。这是"矛盾信号"的典型代表——知识库 `信号冲突处理机制.md` 明确指出"因子方向冲突是常态"，此类型正是系统对冲突的显式回应：不武断说好或坏，而是标记为"需谨慎"。入场要求最高（必须有强右侧确认），否则宁可错过。

**`main_upsurge` — 主升浪**

市场情景：最强力的短线状态。拉升阶段 + 情绪高潮 + 热点板块三者共振——"天时地利人和"式的加速上涨，但也是风险积聚最快的时候，随时可能见顶。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `lifting` | PhaseDetectionEngine |
| `sentiment_phase` | `climax`（情绪高潮） | MarketSentimentService |
| `sector_heat` | `top_10` 或 `top_20` | SectorRotationModel |

现实含义：`lifting` 仅 458 只（7.5%），`sector_heat=top_10` 276 只 + `top_20` 274 只，`sentiment_phase=climax` 覆盖全市场——三者交集极小（预计个位数）。"极稀缺的短线爆发机会"，但知识库 `情绪周期四阶段模型.md` 警告：高潮期经验时长仅 2-3 天，是最需要快速决策的类型。

**`steady_rise` — 慢牛**

市场情景：主力在拉升阶段，但股票不在热点板块——没有情绪泡沫、没有热点炒作，就是一步一个脚印的温和上涨。这种"闷声上涨"往往比主升浪更持久、更健康。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `lifting` | PhaseDetectionEngine |
| `sector_heat` | `none` 或 `normal`（冷门/正常板块） | SectorRotationModel |
| （增强可选）`trend_alignment` | `up_aligned` | PhaseDetectionEngine |

现实含义：`trend_alignment=up_aligned` 1296 只，为慢牛类型提供很好的确认维度。与 `main_upsurge` 的区别就在"是否热点"——不靠情绪也能涨的股票，往往说明有真实资金持续买入，是趋势类中相对安全的选择。

**`lifting_general` — 拉升基线**

市场情景：主力在拉升阶段，但情绪既不是高潮、板块也不是热点（或无法归入前两类）——"普通拉升"状态。没有明显加速信号，也没有明显风险信号，属拉升阶段的默认归类。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `lifting` | PhaseDetectionEngine |
| （隐含）`sentiment_phase` | 非 climax（被 R5 过滤） | — |
| （隐含）`sector_heat` | 非 top_10/top_20 且非 none/normal 的边缘值 | — |

现实含义：`lifting` 458 只中扣掉主升浪和慢牛的剩余部分。机会质量中等——可关注，但不如慢牛稳健、不如主升浪迅猛。

**`wash_hot` — 洗盘热点**

市场情景：主力在洗盘阶段，但股票属热点板块。洗盘是拉升前的"蓄势"——主力故意打压股价清洗浮筹，热点板块说明市场关注度高，洗盘结束后向上突破概率较大。"洗盘+热点"的有利组合。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `washing` | PhaseDetectionEngine |
| `sector_heat` | `top_10` 或 `top_20` | SectorRotationModel |

现实含义：`washing` 2413 只（39.3%）是第二大常见阶段，但热点板块仅 550 只——交集预计几十只。价值在于"洗盘到位 + 关注度在线"，突破洗盘区间上沿时（右侧信号）是较好入场时机。

**`wash_general` — 洗盘基线**

市场情景：主力在洗盘阶段，且不在热点板块——普通洗盘整理。方向未定，等待主力选择向上突破还是向下破位。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `washing` | PhaseDetectionEngine |
| （隐含）`sector_heat` | 非 top_10/top_20 | — |
| （增强可选）`chip_concentration` | `concentrating`（筹码集中） | ChipDistributionService |

现实含义：当前样本 18 只，是 51 只样本中的最大类型（35%）。全量运行后预计占全市场 20-30%。"等待方向"型机会——既不说好也不说坏，等右侧确认信号（放量突破或缩量见底）再做判断。

##### 第四大类：🔴 事件类（催化剂驱动，时效性强）

**`event_driven` — 事件驱动**

市场情景：股票出现明确的催化剂事件，同时波动率处于高位——事件正在被市场定价，行情已开始剧烈波动。"快进快出"型机会，催化剂兑现或失效时信号立即消失。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `catalyst_event` | 非 `none`（如 lhb 上榜/breakout/pledge/regulatory） | EventMonitor |
| `volatility_level` | `high` | VolumePriceStrategy |

现实含义：`catalyst_event` 非 none 约 5300 只（其中 `fraud_sign` 4166 只是"财务造假信号"类负面事件，属警示性），`volatility_level=high` 1920 只——交集较大。**注意**：`catalyst_event` 中占比最大的 `fraud_sign` 是负面事件，这类"事件"应倾向警示而非机会，是后续需要细化的地方。真正的正向催化（lhb 301只、breakout 185只）才是机会。

**`event_watch` — 事件观察**

市场情景：股票有催化剂事件但波动率不高——事件已存在但尚未被市场放大定价，处于"有事件、等放量"的观察期。可能后续启动，也可能事件落空。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `catalyst_event` | 非 `none` | EventMonitor |
| `volatility_level` | 非 `high`（medium/low） | VolumePriceStrategy |

现实含义：与 `event_driven` 的唯一区别是波动率。它是事件类的前置观察状态——一旦波动率升高即升级为 `event_driven`，体现了类型之间的"状态转移"关系，而非静态标签。

##### 第五大类：⚪ 无信号/兜底类（信息不足）

**`no_signal` — 无明确信号**

市场情景：主力阶段无法判定（unknown 或缺失），且没有其他标签能给出有价值的信息——信息严重不足，系统诚实地说"我不知道"。这不是坏信号，而是"暂无判断"。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `main_force_phase` | `unknown`、空或缺失 | PhaseDetectionEngine |

现实含义：`main_force_phase=unknown` 仅 11 只（0.2%）——阶段判定引擎覆盖率极高，此类非常稀少。306号预估 20% 无信号，实际远低于此，因为 phase 判定的覆盖率远超预期。

**`sentiment_ice` / `sentiment_climax` / `sentiment_ebb` / `default` — 情绪兜底系列**

市场情景：前面所有规则都没命中（通常是阶段值处于未知与已知之间、又缺乏基本面/事件信息的边缘情形），系统退而求其次，用市场情绪阶段决定类型基调。

| 标签 | 取值 | 产出引擎 |
|------|------|---------|
| `sentiment_phase` | `ice` / `climax` / `ebb` | MarketSentimentService |

情绪基调规则：
- `sentiment_ice`（情绪冰点）→ "中线机会"基调（知识库：冰点期适合布局）
- `sentiment_climax`（情绪高潮）→ "超短机会"基调（知识库：高潮期应减仓兑现）
- `sentiment_ebb`（情绪退潮）→ "超短机会"基调（知识库：退潮期果断离场）
- `default` → 以上皆非时的最终兜底，"短线机会"基调

现实含义：规则树的"最后防线"，确保每只股票都有归类。当前 `sentiment_phase` 以 recovery 和 climax 为主（情绪服务输出以这两个为主），冰点/退潮极少见——说明市场当前整体处于复苏偏高潮的环境。

#### 3.1.7 多标签共识与证据计数

当前规则树是"单一路径命中即返回"的 if-elif 模式，把所有规则一视同仁，**忽略了信号本身的置信度**。建议引入**证据计数机制**，把单标签判定升级为多标签共识（知识库"多指标共识机制"——"当多个独立指标同时发出同向信号时，信号可靠性显著提升"）：

```
classify_opportunity_type(tags) → {
    type: 'value_bottom',
    evidence_count: 4,    ← 共同支持该判定的标签数
    total_possible: 6,    ← 理论上最多可用的标签数
    confidence: 'confident' | 'plausible' | 'weak'
}
```

| 证据数 | 标记 | 含义 |
|:------:|:----:|------|
| ≥5 | `confident` | 多标签强共识，判定可靠 |
| 3-4 | `plausible` | 中等可信，可参考 |
| 1-2 | `weak` | 仅靠少量标签，判断存疑 |

以 `value_bottom` 为例，证据可来自多个独立维度（最多 7 个）：

```
value_bottom 的证据链:
  ✅ main_force_phase=building                 (质量维度)
  ✅ fina_health=pass                          (质量维度)
  ✅ valuation_level=low/extreme_low           (位置维度)
  ✅ price_position=low_zone                   (位置维度，独立于估值)
  ✅ trend_alignment=up_aligned                (方向维度)
  ✅ chip_concentration=concentrating          (质量维度)
  ✅ fund_flow=inflow                          (资金维度)
  ✅ signal_strength > 4                       (聚合维度)
```

5 个以上标签同时指向同一结论时，误判概率极低。证据计数天然抑制了"养套杀"假信号风险——假信号通常只出现在 1-2 个标签上，不会触发多标签共识。

#### 3.1.8 信号冲突处理：多类型重叠的合理性

**一只股票呈现多个类型特征是市场的常态，不是系统错误。** 知识库 `信号冲突处理机制.md` 明确写道：

> 信号冲突并非偶发现象，而是多信号、多因子、多周期协同下的常态。因子方向冲突——不同因子在同一时点发出方向相反的信号。多周期矛盾——日线趋势向上时，4小时图可能正在回调。这种方向不一致是市场的常态，并非技术错误。

真实例子：
- `main_force_phase=building` + `valuation_level=high` → `build_high`（矛盾信号，市场常态）
- `main_force_phase=lifting` + `sentiment_phase=ice` → 个股拉升但大盘情绪冰点（应警惕）
- `fina_health=pass` + `main_force_phase=distributing` → 基本面好但主力在出货（应警惕）

**if-elif 优先级决议的合理性**：知识库中信号冲突处理的有效方法之一。当前优先级编码的领域逻辑是"买之前先问有没有风险 → 再问基本面好不好 → 再看主力阶段 → 再看事件驱动"，即**风控优先原则**：

```
R1   danger_zone       ← 安全优先，出货+风险 = 不持有
R2   value_bottom      ← 基本面优先，估值低+健康 = 可关注
R3   build_high        ← 矛盾信号优先，建仓+高估
R4   building_watch    ← 建仓基线
R5-R7 lifting 系列     ← 拉升阶段
R8-R9 washing 系列     ← 洗盘阶段
R10-R14 其他类型        ← 事件驱动、高股息等
R15  no_signal         ← 兜底
```

**注意**：逐层筛选对"决策"（入场/退出）合理，对"画像"（第一元）不合理。第一元应并列呈现所有维度（见 3.1.1），逐层筛选逻辑下沉到第二、三元。

#### 3.1.10 与 L4 仲裁层的关系（294号总纲整合）

七维画像与 294号总纲的 **L4 交叉验证仲裁层**（300号§二）不是重复，而是"**展示 vs 决策**"的分工，两者数据同源（均为 L2 标签池），顺序天然衔接：

| 维度 | 第一元：七维画像 | L4 共识投票仲裁（300号§2.2） |
|------|----------------|---------------------------|
| **回答的问题** | "这个机会是什么样？" | "综合来看，值不值得行动？" |
| **本质** | 状态描述（多标签并列） | 决策裁决（多标签汇总） |
| **输出形式** | 七维红绿灯 + 人话描述 | 共识率 + 操作建议 + max_position_ratio |
| **处理冲突的方式** | **展示**冲突（红绿灯并列，用户自见） | **仲裁**冲突（12 标签投票，系统定论） |
| **触发时机** | 地图方块颜色 + 浮窗 + 详情 | 点击方块后的深度诊断 |
| **依赖数据** | L2 标签池 | L2 标签池 + P2.1 事件评分（event_composite_score） |

**分工原则**：画像负责展示冲突，L4 负责仲裁冲突。例如画像显示"价值低估🟢 + 资金流出🔴 + 情绪高潮🔴"——用户看到冲突但不知如何行动；L4 用 12 标签共识投票（300号§2.2 Step C）算出共识率，输出"中等确认，建议建仓"或"分歧，仅做T"的明确结论。

**数据同源**：L4 的 12 个投票标签（`main_force_phase`/`valuation_level`/`trend_alignment`/`fund_flow`/`fina_health`/`catalyst_event`/`sentiment_phase`/`signal_strength`/`buy_sell_point`/`ma_alignment`/`price_position`）与七维画像的输入标签完全重合——**画像就是 L4 投票标签的可视化层**，前端可将 L4 投票表直接复用画像的红绿灯视觉语言。

### 3.2 第二元：入场信号（entry_signals）

告诉用户：**什么样的情形出现意味着可以入场了。** 每种机会类型有对应的入场条件。

| 机会类型 | 入场条件（需同时满足） |
|---------|-------------------|
| `value_bottom` | ① 估值仍在 low/extreme_low，② 基本面 fina=pass 未恶化，③ **趋势已确认向上（右侧）**：放量突破 20 日均线 / 出现底分型回踩确认 |
| `building_watch` | ① 主力阶段仍在 building，② **突破建仓成本区间上沿**（放量） |
| `main_upsurge` | ① 主力阶段 lifting，② **回踩不破关键支撑（如 MA10）时是入场点**，不是追高时入场 |
| `steady_rise` | ① 主力阶段 lifting，② 价格沿 MA20 缓步上行，③ 无超买信号 |
| `dividend_play` | ① 股息率 > 3%，② 价格未出现急涨（避免均值回归），③ 基本面 fina 未恶化 |
| `event_driven` | ① 催化剂事件确认，② 放量启动，③ 设置严格止损位后入场 |
| `wash_hot` | ① 洗盘结束信号（缩量到极致后放量），② 突破洗盘区间上沿 |

**核心变化**：

- 去掉了所有"机会"的暗示——这些条件是"确认入场时机"的工具，不是"评估是否值得入场"
- **第三条"右侧确认条件"是以前缺失的关键环节**——系统先识别机会，然后在"右侧信号出现时"入场，而不是状态一出现就立刻入场
- 入场条件随机会类型变化，而不是一刀切的"买入信号"

**与 L4 仲裁层的衔接（294号总纲）**：入场条件的满足判定**必须叠加 L4 共识率门禁**——只有 L4 共识投票（300号§2.2 Step C/D）达到"中等确认"及以上时，入场条件才真正成立：

```
入场条件 = 各类型右侧确认条件（上表） AND L4 共识率 ≥ 55%
```

| L4 共识率 | 判定 | 入场允许 |
|:---------:|------|:-------:|
| ≥ 75% | ★ 强共识（方向明确） | ✅ 允许建仓/加仓 |
| 55% ~ 75% | ✓ 中等确认 | ✅ 允许建仓 |
| 40% ~ 55% | ℹ 分歧（多空接近） | ❌ 仅做T/持有，不建仓 |
| < 40% | ⚠ 偏空/强烈看空 | ❌ 不推荐/清仓 |

**理由**：右侧确认条件解决"何时入场"（时机），L4 共识率解决"值不值得入场"（方向可信度）——两者 AND 才构成完整的入场决策，避免"技术形态到位但多空分歧"时贸然入场。

### 3.3 第三元：退出条件（exit_conditions）

替代 `hold_period_days`。语义是：**"当这些条件出现时，无论过了多久，都应当退出。"**

| 机会类型 | 退出条件（任一满足即退出） |
|---------|----------------------|
| `value_bottom` | ① 估值回到 fair 以上，② 基本面 fina 变为 fail/suspicious，③ 出出货信号（main_force_phase → distributing） |
| `building_watch` | ① 跌破建仓成本区间下沿（建仓失败），② 主力阶段变为 distributing |
| `main_upsurge` | ① 出现顶分型 + 量价背离，② 跌破 MA10/MA20（取决于强度），③ 主力阶段变为 distributing |
| `steady_rise` | ① 跌破 MA20 且 3 日内未能收回，② 出现出货信号 |
| `event_driven` | ① 催化剂事件已兑现，② 高波动消退（volatility_level 恢复正常），③ 出现反向技术信号 |
| `dividend_play` | ① 股息率跌破 2%，② 基本面 fina 变为 fail |
| `danger_zone` | 无条件——不应入场，已入场者立即退出 |
| `wash_hot` | ① 跌破洗盘区间下沿，② 主力阶段变为 distributing |

**设计原则**：

- **不是"到了什么时间该卖"，而是"什么情况发生了就该卖"**
- 完全不对未来做任何预测
- 多个退出条件以 OR 逻辑组合，任何一个满足即触发
- 退出条件与入场条件对称——入场条件消失即退出

**与 L4 仲裁层的衔接（294号总纲）**：退出条件包含**两条通道**——技术面/资金面退出（上表，由三元框架判定）与 **L4 估值跟踪退出**（300号§2.2，独立于共识投票的并行通道）。两条通道任一触发即退出，**以退出信号优先（涉及本金保护）**：

| 开仓时估值 | 触发条件 | 操作 | 归属通道 |
|-----------|---------|------|:-------:|
| low/extreme_low | `valuation_level` 变为 high/extreme_high + 情绪高潮 | ✗ 建议减仓/止盈 | L4 估值跟踪 |
| low/extreme_low | `composite_rating` 上升超过 +1.0 | ℹ 建议部分止盈 | L4 估值跟踪 |
| extreme_low | `valuation_level` 回升至 fair | ℹ 估值修复完成 | L4 估值跟踪 |
| 任何 | `fina_health` 从 pass 变为 suspicious/fail | ✗ 建议清仓检查 | L4 估值跟踪 |

**关系说明**：即使 L4 共识投票结果为"建仓"，只要估值跟踪退出条件被触发，`operation_advice.action` 以退出信号为准（300号§2.2 "两者冲突时以估值退出优先"）。三元框架的退出条件与 L4 估值跟踪退出并列组成完整退出决策。

## 四、与用户原始设想的对齐

用户最初的设想是：

> 一些优质的股票（基本面非常好且被价格低估的股票）在识别到比较好的低价格阶段入场，然后长期持有并在持有期间把握一些短周期的机会进行低买高卖，一方面提升盈利另一方面优化成本和风险。

用三元条件驱动框架翻译：

| 用户原始设想 | 三元框架的对应实现 |
|------------|-----------------|
| "优质股票在低价格阶段入场" | `opportunity_type=value_bottom` + `entry_signals=放量突破 MA20（右侧确认）` |
| "长期持有" | 不是预设 6 个月，而是**每天检查退出条件**：估值没回归、基本面没变差、没出出货信号→继续持有。持了多久？事后看是 6 个月，但事前不确定。 |
| "短周期机会低买高卖" | 当底仓股票出现 `opportunity_type=main_upsurge` 时，退出条件是"出现顶分型+量价背离"——触发就做差价。**不预设这个短线窗口是几天。** |
| "不是最好的出货阶段就持有" | `exit_conditions` 中包含了 `main_force_phase ≠ distributing`——出货阶段出现时自动触发退出，不管入场多久 |

**整个系统从时间驱动转变为条件驱动，时间变成事后统计而不是事前预设。** 这正是用户最初直觉的实现——"以条件为决策依据，以时间为后验结果"。

### 5.4 操作建议逻辑（消费 L4 共识率，不独立生成）

**操作建议以 L4 共识投票结果为唯一来源**（294号总纲 P2.3），三元框架不再独立生成建议文本，只提供入场/退出条件的状态供 L4 消费。最终建议由 L4 共识率映射（300号§2.2 Step D）：

```
操作建议 = L4 共识率映射表（300号§2.2）:
  共识率 ≥ 75%    → "★ 强共识，建议建仓/加仓"
  共识率 55%~75%  → "✓ 中等确认，建议建仓"
  共识率 40%~55%  → "ℹ 分歧，仅做T/持有"
  共识率 25%~40%  → "⚠ 偏空，减仓/回避"
  共识率 < 25%    → "✗ 强烈看空，清仓/不推荐"
  有效票数 < 3    → "ℹ 数据不足，不推荐"

叠加退出条件检查（优先级最高）:
  if (退出条件任一触发，含 L4 估值跟踪退出)
      → 覆盖上述映射："🔴 退出条件触发，建议卖出"
```

**关键修正**：三元框架的 `_advise_action()` 不再独立生成建议文本，而是**消费 L4 共识率**（作为共识投票的输入补充入场/退出条件状态）。这确保 294 体系（P2.2/P2.3）与 307 体系不会产出两套冲突的建议。

**完整决策流**：

```
L4 共识投票（冲突仲裁，300号§2.2）
   ├─ 输出 consensus（共识率）
   ├─ 输出 operation_advice（操作建议）
   └─ 输出 max_position_ratio（仓位比例）
         ↓ 三元框架在此消费
   第二元 入场条件 check ← 共识率 ≥ 55% AND 右侧信号确认
   第三元 退出条件 check ← 技术面/资金面退出 OR L4 估值跟踪退出
         ↓
   前端 L4 诊断区展示（共识率仪表盘 + 投票明细 + 操作建议）
```

这与同花顺的条件预警、雪球的盯盘逻辑一致——**条件驱动行为，不预设时间**。机会类型的色块保持简洁（用于 Treemap 方块着色），完整的七维画像在详情浮窗/卡片中展示，L4 诊断区在详情面板中展开。

### 5.5 用户直白表述层（小白友好）

> 目标用户为非量化分析师，可能不熟悉股市专业术语。本层确保**无论用户专业知识水平如何，都能快速掌握机会信息**。

#### 5.5.1 三层信息金字塔

不同专业水平的用户对信息深度的需求不同，用三层结构让所有人各取所需：

```
第一层：一句话结论（任何人都能看懂）
    "值得关注，但先别急着买，等它突破后再动手"

第二层：七维画像（有点基础的人能看懂）
    每个维度一句话 + 图标 + 红绿灯色

第三层：专业详情（想看数据的人能看懂）
    具体标签值、PE/PB、信号强度分数
```

**原则**：第一层用大白话，第二层半白话，第三层才允许出现专业术语。

| `cold_value` | 冷门价值 | **"没人注意的好公司，适合耐心埋伏"** 🎣 |
| `no_signal` | 无明确信号 | **"信息不足，暂时看不出什么，继续观察"** 📡 |

**对齐说明**：此结论对应 296号§二 三种模式浮窗的用户视角问题——机会地图浮窗回答"这是什么机会？"，即以本表的大白话结论为答案；价值地图浮窗回答"贵不贵？为什么？"，即引用 `valuation_level` 的人话翻译 + 估值证据链（296号§二"展示估值证据链，让用户自行判断估值结论是否可信"）。

#### 5.5.4 红绿灯直觉系统

小白最需要的是"这个能不能碰"的直觉。每个维度用交通灯三色表达，配合图标，5 秒内可理解：

```
🟢 绿灯 = 好/安全/便宜     → 可关注
🟡 黄灯 = 中性/观察/矛盾    → 需谨慎
🔴 红灯 = 坏/危险/贵       → 回避
```

**每只股票的七维画像直接就是七个红绿灯**——用户不需要理解任何术语就能感知机会的"健康度"：绿灯多就好，红灯多就危险。

**对齐说明**：本系统遵循 294号 D2 决策的"**用户零学习成本**"原则——颜色语义（绿=可关注/红=回避）是用户生活常识的自然延伸，无需记忆任何映射规则。

#### 5.5.5 与 L4 用户字段的整合（300号§2.4）

L4 诊断区（§5.1 L3 层）的用户可读输出全部经过直白表述层渲染：

| L4 字段（300号§2.4） | 直白表述层渲染 |
|---------------------|--------------|
| `verdict`（自然语言总结） | 用机会类型大白话 + 七维红绿灯摘要生成 |
| `voting_detail`（投票明细+原因） | 每个标签的看多/看空原因用 `TAG_PLAIN` 人话渲染 |
| `user_checklist`（用户自判清单） | 风险维度红灯项 + 矛盾信号的人话描述 |
| `operation_advice`（操作建议） | L4 共识率映射文本（§5.4） |

**用户自判原则**（300号§2.4）：系统提供"阅读依据 + 自查风险"（`user_checklist`），**不替用户做最终决定**——直白表述层确保用户能看懂这些依据后自行决策。

## 七、与主流平台实践的对照

### 7.1 通用模式：条件驱动而非时间驱动

各大平台（同花顺 SuperMind、BigQuant、通达信、雪球、东方财富等）的通行做法：

| 平台 | 核心功能 | 时间预设？ | 条件驱动？ |
|------|---------|:---------:|:---------:|
| 同花顺条件预警 | 条件满足时推送通知 | ❌ 无 | ✅ 持续监控 |
| 雪球条件单 | 价格触发执行 | ❌ 无 | ✅ 条件达成立即执行 |
| 通达信形态选股 | 符合特定形态的股票 | ❌ 无 | ✅ 形态判定 |
| BigQuant 策略回测 | 评分调仓 | 用户自行设定周期 | ✅ 因子评分驱动 |
| SuperMind 因子研究 | 因子衰减分析 | 提供参考数据 | ✅ 用户自行决策 |

行业实践中，"机会窗口期"这个概念**没有一个平台直接预设为硬性规则输出**。最接近我们"机会窗口期"概念的是**数据分析工具**中的统计参考——因子 IC 衰减曲线、历史形态回溯统计等，但这些都是展示给用户的**参考信息**，不作为交易系统的强制规则。

### 7.2 三元条件驱动框架的独特性

业内没有直接对标的功能，因为三元条件驱动框架是一个相对新颖的设计：

- 它比条件预警更结构化（入场条件/退出条件/机会类型三者绑定）
- 它比因子评分更可解释（不告诉用户分数，告诉用户"什么条件成立/不成立"）
- 它比形态选股更完整（包含识别→入场→退出全链路）

## 八、与知识库的完全对齐

| 知识库概念 | 核心观点 | 三元框架中的体现 |
|-----------|---------|----------------|
| **UIDF（统一投资决策框架）** | 从"预测"到"分类与应对"，每类预设操作规则 | `opportunity_type` 分类 + `exit_conditions` 规则 |
| **三层信号结构** | 确认层（方向）→ 执行层（时机）→ 过滤层（噪声） | 方向：`entry_signals` 中的右侧确认条件；时机：入场条件的第三条；过滤：`exit_conditions` |
| **多周期层级决策框架** | 背景周期决定方向，决策周期决定买卖 | 背景方向条件编码在 `entry_signals` 中，不做独立时间判断 |
| **因子衰减** | IC 衰减曲线——信号有效性随时间自然衰减 | 由 `exit_conditions` 替代时间预测——条件触发即退出，不论时间 |
| **卖出的考量因素** | "不要让盈利的筹码变成亏损"、"在次级别卖点出现时至少走一半" | 退出条件（顶分型、跌破均线等）取代"预设持有时间" |
| **状态依赖的动态周期** | 不同市场状态下激活不同的策略组合 | 入场条件和退出条件因 `opportunity_type` 而异 |
| **养套杀** | 假建仓信号的识别 | 在 `building_watch` 的退出条件中可增加"成交量脉冲式异常"检测；证据计数机制天然抑制假信号 |
| **道天地将法（五维框架）** | 道=大盘、天=题材、地=量价、将=主力、法=纪律 | 七维画像的直接理论来源——每个维度独立评估 |
| **多维度股票现状分析（七步法）** | 缠论结构→筹码主力→情绪周期→多因子→财报→量价形态→UIDF 验证 | 七维画像的方法论——"多层验证、相互制约，只有多维度同时发出正向信号才执行大仓位操作" |
| **信号冲突处理机制** | 信号冲突是常态，非错误；多指标共识提升可靠性；融合优于仲裁 | 3.1.8 多类型重叠的合理性论证；3.1.7 证据计数=多指标共识机制；**L4 共识投票引擎（300号§2.2）正是"多指标共识机制"的工程实现——12 标签归一化为 +1/0/-1 投票，共识率 ≥2/3 才行动** |
| **情绪周期四阶段模型** | 冰点防守、复苏布局、高潮减仓、退潮空仓 | 情绪兜底系列（sentiment_ice/climax/ebb）的基调依据；L4 情绪加权（300号§2.2 Step B）的理论来源 |

### 9.1 入场条件的量化来源

入场条件需要接入系统现有的技术指标和信号数据：

- "放量突破 20 日均线" → 需要读取 `indicator_ma` 表的 MA20 和日线成交量
- "出现顶分型" → 需要读取缠论分析中的分型判定
- "跌破建仓成本区间" → 需要读取筹码分布数据中的主力集中价

这些数据在现有系统中都已具备，入场条件判定函数可以复用这些数据。

### 9.2 退出条件的优先级冲突

当多个退出条件同时被触发时，系统如何排序和展示？

- 原则：**以最快的条件为准**——技术面退出条件通常应优先于基本面退出条件
- **与 L4 估值跟踪退出的关系**：三元框架退出条件与 L4 估值跟踪退出并列，任一触发即退出；两者冲突时以退出信号优先（涉及本金保护，300号§2.2）
- 前端展示：同时显示所有满足的退出条件，按风险等级排序

### 9.2.1 入场条件与 L4 共识率门禁的联动验证

- 入场条件 check 叠加 L4 共识率 ≥ 55% 门禁后，需验证：共识率 <55% 时入场状态必须为"等待/不宜"，防止仅凭技术形态入场
- 极端场景：右侧确认条件已满足但 L4 共识率仅 40%（多空分歧）——应显示"分歧，仅做T/持有"，提示用户不要建仓

### 9.2.2 操作建议的唯一性保障

- 操作建议以 L4 共识率为唯一来源（294号 P2.3），三元框架不独立生成建议文本
- 需防止两套建议并存：L4 层（P2.2 共识投票）与三元框架层必须单向依赖——三元框架只提供入场/退出条件状态，L4 负责最终裁决
- 验收：任意股票在同一时点，系统只输出一条操作建议

### 9.3 历史经验数据的后验统计

"不预测时间"不意味着不应该收集时间数据。系统可以统计：

- "历史上 opportunity_type=value_bottom 的股票，从入场到退出的平均/中位天数"
- "历史上机会触发退出条件 '跌破 MA20' 的分布统计"

这些数据作为统计参考提供给用户，但不是系统的强制输出。

### 9.4 从 306 号方案的迁移风险

| 风险 | 级别 | 缓解措施 |
|------|:----:|---------|
| 前端展示需要同步改造 | 🟡 中 | 第一阶段先完成服务端改造，前端展示降级为仅显示 `opportunity_label` |

### 9.5 机会类型判定合理性验证方案

为确保第一元的严谨性，实施后应执行以下验证：

1. **分布合理性检查**：全市场 5555+ 只股票的机会类型分布统计——不应出现某一种类型占比极度过半（如 wash_general 全量后预估 20-30%，若超 50% 需核查规则）
2. **人工抽样验证**：各类型随机抽取 20 只，人工核对七维画像与真实行情是否一致
3. **证据计数分布**：confident / plausible / weak 三类占比——若 weak 占比过高（>40%），说明判定依据不足，需补充增强标签（3.1.6 的 7 个未用标签）
4. **矛盾信号展示验证**：抽样股票中画像存在矛盾维度（如低估+资金流出）时，前端是否正确呈现

## 十、结论

1. **"持有周期"这个概念本身存在问题**——无论是"持有天数"还是"窗口期"，只要输出时间数值就是预测。

2. **三元条件驱动框架是彻底的对策**——`opportunity_profile`（多维机会画像）+ `entry_signals`（入场条件）+ `exit_conditions`（退出条件），完全不做任何时间预测。

3. **"周期在机会之后"是正确的逻辑**——持有多久是入场后每天检查退出条件的结果，不是入场前预设的约束。

4. **第一元必须是"多维机会画像"而非"单一机会类型"**——逐层筛选（if-elif）会把多维信息归约为单一标签，导致趋势、量价、资金、情绪等维度信息在呈现层丢失，用户无法全面了解机会也无法信任输出。七维画像（风险/价值/趋势/量价/资金/情绪/事件）每维独立判定、并列呈现，机会类型退化为速览摘要；逐层筛选逻辑下沉到第二、三元（入场/退出决策才需要唯一结论）。

5. **现有标签体系完全支撑判定**——43 个标签覆盖方向/位置/质量/环境/衍生五大类，已投产于 5555+ 只股票。当前规则树只用 8 个标签；引入 `trend_alignment`、`price_position`、`chip_concentration`、`fund_flow`、`phase_confidence`、`buy_sell_point`、`signal_strength` 这 7 个现有标签即可将判定可信度提升一个数量级。

6. **证据计数机制保证判定的严谨性**——多标签共识（≥5 证据 = confident）替代单一 if-elif 路径，天然抑制"养套杀"假信号，是让分类从"猜测"走向"严谨"的核心一步。

7. **一句话总结**：我们不需要告诉用户"这个机会还剩多久"，需要告诉的是"这个机会什么时候会消失"。前者是预测，后者是条件监控。再加上"什么条件出现时可以入场"与"当前机会的全维画像"，用户就拿到了所有决策所需的信息，没有任何预测成分。
