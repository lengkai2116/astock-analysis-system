# 选股系统流程合理性评估与优化方案

## 一、当前架构总览

### 1.1 三层 Pipeline 流程

```
Stock Pool (5000)
    │
    ▼ L1 风险剔除 (DarwinRiskFilter)
    │   ST/退市 → 流动性 → 高PE → 亏损微盘
    │   5000 → 3715 (74.3%)
    │
    ▼ L2 主力评分 (ChipScorer)
    │   筹码成本 → 量能剖面 → 趋势健康 → 价格稳定
    │   排序取 Top 100
    │
    ▼ L3 策略验证
    │   缠论(0.35) + 量价(0.30) + 因子(0.25) + Vibe(0.10)
    │   加权 → 综合评分 → 评级
    │
    ▼ 输出 (100只，有评分无淘汰)
```

### 1.2 当前实测数据

| 指标 | 数据 |
|------|------|
| L1 通过率 | 74.3%（3715/5000）|
| L2 截断 | 硬取 Top 100 |
| L3 通过率 | 100%（0 只被淘汰）|
| 评级分布 | S=1, A=2, B=21, C=61, D=15 |
| 综合分范围 | 27.7~64.8（0-100 尺度）|
| 执行耗时 | ~17 秒 |
| 数据覆盖 | 5537 只日线 + 5534 只 Stock 表 |

## 二、合理性评估

### 2.1 ✅ 架构合理性（好的部分）

| 特性 | 评价 |
|------|------|
| **三层漏斗结构** | 理念先进。相比聚宽/米筐的"单层筛选+排序"，多层管道允许在不同粒度上叠加不同维度的评估逻辑，逻辑更清晰 |
| **L1 风险剔除** | 规则完备（ST/流动性/估值/亏损微盘），使用 daily_basic_cache 数据源合规，不依赖实时 API |
| **L2 筹码评分** | ChipScorer 四维评分体系（成本/量能/趋势/稳定）设计合理，与 LEAN 架构理念一致 |
| **L3 策略正交性** | 缠论+量价+因子的正交低相关（Pearson r ≈ -0.1~-0.2），说明三个策略从不同维度评估股票 |
| **z-score 归一化** | 已修复各策略评分尺度差异，权重与影响力之间的错配从 ~12% 降至 ~2% |

### 2.2 ❌ 关键断点（需修复）

#### 断点 1：L2 硬截断 100 只，而非阈值筛选

```
当前: 取评分最高的 100 只 → 即使市场普跌也输出 100 只
期望: 评分 ≥ 阈值（如 6 分）通过 → 市场不好时可能只通过几十只
```

- ChipScorer 范围 2-10，均值 6.6。若设阈值 6 分，约 55% 通过
- 当前 3715 × 55% ≈ 2043 只，远高于 100，起不到"主力识别"的筛选作用
- 但若设阈值 7 分（前 45%），约 1671 只，又太多了
- **根因**：ChipScorer 本身区分度不足，大量股票集中在 5-7 分区间

#### 断点 2：L3 策略验证形同虚设

```
当前: 100 只候选股 → 100 只全部输出（0% 淘汰）
期望: 设置最低综合分阈值（如 30 分），不合格的股票不进入结果
```

- 当前即使评分最低的 27.7 分也归类为 D 级"回避"，但仍然输出给用户
- 用户看到 D 级股票出现在结果中，会困惑"为什么要推荐回避的股票给我？"

#### 断点 3：L2 → L3 之间无记忆传参

- L2 的 ChipScorer 评分（筹码维度）在 L3 中未被使用
- L3 重新从零计算缠论+量价，两层的计算结果没有交叉验证
- 214 号规格书要求 L3 包含筹码评分的交叉验证，但实际未实现

#### 断点 4：因子评分仅使用 OHLCV，未利用财务数据

```
当前因子 = 20日动量 + RSI14 + 量比 + 波动率（仅 OHLCV）
可用数据 = fina_indicator_cache（ROE/EPS/营收）+ daily_basic_cache（PE/PB/市值）
```

- ECM 已同步 `fina_indicator_cache`（财务指标 7082 行）、`daily_basic_cache`（5620 只×120天）
- 但没有被因子评分利用，因子评分目前仅基于 4 个简单的 OHLCV 派生指标
- 对比聚宽等平台，因子评分通常涵盖 50-200 个因子

#### 断点 5：Vibe 加分无区分度

```
当前: 只要有 Vibe 勾选，所有股票统一加 0.5×N 分
期望: Vibe 策略应产生差异化的评分
```

- Vibe 策略的本质是用户自定义规则，但目前的前端实现是文本描述+假代码生成
- 后端统一加分，没有任何股票级别的差异化判断

#### 断点 6：执行耗时 ~17 秒

| 阶段 | 耗时占比 | 说明 |
|------|---------|------|
| 数据加载 `load_stock_data_batch` | ~60% | 5000 只股票逐只查询 SQLite WAL |
| L3 缠论+量价计算（100 只）| ~35% | 每只运行两个复杂策略 |
| L2 ChipScorer（3715 只）| ~5% | 轻量计算 |

- 17 秒对前端交互体验不可接受（用户等待后可能刷新页面 → 重新计算）
- 前端超时 60 秒虽然足够，但用户感知差

## 三、行业对比分析

### 3.1 主流方案对比

| 维度 | 本系统 | 聚宽(JoinQuant) | 通联(DataYes) | 同花顺iFind | 开源项目(qlib等) |
|------|--------|-----------------|---------------|------------|------------------|
| **筛选架构** | 三层漏斗 | 因子打分排名 | 因子打分排名 | 条件筛选器 | ML 模型预测 |
| **因子数量** | 4 个（OHLCV） | 200+ | 300+ | 50+ 技术指标 | 100+（可扩展）|
| **权重机制** | 用户可调 | 平台固定 | 平台固定 | 无（条件式） | 模型自动学习 |
| **数据使用** | ECM 缓存 | API 实时 | API 实时 | 本地数据库 | 本地缓存 |
| **回测集成** | 独立回测引擎 | 内置回测 | 内置回测 | 模拟盘 | 内置回测 |
| **AI 辅助** | DeepSeek 接入 | 无 | 无 | 无 | ML 模型 |
| **响应时间** | ~17s | <3s | <5s | <1s | ~1s（预测）|

### 3.2 本系统的独特优势

- **三层漏斗架构**比同花顺/通达信的"条件筛选器"更系统化，逻辑层次分明
- **已接入双进程数据系统**（data_daemon 异步采集 + run.py 响应），数据基础扎实
- **DeepSeek AI 接口已注册**，但尚未真正用于选股场景（目前仅用于投研分析）
- **z-score 归一化**解决了多策略评分尺度差异的问题，专业平台上通常不做此处理

### 3.3 对标行业最佳实践的差距

| 差距项 | 行业标准 | 本系统现状 | 影响 |
|--------|---------|-----------|------|
| 因子数量 | 50-300 个 | 4 个 | 因子维度不足，选股维度单一 |
| 结果解释 | 因子贡献度分解 | 仅策略层面 | 用户不知为什么选中这只 |
| 筛选反馈 | 3-5 秒 | 17 秒 | 影响用户使用意愿 |
| 自定义条件 | 丰富的条件组合 | 仅 Vibe（未实现）| 用户控制感不足 |
| 回测验证 | 筛选结果可直接回测 | 需手动跳转 | 筛选→验证链路断裂 |

## 四、优化建议

### 4.1 短期修复（半天-1天）

| # | 问题 | 修复方案 | 涉及文件 | 优先级 |
|--|------|---------|---------|--------|
| S1 | L3 所有 100 只全量输出 | 设 `min_score` 阈值（默认 30 分），低于阈值的标记为 `filtered_out` 不参与排名；前端表格展示"当前条件筛选出 N 只符合条件的股票" | `screener.py` `compute_screening()` | **P0** |
| S2 | L2 硬截断 100 | 恢复为阈值筛选：保留评分排序，但仅输出评分 ≥ 6 分的股票（若无则输出评分最高的 20 只兜底） | `screener.py` L211 | **P0** |
| S3 | 17 秒加载体验 | 前端增加分步加载反馈：L1 完成 → 更新横条计数 → L2 完成 → L3 完成 → 显示结果 | `screener.html` `runScreening()` | P1 |
| S4 | 评级标签过于负面 | 调整评级映射，使 B/C 覆盖 50 分以上常见区间，D 仅用于极端低分（如 <20 分）。当前 S=1/A=2/B=21/C=61/D=15 的分布对用户心理不友好 | `screener_strategy_integration.py` `_score_to_grade()` | P1 |

### 4.2 中期优化（1 轮迭代）

| # | 优化项 | 说明 | 预估工时 |
|--|--------|------|---------|
| M1 | **因子库升级** | 利用已同步的 `fina_indicator_cache`（ROE/EPS/BPS）和 `daily_basic_cache`（PE/PB/市值/换手率），将因子从 4 个扩展到 15-20 个。合并到 `_compute_factor_score()` 中 | 1 天 |
| M2 | **结果可解释性** | 在结果中添加"因子贡献分解"：如"缠论+3.2分、量价+2.1分、因子-0.5分"，让用户知道为什么选中这只 | 0.5 天 |
| M3 | **筛选条件持久化** | 支持保存当前筛选条件为"策略模板"，后续可直接复用。复用 `strategy_templates_v2` 表 | 0.5 天 |
| M4 | **Vibe 真实执行** | Vibe 策略从"统一加分"改为真实条件执行。策略代码解析 `custom_strategy()` 函数，对每只股票计算差异化得分 | 1 天 |

### 4.3 长期方向

| # | 方向 | 说明 |
|--|------|------|
| L1 | **因子自动权重优化** | 基于历史回测数据，使用 LASSO/岭回归自动学习各因子的最优权重，代替用户手动配置 |
| L2 | **AI 选股助手** | 利用 DeepSeek 接口，用户输入自然语言条件（如"找业绩超预期且形态突破的股票"），AI 自动组合因子和策略参数 |
| L3 | **策略组合回测闭环** | 每次筛选完成后，自动对结果执行快速回测（持有期收益/胜率），验证筛选有效性 |

## 五、评估结论

### 5.1 总体判断

选股系统的**三层漏斗架构本身是合理且先进的**，优于同花顺/通达信的"条件筛选器"模式，也不同于聚宽/米筐的"因子打分排名"单层模式。分层处理使逻辑清晰且可独立优化。

### 5.2 当前核心问题

**不是架构不行，而是管道存在断点**：
- L2→L3 之间没有真正的筛选（100 只全部通过）
- L3 策略评分缺乏淘汰机制
- 因子评分停留在 4 个 OHLCV 指标的初级阶段，浪费了已同步的财务数据

### 5.3 推荐优先级

```
P0（当前可修）: S1+L3淘汰 + S2+L2阈值 + 评级标签调整
P1（1-2天）: M1因子升级 + M2结果可解释 + M4 Vibe执行
P2（下一轮）: M3条件持久化 + L1/L2/L3 长期方向
```

### 5.4 一句话总结

> 三层漏斗是好架构，但**管道断了**——L2 不筛选、L3 不淘汰。修复断点 + 升级因子库（利用已同步的财务数据）后，选股系统的有效性可提升 1-2 个数量级。
