## 单维度引擎输出端核查框架

> 本节为dim2-dim7+dim1统一的输出端核查标准，适用于每个维度引擎的分析输出质量评估。

### 一、核查维度（5项）

#### 1. 输出字段消费链路核查

对每个维度引擎的三类输出（status_description / judgment / audit）逐字段追踪：

| 核查项 | 方法 | 判定标准 |
|--------|------|---------|
| **已消费字段** | grep 消费方代码（dim8 / dim_adapter / conflict_matrix / API routes）确认字段被读取 | 标记 ✅ |
| **降级消费字段** | 字段仅在 fallback 路径中被读取（如 dim8 降级兜底） | 标记 ⚠️ |
| **未消费字段** | 任何下游代码均未读取该字段 | 标记 ❌ |
| **消费方一致性** | 同一字段在不同消费方的读取方式是否一致（key名/类型） | 不一致标记 ⚠️ |

**产出**：字段消费率统计表

```
status_description 已消费率 = 已消费字段数 / 总字段数
judgment 已消费率 = 已消费字段数 / 总字段数
audit 已消费率 = 已消费字段数 / 总字段数
```

**基准线**（来自 dim2-dim4 实际数据）：

| 维度 | status_description | judgment | audit |
|------|:-----------------:|:--------:|:-----:|
| dim2 | 64% | 100% | 100% |
| dim3 | 43% | 0% | 0% |
| dim4 | 43% | 67% | 25% |
| dim5 | 72% | 43% | 0% |
| dim6 | 58% | 80% | 25% |
| dim7 | 55% | 71% | 25% |

**目标**：judgment 和 audit 消费率应趋近 100%（这两个字段是给下游判定用的，不消费等于白算）。

#### 2. 输出真实性核查

对每个输出字段判定计算真实性：

| 判定 | 定义 | 处置 |
|------|------|------|
| ✅ 真实计算 | 从数据库/算法实际计算得出 | 正常 |
| ⚠️ 派生值 | 从其他字段简单变换（如 `1.0 - x`） | 标注派生关系 |
| ⚠️ 阈值判定 | 基于阈值的简单分类（如 ASR>80 → "高"） | 标注阈值依据 |
| 🗑️ 占位/默认值 | 固定返回常量或空值 | 需评估是否应删除或实现 |
| ❌ 缺失 | 应有但未实现（breadth=None 等） | 标记为待实现 |

**产出**：真实性判定表，标注每个字段的计算来源和可信度。

#### 3. 输出格式一致性核查

对比所有维度引擎的输出格式是否统一：

| 核查项 | 标准 | 不一致表现 |
|--------|------|-----------|
| **judgment 结构** | 必须包含 `light` / `overall_light` / `overall_direction` / `continuous_value` | dim3 的 judgment 字段全部未被消费 |
| **light 取值** | `green` / `yellow` / `red` 三值 | 无 |
| **overall_direction** | `1`(看多) / `0`(中性) / `-1`(看空) | 无 |
| **audit 结构** | 必须包含 `conditions` / `satisfied_count` | dim3/dim4 的 audit 大部分未被消费 |
| **evidence 字段** | 各维度的 `*_evidence` 字段命名和格式 | dim2 有11个evidence未消费，dim3 有7个 |

**产出**：格式一致性对比表，标注偏差项。

#### 4. 下游消费方覆盖度核查

检查 dim8 / dim_adapter / conflict_matrix 是否为每个维度引擎提供了完整的消费路径：

| 消费方 | 职责 | 核查点 |
|--------|------|--------|
| **dim_adapter** | 读取 judgment 连续值 + 方向 + 置信度 → 转换为 dims 格式 | 是否读取了每个 dim 的 `continuous_value` / `overall_direction` / `light` |
| **dim8** | 读取 status_description → 生成六维三层描述 | 是否为每个 dim 实现了 `_build_xxx_text` 方法 |
| **conflict_matrix** | 读取各 dim 的 light + direction → 冲突检测 | 是否读取了每个 dim 的 `overall_light` + `overall_direction` |
| **API routes** | 读取 status_description → 前端展示 | 是否有对应的 API 端点 |

**产出**：消费方覆盖矩阵（dim × 消费方）

#### 5. 死代码/冗余输出清理评估

对未消费的字段进行分类处置建议：

| 类别 | 处置 | 示例 |
|------|------|------|
| **有价值但未接通** | 建议消费方扩展读取 | dim4 的 `cost_asr` / `cost_cyqkl`（有计算但 dim8 未读） |
| **冗余重复** | 建议删除 | dim3 的 `state_machine_state` 与 `vp_state` 重复 |
| **占位/默认** | 建议实现或删除 | dim5 的 `breadth=None` |
| **派生可推导** | 建议从其他字段推导而非独立计算 | dim4 的 `continuous_value = 1.0 - crowding_score` |
