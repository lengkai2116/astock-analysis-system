## 二、缺失数据详情

### M1：RSI_14（14日相对强弱指标）

**所属维度**：维度2 结构位置 → vs_indicator子维度

**当前状态**：pre_feat_cache中不包含RSI_14字段。dim2的`_assess_vs_indicator`函数从tags读取`RSI_14`，但tags中无此数据，导致vs_indicator永远返回"指标数据不足"。

**分析内容**：RSI衡量价格涨跌力度，判断超买/超卖状态。
- RSI > 70：超买区，可能回调（高位信号）
- RSI < 30：超卖区，可能反弹（低位信号）
- RSI 30-70：正常区间

**知识库依据**：`jishu-zhibiao.md`（RSI组成+超买超卖判断）、`RSI反转信号.md`（康斯坦丝·布朗RSI反转信号体系）

**计算方式**：从daily_cache的OHLCV数据计算，公式：RSI = N日涨幅均值 / (N日涨幅均值 + N日跌幅均值) × 100

**建议补充位置**：RAW-2（FEAT）预计算阶段，写入pre_feat_cache的volume_price或新增indicator组

---

### M2：KDJ_J（随机指标J值）

**所属维度**：维度2 结构位置 → vs_indicator子维度

**当前状态**：pre_feat_cache中不包含KDJ_J字段。dim2的`_assess_vs_indicator`函数从tags读取`KDJ_J`，但tags中无此数据，导致vs_indicator永远返回"指标数据不足"。

**分析内容**：KDJ衡量收盘价在近期价格区间中的位置，J值是最敏感的摆动线。
- J > 80：超买区
- J < 20：超卖区
- K/D金叉：买入信号
- K/D死叉：卖出信号

**知识库依据**：`jishu-zhibiao.md`（KDJ组成+超买超卖判断）、`liangjia-xingtai-KDJ.md`（KDJ量价形态）

**计算方式**：从daily_cache的OHLCV数据计算，公式：RSV = (收盘价 - N日最低价) / (N日最高价 - N日最低价) × 100；K = 2/3 × 前K + 1/3 × RSV；D = 2/3 × 前D + 1/3 × K；J = 3K - 2D

**建议补充位置**：RAW-2（FEAT）预计算阶段，与RSI_14一起写入pre_feat_cache

### M3：sentiment_pool_cache数据过期（高严重度）

**所属维度**：维度5 情绪环境 → 市场情绪层（A层）全部功能

**当前状态**：`sentiment_pool_cache`位于`stock_cache.db`，仅**2行数据**，最新日期**2026-07-17**（已过期2个月）。该表由`akshare_collector.py`的`_collect_sentiment_pool()`函数写入。

**受影响功能链**：
```
sentiment_pool_cache(过期) 
  → MarketSentimentService.get_sentiment_phase() 
    → sentiment_phase tags(全市场全局, 所有股票相同)
      → dim5._assess_market_emotion() — 六段论阶段判定失效
      → emotion_ext.market_emotion — 全部为旧值
      → dim5情绪温度(market_phase权重25%) — 使用过期数据
      → cross_validate.py sentiment_phase投票 — 情绪权重失效
      → data_daemon全局sentiment_phase — 全局变量过期
```

**具体影响**：
| 受影响功能 | 影响程度 | 说明 |
|-----------|---------|------|
| 六段论情绪周期(ice/sprout/ferment/climax/ebb/regression) | **完全失效** | 用2个月前的涨跌停数据判定当前阶段 |
| 涨停生态5指标(涨停家数/炸板率/涨停溢价/连板高度/首板家数) | **完全失效** | sentiment_pool_cache无近期数据 |
| 情绪温度(market_phase 25%权重) | **部分失效** | 使用过期的sentiment_phase |
| BOCIASI四象限 | **不受影响** | 从daily_cache/daily_basic_cache计算 |
| BOCIASI快慢线 | **不受影响** | 从daily_cache/daily_basic_cache计算 |
| 板块热度 | **不受影响** | 从pre_feat_cache.sector_heat读取 |
| 时间节奏 | **不受影响** | 从daily_cache计算 |

**数据验证**：
```sql
-- stock_cache.db
SELECT COUNT(*), MAX(trade_date), MIN(trade_date) FROM sentiment_pool_cache;
-- 结果: count=2, max=2026-07-17, min=2026-07-17

-- 对比：其他表数据新鲜度
daily_cache: 2026-08-28 (5578 stocks)
daily_basic_cache: 2026-08-28
pre_feat_cache: 2026-08-28 (5576 stocks)
indicator_other: 2026-08-28
```

**根因分析**：`_collect_sentiment_pool()`在`akshare_collector.py:307`定义，通过`_CollectThread`定时执行（间隔1800秒）。可能原因：
1. akshare接口变更导致采集失败（静默异常）
2. stock_cache.db分库写入失败
3. 定时线程未正常启动

**建议修复路径**：
1. 检查akshare_collector日志确认采集是否正常执行
2. 手动触发一次`_collect_sentiment_pool()`验证数据写入
3. 确认`ecm.write_sentiment_pool()`的分库路由指向stock_cache.db

### M4：dividend_yield未传入slowline（低严重度）

**所属维度**：维度5 情绪环境 → BOCIASI慢线 → 股债收益差指标

**数据验证**：
```sql
-- compute_cache.db
SELECT COUNT(*) FROM pre_feat_cache WHERE features_json LIKE '%dividend_yield%';
-- 结果: 38872/38872 (100%有此字段)
```

**影响**：慢线从4指标降为3指标（ERP+股债位置差+融资趋势），缺少股债收益差。

**建议修复**：在evaluate()中读取`tags.get('dividend_yield')`并传入`_bociasi_slowline(dividend_yield=dy)`（1行代码）。

### M10：dim7估值精度受限（高严重度）

**所属维度**：维度7 估值 → 四锚加权估值 + 财务健康检查

**当前状态**：dim7依赖的3个财务数据表为空（与dim6共享M6/M7/M8），导致：

| 数据表 | dim7受影响方法 | 影响 |

**建议修复**：确认data_daemon的财务数据采集管道（fina_indicator/income/cashflow/balancesheet）是否正常运行。

## 四、补充方案（待全量审查后统一制定）

### 4.1 补充路径选项

| 选项 | 方式 | 优点 | 缺点 |
|------|------|------|------|
| A | RAW-2（FEAT）预计算阶段补充 | 一次计算全市场复用，不增加dim2运行时开销 | 需修改RAW-2代码+重算pre_feat_cache |
| B | dim2引擎内部自行计算 | 不依赖外部数据源，自包含 | 每次evaluate都重新计算，增加运行时开销 |
| C | 混合模式：RAW-2预计算+dim2兜底计算 | RAW-2有数据时用预计算，无数据时dim2自行计算 | 实现复杂度略高 |

### 4.2 优先级评估（待全量审查后确定）

| 优先级 | 考量因素 |
|--------|---------|
| P0 | 该数据是否直接影响维度核心输出（如vs_indicator影响position判定） |
| P1 | 该数据是否有其他来源可替代（如MACD可替代RSI的部分功能） |
| P2 | 该数据的计算复杂度（RSI简单，KDJ中等） |
