# 551｜机会地图「机会 / 执行」两层拆分（A 口径）

## 一、缘起

用户指出：机会地图本来回答“有没有机会”，但当前 38 只 `enter/light` 中 **25 只（65.8%）同时显示“持有/观望”**，看起来像两个相反结论。

核查确认不是机会地图算错，而是两层语义共用一个枚举并同屏：

- **机会状态**：`status_verdict.opportunity_state` / `treemap_snapshot.opportunity_state`（enter/light/wait/reduce/avoid）。
- **执行建议**：`operation_advice.state/action_label`，在机会状态之后又过 RR<2、L0c 信号延伸等门禁。

25 只不一致中：21 只 RR<2、4 只 L0c；其中 12/25 实际是“上方目标太近”，不是代码文案统一写的“止损过宽”。

## 二、A 口径

保留 `opportunity_state` 作为**机会方向**，不修改阈值、不回写状态；在执行侧新增**独立展示行**，回答“现在这个价是否值得新开”：

```text
🎯 机会（方向）：可入场
🧭 执行（新开）：暂不新开（持有/观望）
   RR 0.36 <2 · 上方 +3.29% · 下方 -9.09%
   原因：盈亏比不足……
   新开 0% · 持有上限 16%
```

## 三、实施（仅前端）

文件：`_ui-prototype/opportunity-treemap.html`

1. 结论卡新增 `#d-execution-row`，只在 `/diagnose` 返回后显示；切股/失败时清空。
2. 新增 `executionMeta(oa)` / `renderExecutionRow(oa)`：
   - 执行状态：`operation_advice.state/action_label`；
   - RR：`geometric.risk_reward`；
   - 空间：`geometric.dist_to_resistance_pct` / `dist_to_support_pct`；
   - 原因：`state_reason` / `summary`；
   - 仓位：执行 wait 时显示“新开 0% · 持有上限 X%”，可执行时显示“仓位上限 X%”。
3. 结论卡主行改“🎯 机会（方向）”，`d-verdict` 改“机会：可入场/可轻仓”。
4. 操作区把“持有/观望”改为“暂不新开（持有/观望）”，不再显示旧“动作待复核”警告。
5. 地图侧统一改称“机会状态”：
   - 筛选标签“机会”；
   - 浮窗“● 机会”；
   - 侧栏“机会”；
   - 图例“机会状态 · … · 点击看执行建议”；
   - 图例说明改为“机会状态回答有没有机会；是否可新开以执行行为准”。
6. 删除 `STATE_ACTION_EXPECT` / `actionConflict` 及“动作待复核”文案。

**未改**：`opportunity_state`、RR 阈值、`operation_advice` 生成逻辑、`status_snapshot`/`treemap_snapshot` 数据。
