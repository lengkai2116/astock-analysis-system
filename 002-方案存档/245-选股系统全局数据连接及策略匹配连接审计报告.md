# 选股系统全局数据连接及策略匹配连接审计报告

> **关联文档：** [214号](./214-选股系统后端开发技术规格书.md) | [123号](./123-选股系统与个股分析解耦重构方案.md) | [239号](./239-系统全局数据体系分层设计方案.md) | [244号](./244-全局数据体系分层架构方案（规则C修订版）.md)

## 一、审计范围

对选股系统（Screener）端到端数据连接链路的全面审查：

```
用户 → 前端Vue页面 → screenerService.js → Flask API路由 → 筛选引擎 → DataManager → 缓存层(DuckDB/SQLite) → Tushare Provider
```

审计焦点：
1. **全局数据连接**：每层数据管道是否有效连通
2. **策略匹配连接**：214号方案要求的缠论/量价/因子/Vibe 4类策略是否真实接入流水线
3. **前端↔后端连接**：API参数传递是否正确匹配

## 三、详细问题清单

### 🔴 问题1：L3策略验证是空壳（优先级P0）

**现象：** `routes/screener.py` `compute_screening()` 的L3验证仅检查 `len(df) >= 60`，无任何真实策略评分。

**代码位置：** `backend/app/routes/screener.py:173-181`

```python
# ── L3: 策略验证 ──
validated = []
for item in l2_top:
    df = data_dict.get(item['symbol'])
    if df is None or len(df) < 60:
        continue
    # 验证条件: 60日数据完整  ← 这就是全部"验证"
    ...
```

**214号方案要求：** 需要输出每个股票的 `strategy_detail` 包含：
- `chanlun`: 方向/评分/信号（三买确认等）
- `volume_price`: 方向/评分/信号（VP-1价涨量增等）
- `factor`: 多因子组合评分
- `vibe`: Vibe策略评分

**可用但未使用的策略代码：**

| 策略文件 | 行数 | 状态 |
|:---------|:-----|:----|
| `backend/app/engine/framework/volume_price_strategy.py` | 3539行 | ✅ 完整实现 |
| `backend/app/engine/framework/chanlun_strategy.py` | 2642行 | ✅ 完整实现 |
| `backend/app/engine/pipeline.py` ChipDistributionStrategy | 完整实现 | ✅ 含PreFilter+筹码分布+资金流 |
| `backend/app/engine/pipeline.py` StrategyPipeline | 全局注册 | ✅ 但未被调用 |
| `backend/app/engine/framework/chip_strategy.py` ChipScorer | 简化版 | ⚠️ 仅为价格/成交量动量评分 |

### 🔴 问题2：API参数命名不一致（优先级P0）

**位置：** Frontend ↔ Backend 参数key不匹配

| 路由 | 后端读取(key) | 前端发送(key) | 调用未传参时 | 传参时 |
|:-----|:-------------|:-------------|:-----------|:------|
| `/layer1` | `data.get('stockPool')` | `stock_pool` | 无症状(None) | ❌ 失效 |
| `/layer2` | `data.get('stockPool')` | `stock_pool` | 无症状(None) | ❌ 失效 |
| `/layer3` | `data.get('stockPool', [])` | `candidates` | 无症状([]) | ❌ 失效 |

**影响：** 即使今后前端开始传参，后端也读不到正确参数。当前因为 `index.vue` 调 `runLayer1/2/3()` 不带参数，所以问题处于潜伏状态。

---

### 🔴 问题3：因子组合API路径不一致（优先级P0）

**214号§2.6要求：** `GET /api/v3/factors/combinations`
**实际后端路由：** `GET /api/factors/combinations`（注册在 `factors_bp`，url_prefix=`/api/factors`）
**前端调用：** `GET /api/factors/combinations`（`factorService.js:50`）

**现状：** 前端与后端一致 ✅，但与214号方案文档中声明的 `/api/v3/factors/combinations` 路径不符。

**问题：** 选股系统前端页面(`screener/index.vue`) 并未调用 `factorService.getCombinations()` 来动态加载因子组合复选框。只有因子管理页和回测页调用了因子组合API。选股页的因子组合功能未对接。

### 🟡 问题5：ChipScorer是简化版而非真实筹码分析（优先级P1）

**位置：** `backend/app/engine/framework/chip_strategy.py:229-308`

`ChipScorer` 仅做了简单的价格动量+成交量+价格位置评分（约40行计算逻辑），并非真实的筹码分布分析。

真实的筹码分析实现在 `pipeline.py` 的 `ChipDistributionStrategy` 中（含 `ChipPreFilter` + 筹码分 布计算 + `TradingPhaseDetector` + 资金流向集成），但选股路由从未使用它。

---

### 🟡 问题6：前端执行策略链为单层串行调用（优先级P2）

**位置：** `frontend/vue-project/src/views/screener/index.vue:87-116`

`startScreening()` 方法依次调用 `runLayer1()` → `runLayer2()` → `runLayer3()`，但：
- 每次调用都不带参数
- L1→L2→L3之间没有传递筛选结果（L2应该对L1通过的股票评分，L3应该对L2评分的股票验证）
- 这意味着L3的 `candidates` 参数始终为空

**214号方案有 `POST /api/v3/screener/run` 端点可以直接执行全流程，但前端没有使用它。**

## 四、策略匹配连接深度分析

### 4.1 214号方案要求的策略体系 vs 实际实现

| 策略 | 214号要求 | 实际实现 | 差距 |
|:-----|:---------|:---------|:----|
| 缠论 (chanlun) | 方向/评分/信号(三买/一卖等) | ❌ 未接入 | `chanlun_strategy.py` 完整实现但未被使用 |
| 量价 (volume_price) | 方向/评分/信号(VP-1~VP-9) | ❌ 未接入 | `volume_price_strategy.py` 3539行完整实现但未被使用 |
| 因子 (factor) | 组合评分 × 组合权重 | ❌ 未接入 | 前端因子组合API可用，但选股页未对接 |
| Vibe Coding | AI动态生成策略 | ❌ Mock数据 | 3个硬编码策略，未从模板DB同步 |
| 筹码 (chip/L2) | 主力阶段+ASR+集中度 | ⚠️ 简化版 | 使用简化的 `ChipScorer`，非真实筹码分析 |

### 4.2 策略注册表使用链

```
pipeline.py: StrategyPipeline (全局注册)
├── DarwinSelectionStrategy  → ❌ stub (implemented: false)
├── ChipDistributionStrategy → ✅ 完整实现（含PreFilter/筹码计算/阶段检测/资金流）
└── ChanLunStrategy          → ❌ stub (implemented: false)
         ↓
  screener.py routes 不使用 StrategyPipeline
         ↓
  screener.py routes 自行创建:
  ├── DarwinRiskFilter (L1)  → ✅ 完整
  └── ChipScorer (L2)        → ⚠️ 简化版
         ↓
  L3: len(df) >= 60          → ❌ 空壳
```

**核心结论：** `StrategyPipeline` 全局实例存在但选股系统从未使用它。真实实现了ChipDistributionStrategy的策略注册表与选股路由之间没有数据流连接。

## 五、修复建议

### P0（立即修复）

1. **接入真实策略到L3验证**
   - 将 `volume_price_strategy.py` 的 `VolumePriceStrategy` 封装为选股可用的批量评分接口
   - 将 `chanlun_strategy.py` 的 `ChanLunAnalyzer` 封装为批量评分接口
   - L3按缠论+量价+因子三引擎输出 `strategy_detail`

2. **修复API参数命名**
   - 后端统一为snake_case `stock_pool` / `candidates`
   - 或前端统一使用camelCase
   - 关键：前后端使用同一套key名

### P1（近期修复）

3. **修复因子组合与选股系统的对接**
   - `screener/index.vue` 在 `mounted()` 或 `created()` 时调用 `factorService.getCombinations()`
   - 将因子组合数据传递给 `PipelineFlow` 或 `ScreeningResults` 的因子评分区域

4. **Vibe策略动态同步**
   - 完成 `TODO Phase 1`，从 `strategy-templates` 数据库读取真实策略
   - 支持用户自建策略写入 `strategy_templates.db`

### P2（规划中）

5. **复用 `POST /api/v3/screener/run` 全流程端点**
   - 前端可以选择使用单端点全流程替代串行三层调用
   - 或保持串行但正确传递各层结果

6. **启用 `StrategyPipeline`**
   - 选股系统使用 `get_strategy_pipeline()` 获取全局注册表
   - 添加 `ChipDistributionStrategy` 作为L2真实筹码评分来源

## 七、结论

选股系统的**数据基础层**（DataManager → DuckDB → Tushare）工作正常，能够获取股票列表、日线数据和基础财务指标。

但**策略匹配连接严重不足**：L3策略验证是完全空壳，214号方案要求的缠论、量价、因子三大策略均未接入流水线。`volume_price_strategy.py`（3539行完整实现）和 `chanlun_strategy.py`（2642行完整实现）存在但未被调用。前端与后端之间还存在API参数名不一致的隐性Bug，一旦开始传参就会触发。

**系统当前状态：L1风险过滤可独立工作，L2主力评分是简化版，L3策略验证无实际价值。整条Pipeline的运行结果不足以作为选股决策依据。**
