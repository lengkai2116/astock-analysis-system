# 全局数据体系全面审计与标准化方案（修订版）

> **修订说明**：v2版基于279号v1的审计结论，按照"前端需求→调用合规→存储层→计算层→采集渠道"五步法全链路重新梳理，
> 明确区分"数据计算"（后台预计算）与"策略核算"（用户触发）两个不同概念，补充采集渠道缺口及最佳通道方案。

---

## 第一部分：核心架构标准

### 1.1 四层架构定义

```
采集层 (Collection Layer)
  独立进程(data_daemon + mootdx_collector + TushareProvider + AkshareProvider)
  职责：从外部数据源获取原始数据，写入存储层
  约束：不关心谁消费数据，只做采集+写入

存储层 (Storage Layer)
  ECM SQLite WAL + InMemoryStateStore + PostgreSQL
  职责：为各层提供读写接口，DataManager 是唯一数据访问网关
  约束：采集层写、计算层读写、调用层只读

计算层 (Computation Layer)
  独立进程(data_daemon 后台线程)
  职责：原始数据到达时自动触发**数据计算**，结果写入存储层
  约束：只处理**数据计算**（技术指标、因子、K线聚合等），不处理策略核算

调用层 (Call Layer)
  Flask REST API + SocketIO
  职责：接收前端请求，从存储层读取数据返回
  约束：只读存储层，不得直接调用外部数据源
```

### 1.2 关键概念区分：数据计算 vs 策略核算

| 维度 | 数据计算 (Data Computation) | 策略核算 (Strategy Computation) |
|------|---------------------------|-------------------------------|
| 定义 | 纯数学/统计变换，输入固定输出确定 | 基于策略逻辑的推理/判断，依赖用户配置 |
| 示例 | MA/MACD/RSI/KDJ计算、分钟K线聚合、因子值计算 | 缠论分析、量价形态识别、筹码主力识别、情绪判断 |
| 触发时机 | **数据到达时后台自动触发** | **用户点击"运行分析"时触发** |
| 是否预计算 | ✅ **必须后台预计算并存储** | ❌ **不预计算**，按需使用已预计算的数据 |
| 输入 | 原始行情数据 | 已预计算的数据 + 用户策略参数 |
| 存储 | 写入 `indicator_ma/macd/other`、`factor_cache` | 暂存于 `AnalysisCache` 内存，用户刷新即丢弃 |
| 消费方 | 所有需要该指标的模块 | 前端策略分析面板 |

### 1.3 数据流转红线

```
✅ 允许的路径:
  采集层 → 存储层 → 计算层(数据计算) → 存储层 → 调用层 → 前端
  采集层 → 存储层 → 调用层 → 前端（原始数据无需计算时）
  调用层 → 策略核算(用户触发) → 读取存储层预计算数据 → 返回

❌ 禁止的路径:
  采集层 → 调用层（跳过存储，数据不可追溯）
  调用层 → 采集层（前端触发数据拉取）
  调用层 → 数据计算（计算应在后台完成，非请求时触发）
  存储层 → Mock数据（违反§13规则）
```

## 第二部分：全链路数据审计方法论

### 2.1 五步审计法

对每项前端数据需求，按以下五步审查：

```
Step 1: 前端需求识别
  页面模块 | 展示位置 | 数据字段 | API端点
  ↓
Step 2: 调用合规检查
  API端点是否只读存储层？是否直调外部数据源？是否触发实时计算？
  ↓
Step 3: 存储层可用性检查
  ECM/InMemory是否有该数据？表名？字段是否匹配？
  ↓
Step 4: 计算层需求判断
  是否需要数据计算（预计算）？还是策略核算（按需）？还是原始数据？
  ↓
Step 5: 采集渠道确认
  数据源是什么？采集方式？是否已注册到自启动后台？
```

### 2.2 审计结果分类

- ✅ **已合规**：完整四层链路，数据已就绪
- 🟡 **部分合规**：数据存在但消费路径未打通/需改造
- 🔴 **不合规**：违反架构红线，需立即修复
- ⚪ **缺口**：数据不存在，需新增采集/存储/计算

## 附录：与用户确认的架构原则对照

| 用户原则 | 279号方案实现方式 |
|---------|-----------------|
| 数据后台独立进程 | `data_daemon.py` 为采集+计算进程，`run.py` 为API进程 |
| 前端不触发数据采集 | 所有采集在 data_daemon 主循环 + 日终同步中完成 |
| 策略核算≠数据计算 | 策略核算（策略分析的5策略）按用户需触发，数据计算（技术指标/因子/分钟聚合）后台预计算 |
| 计算在数据到达时触发 | 日终同步15:30后自动触发指标/因子预计算；分钟5min数据写入后触发聚合计算 |
| 前端只读存储层 | API路由通过 DataManager.get_cached_*() 读取ECM缓存 |
| 调用层不触发数据采集 | 路由中无 `new TushareProvider()` 等采集操作 |
