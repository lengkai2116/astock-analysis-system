## 1. 页面定位

监控通知是**全系统规则中心+通知中心**。用户在这里定义和管理监控条件（规则引擎配置），接收规则触发的实时通知（通知展示与交互），并查看规则运行状态。

### 1.1 页面架构

```
┌─ 页面头部 ─────────────────────────────────────────────────┐
│  [📊 条件库]  [➕ 新建规则]                                  │
├─ 汇总统计条 ──────────────────────────────────────────────┤
│  总规则|今日触发|活跃|暂停·休眠|📈🛡️⚡📋🎯类型分布          │
├─ 批量操作栏 ──── (选中卡片后 slide-down) ────────────────┤
├─ 健康检查横幅 ──── (L3暂停30+天规则提醒) ───────────────┤
├─ 休眠区横幅 ──── (L2归档规则) ─────────────────────────┤
├─ 筛选栏 ──────────────────────────────────────────────────┤
│  搜索框|状态|类型|范围|排序 4个下拉                         │
├─ 顶部通知滚动区 ── (30s横向滚动未处理通知) ──────────────┤
├─ 折叠表格 ──── (按范围分组浏览，默认折叠) ───────────────┤
├─ 规则卡片网格 ──── (CSS Grid 2~3列) ────────────────────┤
│  含checkbox/类型图标(左色条)/热度🔥/状态/条件/触发统计    │
│  +操作按钮[暂停] [编辑] [记录] [克隆] [🗑️]                │
├─ 加载更多 ───────────────────────────────────────────────┤
├─ [底部] 右下通知浮窗 (折叠360px条→展开520px弹窗) ──────┤
│  ⊟ 折叠条: 🔔N条未读·最新摘要·quick-btn·展开               │
│  ▣ 展开: 5类型差异化通知卡片(隐式确认/倒计时/tooltip/内联) │
└──────────────────────────────────────────────────────────┘
```

### 1.2 5种规则类型

| 类型 | 图标 | 颜色 | 推送策略 | 特殊交互 |
|:-----|:-----|:-----|:---------|:---------|
| 📈 发现机会 | 📈 | 蓝 #3B82F6 | 冷静期30分钟 | 6按钮双行,隐式确认 |
| 🛡️ 规避风险 | 🛡️ | 红 #EF4444 | 全渠道强推,冷静期5分钟 | 倒计时+重推 |
| ⚡ 异动追踪 | ⚡ | 黄 #F59E0B | 冷静期60分钟 | ❓tooltip悬浮说明 |
| 📋 状态监控 | 📋 | 绿 #22C55E | 仅收件箱,日1次 | 极简精简展示 |
| 🎯 纪律执行 | 🎯 | 紫 #8B5CF6 | 按用户设定 | 内联止盈止损编辑 |

### 1.3 规则三层次管理

| 层级 | 名称 | 触发条件 | 操作 |
|:-----|:------|:---------|:-----|
| L1 | 自动暂停 | 连续30交易日0触发 | 自动暂停→通知用户 |
| L2 | 休眠区归档 | L1后14天未手动启用 | 移入休眠区横幅展示 |
| L3 | 健康报告 | L2规则暂停30+天 | 横幅提醒"查看健康报告" |

### 2.1 Mock度评估：~93%

监控通知是**全站Mock依赖度最高的页面**。14个API端点全部❌Mock；交互逻辑（创建向导/弹窗/隐式确认/批量/倒计时）全部✅前端独立实现。

### 3.3 后端就绪度评估：~15%

**核心发现：** 监控通知是已审计页面中**后端准备度最低但前端交互最完整**的页面。14个核心端点全部❌待建（规则CRUD+通知查询），仅有条件库（conditions.py）和服务推送（alert_service.py）可用。规则引擎、规则存储、通知检测管道全量待实现。

与复盘中心（~0%）不同——复盘中心后端需全量新建复杂功能（模拟引擎+诊断算法），监控通知虽端点多但逻辑较明确（规则CRUD+条件匹配+通知推送）。

### 4.4 P4：PUT /api/v3/notifications/rules/{id} — 更新规则

软删除（移入回收站），规则状态变为 `deleted`。

### 7.2 交互流程

```python
class RuleEngine:
    """规则引擎服务"""
    
    async def evaluate_rules(self):
        """定时扫描所有运行中规则"""
        rules = Rule.query.filter_by(status='running').all()
        for rule in rules:
            if not self._in_schedule(rule): continue
            result = await self.evaluate_conditions(rule)
            if result.passed:
                if not self._should_notify(rule):
                    # 确认期内，仅记录不推送
                    self._record_interim(rule, result)
                    continue
                self._create_notification(rule, result)
                self._update_stats(rule)
                self._send_push(rule, result)
    
    def evaluate_conditions(self, rule):
        """对规则的所有条件执行评估"""
        from app.services.condition_evaluator import ConditionEvaluator
        evaluator = ConditionEvaluator()
        results = []
        all_passed = True
        for cond in rule.conditions:
            r = evaluator.evaluate(cond['condition_id'], cond['params'], rule.scope)
            results.append(r)
            if not r.passed: all_passed = False
        # AND/OR 逻辑
        if rule.condition_logic == 'AND':
            all_passed = all(r.passed for r in results)
        else:
            all_passed = any(r.passed for r in results)
        return EvaluationResult(passed=all_passed, details=results)
    
    def _should_notify(self, rule):
        """检查冷却期+确认期"""
        # 冷却期内不重复通知
        if rule.cooldown > 0:
            last = self.get_last_notification(rule.id)
            if last and (now - last.trigger_time).minutes < rule.cooldown:
                return False
        # 确认期要求连续通过N次
        if rule.confirm_period > 0:
            recent = self.get_recent_evaluations(rule.id, rule.confirm_period)
            if len(recent) < rule.confirm_period:
                return False
            if not all(r.passed for r in recent[-rule.confirm_period:]):
                return False
        return True
```
