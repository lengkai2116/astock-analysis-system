## 1. 页面结构概览

策略沙箱是**回测系统的轻量前置环节**，针对**单个策略/因子组合**进行快速历史数据测试。定位：快速摸清策略的"脾气"——什么行情下好用、参数调大调小影响多大。

### 1.1 核心定位对比

| 维度 | 策略沙箱 | 回测系统（backtest） |
|:-----|:---------|:-------------------|
| 测试范围 | **单个策略/因子组合** | 多策略组合+多标的+全量化 |
| 测试周期 | 秒级/分钟级 | 全量（分钟~小时级） |
| 用户目标 | 快速摸清策略的"脾气" | 完整评估并决策 |
| 输出粒度 | 信号级明细 | 组合级汇总+稳健性验证 |
| 关键差异 | 参数调节+行情分段看+参数稳定度 | 组合权重+多标的+基准对比+多维验证 |

### 1.4 数据流

```
策略沙箱（原型数据流，当前）
  ↓ 用户选择策略+参数+股票+时间
  ↓ 点击"开始测试"

runSandbox(btn)
  ├─ setTimeout 循环 (180ms/步, 总25步)
  │   ├─ 进度条推进 (4%/步)
  │   ├─ 进度文字更新 "正在测试 西藏矿业 (1/N)"
  │   └─ 100% → 渲染结果
  │
  ├─ 结论: 固定模板拼接（单股或多股汇总）
  ├─ 指标: 8个固定Mock值
  ├─ ECharts: Math.random() × 29个月
  ├─ 行情分段: 固定Mock文案
  ├─ 参数稳定度: Math.random() × 8个周期值
  ├─ 信号明细: 10行硬编码
  └─ 标签: 3个固定结论标签


策略沙箱（生产数据流，目标）
  ↓ 用户配置

POST /api/v3/sandbox/run  {
  strategyId, params, stockCodes[], startDate, endDate, benchmark, capital, period
}
  ↓
后端执行引擎:
  → 并行计算各股票信号序列（基于真实策略引擎）
  → 逐日净值计算（基于Tushare日K线）
  → 指标聚合（总收益/年化/回撤/胜率/盈亏比/夏普/交易次数/超额收益）
  → 大盘基准对比（基准同期净值曲线 + 超额收益计算）
  → 行情段分类（涨/跌/震荡三段自动识别）
  → 参数稳定度（可选: 5→60天步进重算→收益波动）
  → 基于指标的规则推理结论生成
  ↓
前端接受结果JSON → 6区块渲染
```

## 3. 数据源映射

### 3.1 输入数据来源

| 配置项 | 数据源 | 当前状态 | 生产方案 |
|:-------|:-------|:---------|:---------|
| 策略选择（S1-S5） | `strategy-templates.html` 中 `SYSTEM_STRATEGIES` 数组 | ❌ 硬编码8个radio | 需从策略模板页动态加载策略列表（localStorage或API） |
| 因子组合（F1-F3） | `factor-manager.html` 中 `PRESET_COMBOS` | ❌ 硬编码3个radio | 需从因子管理页动态加载组合列表 |
| 股票列表（8只） | 本地 `WATCHLIST_STOCKS` 硬编码数组 | ❌ 硬编码 | 需从自选监控页同步（localStorage `_watchlistCache` 或API） |
| 已选股票 | `selectedStocks` 内存数组 | ⚠️ 页面刷新丢失 | 无持久化需求（每次测试重新选择） |
| 大盘基准数据 | 历史指数行情 | ❌ 无 | 需Tushare index_daily接口（沪深300/中证500/上证/深证/创业板） |
| 测试日期 | 用户输入 | ✅ 交互完整 | 无额外数据源需求 |
| 策略算法 | 策略引擎后端 | ❌ 无 | 需封装回测引擎策略直接调用，或轻量级简化实现 |

### 3.2 输出数据计算来源

| 输出项 | 计算方式 | 数据依赖 |
|:-------|:---------|:---------|
| metrics | 基于信号序列+行情数据的绩效聚合 | 策略引擎输出 + Tushare日K线 |
| equity_curve | 逐日模拟交易，基于信号+行情计算净值 | 信号序列 + 行情数据 |
| phases | 基于基准指数涨跌幅自动分类（涨/跌/震荡） | 大盘基准行情数据 |
| stability | 参数遍历重算（window 5→60步进，计算收益波动） | 完整策略引擎调用链 |
| signals | 原始信号序列（方向/入场出场/行情分类） | 策略引擎输出 |
| summary/tags | 基于指标的规则推理引擎 | 以上所有指标 |

### 3.3 行情数据服务

| 数据 | 数据源 | 更新频率 | 用途 |
|:-----|:-------|:---------|:-----|
| 个股日K线 | Tushare daily | 每日盘后 | 逐日净值计算、信号回测 |
| 复权因子 | Tushare adj_factor | 每日盘后 | 价格复权对齐 |
| 指数日K线 | Tushashare index_daily | 每日盘后 | 大盘基准对比、行情段自动分类 |

## 4. 缓存策略

| 端点/数据 | 缓存Key | TTL | 策略 | 备注 |
|:----------|:--------|:----|:-----|:------|
| `POST /api/v3/sandbox/run` | — | 无 | 不缓存 | 每次测试请求独立（参数/策略/标的组合极多） |
| 个股日K线（内部） | `kline:{ts_code}:{start}:{end}` | 1h | 内部缓存 | 多次测试重用的行情数据 |
| 指数日K线（内部） | `index:{ts_code}:{start}:{end}` | 1h | 内部缓存 | 基准指数行情 |
| 策略定义 | `strategy:{id}` | 5min | 短TTL | 策略配置变更不频繁 |
| 因子组合列表 | `factor:combos` | 1min | 极短TTL | 跨页调用 |

## 附录B: 执行引擎算法概要

### 核心执行流程

```
POST /api/v3/sandbox/run 请求到达
  │
  ├─ 1. 验证参数
  ├─ 2. 获取行情数据（Tushare daily × N只股票）
  ├─ 3. 获取基准指数数据（Tushare index_daily）
  │
  ├─ 4. 逐股票执行策略信号生成
  │   ├─ 解析strategy_id → 加载对应的策略配置
  │   ├─ 代入params (window/threshold/stop_loss)
  │   ├─ 生成信号序列（方向+时间+价格）
  │   └─ 记录逐日盈亏
  │
  ├─ 5. 多股票汇总
  │   ├─ 等权分配各股票资金（initial_capital / N）
  │   ├─ 各股票独立交易
  │   └─ 汇总为组合净值曲线
  │
  ├─ 6. 指标计算
  │   ├─ total_return_pct = (end_equity / start_equity - 1) × 100
  │   ├─ annual_return_pct = (1 + total_return)^(252/days) - 1
  │   ├─ max_drawdown_pct = min(daily_drawdown_series)
  │   ├─ win_rate = correct_signals / total_signals × 100
  │   ├─ profit_loss_ratio = avg_profit / avg_loss
  │   ├─ sharpe_ratio = annual_return / annual_std (简化版)
  │   ├─ total_trades = 信号总数
  │   └─ excess_return_pct = strategy_return - benchmark_return
  │
  ├─ 7. 行情段分类
  │   ├─ 基于基准指数月收益率序列
  │   ├─ > 2% → "up" / < -2% → "down" / 其余 → "flat"
  │   └─ 各段内统计：收益/正确率/信号次数
  │
  ├─ 8. 参数稳定度（可选）
  │   ├─ 遍历 window: [5,10,15,20,30,40,50,60]
  │   ├─ 各步进重算 → 年化收益值序列
  │   ├─ 计算波动范围 = max - min
  │   └─ 判定: < 5% → stable / 5-10% → medium / > 10% → sensitive
  │
  ├─ 9. 结论生成（规则推理）
  │   ├─ tags 生成基于:
  │   │   ├─ win_rate > 60% AND excess_return > 0 → "✅ 上涨行情适用"
  │   │   ├─ 下跌段亏损 > 10% OR 震荡段正确率 < 40% → "⚠️ 震荡行情谨慎"
  │   │   └─ sharpe_ratio < 1.0 OR 信号总数 < 10 → "📌 推荐回测系统进一步验证"
  │   └─ summary 文本拼接（多股汇总/单股，替换当前固定模板）
  │
  └─ 10. 返回结果JSON
```
