# 337 — 成品仓落库与实时套算机制

> **分档定位**：332 号总纲（现状判定引擎统一方案 v3.0）的**分档五**，聚焦总纲 §5.6（成品仓设计——日频现状成品 / 实时操作建议两类，双模块唯一消费源）。
>
> **讨论背景（08-15，沟通纪要 005）**：组4 核查发现系统**无日频现状成品**（九维状态/七维模板/状态条无落库）、operation_advice 每次实时完整计算；但已有可复用积木（treemap_snapshot 原子替换机制、signal_records 验证环、三张未启用候选表）。用户决策：**新建 status_snapshot**（B 方案）、**建议规则参数预生成落库**、**七维模板文本按需组装**（不落库）。
>
> 本方案仅存档细则，不修改任何代码（落地随 332 号 S2/S3）。

## 一、设计原则（用户确认）

1. **新建 status_snapshot 表**（B 方案）：日频现状成品独立落库，treemap_snapshot 保持图谱轻量定位不动；
2. **参数预生成**：建议规则参数（止损位/仓位上限/触发条件模板）盘后预生成落库，支撑实时轻量套算；
3. **模板按需组装**：七维模板文本不落库（避免全市场文本膨胀），个股页打开时从 L1 素材实时拼装；
4. **单一生产环节**：status_snapshot 与 treemap_snapshot 由同一生产环节（S2 status_engine）生成，图谱 API 合并输出，无双源分裂（332 红线）。

## 二、成品仓结构（两类成品，332 §5.6 落定）

| 成品类型 | 内容 | 生成时机 | 落库 | 消费方 |
|---|---|---|---|---|
| **日频现状成品** | 九维状态 / 状态条 / opportunity_state + state_evidence + conflict_evidence + **建议规则参数** | 盘后生产环节统一生成（全市场） | **status_snapshot 表（新建）** | 弹窗九维灯、个股页模板组装、套算层参数源 |
| **实时操作建议** | operation_advice（state/止损/仓位/情景，含盈亏比门禁/降级链/L0 分级） | 按需生成（用户查看时），由轻量套算层输出 | SignalRecord（330 改进2 已实现，验证环） | 弹窗/个股页建议卡 |

## 三、status_snapshot 表设计（B 方案，新建）

**草案 DDL**（复用 treemap_snapshot 的原子替换机制——`status_snapshot_new` → DROP → RENAME）：

```sql
CREATE TABLE IF NOT EXISTS status_snapshot (
    ts_code             TEXT PRIMARY KEY,
    snapshot_date       TEXT DEFAULT (date('now')),   -- 构建日期
    trade_date          TEXT,                          -- 数据交易日
    dim_states          TEXT,   -- 九维状态 JSON {dim: {state, light, confidence}}（334 号输出协议）
    status_bar          TEXT,   -- 状态条（强趋势/趋势确认/趋势转弱/风险区）
    opportunity_state   TEXT,   -- L2 唯一结论（enter/light/wait/avoid，336 号）
    state_evidence      TEXT,   -- 仲裁证据列表 JSON（L0/L1/L2 证据链）
    conflict_evidence   TEXT,   -- 冲突暴露列表 JSON（336 号扩展后 6 条规则输出）
    consensus_rate      REAL,   -- 九维共识（336 号维度共识）
    advice_params       TEXT,   -- 建议规则参数 JSON（§六：止损位/仓位上限/触发条件模板）
    created_at          TEXT
)
```

**与 treemap_snapshot 的关系**：两表同管道生成、ts_code 一一对应；treemap_snapshot 承载图谱展示轻量字段（价格/估值/时机），status_snapshot 承载现状判定成品（九维/状态条/冲突/建议参数）；图谱 API（opportunity_atlas.py）合并读取。

## 四、日频现状成品生成（全市场结构化落库）

- **时机**：日终预计算完成后（P4 标签 → P2 信号 → S2 status_engine 生产环节），与 treemap_snapshot 同管道（S1 步骤扩展，data_daemon.py:3285 处追加）
- **范围**：全市场（与快照一致，5571 只）——图谱需全市场颜色/状态
- **数据源**：L1 维度判定（334 号输出协议）+ L2 聚合（336 号共识/冲突）+ L0 分级（335 号）→ 单条 JSON 落库
- **成本**：结构化字段全市场可承受（P4 已全市场预计算；S2 status_engine 顺带产出，非新增重计算）

## 五、七维模板文本按需组装（不落库）

- **触发**：个股页打开时（analyze 请求）
- **组装函数**：`build_seven_dim_report(ts_code, snapshot_row)` —— 从 status_snapshot.dim_states（九维状态/证据/结论句/大白话）+ 信号注册表（334 号：信号确认状态①）+ advice_params（风险边界⑥）拼装七段文本（334 号七维模板组装映射表）
- **不落库理由**：5571 只 × 7 维文本存储膨胀；L1 素材已结构化落库，组装是纯模板化（毫秒级）
- **一致性**：七段文本的首句结论句与弹窗灯色一致（同一 dim_states 源）

## 六、实时操作建议轻量套算层（C3）

### 6.1 架构

```
status_snapshot.advice_params（盘后预生成：止损位=结构位、仓位上限、触发条件模板、盈亏比公式引用）
        + 现价（实时）
        ↓
套算函数 apply_advice_params(params, price)（毫秒级）
  1. 计算盈亏比 rr = (目标位−现价)/(现价−止损位)
  2. 应用 L0/L2 降级链（335 号 L0 分级 + 336 号共识门槛 + 盈亏比门禁）
  3. 输出 operation_advice（state/仓位/止损/情景）
        ↓
SignalRecord 落库（330 改进2 已实现）→ T+5/10/20 验证环
```

### 6.2 advice_params 预生成内容

```json
{
  "stop_loss": 29.48,            // 结构位止损（盘后算好，现价无关）
  "target_levels": [{"price": 34.11, "label": "近端压力"}],
  "max_position_ratio": 0.2,     // 仓位上限（经 L0/L2 降级后的基准）
  "rr_rule": "rr>=1",            // 盈亏比门禁规则引用（status_engine.yaml）
  "trigger_template": "突破 {price} 确认后入场"
}
```

### 6.3 与现状的关系（advice_builder 改造复用）

- **现状**：advice_builder 每次实时完整算（读 K 线算 60 日低点止损/盈亏比/仓位）——即"完整引擎重跑"
- **改造**（S2）：advice_builder 的"结构位止损/盈亏比门禁/仓位降级"逻辑重构为**套算函数**（输入 = advice_params + 现价），盘后预生成参数、实时轻量套算
- **口径一致性**：日频成品与实时建议共用同一套 advice_params——"日频 wait 但实时 enter"型矛盾（603897）从结构上消除（同一规则，只差现价代入）
- **读取优先级**（332 §5.6）：实时操作建议 > 日频现状成品（盘中以实时为准，盘后回退日频）

## 七、与现有机制的关系

| 机制 | 处理 |
|---|---|
| treemap_snapshot | **不动**（图谱轻量快照）；图谱 API 合并 status_snapshot 读九维灯/conflict |
| signal_records（330 改进2 验证环） | **沿用**：实时操作建议落库入口不变，扩展右侧信号类型字段（334 号 §6.1） |
| opportunity_status_history / advice_history / opportunity_library（三张 0 行候选表） | **不启用**（语义不符：history=变更日志、library=机会池）；status_snapshot 承担日频现状成品；opportunity_library 的 park 停放机制若未来做"机会库"功能另议 |
| AdviceGenerator（闲置组件） | 不沿用（L4 诊断旧链路，S2 status_engine 替代） |
| config/status_engine.yaml（336 号） | 套算规则引用（rr 门禁/仓位上限/降级链配置） |
| signal_registry.yaml（334 号） | 信号注册表（七维模板①信号确认状态素材） |

## 八、验证方案

1. **status_snapshot 构建**：日终后全市场行数 = treemap_snapshot 行数；字段完整（dim_states/status_bar/conflict/advice_params 非空率 ≥99%）
2. **口径一致性**：抽样 10 只（含 300759/301119/000066），断言 status_snapshot.opportunity_state 与 diagnose/analyze 输出一致
3. **套算一致性**：同一股票"日频参数+现价套算" vs "完整引擎重跑"输出一致（抽样 10 只，S2 过渡期对比）
4. **组装函数**：个股页七维模板渲染正常；七段文本首句与弹窗灯色一致
5. **验证环衔接**：实时操作建议继续落 SignalRecord（T+5/10/20 跟踪）；新记录含右侧信号类型字段（334 号）
6. **全量 pytest**：现有 90+ 通过，新增 status_snapshot 构建/套算/组装用例
