### 3.5 dim1 读取 daemon 内存的合规性分析

**问题**：dim1_signal_engine.py L194 `from data_daemon import _market_stats_cache` 是否违反红线规则§III.9？

**§III.9 原文约束对象**：

```
⛔ 禁止：dim2-dim7内部直接调用DataManager.get_cached_*/ecm.get_cached_*/读daemon内存
```

禁止对象明确为 **dim2-dim7**，不是 dim1。dim1 的定位是"唯一数据入口"，职责为"加载全部原料数据"。

**`_market_stats_cache` 数据源现状**：

| 层级 | 状态 |
|------|------|
| daemon 内存（全局变量） | ✅ `_market_stats_cache = {}`，`_precompute_market_stats()` 写入 |
| pre_feat_cache 表 | ❌ 不包含 market_stats |
| 任何 SQLite 表 | ❌ 无持久化 |
| DataManager 接口 | ❌ 无 `get_cached_market_stats()` 方法 |

**结论**：`market_stats` 数据从未被持久化到存储层，dim1 无存储层路径可读。dim1 作为集中取数层，在存储层缺失该数据时，从唯一可用的源头（daemon 内存）读取，是其职责范围内的临时方案。代码注释（L191-192）已标记 TODO：

```python
# ═══ 类别4: 市场级统计（1项，临时从daemon内存读取）═══
# TODO: daemon应将market_stats持久化到独立表，dim1从表中读取
```

**性质判定**：数据管道缺口（market_stats 未持久化），非 dim1 架构违规。

**修复方向**：daemon 将 `_market_stats_cache` 写入 pre_feat_cache 表的 `market_stats` 组 → dim1 通过 DataManager 从表中读取 → 删除 `from data_daemon import _market_stats_cache`。

## 四、`make check` 可执行性验证

### 4.1 现状

```bash
# 从项目根目录执行
make check
# → pytest backend/tests/ → 全部 412 测试失败
# → ModuleNotFoundError: No module named 'app'
```

### 4.2 根因

`pyproject.toml` 的 `[tool.pytest.ini_options]` 缺少 `pythonpath` 配置：

```toml
[tool.pytest.ini_options]
testpaths = ["backend/tests"]
python_files = ["test_*.py"]
addopts = "-v --tb=short"
# 缺少: pythonpath = ["backend"]
```

### 4.3 影响

- CI/CD 和任何从项目根目录触发的 `pytest` 调用都会失败
- 412方案F2要求的 `make check` 端到端验证无法通过
- 当前只有手动 `cd backend && PYTHONPATH=backend pytest` 才能通过

### 4.4 修复建议

在 `pyproject.toml` 中添加 `pythonpath = ["backend"]`，或在 `Makefile` 的 `test` 目标中添加 `cd backend && PYTHONPATH=backend`。
