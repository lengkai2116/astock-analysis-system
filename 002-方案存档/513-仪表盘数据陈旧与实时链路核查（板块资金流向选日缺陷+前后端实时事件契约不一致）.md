## 四、逐项实证

### #D1 🔴 板块资金流向停在 2026-10-09（应 10-12）

- **现象**：`GET /api/v3/market/sector-moneyflow` → `data.date = "2026-10-09"`；`GET /api/v3/dashboard/full` → `data.sector_moneyflow.date = "2026-10-09"`（`updated_at=2026-10-13`）。同页其它区块（`sector_changes`/`sector-sector`）均为 **10-12**。
- **源侧反证**：`data/duckdb/market_cache.db` 的 `moneyflow_cache` 已含 **2026-10-12（5573 行）**，且近三日行数：`10-12=5573`、`10-09=5573`、`10-08=5572`。
- **根因（`app/services/dashboard_service.py:699-711`）**：
  ```python
  date_counts = Counter(r.get('trade_date', '') for r in records)
  best_date = max(date_counts, key=lambda d: date_counts[d]) if date_counts else None
  if not best_date or date_counts.get(best_date, 0) < 50: ...
  ```
  选日口径为**「记录数最多的交易日」而非「最新交易日」**。窗口（now-5d~now）内 **10-12 与 10-09 记录数并列（均 5573）**，`max(..., key=...)` 对并列取**先出现**的键；记录若按日期升序（10-08→10-09→10-12），则命中 **10-09**。
- **定性**：**确凿缺陷**。语义上应为「取最新有足够数据的交易日」；当前实现会在「记录数并列」时**静默回退到旧交易日**（本次即回退 1 个交易日）。
- **影响面**：仅仪表盘「板块资金流向」区块展示旧一日数据；不影响其它区块。

### #D2 🟠 前后端实时事件名不一致

- **前端监听**（`_ui-prototype/dashboard.html`）：`:607 socket.on('market:indices')`、`:620 market:top_stocks`、`:624 market:sectors`、`:633 market:news`。
- **后端 emit 全集**（`grep -rhoE "emit\('..." app data_daemon.py`）：`market:summary`、`market:top_stocks`、`market:sectors`、`stock:quotes`、`market:data_offline`、`market:staleness_warning`、`connected`、`ai_signal`、`watchlist_update`、`kline_init`、`qmt_tick_init`。
- **结论**：`market:indices`、`market:news` **全后端无人 emit**（两个 handler 永不触发）；后端发出的 `market:summary`**无人监听**。仅 `market:top_stocks`、`market:sectors` 名称对齐。

### #D3 🟠 标准模式无实时推送

- **API 侧**：`app/scheduler_manager.py:268` `if not os.environ.get('DATA_DAEMON_RUNNING'):` 方才注册 `market_snapshot_push_5s/30s`；当前 `DATA_DAEMON_RUNNING=1` → **不注册**（启动日志仅见 notification_* 与周/月度任务，无 `market_snapshot_push_*`）。即使注册，wrapper 亦在 `:813/:841` 提前 `return`。
- **daemon 侧**：`data_daemon.py` 中 `socketio|emit\(|push|broadcast|ws_bridge` grep **全为空**；全仓亦无 `socketio.Client`（500号#1 已废止「采集线程→WsBridge」链路）。
- **结论**：本模式下**无任何实时推送流量**；注释所称「daemon 独立管理推送」在代码中无对应实现。

### #D4 🟡 前端无自动刷新

- `dashboard.html` 仅在 `:597` 调用 **一次** `loadDashboardFull()`；全文无 `setInterval`（取数封装 `_cachedFetch` 的 30s TTL 仅在重复调用时才生效）。
- **结论**：页面加载后不自动刷新；结合 #D2/#D3，实时区块实际收不到数据 → 仪表盘为**一次性静态快照**（除手动刷新页面）。

### #D5 🟡 sector_changes 字段空值

- `sector_changes.gainers`（5 条）与 `losers` 中：`lead_stock=""`、`up_count=0`、`down_count=0`（全部为 0）；`name`/`change_pct` 正常（如 `出版业 +4.0%`）。
- **定性（2026-10-13 只读溯源，**非数据缺口**）**：`get_sector_changes` 的 **DuckDB 降级路径**（`dashboard_service.py` 约 :490）构造 `all_sectors` 时**硬编码** `'lead_stock': '', 'up_count': 0, 'down_count': 0`；AKShare 路径（约 :415）同样写 `lead_stock:''`、`up_count/down_count` 取 `s.get(...)`（东财行业接口通常不返回 → 亦 0）。**根因＝代码未计算/未透传，非源缺数据**。
- **消费面**：`dashboard.html` 全文**未引用** `lead_stock`/`up_count`/`down_count`（渲染走 `renderSectorChart`，仅用 `name`/`change_pct`）→ **当前无用户可见影响**。处置建议：可选补产 `up_count/down_count`（按 industry 分组易算），或维持（登记）。

### #R1 ⚠️ 10-12 日终管道 QA-CHECK failed（登记）
