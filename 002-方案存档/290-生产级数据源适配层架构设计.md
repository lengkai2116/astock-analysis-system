# 生产级数据源适配层架构设计

> 解决核心问题：当上游数据源（东财/新浪/腾讯）API发生非兼容变更时，系统如何感知、降级并快速恢复。

## 一、设计原则

| 原则 | 含义 |
|------|------|
| **适配器隔离** | 每种数据源封装为独立适配器，实现统一接口，互不影响 |
| **配置驱动** | 字段映射、端点URL、重试策略全部外部化到配置文件，变更不涉及代码 |
| **健康自检** | 每个采集周期输出数据质量评分，达到阈值自动切换 |
| **降级链** | 主源→备源→缓存→空状态，四级降级自动流转 |
| **变更感知** | 自动检测响应结构变化，通过结构化对比判断"是正常的字段缺失还是API变更" |
| **热加载** | 配置文件通过文件监听自动重载，不重启进程 |

## 三、核心组件设计

### 3.1 统一适配器接口 `DataSourceAdapter`

```python
class DataSourceAdapter(ABC):
    """所有数据源适配器必须实现的接口"""

    @property
    def name(self) -> str:
        """数据源名称: 'eastmoney', 'sina', 'tencent'"""
        ...

    @abstractmethod
    def fetch_snapshots(self, codes: List[str]) -> Optional[pd.DataFrame]:
        """全市场快照采集（核心方法）

        Args:
            codes: 股票代码列表（如 ['600036', '000001', ...]）
        Returns:
            DataFrame with standardized columns, or None if failed
        标准化列名:
            ts_code, name, price, open, high, low, prev_close,
            volume, amount, change_pct, change,
            bid1~bid5, bid_vol1~bid_vol5, ask1~ask5, ask_vol1~ask_vol5,
            market_cap, circ_market_cap, turnover_rate, amplitude,
            pe, pb, volume_ratio
        """
        ...

    @abstractmethod
    def health_check(self) -> DataSourceHealth:
        """返回当前数据源的健康状态（每次fetch后自动调用）"""
        ...

    @abstractmethod
    def verify_schema(self, sample: pd.DataFrame) -> SchemaDiff:
        """校验返回数据的字段Schema是否与期望一致"""
        ...

    @property
    @abstractmethod
    def config(self) -> DataSourceConfig:
        """返回当前配置，支持运行时重载"""
        ...
```

### 3.3 数据源管理器 `DataSourceManager`

```python
class DataSourceManager:
    """数据源适配器管理层——所有采集器通过它获取数据"""

    def __init__(self, config_dir: str):
        self._adapters: Dict[str, DataSourceAdapter] = {}
        self._active_source: str = "eastmoney"  # 当前活动源
        self._fallback_chain: List[str] = []
        self._health_history: Dict[str, List[DataSourceHealth]] = {}
        self._config_watcher = FileWatcher(config_dir)  # 热加载配置
        self._load_adapters(config_dir)

    def fetch_market_snapshot(self, codes: List[str]) -> pd.DataFrame:
        """带自动降级的快照获取"""
        for source_name in self._get_active_chain():
            try:
                adapter = self._adapters[source_name]
                result = adapter.fetch_snapshots(codes)

                # 自动健康检查
                health = adapter.health_check()
                self._record_health(source_name, health)

                if result is not None and not result.empty:
                    if health.passed:
                        self._active_source = source_name  # 保持成功源
                        return result
                    else:
                        logger.warning(f"{source_name} 健康检查未通过: {health.reason}")
                        continue  # 尝试下一个
            except Exception as e:
                logger.warning(f"{source_name} 采集失败: {e}")
                continue

        # 所有源都失败 → 返回缓存数据
        return self._get_stale_cache()
```

#### 降级链自动编排

```
健康评分 > 0.9:  东财(主) → 新浪(备1) → 腾讯(备2)
健康评分 0.5-0.9: 新浪(主) → 腾讯(备1) → 缓存(备2)
健康评分 < 0.5:   缓存 → 空DataFrame
```

降级链根据每个数据源的**最近N次健康评分**动态排序：

```python
def _get_active_chain(self) -> List[str]:
    """根据最近5次健康评分排序降级链"""
    scores = {}
    for name, adapter in self._adapters.items():
        recent = self._health_history.get(name, [])[-5:]
        if not recent:
            scores[name] = adapter.config.priority
        else:
            avg = sum(h.score for h in recent) / len(recent)
            scores[name] = (1 - avg, adapter.config.priority)

    # 按(1-avg_score, priority)升序排列
    sorted_sources = sorted(scores.keys(), key=lambda x: scores[x])
    return sorted_sources
```

### 3.4 健康评分引擎 `HealthScorer`

每个采集周期对数据源输出的质量自动评分，**这是变更感知的核心**。

```python
@dataclass
class DataSourceHealth:
    passed: bool
    score: float          # 0.0 ~ 1.0
    reason: str
    schema_diff: Optional[SchemaDiff]
    metrics: Dict[str, Any]

class HealthScorer:
    """数据源健康评分器"""

    def score(self,
              df: pd.DataFrame,
              requested_codes: List[str],
              config: DataSourceConfig) -> DataSourceHealth:

        issues = []
        score = 1.0

        # 1. 行数检查
        row_ratio = len(df) / max(len(requested_codes), 1)
        if row_ratio < config.schema_check.min_rows_ratio:
            score -= 0.3
            issues.append(f"返回行数比 {row_ratio:.1%} < 阈值 {config.schema_check.min_rows_ratio:.0%}")

        # 2. 必须字段完整性
        for field in config.schema_check.required_fields:
            if field not in df.columns:
                score -= 0.2
                issues.append(f"缺少必须字段: {field}")
            else:
                null_ratio = df[field].isna().mean()
                if null_ratio > config.schema_check.allowed_null_ratio:
                    score -= 0.1
                    issues.append(f"{field} 空值率 {null_ratio:.1%} > {config.schema_check.allowed_null_ratio:.0%}")

        # 3. 值范围合理性（低/null → 疑似格式错误）
        for field in ['price', 'volume', 'amount']:
            if field in df.columns:
                valid = df[field].dropna()
                if len(valid) > 0:
                    if field == 'price' and (valid > 100000).any():
                        score -= 0.2
                        issues.append(f"{field} 出现异常大值（未缩放?）")
                    if field == 'volume' and (valid < 0).any():
                        score -= 0.15
                        issues.append(f"{field} 出现负值")

        # 4. 字段 Schema 变更检测
        schema_diff = self._check_schema(df, config.field_mapping)
        if schema_diff.changed:
            score -= 0.3
            issues.append(f"Schema变更: {schema_diff.summary}")

        return DataSourceHealth(
            passed=score >= 0.6,
            score=max(0.0, score),
            reason="; ".join(issues) if issues else "正常",
            schema_diff=schema_diff,
            metrics={
                'rows_returned': len(df),
                'rows_requested': len(requested_codes),
                'null_rates': {f: df[f].isna().mean() for f in config.schema_check.required_fields if f in df.columns}
            }
        )
```

### 3.5 Schema 变更感知 `SchemaDiffDetector`

自动检测响应结构变化，**区分"正常字段缺失"和"API格式变更"**。

```python
@dataclass
class SchemaDiff:
    changed: bool
    summary: str
    added_fields: List[str]
    removed_fields: List[str]
    type_changes: List[Tuple[str, str, str]]  # (field, old_type, new_type)

class SchemaDiffDetector:
    """检测响应结构中与期望Schema的差异"""

    def __init__(self, expected_schema_path: str):
        # 加载期望Schema（从配置文件生成的规范Schema）
        with open(expected_schema_path) as f:
            self._expected = json.load(f)  # {field_name: type_string}

    def detect(self, actual_df: pd.DataFrame) -> SchemaDiff:
        actual_fields = set(actual_df.columns)
        expected_fields = set(self._expected.keys())

        added = actual_fields - expected_fields
        removed = expected_fields - actual_fields
        type_changes = []

        for field in actual_fields & expected_fields:
            expected_type = self._expected[field]
            actual_type = str(actual_df[field].dtype)
            if not self._type_matches(expected_type, actual_type):
                type_changes.append((field, expected_type, actual_type))

        changed = len(removed) > 0 or len(type_changes) > 3

        return SchemaDiff(
            changed=changed,
            summary=self._build_summary(added, removed, type_changes),
            added_fields=list(added),
            removed_fields=list(removed),
            type_changes=type_changes,
        )
```

#### 变更 vs 正常波动的判断规则

```
字段缺失 ≠ API变更，需要进一步判断：

正常波动（不告警）：
- 单只股票数据为空（停牌/退市）
- 非交易时段无数据（字段全null）
- 字段值=0（未发生交易）

可疑变更（告警，自动降级）：
- 超过50%股票的同一字段为null
- 所有字段的dtype集体变化
- 返回结构完全不同于期望Schema
- 连续3个周期健康评分<0.5

确定性变更（紧急告警）：
- 端点URL返回非JSON/404
- 所有字段名与期望Schema零交集
```

### 3.6 配置热加载 `ConfigWatcher`

```python
class ConfigWatcher:
    """文件系统监听：配置变更后自动重载，不重启进程"""

    def __init__(self, config_dir: str, callback: Callable):
        self._dir = config_dir
        self._callback = callback
        self._last_loaded: Dict[str, float] = {}
        self._start_watcher()

    def _start_watcher(self):
        """启动文件变更轮询（1s间隔，避免inotify复杂依赖）"""
        def _poll():
            while True:
                for f in Path(self._dir).glob('*.yaml'):
                    mtime = f.stat().st_mtime
                    if f.name not in self._last_loaded or mtime > self._last_loaded[f.name]:
                        self._last_loaded[f.name] = mtime
                        logger.info(f"检测到配置变更: {f.name}")
                        self._callback(f)
                time.sleep(1)
        Thread(target=_poll, daemon=True).start()
```

## 四、运维场景推演

### 场景1：东财字段码变更（如 f2 → f_newprice）

```
1. 采集器 fetch_snapshots() → 返回的DataFrame中 price 列为空
2. HealthScorer 检测到 price 空值率 > 10%，评分从 1.0 降至 0.6
3. SchemaDiffDetector 检测到 f_newprice 存在但不在期望Schema中
4. DataSourceManager 自动切换至新浪(备源)
5. 触发告警："东财数据源异常：字段f2缺失，新增字段f_newprice，疑似字段码变更"
6. 运维人员更新 eastmoney.yaml 的 field_mapping：
     f_newprice: price
7. ConfigWatcher 1秒内检测到文件变更 → 自动重载配置
8. 下一周期 Manager 自动恢复东财为主源
9. 全程耗时：配置更新后 1 秒生效，业务无感
```

### 场景2：东财端点URL变更

```
1. HTTP请求返回404 → 适配器返回None
2. HealthScorer评分 → 0
3. DataSourceManager 自动切换至新浪
4. 触发告警："东财端点不可用，已切换至新浪"
5. (后续) 运维获取新端点URL，更新 eastmoney.yaml 的 endpoint 字段
6. ConfigWatcher 自动重载 → 恢复
```

### 场景3：所有HTTP源同时断裂（概率极低）

```
1. 东财、新浪、腾讯全部返回异常
2. DataSourceManager 所有源耗尽 → 返回缓存数据
3. 触发紧急告警："全部数据源不可用，使用缓存（缓存时间：xxx秒前）"
4. 用户界面显示"数据延迟"提示（已有 staleness_warning 机制）
5. 措施：回滚到上一版配置 / 启用手动数据录入 / 等待API恢复
```

### 场景4：字段映射错误（误配置）

```
1. 运维修改 eastmoney.yaml 的字段映射
2. 下个周期 HealthScorer 评分极低
3. 自动回滚到上一版配置（保留最近3个版本）：

   class ConfigManager:
       def __init__(self):
           self._history: Dict[str, List[str]] = {}
           # 每个配置文件保留最近3个版本的原始内容

       def rollback(self, filename: str) -> bool:
           versions = self._history.get(filename, [])
           if len(versions) >= 2:
               # 回滚到上一版
               with open(filename, 'w') as f:
                   f.write(versions[-2])
               return True
           return False
```
