> 状态：✅ 已完成 + 全量验证（2026-09-17）

## 一、背景与问题

445 号《dim2-dim7 引擎正确性知识库核查》§6.1 dim2 抓出**「级别定理/多周期联立」未接线（死 import）」**：

- `framework/chanlun_multi_level.py` 的 `MultiLevelChanlunAnalyzer`（周/日/60min 区间套 + 方向一致性 + 关键价位）是**孤儿**——仅 `test_chanlun_verification.py:480` 类级测试 + `dim2_structure_engine.py:6` docstring 提及，**从未接入生产**。
- dim2 只消费单日线级别；445 定论：缠中说禅买卖点级别定理「大级别买卖点必然是次级别以下某一级别买卖点」，多周期联立是**策略引擎正确性能力缺口**，属引擎基准范畴（先于 444 事实层/437-A 字段清单核查）。
- 下游已预埋消费者：`strategy_analyze.py:381`、`fallback_description.py:56`、`tag_extractor.py:77`、`dim4_chip_fund_engine.py:5458` 均读 `sr.multi_level`，并有「仅单级别分析，无跨级别验证数据」降级文案。

## 二、用户三项决策（拍板）

1. **接入层级**：StatusEngine `data_context` 层——dim1 信令门禁层注入 `weekly_df`/`hourly_df`，dim2 evaluate 消费。贴近 411 Phase 6 预加载模式。
2. **配置接线**：对齐 `bi_zs_mode`——`MultiLevelChanlunAnalyzer` 各级别统一走线段中枢（对齐 dim2 日线 446 号「中长线强制线段中枢」意图）。
3. **缓存串味**：本次修复——`MultiLevelChanlunAnalyzer` 缓存键由 `f'chanlun:{level}:{len(df)}'`（仅行数，跨股票/跨日期串味）改为含 `ts_code` + 最新交易日。

### 数据流

```
dim1 loader ──inject──▶ data_context{weekly_df, hourly_df, daily_df} 
                              │
dim2 evaluate │ 1b 多级别联立：聚合{week,day,hour} → MultiLevelChanlunAnalyzer
              │                → status_description.multi_level
              ▼
status_recognition.multi_level  ← strategy_analyze / fallback_description /
                                   tag_extractor / dim4 已预埋消费
```

周线取数：`minute_kline_cache freq='W'` 缓存优先→日线聚合写缓存→Tushare（`_get_weekly_data`）。
60min 取数：`minute_kline_cache freq='60min'` 缓存优先（`_get_minute_data`）。

### 降级兜底（不阻塞主链）
- 周/60min 数据缺失 → 只分析日线（`_build_direction_text` 可处理 daily-only）。
- `multi_level.enabled=False` → 优雅返回空 levels + 「多级别联立未启用」。
- 无 data_context → 保持既有空壳语义（不产 multi_level dict，仅产 `multi_level_direction_text` 降级文案）。
