# 542｜日终管道 RAW-2D/RAW-2E 未登记致卡死修复与 10-22 核算续跑

## 一、背景

2026-10-23 只读核查 2026-10-22 日终：采集层 COL-1~7 全部完成（daily_cache 5605 行等），但核算层 RAW-2C 起全部停住，SIG/JUD/OUT/QA-CHECK 连续三日（10-20/10-21/10-22）`pending`。用户拍板「开号修复，续跑 10-22 核算」。

## 二、根因

1. 532 批次2 在 `_drive_pipeline()` 的 RAW-2B 之后新增 RAW-2D / RAW-2E 检查（`backend/data_daemon.py:7486-7496`，当前行号随修复略移）。
2. `EnhancedCacheManager.ensure_pipeline_steps()`（`backend/app/data/enhanced_cache_manager.py:4572`）只登记 16 个环节，不含 RAW-2D / RAW-2E。
3. `mark_step_running()` 以 `UPDATE pipeline_status ... WHERE pipeline_date=? AND step_id=?` 加锁；行不存在 → `rowcount=0` → 返回 False。
4. `_run_pipeline_step()` 原实现 `if not mark_step_running(...): return`，无日志、无兜底 → 每 30s tick 重复同一失败，管道永久停在 RAW-2B 之后。

10-21、10-22 的日志均显示 `RAW-2B → done` 后再无任何 `[管道]` 输出，与上述链路一致（10-20 另有 21:41 daemon 停止时 RAW-2 未完成的原因）。

## 三、修复内容（两处代码 + 一项测试）

### 3.1 `ensure_pipeline_steps` 补登记两个环节

`backend/app/data/enhanced_cache_manager.py`：

```python
('RAW-2B', '板块热度持久化'), ('RAW-2D', '板块资金热度持久化'),
('RAW-2E', '板块热度五维预计算'), ('RAW-2C', '个股行业位置持久化'),
```

登记数 16 → 18，顺序与 `_drive_pipeline` 实际推进顺序（2B → 2D → 2E → 2C）一致。

### 3.2 `_run_pipeline_step` 增加缺行兜底

`backend/data_daemon.py`：`mark_step_running` 失败时先 `INSERT OR IGNORE` 补登记并重试一次；仍失败才视为另一 tick 已抢锁。这样未来新增管道步骤即使漏登记也不会静默卡死。

### 3.3 测试

新增 `backend/tests/test_542_pipeline_step_registration.py`：
- `ensure_pipeline_steps` 后 18 行且含 RAW-2D/RAW-2E（幂等）；
- 未登记步骤经 `_run_pipeline_step` 能自动补登记并执行至 `done`。
