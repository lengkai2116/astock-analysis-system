# 322 — 个股策略分析操作建议重构方案

> **背景**：2026-08-08 基于 LLM Wiki《股票现状描述框架（右侧交易信号视角）》重新规划个股策略分析板块的操作建议输出。经全面梳理（explore 报告 + 代码核查）确认：①个股页与机会图谱 ts_code 双向往返已闭环；②操作建议当前为**前端纯推导**（情景概率静态写死、置信度硬编码、目标价拍脑袋）；③后端 analyze 无操作建议字段；④存在死代码。本方案整合多轮讨论，提出"现状描述化 + 双板块结论统一 + 机器可执行"三层重构。
>
> **约束**：①Windows + macOS 双平台长期稳定运行；②符合全局数据体系（292号）四层架构红线；③虚拟实盘/复盘中心互动不在本轮实施，但需前置化数据交互方案；④AI 多角色投研是独立板块，与本方案无关。
>
> **待确认决策**：DeepSeek 在个股页的定位（现状解读 vs 操作建议）；两板块数据源设计（本轮已定原则，细节待确认）。

## 二、设计原则（多轮讨论整合）

1. **数据与逻辑分离**：操作建议由后端结构化生成（`operation_advice`），前端只渲染；
2. **结论统一**：个股页操作建议与机会图谱**同一状态机结论**（321号 `opportunity_state` + `state_evidence`），消除两页不一致；
3. **现状描述优先**（LLM Wiki 框架）：红绿灯 + 一句话结论 + 证据数字 + 大白话，弱化预测（target_price 保留现状，改为空间参考）；
4. **机器可执行**：输出结构化 entry/exit 规则，支持虚拟实盘/复盘中心前置数据交互（本轮只设计流程，不实施）；
5. **死代码全清理**；
6. **三板块定位分明**：AI 多角色投研（独立板块，多角色讨论输出建议）/ 个股策略分析（现状解读+操作参考）/ 机会图谱（筛选层结论）。

## 三、操作建议新结构（后端 operation_advice）

```python
'operation_advice': {
    # ── 结论层（复用 321 号状态机，与机会图谱同源）──
    'state': 'enter|light|wait|avoid',
    'state_reason': '右侧否决：卖出/背离/预跌信号',
    'summary': '🟢 强趋势：信号确认/量价健康/风险边界清晰',
    # ── 七维现状（红绿灯，LLM Wiki 框架）──
    'dimensions': [
        {'key': 'signal', 'light': '✅', 'conclusion': '...', 'evidence': '...', 'plain': '...'},
        # structure / volume_price / fund / sentiment / risk（同类结构）
    ],
    # ── 几何化指标 ──
    'geometric': {'dist_to_support_pct': -3.8, 'dist_to_resistance_pct': 12.1,
                  'risk_reward': 3.1, 'signal_days': 4},
    # ── 操作参考（保留 action；target_price 保留现状，改空间参考语义）──
    'action': {'max_position_ratio': 0.6, 'entry_plan': [...], 'stop_loss': {...}},
    # ── 情景推演（概率由后端推导）──
    'scenarios': [
        {'id': 'a', 'name': '趋势延续', 'prob': 0.60, 'steps': [...]},
        {'id': 'b', 'name': '冲高回落', 'prob': 0.25, 'steps': [...]},
        {'id': 'c', 'name': '破位下行', 'prob': 0.15, 'steps': [...]},
    ],
    # ── 机器可执行规则（虚拟实盘前置，本轮仅设计）──
    'executable': {
        'action_type': 'BUY|HOLD|REDUCE|SELL|WAIT',
        'entry_rules': [{'trigger': 'close <= 10.20', 'action': 'BUY', 'size_pct': 30}],
        'exit_rules': [{'trigger': 'close < 9.80', 'action': 'SELL', 'size_pct': 100}],
        'position': {'max_pct': 60, 'initial_pct': 30},
    },
}
```

### 情景概率推导（规则基线 + Kronos 可选修正）
```
情景概率 = 规则基线（确定性、可核查） + Kronos 修正（可选，标注"AI预测仅供参考"）

规则基线：五维方向一致度 / volume_price_fit / fund_flow / main_force_phase /
          距支撑距离 → 打分 → 归一化三情景概率（和为 1）
Kronos 修正：kronos_enabled 时输出方向倾向，对基线 ±调整；torch 未装优雅降级
诚实标注：Kronos 参与时标注"🔬 AI模型预测，仅供参考，非实证"
```

## 四、两板块数据源设计（本方案原则，292 号红线合规）

### 4.1 原则：数据分、结论统、执行机器可读
- **数据层分离**（各自保留最优形态）：图谱=标签截面（筛选）、个股页=信号深挖（分析）——不强行统一数据，符合 320号 #020"不统一引擎，统一数据消费层"；
- **结论层统一**：两板块操作建议同一 321 状态机（消除不一致）；
- **执行层机器可读**：executable 结构供虚拟实盘/复盘中心消费。

### 4.2 数据核算耗时规避
- 个股页五维继续走 `strategy_signal_detail` 缓存（daemon 预计算），不实时重算（320号 F3 已落地）；
- `operation_advice` 在 analyze 响应时**实时组装**（基于缓存信号 + K线几何指标，毫秒级），**不落库、不入快照**（避免全市场预计算成本；仅诊断场景生成）；
- 机会图谱侧弹窗已复用 diagnose（321号），两处结论同源但各自计算，无重复预计算。

### 4.2.1 对策1：analyze 缓存读取修复（2026-08-08 实测发现，已纳入本方案）

**问题**：`strategy_analyze.py` 使用 `get_signal_detail(ts_code)`（严格查**当日** trade_date）。非交易日/新交易日（如周六）→ 所有股票缓存 miss → 触发 `UnifiedStrategyCore.compute` 实时计算（**实测单只 4.5-6.1 秒**），体验差。

**根因**：320号 F3 已实现 `get_latest_signal_detail()`（`ORDER BY trade_date DESC` 取最新一条，实测命中 08-07 缓存），但 analyze 路由仍在用旧的 `get_signal_detail`。

**对策**：
1. `strategy_analyze.py` 缓存读取改用 `get_latest_signal_detail`（优先）→ 非交易日直接命中最新缓存，**5 秒 → 毫秒级**；
2. 保留 `get_signal_detail`（当日严格）作为**当日数据校验**：当日有缓存用当日，否则回退最新一条；
3. 响应 `data_availability` 标注实际使用的数据日期（`signal_date`），前端提示"数据基于 YYYY-MM-DD"，避免旧数据误导；
4. 首次 miss 仍回退实时计算 + 落盘（cache_signal_detail），之后同股命中。

**验证**：非交易日（周六）打开 600519/000039 → analyze 不再触发实时计算，响应含 `signal_date=2026-08-07`。

### 4.3 虚拟实盘前置数据交互（本轮仅设计流程）
```
个股页生成 operation_advice（含 executable）
  → 用户点"加入复盘池"：存入 review_pool（含 operation_advice JSON 快照）
  → 复盘中心读取：按 executable.entry_rules/exit_rules 回放价格 → 模拟记账
  → 结算：触发条件满足 → 执行买卖 → 盈亏记录
数据契约：operation_advice.executable 即虚拟实盘输入（机器可读、确定性）
```
