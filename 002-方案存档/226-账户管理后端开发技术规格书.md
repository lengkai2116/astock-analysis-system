## 1. 页面定位

账户管理是**用户的实盘记账和交易行为分析入口**。用户在系统内手工录入实盘交易，获得六维操作复盘评估和周期性的交易报告。

### 1.1 页面架构（五层布局）

```
┌─ 页面头部 ──────────────────────────────────────────────────┐
│ 👤 账户管理    [➕ 新建交易] [⚙ 设置]                          │
├─ 第一层：KPI芯片条 ──────────────────────────────────────────┤
│  总资产 │ 总盈亏 │ 总收益率 │ 交易次数 │ 胜率 │ 最大回撤 │ 盈亏比 │
├─ 第二层：持仓监控（可折叠） ────────────────────────────────────┤
│  当前持仓 N只 · 总仓位 · 持仓市值                              │
│  表格：股票│持仓│均价│现价│盈亏│占比│持有│操作（卖出/补仓）    │
├─ 提示条 ──────────────────────────────────────────────────────┤
├─ Tab 栏 ─────────────────────────────────────────────────────┤
│ 📋 交易记录 | 🧠 操作复盘 | 📊 周期回顾                       │
├──────────────────────────────────────────────────────────────┤
│ Tab1 交易记录（子视图：时间线/个股归集）                        │
│  筛选栏：股票/日期范围/方向                                   │
│  子视图A：时间线卡片列表（日期/股票/方向/数量/盈亏/手续费/理由） │
│  子视图B：个股归集（按股票分组展开/折叠+汇总）                 │
│  [新建交易弹窗] — 双向+日期+价格+数量+手续费自动核算            │
│   买入/卖出理由（可选，7种快捷+自定义）+部分卖出标识            │
│   关联复盘策略（RV-xxx候选列表，自动检索同票策略）              │
├─ Tab2 操作复盘（三轴） ────────────────────────────────────┤
│  子视图1：维度归因（A-F六维侧栏导航+详情面板）                │
│    A买卖点质量 / B策略执行 / C资金风控 / D时机节奏            │
│    E行为模式 / F综合归因与建议                                │
│  子视图2：按个股（下拉选择+4指标卡+买卖点/行为/建议）          │
│  子视图3：按时段（双日历点击选择+自动生成回顾）               │
├─ Tab3 周期回顾 ────────────────────────────────────────────┤
│  周期选择：本周/本月/本季/自定义（双日历）                    │
│  报告卡片：4指标+收益归因+行为趋势+TOP改进+下期关注           │
│  [保存到报告中心] + 已存档报告列表（下载/跳转/删除）          │
├─ 设置弹窗（全量4Tab） ──────────────────────────────────────┤
│  开户设置（账户名/初始金额/偏好/止损止盈）                     │
│  资金变动（追加/取出+历史记录表）                             │
│  系统配置（佣金率+行为模式阈值）                              │
│  变动记录（资金变动历史表）                                  │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 六维复盘模型（210号方案）

| 维度 | 核心问题 | 数据源 |
|:-----|:---------|:-------|
| A 买卖点质量 | 这笔单子的位置好不好？ | K线+技术指标 |
| B 策略执行与有效性 | 操作与策略一致吗？策略本身有效吗？ | 复盘中心RV-xxx诊断结论 |
| C 资金与风险管理 | 仓位和止损合理吗？ | 交易记录序列 |
| D 交易时机与节奏 | 持有周期和操作频率合理吗？ | 交易记录+情绪周期参考 |
| E 行为模式识别 | 有追涨杀跌/过早止盈等问题吗？ | 交易记录序列+行为金融学 |
| F 综合归因与建议 | 整体做得如何？怎么改进？ | A-E聚合 |

### 3.3 路由前缀迁移：v1 → v3

当前 `account.py` 使用 `url_prefix='/api/v1/account'`。171号文档的端点均使用 `/api/v1/account/` 前缀。考虑到系统其他页面统一为 v3 路由：

> **决策：** 保持 `/api/v1/account/` 前缀，所有新端点也使用同一前缀。账户模块是独立域，不与系统其他模块共用路由约定。

**原因：** 166号/171号/210号方案均以`/api/v1/account/`标注现有10个端点，迁移成本高于收益。

### 3.4 后端就绪度评估：~50%（10端已实现v1 + 4端待建 + 3端字段需扩展）

已有10个端点的**基础CRUD能力**就绪（交易CRUD+持仓+汇总+资金曲线），但存在三个关键缺口：
1. **路由前缀紊乱：** 当前为v1，与系统v3约定不一致 → 使用account独立域保持v1
2. **数据模型字段不足：** 现有trade不包含buy_reason/sell_reason/rv_id/is_partial 4个原型所需字段
3. **六维复盘引擎不存在：** review/periodic-review端点全量待建，A-F维度分析逻辑无任何后端代码

## 8. 手续费自动核算逻辑

**前端公式（可直接复用为后端）：**
```python
def calc_trade_fee(price: float, quantity: int, direction: str, commission_rate: float = 2.5):
    """手续费自动核算"""
    amount = price * quantity
    commission = amount * commission_rate / 10000
    commission = max(commission, 5.0)      # 最低5元
    stamp_tax = amount * 0.0005 if direction == 'sell' else 0   # 印花税(仅卖出)
    transfer_fee = amount * 0.00001         # 过户费(沪深统一)
    total = commission + stamp_tax + transfer_fee
    return {
        'amount': amount,
        'commission': round(commission, 2),
        'stamp_tax': round(stamp_tax, 2),
        'transfer_fee': round(transfer_fee, 2),
        'total': round(total, 2)
    }
```

**费率配置（可从系统管理配置源读取）：**
| 费用 | 费率 | 适用范围 |
|:-----|:------|:---------|
| 佣金 | 万2.5(可配置，最低5元) | 买入+卖出 |
| 印花税 | 0.05%(固定) | 仅卖出 |
| 过户费 | 0.001%(沪深统一) | 买入+卖出 |
