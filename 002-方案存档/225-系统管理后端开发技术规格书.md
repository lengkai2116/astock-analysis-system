## 1. 页面定位

系统管理是**全系统的配置与控制中心**。用户在这里查看系统运行状态、管理数据缓存同步、配置外部API服务（DeepSeek/Tushare/SMTP）、连接QMT行情源、浏览管理条件库。

### 3.3 后端就绪度评估：~77%（22端点中16个已实现 + 5个待建设 + 1个需路由迁移）

**核心发现：** 系统管理是**全站后端就绪度最高的页面之一**。22个API端点中16个已经实现（health 2端 + cache 7端 + qmt 6端 + conditions 8端），**有5个端点待建设**（config/save + config/load + schedule/config GET/POST + sync-now + logs + next-runs），另有1个需要路由前缀迁移（data-source/status）。

> **注：** 调度配置端点从原2个P1（sync/schedule）升级为5个（232号方案），其中schedule/config GET+POST提升为P0（底盘级交付）。

但是运行概览Tab的数据展示需要**增强health端点**：当前`GET /api/v3/health`仅返回 `{success, status, message}` 极简结构，不包含原型所需的6项服务状态详情（PostgreSQL/Redis/DuckDB/Backend/Nginx/WebSocket的各指标）。

## 6. 运行时配置热更新设计

### 6.1 需求（来自166号§18.3）

> 以上所有配置项必须支持**运行时热更新**，用户修改后无需重启后端即可生效。需后端提供统一配置持久化端点 `POST /api/v3/system/config/save` 写入到 `backend/data/` 或数据库配置表，后端各模块从共享配置源（非 `.env` 文件）动态读取。

### 6.2 架构方案

```
┌─ 用户修改配置 ──────────────────────────────────────────┐
│  Tab③表单修改 → 点击"保存全部配置"                       │
│  → POST /api/v3/system/config/save                      │
└─────────────────────────────────────────────────────────┘
                            │ 写入
                            ▼
┌─ 配置存储 ──────────────────────────────────────────────┐
│  ╔═ 数据库 system_config 表 (推荐) ═══════════════════╗  │
│  ║  key(string PK) | value(JSON) | updated_at(datetime)║  │
│  ╚════════════════════════════════════════════════════╝  │
│  或: backend/data/config.json (简单方案,但不支持并发)    │
└─────────────────────────────────────────────────────────┘
                            │ 通知
                            ▼
┌─ 运行时配置管理器 (RuntimeConfigManager) ───────────────┐
│  • 启动时从DB/文件读取所有配置到内存 dict                │
│  • save() → 写入存储 + 更新内存 dict                    │ 
│  • load() → 读取完整配置JSON供前端回填                   │
│  • get(key) → 各模块调用获取单项配置                     │
│  • reload() → 强制从存储重新加载                         │
└─────────────────────────────────────────────────────────┘
                            │ 读取
                            ▼
┌─ 各模块使用 ────────────────────────────────────────────┐
│  AI分析 : RuntimeConfigManager.get('llm.deepseek_api_key')│
│  数据同步: RuntimeConfigManager.get('data_source.tushare_token')│
│  通知推送: RuntimeConfigManager.get('notification.smtp.host')│
└─────────────────────────────────────────────────────────┘
```
