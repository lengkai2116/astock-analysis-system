## 二、BUG（错误）

### BUG-01（CRITICAL）：`df_fina` 未定义 — NameError 导致 dim7 完全失效

**位置**：`_compute_valuation()` line 796

```python
# line 794-798
_empty_tables = []
if df_fina.empty: _empty_tables.append('fina_indicator')  # ← NameError: name 'df_fina' is not defined
if df_bs.empty: _empty_tables.append('balancesheet')
if df_cf.empty: _empty_tables.append('cashflow')
```

**根因**：`_compute_valuation()` 方法（line 766）内部获取了 `df_basic`、`df_income`、`df_bs`、`df_cf`，但**从未获取 `df_fina`**。`df_fina` 仅在以下两处定义：

1. `_fina_health()` 方法（line 674）：`df_fina = ecm.get_cached_fina_indicator(ts_code)` — 不同作用域
2. `elif fina_health == 'pass'` 分支（line 841）：`df_fina = ecm.get_cached_fina_indicator(ts_code)` — 在 line 796 之后

**影响链**：

```
df_fina NameError (line 796)
  → _compute_valuation() 抛出异常
    → evaluate() line 1021 崩溃
      → status_engine.py:282 except Exception 捕获
        → results['valuation'] = None
          → dim7 所有输出为 None
            → 下游消费方（dim_adapter/dim8/conflict_matrix/reliability_assessor/weight_engine）全部跳过
              → 估值维度在整个系统中完全失效
```

**严重度**：CRITICAL — dim7 在生产环境中完全不工作。

**修复方案**：

在 `_compute_valuation()` 中 line 792 后添加 `df_fina` 获取：

```python
# line 792 后新增
try:
    df_fina = ecm.get_cached_fina_indicator(ts_code)
except Exception:
    df_fina = pd.DataFrame()
```

同时删除 line 796 的 `if df_fina.empty` 检查——`_empty_tables` 追踪逻辑本身因 BUG-01 已是死代码，且 `fina_indicator` 的空表检查在 `_fina_health()` 内部已有独立处理。

**工时**：0.1天

### BUG-02（已撤回）：`deviation` key名不匹配 — 误判

**位置**：`dim_adapter.py:755`

```python
_deviation = _safe_float(_val_sd.get('valuation_deviation', _val_sd.get('deviation')), 0.0)
```

**审计复查结论（406号修订）**：这不是 bug。`.get('valuation_deviation', _val_sd.get('deviation'))` 使用双 key 回退机制，dim7 产出 key 为 `valuation_deviation`，第一个参数即可命中，`deviation` 回退永远不会触发。修改前与修改后代码完全相同（原方案 line 94-98 为 no-op）。

**原影响分析**：不适用（deviation 分量正常工作，不会始终为 0）。

**处置**：撤回此 bug，无需修改。

### BUG-03（LOW）：`int()` 截断 float 锚评分

**位置**：`conflict_matrix.py:131-132`

```python
asset_anchor = int(_safe_float(_safe_get(dim7_sd, 'asset_anchor_rating', default=0)))
earnings_anchor = int(_safe_float(_safe_get(dim7_sd, 'earnings_anchor_rating', default=0)))
```

**根因**：dim7 产出 float 类型（如 0.5、-0.7），`int()` 截断后丢失精度。

**影响**：C14 冲突规则（`asset_anchor <= -1 AND earnings_anchor >= 1`）的阈值在整数边界。-0.9 被截断为 0（中性），丢失有意义的负信号。

**严重度**：LOW — 仅影响边界案例。

**修复方案**：

修改 `conflict_matrix.py:131-132`，去掉 `int()` 截断：

```python
# 修改前
asset_anchor = int(_safe_float(_safe_get(dim7_sd, 'asset_anchor_rating', default=0)))
earnings_anchor = int(_safe_float(_safe_get(dim7_sd, 'earnings_anchor_rating', default=0)))

# 修改后
asset_anchor = _safe_float(_safe_get(dim7_sd, 'asset_anchor_rating', default=0))
earnings_anchor = _safe_float(_safe_get(dim7_sd, 'earnings_anchor_rating', default=0))
```

注意：需同步检查 C14 规则中 `<= -1` 和 `>= 1` 的比较是否仍适用于 float 类型（float 比较在 Python 中对整数阈值是精确的，无需额外处理）。

**工时**：0.05天
