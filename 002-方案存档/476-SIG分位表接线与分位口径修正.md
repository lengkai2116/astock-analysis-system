# 476号｜dim7 SIG 截面基准接线 + 分位口径修正（SSOT 优先 + 实算兜底）

**定位**：dim7 只读检查（2026-09-23）后续落地号。解决 SIG 侧（`StatusEngine → Dim7ValuationEngine`）**截面基准从未构建**导致的与 RAW 预计算（`daemon → ValuationEngine.compute_tags`）口径系统性不一致，并修正分位基准构建侧 3 个口径 bug。

**状态**：✅ **已实施**（2026-09-23）。决策拍板：**D1=C / D2=A / D3=A（含 EV 扩展）/ D4=A**。代码完成 + 测试 182 passed + 冒烟回算验证；全量回算进行中。

## 起因
dim7 只读审查实证（8 股真实 evaluate + tags 探针，daemon 停止态）：
- `status_engine._build_dim_engine_results` 对 dim7 每只股票 `engine_cls()` 直接 `evaluate`，**从不调用任何分位表构建**（`build_composite_percentile`/`build_fcf_percentile`/`build_potential_percentile_tables` 无 SIG 侧调用点；`build_potential_percentile_tables` 全项目无生产调用点）。
- 而 daemon RAW-2（data_daemon:3182/3187）对 `ValuationEngine`（RAW 侧）构建了 composite/fcf 分位 → RAW tags 的 `valuation_level` 是**截面分位 + 行业中性化**口径；SIG evaluate 实算是**绝对阈值**口径。

## 核查结论（实证证据）

### 1. SIG 侧分位表全空 → 三处口径偏离
8 股 `Dim7ValuationEngine` 实例（status_engine 同款创建方式）实证全部：
```
_comp_percentile=None  _fcf_percentile=None  _industry_mean={}  _potential_tables={}
```
| 输出 | SIG 实算 | RAW tags（daemon） | 实证偏差 |
|---|---|---|---|
| level | 绝对阈值分支（无分位、无行业中性化） | 截面分位 + 行业中性化 | **8 股 5 股不一致**：600519 fair vs low、300750 low vs extreme_low、002594 high vs fair、000001 high vs extreme_high、600036 high vs extreme_high |
| 现金流锚 a3 | 国债利差分支（整数 -2~2） | 分位表分支（pct×4-2） | composite 偏差：300750 SIG 0.4843 vs RAW 0.8833 |
| potential val/earn | 表空 → **恒 0.5**（earn 完全恒定；val 仅 suspicious ×0.7→0.35） | RAW 不产 potential（SIG 独有） | 464 §6.3「val→分位表、earn→ROE 分位」**从未生效** |

消费方混用两口径：dim8/judgment 用 SIG 实算 level；`status_engine` dims['valuation'].state 用 `tags.valuation_level`（RAW）→ signal_analyzer/权重/冲突矩阵是 RAW 口径、dim8 是 SIG 口径。

### 2. dim7.build_composite_percentile 必失败（`get_tags_batch` 不存在）
dim7 侧（dim7_valuation_engine.py:256）用 `dm.get_tags_batch(all_codes)`——**DataManager 无此方法**（实证仅有 `get_tags_by_date`/`get_tags_by_group`）→ AttributeError 被 except 吞 → `_comp_percentile` 恒 None。即使接线也不工作。
RAW 侧（valuation_estimator.py:221）用 `cache._query_shard('opportunity_tags_cache', ...)` SQL 直读 composite_rating（分库路由，2026-09-13 修），**实现完全不同且可用**（实证 RAW `_comp_percentile=built`）。

### 3. build_fcf_percentile 口径 bug（**RAW/SIG 双侧共同**）
- 构建分布：`vals.append(fcf / mv * 100)`（无 /1e4）——dim7:316 与 valuation_estimator:189 相同
- 消费口径：`_anchor_cashflow` `fcf_yield = fcf / 1e4 / ev * 100`；`compute_tags` 输出 `fcf / (mv * 1e4) * 100`
- 实证（600519）：`fcf/mv*100=18786.3` vs 消费 `fcf/(mv*1e4)*100=1.8786`，差 **1e4 倍**
- 实际影响（RAW 侧实测）：`pct(1.8786)=0.584`、`pct(18786)=0.798` → **查询用小数值（消费口径）落在分布低端，现金流锚 a3 系统性偏低**：600519 `a3=0.33`（口径修正后应为 `0.798×4-2≈1.19`）
- 属**输入层口径 bug**（分位基准怎么算），445-A2（total_mv 单位）同型；但修正**会改变 composite/level**（需全量回算）

### 4. potential val 表口径错配（构建 PE 分位、查询传 dev）
`build_potential_percentile_tables`（dim7:322）：`val` 表 = `_lookup(sorted(pe_ttm))`（PE 分位，值域 0~数百）；`_compute_potential` 查询传 `tags.valuation_deviation`（值域 -40~40）→ `bisect_left(PE分布, dev)` 把 dev 塞进 PE 分布 → val 维系统性失真（600519 dev=8.5 落在 PE<8.5 的低端 → val 偏小）。B3 注释「用 PE 分位代替 valuation_deviation」只改了构建侧，查询侧未同步。

### 5. StatusEngine 实例化方式
调用方（strategy_analyze:860/1037、cross_validate:731）均 `StatusEngine().evaluate()` **每次新建实例** → 若分位表构建放 `__init__` 会每请求全市场遍历（性能灾难）→ 必须**进程级一次**（模块级全局，惰性）。`build_status_engine()` 工厂存在但调用方未用。

## 方案设计（决策点，待拍板）

### D1：SIG 侧 level/deviation/a3 口径来源
- **A. SIG 自建分位表**：修 §2 的 `get_tags_batch` bug + 进程级预热 + 修 §3/§4 口径。保持 SIG 实算完全独立。
- **B. SSOT 读 RAW tags**：level/deviation/a3 改**优先读 tags**（`valuation_level`/`valuation_deviation`/`cashflow_anchor_rating`，RAW 截面分位口径），SIG 实算仅兜底（tags 缺失时）——**与 461-2 fina_health 完全同构**（SSOT=RAW 预计算，SIG 兜底重算）。零构建成本、天然一致。
- **C. 混合（建议）**：B 为主 + A 作为兜底路径也修正正确（tags 缺失时实算也能对上分位口径）。工作量最大但最稳。

> 445 冻结边界：level 判定**逻辑**（五级分档阈值）不动；本号只改「level 的**输入来源**」与「分位基准的**构建口径**」——属事实/输入层（444「该改就改」），与 461-2/445-A2 先例一致。

### D2：分位表构建时机（仅 A/C 需要）
- A. status_engine **模块级惰性单例**（进程启动后首次访问构建一次，全局缓存）——推荐
- B. 复用 daemon 构建结果（读库）——复杂，不推荐

### D3：fcf 分位口径修正（双侧）
`build_fcf_percentile`（dim7 + valuation_estimator 两处）分布改 `fcf / (mv * 1e4) * 100`，与消费口径对齐。**副作用**：RAW 侧 a3/composite/level 变化（如 600519 a3 0.33→1.19）→ 需 RAW 全量重算（对齐 474 号存量回算流程）→ tags 更新 → SIG 一致。
- 选项：A. 纳入本号一并修（推荐，否则 SIG 接线后仍与 RAW 差一个口径）；B. 单独开号。

### D4：potential val 表口径
- A. 构建改 **dev 分布**（`valuation_deviation` 全市场分布，与查询同口径）——推荐
- B. 查询改传 `pe_percentile_5y`（表不变）
> earn 表（ROE 分位 ↔ roe 查询）口径正确，仅需接线。
