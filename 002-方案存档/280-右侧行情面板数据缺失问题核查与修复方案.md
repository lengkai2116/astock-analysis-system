## 一、问题概述

## 二、全链路审计（五步审计法）

### 审计方法和分类标准

按 279 号方案定义的五步审计法逐组审计：
- **Step 1**: 前端需求识别（字段 + 端点）
- **Step 2**: 调用层合规检查
- **Step 3**: 存储层可用性检查
- **Step 4**: 计算层需求判断
- **Step 5**: 采集渠道确认

分类标准：
- ✅ **已合规**：完整四层链路，数据已就绪
- 🟡 **已修复**：原不合规/缺口，已修复通过验证
- 🔴 **待修复**：违反架构红线，需立即修复
- ⚪ **缺口**：数据不存在，无可用数据源

#### 均价 avg_price — 🟡 已修复

| 层级 | 修复前 | 修复后 |
|------|:------:|:------:|
| 采集 | ✅ Tushare `amount(千元)` + `vol(手)` | 不变 |
| 存储 | ✅ `daily_cache.amount/vol` | 不变 |
| **调用** | **🔴 公式错误**: `amount/(vol*100)` | **🟡 已修复**: `amount*10/vol` |
| 前端 | 所有股票显示 ~0.01 | 000001.SZ: 10.82 (close=10.78 ✅) |
| **根因** | `amount` 单位为千元，`vol` 单位为手。公式 `amount/(vol*100)` 只做了手→股转换，遗漏了千元→元转换（缺 `*1000`） |
| **链路** | 采集: Tushare → 存储: daily_cache → 调用: avg_price=amount*10/vol → 前端 |

#### 涨停 / 跌停 — 🟡 已修复（E09）

| 层级 | 修复前 | 修复后 |
|------|:------:|:------:|
| 采集 | ✅ `_batch_stk_limit()` 日终同步 | 不变 |
| 存储 | ✅ `stk_limit_cache.high_limit/low_limit` | 不变 |
| **调用** | **🔴 硬编码 `today=datetime.now()`**：非交易日查不到 | **🟡 已修复**: 用最新交易日 `SELECT MAX(trade_date) FROM stk_limit_cache` |
| 前端 | 非交易日显示"涨跌停数据不可用" | 返回最新交易日数据 ✅ |

#### 量比 volume_ratio — 🟡 已修复（计算层自算）

| 层级 | 修复前 | 修复后 |
|------|:------:|:------:|
| 采集 | ❌ Tushare `daily_basic.volume_ratio` 返回 NULL（免费 API 限制） | 不变（不再依赖 Tushare 原始字段） |
| 存储 | ❌ `daily_basic_cache.volume_ratio` 全部为 NULL | 不变（列已存在） |
| **计算** | **⚪ 缺口**: 无计算逻辑 | **🟡 已修复**: 新增 `_compute_volume_ratio()` 在 data_daemon 中自算 |
| 调用 | ✅ E07 已读取该字段 | 不变 |
| 前端 | 全部显示 `'--'` | 待日终同步后显示正确值 ✅ |
| **链路** | 采集: Tushare → 存储: daily_cache.vol → **计算**: vol_ratio=today_vol/5d_avg_vol → 回写 daily_basic_cache → 调用 → 前端 |

**计算层实现**：`_compute_volume_ratio()` 在日终 `_batch_daily_basic` 完成后自动触发：
1. 取 daily_cache 最近 5 个交易日 vol
2. 按股票分组：`volume_ratio = 今日vol / 前4日均vol`
3. `UPDATE daily_basic_cache SET volume_ratio = ?` 回写

#### 涨速 speed / 委比 commission — 🟡 已修复

| 层级 | 修复前 | 修复后 |
|------|:------:|:------:|

#### BVPS 每股净资产 — 🔴 待修复（字段名映射断裂）

| 层级 | 审计详情 |
|------|---------|
| 采集 | ✅ Tushare `pro.fina_indicator(period=?)` 返回列 `bps`（Book value Per Share） |
| **存储** | **🔴 断裂点**：DB 表 `fina_indicator_cache` 字段名为 `bvps`，Tushare 返回 `bps`。`_insert_from_df` 按列名匹配合并，`bps` ≠ `bvps`，**整列丢弃** |
| 计算 | ➖ 原始字段，无需计算 |
| 调用 | E07 读取 `fina.get('bvps')` → `None` |
| 前端 | 全部显示 `'--'` |

**真实根因（非积分问题）**：

```
Tushare API 返回的列名:  ts_code  eps  bps  dt_eps  cfps  roe  ...
                                              ↓
DB fina_indicator_cache 表列:  ts_code  eps  bvps  eps_diluted  cf_ps  roe  ...
                                              ↓
                                     bps ≠ bvps → bvps 永远为 NULL
```

同样断裂的字段：

| Tushare 列名 | DB 列名 | 影响 |
|:------------:|:-------:|:----:|
| `bps` | `bvps` | BVPS 全部缺失 (4,994只) |
| `dt_eps` | `eps_diluted` | 稀释EPS全部缺失 |
| `cfps` 或 `ocfps` | `cf_ps` | 每股现金流全部缺失 |
| — | `eps_ttm` | Tushare 不返回该字段，缺失 |
| — | `revenue_ps` | Tushare 有 `total_revenue_ps` 和 `revenue_ps`，需核对映射 |
| — | `profit_ps` | Tushare 无对应字段，缺失 |

**修复方案**：在 `enhanced_cache_manager.py:1121-1131` 的 `cache_fina_indicator_data()` 中，插入前添加列名映射：

```python
column_map = {
    'bps': 'bvps',
    'dt_eps': 'eps_diluted',
    'cfps': 'cf_ps',
    'ocfps': 'cf_ps',
    'total_revenue_ps': 'revenue_ps',
}
df.rename(columns=column_map, inplace=True)
```

**修复时间点**：修改后随下一次 `_batch_fina_indicator()` 运行自动生效。
