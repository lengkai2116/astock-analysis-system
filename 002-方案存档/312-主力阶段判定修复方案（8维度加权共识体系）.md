# 主力阶段判定修复方案（8 维度加权共识体系）

## 一、背景与问题

### 1.1 现状问题（2026-08-02 实证核查，见 26-08-02 沟通纪要 008-013）

`PhaseDetectionEngine`（298号设计的五源投票实现）存在三类结构性问题：

| 问题 | 实证 | 根因 |
|------|------|------|
| **washing 兜底垃圾筐** | washing 占 57.8%（3224/5578） | ASR else→washing（phase_detector.py:308）+ StageDetector CONSOLIDATION 兜底（volume_price_strategy.py:2118）+ 资金流 mixed→washing（phase_detector.py:252）三源"兜底即洗盘" |
| **弱共识采纳** | phase_confidence=0.4（2/5 一致）1887 只占 33.8% | `_vote_decision` 2 源一致即采纳（phase_detector.py:460-466），违背 298 号"≥3 一致才确认"；无分歧原因输出 |
| **单源数值抹平** | confidence 仅 5 个离散档（0.35/0.4/0.6/0.8/1.0） | 阈值离散化（pos_ratio 0.29/0.31 断裂）+ 票数制（ASR 0.16 与 0.89 同投 washing、振幅 1% 与 15% 同 CONSOLIDATION 固定 0.50） |
| **资金博弈维度缺失** | capital_nature（龙虎榜）、SSRP（主力成本）、融资反向、股东户数均未参与判定 | 五源只采用筹码策略部分输出；知识库《筹码分布分析（主力视角）》的主力集中价/融资成本价/控盘度/散户反向维度系统未实现 |

### 1.2 修复目标

把"主力阶段判定"从 **5 源等权票数制（兜底垃圾筐）** 升级为 **8 核心维度加权连续强度共识（有证据才判定）**：

- 有证据才投票：无证据归 unknown（细分），不兜底
- 单源携带连续强度：过阈值不再是 1 票，输出阶段分布向量
- ≥3 维度加权共识：置信度连续，不再离散档位
- 接入资金博弈维度：主力成本锚定、控盘度、融资反向、资金性质、股东户数
- 分歧显性化：phase_conflict 标记 + 用户端风险说明

### 1.3 与 311 号方案的关系

本方案是 311 号（信号强度评分体系重构）的**上游引擎修复**：311 基础层"方向×强度"的强度来源 `phase_confidence` 由本方案产出（连续化后直接受益），§3.1.1 数据通道的 `phase_vote_ratio` 由本方案输出。

### 3.1 维度清单与权重

| # | 维度 | 类型 | 数据来源 | 权重 | 说明 |
|:-:|------|------|---------|:---:|------|
| 1 | 筹码形态 | 修复 | TradingPhaseDetector（chip_strategy_impl.py） | 3.0 | 去兜底、设最低分门槛 |
| 2 | 资金流向 | 修复 | MainForceScorer 0-10 完整评分（chip_strategy.py:412） | 3.0 | 替代 5 日方向简化版 |
| 3 | 量价四阶段 | 修复 | StageDetector（volume_price_strategy.py:2096） | 2.5 | CONSOLIDATION 加箱体/量能/成本区验证 |
| 4 | ASR 筹码分布 | 修复 | ASR 原值（phase_detector.py:266） | 2.0 | 去 else→washing 兜底，用 ASR 连续值 |
| 5 | 趋势方向 | 修复 | VolumePrice 三周期斜率 | 1.5 | 用斜率原值 |

### 3.2 各维度判定规则（阶段分布向量输出）

**输出约定**：每维度输出 `{building: w1, washing: w2, lifting: w3, distributing: w4}`，Σw ≤ 1；无证据时输出全 0 向量（**不兜底**）。

#### 维度1 筹码形态（修复）
- 保留五阶段评分（BUILDING/WASHING/RAISING/SHIPPING/SUPPORT），修复点：
  - **设最低分门槛**：最高阶段分 < 2.0（或最高分占比 < 40%）→ 输出全 0（无证据），不强行归类
  - 阶段分布 = 各阶段分 / 总分（连续），替代"最高分 1 票"

#### 维度2 资金流向（修复）
- 使用 `MainForceScorer.score()` 0-10 完整评分 + 分项（moneyflow/volume_price/股东户数）：
  - `score_a`（资金流）方向 → lifting（净流入）/ distributing（净流出）
  - 强度 = 分项分/满分（连续）
  - 阶段向量 = 方向主项 + 强度 + 次要项
- 修复点：替代 `_fund_flow_to_phase` 的 5 档简化（inflow/mixed/outflow/none）；mixed 不再投 washing

#### 维度3 量价四阶段（修复）
- 保留 MA60 方向 + HH/HL 序列判定；修复点：
  - **CONSOLIDATION 加证据验证**：需同时满足 ①价格箱体振幅收窄（20 日振幅 < 15%）②量能萎缩（5 日均量 < 20 日均量）③价格贴近筹码成本区（±10%）——**任一不满足 → 输出全 0（unknown）**，不再无条件兜底
  - 置信度用阶段内强度（振幅/量能比），替代固定 0.50

#### 维度4 ASR 筹码分布（修复）
- 保留 298 号 4 条 ASR 规则（lifting/building/lifting/distributing），修复点：
  - **删除 else→washing 兜底**：不满足任何规则 → 输出全 0
  - 强度 = ASR 原值映射（0-1 连续），ASR 0.16 与 0.89 给出不同强度
  - 补全 304 号规划的 ASR 趋势维度（30 日斜率）作为辅助

#### 维度5 趋势方向（修复）
- 三周期斜率原值：`strength = min(1, Σ|slope_i|/阈值)`；方向 up → lifting 支持、down → distributing 支持
- 修复点：用斜率连续值替代 up/down/mixed/no_trend 四态离散

#### 维度6 主力成本锚定（新增，批次1）
- 规则：
  - 价格 < SSRP × 0.95 → building（价在主力成本下方，安全边际）
  - 价格在 SSRP ±10% → washing（回踩成本区，蓄势）
  - 价格 > SSRP × 1.2 → lifting（浮盈，拉升动力）
  - 价格远离成本 + 获利盘厚 → distributing
- 强度 = |价格/SSRP − 1| 归一化（连续）；SSRP 缺失 → 输出全 0

#### 维度7 控盘度（新增，批次3）
- 5/10 日线"通气"（不交叉）天数 & 均线间距：
  - 5/10 日线持续不交叉 ≥ 20 日 → 高控盘 → 佐证 building/lifting（主力在场）
  - 间距收窄交叉频繁 → 低控盘 → 全 0 或轻微佐证 washing
- 强度 = 通气天数/20（连续）

#### 维度8 缠论买点（新增，批次1）
- first_buy/third_buy → building/lifting 支持（强度 0.7）
- first_sell/second_sell → distributing 支持（强度 0.7）
- 无买点 → 输出全 0

### 3.3 加权共识与阶段判定

```
阶段总分(Sᵢ) = Σ( 维度权重 wᵢ × 维度阶段向量[i] )        # 8 维度加权汇总
主力方向 = argmax(Sᵢ)
置信度   = S_max / ΣSᵢ                                # 连续 0-1（替代 5 档）
分歧检测 = (S_max − S_2nd) / ΣSᵢ < 0.15 → phase_conflict = True
```

**分歧处理（决策点3-B）**：
- 仍输出最高分阶段（主判定），标记 `phase_conflict = True`
- 置信度打折：`confidence_final = confidence × 0.6`（分歧降信）
- **用户端可见时必须说明分歧风险**：前端展示时附风险文案，如"⚠️ 信号冲突：建仓(3.8)与出货(3.5)证据接近，方向不明，建议观望/仅做T"
- 输出 `conflict_detail`：两个竞争阶段及其得分，供前端渲染

**unknown 细分**（替代单一 unknown）：
| 细分 | 判定 | 含义 |
|------|------|------|
| `unknown_insufficient` | 核心数据不足（K线<60 日等） | 数据不足，无法判定 |
| `unknown_no_evidence` | 8 维度全部或大部分无证据 | 无明确主力行为证据 |
| `unknown_conflict` | phase_conflict 且主判定置信度过低 | 信号冲突，方向不明 |

## 四、修正维度（条件性投票，决策点4-C）

修正维度**不参与核心共识**，仅在"数据存在且信号明确"时输出一张额外票，计入阶段总分但权重较低（0.5-1.0）：

| 修正维度 | 数据源 | 触发条件 | 投票规则 | 批次 |
|---------|--------|---------|---------|:---:|
| 资金性质 | capital_nature（已算未入，chip_strategy.py:1111） | 标签存在 | institutional → 相关证据置信度 +0.1；hot_money → 阶段强度 ×0.8（短节奏不可靠）；unknown → 不参与 | 1 |
| 融资反向 | margin_cache（19.6 万行 ✅） | 30 日融资余额增幅 >50% 且 20 日涨幅 <5% | 投 distributing 0.6 票（知识库"散户反向"） | 2 |
| 股东户数 | stk_holder_cache（9.6 万行 ✅） | 户数环比变化 >5% | 减少 → 佐证 building（+0.1 置信度）；增加 → 佐证 distributing | 2 |
| 筹码转移 | TradingPhaseDetector 内部 transfer_info（已算） | 转移方向明确 | 向上转移 → 佐证 lifting；向下转移 → 佐证 distributing | 1 |

**原则**：数据缺失 → 该维度不参与（输出全 0），无惩罚；信号不明确 → 不参与。

| 输出 | 类型 | 消费方 |
|------|------|--------|
| `main_force_phase` | 枚举（5 阶段 + unknown 细分） | 下游兼容 ✓；机会类型/画像/L4 |

**与 311 号方案的衔接**：311 §3.1.1 数据通道的 `phase_vote_ratio` 由本方案输出；311 基础层"主力阶段方向×强度"的强度来源 `phase_confidence` 连续化后直接受益，311 v2 验证分布问题同步缓解。

## 八、验证方案

1. **判定分布**：washing 目标 25-35%（现 57.8%）、building 15-25%、unknown 10-20%（含细分）
2. **单源连续性**：ASR 0.16 vs 0.89 强度差异体现；confidence 连续分布（不再 5 档）

5. **下游回归**：L4 共识率分布、311 评分分布（washing 占比下降 → 0 分塌陷缓解）
