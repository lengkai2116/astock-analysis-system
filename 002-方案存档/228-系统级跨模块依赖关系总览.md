## 四、模块间数据流

```
写入方向:  A → B  表示 A 写入数据到 B
读取方向:  A ← B  表示 A 从 B 读取数据

indicator-ide (个股策略)
  ├── 加入复盘池 → playback (复盘中心)
  ├── 实操参考信号 → backtest (回测系统)
  └── 设为监控条件 → alert (监控通知)

playback (复盘中心)
  ├── 报告存档 → reports-center (报告中心)
  └── RV-xxx诊断 → account (账户管理六维复盘)

strategy-templates (策略模板)
  ├── 系统策略列表 → screener (选股系统 L3)
  ├── 用户策略CRUD → sandbox (策略沙箱 策略选择)
  └── 报告存档 → reports-center

factor-manager (因子管理)
  └── 因子组合列表 → screener (选股系统 L3) ★硬约束

backtest (回测系统)
  ├── 参数优化结果 → strategy-templates (参数快照)
  └── 回测报告 → reports-center

sandbox (策略沙箱)
  └── 测试报告 → reports-center

account (账户管理)
  └── 存档报告 → reports-center

alert (监控通知)
  ├── 触发通知 → 桌面/WxPusher (外部)
  └── 跳转详情 → indicator-ide / screener / watchlist
```

## 五、开发阶段注意点

| 先后依赖 | 说明 |
|:---------|:------|
| 策略引擎 → 所有消费端 | 策略引擎（缠论/量价/筹码等）必须先就绪或至少提供Mock接口，选股系统/个股策略/自选监控才能接入真实数据 |
| 因子管理 → 选股系统 L3 | **硬约束**：选股系统L3的因子组合列表必须从因子管理页动态同步，禁止硬编码 |
| 回测引擎 → 策略沙箱 | 策略沙箱的单策略信号生成应复用回测引擎的信号模块，而非独立实现 |
| 报告中心 → 上游 5 模块 | 报告中心是下游消费端，上游 5 个模块（策略模板/回测/沙箱/复盘/账户）在实现了报告存档功能后，再对接报告中心的写入口 |
| 复盘中心 → 账户管理 | review-link 功能需要复盘中心诊断就绪后，账户管理才能获取 RV-xxx 结论 |
| DuckDB 缓存 → 全站 | 所有模块依赖 Tushare 数据管道（DuckDB 缓存），这是前置基础设施 |
