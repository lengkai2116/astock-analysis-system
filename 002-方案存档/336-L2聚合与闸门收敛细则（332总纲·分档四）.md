# 336 — L2 聚合与闸门收敛细则

> **分档定位**：332 号总纲（现状判定引擎统一方案 v3.0）的**分档四**，聚焦总纲 §5.3（L2 聚合判定层——统一共识/冲突暴露/降级链）与 §5.5（闸门体系收敛性影响——闸门2/3 吸收、共识阈值重校、颜色保守化）。
>
> **讨论背景（08-15，沟通纪要 004）**：组3 讨论确认——共识从"14 标签等权投票"改为"10 维度独立判定后计票"，是与知识库 UIDF 维度分层流程一致的正确方向；可入场门槛对齐知识库《多指标共识机制》≥2/3（67%）；conflict_evidence 符合知识库"不要追求完美一致、暴露矛盾"哲学，扩展"缺失证据"类；快照字段来源同步到 L1/L2 输出；颜色保守化取舍确认。
>
> 本方案仅存档细则，不修改任何代码（落地随 332 号 S1/S2/S3）。

## 一、决策依据（LLM Wiki 知识库）

| 知识库文档 | 主张 | 落地 |
|---|---|---|
| 《信号冲突处理机制》 | **共识计数**：指标归一化（+1/0/-1），≥2/3 方向一致才执行交易 | 维度归一化计票 + 可入场门槛 67% |
| 《信号冲突处理机制》 | **多智能体**：风控智能体最高优先级，可直接否决 | 否决一票降级不被稀释（闸门2/L0，335 号已定） |
| 《信号冲突处理机制》 | **"不要追求完美一致"**：市场几乎不存在全维度共振，框架使命是在矛盾中做最优选择 | conflict_evidence 暴露矛盾（已有）+ 消灭 603897 虚假 100% 共识 |
| 《信号冲突处理机制》 | **"少即是多"**：信号过滤能力比信号生成能力更重要 | 可入场门槛从严（55%→67%） |
| 《统一投资决策框架（UIDF）》 | 统一决策流程 = 顶层观测→走势定位→结构量化→因子校验→风控（**维度分层校验**） | 共识=维度级推导（非标签等权投票） |

## 二、共识口径切换（C1 核心）：L4 标签投票 → L1 维度推导

### 2.1 现状（必须替换的口径分裂源）

| 口径 | 位置 | 用途 | 问题 |
|---|---|---|---|
| L4 标签投票（VOTE_MAP 14 票源） | cross_validate._compute_consensus / data_daemon._compute_snapshot_consensus_rate | 弹窗摘要 + 快照 consensus_rate | 票源不同质（位置/阶段/形态语义混投）、技术面同质重复放大、603897 虚假 100% |
| 五维方向推导 | advice_builder._approximate_consensus | 个股页建议卡 | 与弹窗口径不一致（603897：100% vs 67%） |

### 2.2 新口径：L1 维度状态归一化计票

**每维方向映射表**（334 号 L1 十维状态 → +1/0/-1，语义对齐 VOTE_MAP 口径——中性不稀释方向共识）：

| 维度 | +1（看多） | 0（中性） | -1（看空） |
|---|---|---|---|
| 估值 | 低估 | 合理 | 高估 |
| 结构 | 上升 | 盘整 | 下降 |
| 位置 | 站上防守位 | 中位 | 跌破 |
| 筹码资金 | 流入 | 中性 | 流出 |
| 情绪 | 复苏 | 正常 | 退潮/高潮 |
| 财务 | 健康 | 关注 | 风险 |
| 事件 | 正向 | 中性 | 负面 |
| 时间 | 初期 | 中期 | 已延伸 |
| 风险 | 低 | 中 | 高 |
| 因子（校验维） | 看多 | 中性 | 看空 |

**共识率公式**（与 L4 同口径）：`共识率 = 优势方向维度加权数 / 方向维度总数`（中性不稀释；全中性→0；多空打平→tie 标记）。

**说明**：
- "九维共识"实为 **10 维计票**（含因子校验维，334 号已定因子参与共识）；展示可称"九维+因子辅助"
- 消双口径：弹窗摘要/个股页/快照全部读同一 L2 输出共识（332 §5.4 成品仓唯一消费）

## 三、阈值重校（C1）：对齐知识库 ≥2/3

### 3.1 阈值对照表

| 阈值 | 现状（硬编码） | 新值（初值） | 依据 |
|---|---|---|---|
| arbiter `_BULLISH_ENTER`（P6 可入场） | 0.55 | **0.67** | 知识库 ≥2/3 才执行交易 |
| arbiter `_BEARISH_STRONG`（P3 强看空） | 0.65 | **0.67** | 对齐 2/3（对称） |
| 前端深蓝（高共识） | ≥0.70 | ≥0.70（初值保留） | 待九维分布校准 |
| 前端浅蓝（可入场下限） | 0.55-0.70 | **0.67-0.70** | 门槛对齐 67% 后浅蓝下限同步上移 |
| 0.50-0.67 区间 | —（浅蓝） | 降为"方向可信度待确认"（wait/light 语义 + 边框提示，313 §6.5 沿用） | 少即是多 |

### 3.2 校准流程（复用 334 号阈值管理机制）

- **初值**：上表（知识库推导，先跑起来）
- **正式定标**：九维共识上线后，用 `daily_cache` 离线重放 + `signal_records` 在线积累，统计全市场九维共识分布 → 深蓝/浅蓝分位点校准（P80=深蓝、P50-P80=浅蓝 之类），方法同 334 号校准脚本（`scripts/calibrate_signal_thresholds.py` 扩展共识校准）
- **配置载体**：`config/status_engine.yaml`（§七）

## 六、颜色保守化确认（C2，产品取舍）

**确认**（用户同意 332 §5.5 方向）：L2 纪律降级（盈亏比门禁/硬约束/共识门槛 67%）会让部分"强确认+高共识"股从可入场降为 wait、地图颜色变保守——**接受"三处结论一致优先于颜色激进"**（知识库"少即是多/过滤优先"支持）。

**预期影响管理**：
- 门槛 55%→67% 后，可入场股数量下降（部分"半确认"降为 wait/light）
- 弹窗/地图/个股页三处口径完全一致（603897 差异#1 根治）
- 图例/分享文案同步说明（S3）

## 七、系统配置细节（新增 status_engine.yaml）

**配置载体**：`config/status_engine.yaml`（与 334 号 `signal_registry.yaml` 并列，均为 status_engine 的配置；版本化可回滚，复用 334 号阈值管理机制）

```yaml
# config/status_engine.yaml（草案 v1，初值）
version: 1
consensus:
  enter_threshold: 0.67        # 可入场门槛（知识库 ≥2/3）
  bearish_strong: 0.67         # 强看空 → avoid
  color_high: 0.70             # 深蓝（高共识），待分布校准
  color_low: 0.67              # 浅蓝下限（低于 → wait/轻仓语义）
  neutral_is_zero: true        # 中性维度不稀释共识（口径与 L4 一致）
dimension_weights:             # 预留维度权重（知识库"融合优于仲裁"提示，默认等权）
  valuation: 1.0
  structure: 1.0
  position: 1.0
  chip_fund: 1.0
  emotion: 1.0
  finance: 1.0
  event: 1.0
  time: 1.0
  risk: 1.0
  factor: 1.0                  # 因子校验维
conflict_rules:
  enabled: true
  rules: [trend_vs_multi, high_profit_no_flow, distributing_vs_confirm, risk_high_vs_confirm,
          high_profit_no_presence, deep_valuation_confirm]   # 6 条（文案模板同文件维护）
```

**说明**：
- `dimension_weights` 预留但**默认等权**（知识库"先简单后复杂"；等权可解释性好）
- 阈值变更走版本化流程（改 yaml → version+1 → 可回滚），不硬编码
- arbiter 阈值（现状硬编码 `_BEARISH_STRONG/_BULLISH_ENTER`）迁移为从 yaml 读取（S2 实施）
