# 自选监控与操作建议系统设计

## 一、定位

自选是用户的"家"。用户在机会图谱（Treemap）中发现感兴趣股票→手动加入自选→在自选页面持续跟踪。**入库是用户决策，系统不自动替用户入库**，但系统提供两重发现辅助：

1. **自选看板**：已入库股票的全维度日常监控（盘中实时数据 + 日频标签变化）
2. **机会雷达**：非自选股中今日触发关键信号的个股轮播展示，供用户发现

自选与机会图谱的价值区隔：

| 维度 | 机会图谱（Treemap） | 自选监控（看板） | 机会雷达 |
|------|-------------------|----------------|---------|
| 用户问题 | "今天市场哪里有机会？" | "我关注的股票今天怎么样了？" | "今天有没有我漏掉的信号？" |
| 股票范围 | 全市场 4800 只 | 用户自选 20-200 只 | 非自选中有信号者 |
| 用户行为 | 浏览→发现 | 跟踪→操作 | 扫一眼→按需加入 |
| 数据深度 | 当日全量标签 | 盘中实时 + 日频变化 diff | 仅触发信号摘要 |
| 更新频率 | 盘前全量刷新，盘中实时涨跌幅 | 5s 实时 + 盘前标签 diff | 盘中实时 + 盘前 diff |
| 持久化 | 否（用完即走） | 是（持续跟踪） | 否（过期消失） |

## 二、自选分级

| 等级 | 标识 | 含义 | 入/出库规则 |
|:----:|:----:|------|------------|
| ⭐⭐⭐ 核心持仓 | core | 已建仓，主动管理 | **仅用户手动标记** / 从 watch 升级 |
| ⭐⭐ 重点观察 | watch | 待决策，紧密跟踪 | **用户手动加入** 或 scan 自动升级（signal_strength > 6.0 持续 3 日 + phase_confidence > 0.6）|
| ⭐ 潜力扫描 | scan | 新发现，积累数据 | **仅用户手动加入**（从 Treemap/机会雷达点击"加入自选"）|
| 📉 暂存监控 | park | 短期不关注但保留后台监控 | **用户手动操作**"暂存监控"移入；自动唤醒后升回 scan |
| 历史记录 | done | 已出库，保留数据 | 用户手动删除 / 用户手动从 park 移入 |

**等级流转规则**：

```
用户从 Treemap/雷达加入 → scan
  ├── signal_strength > 6.0 持续3日 + phase_confidence > 0.6 → 自动升为 watch
  └── 用户手动 → watch
watch ── 用户手动标记 → core
watch/scan ── 用户点击"暂存监控" → park
park ── 5维后台监控触发任一唤醒条件 → 自动升回 scan + 推送"唤醒通知"
scan/watch/core ── 用户点击"删除" → done
```

### park 暂存级的定位

`park` 不是折叠隐藏，而是**降维监控 + 卡片色驱动注意唤醒**：

- 展示位置：自选看板底部独立的 park 卡片条（非折叠区，始终可见）
- 监控力度：仅 5 个精选信号维度（估值/主力/催化剂/信号强度/财务）
- 外观：灰色无变化卡片。有积极信号 → 绿色边框；有消极信号 → 红色边框
- 用户操作：单击卡片查看信号详情 → 选择"恢复跟踪"（升回 scan）或"删除"（进入 done）
- 不推送远程通知，仅看板内卡片颜色变化驱动用户注意

**park 唤醒条件**（任一触发即自动升回 scan）：

```
1. valuation_level → low/extreme_low                     "估值已进入低估区间"
2. main_force_phase → building                           "主力开始建仓"
3. catalyst_event → 从 none 变为有效值                    "出现催化剂事件"
4. signal_strength 从 park入库点起上升 > 2.0              "信号强度显著回升"
5. fina_health → 从 pass 变为 fail（消极唤醒，告知风险）    "财务风险变化"
```

## 三、数据库设计

```sql
CREATE TABLE opportunity_library (
    ts_code TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    category TEXT,
    pipeline TEXT,
    lib_level TEXT DEFAULT 'scan',    -- core / watch / scan / park / done
    added_date TEXT,
    added_reason TEXT,
    last_update TEXT,
    status TEXT,
    days_in_status INTEGER,
    total_days INTEGER,
    manual_keep INTEGER DEFAULT 0,
    is_active INTEGER DEFAULT 1,
    park_trigger_count INTEGER DEFAULT 0,    -- park 模式下信号触发次数
    park_last_signal TEXT,                   -- park 触发的最后一个信号摘要
    park_entered_signal REAL,                -- park 入库时的 signal_strength（用于唤醒条件4的差值计算）
    -- 分层评分（基础引擎分不变，Factor/Vibe 加成可变）
    base_value_score REAL,
    base_trend_score REAL,
    base_event_score REAL,
    base_technical_score REAL,
    factor_boost REAL,
    vibe_boost REAL,
    composite_score REAL,
    factor_vibe_version TEXT
);

CREATE TABLE opportunity_status_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts_code TEXT NOT NULL,
    date TEXT NOT NULL,
    old_status TEXT,
    new_status TEXT,
    trigger_event TEXT,
    score REAL,
    detail TEXT
);

CREATE TABLE opportunity_advice_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts_code TEXT NOT NULL,
    date TEXT NOT NULL,
    advice_type TEXT,        -- build / add / hold / t0 / reduce / stop / observe
    target_price REAL,
    stop_loss REAL,
    reason TEXT
);
```

## 四、操作建议类型

| 操作 | 含义 | 适用场景 |
|------|------|---------|
| 建仓 | 建议开始买入 | 新发现，信号确认 |
| 加仓 | 建议增加仓位 | 信号增强 |
| 持有 | 建议不动 | 逻辑未变 |
| 做T | 利用波动降成本 | 标的优质但波动大 |
| 减仓 | 建议降低仓位 | 目标接近或风险上升 |
| 止损 | 建议清仓退出 | 条件被破坏 |
| 观察 | 暂时不做操作 | 信息不充分 |

> 操作建议由 L4 仲裁层多通道合并产出：估值跟踪通道（估值止盈/减仓）+ 事件评分通道（事件-仓位联动）+ 共识投票引擎（12标签投票+情绪加权+估值退出）。三通道最终汇合为一个统一的 `advice_today`。详见 300号 §2。

## 五、自选变更监控与推送

### 5.1 变更检测归属

变更检测（当日标签 vs 上日标签的比较）由 **L4 仲裁层**统一执行，不在自选系统（299号）或 notifier（P2.4）中独立做——因为 L4 已经读取了全量标签用于仲裁规则，内存中做 diff 不需要额外 IO。

L4 仲裁层输出 `daily_change_summary` 结构体，自选看板消费展示。详见 300号 §2.3。

### 5.2 自选监控八维度

| # | 监控项 | 标签名 | 变化检测 | 比较规则 |
|:-:|--------|--------|---------|---------|
| 1 | 主力阶段 | `main_force_phase` | 值变化（5种阶段切换） | 任意变化即标记 |
| 2 | 估值定位 | `valuation_level` | 5档区间切换 | 任意变化即标记 |
| 3 | 趋势方向 | `trend_alignment` | 方向反转（up↔down） | up→down 或 down→up 标记 |
| 4 | 资金流向 | `fund_flow` | 方向反转（inflow↔outflow） | 流入↔流出标记 |
| 5 | 主力可信度 | `phase_confidence` | 连续差值 | ±0.2 以上标记 |
| 6 | 催化剂 | `catalyst_event` | 有/无切换 | none→有值 或 反之标记 |
| 7 | 财务健康 | `fina_health` | 健康度变化 | 从 pass→非 pass 标记 |
| 8 | 综合信号 | `signal_strength` | 差值 | ±1.0 以上标记 |

### 5.3 推送分级

同一只股票在同一个批处理批次中如有多个维度变化，合并为一条聚合通知。

| 推送级别 | 触发条件 | 展示方式 |
|:--------:|---------|---------|
| 🔴 紧急 | fina_health→fail / valuation_level→extreme_high | 弹窗 + 看板置顶 |
| 🟡 重要 | main_force_phase 切换 / catalyst_event 新增 | 看板置顶 + 角标 |
| 🔵 常规 | signal_strength ±1.0 / trend_alignment 切换 | 看板卡片标注 |

## 六、输出标签

| 标签名 | 取值 | 说明 |
|--------|------|------|
| `in_library` | `core` / `watch` / `scan` / `park` / `done` / `none` | 股票在自选中的等级。none=不在自选 |
| `advice_today` | `build` / `add` / `hold` / `t0` / `reduce` / `stop` / `observe` | 今日操作建议 |

## 七、自选看板

### 7.1 顶部概览仪表盘

用户在自选看板顶部第一眼看到的全量自选整体概览：

```
┌─ 我的自选仪表盘 ─────────────────────────────────────────────────┐
│                                                                   │
│  全部 28 只  │  core(3) │ watch(7) │ scan(12) │ park(6) │ done(2)│
│  ─────────────────────────────────────────────────────────────── │
│  🟢 上涨 15  │  🔴 下跌 10  │  ⚪ 平盘 3                           │
│  平均涨跌幅: +0.87%  │  今日有变化: 8只 🔔  │  待办日程: 3项      │
│                                                                   │
│  ⚡ 今日重点关注                                                    │
│  ├── 西藏矿业: 主力阶段 建仓→洗盘〔第1日〕建议: 持有             │
│  ├── 平安银行: 估值 fair→low〔进入低估区〕建议: 关注建仓          │
│  └── 中公教育: fina_health pass→suspicious ⚠️ 建议: 检查         │
└───────────────────────────────────────────────────────────────────┘
```

仪表盘数据来源：`opportunity_library`（总数/分级） + `daily_change_summary`（变化/重点关注）+ L1 实时（涨跌分布）。

### 7.2 三大操作区块

#### 区块一：今日操作榜

按 urgency 降序列出今日有操作建议的标的（止损 > 减仓 > 建仓 > 做T > 加仓 > 观察）。如无操作建议的标的，此区域不展示。

```
┌─ 今日操作 ────────────────────────────────────────────┐
│  🔴 止损  中公教育   财务 health→fail                 │
│  🟢 建仓  平安银行   估值偏低+资金流入                 │
│  🔵 做T   西藏矿业   洗盘期，波动方差2.5%              │
└─────────────────────────────────────────────────────┘
```

#### 区块二：待办事件日历

来自 300号 `event_calendar_upcoming`，仅展示自选库内标的的未来 30 日预判事件。

```
┌─ 待办日程 ────────────────────────────────────────────┐
│  7/28 赣锋锂业  中报披露（关注超预期）                 │
│  7/29 西藏矿业  碳酸锂价格数据公布                     │
│  8/05 平安银行  分红除权除息日                         │
└─────────────────────────────────────────────────────┘
```

#### 区块三：持仓总览

按 core / watch / scan 分组展示，每只股票一张独立卡片。

### 7.3 个股卡片设计

每只自选股对应一张卡片，分两个数据维度：

```
┌─ 西藏矿业 000762.SZ ──── scan ──── 18天 ──────────────────┐
│                                                             │
│  📊 盘中实时 (Part A)               🔄 今日变化 (Part B)    │
│  28.50  ▲ +2.35%                   主力: building→washing  │
│  成交 3.2亿  换手 3.2%             信号: 7.5→5.8（↓1.7）  │
│  板块: 有色金属 ▲ +1.8%            催化剂: 无（消失）       │
│  大单净额 +1200万                                           │
│                                                             │
│  今日建议: 持有不动（洗盘期，预计5-15日）                    │
│                                                             │
│  [📋 诊断] [📈 策略] [🤖 AI]  [🔝 升级] [📉 暂存] [🗑️]  │
└─────────────────────────────────────────────────────────────┘
```

**Part A — 盘中实时数据**（5s 更新）：
- 现价 + 涨跌幅（颜色绿涨红跌）
- 成交额 + 换手率
- 所属板块 + 板块涨跌幅
- 大单净额（盘中估算）

**Part B — 日频监控变化**（盘前一次计算）：
- 只展示当日有变化的维度（无变化不展示）
- 最多排列 3-4 个标签
- 来源：L4 仲裁层产出的 `daily_change_summary`

**底部操作栏**：

| 按钮 | 触发动作 | 关联系统 |
|------|---------|---------|
| 📋 诊断 | 弹出 L4 完整诊断弹窗（同 Treemap 点击弹窗） | 300号 §2.4 |
| 📈 策略 | 跳转到个股策略分析页面（K线+五维） | 已有 route |
| 🤖 AI | 跳转到 AI 多角色投研页面 | 已有 route |
| 🔝 升级 | scan→watch / watch→core（用户手动）| 自选系统自身 |
| 📉 暂存 | 当前等级→park（进入后台降级监控） | 自选系统自身 |
| 🗑️ 删除 | → done（完全删除） | 自选系统自身 |

### 7.4 暂存（park）卡片条

位于看板底部，非折叠区，始终可见：

```
┌─ 暂存监控 ───────────────────────────────────────────────────────┐
│                                                                   │
│  ⬜ 中公教育    🟢 赣锋锂业    ⬜ 贵州茅台    🔴 宁德时代        │
│  [7/28 无变化]  [7/28 估值→低] [7/28 无变化]  [7/28 主力→出货] │
│                                                                   │
│  单击卡片查看变化详情 · 双击恢复为 scan                            │
└───────────────────────────────────────────────────────────────────┘
```

| 卡片边框 | 含义 |
|:--------:|------|
| ⬜ 灰色 | 无变化或中性信号 |
| 🟢 绿色 | 积极信号触发（building/低估/催化剂） |
| 🔴 红色 | 消极信号触发（distributing/财务异常） |

## 八、机会雷达

### 8.1 定位

机会雷达是**系统发现层**——检测全市场非自选股中触发关键信号的个股，以水平轮播条的形式展示在自选看板顶部或 Treemap 侧边。它不要求用户决策，不作为持久化数据存储，纯粹供用户"扫一眼看看今天有什么漏掉的"。

### 8.2 触发条件

非自选股满足以下任一条件即进入雷达：

```
1. main_force_phase → building（建仓信号最高优先级）
2. valuation_level → low/extreme_low（进入低估区间）
3. catalyst_event → 从 none 变为有效值（出现催化剂事件）
4. signal_strength 单日上升 > 1.5（信号强度跳升）
5. phase_confidence > 0.8 且连续 3 日上升（信号趋于稳定）
```

每日触发数量通常 10-30 只。

### 8.3 展示形式

```
┌─ 机会雷达 ──────────────────────────────────────────────────────┐
│                                                                   │
│  [东方财富 300059]    [药明康德 603259]    [天齐锂业 002466]     │
│   主力→建仓 ⭐          估值→低估 💎          催化剂→业绩预告⚡   │
│   信号强度 7.2          信号强度 6.8          信号强度 6.5       │
│  [➕ 加入自选]          [➕ 加入自选]          [➕ 加入自选]       │
│                                                                   │
│              ← 滑动查看更多（共12只今日信号）→                    │
└───────────────────────────────────────────────────────────────────┘
```

每张卡片只突出 **最重要的那个信号**（一个事件类型图标 + 一条文字摘要），右侧一个"➕ 加入自选"按钮。点击加入自动入库（默认 level = scan）。

### 8.4 数据来源

直接从 `opportunity_tags_cache` 读取非自选股（不在 `opportunity_library` 表中的股票）的当日标签，应用 5 条触发条件过滤。不需要新建数据表或采集任务。

## 九、自选与机会图谱的流程机制

### 9.1 数据传导链路

```
1. 全市场 L2 标注（P0.4）产出 opportunity_tags_cache
   │
2. 机会图谱 Treemap API（P1.4）从 opportunity_tags_cache 读取
   │ 用户点击"加入自选" → POST /api/v3/opportunity-atlas/library
   │
3. 标的库 CRUD API（P1.2）写入 opportunity_library 表（lib_level = scan）
   │
4. L4 仲裁层（P2.2）读取自选库内股票的当日标签
   │ 与上日比较 → 产出 daily_change_summary
   │ 执行仲裁规则 → 产出 operation_advice
   │ 写入 opportunity_advice_history
   │
5. 状态变更通知（P2.4）读取 daily_change_summary
   │ 判断推送级别 → 推送到前端
   │
6. 自选看板（L5）展示顶部仪表盘 + 三大区块 + 个股卡片
   │
7. 机会雷达（P2.4）读取非自选股的 opportunity_tags_cache
     过滤触发条件 → 水平轮播条展示
```

### 9.2 两板块功能区隔

| 维度 | 机会图谱（Treemap） | 自选监控（看板） |
|------|-------------------|----------------|
| 用户场景 | "今天哪里有机会？" | "我关注的那些怎么样了？" |
| 数据范围 | 全市场 4800 只 | 自选库 20-200 只 |
| 交互深度 | 浏览→发现→加自选 | 看变化→读建议→做操作 |
| 更新节奏 | 盘前全量，盘中实时色 | 5s实时+盘前diff+事件实时 |
| 卡片展示 | 行业分组下的方块 | 按等级分组的完整卡片 |
| 生命周期 | 用完即走 | 持续跟踪 |

### 9.3 用户互动模块

自选看板中每只个股卡片底部操作栏的 6 个按钮，关联系统已有的功能模块：

| 按钮 | 关联系统 | 数据来源 |
|------|---------|---------|
| 📋 诊断 | 300号 L4 交叉验证仲裁 | 诊断输出 JSON |
| 📈 策略 | 现有 route `strategy_analyze.py` | 五维策略分析 |
| 🤖 AI | 现有 route `ai_analysis.py` | AI 多角色投研 |
| 🔝 升级 | 自选系统（简单 CRUD） | opportunity_library |
| 📉 暂存 | 自选系统（park 模式下写入）| opportunity_library |
| 🗑️ 删除 | 自选系统（简单 CRUD） | opportunity_library |

所有 6 个按钮均指向已有或本轮方案中已规划的功能，无须新建独立模块。
