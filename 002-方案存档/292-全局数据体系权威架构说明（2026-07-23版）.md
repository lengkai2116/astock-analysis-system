## 第一部分：总览

### 1.1 架构图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           data_daemon 数据采集进程                            │
│                                                                             │
│  ┌─ 实时采集 ────────────────────────────────────────────────────────────┐  │
│  │  Thread 1: 快照采集 (5s)                                               │  │
│  │    ├─ 主源: 东财 HTTP API  (push2.eastmoney.com)  ← 当前活动源          │  │
│  │    ├─ 备源: 新浪 HTTP API  (hq.sinajs.cn)                              │  │
│  │    └─ 备源: 腾讯 HTTP API  (qt.gtimg.cn)                               │  │
│  │  Thread 2: 板块+涨跌停池 (30min)  ← AKShare                             │  │
│  │  Thread 3: 分钟K线 (5min)        ← mootdx minute() / AKShare           │  │
│  │  Thread 4: 龙虎榜+舆情 (30min)    ← AKShare / Tushare                   │  │
│  │  Thread 5: 情绪池 (30min)        ← AKShare                              │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  ┌─ 定时任务 ────────────────────────────────────────────────────────────┐  │
│  │  15:30  日终批量同步 (Tushare 全市场 API, 8类 × 1次/类)                 │  │
│  │  15:35  指标预计算 → 因子预计算 → 策略信号预计算 (后台线程)              │  │
│  │  整点   非交易时段完整性巡检 (backfill_days=1)                           │  │
│  │  30s    轮询 sync_requests 队列消费                                      │  │
│  │  开盘   开机自检(P6): 预计算完整性检查 + 自选股增量触发                   │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  ┌─ 数据源管理层 (DataSourceManager) ─────────────────────────────────────┐  │
│  │  ├─ 健康评分引擎: 每周期自动评分 (null率/值范围/Schema一致性)           │  │
│  │  ├─ 自动降级链: 东财 → 新浪 → 腾讯 → 缓存                              │  │
│  │  ├─ Schema变更感知: 自动检测API响应结构变化                             │  │
│  │  └─ 配置热加载: YAML变更1s内生效(ConfigWatcher)                         │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                               ↓                                            │
│                    InMemoryStateStore (盘中实时)                            │
│                    ECM SQLite WAL (盘后持久化)                              │
│                               ↓                                            │
│  ┌─ API 进程 (run.py) ─────────────────────────────────────────────────┐  │
│  │  Flask REST :5001                                                    │  │
│  │  SocketIO WebSocket                                                   │  │
│  │  DataManager(只读存储层) + TieredMemoryCache(方法级缓存)               │  │

│  │  ** 所有数据读取只走 DataManager 网关，不直调数据源 **                  │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 数据流路径

```
采集层 → 存储层 → 计算层(数据计算) → 存储层 → 调用层 → 前端     [标准路径]
采集层 → 存储层 → 调用层 → 前端                             [原始数据无需计算]
采集层 → 存储层 → 计算层(策略核算,用户触发) → 返回前端       [策略分析路径]
调用层 → sync_requests → 采集层 → 存储层 → 调用层            [数据缺失补采路径]
```

### 1.3 进程分工

| 进程 | 文件 | 职责 | 启动方式 | 资源 |
|------|------|------|---------|------|
| **数据进程** | `backend/data_daemon.py` | 实时采集、日终同步、完整性检查、预计算、sync_requests消费 | launchd 开机自启，后台静默运行 | ~50MB |
| **API 进程** | `backend/run.py` | Flask REST API、SocketIO 推送、前端SPA托管 | `start.command` 手动启动 + 打开浏览器 | ~200MB |

## 第二部分：四层架构红线标准

### 2.1 四层定义

```
┌─────────────────────────────────────────────────────────────┐
│ 采集层 (Collection Layer)                                    │
│   代码位置: backend/data_daemon.py + backend/app/data/       │
│   进程: data_daemon (独立进程)                                │
│   职责: 从外部数据源获取原始数据，写入存储层                    │
│   约束: 不关心谁消费数据，只做采集+写入                         │
│   数据源: 东财HTTP / 新浪HTTP / Tushare / AKShare / mootdx   │
│                                                             │
│   采集频率由 data_daemon 主循环统一管理                       │
│   禁止在 API 进程中触发任何采集操作                            │
│                                                             │
│ 存储层 (Storage Layer)                                       │
│   入口: DataManager (data/__init__.py) — 唯一数据访问网关     │
│   组件: ECM SQLite WAL (盘后) + InMemoryStateStore (盘中)     │
│         + TieredMemoryCache (方法级TTL缓存)                   │
│   约束: 采集层写、计算层读写、调用层只读                        │
│                                                             │
│ 计算层 (Computation Layer)                                   │
│   入口: data_daemon 后台线程                                  │
│   类型1: 数据计算 — 数据到达时自动触发 (MA/MACD/RSI/分钟聚合) │
│   类型2: 策略核算 — 用户触发执行 (缠论/量价/筹码策略分析)      │
│   约束: 只读存储层，不得直连数据源                              │
│                                                             │
│ 调用层 (Call Layer)                                          │
│   代码位置: backend/app/routes/ + backend/app/services/      │
│   职责: 接收前端请求，从存储层读取数据返回                      │
│   约束: 只读存储层，不得直调数据源，不得 use_cache=False       │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 红线规则

**红线 1** — 所有非采集层代码禁止实例化数据源 Provider：
```python
# ❌ 禁止
TushareProvider()
AkshareProvider()
mootdx.Quotes.factory()
```

**红线 2** — 禁止调用 `DataManager.sync_*()` 系列方法（`sync_daily_data`、`sync_stock_list`、`sync_all_daily_data` 等）

**红线 3** — 禁止 `use_cache=False` 参数出现在非采集层代码中

**红线 4** — API 路由中禁止实时计算技术指标。策略核算可按用户操作触发

**红线 5** — 所有数据读取必经 DataManager 只读方法（`get_*`），禁止绕过

**红线 6** — 禁止使用 Mock/随机数据作为数据降级方案

**红线 7** — 分钟K线数据必须持久化到 `minute_kline_cache` 表，禁止直调不落缓存

**红线 8** — 数据缺失时禁止直调数据源降级，必须走 `sync_requests` 异步队列

### 2.3 sync_requests 数据就绪保障机制

```
调用层发现数据缺失
  → DataManager.request_data(task_type, ts_code?)
  → 写入 SQLite sync_requests 表 (status='pending')
  → 返回空结果 / HTTP 503
  → data_daemon 30s 轮询消费
  → 批量同步 (全市场API, 非逐只)
  → 写入存储层 + 标记 status='done'
  → 计算层自动触发预计算
  → 调用层下次请求命中缓存
```

| task_type | 触发的采集函数 | 说明 |
|-----------|---------------|------|
| `full_daily` | `_batch_daily` + `_batch_daily_basic` | 全市场日线+基本面 |
| `full_moneyflow` | `_batch_moneyflow` | 全市场资金流向 |
| `full_basic` | `_batch_daily_basic` | 全市场基本面 |
| `full_stock_list` | `_batch_stock_list` | 股票列表 |
| `per_stock` | `_batch_daily` + 数据补采请求 | 单只股票数据 |
| `adj_factor` | `_batch_adj_factor` | 复权因子 |
| `top10_holders` | `_batch_top10_holders` | 前十大股东 |
| `stk_holder` | `_batch_stk_holder` | 股东人数 |
| `finance_report` | `_batch_finance_report` | 扩展财务 |
| `margin` | `_batch_margin` | 融资融券 |
| `concept` | `_batch_concept` | 概念板块 |
| `precompute_strategy` | `_precompute_single` | 单只策略预计算 |

### 3.1 实时行情数据源（5s 快照）

#### 主源：东方财富 HTTP API

| 端点 | 方法 | 参数 |
|------|------|------|
| `https://push2.eastmoney.com/api/qt/ulist.np/get` | GET | `fltt=2`, `fields=f2,f3,f4,f5,f6,f7,f8,f9,f10,f12,f14,f15,f16,f17,f18,f20,f21,f37,f38,f39,f40,f41,f45,f46,f48,f50,f57,f58,f60,f61,f62`, `secids=市场.代码` |

- **批量大小**：60只/请求，URL 长度可控
- **并行度**：4~8 线程，全市场 5000 只约 2.6~5.2s
- **字段缩放**：`fltt=2` 返回正确缩放的值（价格直接可用）
- **状态**：✅ 200次连续测试100%成功率，P95=97ms
- **覆盖**：🟡 批量端点不含五档盘口（个股五档走新浪）

**字段映射（东财 → 内部列名）：**

|--------|-----------|------|
| f2 | price | 最新价 |
| f3 | change_pct | 涨跌幅% |
| f4 | change | 涨跌额 |
| f5 | volume | 成交量(手) |
| f6 | amount | 成交额 |
| f7 | amplitude | 振幅% |
| f8 | turnover_rate | 换手率% |
| f10 | volume_ratio | 量比 |

#### 备源：新浪 HTTP API

```
GET http://hq.sinajs.cn/list=sh600036,sz000001
```

- CSV 格式，按索引位置解析
- 字段[3]=最新价, [4]=最高, [5]=最低
- 字段[10-19]=买五档(vol/price交替), [20-29]=卖五档(vol/price交替)
- 支持五档盘口（全市场快照不需要，个股详情按需查）
- 时效性：与东财完全一致

#### 备源：腾讯 HTTP API

```
GET http://qt.gtimg.cn/q=sh600036,sz000001
```

- `~` 分隔的 CSV，字段丰富
- 含五档盘口字段[7-26]
- 偶有 ~2s 延迟

#### 降级链策略

```
正常状态: 东财(评分>0.9) → 新浪 → 腾讯 → 缓存
降级状态: 新浪(评分0.5~0.9) → 腾讯 → 缓存
紧急状态: 缓存(评分<0.5) → 空DataFrame(前端显示数据延迟)
```

自动降级依据 HealthScorer 每周期评分：
- **评分 0.9~1.0**：正常，继续使用当前源
- **评分 0.6~0.9**：有异常但可用，记录日志
- **评分 < 0.6**：自动切换备源+告警

## 第四部分：存储层

### 4.1 ECM SQLite WAL（盘后持久化）

**文件位置**：`$DATA_DIR/duckdb/stock_cache.db`

| 配置 | 值 | 说明 |
|------|----|------|
| 引擎 | SQLite WAL 模式 | 0依赖，写不阻塞读 |
| 连接池 | 单连接 + 写锁 | `_write_lock` 串行化写入 |
| busy_timeout | 5000ms | 等待 5s 而非立刻报错 |
| cache_size | 8MB | |

**快照独立数据库**：`market_snapshot.db` — 独立的 SQLite WAL 数据库，与缓存库物理隔离（写入锁竞争、故障隔离、文件大小管理）

**表结构规范**：所有持久表遵循 `{data_type}_cache` 命名模式。

### 4.2 InMemoryStateStore（盘中实时）

```
内存数据结构:
  _snapshot: Dict[str, Dict]      # 全市场快照（覆盖式）, {ts_code: {field: value}}
  _sectors: List[Dict]            # 板块排行（覆盖式）
  _concepts: List[Dict]           # 概念排行（覆盖式）
  _top_stocks: Dict               # 涨跌榜（覆盖式）, {'up': [...], 'down': [...]}
  _limit_pools: Dict              # 涨跌停池（覆盖式）
  _minute_kline: List[Dict]       # 分钟K线（追加式）
  _lhb: List[Dict]                # 龙虎榜（覆盖式）
  _lhb_detail: Dict[str, List]    # 席位龙虎榜（覆盖式）
  _news: List[Dict]               # 新闻（按需缓存）
```

- **线程安全**：`threading.RLock` 保护批量操作
- **O(1) 读取**：零 IO，零 DB 连接
- **数据不存在**返回 `None` / `[]`，绝不抛异常
- **日终清理**：同步完成后清空盘中数据

### 4.3 TieredMemoryCache（方法级 TTL 缓存）

| analysis | 1800s | 300 | 资金流向/板块/概念 |

### A.3 全局速率限制器规范

所有 Tushare API 调用必须通过 `_ts()` 包装器进行，确保 ≤5次/秒的频率：

```python
# 在 data_daemon.py 和 tushare_provider.py 中均需实现
import time as _time
_ts_last_call = 0.0
_TS_MIN_INTERVAL = 0.2  # 5次/秒 → 200ms间隔

def _ts(pro_func, *args, **kwargs):
    global _ts_last_call
    elapsed = _time.time() - _ts_last_call
    if elapsed < _TS_MIN_INTERVAL:
        _time.sleep(_TS_MIN_INTERVAL - elapsed)
    _ts_last_call = _time.time()
    return pro_func(*args, **kwargs)
```
