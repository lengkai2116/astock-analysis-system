# 全局数据体系全量架构说明（2026-07-06 版）

> 本文档汇总当前生效的全局数据体系全部配置、数据路径、采集器设置和管理机制。
> 读者可基于本文档快速理解整个系统的数据从哪里来、存哪里、怎么用。

---

## 一、架构总览

```
时间轴       数据路径                  数据源            存储层             消费方式
────────────────────────────────────────────────────────────────────────────────────
交易时段     盘中实时采集路径          mootdx TCP        InMemoryStateStore   WebSocket推送 + REST
(9:30-15:00) 北交所补充采集            腾讯HTTP API      InMemoryStateStore   WebSocket推送 + REST
             指数采集                  mootdx index()    InMemoryStateStore   WebSocket推送 + REST
             板块排行自算              Tushare分类+快照   InMemoryStateStore   WsBridge定期推送
             涨跌榜/涨跌停池自算       从快照计算         InMemoryStateStore   WsBridge定期推送
             AKShare低频补充           AKShare(HTTP)     InMemoryStateStore   WsBridge定期推送
────────────────────────────────────────────────────────────────────────────────────
盘后         日终同步                  Tushare Pro       SQLite WAL           REST + 预聚合
(15:30+)
```

## 二、数据源详细配置

### 2.1 mootdx TCP（主数据源）

| 项目 | 配置 |
|------|------|
| **库** | mootdx 0.11.7 |
| **协议** | TDX 通达信 TCP 二进制 |
| **服务器** | 自动选择最佳IP（默认 123.125.108.14:7709） |
| **客户端** | `Quotes.factory()` → StdQuotes |
| **覆盖** | 沪深 A 股（0/3/6 开头，6位数），约 2761 只候选，实际 ~2000 只有效交易 |
| **字段** | 46 字段 + 五档盘口（bid1~5, ask1~5 + vol） |
| **刷新频率** | 5 秒 |
| **采集方式** | 分批（每批 100 只），约 28 批，总耗时 ~1s |
| **断连处理** | `_client_instance = None` → 下次自动重连 + 退避 |
| **文件** | `backend/app/data/mootdx_collector.py` |

### 2.2 腾讯财经 HTTP API（北交所补充）

| 项目 | 配置 |
|------|------|
| **URL** | `https://qt.gtimg.cn/q=bj{code}` |
| **覆盖** | 北交所 324 只（Tushare stock_basic market='北交所'） |
| **字段** | 12 核心字段（price, last_close, open, high, low, volume, bid1, ask1 等） |
| **刷新频率** | 10 秒 |
| **成功率** | 100%（10/10 测试） |
| **延迟** | ~220ms/批 |
| **并发** | 每批 50 只，7 批覆盖全部 |
| **位置** | `mootdx_collector.py:_collect_bse_quotes()` |

### 2.3 mootdx index()（指数数据）

| 项目 | 配置 |
|------|------|
| **API** | `client.index(code)` |
| **覆盖** | 上证指数(000001.SH)、深证成指(399001.SZ)、沪深300(000300.SH)、上证50(000016.SH)、创业板指(399006.SZ) |
| **字段** | OHLC + up_count/down_count |
| **刷新频率** | 30 秒 |
| **位置** | `mootdx_collector.py:_collect_indices()` |

### 2.4 AKShare HTTP（低频补充）

| 线程 | 数据 | 间隔 | 当前状态 |
|------|------|------|---------|
| sector_and_limit | 行业/概念板块排行 | 1800s (30min) | ⚠️ RemoteDisconnected |
| minute_kline | 分钟 K 线（自选股） | 300s (5min) | ✅ 可用 |
| lhb_and_news | 龙虎榜 + 新闻 | 1800s (30min) | ⚠️ 龙虎榜不可用，新闻可用 |

> 板块排行已由 mootdx 内存自算替代（105 个行业）。AKShare 线程保留为备用通道。
> **文件**: `backend/app/data/akshare_collector.py`（326 行，瘦身版）

### 2.5 Tushare Pro（盘后日线）

| 数据类型 | 同步方式 | 存储位置 | API 可用性 |
|---------|---------|---------|-----------|
| daily（日线） | 日终调度 15:30 | SQLite WAL daily_cache | ✅ |
| daily_basic（基本面） | 日终调度 15:30 | SQLite WAL daily_basic_cache | ✅ |
| moneyflow（资金流向） | 日终调度 15:30 | SQLite WAL moneyflow_cache | ✅ |
| index_daily（指数日线） | 日终调度 15:30 | SQLite WAL | ✅ |
| adj_factor（复权因子） | 日终调度 15:30 | SQLite WAL | ✅ |

> Tushare Provider 内置 `check_health()` 真实健康检查（`app/data/tushare_provider.py`）。

## 三、存储层

### 3.1 InMemoryStateStore（盘中实时）

| 项目 | 配置 |
|------|------|
| **类型** | 内存 Dict + threading.RLock |
| **数据槽** | snapshot(全市场快照)、sectors(板块)、concepts(概念)、top_stocks(涨跌榜)、limit_pools(涨跌停池)、minute_kline(分钟K线)、lhb(龙虎榜)、news(新闻) |
| **读取** | `O(1)` 无锁（Python GIL 保护，返回浅拷贝） |
| **写入** | 覆盖式（snapshot/top_stocks/limit_pools）+ 追加式（minute_kline） |
| **清理** | 日终 `clear_all()`（由盘后清理链触发） |
| **文件** | `backend/app/data/in_memory_store.py` |

### 3.2 SQLite WAL（盘后缓存，替代 DuckDB）

| 项目 | 配置 |
|------|------|
| **文件位置** | `data/duckdb/stock_cache.db`（复用原 DuckDB 目录） |
| **连接模式** | `sqlite3.connect()` + `PRAGMA journal_mode=WAL` |
| **并发** | WAL 模式：多读单写，读不阻塞写，写不阻塞读 |
| **缓存** | `PRAGMA cache_size=-8192`（8MB） |
| **超时** | `PRAGMA busy_timeout=5000`（5s 等待后报错） |
| **同步** | `PRAGMA synchronous=NORMAL` |
| **文件管理** | 单文件，无 corrupted 备份膨胀问题 |
| **表结构** | 17 张表（daily_cache, daily_basic_cache, moneyflow_cache, indicator_cache, chip_distribution_cache, win_rate_cache + 10 张 as_* 兼容表） |
| **全局单例** | `get_ecm_instance()` 禁止多实例 |
| **文件** | `backend/app/data/enhanced_cache_manager.py`（398 行，-1100 行精简） |

### 3.3 PostgreSQL（业务数据）

| 项目 | 配置 |
|------|------|
| **用途** | 策略模板、信号、账户、监控通知、复盘记录、系统配置等业务数据 |
| **连接** | `DATABASE_URL=postgresql:///stock_analysis`（SQLAlchemy ORM） |
| **与缓存关系** | 仅用于业务事务，不参与数据采集管道 |

## 五、自动采集机制

### 5.1 线程一览

| 采集器 | 线程 | 间隔 | 数据 | 启动方式 |
|--------|------|------|------|---------|
| MootdxCollector | `market_snapshot` | 5s | L1 快照 + 指数 + 板块 + 北交所 | `__init__.py` / gunicorn on_starting |
| AkshareCollector | `sector_and_limit` | 1800s | 板块排行(备用) | `__init__.py` / gunicorn on_starting |
| AkshareCollector | `minute_kline` | 300s | 分钟 K 线 | `__init__.py` / gunicorn on_starting |
| AkshareCollector | `lhb_and_news` | 1800s | 龙虎榜+新闻 | `__init__.py` / gunicorn on_starting |

### 5.2 定时调度（APScheduler）

| 调度任务 | 触发时间 | 功能 | 当前状态 |
|---------|---------|------|---------|
| 日终同步 | 每日 15:30 | 从 Tushare 同步 daily/basic/moneyflow/index/adj_factor 到 SQLite | ✅ 已安装 |
| 盘后清理链 | 同步成功后 | 清理盘中缓存(InMemoryStateStore/TieredMemoryCache/分钟K线) | ⏳ 待APScheduler启动 |
| 通知模块评估 | 每 15min | 条件评估、倒计时推送 | ⏳ 待APScheduler启动 |
| 每周健康报告 | 周一 06:30 | 系统健康检查 | ⏳ 待APScheduler启动 |

> APScheduler (`apscheduler>=3.10.4`) 已于 2026-07-06 安装。下次 Flask 启动后自动生效。

### 5.3 数据管理机制

| 机制 | 频率 | 功能 |
|------|------|------|
| SQLite 缓存清理 | 日终 | `invalidate_old_data(30)` 删除 30 天前缓存 |
| InMemoryStateStore 清理 | 日终 | `clear_all()` 清空盘中内存 |
| 行业映射刷新 | 每日 1 次 | 从 Tushare stock_basic 刷新 110 行业分类 |
| 北交所列表刷新 | 每日 1 次 | 从 Tushare stock_basic 刷新 324 只北交所 |
| mootdx 名称映射 | 每小时 1 次 | 刷新 27530 只股票名称映射 |
| 断连自动重连 | 每次采集 | mootdx TCP 断连后 `_client_instance = None` |
