# 436 — SIG 文字类输出（七维现状描述）空壳化与键契约错位修复方案

> **性质**：方案（生产者数据源改造 + 前后端键契约对齐 + 质量门禁收紧）。承接 435 号 §5.1 结论——「**真正的风险点（OUT/前端侧缺陷，非 JUD）**：文字类输出本身空壳化」。
>
> **编号说明**：`002-方案存档/` 当前最大实体编号为 435，故本文档取 **436**。
>
> **前提声明**：本方案与 435 号是**两条独立修复线**——435 号是只读核查（含 JUD 侧 v390 键契约错位，未改代码），本方案只处理 **`seven_dim_json → OUT.one_liner_detail → 前端`** 这条文字类通路；JUD 侧键契约错位**不在本方案范围**。
>
> **一句话结论**：`signal_json.signals` 自 411 号起恒为空，导致 `generate_seven_dim_from_signals` 的提取器对 5 个引擎全部落空，产出退化为 `{risk, summary}` 两个兜底段、灯色恒为 `yellow`、键名与灯色格式又双双与前端契约不符——**生产者手里其实已有富数据（同一循环内的 `dim_results`）却未被使用**。修复方向即「换数据源 + 对齐契约 + 清理死码 + 收紧门禁」。

## 一、问题背景

### 1.1 通路边界的重申（SIG 的两类输出）

| 类别 | 产物 | 下游 | 是否经 JUD |
|---|---|---|---|
| **数据类** | `dim_results_json` | JUD 消费（`StatusEngine.evaluate` v390） | ✅ 是 |
| **文字类**（股票现状描述） | `seven_dim_json` | **OUT** 透传 → `status_snapshot.one_liner_detail` → **前端** | ❌ 否（设计上直通） |

- 依据：`enhanced_cache_manager.py:853` 建表注释「seven_dim_json→OUT直通，dim_results_json→JUD消费」；`status_engine.py:928-933` docstring「产出直接透传到OUT写入one_liner_detail，不经过JUD」。
- 因此本方案的验证面是 **SIG 产出 → OUT 透传 → 前端渲染**，与 JUD 无关。

## 三、详细设计

### 3.1 总设计：换数据源为 `dim_results`，`summary` 段交 dim8 组装

**核心洞察**：`data_daemon.py:5800`（生成 seven_dim）与 `:5815`（生成 dim_results）位于**同一循环体的上下相邻位置**，改造点集中、无跨环节耦合。

```
改造前：signal_json.signals（恒空）→ generate_seven_dim_from_signals → 空壳
改造后：dim_results（7维富数据，同循环已产出）
          → Dim8SummaryEngine.build_seven_dim_report(dim_results, tags)   ← ★ 整体归集器（dim8）
              ├─ 7 段：dim_results[..] 的 judgment/status_description/audit 直取整形
              │        （含 summary 段的 dim8 综合组装）
              └─ 顶层 light = emoji、每段 judgment/audit/plain 对齐前端契约
          → seven_dim_json（契约对齐）→ OUT 透传（不变）→ 前端（不变）
```

> **📍 B1 架构（2026-09-15 用户拍板：dim8 归集，替换本小节原 D3）**：整体归集由 **dim8** 承担（`build_seven_dim_report`），不再由旁路 `build_seven_dim_from_dim_results` 单独整形 6 段 + dim8 只管 summary。`status_engine.build_seven_dim_from_dim_results` 保留名字/签名作为 **B2 daemon 接线入口**，内部委派 dim8。这使 SIG 现状描述统一整理模块化于 dim8（437 共识第 1/3 点）。

**为何 `summary` 用 dim8**：
- dim8（`Dim8SummaryEngine`）定位即「纯整理输出：读取 dim1-dim7 组装综合报告」，其返回结构 `{status_description:{status_bar,text,plain,consensus_rate,conflicts,data_warning}, judgment:{overall_light,overall_direction,...}, audit:{conditions,satisfied_count,total_count,confidence}}` **正是 frontend 契约所需形态**；
- 复用 420 号 6 项增强（共识率置信度加权 / rr 状态修正 / 信号老化 / 冲突扩展 / 文字富化 / 审计置信度），一次投入两处收益（JUD 与 SIG 同源）；
- 调用约定与 JUD 主路径一致：`dim8.evaluate(dims={}, tags=tags, lifecycle={'dim_results': dim_results})`（`status_engine.py:93-95`）；
- **同时契合用户既有心智模型**（"由 dim8 整理输出文字类"）——本方案不复活 394 号，但以"SIG 内直接调用 dim8 组件"实现其意图的可用部分。

**为何 `summary` 不能从 `dim_results` 直接取**：实测 `dim_results` 键为 7 维（含 `valuation`），**不含 `summary`**（dim8 产物在 JUD 路径落 `status_snapshot.dim_engine_results`，SIG 预计算路径未调用 dim8）——故必须由本方案显式组装，且这正是门禁恒需的键。

  "structure":    {…同上形态…},

  "fund_chip":    {…},          // ← 由 dim_results['chip_fund'] 改名
  "emotion":      {…},
  "risk":         {…},
  "summary":      {"title":"状态总结", "light":"🟡", "text":"<dim8 状态条+共识率+冲突摘要>", "plain":"<同 text>",
                   "evidence":[冲突描述…], "confidence":0.62,

- `plain`：`status_description.plain` 白话原文，供 indicator-ide 的 `（plain）` 括注。

**`evidence` 截断**：沿用现约定上限 5 条，控制行体积（见 §6 R4）。

### 3.3 调用点改造（`data_daemon.py:_precompute_strategy_signals`）

**现状**（`:5799-5817`，示意）：seven_dim 先算（只依赖 `rd`），dim_results 后算（依赖 `_tags/_signals/_lifecycle`，且 `_tags` 等定义在 `if _tags or _signals:` 块内）。

**改造**：`_tags/_signals/_lifecycle` 提升至循环体起始（默认 `{}` / `None`），并把 seven_dim 生成**移到 dim_results 生成之后**：

```python
for ts_code, result in results.items():
    try:
        rd = result.to_dict()
        _tags, _signals, _lifecycle = {}, {}, None
        dim_results = None
        if _se_engine:
            try:
                _tags = _se_engine._load_tags(ts_code)
                _signals = _se_engine._load_signals(ts_code)
                if _tags or _signals:
                    _lifecycle = _se_engine._signal_lifecycle(ts_code, _tags, _signals)
                    dim_results = _se_engine._build_dim_engine_results(_tags, _signals, {}, _lifecycle, ts_code=ts_code)
            except Exception:
                pass
        # 436号：文字类产出改由 dim_results 派生（原 signals 路径恒空）
        seven_dim = None
        if dim_results:
            try:
                from app.opportunity_atlas.status_engine import build_seven_dim_from_dim_results
                seven_dim = build_seven_dim_from_dim_results(dim_results, tags=_tags, lifecycle=_lifecycle)
            except Exception:
                pass
        rows.append((...))
```

- **关键**：`dim_results` 缺失（无 tags/signals 或引擎异常）→ `seven_dim = None`（**写 NULL 而非空壳**）→ 现有门禁 `if sd:` 自然跳过，前端回退到 `opportunity_profile` 分支（保持既有降级语义）。
- 顺序反转是**唯一的结构性改动**，务必在实施时核对缩进与变量作用域。

### 3.4 生产者函数改造（`status_engine.py`）

### 3.5 逐维整形规则（伪代码，实施参照）

```python
def _segment_from_dim(segs: dict, key_in: str, title: str) -> dict | None:
    seg = (dim_results or {}).get(key_in)
    if not isinstance(seg, dict) or not seg:
        return None                              # 缺该维 → 跳过（不产出假段）
    jg = seg.get('judgment', {}) or {}
    sd = seg.get('status_description', {}) or {}
    au = seg.get('audit', {}) or {}
    return {
        'title': title,
        'light': _LIGHT_EMOJI.get(jg.get('overall_light', 'yellow'), '🟡'),
        'text': _brief_text(key_in, jg, sd),      # 短结论
        'evidence': _yield_evidence(sd)[:5],
        'confidence': round(float(jg.get('continuous_value') or au.get('confidence') or 0.5), 2),
        'judgment': {'overall_light': jg.get('overall_light', 'yellow'),
                     'overall_direction': jg.get('overall_direction', 0),
                     'continuous_value': jg.get('continuous_value')},
        'audit': {'conditions': [{'name': c.get('name'), 'satisfied': bool(c.get('satisfied'))}
                                 for c in (au.get('conditions') or [])][:8],
                  'satisfied_count': au.get('satisfied_count', 0),
                  'total_count': au.get('total_count', 0),
                  'confidence': au.get('confidence', 0)},
        'plain': sd.get('plain', ''),
    }
```

- `dim1` 特例：`dim_results` 无 `signal` 维时，用 `tags.get('right_side_confirm')` 造最小段（`{'title':'信号确认状态','light':映射,'text':f'信号确认: {rsc}',...}`）；`rsc` 空则跳过该段。
- 段标题沿用现 generator 文案（`信号确认状态/结构位置状态/量价健康度/资金与筹码状态/情绪环境状态/风险边界状态/状态总结`），保持前端观感连续。
