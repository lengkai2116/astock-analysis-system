## 七、维度六：全站 UI 字体与色彩统一性

### 7.1 字体体系现状

**base.css 定义的设计 token：**

| Token | 用途 | 频率 |
|:-----|:-----|:----:|
| `14px` | body 基线 | 8处 |
| `13px` | 表格/按钮 | 4处 |
| `12px` | 侧栏/脚注 | 5处 |
| `16px` | 标题 | 2处 |
| `24px` | 大数值 | 3处 |
| `20px` | H1 | 1处 |
| `11px` | 小标注 | 1处 |
| `9px` | 标签 | 1处 |

**各页面实际使用的非 token 尺寸（超标统计）：**

| 页面 | 超标尺寸（不在 base.css token 中的 size） | 最极端值 |
|:----|:-----------------------------------------|:--------:|
| **indicator-ide** | 10/15/17/18/22/26/28/30/32/36/40/48px | 48px, 8px |
| **playback** | 10/15/16/17/40/48px | 48px, 8px |
| **alert** | 10/15/17/18/20/22/24/26/28/30px | 30px, 10px |
| **backtest** | 10/15/16/18/20px | 20px, 8px |
| **screener** | 10/11/14/18/32px | 32px |
| **account** | 9/10/14/15/18/32px | 32px, 9px |
| **strategy-templates** | 10/14/16/18/24/40px | 40px |

**最突出的问题：** 多数页面存在 `8px`~`10px` 的超小字体，低于常规可读性阈值（12px）。

### 7.2 问题清单

#### P0-02：全站字体体系分散，缺乏统一 token 约束

- **现象：** 各页面独立覆盖 `font-size`，使用大量非 token 值（10/15/17/18/22/24/26/28/30/32/36/40/48px），设计系统 Token 形同虚设
- **影响：** 
  - 视觉不一致：同级别元素在不同页面字号不同
  - 维护成本高：改动基础字号需要逐页搜索
  - 可读性下降：多处使用 ≤11px 字体
- **根因：** 原型开发为快速实现，未统一使用 base.css 的 CSS 变量尺寸体系
- **后续：** 需统一识别并整改（memory 已记录 `ui-font-color-revision.md`）

#### P1-03：多页面存在极低可读性字体（≤10px）

- account.html: `font-size:9px`（tc-reason标签）、`font-size:10px`（tc-rv标签）
- indicator-ide.html: `font-size:8px`（多处次级标注）、`font-size:9px`（tab项）
- backtest.html: `font-size:8px`（策略参数表格）
- playback.html: `font-size:8px`（日期小标）、`font-size:9px`（多处）
- strategy-sandbox.html: `font-size:9px`（多处）
- 最低至 8px，远低于 A 股市值软件的常规最小字号（11-12px）

**建议：** 将全站最小可读字体统一提升至 11px（次要标注）或 12px（正文小字），消除 ≤10px 的使用。
