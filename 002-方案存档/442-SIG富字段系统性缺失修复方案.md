# 442 — SIG 富字段系统性缺失修复方案

> **定位**：437-A 示例编排暴露大量降级项，全局核查（09-14 全市场 5577 只）确认 **5 类系统缺陷 + 1 附注**——**数据源表有数据，但引擎字段不产出**（与 441 的「数据源真缺」性质不同）。本号逐项锁定根因并给出修复方案。根因均已**代码定位 + 实证复现**。

## 一、缺陷①：dim4 `phase` + `crowding` 100% 缺失（status_engine 未传 ts_code）

### 根因（已实证）
- `status_engine._build_dim_engine_results`（status_engine.py:266）调 dim2-dim7 `engine.evaluate(dims, tags, signals, lifecycle, data_context=data_context)` **未传 ts_code**；
- dim4 `evaluate` 内部 `ts_code = tags.get('ts_code', '')`（dim4:5937）——tags 是 pre_feat 扁平化结果（`_flatten_pre_feat`，**无 ts_code 键**，419 号只给 dim1 加了 ts_code 参数并显式传递，**dim4 未同步**）；
- 故 `if ts_code and df is not None and not df.empty and len(df) >= 30:`（dim4:5954）**恒 False** → PhaseDetectionEngine 与 CrowdingFactor 块整体跳过 → phase 恒"未知"、crowding 恒"unknown"。

### 实证（000002.SZ，真实运行时 data_context）
| 场景 | phase | crowding |
|---|---|---|
| 现状（tags 无 ts_code） | ❌ 未知（主力阶段数据缺失） | ❌ 拥挤度=unknown |
| **补 `tags['ts_code']` 后** | ✅ **建仓期（置信度 0.22）** | ✅ **MODERATE（适中）** |

### 修复
**status_engine.py `_build_dim_engine_results`**：dim2-dim7 evaluate 显式传 `ts_code=ts_code`（对齐 419 号 dim1 做法）。可选：给 dim4.evaluate 增加 `ts_code` 参数并优先于 `tags.get`。

## 二、缺陷②：dim4 `margin` 100% 缺失（margin_change_5d 无产出点）

### 根因
- `_assess_margin(tags)`（dim4:5898）读 `tags['margin_change_5d']`；
- **全代码无 `margin_change_5d` 产出点**（`calc_margin_ratio` 仅在 CrowdingFactor 内部用，不写 tag）→ 恒"融资数据不足"；
- **margin_cache 有 62153 行数据**（data_context.margin_df 已加载），但从未被用于该字段。

### 修复
`_assess_margin` 改造：优先读 `data_context['margin_df']` 计算 5 日融资余额变化（rzye 列，参照 `_calc_margin_cost_price` dim4:3581 的用法），产出真实「融资余额5日变化 X%」；tags 兜底保留。

## 三、缺陷③：dim2 `vs_indicator` 100% 缺失（读不存在的键）

### 根因
- `_assess_vs_indicator(tags)`（dim2_structure_engine.py:250）读 `tags['rsi14']` / `tags['kdj_j']`；
- pre_feat `derived` 组**不产出**这两个键（实为 `structure_ext.indicator_status: ma=bullish,trend=`）→ 恒"指标数据不足"。

### 修复
- 方案 A：dim2 改读 `tags['indicator_status']`（已产出），解析 `ma=...,trend=...`；
- 方案 B：pre_feat 生产侧补产 rsi14/kdj_j（`indicator_other` 表有该列，见 dim1:174-179 的 `other_cols` 提取）。
- **建议 A**（改动小、数据现成）。

## 四、缺陷④：`emotion.sector` 84% 缺失（SectorRotationModel 产出 none）

### 根因
- pre_feat `sector` 组由 `SectorRotationModel.evaluate(code)` 产出（data_daemon.py:3183，`sr=SectorRotationModel()`）；
- evaluate（sector_rotation_model.py:134）任一条件不满足即返回 `sector_heat='none'`、`rank=-1`：
  1. `dm.get_stock_industry(ts_code)` 为空（行业映射缺失）；
  2. `all_heat` 缓存为 None（`compute_all_heat` 未预热/失败）；
  3. 行业不在 all_heat 中。
- 000002.SZ pre_feat `sector_heat='none'`、`sector_rank=0` → 走了失败分支。

### 修复（需专项定位二选一）
- a) 核查 `get_stock_industry` 行业映射可用性（Stock 表来源）；
- b) 核查 `compute_all_heat` 预热链路（sector_heat_cache 有 109 行业数据，确认 RAW-2B `_precompute_sector_heat` 与 SectorRotationModel 缓存是否衔接）。

## 五、缺陷⑤：`relative_strength` 60d 窗口 99% 缺失（含 3 天全市场采集空洞）

### 根因（两层）
1. **`_compute_relative_strength`（data_daemon.py:458）窗口逻辑**：`dates` 仅取最近 61 交易日，`_n_day_ret(sub, 60)` 需 `len(s)>=61` 观测；窗口内任何缺失日 → 60d 变 None。
2. **daily_cache 存在 08-19/20/21 三天全市场采集空洞**（实证：这三天全市场仅 145/146/147 只记录，正常 ~5600 只；抽 200 只 195 只缺 3 天）→ 99% 股票 `len(sub)<61` → 60d 恒 None。

### 修复（建议两路并行）
- **A. 补采 3 天空洞**：回填 2026-08-19/20/21 三天全市场日线（复用 daemon `_batch_daily` 补采路径），根治空洞；
- **B. 窗口容错**：`_compute_relative_strength` 取数窗口扩至 70+ 交易日（`LIMIT 61`→`LIMIT 75` 等），dropna 后仍有 ≥61 观测，容忍零星缺失。

## 六、附注：存库 data_context 损坏（非本号主修，消费方须知）

- `strategy_signal_detail.dim_results_json` 中 `signal.data_context` 的 DataFrame 被 JSON 序列化为 **str**（实证：`daily_df` 为 str，非 DataFrame）；
- **回填/消费路径**（如 `_436_recompute_backfill`）若依赖存库 data_context 会踩 `'str' object has no attribute 'columns'`；
- 建议：data_context 本为运行时对象，不应作为持久消费源；消费方以 `signal.status_quality`/`dim_results` 为准。

### 缺陷④实施记录（2026-09-15）：emotion.sector 根因 = RAW-2 线程池无 app_context（含 3 层发现）

**根因（专项定位，逐层深入）**：`_precompute_raw_features`（RAW-2）经 `_raw_pool.submit` **线程池**执行（data_daemon:5672），线程内无 Flask app_context；`sr.compute_all_heat` 内部 `dm.get_stock_industry_batch` 依赖 `db.session.query` → **RuntimeError: Working outside of application context**（实证），被 `except: pass` 静默吞掉 → `sr._cache['all_heat']` 恒空 → `sr.evaluate` 恒 `sector_heat='none'`。行业映射本身有数据（app_context 下 000002.SZ→全国地产、600519.SH→白酒 ✅）。

**3 层修复**（`data_daemon.py` + `dim5_emotion_engine.py`）：
1. **compute_all_heat 包 app_context**（主线程预热）；
2. **`_raw2_one` 带参 bug（预存缺陷）**：`_raw2_one(code)` 是唯一带参嵌套函数，而 `_run_with_timeout` 的 `submit(func)` 不带参 → TypeError → **RAW-2 自 428 P1-2 单股超时改造以来从未成功**（`succeeded=0`，pre_feat 一直用旧数据）。修复：调用处 `_run_with_timeout(lambda: _raw2_one(code), ...)`。修复后 **5546/5550 成功**；
3. **sector 写入键名错位**：data_daemon 读 `sector_rank`/`sector_momentum`，evaluate 返回 `rank`/`strength` → 恒 0。修复：对齐返回键。另 dim5 heat_map 把 `'none'`（rank>40 冷门）误描述为「板块数据不足」——改为「冷门板块」。

**实证（全量重算后，5546 只）**：succeeded 5546/5550；**rank>0 5529 只（99.7%）**、-1 仅 17 只（行业映射缺失极少数）；heat 分布 top_10 210 / top_20 175 / normal 411 / none 4750（85.7% 冷门=rank>40 行业合理，对照 sector_heat_cache 全国地产 rank42 冷门一致）；**000002.SZ rank=42、momentum=0.2308、emotion.sector「板块排名40以外（冷门板块）」**。回填脚本 `scripts/_442_recompute_raw2.py`（含备份/冒烟）。compute_cache.db 备份 `bak_442_raw2_*`。

**回归**：相关套件 **136 passed**（含 test_419_dim5_compliance）。
