# 539 仪表盘模块容器高度自适应与统一间距

**缘起**：用户提出——仪表盘模块内容随行情变化，当前部分容器高度固定导致内容多时展示不全；要求**左右宽度、展示次序、模块间距保持固定**，**上下高度随内容多少自适应**，且**同一排两个容器上下高度始终一致**；同时要求**所有模块容器的横向与纵向间距一致**。
**范围**：仅 `_ui-prototype/dashboard.html` + `_ui-prototype/assets/base.css` 展示层；不改后端 API、数据表、模块取数口径、左右列宽与展示次序。
**本档只落实施计划，未改代码。**

| 项 | 现状 | 代码证据 |

| 页面滚动 | `.main-content {overflow:hidden}`；`base.css` 为 `flex:1; min-height:100vh` | `dashboard.html:62`、`base.css:154` |
| 总览卡裁切 | `.mkt-overview {overflow:hidden}`（背景渐变用） | `dashboard.html:23` |

**关键结论**：

1. “同排两容器等高”**不需要 JS 同步**，CSS Grid 的 `stretch` 已具备；只要不写死卡片 `height`、不使用 `align-self:start`，内容变化时整行高度自动取最高者，另一张自动拉伸。
2. 真正导致“内容多展示不全”的是**内层图表固定像素高度**与**长列表 `max-height`**，不是外层卡片高度。
3. “所有间距一致”目前并未完全成立：横向 16px、纵向 20/24px 混用；模块内部 10/8/6px 属于密度层级，需要与模块级间距分开定义。

## 二、目标与非目标

### 目标

- 模块左右宽度、DOM 次序、模块级横纵间距固定。
- 模块级横向间距 = 纵向间距 = 单一 token（建议 **16px**）。
- 卡片外层高度由内容决定；同一排两张卡片高度始终一致。
- 内容型模块（表格/列表/行业柱/走势）可随行数增高；图表画布随容器高度 `resize()`。
- 长列表可完整查看，但避免页面无限拉长。

### 非目标

- 不改后端取数、API、指标/策略口径。
- 不调整模块左右列宽与展示次序。
- 不把散点图、30 日序列等大数据模块按数据点数量无限撑高。
- 不做全站组件化重构。

## 三、设计口径（默认方案，实施前可拍板调整）

### 3.1 两级间距 token

```css
--module-gap: 16px;  /* 模块与模块之间：横向、纵向统一 */
--inner-gap: 8px;    /* 模块内部：KPI、标签、表格行等密度层级 */
```

- 顶层模块的 `margin-bottom` 全部改为 `var(--module-gap)`，替换 20/24 混用。
- `.index-grid`、`.grid-2`、`.grid-3`、`.grid-4` 的 `gap` 统一为 `var(--module-gap)`。
- `.grid-2` 在 `base.css` 与 `dashboard.html` 重复定义，建议收敛到一处，避免以后两处漂移。
- `.mkt-flow-grid`、`.mkt-kpi`、Top5 卡片等**模块内部**小网格保持 `--inner-gap` 或现有 6/8/10px，不强行拉到 16px，避免页面松散。
- 若用户要求“字面所有 gap 一律 16px”，需接受信息密度下降与页面变高，作为可选项登记。

### 3.2 卡片高度

- 卡片只允许 `min-height`，禁止固定 `height`。
- 卡片不设置 `align-self:start`；保持 Grid 默认 `stretch`。
- 卡片内部若需图表填满：`display:flex; flex-direction:column;`，图表容器 `flex:1; min-height:...`。
- 同排等高由 Grid 自动完成，不额外写 JS 同步外层高度。

### 3.3 图表高度策略

| 类型 | 策略 | 说明 |
|---|---|---|
| 数据点固定的摘要图 | **固定高度** | 指数迷你图 100、宽度环形 180、强弱 180、涨停对比 70、封板率 104、昨涨停 100、成交额 260、资金流 260、ETF/融资 180、行业净流入 280、板块涨跌幅 320、散点/四象限 320 |
| 行数可变的行业/走势图 | **按行数自适应** | 涨停/跌停行业图、板块资金列表、近5日板块走势（11/31 行）、板块热度表 |
| 大数据图 | **固定高度 + 采样/展开** | 5567 点散点、30 日序列不按数据量撑高 |
| 长列表 | **展开/收起或滚动** | 板块热度 31 行、近5日走势 31 行、Top5 个股 chip |

- 自适应图表统一用 `fitChartHeight(el, rows, base, perRow, min, max)` 计算，设高度后调用 `chart.resize()`。
- 用 `ResizeObserver` 监听容器宽度/高度变化，debounce 后 resize；数据签名未变时跳过，避免 30 秒轮询抖动。

### 3.4 页面滚动

- 优先把 `.main-content { overflow:hidden; }` 改为 `overflow:visible`，由页面自然滚动；`base.css` 的 `min-height:100vh` 已允许内容撑高。
- 若希望侧边栏/头部固定、仅内容区滚动，改为 `height:100vh; overflow-y:auto`，需同步调整 padding。
- `.mkt-overview` 的 `overflow:hidden` 仅用于背景渐变，保留；但需目检确认内容不被裁切。

### 3.5 响应式

- `max-width:1100px` 时 `.grid-2` 变单列，“同一排两个容器”不再存在，等高规则自然失效；这是预期行为。
- 若要求窄屏也保持两列配对，需要额外媒体查询，默认不做。

### 批次 2：图表高度内容驱动（核心）

**改动**

  1. 涨停/跌停行业图（行业数变化）

- 30 秒轮询连续观察 2 分钟，无高度抖动/闪烁。

### 批次 3：长列表、响应式与收尾

**改动**

- `.main-content` / `.mkt-overview` 裁切目检。
- 记录各模块默认/展开高度。

**验收**

- 1200px+ 两列：同排等高、间距一致。
- 1100px 以下单列：无溢出、无横向滚动。
- 展开全部后内容完整可见，页面滚动正常。
- 用户手动起服目检通过（助手不做无头浏览器截图）。
