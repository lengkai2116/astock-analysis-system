# 390 — JUD环节多因子决策引擎架构方案

> **背景**：389号审计发现SIG 8维度引擎产出216个结构化字段，JUD仅消费54个（25%）。根因不是SIG产出过多，而是JUD的"标签规则引擎"架构无法消化引擎的连续数值、嵌套结构和多层级判定。本方案对JUD进行架构级升级——从if-else规则链升级为多因子决策引擎。
>
> **理论依据**：知识库三层信号结构、多周期层级决策框架、状态依赖动态权重、组合语义识别、多指标共识机制（含去相关）、311号三层评分框架
>
> **行业对标**：i问财/雪球/BigQuant/Bloomberg均采用多条件组合或加权融合，无平台使用单标签决定论

---

## 一、现状诊断

### 1.1 当前JUD架构

```
dim_adapter（标签翻译）
  → weight_engine（静态/IC动态权重）
  → conflict_detector（9条固定规则）
  → arbiter（P0-P7八级优先级if-else链）
  → status_engine._aggregate（加权投票共识率）
  → status_engine._assemble（仓位公式+advice_params）
```

### 1.2 架构短板

| 短板 | 现状 | 影响 |
|------|------|------|
| **仲裁器是规则链** | P0→P7逐级匹配命中即止 | 只看right_side_confirm一个标签，不看维度引擎的分析深度 |
| **共识率是简单投票** | state查表±1×权重求和 | 维度间无可靠性调节，相关维度重复投票 |
| **冲突检测是固定规则** | 9条if-else | 维度交叉冲突（如"欲病+强确认"）完全未覆盖 |
| **仓位计算是固定公式** | 0.6×系数连乘 | 不与盈亏比/波动率/距防守位联动 |
| **连续强度在管道中丢失** | 引擎confidence→标签离散化→评分重新赋分 | 二次信息丢失，评分分布偏态 |

### 1.3 SIG输出利用率低的根因

不是SIG产出无用，而是JUD架构消化不了。具体表现为：

- dim2的chanlun_phase（未病/欲病）→ arbiter不读取，无法影响判定
- dim3的stage_name（UPTREND_ACTIVE等）→ 共识率计算不使用
- dim4的phase_confidence（0-1连续值）→ confidence固定为0.5
- dim5的bociasi_slow_signal → 完全被忽略
- dim6的volatility_percentile → P6阈值调整不使用
- dim7的composite_rating + potential_score + dividend_yield → 已部分接入但未参与评分

## 三、L1 维度适配层（dim_adapter升级）

### 3.1 职责

将8个维度引擎的输出统一转换为JUD内部的**维度因子**格式，每个因子包含：
- `direction`：方向（+1看多 / 0中性 / -1看空）
- `strength`：连续强度（0-1，来自引擎原始confidence或连续数值）
- `evidence`：判定依据文本列表

> **注意**：reliability由L2单独计算，不在此层输出（ARCH-1修复：避免L1/L2循环依赖）。

## 五、L3 共识聚合层（consensus_engine）

### 5.1 职责

将11个维度的方向和强度聚合为综合共识得分，同时处理维度去相关和状态依赖权重。

### 5.2 计算流程

```
Step 1：族级去相关
Step 2：状态依赖权重矩阵
Step 3：可靠性加权共识得分
Step 4：中性方向处理
```

### 5.3 Step 1：族级去相关

将11个维度分为4个族，同族内合并为一个族级证据，避免相关维度重复投票。

| 族 | 包含维度 | 合并规则 |
|----|---------|---------|
| **主力行为族** | chip_fund(phase+fund_flow+crowding) | 三者方向取多数；强度取均值 |
| **结构趋势族** | structure + signal + time | 三者方向取多数；强度取均值 |
| **量价状态族** | vp | 独立（已含多时间框架信息） |
| **估值质量族** | valuation + finance | 两者方向取多数；强度取均值 |
| **环境族** | emotion + event + factor | 三者方向取多数；强度取均值 |
| **风险族** | risk | 独立（独立否决权） |

去相关后，共识计算的输入从11个维度变为**6个族级因子**。

**族内合并规则（ARCH-6修复：先检测族内冲突，再决定族级方向）**：

```python
def merge_family(dims_factor: dict, family_dims: list) -> dict:
    """族内合并：先检测冲突，再取多数方向"""
    directions = [dims_factor[d]['direction'] for d in family_dims if d in dims_factor]
    strengths = [dims_factor[d]['strength'] for d in family_dims if d in dims_factor]

    if not directions:
        return {'direction': 0, 'strength': 0.5, 'has_conflict': False}

    pos = sum(1 for d in directions if d > 0)
    neg = sum(1 for d in directions if d < 0)

    # 族内冲突检测：如果既有看多又有看空，标记冲突
    has_conflict = pos > 0 and neg > 0

    if has_conflict:
        # 族内有冲突时：方向取多数但降低强度
        group_dir = 1 if pos > neg else (-1 if neg > pos else 0)
        group_str = sum(strengths) / len(strengths) * 0.6  # 冲突降低40%强度
    else:
        group_dir = 1 if pos > 0 else (-1 if neg > 0 else 0)
        group_str = sum(strengths) / len(strengths)

    return {'direction': group_dir, 'strength': group_str, 'has_conflict': has_conflict}
```

- 高潮期：风险权重最高（追涨风险大），估值权重最低（亢奋时估值参考下降）
- 正常期：各族均衡

### 5.5 Step 3：可靠性加权共识得分

```python
def compute_consensus(dims_factor: dict, reliability: dict, weights: dict) -> dict:
    """可靠性加权共识得分计算"""
    bull_score = 0.0  # 多头总分
    bear_score = 0.0  # 空头总分
    total_weight = 0.0

    for group_name, group_dims in GROUP_MAPPING.items():
        group_directions = [dims_factor[d]['direction'] for d in group_dims if d in dims_factor]
        group_strengths = [dims_factor[d]['strength'] for d in group_dims if d in dims_factor]
        group_reliabilities = [reliability.get(d, 0.5) for d in group_dims if d in dims_factor]

        if not group_directions:
            continue

        # 族内方向取多数
        pos = sum(1 for d in group_directions if d > 0)
        neg = sum(1 for d in group_directions if d < 0)
        group_dir = 1 if pos > neg else (-1 if neg > pos else 0)

        # 族内强度取均值
        group_str = sum(group_strengths) / len(group_strengths)

        # 族内可靠性取均值
        group_rel = sum(group_reliabilities) / len(group_reliabilities)

        # 有效权重 = 静态权重 × 可靠性
        effective_weight = weights.get(group_name, 0.15) * group_rel

        # 贡献到共识
        if group_dir > 0:
            bull_score += effective_weight * group_str
        elif group_dir < 0:
            bear_score += effective_weight * group_str
        total_weight += effective_weight

    # 共识率 = 优势方向分 / (多头分 + 空头分)
    if bull_score + bear_score > 0:
        raw_consensus = max(bull_score, bear_score) / (bull_score + bear_score)
        direction = 'bullish' if bull_score > bear_score else 'bearish'
    else:
        raw_consensus = 0.0
        direction = 'neutral'

    # BUG-3修复：纳入整体可靠性因子，避免低可靠性也能高共识率
    max_possible_weight = sum(weights.values())  # 所有族权重加和（应为1.0）
    reliability_factor = total_weight / max_possible_weight if max_possible_weight > 0 else 0.5
    consensus_rate = raw_consensus * reliability_factor

    return {
        'consensus_rate': round(consensus_rate, 4),
        'raw_consensus_rate': round(raw_consensus, 4),  # 保留原始值供诊断
        'reliability_factor': round(reliability_factor, 4),
        'direction': direction,
        'bull_score': round(bull_score, 4),
        'bear_score': round(bear_score, 4),
        'group_details': {...},
    }
```

### 7.2 计算流程

### 7.3 Step 1：硬否决检查

保留以下一票否决条件（与当前P0/P1对齐）：

| 条件 | 来源 | 处理 |
|------|------|------|
| right_side_confirm == '否决' | tags | 直接avoid |

### 7.4 Step 2-3：综合分计算

```python
def compute_final_score(consensus: dict, conflict: dict, tags: dict,
                        dims_factor: dict, reliability: dict) -> dict:
    # 基础分：共识率映射到0-100
    base_score = consensus['consensus_rate'] * 100

    # 组合语义调整
    adjusted_score = base_score * conflict['semantic_adjustment']

    # right_side_confirm门禁修正
    rsc = tags.get('right_side_confirm', '未确认')
    rsc_multiplier = {
        '强确认': 1.0,
        '基础确认': 0.8,
        '未确认': 0.5,
    }.get(rsc, 0.5)
    final_score = adjusted_score * rsc_multiplier

    # 情绪极端修正
    temperature = dims_factor.get('emotion', {}).get('strength', 0.5) * 100
    if temperature > 80:
        final_score *= 0.85  # 亢奋期压缩
    elif temperature < 20:
        final_score *= 0.75  # 恐慌期压缩

    return {'final_score': round(final_score, 1)}
```

### 8.2 动态仓位模型

```python
def compute_position(final_score: float, dims_factor: dict, l0: dict,
                     dim_results: dict, ts_code: str) -> dict:
    """动态仓位计算"""

    # 1. 基础仓位（从综合分推导）
    if final_score >= 70:
        base = 0.6   # enter
    elif final_score >= 55:
        base = 0.4   # light
    elif final_score >= 30:
        base = 0.1   # wait
    else:
        base = 0.0   # avoid

    # 2. L0软风险系数连乘（保留现有逻辑）
    position = base * l0['position_coeff']

    # 3. 情绪阶段上限（保留现有逻辑）
    if l0.get('emotion_position_cap') is not None:
        position = min(position, l0['emotion_position_cap'])

    # 4. 新增：风险预算约束（2%规则，已部分实现）
    risk_position = _compute_risk_budget(dim_results, ts_code)
    if risk_position is not None:
        position = min(position, risk_position)

    # 5. 新增：波动率调整（ARCH-5修复：结合市场状态，趋势市对高波动更容忍）
    atr_pct = _get_field(dim_results, 'risk', 'atr_pct', 0.5)
    market_regime = _detect_market_regime(tags, dims_factor)
    if market_regime in ('trending_up', 'trending_down'):
        # 趋势行情中高波动是正常的，仅在极端波动时压缩
        vol_threshold = 0.85
    else:
        # 震荡市中高波动意味着方向不明，更敏感
        vol_threshold = 0.65
    if atr_pct > vol_threshold:
        vol_adjustment = 1.0 - (atr_pct - vol_threshold) * 2
        position *= max(vol_adjustment, 0.5)  # 最低保留50%

    # 6. 新增：盈亏比调整
    rr = _get_field(dim_results, 'risk', 'rr_value', 1.0) or 1.0
    rr_adjustment = min(rr / 2.0, 1.0)
    position *= rr_adjustment

    # 7. 新增：距防守位调整（v3.0：使用dim6.dist_to_support_pct）
    dist_support = dims_factor.get('risk', {}).get('dist_support_pct', -5.0)
    if dist_support > -2:  # 距防守位<2%
        position *= 0.6  # 止损空间太小，压缩仓位

    # 8. 单票上限30%
    position = min(position, 0.30)

    return {'max_position_ratio': round(position, 2)}
```

## 九、完整运行流程

### 9.1 日终批量管道调用顺序

```python
def evaluate(ts_code: str, dim_results: dict) -> dict:
    """JUD多因子决策引擎主流程"""
    tags = _load_tags(ts_code)
    signals = _load_signals(ts_code)
    lifecycle = _signal_lifecycle(ts_code, tags, signals)

    # L0：风险分级（保留现有逻辑）
    l0 = _apply_l0(ts_code, tags, lifecycle)

    # L1：维度适配 → 11维因子（ARCH-1修复：不含reliability）
    dims_factor = dim_adapter.convert_to_factors(dim_results, tags)

    # L2：可靠性评估（独立于L1，无循环依赖）
    reliability = reliability_assessor.assess(dims_factor, dim_results)

    # L3：共识聚合（族级去相关 + 状态依赖权重 + 可靠性加权）
    regime = detect_market_regime(tags, dims_factor)
    weights = weight_engine.get_weights(regime, ic_values, emotion_quadrant)
    consensus = consensus_engine.compute(dims_factor, reliability, weights)

    # L4：冲突矩阵（维度交叉 + 组合语义；ARCH-2修复：致命冲突分离路由）
    conflict = conflict_matrix.detect(dims_factor, tags, dim_results)

    # 硬否决检查（ARCH-2修复：接收L4的fatal_to_veto，不重复检测）
    if l0['hard_veto']:
        return _build_avoid_result(ts_code, l0, reason=l0['hard_reason'])
    if conflict.get('fatal_to_veto'):
        return _build_wait_result(ts_code, reason=conflict['fatal_to_veto'])

    # L5：多因子仲裁（仅接收warn冲突做语义调整，不重复处理致命冲突）
    arb_result = factor_arbiter.arbitrate(consensus, conflict, tags, dims_factor, reliability)

    # L6：操作建议
    advice = advice_engine.compute(arb_result['final_score'], dims_factor, l0, dim_results, ts_code)

    # 组装输出
    return _assemble(ts_code, dims_factor, l0, arb_result, advice, conflict, reliability)
```
