# 桌面端载体方案探讨

> **问题：** 当前规划的用户交互方式是打开浏览器访问 `localhost:5001` —— 这不够像"真正的软件"。有没有更接近本地桌面应用的载体？

---

## 一、当前规划的实质

227号方案定义的生产环境交互流程：

```
用户双击 Astock.app
    ↓
Platypus (macOS) / Inno Setup (Windows)
    ↓
启动 Flask 进程（port 5001）
    ↓
打开系统默认浏览器 → http://localhost:5001
    ↓
用户在浏览器中查看/操作      ← 问题就在这里
```

**用户感受到的"不像软件"的点：**

| 感受 | 原因 |
|:-----|:------|
| 浏览器工具栏/地址栏/标签页可见 | 视觉上就是"浏览器开了一个网页" |
| 可能误关标签页 | 浏览器标签容易混淆，用户可能关掉系统页 |
| 没有系统托盘 | 无法最小化到后台运行（Flask跑着但没有"一直在那儿"的感觉） |
| 没有原生菜单 | 没有 File/Edit/View 菜单，没有 About/设置入口 |
| 通知不够原生 | 目前走 WebSocket 推送，不具备系统通知中心的深度集成 |
| Dock栏不"属于"这个应用 | macOS Dock 显示的是浏览器图标，不是 Astock |
| 多实例风险 | 用户可能不小心打开多个标签页产生多个操作 |

---

## 二、可选方案对比

### 方案A：Flask + 系统浏览器（当前规划）

```
实现: Platypus/Inno Setup 启动 Flask + 打开系统浏览器
技术: 无需额外框架
```

| 维度 | 评价 |
|:-----|:----:|
| 实现难度 | ✅ 现成方案，零额外开发 |
| 分发体积 | ✅ 极小（仅 Flask + SPA） |
| 系统托盘 | ❌ 无（Flask 后台进程，无托盘图标） |
| 原生菜单 | ❌ 无 |
| 通知集成 | ❌ WebSocket 推，浏览器内弹 toast |
| 窗口管理 | ❌ 浏览器标签页，非独立窗口 |
| 自动更新 | ❌ 用户自行下载新版 |

**适合阶段：** 开发调试、早期验证

### 方案B：Electron 包装（推荐迁移目标）

```
Electron 进程
  └─ 生成 Python 子进程 (Flask)
  └─ BrowserWindow → http://localhost:5001
  └─ 系统托盘 / 原生菜单 / 通知 / 自动更新
```

| 维度 | 评价 |
|:-----|:----:|
| 实现难度 | 🟡 中等（配置 Electron + 子进程管理） |
| 分发体积 | ⚠️ ~150MB（含 Chromium + Node.js 运行时） |
| 系统托盘 | ✅ 原生托盘图标，点击显示/隐藏窗口 |
| 原生菜单 | ✅ File/Edit/View/Tools/Help 完整菜单栏 |
| 通知集成 | ✅ OS 原生通知（Electron Notification API） |
| 窗口管理 | ✅ 独立窗口，关闭最小化到托盘，记住位置大小 |
| 自动更新 | ✅ electron-updater 自动检查+静默更新 |
| 打包方式 | electron-builder → .dmg(macOS) / .exe(Windows) |
| 对现有代码影响 | 无需改 Vue 代码，仅需添加 Electron main process |

**关键优势：** 应用级体验完整、技术支持成熟、用户感知最接近"买了款软件"。

**技术注意事项：**
- Electron 不直接运行 Python，需通过 `child_process.spawn('python3', ['backend/run.py'])` 启动 Flask
- Flask 进程管理：主进程退出时自动杀子进程
- 开发调试时可选择 "Electron → 已有 Flask"（无需每次都靠 Electron 启动）

### 方案C：PyWebView 轻量级包装

```
Flask 进程
  └─ pywebview 创建原生 WebView 窗口 → http://localhost:5001
  └─ Python 内直接管理窗口（无需 Node.js）
```

| 维度 | 评价 |
|:-----|:----:|
| 实现难度 | ✅ 极低（pip install pywebview + 20 行代码） |
| 分发体积 | ✅ ~10MB（仅系统 WebView 运行时） |
| 系统托盘 | ✅ 有（pywebview 支持托盘） |
| 原生菜单 | ✅ 有（可自定义菜单栏） |
| 通知集成 | 🟡 Python 侧实现（plyer/desktop-notifier） |
| 窗口管理 | 🟡 基本（窗口创建/隐藏/显示） |
| 自动更新 | ❌ 需自行实现 |
| 打包方式 | PyInstaller → .app(macOS) / .exe(Windows) |
| 对现有代码影响 | 零影响，纯包装层 |

**关键优势：** 轻量、Python 原生、代码极少。如果只想去掉浏览器工具栏，这是最快方案。

**局限：**
- macOS 用 WKWebView / Windows 用 WebView2，不是 Chromium——渲染与 Chrome 有细微差异
- 调试不方便（无 DevTools 开箱即用）
- 社区不如 Electron 活跃，遇到坑资源少

## 三、推荐路径

```
短期（开发阶段）:   方案A — 浏览器启动（零变更，按当前计划开发）
                    ↓ 所有功能验证通过后
中期（打包阶段）:   方案C — PyWebView 包装（轻量，消除"浏览器感"）
                    ↓ 用户反馈需要更深集成时
长期（成熟产品）:   方案B — Electron 包装（完整的桌面软件体验）
```

### 对各阶段开发的影响

| 阶段 | 方案 | 对当前开发的影响 |
|:-----|:-----|:----------------|
| 模块开发 | 方案A | **零影响。** 继续用 `python backend/run.py` + 浏览器调试 |
| 模块验证 | 方案A | 零影响。验证功能正确性即可 |
| 集成测试 | 方案A→C | 开发完成后用 PyWebView 包一版测试。PyWebView 是包装层，不改任何功能代码 |
| 发布 | 方案C或B | 决定后才涉及打包脚本编写 |

**核心结论：不管选什么载体，当前的后端开发和前端开发都不受影响。** Flask 提供 HTTP API + SPA 的架构与桌面载体正交——无论是浏览器、Electron 还是 PyWebView，都只是消费 `http://localhost:5001` 的不同方式。

## 四、技术实现简述

### PyWebView 实现（~30 行）

```python
import webview
import threading
from backend.run import app  # Flask app

def start_flask():
    app.run(host='127.0.0.1', port=5001, debug=False)

if __name__ == '__main__':
    flask_thread = threading.Thread(target=start_flask, daemon=True)
    flask_thread.start()
    webview.create_window('A股分析系统', 'http://127.0.0.1:5001', width=1400, height=900)
    webview.start()
```

### Electron 实现骨架

```javascript
// main.js — Electron 主进程
const { app, BrowserWindow, Tray, Menu, Notification } = require('electron');
const { spawn } = require('child_process');
const path = require('path');

let flaskProcess;
let mainWindow;
let tray;

function startFlask() {
  flaskProcess = spawn('python3', [path.join(__dirname, '../backend/run.py')], {
    env: { ...process.env, FLASK_ENV: 'production' }
  });
  // 等待端口就绪后加载
  waitForPort(5001).then(() => {
    mainWindow.loadURL('http://localhost:5001');
  });
}

function createWindow() {
  mainWindow = new BrowserWindow({
    width: 1400, height: 900,
    webPreferences: { nodeIntegration: false }
  });
  // 关闭时最小化到托盘
  mainWindow.on('close', (e) => { e.preventDefault(); mainWindow.hide(); });
}

app.whenReady().then(() => {
  startFlask();
  createWindow();
  createTray();
});

app.on('before-quit', () => {
  flaskProcess && flaskProcess.kill();
});
```

## 五、决策建议

| 您更看重 | 推荐方案 |
|:---------|:---------|
| 现在立刻开发，不想改架构 | **方案A — 当前规划**（打包阶段再选） |
| 轻量级，去掉浏览器感就行 | **方案C — PyWebView** |
| 完整的桌面软件体验 | **方案B — Electron** |

**我的建议：** 先按方案A继续开发（不影响现有工作流），到了集成交付阶段前，花 1-2 天尝试 PyWebView 包装。效果不满意再升级到 Electron。改载体的成本极低 —— 底层代码完全不变。

另外，不管最终选什么，Vue 项目当前做的所有 UI 交互（SPA 页面结构、组件、路由、API 调用）在 Electron/PyWebView 中完全一样，因为本质都是渲染 HTML+JS。
