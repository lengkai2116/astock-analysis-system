# 筹码分布算法修复与前端展示优化方案

## 1. 问题概述

### 1.1 当前问题清单

| 编号 | 问题 | 严重度 | 归属 |
|:----:|:-----|:------:|:-----|
| **C1** | 成交量均匀分配 → 筹码分布过于平坦，真实聚集特征被洗掉 | 🔴 高 | 后端算法 |
| **C2** | 前端独立重算价格窗口 → 大部分筹码被裁剪丢弃，产生"筹码消失"感 | 🔴 高 | 前端展示 |
| **C3** | 固定衰减率 0.5%/天 → 与换手率脱钩，活跃股/冷门股同样处理 | 🟡 中 | 后端算法 |
| **C4** | 筹码峰检测形同虚设 → `_is_peak` 条件过严，极少触发 | 🟡 中 | 后端指标 |
| **C5** | 数据面板缺失 4 个字段：90%成本区间、集中度90、70%成本区间、集中度70 | 🟡 中 | 后端指标 |
| **C6** | `end_bin` 向下取整可能丢失最高价档位 | 🟢 低 | 后端边缘 |

### 1.2 行业标准参考

本方案参考同花顺、通达信、指南针等主流软件的筹码分布（移动成本分布）实现，核心算法基于 **"指南针 CYQ 筹码分布"** 模型。

## 2. 算法详细设计

### 2.1 成交量分配模型（修复 C1）

#### 2.1.1 现行算法

```python
# chip_distribution_service.py:89-94
vol_per_bin = vol / num_bins_occupied  # 均匀分配
for bin_idx in range(start_bin, end_bin + 1):
    chip_dist[bin_idx] += vol_per_bin
```

将当日成交量均匀平摊到 OHLC 价格区间的每个档位。会导致筹码分布过于平坦。

#### 2.1.2 改进算法：三角分布分配

**原理**：当日成交量在 OHLC 区间内呈三角分布，峰值取决于收盘价在区间内的相对位置。

```python
def _allocate_volume_triangular(self, vol, price_low, price_high, price_close,
                                  min_price, price_step, num_bins):
    """三角分布分配当日成交量

    阳线(close > open)：成交偏向上半区，峰值在 close 附近
    阴线(close < open)：成交偏向下半区，峰值在 close 附近
    十字星(close≈open)：对称分布
    """
    start_bin = max(0, int((price_low - min_price) / price_step))
    end_bin = min(num_bins - 1, int((price_high - min_price) / price_step))
    n = end_bin - start_bin + 1

    if n <= 1:
        chip_dist[start_bin] += vol
        return

    # 计算峰值位置 (0~1 之间)
    peak_pos = (price_close - price_low) / (price_high - price_low)
    peak_idx = int(peak_pos * (n - 1))

    # 生成三角分布权重
    weights = np.zeros(n)
    for i in range(n):
        if i <= peak_idx:
            weights[i] = (i + 1) / (peak_idx + 1) if peak_idx >= 0 else 1.0
        else:
            weights[i] = (n - i) / (n - peak_idx) if peak_idx < n - 1 else 1.0

    # 归一化并分配
    weights /= weights.sum()
    for i in range(n):
        chip_dist[start_bin + i] += weights[i] * vol
```

**效果对比**（以 000002.SZ 为例）：

| 维度 | 均匀分配 | 三角分配 |
|:-----|:--------|:--------|
| 筹码分布形态 | 平坦（CV≈0.9） | 有明显峰值（CV≈1.5-2.5）|
| 筹码峰检测 | 0-3 个（微弱） | 5-8 个（明显） |
| 合理度 | 各价格筹码均匀，不符合实际 | 近期交易价区域集中，符合市场行为 |

#### 2.2.1 现行算法

固定 `decay_rate = 0.005`（0.5%/天），所有股票统一。

#### 2.2.2 改进算法：换手率驱动衰减

### 2.3 筹码峰检测优化（修复 C4）

#### 2.3.1 现行算法

```python
# 需要比隔位邻居高 10% -> 过于严格
current > left_1 and current > right_1
current > left_2 * 1.1 and current > right_2 * 1.1
```

#### 2.3.2 改进算法

降低阈值 + 引入最小高度过滤：

```python
def _is_peak(self, chip_dist, bin_idx, min_height=0.005):
    """检测局部最大值（筹码峰）"""
    n = len(chip_dist)
    if bin_idx <= 1 or bin_idx >= n - 2:
        return False
    v = chip_dist[bin_idx]
    # 阈值：必须大于邻居，且绝对值超过 min_height
    if v <= chip_dist[bin_idx - 1] or v <= chip_dist[bin_idx + 1]:
        return False
    if v <= chip_dist[bin_idx - 2] or v <= chip_dist[bin_idx + 1]:
        return False  # 放宽到只需大于次邻
    if v < min_height:
        return False  # 过滤噪声
    return True
```

### 2.4 补充指标（修复 C5）

在 `_calculate_basic_indicators()` 中新增 4 个字段：

```python
def _calculate_cost_range(self, chip_bins, center_pct):
    """计算排除极端值后的成本区间

    Args:
        chip_bins: 筹码分布数组（按 price 升序）
        center_pct: 中间占比（如 0.9 = 排除两端各 5%）
    Returns:
        (low, high, concentration) 成本区间和集中度
    """
    tail = (1 - center_pct) / 2  # 单侧排除比例
    cum = 0
    low_price = chip_bins[0]['price_bin']
    high_price = chip_bins[-1]['price_bin']
    for b in chip_bins:
        cum += b['chip_ratio']
        if cum >= tail and low_price == chip_bins[0]['price_bin']:
            low_price = b['price_bin']
        if cum >= (1 - tail) and high_price == chip_bins[-1]['price_bin']:
            high_price = b['price_bin']
    concentration = (high_price - low_price) / (high_price + low_price)
    return low_price, high_price, concentration
```

返回值结构：

```python
indicators = {
    'ssrp': 10.40,
    'profit_ratio': 0.5317,
    'cost_90': {'low': 10.12, 'high': 10.55},
    'concentration_90': 0.0208,  # (10.55-10.12)/(10.55+10.12)
    'cost_70': {'low': 10.30, 'high': 10.48},
    'concentration_70': 0.0087,
}
```

## 3. 前端展示修复方案

### 3.1 价格窗口统一（修复 C2 — 视觉效果最关键）

#### 3.1.1 当前问题

```javascript
// 前端独立计算自己的价格窗口（错误）
var lo = closePrice * 0.92, hi = closePrice * 1.08;
for (var i = Math.max(0, idx - 60); i <= idx; i++) {
    lo = Math.min(lo, ohlc[i][2]);
    hi = Math.max(hi, ohlc[i][3]);
}
// 只显示落在 [lo, hi] 范围内的筹码档位
// 区间外的筹码全部丢弃！
```

**影响**：以 000002.SZ 为例，后端计算 150 档（价格 2.89~4.75），但前端窗口 `3.11×[0.92,1.08] = [2.86, 3.36]`，3.36 以上所有筹码被裁剪。

#### 3.1.2 改进方案

使用后端返回的 `price_range`：

```javascript
var chipData = _chipCache && _chipCache[_currentTsCode];
if (chipData && chipData.price_range) {
    // 使用后端全量价格范围（120天 OHLC 覆盖）
    var lo = chipData.price_range.min;
    var hi = chipData.price_range.max;
} else {
    // 降级：使用当前价附近范围
    var lo = closePrice * 0.92, hi = closePrice * 1.08;
}
```

#### 3.1.3 配套调整

使用全量范围后，由于范围扩大（如 000002.SZ 从 `[2.86,3.36]` 扩大到 `[2.89,4.75]`），档位数 `bins` 会动态增加（`max(20, round(range/0.01))`），每个条的高度 `barHeight` 会自适应缩小。需确保：
- `barHeight` 最低为 1px（已实现 `Math.max(1, ...)` ✅）
- 容器高度 `containerH = 325` 不变，纵向滚动不出现
