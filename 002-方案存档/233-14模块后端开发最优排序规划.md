## 四、各阶段详细理由

### 为什么 225 系统管理排第一？

| 理由 | 说明 |
|:-----|:-----|
| 底盘级交付 | RuntimeConfigManager + APScheduler + daily_close_sync 是全站基础设施 |
| 最高就绪度 | ~77%（16/22端就绪），开发风险最低 |
| 配置先行 | 所有后续模块的配置读取、定时调度、数据同步均依赖它 |
| 用户首次体验 | 用户安装后第一步就是配置系统（Token/API Key/同步计划）|

### 为什么 219 因子管理排第三？

| 理由 | 说明 |

| 214选股硬依赖 | 选股系统L3层★硬约束要求从因子管理动态获取因子组合 |
| 快速产出 | 3天完成，用户即可浏览500+因子库 |
