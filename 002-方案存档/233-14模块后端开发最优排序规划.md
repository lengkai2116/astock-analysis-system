# 14 模块后端开发最优排序规划

> **总工时：** ~65 人日（~3 人月）
> **关键路径：** 225→215→218→221→226 = 37 天（决定最短完工周期）
> **排序原则：** ① 基础设施先行 ② 依赖链优先 ③ 难度交替 ④ 尽早可见成果

## 二、开发排序（6 阶段 / 14 模块）

### 阶段一：基础设施 + 数据管道验证（~8 天）

> **目标：** 交付全部底盘级能力 + 验证三层数据管道可用

| 序号 | 模块 | 工时 | 依赖 | 本阶段交付的底盘能力 |
|:----:|:-----|:----:|:----:|:--------------------|
| ① | **225 系统管理** | ~3天 | 无 | RuntimeConfigManager / APScheduler / daily_close_sync / 定时配置5端点 / Config接入 / Alembic初始化 |
| ② | **213 仪表盘** | ~2天 | ① | 验证数据管道端到端（AKShare盘中→Tushare盘后→DuckDB缓存→API→前端）|
| ③ | **219 因子管理** | ~3天 | 无 | 12/12端全量就绪，仅前端对接。可与②并行 |

**阶段产出验证：**
- ①完成后：Tab②定时调度配置可保存、日终同步可自动触发、RuntimeConfigManager可读写
- ②完成后：仪表盘展示真实指数行情+涨跌榜+资金流向（非Mock数据）
- ③完成后：因子库500+因子可浏览/搜索/组合

**难度曲线：** 中→低→低 ✅（以基础设施为主，穿插简单模块）

**可见成果：** 系统管理UI + 仪表盘真实数据 + 因子浏览器

---

### 阶段二：核心分析能力（~14 天）

> **目标：** 建立策略引擎的完整API消费链路，产出可展示的分析结果

| 序号 | 模块 | 工时 | 依赖 | 说明 |
|:----:|:-----|:----:|:----:|:-----|
| ④ | **214 选股系统** | ~3天 | ①③ | ★硬依赖219因子L3（已就绪）。L1/L2筛选+L3因子组合 |
| ⑤ | **220 策略模板** | ~5天 | ① | 11策略种子数据+CRUD+策略引擎绑定。可与④并行 |
| ⑥ | **215 个股策略分析** | ~6天 | ①③ | 策略引擎首个完整消费者：28字段实时+5策略分析+芯片分布 |

**阶段产出验证：**
- ④完成后：选股系统可运行三层筛选（L1达尔文+L2技术+L3因子），产出真实选股结果
- ⑤完成后：11个系统策略可浏览/编辑/复制，策略参数持久化
- ⑥完成后：个股详情页展示真实策略分析结论（缠论/量价/筹码/BOCIASI/StatusRecognition）

**难度曲线：** 中→中高→高 ✅（逐步加深，⑥是第一个重量级模块）

**可见成果：** 选股结果 + 策略模板库 + 个股策略分析报告

**⚠️ 关键里程碑：** ⑥完成后，策略引擎的完整API链路已打通，后续回测/沙箱/复盘均可启动

### 阶段三：验证体系（~16 天）

> **目标：** 构建策略验证闭环（回测→沙箱→复盘→账户）

| 序号 | 模块 | 工时 | 依赖 | 说明 |
|:----:|:-----|:----:|:----:|:-----|
| ⑦ | **218 回测系统** | ~8天 | ①⑥ | 横截面聚合层+Flask路由+格式适配+7个APScheduler任务激活 |
| ⑧ | **222 策略沙箱** | ~3天 | ⑤⑦ | 复用回测引擎信号生成模块，单策略轻量测试 |
| ⑨ | **223 报告中心** | ~2天 | ① | 被动存储层，先建框架+routing v2→v3。可与⑧并行 |
| ⑩ | **216 自选监控** | ~3天 | ①⑥ | WebSocket实时推送+策略评分刷新。可与⑧⑨并行 |

**阶段产出验证：**
- ⑦完成后：可运行任意策略的历史回测，产出净值曲线/赢率/T+5/10/20检查点
- ⑧完成后：可快速测试单个策略参数变体的表现（无需完整回测流程）
- ⑨完成后：报告列表/详情/搜索/下载/删除可用，上游模块可写入
- ⑩完成后：自选股列表实时行情推送+日终策略评分更新

**难度曲线：** 高→中→低→低 ✅（回测是最复杂的，后面递减恢复节奏）

**可见成果：** 回测报告 + 沙箱测试 + 报告存档 + 自选实时行情

**⚠️ 关键里程碑：** ⑦完成后，策略验证引擎就绪；⑧⑨⑩为轻量模块，快速推进

### 阶段四：高阶分析（~23 天）

> **目标：** 交付最高复杂度的分析模块，完成系统核心能力

**⚠️ 关键里程碑：** ⑪复盘中心完成后，关键路径上的最后一环打通，仅剩⑬账户管理

## 四、各阶段详细理由

### 为什么 225 系统管理排第一？

| 理由 | 说明 |
|:-----|:-----|
| 底盘级交付 | RuntimeConfigManager + APScheduler + daily_close_sync 是全站基础设施 |
| 最高就绪度 | ~77%（16/22端就绪），开发风险最低 |
| 配置先行 | 所有后续模块的配置读取、定时调度、数据同步均依赖它 |
| 用户首次体验 | 用户安装后第一步就是配置系统（Token/API Key/同步计划）|

### 为什么 219 因子管理排第三？

| 理由 | 说明 |
|:-----|:-----|
| 12/12端全量就绪 | 后端就绪度100%，仅需前端对接，零风险 |
| 214选股硬依赖 | 选股系统L3层★硬约束要求从因子管理动态获取因子组合 |
| 快速产出 | 3天完成，用户即可浏览500+因子库 |

### 为什么 215 个股策略分析排第六（阶段二末尾）？

| 理由 | 说明 |
|:-----|:-----|
| 策略引擎首消费者 | 是策略引擎（缠论/量价/筹码/BOCIASI/StatusRecognition）的首个完整API消费者 |
| 回测系统前置 | 218回测系统的信号源来自个股策略分析的UPF→ConflictArbiter→UIDF链路 |
| 复盘中心前置 | 221复盘中心的复盘池来自个股策略分析的"加入复盘池"操作 |
| 需要因子数据 | 分析输入依赖219因子管理提供的因子计算结果 |

### 为什么 218 回测系统排第七？

| 理由 | 说明 |
|:-----|:-----|
| 依赖215信号源 | 回测需要逐日期运行策略完整链路，信号来自个股策略分析 |
| 激活7个APScheduler任务 | scheduler.py已有的月度评估/周度检查/健康巡检在此模块激活 |
| 沙箱和报告的前置 | 222沙箱复用回测引擎，223报告中心接收回测报告归档 |

### 为什么 221 复盘中心排第十一（阶段四开头）？

| 理由 | 说明 |
|:-----|:-----|
| 全站最高复杂度 | ~10天，含模拟引擎日推进+九维/五层诊断算法 |
| 依赖链最长 | 225→215→218→221，需要日终同步事件+策略信号+回测数据 |
| 账户管理前置 | 226账户管理的六维复盘引用复盘中心的RV-xxx诊断结论 |
| 放在阶段四的理由 | 此时所有上游数据就绪（日终同步/策略信号/回测引擎），可专注核心算法 |

### 为什么 224 监控通知排最后？

| 理由 | 说明 |
|:-----|:-----|
| 全站工作量最大 | ~13天，放最后避免阻塞其他模块 |
| 条件库已交付 | 225号开发时已交付conditions.py CRUD，224号仅需规则引擎+推送 |
| 独立性强 | 规则引擎+推送管道是独立子系统，不影响其他模块 |
| 可分Phase交付 | Phase 1(规则CRUD)→Phase 2(推送)→Phase 3(评估)，逐步交付 |

## 五、风险缓解策略

### 5.1 关键路径风险

| 风险点 | 影响 | 缓解措施 |
|:-------|:-----|:---------|
| 221复盘中心超期 | 阻塞226账户管理 | Phase 0先搭模拟引擎框架(~3天)，九维诊断可分批实现 |
| 218回测系统复杂度高 | 阻塞222沙箱 | Phase 1先实现单股票回测(~5天)，横截面聚合放Phase 2 |
| 215个股策略引擎集成困难 | 阻塞218/221 | 策略引擎代码已85%就绪，先暴露简化版API，逐步补全 |

### 5.2 并行窗口利用

在等待关键路径模块完成时，利用空闲窗口穿插低风险模块：

```
等待218回测开发时 → 穿插223报告中心框架(2天) + 216自选监控(3天)
等待221复盘开发时 → 穿插217 AI投研(8天，独立于复盘中心)
等待224监控开发时 → 全模块联调 + 缺陷修复
```

### 5.3 降级策略

| 模块 | 完整功能 | MVP降级 | 降级后工时 |
|:-----|:---------|:--------|:----------:|
| 221复盘中心 | 九维诊断+模拟引擎 | 模拟引擎+三维诊断(其余Mock) | ~6天 |
| 224监控通知 | 5类规则+微信推送 | 价格规则+桌面通知(其余Phase 2) | ~7天 |
| 217 AI投研 | 多角色+情景推演 | 单角色分析+基础LLM调用 | ~4天 |
| 218回测系统 | 横截面+T+N检查 | 单股票回测+基础绩效 | ~5天 |
