# 405号 — dim6数据访问路径统一与架构修正方案

---

## 一、问题背景

dim6 在 daemon 的 `_precompute_strategy_signals()` 中被调用**两次**，两次传入的标签来源不同，导致分析结果不一致、大量计算资源浪费、架构不符合353号方案设计原则。

### 两次调用对比

| | 第一次（旧路径） | 第二次（新路径） |
|---|---|---|
| 调用入口 | `SignalComputationService.compute_via_engines()` | `StatusEngine._build_dim_engine_results()` |
| 代码位置 | signal_computation_service.py 行191 | status_engine.py 行281（daemon 行4756调用） |
| tags 来源 | `_load_market_context()` → daily_basic_cache | `_load_tags()` → pre_feat_cache |
| 标签完整性 | 缺失 risk_level / volatility_level / fina_health / catalyst_event / main_force_phase / valuation_level / sentiment_phase（8个核心标签） | 基本完整（缺 turnover_rate / right_side_confirm） |
| 对 dim6 结果的消费 | 只取 judgment.level + continuous_value + status_description.risk_level（3个值），其余20+字段丢弃 | 完整保留 status_description + judgment + audit |
| 产出去向 | strategy_signal_detail.signal_json | strategy_signal_detail.dim_results_json |
| dim6 风险等级检测 | ❌ 大部分空转（核心标签缺失） | ✅ 正常运行 |

### 根因

第一次调用是353号方案之前的旧体系遗留——dim6 作为"风险警示"信号源混入 signal_json。353号方案新增 `_build_dim_engine_results` 维度引擎路径后，dim6 又在新路径中被调用一次，但旧路径的调用未被删除。

---

## 二、353号方案架构原则核查

| 原则 | 353号定义 | dim6 当前状态 | 符合度 |
|------|----------|-------------|--------|
| RAW 层预计算 | 非分析类纯计算在日终批量完成，写入存储层 | calc_geometric / _calc_volatility / EventMonitor.detect_all() 在 dim6 内部实时执行 | ⚠️ 未覆盖 |
| SIG 层读取预计算结果 | 维度引擎从存储层读取预计算数据 | dim6 部分从 pre_feat_cache 读取，部分自行实时计算 | ⚠️ 半覆盖 |
| 单次调用 | 同一引擎只运行一次 | dim6 被调用两次（旧路径 + 新路径） | ❌ 重复 |
| DataManager 唯一网关 | 所有数据通过存储层分库 | 13张表全部在存储层分库 | ✅ 符合 |
| 预计算是运行原则 | 日终空闲窗口批量完成后台处理 | dim6 在 daemon SIG 管道中预计算 | ✅ 符合 |

**补充说明**：`dims['l0']` 始终为空（404号 DATA-04 已记录），导致 `_assess_risk_level` 和 `_list_risk_factors` 中的 hard_veto / soft_risks 检测为死代码。这是 T42 修复的已知设计限制（消除循环依赖），本次修正方案不涉及此问题，修正后状态不变。

## 三、修正方案

### 建议1（P0）：剔除旧路径的 dim6 调用

**原因**：第一次调用 tags 不完整，8个核心标签缺失导致风险等级/波动率/财务健康等检测全部空转，产出的"风险警示"信号质量低下。且与第二次调用重复执行相同的计算，浪费资源。

**操作**：

删除 `signal_computation_service.py` 中行188-206 的 dim6 调用：

```python
# 删除以下代码块
# dim6: 风险边界
try:
    from app.opportunity_atlas.dimensions.dim6_risk_engine import Dim6RiskEngine
    r6 = Dim6RiskEngine().evaluate(dims, tags, lifecycle=lifecycle or {})
    ...
except Exception as e:
    logger.debug(f"dim6引擎调用失败: {e}")
```

`compute_via_engines` 只保留5个策略引擎（缠论/量价/筹码/情绪/因子），signal_json 中不再有"风险警示" signal entry。

**影响评估**：JUD-2 步骤5（SIG信号消费）原本从 signal_json 读取 risk 信号。剔除后，JUD 步骤6（维度引擎判定）从 dim_results_json 读取的 dim6 完整结果（judgment.level / light / direction / continuous_value）已完全覆盖 signal_json 中"风险警示"的所有信息。

**工时**：0.1天

### 建议2（P0）：统一两份 EventMonitor 为一份

**原因**：当前存在两份 EventMonitor 代码：

| | 独立模块 | 内嵌版本 |
|---|---|---|
| 文件 | event_monitor.py（925行） | dim6_risk_engine.py 行426~1313（~900行） |
| 调用方 | RAW-2（daemon 行2730） | dim6.evaluate()（行1996） |
| 调用方式 | `compute_tags()` — 摘要 | `detect_all()` — 完整检测 |
| 产出 | 5个摘要字段 | 完整事件列表 + 结构化详情 |

两份代码功能重复，369号方案物理合入时将完整代码复制进 dim6，未复用已有独立模块。

**操作**：

- dim6_risk_engine.py 中删除内嵌的 EventMonitor 类（行426~1313）
- dim6.evaluate() 中删除 `monitor.detect_all(ts_code)` 调用（行1996-2005）
- dim6 改为从 tags（pre_feat_cache）读取 RAW-2 已预计算的事件标签
- 统一使用 event_monitor.py 中的独立 EventMonitor

**前提**：建议2 的执行依赖建议5（扩展独立 EventMonitor.compute_tags 产出）先行完成。只有当独立版本的 compute_tags 产出覆盖了 dim6 所需的全部事件字段后，才能安全删除内嵌版本。因此实施顺序为：建议5 → 建议2。

**工时**：0.5天

### 建议3（P2）：calc_geometric 预计算并存入存储层

**原因**：`calc_geometric`（支撑位/阻力位/盈亏比/信号天数）是纯数学计算，不涉及分析判断，符合 RAW 层预计算定义。当前每次 dim6 调用都从 daily_cache 实时计算，违反"SIG 层读取预计算结果"原则。calc_geometric 只存在于 dim6_risk_engine.py（行119），不在 RAW 中。

**可行性验证**：
- 输入：仅需 `df`（daily_cache OHLCV），需含 close/high/low 列 + 最少20行 → RAW-2 中 `df` 已满足
- 输出：7个字段（support_price / resistance_price / dist_to_support_pct / dist_to_resistance_pct / dist_to_prev_high_pct / risk_reward / signal_days）
- 外部依赖：无（纯 pandas 计算）
- calc_geometric 是模块级函数（行119），不依赖类实例 → daemon import 安全

**工时**：0.3天

---

### 建议4（P2）：_calc_volatility 纳入 RAW 预计算

**原因**：RAW 已有 `_calc_volatility_percentile`（波动率分位数），dim6 额外计算 ATR 14日和 ATR 百分比。三者都是从 daily_cache OHLCV 计算的纯数学指标，应统一在 RAW 预计算。

**可行性验证**：
- 输入：`df`（daily_cache）+ `tags`（可选，用于读取 volatility_level）
- 输出：4个字段（level / atr_14d / atr_pct / percentile）
- 外部依赖：无（纯 pandas + numpy 计算）
- **tags 参数说明**：`_calc_volatility` 行196 从 tags 读取 `volatility_level` 作为 `level` 字段。在 RAW-2 中调用时 tags 传空 `{}`，`level` 默认 `'medium'`。这不影响核心逻辑——dim6 的 `_assess_risk_level`（行243）从 tags 读取 `volatility_level`，与 `_calc_volatility` 返回的 `level` 是独立的。`level` 仅用于 status_description 展示字段。

**操作**：

建议3和建议4合并实施——在 daemon RAW-2 的"风险边界扩展字段"组（行2479-2488）中替换原有 `_calc_volatility_percentile`，统一为完整计算：

```python
# 12. 风险边界扩展字段（365号批次A / Phase 2 → 405号扩展）
_risk_feat = {}
if len(df) >= 20:
    # 建议4：替换 _calc_volatility_percentile 为完整 _calc_volatility
    from app.opportunity_atlas.dimensions.dim6_risk_engine import _calc_volatility
    vol = _calc_volatility(df=df)  # tags 传空，level 默认 medium
    _risk_feat['vol_atr_14d'] = vol.get('atr_14d')
    _risk_feat['vol_atr_pct'] = vol.get('atr_pct')
    _risk_feat['volatility_level'] = vol.get('level')
    _risk_feat['volatility_percentile'] = vol.get('percentile')
    # 建议3：新增 calc_geometric
    from app.opportunity_atlas.dimensions.dim6_risk_engine import calc_geometric
    geo = calc_geometric(df)
    for k, v in geo.items():
        _risk_feat[f'geo_{k}'] = v
else:
    _risk_feat['volatility_percentile'] = None
features['risk_ext'] = _risk_feat
```

原有的 `_calc_volatility_percentile` 局部函数（daemon 行2142-2153）可删除。

dim6.evaluate() 从 tags 读取 `geo_*` / `vol_*` 字段，不再自行调用 calc_geometric 和 _calc_volatility。

**工时**：0.2天（与建议3 合并后）

### 建议5（P1）：迁移商誉检测器 + 扩展独立 EventMonitor.compute_tags 产出

**前提发现**：核查发现内嵌版本（dim6）有21个检测器，独立版本（event_monitor.py）只有20个——缺失 `_detect_goodwill_risk`（C4 商誉暴雷风险）。dim6 行2005-2010 对商誉风险有特殊处理（直接将风险等级提升为"高"）。删除内嵌版本前必须先迁移此检测器。

**操作**：

**步骤1**：将 `_detect_goodwill_risk` 方法从 dim6_risk_engine.py 迁移至 event_monitor.py 的 EventMonitor 类中。同时在 detect_all 的 detectors 列表中添加：

```python
# event_monitor.py detect_all() detectors 列表中添加（C 监管组）
('goodwill_risk', self._detect_goodwill_risk),
```

迁移后独立版本拥有完整21个检测器，与内嵌版本对齐。

**步骤2**：扩展 `event_monitor.py` 中 `compute_tags()` 的产出，增加供 dim6 消费的完整事件数据：

```python
def compute_tags(self, ts_code: str) -> dict:
    result = self.detect_all(ts_code)
    tags = {
        'catalyst_event': result['catalyst_event'],
        'catalyst_impact': result['catalyst_impact'],
        'event_composite_score': result['event_composite_score'],
        'upward_driver': result.get('upward_driver', 'no_upward'),
        # 新增：供 dim6 消费的完整事件数据
        'event_count': len(result.get('events', [])),
        'event_details': [
            {
                'event_type': e.get('event_type', ''),
                'description': e.get('description', ''),
                'direction': e.get('direction', 0),
                'confidence': e.get('confidence', 0),
                'event_date': e.get('event_date', ''),
            }
            for e in result.get('events', [])[:5]
        ],
        'event_risk_factors': [
            {
                'category': '事件风险',
                'factor': e.get('event_type', ''),
                'severity': '高' if abs(e.get('direction', 0)) >= 2 else '中',
                'satisfied': True,
            }
            for e in result.get('events', [])
            if e.get('detected')
        ],
    }
    # ... 原有 event_summary 逻辑保持不变
```

这些字段写入 pre_feat_cache.event 组。dim6 从 tags 读取，不再自行运行 detect_all()。

**可行性验证**：
- detect_all() 返回的 events 列表中每个事件包含 event_type / detected / direction / confidence / source / description / event_date → 所有扩展字段数据源充分
- event_date 格式为字符串（`self._today_str()` 输出 `YYYYMMDD`）→ JSON 序列化安全
- event_details 限制 `[:5]` → 写入 pre_feat_cache 时不会过大

**工时**：0.5天（含迁移 + 扩展）

### 建议6（P1）：修复 turnover_rate 断链

**原因**：404号 DATA-02 已记录——tag_extractor 的三个深度提取器均不产出 turnover_rate，dim6 的流动性风险检测永远不触发。

**操作**：

在 `tag_extractor.py` 的 `extract_fund_risk_tags()` 中补充 turnover_rate：

```python
def extract_fund_risk_tags(ts_code: str) -> dict:
    """提取资金风险标签"""
    tags = {}
    # ... 现有逻辑 ...
    # 新增：从 daily_basic_cache 读取换手率
    try:
        from app.data import DataManager
        dm = DataManager()
        df_basic = dm.get_cached_daily_basic(ts_code)
        if df_basic is not None and not df_basic.empty:
            latest = df_basic.iloc[-1]
            tags['turnover_rate'] = float(latest.get('turnover_rate')) if pd.notna(latest.get('turnover_rate')) else None
    except Exception:
        tags['turnover_rate'] = None
    return tags
```

## 四、修正后的数据流

```
RAW-2（日终预计算）
  ├── calc_geometric(df)              → risk_ext.geo_* (7字段)
  ├── _calc_volatility(df)            → risk_ext.vol_* (4字段)
  └── EventMonitor.compute_tags()     → event.* (8字段，含扩展)
     （21个检测器，含迁移后的商誉风险检测）

pre_feat_cache（存储层）
  ├── risk_ext: {volatility_percentile, vol_atr_14d, vol_atr_pct, volatility_level, geo_*...}
  ├── event: {catalyst_event, event_count, event_details, event_risk_factors...}
  ├── depth: {turnover_rate（修复后）, main_force_phase...}
  └── valuation/sentiment/chanlun/chip/...

dim6.evaluate()（SIG环节，单次调用）
  输入：tags（pre_feat_cache 扁平化）+ dims
  内部：只做分析判断逻辑（风险等级评估/失效条件/失效判定），不做数据计算
  输出：status_description + judgment + audit
  写入：strategy_signal_detail.dim_results_json（供JUD消费）
```

**关键变化**：
- dim6 不再直读 daily_cache（calc_geometric / _calc_volatility 不再实时计算）
- dim6 不再运行 EventMonitor.detect_all()（从 tags 读取预计算结果，含商誉风险）
- dim6 从"半实时分析引擎"变为"纯分析判定器"
- dim6 只被调用一次（_build_dim_engine_results），结果完整保留供JUD消费
