## 1. 页面结构概览

个股策略分析页面是系统的**核心分析引擎**，提供个股级 K 线技术分析 + 多维度策略现状识别 + AI 交叉验证与仲裁的全链路分析能力。

### 1.1 区块布局


### 1.2 数据加载流程

```
用户操作 → switchStock(tsCode) 触发
  │
  ├─ 1️⃣ GET /api/v3/chart/kline/{tsCode}?limit=200
  │   ├─ header-bar: chart-title, latest-price, latest-pct, MA values
  │   └─ K-line data (200 bars) → ECharts setOption (⏳ not yet auto-connected)
  │
  ├─ 2️⃣ GET /api/v3/stock/{tsCode}/quote → right panel 28 fields (P0待建)
  ├─ 3️⃣ GET /api/v3/stock/{tsCode}/orderbook → order book 10 rows (P1待建)
  ├─ 4️⃣ GET /api/v3/stock/{tsCode}/moneyflow → money flow + sub-orders + 5d (P1待建)
  ├─ 5️⃣ GET /api/v3/chip/distribution/{tsCode} → chip panel (P2待建, backend已有)
  ├─ 6️⃣ POST /api/v3/strategy/analyze → strategy cards 1-5 (P1待建)
  │                     └─ → POST /api/v3/ai/status-interpret → AI narratives (P0✅已有后端)
  └─ 7️⃣ POST /api/v3/strategy/status-aggregate → cross-verify + dimension relations (P1待建)

当前状态：仅 #1 header-bar 已动态化；#2〜#7 全量 Mock
```

### 2.3 筹码分布 API（P2）

#### E11 `GET /api/v3/chip/distribution/{tsCode}` — **筹码分布**（P2）

> **后端已有能力：** `ChipDistributionEstimator` ✅、`ChipDistributionService.calculate_chip_distribution()` ✅、`ChipIndicators` ✅、缓存表 `chip_distribution_cache` ✅
> **仅缺 API 路由暴露**

**参数：** `?date=2026-06-30`（可选，默认最新交易日）

**响应 JSON Schema：**
```json
{
  "code": 0,
  "data": {
    "ts_code": "000762.SZ",
    "trade_date": "2026-06-30",
    "chip_bins": [
      {"price": 12.10, "volume_pct": 0.15},
      {"price": 12.11, "volume_pct": 0.18},
      ...
    ],
    "profit_ratio": 42.0,
    "cursor_profit_ratio": 52.3,
    "avg_cost": 12.50,
    "cost_90": {"low": 11.50, "high": 13.50},
    "concentration_90": 8.44,
    "cost_70": {"low": 11.90, "high": 13.10},
    "concentration_70": 5.71
  }
}
```

**说明：** `chip_bins` 为价格档位数组，前端用 `Math.max(20, round(range/0.01))` 档位渲染水平柱状条。`profit_ratio` 为获利比例，`avg_cost` 为平均成本。`concentration_90` 和 `concentration_70` 越小表示筹码越集中。

**缓存策略：**
| 缓存位置 | TTL | 备注 |
|:---------|:----|:------|
| DuckDB `chip_distribution_cache` | 按 ts_code + trade_date | 基于 OHLCV 估算 |
| 前端 | 无额外缓存 | 每次股票切换或日期变化重新请求 |

### 4.2 生产环境 switchStock() 伪代码

```javascript
async function switchStock(tsCode){
  // Step 1: 前端状态重置
  _currentTsCode = tsCode;
  updateCodeInput(tsCode);
  updateStockStatus(tsCode);

  // Step 2: 并行请求全部 7 个数据区
  const [klineRes, quoteRes, orderbookRes, moneyflowRes, chipRes] = await Promise.all([
    fetch(`/api/v3/chart/kline/${tsCode}?limit=200`),
    fetch(`/api/v3/stock/${tsCode}/quote`),
    fetch(`/api/v3/stock/${tsCode}/orderbook`),
    fetch(`/api/v3/stock/${tsCode}/moneyflow`),
    fetch(`/api/v3/chip/distribution/${tsCode}`)
  ]);

  // Step 3: 解析并分发
  const klineData = await klineRes.json();
  const quoteData = await quoteRes.json();
  const orderbookData = await orderbookRes.json();
  const moneyflowData = await moneyflowRes.json();
  const chipData = await chipRes.json();

  // Step 4: 更新各面板
  updateHeaderBar(klineData.data.stock, klineData.data.latest);
  switchChartData(klineData.data.kline);       // K线 + 副图 + 叠加
  updateSidePanel(quoteData.data);              // 右侧 28 字段
  updateOrderBook(orderbookData.data);          // 盘口 10 行
  updateMoneyFlow(moneyflowData.data);          // 资金流向
  updateChipChart(chipData.data);              // 筹码分布

  // Step 5: 触发策略分析（异步，非阻塞）
  triggerStrategyAnalysis(tsCode);
}
```
