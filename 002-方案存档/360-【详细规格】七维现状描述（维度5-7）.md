## 第5维：情绪环境状态（已确认）

### 5.1 维度定位

- **核心问题**："现在是不是好时候"
- **主责引擎**：MarketSentimentService + BOCIASI四象限 + SectorRotationModel + VolumePriceStrategy
- **辅助引擎**：EventMonitor、ChipIndicators（情绪拥挤度）
- **数据来源**：daily_cache + sentiment_pool_cache + margin_cache + stk_limit_cache + daily_basic_cache + concept_cache
- **独特价值**：描述市场/板块/个股三个层面的情绪状态，为其他维度的信号提供环境背景
- **设计原则**：
  - 纯描述维度，不生成买卖信号（信号由第1维负责）
  - 市场情绪和个股情绪是两个独立层面，各自有专属指标（LLM Wiki框架）
  - 双轨输出：现状描述（条件事实）+ 结论判定（红绿灯）
  - 不约束用户总仓位（总仓由用户自行决定），仅描述情绪状态

### 5.2 三个层面

| 层面 | 核心问题 | 回答内容 |
|------|---------|---------|
| **A. 市场情绪** | 整体市场是什么氛围 | 情绪周期阶段、涨停生态、BOCIASI四象限、情绪温度 |
| **B. 板块情绪** | 该股所在板块是否在风口 | 板块热度、轮动状态、龙头状态 |
| **C. 个股情绪** | 这只股票自己的情绪状态 | 量价形态打分、四类八种状态、情绪拥挤度、换手率异常 |

### 5.3 各层面详细规格

#### A. 市场情绪（整体市场氛围）

##### A1. 情绪周期阶段

**LLM Wiki依据**：《情绪周期四阶段模型》（约投顾系统）+《情绪周期六段论》（国盛证券2022）+《情绪周期各阶段经验性时长》（2018-2025统计）

**六段论划分**：

| 阶段 | 量化特征 | 经验时长 | LLM Wiki来源 |
|------|---------|---------|-------------|
| **冰点** | 涨停<15家 + 炸板率>50% + 连板≤2板 + 涨停溢价<0% | 5-8天（极端12天） | 《情绪周期各阶段经验性时长》 |
| **萌芽** | 涨停开始增加 + 炸板率下降 + 3板出现 + 赚钱效应边际改善 | 3-5天 | 《情绪周期六段论》 |
| **发酵** | 涨停30-50家 + 炸板率<30% + 连板4-6板 + 赚钱效应良好 | 5-10天 | 《情绪周期四阶段模型》 |
| **高潮** | 涨停>80家 + 炸板率<20% + 连板≥7板 + 赚钱效应极好 | 2-3天（极端1.5天） | 《情绪周期四阶段模型》 |
| **退潮** | 涨停减少 + 炸板率>40% + 连板断裂 + 亏钱效应蔓延 | 5-10天 | 《情绪周期四阶段模型》 |
| **回归** | 回到冰点特征 | 循环 | 《情绪周期六段论》 |

**系统现状**：MarketSentimentService有四阶段映射（ice/recovery/climax/ebb），data_daemon有基于daily_cache的近似计算。缺炸板率/涨停溢价/首板家数/连板高度标准化。

##### A2. 涨停生态5指标

**LLM Wiki依据**：《情绪周期量化验证》核心框架（用户提供的LLM Wiki沟通内容确认）

| 指标 | 计算方式 | 阈值参考 | 系统现状 |
|------|---------|---------|---------|
| **涨停家数** | 当日涨停板个股数量 | >80=高潮；30-80=发酵；<30=退潮/冰点 | ✅ daily_cache统计 |
| **炸板率** | 炸板数÷(涨停数+炸板数) | <20%=强势；20-40%=正常；>40%=退潮 | ⚠️ 有近似封板率 |
| **涨停溢价** | 昨日涨停股今日平均涨幅 | >3%=赚钱效应强；0-3%=中性；<0%=亏钱效应 | ❌ 缺失 |
| **连板高度** | 最高连板股的连板数 | ≥7板=极度亢奋；4-6板=正常；≤3板=冰点 | ⚠️ sentiment_pool有 |
| **首板家数** | 当日首次涨停的个股数量 | 持续增加=萌芽；持续减少=退潮 | ❌ 缺失 |

### 7.3 用户现状描述的整理原则

#### 原则1：不简化，只整理

第七维不是将6个维度压缩为一句话，而是将6个维度的分析结果**整理为用户能看懂的直白语言**。每个维度的关键信息都要保留，但用更易读的方式呈现。

| 前6维的原始输出 | 第7维的整理输出 |
|----------------|---------------|
| `{"vp_score": 6, "vp_state": "价涨量增", "vp_detail": "量价齐升+1/均线多头+1/黑马+3"}` | "量价形态打分6/10（偏积极），当前状态'价涨量增'（健康动量类），5日趋势确认强势延续" |
| `{"risk_level": "低", "soft_risks": ["distributing"], "support": 28.2}` | "风险等级低，财务健康、流动性充足；但主力处于出货阶段需关注；防守位28.2元" |

#### 原则2：不判定，只描述

第七维不输出"该买"或"该卖"，只输出"系统看到了什么"。

| ❌ 判定性输出（不应出现） | ✅ 描述性输出（应采用） |
|------------------------|---------------------|
| "建议买入" | "突破信号已确认5天，距突破位+4%" |
| "风险可控" | "防守位28.2元（距现价-5.1%），盈亏比2.7" |
| "趋势向上" | "价格站上MA20/MA60，均线多头排列" |

#### 原则3：条件本身即现状

判定所依据的条件就是股票的客观事实状态。描述这些条件，而非描述判定结论。

| 判定结论（不应作为描述主体） | 条件/事实（应作为描述主体） |
|---------------------------|------------------------|
| "主力在建仓" | "大单5日净流入1.2亿（连续3日），筹码在集中（股东户数减少4.2%）" |
| "量价健康" | "上涨时放量（量比1.5），回调时缩量，量价关系VP-1" |
| "情绪发酵期" | "涨停58家，炸板率18.5%（强势），连板最高5板" |

#### 原则4：红绿灯三态标注

每个段落用✅/⚠️/🚫标注状态：

| 标记 | 含义 | 使用场景 |
|------|------|---------|
| ✅ | 该维度分析结果偏积极/正常 | 无重大风险、指标正常 |
| ⚠️ | 该维度有需关注的点 | 存在风险因素但非致命 |
| 🚫 | 该维度分析结果偏消极/危险 | 硬否决触发、重大风险 |

#### 原则5：条件稽核（核心原则）

**现状描述的本质是条件稽核**——对每个维度结论性输出背后的**条件、规则、逻辑**进行核查，报告：
1. **哪些条件被满足**（实际值 vs 阈值）
2. **满足了几个条件**（满足数/总数）
3. **综合判定依据**（基于哪些条件得出结论）

**条件稽核的结构**：

```
【维度名称】结论：XXX（light: green/yellow/red）

判定条件稽核：
✅ 条件1：名称 - 满足（实际值=XXX，阈值=YYY）
✅ 条件2：名称 - 满足（实际值=XXX，阈值=YYY）
❌ 条件3：名称 - 不满足（实际值=XXX，阈值=YYY）
→ 综合判定：满足X/Y条件（置信度ZZ%）

大白话：一句话总结
```

**条件来源**：各维度的条件、规则、逻辑**已配置在系统中**（yaml配置/代码逻辑/引擎规则），现状描述就是对这些配置的稽核。

**各维度条件来源**：

| 维度 | 条件来源位置 | 配置内容 |
|------|------------|---------|
| 第1维 信号确认 | `signal_registry.yaml` + `status_engine._detect_registered_signals()` | 5类信号触发条件+7类属性判断条件 |
| 第2维 结构位置 | `chanlun_strategy.py` + `advice_builder._geometric()` | 中枢位置/均线排列/支撑阻力计算规则 |
| 第3维 量价健康 | `volume_price_strategy.py` VP-1~VP-9 | 8种量价关系判定条件+健康度评分规则 |
| 第4维 资金筹码 | `phase_detector.py` + `chip_strategy_impl.py` | 主力阶段4阶段判定条件+筹码信号触发条件 |
| 第5维 情绪环境 | `market_sentiment_service.py` + `bociasi_*.py` | 情绪周期阶段/BOCIASI四象限判定条件 |
| 第6维 风险边界 | `status_engine._apply_l0()` + `event_monitor.py` | 风险等级/PIERS排雷/止损止盈条件 |

**条件稽核示例（第4维：资金与筹码状态）**：

```
【资金与筹码状态】结论：建仓期（light: green）

判定条件稽核：
✅ 条件1：低位涨停 - 满足（20日跌幅18% > 阈值15%）
✅ 条件2：非巨量涨停 - 满足（涨停日量比2.1 < 阈值3.0）
✅ 条件3：大单持续净流入 - 满足（5日净流入8200万 > 阈值5000万，连续3日）
✅ 条件4：筹码集中 - 满足（ASR=75 > 阈值50）
✅ 条件5：非高位 - 满足（价格分位35% < 阈值70%）
→ 综合判定：满足建仓期5/5条件（置信度0.85）

大白话：主力处于建仓期，因为低位出现涨停、量能温和、大单持续流入、筹码在集中、价格不在高位
```
