## 3. 存储层设计

### 3.1 数据目录选择

#### 原则

生产环境中，数据目录**不能放在应用安装目录下**，原因：
- macOS: `.app` 放在 `/Applications/` → 无权写入（SIP 保护）
- Windows: 安装到 `C:\Program Files\` → 无权写入（UAC 保护）
- 重装/升级应用时数据必须保留

#### 平台标准路径

| 平台 | 数据目录 | 说明 |
|:-----|:---------|:------|
| **macOS** | `~/Library/Application Support/Astock/` | macOS 标准应用数据目录，Time Machine 自动备份 |
| **Windows** | `%APPDATA%/Astock/` (即 `C:\Users\<用户名>\AppData\Roaming\Astock\`) | Windows 标准应用数据目录，Roaming 属性支持漫游 |

#### 目录结构

```
<DATA_DIR>/
├── app.db                   # SQLite 应用数据库
├── auth_token.txt           # 访问令牌持久化
├── duckdb/
│   ├── stock_cache.db       # DuckDB 市场数据缓存 (~180MB)
│   └── temp/                # DuckDB 临时目录
└── logs/
    └── app.log              # 应用日志 (30天轮转)
```

#### 自定义覆盖

用户可在 `.env` 中添加 `DATA_DIR=/path/to/custom/data` 覆盖默认路径。

#### 开发环境

开发时直接使用项目根目录下的 `data/` 文件夹。启动脚本在检测到开发模式时自动使用相对路径。

### 3.2 SQLite 承载能力评估

#### 预期数据量

| 数据类型 | 年增量 | 总预估 (5年) | 字段特征 |
|:---------|:-------|:-------------|:---------|
| 交易记录 | ~500-2000 条 | ~10,000 条 | 每条约 0.5KB 结构化数据 |
| 复盘报告 | ~300-500 份 | ~2,500 份 | 每份含 JSON 诊断数据 ~10KB |
| 监控规则 | ~50-200 条 | ~500 条 | 每条约 1KB（含条件配置 + 参数）|
| 通知记录 | ~5000-10000 条 | ~50,000 条 | 每条约 0.3KB |
| 报告存档 | ~100-300 份 | ~1,500 份 | 每份报告 ~5-50KB |
| 配置记录 | ~50-100 条 | ~500 条 | 每条约 0.5KB |
| **合计** | | **< 200MB** | |

#### 技术限制 vs 实际需求

| 维度 | SQLite 理论限制 | 实际需求 | 余量 |
|:-----|:---------------|:---------|:-----|
| 最大数据库大小 | 140 TB | < 200 MB | **~70 万倍** |
| 最大行数 | ~2^64 | ~65,000 条 (5年) | **~2.8亿倍** |
| 并发写入 | 1 个 writer | 1 个用户 → 1 个进程 | **恰好满足** |
| JSON 列 | TEXT 存储 (SQLAlchemy 自动序列化) | 报告/诊断/条件配置 | ✅ **完全支持** |
| 全文检索 | FTS5 扩展 | 报告搜索/规则查找 | ✅ **可选增强** |

#### 结论

**SQLite 对于单用户自用场景绰绰有余。** 当前使用 SQLAlchemy ORM 且已配置 `DATABASE_URL=sqlite:///...`，无需更换为 PostgreSQL。无需启用 WAL 模式（单进程单用户不需要并发），默认 rollback journal 模式更简单可靠。

### 3.3 DuckDB — 市场数据缓存

#### 现状

| 指标 | 值 |
|:-----|:----|
| 当前大小 | ~180 MB |
| 数据内容 | OHLCV 611万条、资金流向、日线基本面 |
| 更新模式 | Tushare 增量同步 (sync_stocks.py) |
| 写入来源 | EnhancedCacheManager |
| 读取来源 | 策略引擎 (strategies)、REST API 路由 |

#### 定位

- **OLAP 数据仓库**：专为时间序列分析优化（列式存储、向量化执行）
- **不可变数据**：Tushare 历史数据写入后只读，不会修改
- **不需要索引**：DuckDB 全表扫描 + 列式过滤的性能已足够（单用户毫秒级）

### 3.4 内存缓存替代 Redis

#### 方案

使用 `cachetools.TTLCache` 替换 `RedisCacheManager`：

```python
from cachetools import TTLCache

# 替换 RedisCacheManager：
# - Redis: import + 连接 + 序列化/反序列化 + 网络开销
# - TTLCache: 纯内存 dict, TTL 1h, maxsize=1000
# - 优势: 零依赖、零网络、比 Redis 快 100x（无序列化+无网络）
class MemoryCache:
    def __init__(self, maxsize=1000, ttl=3600):
        self.cache = TTLCache(maxsize=maxsize, ttl=ttl)
    
    def get(self, key):
        return self.cache.get(key)
    
    def set(self, key, value):
        self.cache[key] = value
```

#### 性能对比

| 维度 | Redis (当前) | TTLCache (替换后) |
|:-----|:------------|:------------------|
| 响应时间 | ~0.5ms (网络) + 序列化 | **~0.001ms (纯内存 dict)** |
| 依赖 | 需 Redis 服务 | **零依赖** |
| 持久化 | RDB/AOF 文件 | **无（DuckDB 已持久化）** |
| 容量 | 取决于 RAM | 默认 1000 条目，单用户足够 |
| 代码改动 | — | 修改 1 个文件 (enhanced_cache_manager.py) |

#### 缓存策略（不变）

| 层级 | 存储 | TTL | 数据 |
|:-----|:-----|:----|:------|
| L1 | TTLCache (内存) | 1h | 热点日线数据、策略引擎输出 |
| L2 | DuckDB (磁盘) | 持久 | 全量历史行情、基本面、资金流向 |
| L3 | Tushare API (网络) | 实时 | 当日增量、分钟级数据 |

## 4. macOS 启动方案

### 4.1 启动流程

```
用户双击 Astock.app (Platypus 封装)
  ↓
Platypus 运行内部 shell 脚本
  ↓
① 确定项目根目录 (APP_DIR = 脚本所在目录)
② 创建数据目录 (DATA_DIR = ~/Library/Application Support/Astock/)
③ 加载 .env (若存在) + 合并环境变量
④ 判断 SQLite 数据库是否存在 → 不存在则首次初始化 (tables)
⑤ 启动 Flask: python3 run.py --port 5001
⑥ 等待 health check 通过 (最多等待 15 次 × 2 秒)
⑦ open http://localhost:5001
```

### 4.2 启动脚本 (`start.command` → Platypus 内嵌)

```bash
#!/bin/bash
set -e
cd "$(dirname "$0")"

# ── 环境初始化 ──
if [ -f .env ]; then
    set -a; source .env; set +a
fi

# ── 数据目录 ──
DATA_DIR="${DATA_DIR:-$HOME/Library/Application Support/Astock}"
export DATA_DIR
mkdir -p "$DATA_DIR/duckdb/temp" "$DATA_DIR/logs"

# ── 日志 ──
LOG_FILE="$DATA_DIR/logs/start.log"
exec > "$LOG_FILE" 2>&1

echo "[$(date)] 启动 A股分析系统..."
echo "  DATA_DIR=$DATA_DIR"

# ── 数据库首次初始化 ──
SQLITE_DB="$DATA_DIR/app.db"
export DATABASE_URL="sqlite:///$SQLITE_DB"
if [ ! -f "$SQLITE_DB" ]; then
    echo "  [首次运行] 初始化数据库..."
    python3 backend/run.py --init-db
fi

# ── 启动后端 ──
python3 backend/run.py --port 5001 &
SERVER_PID=$!
echo "  PID=$SERVER_PID"

# ── 等待服务就绪 ──
for i in $(seq 1 15); do
    if curl -s -o /dev/null "http://localhost:5001/api/v3/health"; then
        break
    fi
    sleep 2
done

# ── 打开浏览器 ──
open "http://localhost:5001"
echo "[$(date)] 系统就绪 → http://localhost:5001"

# ── 保持进程（Platypus 需要前台进程）──
wait $SERVER_PID
```

### 4.3 停止脚本 (`stop.command`)

```bash
#!/bin/bash
# 优雅停止 A股分析系统
PID=$(pgrep -f "python3.*run.py")

if [ -n "$PID" ]; then
    echo "正在停止后端 (PID=$PID)..."
    kill -TERM $PID
    # 等待最多 10 秒
    for i in $(seq 1 10); do
        if ! kill -0 $PID 2>/dev/null; then
            echo "后端已停止"
            exit 0
        fi
        sleep 1
    done
    # 强制结束
    kill -KILL $PID 2>/dev/null
    echo "后端已强制停止"
else
    echo "后端未运行"
fi
```

## 8. 开发约束（开发者必须遵守）

以下约束在代码开发过程中必须始终遵循，确保与生产环境兼容。

### 8.1 SQL 兼容性

> **数据库引擎：SQLite + DuckDB（无 PostgreSQL）**

| 规则 | 说明 | 禁止项 |
|:-----|:------|:-------|
| 使用通用 SQLAlchemy ORM | 所有模型必须使用 SQLAlchemy 跨数据库通用的数据类型 | ❌ ARRAY、TSVECTOR、`func.now()`（SQLite 不兼容）|
| JSON 列使用 `db.Column(JSON)` | SQLAlchemy 自动适配 SQLite TEXT 存储 | ❌ `postgresql.JSON`、`postgresql.ARRAY` |
| 布尔值使用 `db.Boolean` | SQLAlchemy 自动映射到 SQLite 的 INTEGER(1) | ❌ 原生 BOOLEAN 类型假设 |
| 自增值使用 `db.Integer` + primary_key | SQLite 自动产生 INTEGER PRIMARY KEY 自增 | ❌ `SERIAL` 类型 |
| 时间戳使用 `db.DateTime` | SQLite 存储为 ISO 8601 字符串，SQLAlchemy 自动处理 | ❌ `TIMESTAMP WITH TIMEZONE` |
| 唯一约束使用 `UniqueConstraint` | 标准 SQLAlchemy | ✅ 通用 |

**当前代码检查结果**：✅ 所有模型文件均使用通用 SQLAlchemy 类型，无 PostgreSQL 特有类型。JSON 列使用 `db.Column(JSON)` 格式。**无需修改任何模型文件。**

### 8.2 避免使用的外部服务

| 服务 | 状态 | 替代方案 |
|:-----|:------|:---------|
| **Redis** | ❌ 不部署 | `cachetools.TTLCache` 内存缓存 |
| **Nginx** | ❌ 不部署 | Flask `send_from_directory` |
| **PostgreSQL** | ❌ 不部署 | SQLite + DuckDB |
| **Gunicorn** | ❌ 单 worker 足够 | eventlet（Flask + SocketIO 内置）|
| **Docker Desktop** | ❌ 不使用 | 裸跑 |

### 8.3 端口占用

| 端口 | 用途 | 约束 |
|:-----|:------|:------|
| 5001 | Flask 应用（唯一端口） | 必须可用，不能与其他进程冲突 |

### 8.4 数据目录

- 代码使用 `os.getenv('DATA_DIR', default)` 获取数据目录
- 不硬编码目录路径
- 配置文件（`config.py`）从环境变量读取，不从本地文件猜测

### 8.5 日志

- 日志写入 `$DATA_DIR/logs/app.log`
- 30 天轮转（`TimedRotatingFileHandler`）— 已实现 ✅
- 控制台同时输出（调试用）

### 8.6 前端构建

- 前端在构建时（`npm run build`）产生 `dist/` 目录
- Flask 只在 `dist/` 存在时托管前端
- `dist/` 不存在时，Flask 仅提供 REST API（适用于 Headless 场景或开发期前后端分离）
