# 419号 — dim5数据分拨合规与性能修复专项方案

---

## 一、问题背景

### 1.1 架构违规：dim5 绕过 dim1 唯一数据入口

409号方案 §2.1/§3.3 与 AGENTS.md 红线规则 9 明确：**dim1 是 SIG 唯一数据入口**，dim2-dim7 的 evaluate 只从 `data_context` 读取，禁止直接调用 DataManager/ECM。

实测核查（418号后真实数据验证时发现）dim5 `evaluate()` 绕过 dim1 直接取数共 5 处：

| # | 位置 | 直调行为 | 判定 |
|---|------|---------|------|
| 1 | `_time_rhythm` L305 | `DataManager().get_cached_indicators(ts_code)` 取 MA20/BOLL | ❌ 死代码（evaluate 未调用），但违规存在 |
| 2 | L670 | `ecm.get_cached_daily(ts_code)`（data_context 缺失时 fallback） | ⚠️ fallback 语义允许 |
| 3 | L681 | `ecm.get_cached_daily_basic(ts_code)`（fallback） | ⚠️ fallback 语义允许 |
| 4 | L690 | `BociasiQuadrantAnalyzer(ecm, market_stats)` 内部 SQL 回退 | ❌ 主因 |
| 5 | L730 | `SectorRotationModel(data_manager)` 全市场数据 | ❌ 架构缺口 |

### 1.2 性能主因：analyzer 缓存短路失效

`BociasiQuadrantAnalyzer._compute_fast_line/_compute_slow_line` 7 处 `raise StopIteration` + `except (ImportError, StopIteration): pass` 缺陷——**缓存命中后仍执行 SQL 回退**：

- daemon 日终 `_precompute_market_stats` 预计算 6 指标 → 持久化 `market_stats_cache` → pre_feat_cache `features['market_stats']` → dim1 加载进 data_context（实测确认完整）
- 但 analyzer 无视 market_stats 缓存，仍回退 `_compute_rsi_percentile`（`WHERE trade_date=?` 全表扫描 indicator_other 617 万行，无 trade_date 索引）→ **单只 5.2s**
- 实测：传完整 market_stats 仍跑 5.5s，limit_ratio 缓存值 0.1 被回退值 1.0 覆盖

### 1.3 功能断链：板块热度长期为空

- daemon L2280 用 `app/engine/framework/sector_rotation_model.py` 的 SectorRotationModel 预计算，结果仅在**daemon 进程内实例 `_cache`**（30 分钟 TTL），**未持久化**
- dim5 L730 用 `dim5_emotion_engine.py` 内**独立副本类**（不同类、无 indicator_ma_dict 对接），新建实例 → 缓存空 + `TTLCache` 未定义 NameError 被吞 → **板块热度恒 NONE**（功能长期缺失）
- 409号方案未将板块热度纳入 data_context → dim1 无法分拨 → 架构缺口

---

## 二、方案目标

1. **合规**：dim5 全部原料数据改经 dim1 data_context 分拨，消除直调 DataManager/ECM（保留 fallback 语义）
2. **性能**：修复 analyzer 缓存短路失效，market_stats 命中后不再 SQL 回退（单只 5.2s → <100ms）
3. **功能**：板块热度纳入 daemon 预计算持久化 + dim1 data_context 分拨 + dim5 消费，恢复真实板块热度
4. **存储**：indicator_other 补 trade_date 索引，为回退路径兜底

---

## 三、详细设计

### 3.1 修复 A：BociasiQuadrantAnalyzer 缓存短路失效（P0，性能主因）

**文件**：`backend/app/engine/framework/bociasi_quadrant.py`

将 `_compute_fast_line` / `_compute_slow_line` 中 7 处 "`if 缓存命中: ... raise StopIteration` / `except ...: pass` / 无条件执行回退" 模式重构为 **if/else 直接消费缓存**：

```python
# 当前（缺陷模式，7处一致）：
try:
    try:
        if self._market_stats.get('ma20_ratio') is not None:
            ratio = self._market_stats['ma20_ratio']
            scores.append(self._normalize(ratio, 0.2, 0.8))
            self._cache['ma20_ratio'] = round(ratio, 4)
            raise StopIteration  # ← 被except捕获后继续执行下方回退！
    except (ImportError, StopIteration):
        pass
    ratio = self._compute_ma20_ratio()   # ← 无条件执行
    ...

# 重构后：
cached = self._market_stats.get('ma20_ratio')
if cached is not None:
    scores.append(self._normalize(cached, 0.2, 0.8))
    self._cache['ma20_ratio'] = round(cached, 4)
else:
    ratio = self._compute_ma20_ratio()
    scores.append(self._normalize(ratio, 0.2, 0.8))
    self._cache['ma20_ratio'] = round(ratio, 4)
```

覆盖全部 7 处指标：`ma20_ratio / turnover_percentile / limit_ratio / rsi_percentile`（快线）+ `erp_percentile / margin_trend / pe_percentile`（慢线）。

**效果**：market_stats 命中时 analyzer 零 SQL 查询。

### 3.2 修复 B：板块热度纳入 dim1 data_context 分拨（P0，功能恢复）

#### B1：板块热度预计算结果持久化（daemon 侧）

新增存储：扩展 `market_stats_cache` 语义或新建 `sector_heat_cache` 表。采用**新建 `sector_heat_cache` 表**（板块热度为每行业一条，与市场级单行 stats 语义不同）：

```sql
CREATE TABLE IF NOT EXISTS sector_heat_cache (
    stat_date TEXT NOT NULL,
    industry   TEXT NOT NULL,      -- 申万一级行业名
    heat_level TEXT NOT NULL,      -- top_10/top_20/normal/none
    strength   REAL NOT NULL,
    rank       INTEGER NOT NULL,
    stock_count INTEGER NOT NULL,
    cached_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (stat_date, industry)
)
```

#### B2：daemon 预计算写入（data_daemon.py）

`_precompute_raw_features` 中 `compute_all_heat` 之后，将 `sr._cache['all_heat']` 结果写入 `sector_heat_cache`：

```python
# 当前 L2319：sr.compute_all_heat(all_data, indicator_ma_dict=indicator_ma_dict)
# 之后追加：
all_heat = sr._cache.get('all_heat')
if all_heat:
    _ecm.cache_sector_heat(all_heat, stat_date=last_date)
```

> 注：daemon 用 framework 版 `compute_all_heat`（不含 indicator_ma_dict 参数），L2319 传参被忽略；本方案**统一** framework 版与 dim5 副本——以 framework 版为唯一实现，补 `indicator_ma_dict` 参数。

#### B3：EnhancedCacheManager 新增 cache_sector_heat / get_cached_sector_heat

仿照 `cache_market_stats` 模式（L1328）：

```python
def cache_sector_heat(self, heat: dict, stat_date: str):
    """持久化板块热度全量结果 {industry: {heat_level, strength, rank, stock_count}}"""
    with self._write_lock:
        self._execute("DELETE FROM sector_heat_cache WHERE stat_date = ?", [stat_date])
        for ind, info in heat.items():
            self._execute("INSERT INTO sector_heat_cache ...", [...])
        self.conn.commit()

def get_cached_sector_heat(self, stat_date: str = None) -> dict:
    """读取板块热度，返回 {industry: {...}}"""
```

#### B4：dim1 data_context 加载板块热度（dim1_signal_engine.py）

`evaluate()` 类别 3（pre_feat_cache ext 组）之后，新增加载 `sector_heat`：

```python
try:
    sh = dm.get_cached_sector_heat()
    if sh:
        loaded_data['sector_heat'] = sh
except Exception:
    pass
```

#### B5：dim5 消费 data_context 板块热度（dim5_emotion_engine.py）

删除 dim5 内 `SectorRotationModel` 副本类（L485-665），evaluate L727-733 改为从 data_context 读取：

```python
# 当前：sr_model = SectorRotationModel(data_manager=self._get_dm()); heat_result = sr_model.evaluate(tags['ts_code'])
# 改后：
sector_heat = data_context.get('sector_heat') if data_context else None
if sector_heat:
    industry = <行业名>  # 从 data_context 或 tags 获取
    info = sector_heat.get(industry)
    if info:
        sector['heat'] = info['heat_level']
        sector['detail'] = f"板块{industry}(排名{info['rank']})"
```

> 行业名来源：dim5 需行业名才能查板块热度。方案采用 daemon 预计算时**额外写入目标股票行业映射**或复用 `dm.get_stock_industry(ts_code)`（读取行业名走 DataManager 只读接口，属合规——行业名不是原料数据）。

### 3.3 修复 C：dim5 直调 DataManager 清理（P1，合规）

- `_time_rhythm`（L305 直调 `get_cached_indicators`）：函数未在 evaluate 中调用，属死代码——**删除直调逻辑**（保留函数但改为纯 DataFrame 参数或整体移除）。鉴于 `time_rhythm` 语义已由 `_assess_stock_emotion` 覆盖，直接**移除该死函数**。
- L670/L681/L749 的 fallback：保留（409号 §4.1 明确保留回退路径），但确保主路径 data_context 命中后不触发——本方案 BociasiQuadrantAnalyzer 修复后 L690 主路径即命中，无需改 fallback。

### 3.4 修复 D：indicator_other 补 trade_date 索引（P1，兜底）

**文件**：`backend/scripts/migrate_indicator_columns.py`（复用 416 号迁移脚本模式）或新增幂等建索引：

```python
# 幂等：查询 sqlite_master 是否存在，不存在则建
CREATE INDEX IF NOT EXISTS idx_ind_other_date ON indicator_other(trade_date)
```

> 修复 A 生效后回退路径不再触发，此索引为缓存缺失场景兜底。
