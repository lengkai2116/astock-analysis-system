## 一、真实环境诊断（修正前序误判）

### 1.1 根因：HTTP_PROXY 环境变量 —— 非 Surge 代理封锁

**关键事实**（用户已验证）：
- 系统当前 **无 Surge/Clash 运行**
- `curl --noproxy '*'` 到东方财富 API 返回 `200`，耗时 0.22s
- 网络层（系统代理软件）未封锁东方财富

**真正的堵点是 Python 的代理环境变量**：

```
HTTP_PROXY=http://srt:663f87e4f1d5db2ff8105ccabe8d9a43@localhost:49577
HTTPS_PROXY=http://srt:663f87e4f1d5db2ff8105ccabe8d9a43@localhost:49577
ALL_PROXY=socks5h://srt:663f87e4f1d5db2ff8105ccabe8d9a43@localhost:49578
```

| 环境变量状态 | 效果 | 原因 |
|---|---|---|
| `HTTP_PROXY` 生效 | `ProxyError: CONNECT tunnel refused` | requests 试图通过 localhost:49577 隧道到 eastmoney，代理已不再运行 |
| `ALL_PROXY=socks5h://` 生效 | `InvalidSchema: Missing dependencies for SOCKS support` | PySocks 未安装，无法处理 SOCKS5 协议 |
| 全部清除 | ✅ **直连成功** | curl 已验证，EastMoney 无封锁 |
| `--noproxy '*'` (curl) | ✅ 200 | curl 不读取 `HTTP_PROXY` 环境变量 |

**链条**：shell（`.zshrc` / `.zshenv`）中 export 了代理变量 → Python 进程继承 → `requests.Session` 自动应用 → 东方财富触发代理隧道 → 代理服务已死 → 失败。

**curl 总是成功**是因为它不使用 `HTTP_PROXY` 环境变量（除非显式 `-x`）——所以用户用 curl 测试时一切正常。

### 1.2 历史对比：从不工作到依赖 Tushare 兜底

| 时期 | 状态 | 原因 |
|---|---|---|
| 原始开发环境 | Surge 运行时 → 用户关闭了 Surge | 代理随 Surge 注销 |
| Surge 关闭后 | HTTP_PROXY 环境变量残留，指向死代理 | `srt:...@localhost:49577` 是一直残留在 shell 中的 CI/工具代理 |
| 当前 | AKShare 无法连接 → Tushare 单数据源运行 | 代理变量被 Python 继承 |
| 修复后 | ✅ AKShare + Tushare 双源正常 | 清除代理变量或代码层面免疫 |

### 1.3 多平台影响预测

| 平台 | 风险 | 处理方式 |
|---|---|---|
| **macOS** | `.zshrc` / `.zshenv` 中可能残留代理变量 | 诊断脚本 → 清除 |
| **Windows** | 不会继承 macOS 的 `HTTP_PROXY`，但可能因企业内网需要设置代理 | 代码层 `trust_env=False` 免疫 |
| **双平台打包** | macOS Platypus、Windows Inno Setup 各自启动环境不同，不能依赖 shell 配置 | 必须代码层解决 |

### 1.4 推荐修复方案（三选一，推荐 C）

| 方案 | 操作 | 优点 | 缺点 |
|---|---|---|---|
| **A** 清除 shell 代理变量 | 在 `~/.zshrc` 中注释掉 export | 简单 | 仅限本地，不覆盖 Windows/打包 |
| **B** 安装 PySocks | `pip install PySocks` | 兼容现有 SOCKS5 配置 | 需要代理服务实际运行 |
| **C** 代码免疫 | 在 `requests.Session` 中设置 `trust_env=False` | **一次修改，所有平台生效** | 需要改两层（akshare 底层 + akshare_provider） |

**推荐方案 C**：在 `akshare_provider.py` 和代码中所有创建 `requests.Session` 的地方加上 `session.trust_env = False`。AKShare 底层使用 `ak.get` 调用时传递 `trust_env=False` 给底层 session（或通过 monkey-patch 实现）。

## 二、go-stock-analyzer 架构深度分析

### 2.1 核心架构模式

```
┌─────────────────────────────────────────────────────────┐
│  go-stock-analyzer                                       │
│                                                          │
│  ┌──────────┐    ┌───────────┐    ┌────────────────┐    │  WebSocket
│  │ Fetcher  │───→│  Hub      │───→│ Client Manager │───→│←──→ Browser
│  │(定时轮询) │    │(广播中心)  │    │(按symbol订阅)   │    │    (Vue)
│  └──────────┘    └───────────┘    └────────────────┘    │
│       │                                                 │
│       ↓                                                 │
│  ┌──────────┐                                           │
│  │ SQLite   │ ←── 持久化归档                             │
│  │ Storage  │                                           │
│  └──────────┘                                           │
└─────────────────────────────────────────────────────────┘
```

**三个核心模块**：

#### a) Fetcher（数据采集层）
- `fetcher/fetcher.go` — 定时轮询新浪 / 东方财富 API
- `fetcher/stock_list.go` — 股票列表抓取与 symbol 生成（`sz000001` / `sh600000` 格式）
- 采集后自动计算技术指标（MA、MACD）
- 结果同时写入 **SQLite 持久化** + **WebSocket Hub 实时推送**

#### b) WebSocket Hub（实时推送层）
- `realtime/hub.go` — 中心广播管理器，管理所有 WebSocket 客户端连接
- `realtime/client.go` — 每个客户端对应一个 goroutine，管理订阅状态
- **核心特征**：按 `symbol`（股票代码）分发，而非全量广播

#### c) 前端消费层（Vue）
- 连接 `ws://localhost:8080/ws/realtime`
- 发送 `{"action": "subscribe", "symbol": "sz000001"}` 订阅特定股票
- 接收推送：
  ```json
  // 实时行情
  {"type": "quote", "symbol": "sz000001", "price": 10.92, "volume": 120000, ...}
  // 策略信号
  {"type": "signal", "symbol": "sz000001", "strategy": "ma_cross", "signal": "buy", ...}
  ```
- **增量更新 DOM**：收到推送后只更新对应组件的状态，不刷新页面

### 2.2 与我们系统的对比

| 维度 | go-stock-analyzer | 我们的系统（当前） |
|---|---|---|
| 采集方式 | Fetcher 定时轮询 → WebSocket Hub | 5 个采集器线程 → InMemoryStateStore + DuckDB |
| 前端数据获取 | **WebSocket 推送**（主动） | REST API **轮询**（被动，需刷新页面） |
| 订阅粒度 | 按 symbol 订阅 | 无订阅机制，整页拉取 |
| 持久化 | SQLite（轻量） | DuckDB + SQLite（双库） |
| 数据源 | 新浪/东方财富（Go 原生 HTTP） | AKShare（Python 封装）+ Tushare |
| 技术栈 | Go + Vue(Vite) | Flask + Vue3 |
| WebSocket 实现 | Gorilla WebSocket + 自定义 Hub | Flask-SocketIO（已初始化但未启用推送） |

### 2.3 关键可借鉴点

1. **Fetcher→Hub→Client 管道**：采集器完成 → 即时推送给前端，无需前端轮询
2. **按 symbol 订阅**：前端在连接时发送订阅清单，服务端按需推送（而不是全量广播）
3. **增量 DOM 更新**：前端收到推送后只修改对应组件的状态，维持页面不闪烁

### 4.2 WebSocket 桥接器设计（新增模块）

创建 `backend/app/data/ws_bridge.py`：

```python
"""
WebSocket 桥接器 — 采集器 → InMemoryStateStore → SocketIO
========================================================

职责：
  - 在每个采集线程完成一轮采集后，从 InMemoryStateStore 读取数据
  - 通过 Flask-SocketIO 推送到对应的订阅房间
  - 不阻塞采集器，不持有 DB 连接

使用方式：
  ws_bridge = WsBridge(socketio)
  ws_bridge.broadcast('snapshot', data)  # 由采集器在 collect 完成后调用
"""
```

**事件协议**：

| 事件名 | 数据内容 | 推送时机 | 房间 |
|---|---|---|---|
| `market:snapshot` | 全市场快照（按需批量） | 15s | `market_room` |
| `market:sectors` | 行业板块排行 | 5min | `market_room` |
| `market:top_stocks` | 涨跌榜（up/down） | 30s | `market_room` |
| `market:limit_pool` | 涨跌停池 | 5min | `market_room` |
| `stock:quote` | 单只/批量股票行情 | 按订阅 | `user:{sid}` |
| `stock:signal` | 策略信号 | 触发时 | `user:{sid}` |

**推送时机**：在每个 `_CollectThread.collect()` 完成后立即触发，而非再单独起定时器。这样天然对齐采集频率，不额外增加系统开销。

### 4.3 前端消费模式设计

**目标**：前端先连接 WebSocket，收到推送数据后**增量更新对应组件**；如果 WebSocket 断连，自动降级为 REST API 轮询。

```typescript
// 核心逻辑（在 useRealtimeData composable 中）
const wsConnected = ref(false)

// 1. 连接 WebSocket → 订阅需要的房间
// 2. 收到 market:snapshot → 更新价格显示组件
// 3. 收到 market:sectors → 更新板块排行组件
// 4. 30s 内无推送 → 自动发起 REST API 获取（降级）
// 5. WebSocket 重连 → 取消降级，切回推送
```

### 4.4 解决 Redis 依赖问题

当前 `RealtimeDataService._data_publisher_loop` 在没有 Redis 时静默跳过（第 64-66 行）。这是设计缺陷——推送层不应强制依赖 Redis。

**修复**：将推送逻辑从 Redis pub/sub 改为直接 InMemoryStateStore 读取 + SocketIO emit。Redis 作为可选增强（跨进程同步），而非必经路径。

### 4.5 异常场景保障

| 场景 | 保障措施 |
|---|---|
| **WebSocket 断连** | 前端自动降级为 REST API 轮询（15s 间隔），断连时用户可见状态提示 |
| **采集器超时/失败** | 单个采集异常不影响其他 4 个采集器；WebSocket 广播上次成功数据 + 新鲜度标记 |
| **数据源（AKShare）不可用** | WebSocket 推送 `{type: "status", source: "akshare", available: false}`，前端显示降级提示 |
| **Flask-SocketIO 重启** | 前端指数退避重连（1s → 1.5s → 2.25s → ... → 30s max，最多 10 次）|
| **大量客户端** | SocketIO 在单进程下支持数百并发连接；后续可加 Redis pub/sub 做多进程扩展 |

## 六、风险与降级

| 组件 | 单点故障 | 降级策略 |
|---|---|---|
| `InMemoryStateStore` | 进程重启丢失盘中数据 | 重启后采集器 15s 内填充，期间 REST 提供前一日 DuckDB 数据 |
| `Flask-SocketIO` | 主进程崩溃，所有 WS 断开 | 前端自动降级 REST 轮询，等待重启重连 |
| `AKShare` | 东方财富 API 变更/限流 | WebSocket 推 `source_unavailable` 事件，前端显示"盘中数据暂不可用" |
| `WebSocket` 房间管理 | 用户切换页面后旧房间未清理 | 每个页面离开时调用 `socket.emit('leave_room', {room: '...'})` |
