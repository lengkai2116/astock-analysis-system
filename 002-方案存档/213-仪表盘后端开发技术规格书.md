## 2. API端点技术规格

### 2.1 `GET /api/v3/market/overview` — 指数行情总览

**用途:** 页头成交额 + 四大指数卡片（含迷你K线）
**所属区块:** #1 页头 + #2 四大指数卡片
**优先级:** P0
**HTTP方法:** GET

#### 请求参数

无（返回全部配置指数的基础行情）

#### 响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "timestamp": "2026-06-30 15:30:00",
    "market_status": "trading",               // trading|closed|holiday
    "total_volume": 874200000000,             // 总成交额（元），对应页头 ¥8,742亿
    "total_volume_change_pct": 12.5,          // 成交额同比变化%
    "indexes": [
      {
        "ts_code": "000001.SH",
        "name": "上证指数",
        "price": 3287.45,
        "change_pct": 0.87,
        "change_amount": 28.32,
        "mini_kline": [                        // 近20日迷你K线（交易日至多20根）
          {"date": "06/03", "open": 3250.10, "close": 3268.30, "low": 3245.20, "high": 3272.50},
          {"date": "06/04", "open": 3268.30, "close": 3287.45, "low": 3260.10, "high": 3290.80}
        ]
      }
    ]
  }
}
```

| 字段 | 类型 | 说明 | 映射到原型 |
|:-----|:-----|:------|:-----------|
| `timestamp` | string | 数据时间 | 页头 `2026-06-11 15:30` |
| `market_status` | string | 市场状态 | — |
| `total_volume` | number | 总成交额(元) | 页头 `¥8,742亿`，前端需 `/1e8` 转换为亿 |
| `total_volume_change_pct` | number | 成交额同比变化% | 页头 `↑ +12.5%` |
| `indexes[].ts_code` | string | 指数代码 | 卡片副标题 |
| `indexes[].name` | string | 指数名称 | 卡片`.name` |
| `indexes[].price` | number | 当前点位 | 卡片`.value`（24px加粗） |
| `indexes[].change_pct` | number | 涨跌幅% | 卡片`.change`，正数`up`/负数`down` |
| `indexes[].change_amount` | number | 涨跌点数 | — |
| `indexes[].mini_kline` | array | 迷你K线(至多20根) | 4个mini-chart ECharts实例 |

#### 迷你K线特殊处理说明

- 前端 ECharts 初始化代码（`drawMiniK`）需要 `date/close/open/low/high` 四个字段
- 只有 K 线系列的 `close` 用于计算 Y 轴范围（`minP/maxP`）
- `itemStyle.color: '#EF4444'`（close>=open 的上涨日红色）
- `itemStyle.color0: '#22C55E'`（close<open 的下跌日绿色）
- 原型使用4只指数：上证(000001.SH)、深证(399001.SZ)、北证50(899050.BJ)、创业板(399006.SZ)
- 后端需支持 Tushare `index_daily()` 获取

#### 数据更新频率

- 盘中：每5秒轮询
- 盘后：最后行情数据缓存至下一交易日

#### 缓存策略

- TTL: 5s（盘中）/ 16h（盘后）
- 客户端Cache-Control: `no-cache`
- 服务端可Redis缓存，key: `market:overview`

#### 降级方案

| 故障 | 前端表现 | 数据源切换 |
|:-----|:---------|:-----------|
| Tushare不可用 | 展示缓存最后数据 | 切AkShare `stock_zh_index_daily_em` |
| 全部数据源不可用 | 显示Mock占位值 | 返回HTTP 503 + 前端fallback静态值 |

### 2.2 `GET /api/v3/chart/kline/<ts_code>?mini=true` — 迷你K线（轻量版）

**用途:** 指数卡片20日迷你K线（与个股750根K线不同，此为轻量版）
**所属区块:** #2 四大指数卡片内迷你K线
**优先级:** P0
**HTTP方法:** GET

#### 请求参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|:-----|:-----|:-----|:-----|:------|
| `ts_code` | string | ✅ | — | 路径参数，如 `000001.SH` |
| `mini` | boolean | 否 | false | `true` 时返回20条精简K线（仅含`date/open/close/low/high`） |
| `limit` | int | 否 | 20 | 仅`mini=true`时生效 |

#### 响应格式

```json
{
  "code": 0,
  "data": {
    "ts_code": "000001.SH",
    "name": "上证指数",
    "kline": [
      {"date": "06/03", "open": 3250.10, "close": 3268.30, "low": 3245.20, "high": 3272.50}
    ]
  }
}
```

#### 数据来源

Tushare `index_daily(ts_code, start_date, end_date)` 取 `open/close/low/high`

#### 数据更新频率

每日盘后更新（T+1）

### 2.3 `GET /api/v3/market/index-daily` — 成交额柱状图

**用途:** 四大交易所合计每日成交额柱状图
**所属区块:** #3 成交额柱状图（`#volume-chart`）
**优先级:** P2
**HTTP方法:** GET
**端点命名说明:** 以166号§8.4.2记录的 `/api/v3/dashboard/volume` 为准，171号中记录的 `/api/v3/market/index-daily` 统一为此命名

#### 请求参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|:-----|:-----|:-----|:-----|:------|
| `days` | int | 否 | 20 | 返回天数（仅计算交易日，跳过周末） |
| `exchange` | string | 否 | all | `all` 四大交易所汇总；支持传 `sh/sz/bj/cy` 单交易所 |

#### 响应格式

```json
{
  "code": 0,
  "data": {
    "exchange_summary": "上证+深证+北证50+创业板",
    "days": [
      {
        "date": "06/03",
        "total_amount": 874200000000,      // 4交易所合计成交额（元）
        "amount_per_exchange": {            // 各交易所分项（可选扩展）
          "sh": 320000000000,
          "sz": 380000000000,
          "bj": 25000000000,
          "cy": 149200000000
        }
      }
    ],
    "average_amount": 812500000000,         // 期间日均成交额（用于柱状着色判定）
    "updated_at": "2026-06-30"
  }
}
```

| 字段 | 类型 | 说明 | 前端使用 |
|:-----|:-----|:------|:---------|
| `days[].date` | string | 日期 `M/D` | xAxis data |
| `days[].total_amount` | number | 成交额(元) | yAxis值，色彩判定：>=average→红, <→绿 |
| `average_amount` | number | 期间日均(元) | 前端 `vals.reduce()/n` → 色彩判定阈值 |
| `updated_at` | string | 数据日期 | 渲染即可 |

#### 前端渲染参数

- 图表高度: **260px**（以原型`style="height:260px"`为准）
- 柱宽: 12px
- 柱顶标注: 显示为`X亿`（响应格式中取整即可，也可由前端`/1e8`转换）
- Tooltip格式: `成交额: ¥X.XX万亿`（前端`/1e12`转换）
- 着色规则: `>=average_amount` → `#EF4444`（红色），`<` → `#22C55E`（绿色）

#### 数据来源

Tushare `index_daily()` 各指数 amount 汇总
- 上证指数 000001.SH
- 深证成指 399001.SZ
- 北证50 899050.BJ
- 创业板指 399006.SZ

#### 聚合规则

```
total_amount = sum(index_daily('000001.SH').amount, index_daily('399001.SZ').amount,
                   index_daily('899050.BJ').amount, index_daily('399006.SZ').amount)
```

#### 更新频率+缓存

- 每日盘后更新（T+1）
- Cache TTL: 至下一交易日开盘（约16h）
- Redis key: `market:index-daily`

#### 降级方案

- Tushare不可用 → 切 AkShare `stock_zh_index_daily_em`
- 全不可用 → 返回空数组，前端展示空白ECharts + 提示条

### 2.4 `GET /api/v3/dashboard/summary` — AI雷达+策略信号聚合

**用途:** 聚合 Screener L3 场景A输出，同时驱动AI雷达卡片和策略信号汇总
**所属区块:** #4 AI交易机会雷达 + #11 策略信号汇总
**优先级:** P2
**HTTP方法:** GET

#### 请求参数

无（返回最新一次的 Screener L3 场景A聚合结果）

#### 响应格式

```json
{
  "code": 0,
  "data": {
    "updated_at": "2026-06-30 10:32:00",
    "update_note": "来自 Screener L3 · 3 分钟前更新",
    "radar_stocks": [
      {
        "ts_code": "000762.SZ",
        "name": "西藏矿业",
        "score": 92,                         // combined_score（L2+L3融合）
        "direction": "bullish",              // bullish|bearish|watch
        "price": 12.34,
        "change_pct": 2.3
      }
    ],
    "signal_summary": {
      "bullish_count": 12,                   // L3结果中strategy_detail方向为bullish的数量
      "bearish_count": 8,                    // 方向为bearish的数量
      "chanlun_signal": 15,                  // chanlun.score > 0 的数量
      "chip_signal": 7,                      // chip.score > 0 的数量
      "ai_judgment": 5,                      // direction='bullish'且score>80的数量
      "resonance": {                         // 共振信号
        "label": "🔥 共振信号",
        "detail": "3 个策略同时看多"
      },
      "high_confidence": {
        "label": "⚡ 高置信度",
        "detail": "置信度 ≥ 85%"
      }
    },
    "total_signals": 47
  }
}
```

#### 前端字段映射

| 响应字段 | 原型使用 |
|:---------|:---------|
| `radar_stocks[].ts_code` | 雷达卡片`.stock-code`文本 |
| `radar_stocks[].name` | 雷达卡片`.stock-name`文本 |
| `radar_stocks[].score` | 雷达卡片`★92` |
| `radar_stocks[].direction` → `bullish/watch/bearish` | 映射 `看多/关注/看空`，色条颜色+标签颜色 |
| `radar_stocks[].price` | 可选扩展（原型已定义但未渲染） |
| `radar_stocks[].change_pct` | 可选扩展 |
| `update_note` | `来自 Screener L3 · 3 分钟前更新` |
| `signal_summary.bullish_count` | 看多信号卡片`.count`=12 |
| `signal_summary.bearish_count` | 看空信号卡片`.count`=8 |
| `signal_summary.chanlun_signal` | 缠论信号`.count`=15（颜色 `var(--signal-watch)`） |
| `signal_summary.chip_signal` | 筹码信号`.count`=7（颜色 `var(--color-brand-500)`） |
| `signal_summary.ai_judgment` | AI研判`.count`=5（颜色 `flat`= `var(--text-secondary)`） |

#### 方向颜色/标签映射

| `direction` | 色条颜色 | 标签文字 | 标签背景 | 评分颜色 |
|:------------|:---------|:---------|:---------|:---------|
| `bullish` | `#EF4444` | 看多 | `#EF444422` | `#EF4444` |
| `watch` | `#F59E0B` | 关注 | `#F59E0B22` | `#F59E0B` |
| `bearish` | `#22C55E` | 看空 | `#22C55E22` | `#22C55E` |

**注意：** A股惯例「红涨绿跌」，涨价看多=红(`#EF4444`)，跌价看空=绿(`#22C55E`)——这与一般金融UI的"红跌绿涨"相反，是A股标准。

#### 雷达卡片交互

- **CSS轮播：** `@keyframes scrollRadar` + `transform: translateX(-50%)`，`30s linear infinite`
- **鼠标悬停：** `animation-play-state: paused`
- **点击：** 跳转 `/indicator-ide.html?symbol={ts_code}`
- **无缝循环：** 前端将 `radar_stocks` 复制一份拼接，80%偏移无限重复

#### 数据来源

从 Screener Pipeline L3 场景A输出聚合计算，不直接依赖Tushare

#### 聚合规则

| 信号项 | 聚合逻辑 |
|:-------|:---------|
| `bullish_count` | `L3结果.filter(s => s.direction === 'bullish').length` |
| `bearish_count` | `L3结果.filter(s => s.direction === 'bearish').length` |
| `chanlun_signal` | `L3结果.filter(s => s.strategy_detail.chanlun.score > 0).length` |
| `chip_signal` | `L3结果.filter(s => s.strategy_detail.chip.score > 0).length` |
| `ai_judgment` | `L3结果.filter(s => s.direction === 'bullish' && s.score > 80).length` |

#### 更新频率

每次 Screener Pipeline 运行时更新（用户触发或定时任务）

#### 缓存策略

- 缓存至下次Screener运行
- 默认TTL: 30分钟
- Redis key: `dashboard:summary`

#### 降级方案

- Screener未运行 → 返回最近一次缓存数据
- 从未运行 → 返回空数组+零值信号，前端显示"暂无数据"

### 2.5 `GET /api/v3/market/moneyflow-summary` — 全市场资金流向趋势

**用途:** 全市场每日主力净流入+散户净流出示意图（20日序列）
**所属区块:** #5 资金流向趋势（`#chart-fund-flow`）
**优先级:** P2（新增端点，166号/171号此前未正式记录）
**HTTP方法:** GET

#### 请求参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|:-----|:-----|:-----|:-----|:------|
| `days` | int | 否 | 20 | 交易日天数（不计算周末） |

#### 响应格式

```json
{
  "code": 0,
  "data": {
    "updated_at": "2026-06-30",
    "period_note": "数据截止前一交易日",
    "days": [
      {
        "date": "06/03",
        "main_force_net_inflow": 2.8,       // 主力净流入(亿) 正=流入 负=流出
        "retail_net_outflow": -1.2           // 散户净流出(亿) 负=流出
      }
    ]
  }
}
```

#### 前端渲染参数

- ECharts bar（主力净流入）+ line（散户净流出）
- 柱状线性渐变: `LinearGradient(0,0,0,1,[{0,'#3B82F6'},{1,'rgba(59,130,246,0.2)'}])`
- 折线颜色: `#EF4444`，`smooth: true`，`symbol: 'none'`，areaStyle同色8%透明度
- Legend: `['主力净流入','散户净流出']`
- Tooltip: `trigger: 'axis'`

#### 主力净流入定义

```
主力净流入 = 大单(20万~100万)买入额 - 大单卖出额 + 特大单(≥100万)买入额 - 特大单卖出额
散户净流出 = 小单(<4万)买入额 - 小单卖出额（通常为负值）
```

参考: 166号§3.8.1决策表

#### 数据来源

Tushare `moneyflow()` 全市场聚合
- **注意：** 这是全市场汇总而非单只股票，Tushare按月返还会产生较大数据量
- 建议方案：后端每日定时计算并缓存结果，不实时计算

#### 更新频率

每日盘后更新（T+1），Tushare moneyflow数据T+1可用

#### 缓存策略

- 缓存至下一交易日
- Redis key: `market:moneyflow-summary`

#### 降级方案

- Tushare积分不足 → 使用已缓存数据
- 无缓存 → 返回空数组，ECharts展示空图+提示条

### 2.6 `GET /api/v3/market/sector-moneyflow` — 行业板块资金流向

**用途:** 行业板块净流入排行ECharts + Top5板块×前3个股卡片（流入+流出）
**所属区块:** #6 板块净流入排行 + #7 个股流入卡片 + #8 个股流出卡片
**优先级:** P2
**HTTP方法:** GET

#### 请求参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|:-----|:-----|:-----|:-----|:------|
| `top_n` | int | 否 | 8 | 返回板块数 |
| `stocks_per_sector` | int | 否 | 3 | 每板块返回前N只个股 |
| `date` | string | 否 | 前一交易日 | 格式 YYYY-MM-DD |

#### 响应格式

```json
{
  "code": 0,
  "data": {
    "date": "前一交易日",
    "updated_at": "2026-06-30",
    "sectors": [
      {
        "name": "半导体",
        "net_inflow": 5.2,                  // 板块净流入(亿)
        "net_inflow_change_pct": 8.5,       // 板块净流入变化%
        "stocks": [                          // 前3只主力净流入最大个股
          {"name": "北方华创", "net_inflow": 0.85},
          {"name": "韦尔股份", "net_inflow": 0.72},
          {"name": "中芯国际", "net_inflow": 0.58}
        ]
      }
    ],
    "out_sectors": [                         // 净流出前5板块
      {
        "name": "地产",
        "net_inflow": -1.2,
        "stocks": [
          {"name": "万科A", "net_outflow": -1.32},
          {"name": "保利发展", "net_outflow": -0.95},
          {"name": "招商蛇口", "net_outflow": -0.61}
        ]
      }
    ]
  }
}
```

#### 前端字段映射

| # | 区块 | 使用字段 | 渲染方式 |
|:-:|:-----|:---------|:---------|
| 6 | 板块净流入排行ECharts | `sectors[].name` (y轴) + `sectors[].net_inflow` (x值) | 横向柱状图，净额>=0红(`#EF4444`)，<0绿(`#22C55E`) |
| 6 | 同上Label | `net_inflow` → `{c}亿` | label右侧显示 |
| 7 | Top5流入卡片 | `sectors[0..4].name` (卡片标题) + `stocks[0..2].name/inflow` (行) | 5个flex容器，每个3行 |
| 8 | Top5流出卡片 | `out_sectors[0..4].name` + `stocks.outflow` | 同上，但金额标记`down`类 |

#### 板块排行排序规则

- 流入排行（`sectors`）: 按 `net_inflow` 降序（正流入多→少）
- 流出排行（`out_sectors`）: 按 `net_inflow` 升序（负流出多→少，最多展示5个）
- 个股排序: 按 `net_inflow` 绝对值降序

#### 数据来源

Tushare `moneyflow()` 按行业聚合

#### 聚合规则

```
板块净流入 = 该板块内所有股票的主力净流入之和
板块个股Top3 = 板块内按主力净流入绝对值排序的前3只
```

#### 更新频率

每日盘后更新（T+1）

#### 缓存策略

- Cache TTL: 至下一交易日
- 建议服务端定时计算（收盘后定时任务）

## 4. 错误处理矩阵

| 故障场景 | 受影响区块 | 前端表现 | 后端降级 |
|:---------|:----------|:---------|:---------|
| Tushare 5000分耗尽 | 全部Tushare依赖区块 | 展示上次缓存/静态Mock | 切AkShare备用 |
| 个别指数数据缺失 | #2 指数卡片 | 缺失的卡片隐藏/显示"--" | 其他指数正常返回 |
| 节假日无数据 | #3/#5/#6/#9 | 显示"前一交易日"数据 | 后端自动回退到最近交易日 |
| Screener未运行 | #4/#11 | 空雷达+零值信号 | 返回最近缓存/空数组 |
| 个股停牌 | #10 | 显示"停牌"标记 | 停牌股票不参与涨跌幅排序 |
| API超时(>3s) | 所有区块 | 区块显示骨架屏→Mock占位 | 尽早返回已就绪数据 |
| 网络断开 | 全部 | 显示离线提示条+最后数据 | — |
| `moneyflow-summary` 无数据 | #5 | 空白ECharts+"[暂无数据]" | HTTP 200 + data:null |

### 统一错误响应格式

```json
{
  "code": -1,
  "message": "错误描述",
  "data": null
}
```

前端 **必须根据 `code` 判断**，不应依赖 HTTP Status Code 判断业务逻辑成功与否。

**数据约束：**
- 大盘指数数据源：Tushare `daily` → DuckDB，需确保 `000001.SH` / `399001.SZ` 等核心指数日线完整
- 成交额/资金流向聚合数据：实时计算而非缓存，依赖 `market/moneyflow-summary` 新建路由
- 迷你K线 20 日数据：DuckDB 缓存命中率应 >95%（历史数据不变，首次请求后永久缓存）

### 数据定时获取

参见 [229号方案 §3.1](229-系统定时机制全面分析报告.md) 数据获取定时需求表。

- **数据类型**：指数行情（盘中 5s）、涨跌榜（盘中 1min）、日终全量更新（15:05）
- **实现机制**：指数行情和涨跌榜前台轮询调用 API（非 WebSocket 推送），由 APScheduler 日内定时器提供数据就绪信号
- **日终依赖**：`daily_close_sync` 日终同步任务（Phase 1 待实施）提供全量盘后数据，仪表盘通过定时缓存刷新（09:25/14:55/15:05）读取
- **缓存策略**：详见本文 §3 数据更新与缓存总表（5s/1min/16h/24h 四级 TTL）
