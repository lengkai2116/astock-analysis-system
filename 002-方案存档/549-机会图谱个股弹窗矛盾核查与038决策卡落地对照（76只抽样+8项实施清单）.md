## 二、核查范围与方法

### 2.1 路径确认

弹窗入口与地图模式无关：页面首屏固定请求 `/api/v3/opportunity-atlas/treemap?mode=market`（`_ui-prototype/opportunity-treemap.html:708`），三种地图只是前端渲染视图；点击后统一进入 `showDetail()`（`:1738`）。

```
点击方块 / 搜索命中 / ?ts_code=
  → showDetail(data)
  → GET /opportunity-atlas/stock?ts_code=...      （补 one_liner_detail / state_evidence / entry_signals / exit_conditions）
  → GET /opportunity-atlas/diagnose?ts_code=...   （补 status_verdict / operation_advice / risk_warnings / tags_summary）
  → /quotes 30s 只刷价格
```

### 2.3 判定口径

- **状态**取 `status_verdict.opportunity_state`（弹窗最终展示源）。
- **动作**取 `operation_advice.action_label` / `action`。
- **止损**取 `operation_advice.stop_loss`；**失效条件**取 `operation_advice.invalidation[0]`。
- **共识**取 `status_verdict.consensus_rate`（带符号）与 `cross_validation.consensus`（九维）。
- **估值**取 bulk `valuation_level` + `tags.pe_percentile_5y/pb_percentile_5y`。
- **风险**取 `dim_states.risk.light` 与 `risk_warnings`。
- **一致性**用脚本对 76 只逐项校验；全市场规模另用 5570 只快照统计。

### 5.1 逐项补充说明

#### ① 主结论 state vs action

038 的核心是“只允许一个主结论”。549-A 已把 state 保留为主结论，并在动作块加“动作待复核”徽标；降级原因优先取 `operation_advice.summary`（如“盈亏比不足 0.94<2，建议观望”），回退 `state_reason`/`state_evidence`。动作仍以并列形式显示，未同步改 L2 state——这是 A 口径的刻意选择。

根因链（600872）：
```
status_verdict.opportunity_state = enter      （L2 日频状态）
status_verdict.state_evidence[0] = 盈亏比不足 0.94<2，建议观望
operation_advice.action = HOLD / action_label = 持有/观望  （实时套算后降级）
```
弹窗同时显示 `●可入场 / 强势确认 / 共识100%` 与 `持有/观望 / 仓位20%`，用户无法判断该信哪个。

建议采用 **A 口径**：保留 state 主结论，动作降级时显示“动作已降级 + 原因”，不直接把 state 改成 wait（避免改 L2 语义与历史回测基线）。

#### ② 潜力/时机

当前“信号强度”在标题行，“时机”在下一行，物理上已并列；缺的是**语义标签**与**高潜力+回避的解释**。
600519：信号强度 92（JUD）、state=avoid、status_bar=风险警示；用户看到 92/100 与“回避”会天然认为矛盾。
建议加一句固定解释：“潜力衡量未来空间（慢变量），时机衡量当下右侧确认（快变量），二者可不一致。”

#### ③ 负共识

这是纯展示 bug，不改任何上游数据：`consensus_rate` 已带方向符号，前端只需 `Math.abs` + 方向词。
注意两处都要改：标题行（bulk）与裁决行（diagnose）；否则会出现“标题看空 81%、裁决 -81%”的新不一致。
同时 `d-timing-row` 的 `L4共识` 没有方向字段，需按符号推导：`rate < 0 → 看空`，`rate > 0 → 看多`，`0 → 中性`。

#### ④ opportunity_summary

当前弹窗没有显示 grade/score/time_horizon，这一点实际已符合 038 的“删除项”；但 `risk_level` 也没用上，风险区只取 `risk_warnings[0]`。
建议不要把 `risk_level` 当成“严重度”展示（它的真实语义是风险条数分档），若要显示，写成「风险提示 3 条」而不是「风险等级：高」。

#### ⑤ 基础信号强度 / 事件加成

`signal_strength` 是 JUD 基础值；`signal_strength_adjusted = signal_strength × (1+事件调整)`（earnings/lhb/buyback/breakout +15%，pledge/float/reduce/fraud_sign/regulatory -15%，concept 等 +10%）。
当前标题行只显示基础值，符合 038 的“主数字用基础值”；但事件加成完全没有提示。建议在数字旁加小徽标，不改变主数字。

#### ⑥ 三条关键依据

这是本轮“为什么不解释”的最大缺口。弹窗已经请求了 `/stock` 并拿到 `state_evidence`、`entry_signals`、`exit_conditions`，但只把它们挂在 `data` 上，从未写入 DOM。
建议新增一个“📌 关键依据”块（3 行），并在 038 六区中作为“结论卡”下方固定区；`entry_signals/exit_conditions` 可在同块下方以“入场/离场触发”各 1 行呈现（038 原计划）。

#### ⑦ 底部按钮

当前“加入自选”“AI 投研”都是 `closeDetail()`，点击后没有任何持久化/跳转；“策略分析”是唯一真实动作（跳 `indicator-ide.html?ts_code=...`）。
`backend/app/routes/watchlist.py:351` 存在 `POST /api/v3/watchlist`，但前端未接；需先确认请求体契约（ts_code/name/group 等）再接入，或本轮先隐藏“加自选”。
建议：保留“看完整七维现状”（改名或加副文案）+ 真实“加自选”；删除“AI 投研”。

#### ⑧ 估值一行化

当前“💎估值定位”是整段区块（结论卡 + 3 张卡），且 `_valuationKey('')` 返回“合理”，会让缺失估值的股票显示“估值合理，不便宜也不贵”。
建议一行化并标注两种口径：
- `估值（模型）：偏低`
- `PE 20.3（近5年22%分位） · PB 6.64（9%分位） · 股息 3.95%`
若 PE/PB/股息/估值全空则整行隐藏；若仅估值有值而 PE/PB 缺失，显示“偏高（PE/PB 缺失）”而不是“合理”。
