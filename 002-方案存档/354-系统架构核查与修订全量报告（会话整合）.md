## 二、核查发现

### 2.1 兴齐眼药矛盾（consensus=100% + state=avoid）

**现象**：弹窗显示"L4 看多共识 100%"但状态为"回避"，consensus_rate 与 opportunity_state 矛盾。

**根因**：L1 九维共识（DIM-1~11 方向计票）与 arbiter P0 否决（right_side_confirm 标签）使用不同数据源。right_side_confirm=否决（缠论一卖触发）的判定因子（buy_sell_point / volume_price_fit / pattern_signal）不在 11 个维度中，导致维度投票无看空（consensus=100%），但 P0 否决直接覆写为 avoid。

**332 号设计依据**：332 号§5.5 明确"right_side_confirm 不允许参与九维平均"——P0 否决是独立于维度投票的旁路机制，设计意图是"风控智能体最高优先级"。

**修复**：G2（diagnose 传入 L1 共识给 advice_builder）+ G3（_arb 共识改 L1）+ G1（新增 signal_confirm 维度输出到前端）。修复后弹窗/个股页完全一致（avoid/0.0）。

### 2.3 九典制药矛盾（七维画像 vs 九维）

**现象**：个股页「现状诊断」卡片显示"趋势：🟡 不明 / 量价：🟢 健康 / 价格位置：中位"，与九维灯"structure=上升 / vp=中性 / position=站上防守位"矛盾。

**根因**：两套七维数据源不同——

| 数据 | 来源 | 生产方 |
|------|------|--------|
| 七维画像（现状诊断卡） | `opportunity_profile` P4 标签 | `_build_opportunity_profile()`（PRE-2 预计算） |
| 九维灯（status_verdict） | `dim_states` StatusEngine 输出 | `StatusEngine._build_dimensions()`（JUD 实时判定） |

opportunity_profile 是 PRE-2 旧体系（320 号设计），从 7 个原料标签直接推导；StatusEngine 从 SIG 信号+PRE-2 标签联合判定。两套用不同数据源、不同判定逻辑，导致同一股票出现矛盾结论。

**332 号设计要求**：成品仓唯一消费，弹窗/个股页/快照三处口径一致。opportunity_profile 未接入 StatusEngine L1 九维是 S3 遗留项。

### 4.4 层间数据流向

```
COL（第1层）──写──→ STG（第2层）──读──→ PRE（第3层）──写──→ STG
                                                      │
STG ←──读── SIG（第4层）←──读── STG                   │
  │                                                     │
  └──写──→ STG ←──读── JUD（第5层）←──读── STG ←──────┘
                │
                └──写──→ OUT（第6层）──读──→ USE（第7层）
```

**关键依赖链**：
- `PRE-2 标签 → SIG 信号 → JUD 判定 → OUT 成品 → USE 消费`（主链路）
- `PRE-2 标签 → JUD 门禁/聚合`（直接依赖，不经过 SIG）
- `USE → JUD 实时调用`（弹窗/个股页请求时实时计算，不依赖 OUT 日终快照）

## 五、现存问题清单

### 问题 1：opportunity_profile 是 PRE-2 旧体系遗留（架构性）

- **生产位置**：PRE-2 `_build_opportunity_profile()`（从 7 个原料标签推导）
- **消费位置**：treemap 弹窗画像行 + 个股页诊断卡 + DeepSeek prompt
- **问题**：与 JUD-2 维度层使用不同数据源、不同判定逻辑，导致矛盾结论
- **设计要求**（332 号§5.4）：成品仓唯一消费，弹窗/个股页/快照三处口径一致
- **建议方案 B**：保留七维画像展示结构，数据源改为 JUD dim_states 映射

### 问题 2：treemap_snapshot 是双源混合表（架构性）

- 47 列中 27 列来自 PRE-2 标签，4 列来自 JUD 输出
- 前端从同一张表可以读到两套不同口径的数据
- **设计要求**：成品层应统一数据来源

### 问题 3：前端同时渲染两套七维（展示层）

- treemap 弹窗：九维灯（JUD 输出）+ 画像行（PRE-2 opportunity_profile）
- 个股页：诊断卡（PRE-2 opportunity_profile）+ 体检报告（JUD dim_states）
- **设计要求**：同一页面只展示一套口径

### 问题 4：confidence 与 consensus 分离（逻辑性）

- advice_builder 的 confidence 由 factor.conflict_items 数量决定（≥3→低）
- consensus_rate 由 JUD-3 维度计票决定
- 两者独立计算，可能出现"100%共识+低置信度"的矛盾组合

### 问题 5：is_win 数据质量（数据性）

- signal_records 存在重复记录（000002.SZ 同日 100 条相同记录）
- 单条 is_win 计算时 return 未回填（ret=0.07% 但 is_win=0）

### 问题 6：342 号遗留未完成项（验证性）

- 历史问题股白盒抽查：已完成（4 只全判定合理）
- G3.3 多交易日时间序列：已完成（2 天稳定性确认）
- is_win watch 语义疑点：已完成（逻辑正确，数据质量有问题）
