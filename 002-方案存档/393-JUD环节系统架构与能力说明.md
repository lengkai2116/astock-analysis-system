# 393 — JUD环节系统架构与能力说明

> **文档定位**：本文档基于系统代码实际实现倒推编制，描述JUD（现状判定）环节的真实架构、L1-L6六层组件、配置系统、管道集成及输出，反映2026-09-17代码审计+391号修复后的系统现状。

---

## 一、JUD环节定位

JUD是数据管道第6步（COL→RAW→SIG→JUD→OUT），负责**股票现状判定**——将SIG的多维度分析结论聚合为单一的`opportunity_state`（enter/light/wait/avoid）和操作建议。

**核心职责**：
1. 消费SIG预计算的dim_results，通过L1-L6六层流水线产出判定结论
2. 计算共识率、冲突检测、综合评分
3. 生成操作建议（仓位/止损/目标/入场区间）
4. 输出到status_snapshot成品表供前端消费

**设计原则**：
- 纯判定层，不做分析（分析在SIG完成）
- 多因子决策，非单一标签决定论
- 向后兼容：通过`jud_engine_version`开关支持新旧管线切换

## 二、主流程 evaluate()

### 2.1 完整调用链

```
StatusEngine.evaluate(ts_code, dim_results=None)
  │
  ├─ 1. _load_tags(ts_code)              → pre_feat_cache读标签
  ├─ 2. _load_signals(ts_code)           → strategy_signal_detail读信号
  ├─ 3. _signal_lifecycle(ts_code)       → 计算信号生命周期
  ├─ 4. _build_dim_engine_results()      → 7引擎维度判定（若dim_results未传入）
  ├─ 5. Dim8SummaryEngine().evaluate()   → 状态总结
  ├─ 6. _convert_to_dims_format()        → 旧格式转换（legacy兼容）
  ├─ 7. _apply_l0()                      → L0风险分级
  │
  ├─ 8. if v390: _aggregate_v390()       → 新管线L1-L6
  │    else:     _aggregate()            → 旧管线
  │
  ├─ 9. _detect_registered_signals()     → 信号触发检测
  ├─ 10. _assemble()                     → 组装输出
  └─ 11. 性能日志（>500ms告警）
```

### 2.2 配置切换

```python
_engine_version = self.cfg.get('jud_engine_version', 'legacy')
if _engine_version == 'v390' and dim_engine_results:
    l2 = self._aggregate_v390(...)   # 新管线
else:
    l2 = self._aggregate(...)        # 旧管线
```

**当前配置**：`config/status_engine.yaml` → `jud_engine_version: "v390"`（新管线已激活）

## 三、v390新管线（L1-L6）

### 3.1 架构全景

```
dim_results（SIG预计算）
  │
  ▼
L1 dim_adapter.convert_to_factors()     → dims_factor（13维因子）
  │
  ▼
L2 reliability_assessor.assess()         → reliability（7维可靠性）
  │
  ▼
L3 consensus_engine.compute()            → consensus（6族去相关+可靠性加权）
  │
  ▼
L4 conflict_matrix.detect()              → conflict（14条规则+4种语义）
  │
  ▼
L5 factor_arbiter.arbitrate()            → final_score + opportunity_state
  │
  ▼
L6 advice_engine.compute_advice()        → advice_params（动态仓位+止损/目标）
```

### 3.2 L1 维度适配层

**文件**：`dim_adapter.py` convert_to_factors()（L443-855，855行）

**职责**：将7引擎的嵌套输出统一转换为JUD内部的因子格式。

**输出格式**：13维因子

```python
dims_factor = {
    'signal':     {'direction': int, 'strength': float, 'evidence': list[str]},
    'structure':  {'direction': int, 'strength': float, 'evidence': list[str], 'stage_name': str, ...},
    'vp':         {'direction': int, 'strength': float, 'evidence': list[str], 'divergence': str, ...},
    'chip_fund':  {'direction': int, 'strength': float, 'evidence': list[str], ...},
    'emotion':    {'direction': int, 'strength': float, 'evidence': list[str], 'slow_confidence': float},
    'risk':       {'direction': int, 'strength': float, 'evidence': list[str], ...},
    'valuation':  {'direction': int, 'strength': float, 'evidence': list[str], ...},
    'time':       {'direction': int, 'strength': float, 'evidence': list[str]},
    'finance':    {'direction': int, 'strength': float, 'evidence': list[str]},
    'event':      {'direction': int, 'strength': float, 'evidence': list[str]},
    'factor':     {'direction': int, 'strength': float, 'evidence': list[str]},
    'position':   {'direction': int, 'strength': float, 'evidence': list[str]},
    'signal_confirm': {'direction': int, 'strength': float, 'evidence': list[str]},
}
```

**各维direction映射规则**：

| 维度 | 映射规则 |
|------|----------|
| signal | right_confirmed→+1, risk_warning→-1 |
| structure | judgment.overall_direction + buy_sell_points增强 |
| vp | state_machine_direction: BUY→+1, SELL→-1 |
| chip_fund | judgment.phase→DIM_DIRECTION查表 |
| emotion | ice→+1(看多), positive→-1(看空)（均值回归） |
| risk | risk_level+rr_value组合判定 |
| valuation | composite_rating: ≥0.5→+1, ≤-0.5→-1 |

**降级路径**：引擎输出缺失时回退到tags标签

### 3.3 L2 可靠性评估层

**文件**：`reliability_assessor.py` assess()（345行）

**职责**：每个维度对自身信号可靠度进行评估，输出reliability（0-1）。

**评估规则**：

| 维度 | 可靠性来源 | 映射规则 |
|------|-----------|---------|
| signal | maintenance.status | healthy→0.8, fading→0.5, decayed→0.2 |
| structure | level_cross_score + chanlun_strength_components + divergence_multi_algo一致性 | 三源加权+算法一致性±0.1 |
| vp | multi_timeframe_consistency + three_laws.effort_result + stage_confidence | "一致"→0.9, "冲突"→0.3 |
| chip_fund | pde_conflict + phase_confidence + pde_vote_ratio | conflict=False且conf>0.6→0.8 |
| emotion | bociasi_slow_confidence + sector_heat | slow_confidence直接用 |
| risk | atr_pct(反向) + volatility_percentile | atr_pct<0.3→0.9, >0.7→0.4 |
| valuation | pe_percentile_5y可用性 + pb/ps极端百分位 | is not None→0.8 |
| 其他6维 | 默认 | 0.5 |

**降级**：单维评估异常不影响其他维度，默认reliability=0.5

### 3.4 L3 共识聚合层

**文件**：`consensus_engine.py` compute()（354行）

**职责**：将13维因子聚合为综合共识得分。

**计算流程**：

```
Step 1: 族级去相关（13维→6族）
Step 2: 状态依赖权重矩阵（6族×6情绪阶段）
Step 3: 可靠性加权共识得分
Step 4: 中性方向处理
```

**6族分组**：

| 族 | 包含维度 |
|----|---------|
| main_behavior（主力行为） | chip_fund |
| structure_trend（结构趋势） | structure + signal + time |
| volume_price（量价状态） | vp |
| valuation_quality（估值质量） | valuation + finance |
| environment（环境） | emotion + event + factor |
| risk（风险） | risk（独立否决权） |

**状态依赖权重矩阵**（6阶段×6族）：

| 族 | ice | ebb | normal | recovery | positive | climax |
|----|-----|-----|--------|----------|----------|--------|
| main_behavior | 0.15 | 0.20 | 0.25 | 0.25 | 0.20 | 0.15 |
| structure_trend | 0.15 | 0.20 | 0.20 | 0.20 | 0.20 | 0.15 |
| volume_price | 0.20 | 0.20 | 0.20 | 0.20 | 0.20 | 0.20 |
| valuation_quality | **0.30** | 0.20 | 0.15 | 0.15 | 0.15 | 0.10 |
| environment | 0.10 | 0.10 | 0.10 | 0.10 | 0.15 | 0.20 |
| risk | 0.10 | 0.10 | 0.10 | 0.10 | 0.10 | 0.20 |

**设计意图**：冰点期估值权重最高（恐慌创造低估机会），高潮期风险权重最高（追涨风险大）

**族内合并**：方向取多数，强度用真实strength值（非direction绝对值），族内冲突惩罚×0.6

**中性处理**：neutral维度占比>60%时，共识率cap到0.5

### 3.5 L4 冲突矩阵层

**文件**：`conflict_matrix.py` detect()（318行）

**职责**：检测维度间信号冲突，识别组合语义模式。

**14条冲突规则**：

| 规则 | 冲突模式 | 等级 |
|------|---------|------|
| C1 | 缠论欲病+右侧强确认 | warn |
| C2 | 量价下跌趋势+结构看多 | warn |
| C2b | 多时间框架趋势分歧 | warn |
| C3 | 情绪冰点+估值低估+量价背离 | warn |
| C4 | 主力建仓+筹码拥挤 | warn |
| C4+ | 主力出货+标注建仓/拉升 | **fatal** |
| C4++ | 单峰密集+高拥挤+高获利 | **fatal** |
| C5 | 高波动+低盈亏比+弱共识 | warn |
| C6 | 背驰+123反转信号 | warn→**fatal**(>0.7) |
| C7 | risk=高+右侧确认 | **fatal** |
| C8 | 盈利盘>80%+无主力 | **fatal** |
| C9 | 监管事件（冗余安全检查） | **fatal** |
| C10 | 背驰+多数维度看多 | warn |
| C11 | 量价顶背离+结构看多 | warn |
| C11+ | 量价顶背离+缩量+看多 | **fatal** |
| C12 | 量价引擎风险提示+方向看多 | warn |
| C13 | 盈亏比计算不一致 | warn |
| C14 | 估值分歧PB高估+PE低估 | warn |

**4种语义类型**：

| 类型 | 条件 | 调整系数 |
|------|------|---------|
| 矛盾型 | 致命冲突≥1或warn≥3 | ×0.5 |
| 追高警示型 | consensus≥0.8且距前高>-3% | ×0.7 |
| 确认型 | 方向一致≥4/6且consensus≥0.7 | ×1.15 |
| 初现型 | 方向一致=2/6且无强维度 | ×1.0 |

### 3.6 L5 多因子仲裁层

**文件**：`factor_arbiter.py` arbitrate()（219行）

**职责**：融合共识得分、冲突结果、硬否决条件，计算综合评分。

**6步评分流水线**：

```
Step 1: 硬否决检查（right_side_confirm=否决/regulatory/fatal_to_veto → 一票否决）
Step 2: base = consensus_rate × 100
Step 3: 综合分 × semantic_adjustment（语义调整）
Step 4: 综合分 × rsc_multiplier（right_side_confirm门控：强确认×1.0, 基础确认×0.8, 未确认×0.5）
Step 5: 情绪极端修正（temperature>80→×0.85, <20→×0.75）
Step 6: 阈值映射 → opportunity_state
```

**阈值映射**：

| 综合分 | opportunity_state | 含义 |
|--------|-------------------|------|
| ≥70 | enter | 可入场 |
| 55-69 | light | 可轻仓 |
| 30-54 | wait | 等待 |
| <30 | avoid | 回避 |

### 3.7 L6 操作建议层

**文件**：`advice_engine.py` compute_advice()（737行含迁移函数）

**职责**：根据综合评分和多维度输入，计算仓位比例、止损位、目标位等操作建议。

**8步动态仓位模型**：

```
Step 1: 基础仓位（≥70→0.6, 55-69→0.4, 30-54→0.1, <30→0）
Step 2: × L0软风险系数（position_coeff）
Step 3: min(仓位, emotion_position_cap)
Step 4: 风险预算约束（2%规则，需entry_price）
Step 5: 波动率调整（atr_pct>0.8→×0.6）
Step 6: 盈亏比调整（rr/2.0, 上限1.0）
Step 7: 距防守位调整（dist>-2%→×0.6）
Step 8: 单票上限30%
```

**输出字段**：

```python
advice = {
    'max_position_ratio': 0.25,        # 最大仓位比例
    'hold_only': False,                 # 是否仅可持有
    'soft_risks': [...],                # 软风险列表
    'hard_veto': False,                 # 硬否决标志
    'stop_loss_price': 10.62,           # 止损位
    'target_price': 11.75,              # 目标位
    'risk_reward_ratio': 1.8,           # 盈亏比
    'entry_zone': [10.80, 11.20],       # 入场区间
    'target_zone': [12.0, 13.0],        # 目标区间
    'invalidation_conditions': [...],   # 失效条件
    'temperature': 62,                  # 情绪温度
    'atr_pct': 1.5,                     # ATR百分比
    'risk_budget_position': 0.22,       # 风险预算仓位
    'final_score': 68.5,                # 综合评分
    'semantic_type': '确认型',           # 组合语义类型
    'consensus_detail': {...},          # 共识明细
    'conflict_summary': {...},          # 冲突摘要
    'reliability_summary': {...},       # 可靠性摘要
}
```

## 五、管道集成

### 5.1 JUD步骤执行

```
_run_pipeline_step(today, 'JUD', _jud_build, codes)
  │
  ├─ _build_status_snapshot(codes)        子步骤1：现状成品
  │   ├─ StatusEngine单例获取
  │   ├─ 读取dim_results_json缓存
  │   ├─ ThreadPoolExecutor(8)并行evaluate
  │   ├─ 组装status_snapshot_new临时表
  │   └─ 原子替换DROP+RENAME
  │
  ├─ _jud_enrich_with_meta(codes)         子步骤2：机会分类+潜力+右侧确认
  │   ├─ _compute_opportunity_meta()
  │   ├─ _check_right_side_confirm()
  │   └─ PotentialEngine.compute_potential()
  │
  └─ _build_treemap_snapshot(codes)       子步骤3：treemap快照
```

### 5.2 性能

- **并行评估**：ThreadPoolExecutor(max_workers=8)
- **DB写入串行**：SQLite单写入者约束
- **全市场耗时**：~5000只×~50ms/只÷8线程≈~30s
- **单只告警**：>500ms记录日志

### 5.3 错误处理

- **步骤级**：`_run_pipeline_step` try/except → 标记failed
- **重试**：最多3次（retry_count<3 → pending重入）
- **超时**：4小时全局超时自动重置
- **子步骤级**：`_jud_enrich_with_meta`失败不影响status_snapshot已写入数据

## 七、降级策略总览

| 场景 | 降级行为 |
|------|---------|
| 单引擎dim_results=None | L1该维度回退到tags |
| reliability缺失 | 默认0.5（等权） |
| conflict_matrix异常 | semantic_adjustment=1.0 |
| factor_arbiter异常 | 返回wait |
| advice_engine异常 | 返回空advice |
| dim_results整体为空 | evaluate返回None |
| 配置文件缺失 | jud_engine_version默认'legacy' |
| fatal_to_veto≥1 | 直接返回wait（不进入评分） |
| L0 hard_veto | 直接返回avoid |
| consensus_rate=0 | 评分<30→avoid |

## 八、与SIG的关联

### 8.1 数据流

```
SIG步骤
  → strategy_signal_detail.dim_results_json（7引擎预计算）
  ↓
JUD步骤
  → 读取dim_results_json → StatusEngine.evaluate()
  → L1 convert_to_factors() 从dim_results提取13维因子
  → L2-L6 产出判定结论
  → 写入status_snapshot
```

### 8.2 JUD对SIG的依赖

| JUD层 | 消费的SIG字段 |
|-------|-------------|
| L1 | 7引擎status_description+judgment全部字段 |
| L2 | level_cross_score, multi_timeframe_consistency, phase_confidence, bociasi_slow_confidence, atr_pct, pe_percentile_5y等 |
| L4 | stage_name, divergence, vol_ratio, chanlun_phase, retail_institution, cost_concentration等 |
| L5 | right_side_confirm(tags), catalyst_event(tags) |
| L6 | support_price, resistance_price, rr_value, entry_zone, target_zone, temperature |
