## 一、核心发现：系统当前**不存在**任何自动定时机制

经复盘所有后端代码与 14 份模块规格书，得出一个重大结论：

### 1.1 scheduler.py 为死代码

- `backend/app/scheduler.py` 定义了完整的定时任务函数（T+5/10/20 回测检查、周度评估、月度参数平原校验）
- `register_scheduler_jobs()` 函数接收 APScheduler 实例作为参数 → **但该函数从未被任何代码调用**
- `run.py` / `__init__.py` 中均**不存在** APScheduler 的初始化和启动逻辑
- `requirements.txt` 中**未包含** `apscheduler` 依赖
- → 所有已定义的定时任务**永远不会被执行**

### 1.2 所有同步脚本均为手动 CLI

| 脚本 | 用途 | 执行方式 | 自动化状态 |
|:-----|:------|:---------|:-----------|
| `sync_data.py` | 同步股票列表 + 热门股日线 | `python sync_data.py` | ❌ 手动 |
| `incremental_sync.py` | 增量同步全市场日线 | `python incremental_sync.py` | ❌ 手动 |
| `bulk_sync.py` | 批量全量同步 | `python bulk_sync.py` | ❌ 手动 |
| `init_duckdb_cache.py` | DuckDB 缓存初始化 | 单次脚本 | ❌ 手动 |
| `init_duckdb_simple.py` | 简化初始化 | 单次脚本 | ❌ 手动 |

### 1.3 系统管理 Tab② 的"定时调度配置"仅为前端 Mock

- 225号规格书记载：`GET+POST /api/v3/system/sync/schedule` 为 **P1 待建**
- 前端提供定时调度下拉菜单 + 保存按钮 → 纯前端展示，后端对应 API **不存在**

## 二、A 股市场时间约束

### 2.1 核心时间点

| 时间 | 事件 | 数据可用性 |
|:-----|:------|:-----------|
| **09:00** | 集合竞价开始 | 隔夜信息、前日盘后数据 |
| **09:25** | 开盘价确定 | 集合竞价结果 |
| **09:30** | 连续竞价开始（上午盘） | 实时行情可用 |
| **11:30** | 上午收盘 | 半日累计数据 |
| **13:00** | 下午盘开始 | — |
| **15:00** | 收盘 | 当日最终行情 |
| **~15:30** | Tushare 盘后数据可用 | daily()/daily_basic()/moneyflow() 等 |
| **~17:00** | 龙虎榜数据可用 | top_list() |
| **20:00~次日 08:00** | 财务数据更新窗口 | fina_indicator()/income() 等可能 T+N 更新 |
| **周末/节假日** | 非交易日 | 无新数据 |

### 2.2 Tushare API 调用限制

- 当前积分：**5000 分**
- 每日总调用额度：约 **50000~80000 次**（按 5000 分档位）
- 调用频率限制：**~200 次/分钟**
- **关键约束**：单次 `pro.daily(trade_date=xxx)` 可获取全市场约 5000 只股票的日线数据（1次调用）
- **关键约束**：单次 `pro.daily_basic(trade_date=xxx)` 也可获取全市场基本面数据（1次调用）

**数据量估算**：
- 全市场日线同步：1 次调用/天
- 全市场基本面同步：1 次调用/天
- 全市场资金流向同步：1 次调用/天
- 指数日线 4 指数：4 次调用/天
- 复权因子全量：~1 次调用/天（或按需）
- → **每日基础同步仅需 ~10 次 API 调用**，额度完全充足

```
├──────────┼──────────────────┼───────────────────────────────┤
│ 层级二   │ 日内刷新层        │ 交易时段 9:30-15:00 周期执行   │
```

### 5.2 触发时序图（建议）

```
时间     事件                         触发动作
───      ────                         ────
09:00    开盘前                        预热缓存（基于昨日盘后数据）
09:25    集合竞价结束                   无（实时数据已预热）
09:30    连续竞价开始                   启动日内定时器
  │                                    ├─ 5s: 指数行情刷新（WebSocket push）
  │                                    ├─ 30min: 资金流向刷新
  │                                    └─ 5/15/30/60min: 监控规则扫描
11:30    上午收盘                       无特殊操作
13:00    下午开盘                       无特殊操作

  │                                    ├─ pro.daily() → DuckDB/SQLite
  │                                    ├─ pro.daily_basic() → DuckDB
  │                                    ├─ pro.moneyflow() → DuckDB
  │                                    ├─ pro.index_daily() → DuckDB
  │                                    └─ pro.adj_factor() → DuckDB
16:00    日终同步完成                    层级三：触发分析计算
  │                                    ├─ 复盘中心模拟引擎日推进
  │                                    ├─ 监控通知批量评估
  │                                    └─ 缓存更新通知（WebSocket）
18:00                                   T+5/10/20 回测检查(已有代码)
周一06:00                               周度赢率评估(已有代码)
周日20:00                               周度报告生成(已有代码)
每月1日05:00                            月度参数平原校验(已有代码)
```

### 5.3 时间线存储建议

所有定时同步、计算结果存储在 DuckDB（OLAP 缓存）而非 SQLite（应用数据），确保：
- SQLite 不存储高频写入的缓存数据
- DuckDB 列式存储天然适合定期写入 + 分析查询
- 旧数据可设置保留期自动清理（保留策略：日线 5 年、分钟线 30 天、资金流向 1 年）
