# 444 — SIG 股票现状描述的事实层构建与显现

> **v0.2 重构说明（2026-09-16）**：用户拍板本号**去仲裁化**。v0.1 名称为「事实层仲裁」——但事实既然唯一既定，**不需要仲裁**；仲裁/判定是 JUD 的职责。本号只做：**把每个现状字段变成单一事实来源（SSOT），按事实显现契约组织成可读的现状描述，喂给 OUT/前端**。矛盾清单重新定位为「标签污染审计报告」（净化依据），主源表升级为「SSOT 单一事实来源表」。

## 〇、起因与用户方法论修正

### 起因（2026-09-16）
437-A 样板预审（000002.SZ 真实数据）时，用户以普通股民视角审读发现——**按 437-A 建议值排出的七段式输出不能说明股票现状，叙事逻辑缺失**。用户指出这正是一直无法完成 437-A 排版的原因，并纠正方法论：**叙事是最后一个方面，先弄清楚内容、框架、逻辑**（4 步流程，见 §一）。本号按此重构 437-A 前置，**不修改 437-A 既定方案内容**，先补「事实层构建 + 现状框架 + 叙事骨架」三层前置设计。

### 用户方法论修正（2026-09-16，本号 v0.2 基石）
用户审读矛盾清单后提出核心质疑：*"如果是同样的数据源、同样的分析逻辑和维度，为何会出现相互矛盾的结论？现状应该是既定存在的唯一。"*

代码实证支持该判断：**现状（事实层）唯一自洽，矛盾全部发生在标签/结论层**——无一项是"两个事实打架"，全是同一条数据链路上某环节出错/口径分叉/代理错位，导致同一事实被加工成互相矛盾的标签（§三）。

由此拍板三条：
1. **事实无仲裁**：事实唯一既定，凡需"裁决哪个结论对"的，全部是 JUD 的职责，不在 SIG。
2. **SIG 双职责**：① 整理事实 → OUT → 前端消费（现状描述，唯一、可验证）；② 策略引擎分析输出结论 → JUD → 判定与操作建议。本号只做第①条。
3. **多数"矛盾"的解法是删除，不是裁决**：如 derived 的 volatility_level/risk_level/price_position 三个伪字段**本身没有测量任何东西**（量比≠波动率、买卖点≠价格位置、main_force_phase 从未接线）——直接删除伪字段，矛盾自动消失，每个概念只剩一个真实测量。

**辨析（避免误读）**：技术口径的选型 ≠ 对股票状态的判定。选 ATR 还是量比作为"波动率"的唯一生产口径是工程决策；口径定了，"波动率"就是唯一事实。判定"波动率高低、该不该警惕"才属 JUD。

### 用户方法论修正（第二波，2026-09-16 审读 v0.2 后拍板）
1. **现状=事实层=唯一，共识达成**：dim8 输出的股票现状描述 = 整理这个事实（事实层）。
2. **矛盾解法 = 梳理统一，不是删除**：各 dim 的策略分析**依赖这些事实字段**，简单删除可能导致 dim 分析出问题。正确顺序（三步走）：**数据同源、依据标准统一、事实情况输出统一**——确立单一事实来源（SSOT）→ 迁移所有消费方从 SSOT 读 → 再废弃冗余字段（此时删除才安全）。
3. **净化边界：只解决"事实的矛盾"，不解决"策略结论的矛盾"**：事实一定唯一；但不同策略视角对同一事实的组合/分析会产生结论差异——这种**结论矛盾允许存在、不归本号处理**（是 JUD 判定输入）。444 只统一"事实字段"的生产与口径，**绝不触碰 dim 的分析结论/判定逻辑**。
4. **现状 = 因果链的因，绝不是果**：结论（果，如"走势上升"）由引擎判定规则（如满足条件 1 或 2 → 上升）产出；**被实际满足的条件（因，如"满足条件 2"）才是现状**。dim8 整理的就是"因"（= audit.conditions 中 satisfied=true 的项），不整理"果"。详见 §一 判据。

## 一、方法论（用户拍板的 4 步流程 + 现状判据）

1. **原料盘点**：全面看 dim2-dim7 包括 RAW 简单计算能产出哪些初始数据，涵盖一只股票哪些类型的信息（原料）。✅ 已完成（§二）
2. **现状框架**：这些原料能搭建出什么样的"股票现状"（**而非分析/判定结论**）初步框架。→ v0.2 重构为 **SSOT 单一事实来源表 + 事实显现契约**（§四）
3. **覆盖度评估**：框架能否说清现状？哪些事实字段缺生产点、哪些被标签污染掩盖、需调整引擎还是补充数据佐证。→ v0.2 重构为 **事实生产核查**（§五）
4. **叙事结构**：事实按因果链组织成可读叙述，确认叙事方式与描述风格。→ v0.2 重构为 **事实的因果显现**（§五）

**现状 vs 结论判据（本号核心口径）**：
> **现状** = 不依赖"好/坏、涨/跌、强/弱"评价，换一个观察者用同一批数据必然得到相同结论的、可验证的状态描述。
> - ✅ 现状："现价 3.05 元，处于近 120 日区间中位，距前高 -10%"
> - ❌ 结论："低位""强健康 8/10""结构向上""值得交易"（评价/预期/操作）
> - ⚠️ 灰色："均线多头排列"是**形态命名**（可验证 MA5>MA10>MA20）算现状；"看涨"是结论。结论必须能回溯到事实。

**因果链因/果模型（本号核心逻辑，2026-09-16 用户拍板）**：
> **现状 = 因果链的因，绝不是果。**
> - **果（结论）**：引擎判定输出，如"走势上升""值得买入"。
> - **判定规则**：引擎代码里的条件集，如"满足条件 1 或 2 → 上升；满足条件 3/4/5 → 下降"。
> - **因（现状）**：该股票数据**实际满足的条件**（如"满足条件 2"）——这才是现状，是 dim8 整理的对象。
> - 与 audit 条件稽核对应：`conditions[].{satisfied=true}` 的项就是"因"。dim8 整理 satisfied=true 的条件（现状），**不整理结论（果）**。
> - 例：结论"走势上升"（果）；实际满足"条件2：MA5>MA10>MA20 且近5日收盘走高"（因）→ dim8 输出的是条件2 的事实描述，不是"上升"。

## 四、SSOT 单一事实来源表（第②步，进行中）

### 4.1 定义与模板
每个现状字段 = 单一事实来源：**全系统只有一处生产、一个口径、一个单位**；其余引擎只读不重算。

**统一三原则（2026-09-16 用户拍板，矛盾解法 = 梳理统一，不是删除）**：
1. **数据同源**：同一事实概念从同一数据表/同一计算点产出；
2. **依据标准统一**：同一概念的口径、阈值、枚举值域全局唯一；
3. **事实情况输出统一**：同一事实输出到同一键名、同一单位、同一展示格式。

**安全废弃前提**：任何字段只有在"SSOT 确立 + 所有消费方已迁移到 SSOT"之后才允许废弃（删除）。删除不是解法，是统一完成后的收尾动作——否则 dim 分析会失去依据（如 derived.risk_level 正被 dim6:236/288 消费）。

**净化边界（本号只做事实层）**：SSOT 只统一"事实字段"的生产与口径；**不触碰各 dim 的分析结论/判定逻辑**（不同策略对同一事实组合出的结论差异允许存在，属 JUD 判定输入）。

字段契约模板：
```
{字段名 | 数值 | 单位 | 时间窗 | 唯一生产点(SSOT) | 口径 | 消费方}
```
