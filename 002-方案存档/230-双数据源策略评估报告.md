### 2.2 Tushare 盘后角色是否合理？

AKShare 分担盘中查询后，Tushare 每日调用量从 **~168 次降至 ~10 次**（减少 94%）：

| 日终操作 | 调用次数 | 时间 |
|:---------|:---------|:-----|
| pro.daily() 全市场日线 | 1 | 15:30 |
| pro.daily_basic() 全市场基本面 | 1 | 15:30 |
| pro.moneyflow() 全市场资金流向 | 1 | 15:30 |
| pro.index_daily() 4 指数 | 4 | 15:30 |
| pro.adj_factor() 复权因子 | 1 | 15:30 |
| pro.stock_basic() 股票列表 | ~1 | 按周 |
| 月度财务数据 | ~20 | 按需 |
| 用户主动查询（日线/分钟线） | ~50 | 按需 |
| **日终基础** | **~10** | **15:30~15:35** |

Tushare 仅用于：
1. **日线权威存档** — DuckDB 存储 5 年历史 K 线的单一可信源
2. **基本面财务数据** — `fina_indicator`/`income`/`balancesheet` 等（AKShare 不具备结构化财务能力）
3. **历史数据补全** — 新股历史、停牌期间缺失日线

**结论：合理。** 5000 分的 Tushare 额度完全溢出，其核心价值从"全量查询"变为"日终存档"。

### 2.3 QMT 升级路径设计

采用 **配置即服务** 模式——不写死任何 QMT 依赖，通过系统管理 Tab③ 一键激活：

```
AKShare (盘中, priority=-1)
  ↓ QMT 开通并配置后
QMT (盘中, priority=-2, 条件注册)
  ↓ 替换
AKShare 降级为 T+1 备份 (priority=0)
  ↓ 保持不变
Tushare 盘后存档 (priority=0)
```

**QMT 替换范围（替换 AKShare 的盘中能力，不碰 Tushare 的盘后角色）：**

| 能力 | AKShare | QMT 替换后 |
|:-----|:--------|:------------|
| 实时行情 | 3-15s REST 轮询 | <1s WebSocket 推送 |
| 逐笔成交 | ❌ 不支持 | ✅ xtdata tick |
| 全市场快照 | 单次 spot_em 覆盖 | 实时订阅推送 |
| 分钟 K 线 | REST 调用 | 订阅+本地缓存 |
| 盘口深度 | 5 档 | 10 档+ |

**实现方式**：环境变量 `QMT_ENABLED=true` + 系统管理配置保存 → `__init__.py` 条件注册 `QmtDataProvider` 到 `DataSourceManager`（`priority=-2`）。用户无需重启、无需改代码。

## 三、当前系统关键问题

审计发现 3 个需要修复的问题：

### 问题一：「实时数据不实时」（严重，当前代码 bug）

`backend/app/routes/realtime.py` 中 `RealtimeDataService._get_stock_realtime_data()` 的核心路径调用 `tushare.get_daily_data(ts_code)` —— 返回的是 **昨日收盘价**，根本不是实时数据。

```python
# 当前（错误）:
latest = tushare.get_daily_data(ts_code)  # → 昨日收盘价
# 预期:
latest = akshare.get_realtime_spot(ts_code)  # → 今日实时最新价
```

**影响**：任何调用"实时行情"API 的页面（个股策略右侧 28 字段、自选监控批量行情）在交易时段拿到的都是过期数据。

### 问题二：TTLCache 未实现（仅注释中承诺）

`backend/app/data/redis_cache_manager.py` 的文档字符串声称"已使用 cachetools.TTLCache 替代 Redis"，但实际代码中：
- `cachetools` 未出现在 `requirements.txt` 中
- 全项目 grep `TTLCache` / `cachetools` **零命中**
- `RedisCacheManager` 回退到普通 `dict`（无 TTL，无限膨胀）

### 问题三：AKShare 导入名不匹配

`backend/app/__init__.py:206`：
```python
from app.data.akshare_provider import AkshareProvider  # ← 类不存在
```
但 `akshare_provider.py` 中只有 `AkShareRealtimeProvider` 类。这个 import 被 `try/except` 静默捕获，AKShare 在 DataSourceManager 中**实际不可用**。
