### 2.4 基于存储层设定的管道重排建议

292号存储层设定：**采集层写、计算层读写、调用层只读**。当前违规主要在计算层（dim引擎）和调用层（routes/services）绕过DataManager直连ECM。

**重排原则**：
1. 维度引擎必须通过 `DataAwareMixin._get_dm().cache` 读取数据
2. 路由层必须通过 `DataManager()` 实例读取数据
3. `pd.read_sql` 必须使用 `dm.cache` 提供的连接
4. 消除所有 `_get_conn()` 永久旁路

### 3.2 管道步骤部分失败行为（关键发现）

**所有12个管道步骤都存在同一问题：部分失败时仍标记 `done`。**

| 步骤 | 部分失败行为 | pipeline_status记录 | 下游影响 |
|------|------------|-------------------|---------|
| COL-1~5 | 数据≥4000行直接跳过标记done | done | 下游基于可能不完整的数据 |
| RAW-1 | 单股失败try/except跳过 | done | indicator表部分缺失 |
| **RAW-2** | 17组特征各自try/except，单组失败不影响整股 | done | **pre_feat_cache部分股票缺失，JUD跳过** |
| RAW-3 | 单股失败跳过 | done | factor_cache部分缺失 |
| **SIG** | compute_batch内部_safe_compute捕获异常 | done | **strategy_signal_detail部分股票缺失** |
| **JUD** | evaluate()返回None时continue跳过 | done | **status_snapshot部分股票缺失** |
| OUT | 单股透传失败跳过 | done | one_liner_detail部分缺失 |

**根因**：`_run_pipeline_step()` (L4677) 仅判断函数是否抛出异常，不检查返回值或处理计数。`pipeline_status` 表无 `total_stocks/success_count/failure_count` 字段。

### 3.3 `_is_pipeline_complete()` 仅检查步骤状态

```python
return row and row[0] >= 12  # 只数done步骤数，不查数据完整性
```

**不存在以下任何机制**：
- 步骤完成后验证输出表行数
- 跨步骤股票数一致性比对
- 基于数据完整性的自动补算触发
- pipeline_status记录成功/失败计数

## 八、SIG与JUD边界及模块归属（已确认）

### 8.1 SIG与JUD的明确区隔

> **SIG**：除状态描述（seven_dim_json）直入OUT外，其余输出（signal_json/dim_results_json）供JUD消费。
>
> **JUD**：产出仅供OUT，为前端提供调取支持。

| SIG产出 | 去向 | 说明 |
|---------|------|------|
| `signal_json`（5引擎信号） | → JUD消费 | 供StatusEngine._load_signals()读取 |
| `dim_results_json`（维度引擎结果） | → JUD消费 | 供_build_status_snapshot传入evaluate() |
| `seven_dim_json`（七维描述） | → **直入OUT** | 不经过JUD，直接写入one_liner_detail |

| JUD产出 | 去向 | 说明 |
|---------|------|------|
| `status_snapshot`（17列） | → OUT归档 + 前端调取 | 含9维状态/共识/仲裁/操作建议 |
| `treemap_snapshot`（47列） | → OUT归档 + 前端调取 | 图谱快照 |
| `opportunity_state` | → OUT + 前端 | enter/light/wait/avoid |
| `consensus_rate` / `direction` | → OUT + 前端 | 共识率和方向 |
| `advice_params` | → OUT + 前端 | 操作建议参数 |

### 8.2 模块归属决策

#### dim1（信号确认引擎）— SIG预计算，职责归JUD

dim1是**元维度**，不分析原始市场数据，读取dim2-dim7的判定结果做二次综合：
- 7类信号分类（右侧确认/左侧试探/趋势运行等）
- 共振评分（多维加权一致性）
- 衰减检测（5维信号衰减）
- 生命周期阶段（初中期/中期/已延伸）
- 条件审核清单

**5个独特子功能在JUD中无等价替代**。dim1在SIG中预计算（作为dim_results的一部分），结果传递给JUD消费（dim8/cross_validate/L2聚合），不重复计算。

#### PotentialEngine（潜力评分）— 归入JUD层

- **来源**：opportunity_atlas模块（313号方案），备份验证与当前文件一致
- **产出**：signal_strength(0-100)直接驱动前端图谱**方块大小**
- **性质**：判定类（6维IC加权聚合+情绪调节+质量否决+共振加分）
- **当前状态**：管道孤儿（旧P4调用已注释，SIG/JUD均未接入）
- **决策**：归入JUD层，在JUD步骤中调用，产出signal_strength写入treemap_snapshot

#### opportunity_meta（机会类型/画像）— 归入JUD层

- **_classify_opportunity_type**：16条优先级规则树，以main_force_phase为主轴联合多标签判定
- **_build_opportunity_profile**：7维独立评估（红绿灯）
- **_count_evidence**：证据命中率+置信度
- **_compute_entry_signals/exit_conditions**：策略规则模板
- **性质**：判定类（规则引擎）
- **决策**：归入JUD层，在JUD步骤中执行，产出写入treemap_snapshot供前端调取
