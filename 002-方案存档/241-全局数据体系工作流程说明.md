# 全局数据管理体系 — 工作流程说明

## 概览

自 239/240 号方案实施完成后，系统拥有 **4 条独立的数据路径**，按时间和场景自动路由：

```
时间轴        数据路径                  数据源           存储层           消费方式
─────────────────────────────────────────────────────────────────────────────
交易时段      盘中实时采集路径         AKShare(东方财富)  InMemoryStateStore  WebSocket 推送 + REST
(9:30-15:00)  按需查询路径(备用)       AKShare(东方财富)  TieredMemoryCache    REST（降级）
───────────────┼──────────────────────────────────────────────────────────────
盘后          日终同步路径             Tushare Pro       DuckDB *_cache     REST + 预聚合
(15:30+)      QMT 队列路径(可选升级)   QMT(券商直连)     本地DB/内存          WebSocket L2
```

## 一、盘中实时采集路径（主力，239号核心）

### 采集器架构

`AkshareCollector` 启动 **5 个 daemon 线程**，仅在 A 股交易时段工作：

```
┌─────────────────────────────────────────────────────────────────────┐
│ AkshareCollector (akshare_collector.py)                              │
│                                                                     │
│  Thread 1: 全市场快照 ── 15s ── stock_zh_a_spot_em() ── 覆盖式写入 │
│  Thread 2: 涨跌榜     ── 30s ── 东方财富直连 API    ── 覆盖式写入  │
│  Thread 3: 板块+涨跌停 ── 5min ─ board_industry + zt ── 覆盖式写入 │
│  Thread 4: 分钟K线    ── 5min ─ hist_min_em(自选200股) ── 追加式写入│
│  Thread 5: 龙虎榜+新闻 ── 30min─ lhb_detail + news   ── 覆盖式写入  │
└──────────────────────────┬──────────────────────────────────────────┘
                           │
                           ▼ (写入两处)
              ┌──────────────────────┐      ┌──────────────────┐
              │ InMemoryStateStore    │      │ DuckDB as_* 表   │
              │ (内存, O(1), 零IO)    │      │ (归档, 异步写入)  │
              │                      │      │                  │
              │ snapshot  ~5000 条   │      │ as_market_       │
              │ sectors        ~70  │      │ snapshot(覆盖)    │
              │ limit_pool    ~100  │      │ as_minute_kline   │
              │ minute_kline   ~200 │      │ (追加)            │
              │ ...                 │      │ as_limit_pool     │
              │                      │      │ (覆盖)            │
              └────────┬─────────────┘      └──────────────────┘
                       │
                       ▼ (采集完成回调)
              ┌──────────────────┐
              │ WsBridge          │ ← ws_bridge.py
              │ (WebSocket 桥接器) │
              │                   │
              │ market:summary    │
              │ market:top_stocks │
              │ market:sectors    │
              │ market:news       │
              │ stock:quotes      │
              └────────┬──────────┘
                       │
                       ▼ (SocketIO emit)
              ┌──────────────────┐
              │ 前端 useRealtimeData composable  │
              │ (WS 推送优先 / REST 降级轮询)    │
              └──────────────────┘
```

### 写入策略三分类

| 类型 | 说明 | 涉及表 | 数据量 |
|:-----|:------|:-------|:-------|
| **覆盖式** (overwrite) | 每次采集全量替换，只保留最新值 | `snapshot`, `sectors`, `limit_pool`, `top_stocks` | ~5000 行/次 |
| **追加式** (append) | 每轮追加新数据行，盘后清理 | `minute_kline` | ~200 股 × 5 分钟斜率 |
| **按需缓存** (on-demand) | 查询时写入，TTL 过期后下次查询刷新 | `lhb_detail`, `news`, `quote_cache` | 低频 |

### 5 个线程的间隔设计

```
总调用频次 ≈ 388 次/小时
│
├─ 15s 快照 × 240 次/小时 =  240 次  (最高频，全市场~5000只)
├─ 30s 涨跌榜 × 120 次/小时 = 120 次
├─ 5min 板块 × 12 次/小时  =  12 次
├─ 5min 分钟K × 12 次/小时  =  12 次
└─ 30min 龙虎榜 × 2 次/小时 =   2 次
```

远低于 AKShare 实际支撑能力（东方财富接口通常可承受每秒数十次调用）。

### 交易时段启停逻辑

```
交易时段 (9:30-11:30, 13:00-15:00):
  └─ 5 个线程按各自间隔正常采集

非交易时段:
  └─ 每个线程 wait(60s) 每分钟检查一次
      └─ 一旦进入交易时段 → 自动恢复采集

交易日判断:
  └─ trading_hours.is_trading_time() 执行日期+时间双重判断
```

## 二、按需查询路径（盘中 REST 降级，DataSourceManager）

当模块需要盘中数据时，通过 `DataSourceManager` 进行**时间感知路由**：

```
                              请求
                               │
                               ▼
                    ┌─────────────────────┐
                    │ DataSourceManager    │
                    │ get_data_time_aware()│
                    └──────────┬──────────┘
                               │
              ┌────────────────┴────────────────┐
              │                                 │
        交易时段?                           盘后/节假日?
              │                                 │
              ▼                                 ▼
    AKShare (priority=-1)              Tushare (priority=0)
         │                                   │
         ▼                                   ▼
   TieredMemoryCache(3s TTL)            DuckDB *_cache
         │                                   │
         ▼                                   ▼
    返回数据                            返回数据
```

### 数据源优先级

| 数据源 | priority | 适用场景 | 数据延迟 |
|:-------|:---------|:---------|:---------|
| AKShare | -1 | 盘中实时行情/板块/涨跌停 | 3-15s |
| Tushare Pro | 0 (默认) | 盘后日线/财务/历史数据 | T+1 |
| QMT (可选) | -2 (预留) | 券商直连 L2 行情 | <1s |

`get_data_time_aware()` 的切换逻辑：
- **交易时段**：从已注册源中筛选 `priority <= -1` 的（AKShare），按 priority 升序尝试
- **非交易时段**：走默认路由（Tushare），从 DuckDB 读取

## 三、盘后读取路径（AkshareDataReader 只读接口）

239号方案统一读取接口，**内存优先 → DuckDB 归档回退**：

```
模块请求
   │
   ▼
AkshareDataReader.get_xxx()
   │
   ├─ InMemoryStateStore.is_stale('snapshot')?
   │     │
   │     ├─ 新鲜 (age < 600s) ──→ 返回内存数据 (O(1), 零IO)
   │     └─ 过时 (age >= 600s) ──→ 回退 DuckDB as_* 表
   │
   └─ 5 分钟 staleness 阈值
       └─ 超过阈值时记录日志"行情数据可能延迟 X 分钟"
```

可用方法：

| 方法 | 内存键 | DuckDB 回退表 | 典型场景 |
|:-----|:-------|:--------------|:---------|
| `get_market_snapshot()` | `snapshot` | `as_market_snapshot` | 仪表盘统计卡片 |
| `get_batch_quotes(ts_codes)` | `snapshot` (过滤) | `as_market_snapshot` | 自选监控报价 |
| `get_realtime_spot(ts_code)` | `snapshot` (单只) | `as_market_snapshot` | 个股策略实时行情 |
| `get_top_stocks()` | `top_stocks` | - | 涨幅榜/跌幅榜 |
| `get_sector_rankings()` | `sectors` | `as_sector_ranking` | 板块排行面板 |
| `get_limit_pool()` | `limit_pools` | `as_limit_pool` | 涨跌停池 |
| `get_minute_kline(ts_code)` | `minute_kline` | `as_minute_kline` | 个股分时图 |
| `get_lhb_detail()` | `lhb` | `as_lhb_detail` | 龙虎榜面板 |
| `get_news()` | `news` | `as_news` | AI投研舆情 |
| `get_quote_cache(ts_code)` | - | `as_quote_cache` | 盘口五档 |

## 四、日终同步路径（Tushare 盘后）

由 `SchedulerManager.run_daily_sync()` 触发，每天 15:30 执行：

```
run_daily_sync() (APScheduler, 每天15:30)
   │
   ├─ 阶段1: Tushare 批量同步
   │   ├─ TushareProvider.get_daily_data()    → DuckDB daily_cache
   │   ├─ TushareProvider.get_daily_basic()   → DuckDB daily_basic_cache
   │   ├─ TushareProvider.get_moneyflow_data() → DuckDB moneyflow_cache
   │   └─ TushareProvider.get_adj_factor()    → DuckDB adj_factor_cache
   │
   ├─ 阶段2: 缓存预热
   │   └─ DuckDB 查询预执行（冷启动加速）
   │
   ├─ 阶段3: 发送 daily_sync_completed 信号
   │
   └─ 阶段4: 下游模块响应
       ├─ RuleScheduler → 执行日终条件评估
       ├─ 清理 as_minute_kline（当天分钟K线）
       ├─ 清空 TieredMemoryCache 盘中缓存
       └─ 清空 AkshareCollector 关注列表
```

盘后同步完成后，系统自动从"盘中模式"切换到"盘后模式"。
前端仪表盘在盘后读 DuckDB 预聚合数据，零 API 调用。


### 5 页面的推送规划

| 页面 | 优先级 | 状态 | 推送数据 | 实现方式 |
|:-----|:-------|:-----|:---------|:---------|
| **仪表盘** | P0 | ✅ 已完成 | 市场概况、涨跌榜、板块排行 | `useRealtimeData` composable → watch 增量更新 |
| **自选监控** | P0 | ⏳ 阶段二 | 自选股实时行情 | WS 订阅自选 code → 增量更新 |
| **个股策略** | P1 | ⏳ 阶段二 | 个股实时行情 | 页面打开时订阅 → 关闭时取消 |
| **监控通知** | P2 | ⏳ 阶段三 | 条件触发通知 | SSE 推送 + WebSocket |
| **复盘中心** | P2 | ⏳ 阶段三 | 历史日线按需 | 仍用 REST（推送非必须） |

## 六、异常场景保障

| 场景 | 保障措施 |
|:-----|:---------|
| **WebSocket 断连** | 前端自动降级为 REST API 轮询（30s 间隔），连接恢复后切回推送 |
| **采集器线程异常** | 单个线程异常不影响其他 4 个，异常后等待一个完整间隔自动重试 |
| **非交易时段** | 采集器每分钟检查一次，进入交易时段自动恢复；前端读 DuckDB 盘后数据 |
| **AKShare 不可用** | 盘中读内存上次成功数据 + 5 分钟 staleness 标记；超时后降级到 Tushare |
| **DuckDB 文件锁冲突** | `_clean_stale_duckdb_locks()` 启动时清理僵尸 .wal/.tmp 文件 |
| **Flask-SocketIO 重启** | 前端指数退避重连（1s → 1.5s → ... → 30s max，最多 10 次）|
| **代理环境变量** | 所有 Provider 模块加载时自动清除 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY |
