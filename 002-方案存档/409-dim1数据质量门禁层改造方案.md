# 409号 — dim1数据质量门禁层改造方案

---

## 一、问题背景

### 1.1 dim1当前定位与问题

dim1（Dim1SignalEngine）位于SIG环节，当前执行三件事：7类信号属性分类、5维度共振评分、衰减检测+生命周期。但存在以下结构性问题：

| 问题 | 说明 |
|------|------|
| **职责错位** | dim1做的是判定逻辑（属性分类、评分、衰减判断），与JUD重叠 |
| **消费率为零** | 389号审计显示dim1的18个输出字段0%被JUD消费 |
| **循环依赖** | dim1在engine_map中排第一，但classify_attribute()依赖dims.get('risk')等，此时其他dim尚未计算，dims传入空字典{} |
| **重复IO** | dim2-dim7各自独立调用ECM获取数据，同一只股票的daily_cache被查询5次，无内存缓存层（get_cached_daily每次直查SQLite） |

### 1.2 设计目标

将dim1从"信号确认引擎"重构为**SIG环节的数据质量门禁层**，职责：

1. **数据提取**：集中预加载dim2-dim7所需的全部数据
2. **质量校验**：对预加载数据执行完整性检查
3. **STG联动**：校验不通过时触发STG补算闭环（398号方案）
4. **数据供应**：校验通过后通过data_context参数传递给dim2-dim7

同时将dim1的判定逻辑（属性分类/共振评分/衰减检测/生命周期）迁移到JUD，使SIG成为纯分析环节。

### 1.3 与现有方案的关系

| 方案 | 关系 |
|------|------|
| 353号（总纲） | SIG直读STG原始表，dim1作为SIG第一步 |
| 398号（STG） | dim1的校验+补算闭环对接STG的QualityChecker和RecomputeScheduler |
| 407号（数据路径冲突） | dim1集中预加载消除dim2-dim7的重复IO |
| 408号（dim1重构） | 本方案是408号的深化版本，修正了调用顺序、传输路线、STG集成等设计问题 |

### 2.3 数据传输路线选择

```python

    """dim1作为数据质量门禁，返回data_context供dim2-dim7使用"""

    return {
        'status_description': {...},   # 数据质量报告
        'judgment': {...},             # 数据质量判定
        'audit': {...},                # 数据校验审计

```

status_engine.py在调用dim2-dim7时，从dim1结果中提取data_context并传递：

```python

data_ctx = results.get('signal', {}).get('data_context')

for dim_name in ['structure', 'volume_price', 'chip_fund', 'emotion', 'risk', 'valuation']:
    results[dim_name] = engine.evaluate(dims, tags, signals, lifecycle, data_context=data_ctx)
```

**选择路线A的原因（排除路线B/C）：**

| 路线 | 判定 | 原因 |
|------|------|------|
| 路线B（ECM内存缓存） | **排除** | 隐式耦合；进程迁移后失效；与STG质量语义不兼容（内存数据无法表达"已校验"） |
| 路线C（dims字典传递） | **排除** | dims混合了判定结果和预校验数据，职责混杂；跨进程序列化时DataFrame需额外处理 |
| 路线A（显式参数） | **采用** | 签名自文档化；故障链路可追踪；跨进程天然兼容；STG质量语义完整 |

### 3.2 核心流程

```python
class Dim1DataGate:
    """SIG数据质量门禁 — 提取+校验+STG联动+供应"""

    def evaluate(self, dims, tags, signals=None, lifecycle=None) -> dict:
        ts_code = tags.get('ts_code', '')
        trade_date = tags.get('trade_date', '')

        # 阶段1：批量数据提取
        raw_data = self._batch_extract(ts_code)

        # 阶段2：质量校验
        validation = self._validate(raw_data, ts_code, trade_date)

        # 阶段3：STG补算闭环（如有问题）
        if not validation.passed:
            repair_result = self._stg_repair_loop(raw_data, validation, max_rounds=3)
            if repair_result.success:
                raw_data = repair_result.repaired_data
                validation = repair_result.final_validation
            else:
                # 3轮补算仍失败，标记降级
                return self._build_degraded_result(ts_code, repair_result)

        # 阶段4：构建data_context
        data_context = self._build_data_context(raw_data, validation)

        return {
            'status_description': self._build_status_desc(data_context, validation),
            'judgment': self._build_judgment(validation),
            'audit': self._build_audit(validation),
            'data_context': data_context,
        }
```

```python
class DataValidator:
    """dim1数据质量校验器"""

    RULES = {
        'daily': {
            'min_rows': 60,           # 至少60个交易日
            'required_fields': ['open', 'high', 'low', 'close', 'vol', 'pct_chg'],
            'date_order': True,        # 日期升序排列
            'no_future_dates': True,   # 无未来日期
        },
        'daily_basic': {
            'min_rows': 20,
            'required_fields': ['pe_ttm', 'pb', 'total_mv'],
        },
        'moneyflow': {
            'min_rows': 5,
            'required_fields': ['net_lg_amount', 'buy_lg_amount', 'sell_lg_amount'],
        },
        'fina_indicator': {
            'min_rows': 1,
            'required_fields': ['roe'],
        },
        'income': {
            'min_rows': 1,
            'required_fields': ['revenue'],
        },
        'balancesheet': {
            'min_rows': 1,
            'required_fields': ['total_assets', 'total_liab'],
        },
        'cashflow': {
            'min_rows': 1,
            'required_fields': ['cashflow_oper'],
        },
    }

    def validate(self, raw_data: dict, ts_code: str, trade_date: str) -> ValidationReport:
        """执行全量校验"""
        issues = []
        scores = {}

        for table_name, rules in self.RULES.items():
            df = raw_data.get(table_name)
            result = self._check_table(table_name, df, rules, ts_code, trade_date)
            scores[table_name] = result.score
            if not result.passed:
                issues.extend(result.issues)

        return ValidationReport(
            passed=len(issues) == 0,
            scores=scores,
            issues=issues,
            completeness_score=sum(scores.values()) / len(scores),
        )
```

### 3.5 阶段3：STG补算闭环

```python
def _stg_repair_loop(self, raw_data: dict, validation: ValidationReport, max_rounds: int = 3) -> RepairResult:
    """STG补算闭环：校验→补算→再校验（最多max_rounds轮）"""

    for round_num in range(1, max_rounds + 1):
        # 1. 从校验结果提取需要补算的问题
        recompute_tasks = self._extract_recompute_tasks(validation)
        if not recompute_tasks:
            return RepairResult(success=True, repaired_data=raw_data, final_validation=validation)

        # 2. 写入sync_requests，通知daemon补算
        request_ids = []
        for task in recompute_tasks:
            request_id = self._get_dm().request_data(task_type=task.type, ts_code=task.ts_code)
            request_ids.append(request_id)

        # 3. 等待补算完成（轮询sync_requests状态）
        all_completed = self._wait_for_repair(request_ids, timeout_seconds=300)
        if not all_completed:
            logger.warning(f"dim1 STG补算第{round_num}轮超时")

        # 4. 重新提取数据
        raw_data = self._batch_extract(task.ts_code)

        # 5. 再校验
        validation = self._validate(raw_data, task.ts_code, task.trade_date)
        if validation.passed:
            return RepairResult(success=True, repaired_data=raw_data, final_validation=validation)

    # 3轮未通过
    return RepairResult(
        success=False,
        repaired_data=raw_data,
        final_validation=validation,
        failure_reason=f"{max_rounds}轮STG补算后仍不通过",
    )

def _extract_recompute_tasks(self, validation: ValidationReport) -> list:
    """校验问题→STG补算任务映射"""
    RECOMPUTE_MAP = {
        'daily缺失': ('COL', '_batch_daily'),
        'daily行数不足': ('COL', '_batch_daily'),
        'daily_basic缺失': ('COL', '_batch_daily_basic'),
        'moneyflow缺失': ('COL', '_batch_moneyflow'),
        'fina_indicator缺失': ('COL', '_batch_fina_indicator'),
        'income缺失': ('COL', '_batch_income_recent'),
        'balancesheet缺失': ('COL', '_batch_balancesheet'),
        'cashflow缺失': ('COL', '_batch_cashflow'),
    }
    tasks = []
    for issue in validation.issues:
        task_info = RECOMPUTE_MAP.get(issue.type)
        if task_info:
            tasks.append(RecomputeTask(type=issue.table, ts_code=issue.ts_code))
    return tasks
```

### 4.2 各dim改造清单

| dim | 读取的data_context字段 | 改造量 | 说明 |
|-----|----------------------|--------|------|
| dim2（结构） | `daily` | ~5行 | 替换`ecm.get_cached_daily()` |
| dim3（量价） | `daily` | ~5行 | 替换`ecm.get_cached_daily()` |
| dim4（筹码资金） | `daily` + `daily_basic` + `moneyflow` + `margin` + `stk_holder` + `lhb` | ~20行 | 替换6处数据库调用 |

**改造原则：**
- 每个dim独立改造，可渐进式实施
- 保留回退路径：data_context缺失时走原查询
- 不改变dim的分析逻辑，只改变数据获取方式

```python
def _call_engine(self, dim_name, dims, tags, signals, lifecycle, data_context=None):
    try:
        engine = self._load_engine(dim_name)
        if dim_name == 'signal':
            return engine.evaluate(dims, tags, signals, lifecycle)
        else:
            return engine.evaluate(dims, tags, signals, lifecycle, data_context=data_context)

        return None
```

```python
def assess_signal_reliability(dim1_result):
    if not dim1_result:
        return {'level': 'unknown', 'confidence': 0.5, 'evidence': ['dim1结果缺失']}

    judgment = dim1_result.get('judgment', {})

        'confidence': confidence_map.get(decay_status, 0.5),
        'evidence': [f'衰减状态={decay_status}'],
    }
```

### 5.4 迁移过渡期设计

dim1改造不是原子操作，存在v3.0→v3.1的共存期。必须确保过渡期内JUD判定不断裂。

#### a) dim_adapter v3.0→v3.1 共存策略

当前dim_adapter v3.0（line 454-462）从 `dim_results.get('signal')` 提取 `attribute.code` → `direction`。改造后dim1的signal结果格式变化，需按阶段兼容：

| 阶段 | dim1输出格式 | dim_adapter行为 | 兼容性 |
|------|------------|----------------|--------|
| **Phase 1（判定迁移）** | 旧格式不变（仍含judgment.attribute.code） | v3.0逻辑不变 | ✅ 无断裂 |
| **Phase 2（dim1重写）** | 新格式：`{status_description: 数据质量报告, judgment: 数据质量判定, data_context: ...}` | v3.1检测：若`_sig_judg.get('attribute')`存在→走v3.0路径；若不存在→走v3.1路径（从tags预计算字段fallback） | ✅ 向后兼容 |
| **Phase 3（dim8/JUD全面改造，后续方案）** | 最终格式（含数据质量+data_context） | v3.1完整路径 | ✅ 最终态 |

**关键：Phase 1必须在Phase 2之前完成**，确保dim_adapter v3.1已就绪后再改dim1输出格式。

#### b) `dims['signal_confirm']` 处理

dim_adapter line 845 从 `tags.right_side_confirm` 推导 `dims['signal_confirm']`。这与dim1的7类属性分类**语义重叠但来源不同**：

| 来源 | 分类体系 | 触发时机 |
|------|---------|---------|
| tags.right_side_confirm | 3值（confirmed/emerging/none） | RAW-2预计算 |
| dim1.classify_attribute | 7类（right_confirmed/right_emerging/.../neutral） | SIG运行时 |

**合并策略**：
- Phase 1-2期间：两套逻辑并行，`dims['signal_confirm']` 保留（来自tags），dim1的7类分类通过dim_adapter v3.1独立接入JUD
- 后续dim8/JUD全面改造时：统一为单一分类体系，消除重复

#### c) reliability_assessor 接口兼容

当前 `reliability_assessor.py` 从tags直接读取。改造后改为从dim1结果读取。

**兼容方案**：新函数 `assess_signal_reliability(dim1_result)` 为**新增入口**，不修改现有 `assess()` 函数签名。调用方（JUD-3聚合层）在dim1结果可用时调用新函数，不可用时回退到现有 `assess()`。

### 5.5 输出语义变更对dim8/OUT的影响

dim1改造后，`status_description` 内容从**信号判定**变为**数据质量报告**。影响链：

| 影响方 | 当前消费内容 | 改造后变化 | 适配方案 |
|--------|------------|-----------|---------|
| dim8 `_build_signal_text` | dim1.status_description.attribute/strength/maintenance | status_description不再包含信号判定字段 | Phase 1期间dim1保持旧输出格式；后续dim8/JUD全面改造时统一适配（见399号方案） |
| dim8 `_extract_key_metrics` | dim1.status_description.lifecycle_days/lifecycle_stage | 同上 | 同上 |
| dim8 `_build_plain` 降级兜底 | dim1.status_description.plain | 数据质量报告的plain替代信号plain | 改造为数据质量plain（如"数据完整，已通过门禁校验"） |
| treemap_snapshot signal_confirm | dim_adapter.signal_confirm.state | 不受dim1改造影响（来源为tags预计算） | 无需改动 |
| status_snapshot signal_confirm | dim_adapter.signal_confirm.state | 同上 | 无需改动 |

**注意**：399号方案已完成dim2-dim7的输出消费梳理。后续将对dim8及JUD进行全面的再次沟通改造，届时统一处理dim1输出格式变化的适配。本方案Phase 1-2期间dim1保持旧输出格式，确保dim8/OUT不受影响。

### 5.6 端到端降级策略

dim1数据门禁失败时，需确保端到端链路有明确的降级路径：

```
dim1校验失败 → 3轮STG补算仍未通过
  │
  ├── dim1返回：data_context=None + status_description标注"数据未经门禁校验"
  │
  ├── dim2-dim7：回退到独立SQLite查询
  │     └── 读到的数据可能不完整/过期，但分析管道不中断
  │
  ├── dim_adapter：signal因子使用默认值
  │     ├── direction=0（中性）
  │     ├── strength=0.5（默认）
  │     └── reliability=0.5（中等）
  │
  ├── dim8：signal_confirm降级到tags.right_side_confirm（RAW预计算标签）
  │     └── 不依赖dim1的signal判定结果
  │
  └── 最终输出（status_snapshot/treemap_snapshot）：
        └── 标注"data_quality":"degraded"
            └── 前端可据此展示"数据质量待确认"提示
```

**降级原则**：
1. **不中断**：任何降级都不阻塞分析管道，确保用户始终能看到结果
2. **可追踪**：降级事件写入日志+标注到输出，运维可定位
3. **可恢复**：下次daemon运行时重新触发dim1门禁，数据恢复后自动升级
