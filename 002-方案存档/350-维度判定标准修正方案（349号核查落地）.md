# 350 — 维度判定标准修正方案

## 一、背景

349 号《维度判定标准核查报告》对照 LLM Wiki 知识库逐维度核查，发现 3 项需修正（8 项已一致无需改动）：

| # | 维度 | 问题 | 优先级 |
|---|---|---|---|
| 1 | 估值 | 二值化（低估/合理/高估）缺极度低估/极度高估分档 | P1 |
| 2 | 位置 | 价格高于中枢上沿仍判"中位"，知识库应判"站上防守位" | P1 |
| 3 | 量价 | 三态标签（healthy/diverging/neutral）缺量化评分 | P2 |

## 二、修正方案

### 2.1 估值分档细化（P1）

**现状**（status_engine.py:180-183）：
```python
put('valuation', {'extreme_low': '低估', 'low': '低估', 'fair': '合理',
                  'high': '高估', 'extreme_high': '高估'}.get(vl, '合理'), ...)
```
问题：extreme_low 与 low 合并为"低估"，extreme_high 与 high 合并为"高估"——丢失极度低估/极度高估的区分度。

**知识库依据**：《多锚点估值框架》PB百分位五级分档——<5%极度低估(+2)、5-20%低估(+1)、20-80%合理(0)、80-95%高估(-1)、>95%极度高估(-2)。

**修正方案**：

**a) _DIM_DIRECTION 映射表扩展**（status_engine.py:27）：
```python
# 现状
'valuation': {'低估': 1, '合理': 0, '高估': -1},
# 修正为
'valuation': {'极度低估': 2, '低估': 1, '合理': 0, '高估': -1, '极度高估': -2},
```
注意：共识计票仍用 +1/0/-1（`v > 0 → bull += 1`），极度低估(+2)仍算 1 票看多。区分度体现在状态描述而非票数。

**b) 维度状态推导扩展**（status_engine.py:180-183）：
```python
# 现状
put('valuation', {'extreme_low': '低估', 'low': '低估', 'fair': '合理',
                  'high': '高估', 'extreme_high': '高估'}.get(vl, '合理'), ...)
# 修正为
put('valuation', {'extreme_low': '极度低估', 'low': '低估', 'fair': '合理',
                  'high': '高估', 'extreme_high': '极度高估'}.get(vl, '合理'), ...)
```

**c) _DIM_LIGHT 映射自动适配**（status_engine.py:39-42）：
现有逻辑 `v > 0 → green, v == 0 → yellow, v < 0 → red` 自动适配（极度低估 +2 → green，极度高估 -2 → red），无需额外修改。

**d) 前端适配**：
前端灯色渲染基于 `d.light`（green/yellow/red），不依赖具体状态文字——无需修改。文案展示（如"估值：低估"→"估值：极度低估"）会自动更新。

**影响评估**：
- 共识计票不变（极度低估仍算 1 票看多）
- 状态描述更精确（"极度低估"比"低估"信息量更大）
- L0 分级不受影响（`valuation_level in ('high', 'extreme_high')` 仍触发 deep_valuation）
- 需重算 S1 快照（status_snapshot 估值状态文字更新）

### 2.2 位置阈值复核（P1）

**现状**（phase_detector.py:393-414）：
```python
# 120日价格分位
pos_ratio = (current - recent_low) / (recent_high - recent_low)
if pos_ratio < 0.3: price_pos = "low_zone"
elif pos_ratio > 0.7: price_pos = "high_zone"
else: price_pos = "mid_zone"
```
status_engine.py:209-211 消费标签：`{'low_zone': '站上防守位', 'high_zone': '跌破'}.get(pp, '中位')`

问题：price_position 用120日价格分位（0.3/0.7 阈值），与知识库"站上防守位"（缠论概念：价格高于中枢上沿+回踩未破）定义不同。九典制药 pos_ratio=0.467（mid_zone），但价格已高于中枢上沿 11.30（+11.7%）。

**知识库依据**：《面向普通用户的量化系统》——"价格站上防守位"=价格高于中枢上沿+回踩未破。

**修正方案**（两步，标签层+判定层）：

**a) 标签层：price_position 增加"突破"语义**（phase_detector.py:393-414）：
在现有120日分位基础上，增加缠论中枢位置判定——如果价格高于最近中枢上沿，覆盖为"站上防守位"：
```python
# 现有逻辑保留（120日分位基础）
if pos_ratio < 0.3: price_pos = "low_zone"
elif pos_ratio > 0.7: price_pos = "high_zone"
else: price_pos = "mid_zone"

# 新增：缠论中枢位置覆盖
# 从 strategy_signal_detail 提取最近中枢上沿（如有）
# 如果价格高于中枢上沿且非 high_zone，覆盖为"站上防守位"
```
注意：这需要读取缠论中枢数据（从 P2 策略信号中提取），增加标签层复杂度。**替代方案**：在 status_engine 判定层覆盖（见下）。

**b) 判定层：status_engine position 维增加中枢上沿判定**（status_engine.py:209-211）：
```python
# 现状
put('position', {'low_zone': '站上防守位', 'high_zone': '跌破'}.get(pp, '中位'), ...)

# 修正为：检查缠论中枢位置（从 strategy_signal_detail 提取最近中枢上沿）
# 如果价格高于中枢上沿且 pp != 'high_zone'，覆盖为'站上防守位'
```
优点：不改标签层，只在判定层增加覆盖逻辑。缺点：需要读取 strategy_signal_detail（增加 status_engine 的数据依赖）。

**推荐方案**：方案 b（判定层覆盖）——最小侵入，不改标签层定义。

**影响评估**：
- 价格高于中枢上沿的股票从"中位"→"站上防守位"（看多信号）
- 共识计票：站上防守位 +1（看多），中位 0（中性）——可能增加看多票数
- 需重算 S1 快照

### 2.3 量价评分细化（P2）

**现状**：volume_price_fit 三态标签（healthy/diverging/neutral），status_engine 直接映射为三态（健康/背离/中性）。

**知识库依据**：《量价形态打分系统》——量化评分 0-100，形态评分系统。

**修正方案**：

**a) 标签层：volume_price_fit 扩展为五态**（signal_computation_service.py）：
```python
# 现状
volume_price_fit: healthy / diverging / neutral
# 修正为
volume_price_fit: strong_healthy / healthy / neutral / diverging / severe_diverging
```
判定标准：
- strong_healthy：量价配合极佳（突破日放量≥2倍+缩量回踩未破位）
- healthy：量价配合良好（放量≥1.5倍+回踩未破位）
- neutral：量价无明确信号
- diverging：量价轻度背离（价格新高但量能未新高）
- severe_diverging：量价严重背离（价格新高但量能持续萎缩）

**b) _DIM_DIRECTION 映射扩展**（status_engine.py:29）：
```python
# 现状
'vp': {'健康': 1, '中性': 0, '背离': -1},
# 修正为
'vp': {'强健康': 2, '健康': 1, '中性': 0, '背离': -1, '严重背离': -2},
```

**c) _derive_vp_state 扩展**（status_engine.py:151-156）：
```python
# 现状
return ({'healthy': '健康', 'diverging': '背离'}.get(vpf, '中性'), ...)
# 修正为
return ({'strong_healthy': '强健康', 'healthy': '健康', 'diverging': '背离',
         'severe_diverging': '严重背离'}.get(vpf, '中性'), ...)
```

**影响评估**：
- 量价维度区分度提升（五态 vs 三态）
- 共识计票：强健康/健康仍算 1 票看多，背离/严重背离仍算 1 票看空
- 需重算 P4 标签 + S1 快照
- 依赖 P2 量价引擎输出扩展（signal_computation_service.py）

## 三、实施顺序

| 步骤 | 内容 | 改动范围 | 依赖 |
|---|---|---|---|
| 1 | 估值分档细化 | status_engine.py（2处） | 无 |
| 2 | 位置阈值复核 | status_engine.py（1处）+ 可能 phase_detector.py | 缠论中枢数据读取 |
| 3 | 量价评分细化 | status_engine.py（3处）+ signal_computation_service.py | P2 量价引擎输出扩展 |
| 4 | 重算 S1 快照 | kill daemon → 重置 S1 → 重启 | 步骤 1-3 完成 |

## 四、验收标准

1. 九典制药（300705.SZ）估值状态从"低估"→"极度低估"（PE分位9.9% <20%）
2. 价格高于中枢上沿的股票位置状态从"中位"→"站上防守位"
3. 量价维度五态分布合理（strong_healthy + healthy 占比 >50%，severe_diverging <5%）
4. 共识计票不变（极度低估/强健康仍算 1 票看多）
5. 现有测试全通过（无回归）

## 五、风险提示

1. **估值分档细化**风险低：仅改状态描述文字，不改计票逻辑，不影响共识率
2. **位置阈值复核**风险中：可能增加看多票数（价格高于中枢上沿的股票从"中位"→"站上防守位"+1），需验证共识分布变化
3. **量价评分细化**风险中：依赖 P2 量价引擎输出扩展，需同步修改 signal_computation_service.py
4. **重算耗时**：S1 重建 ~47s，P4 标签重算 ~857s——需在非交易时段执行
