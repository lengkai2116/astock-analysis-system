# 自选监控列字段开发任务计划

## 背景

自选监控页（watchlist.html）列配置中，存在多类未实现字段。经审计分类后，制定本开发任务计划。

## 字段分类

| 类别 | 字段数 | 说明 |
|------|--------|------|
| **A — 可立即实现** | 5 | 数据已就绪，仅需少量编码 |
| **B — 依赖盘中数据** | 3 | 需对接 mootdx InMemoryStateStore |
| **C — 需外部数据源** | 2 | 需接入新 API 或数据提供商 |
| **D — 需开发新功能** | 4 | 需设计实现新算法/模块 |
| **E — 需 QMT/L2** | 3 | 仅 Level-2 行情可解 |

---

## A 类：数据已就绪，可立即实现（~1 天）

### A1. `shareholder_n` 股东总数

| 项 | 说明 |
|----|------|
| **现状** | 后端通道已打通（`dm.cache.get_cached_stk_holder()` 返回数据），Tushare 实际返回的 `holder_number` 全为 None |
| **替代方案** | ① **AKShare** `stk_holdernumber` API 补充（2000 积分级别）② **EFinance** 股东人数接口（免费，无需积分） |
| **建议** | 优先级 P3，数据覆盖不可控，前端已标准化显示 `—`，不影响使用 |
| **工时** | 0.5 天（新增 Provider 方法 + 写入 stk_holder_cache） |

### A2. `peg` 历史 PEG 值

| 项 | 说明 |
|----|------|
| **现状** | `pe_ttm` 和 `np_growth`（净利润增长率）均已就绪 |
| **实现** | `PEG = PE_TTM / (np_growth * 100)`，数据均为 `fina_indicator_cache` / `daily_basic_cache` 已有字段 |
| **工时** | 0.25 天 |
| **文件** | `watchlist.py` `_fetch_stock_quotes()` |

### A3. `main_force_pwd` 主力密码

| 项 | 说明 |
|----|------|
| **现状** | `MainForceScorer`（`chip_strategy.py:379`）已实现完整评分逻辑，含主力成本、资金集中度等 |
| **实现** | 从 `MainForceScorer` 提取主力成本价/集中度/控盘度 → 简化为文本描述（如"高度控盘/中度控盘/分散"） |
| **工时** | 0.5 天 |
| **文件** | `chip_strategy.py`（新增提取方法）+ `watchlist.py` |

### A4. `main_force_intent` 主力意图

| 项 | 说明 |
|----|------|
| **现状** | `MainForceScorer.identify_phase()`（`chip_strategy.py:659`）已实现建仓/洗盘/拉升/出货四阶段识别 |
| **实现** | 直接调用 `identify_phase()` 返回阶段文本；
也可根据资金流向趋势进一步细化为"吸筹/派发/观望/试盘"等 |
| **工时** | 0.25 天 |
| **文件** | `watchlist.py`（调用 `identify_phase`） |

### A5. `ai_strategy` AI 炒股攻略

| 项 | 说明 |
|----|------|
| **现状** | DeepSeek V4 API 已接入（`deepseek_analysis_service.py`），`StatusOutputService.aggregate()` 已实现 |
| **实现** | 调用 `interpret_status()` 对单只股票生成自然语言策略建议；
结果转为简短标签文本（不超过 20 字） |
| **工时** | 0.5 天 |
| **注意** | 每次刷新调用 LLM 有 token 成本，建议加 TTLCache 缓存（3600s） |

## B 类：依赖盘中实时数据（~1.5 天）

### B1. `buy1` / `sell1` 买一/卖一

| 项 | 说明 |
|----|------|
| **现状** | mootdx 5s 快照采集了 bid1~5/ask1~5，写入 InMemoryStateStore |
| **实现** | `watchlist.py` `_fetch_stock_quotes()` 增加盘中实时数据补充段：
从 `InMemoryStateStore` 读取 bid1/ask1（通过 `store.get_by_code()`），盘后返回 `None` |
| **工时** | 0.5 天 |

### B2. `commission` 委比%

| 项 | 说明 |
|----|------|
| **现状** | 依赖 B1 的 bid1~5/ask1~5 |
| **实现** | `(buy_vol - sell_vol) / (buy_vol + sell_vol) * 100`，其中 buy_vol =
 sum(bid1_vol...bid5_vol)，sell_vol = sum(ask1_vol...ask5_vol) |
| **工时** | 0.5 天（含 B1 共用工时） |

### B3. 前段数据降级标注优化

| 项 | 说明 |
|----|------|
| **现状** | 已标记 `source: 'qmt'`，显示"⏳ 需QMT" |
| **优化** | 盘中可用时改为 `source: 'avail'` + 新增 `data_available: 'intraday'` 标注 |
| **工时** | 0.5 天 |

## D 类：需开发新功能（~3 天）

### D1. `chg_speed` 涨速%（隔日计算）

| 项 | 说明 |
|----|------|
| **替代实现** | 盘中涨速需 L2 tick 级数据，不可行。但可用盘后等效指标"隔日涨速"替代：`(close[t] - close[t-1]) / close[t-1] / 1 * 100`（就是涨跌幅本身） |
| **建议** | 取消该列或标记 `source: 'qmt'`，涨跌幅已覆盖核心需求 |
| **工时** | — |

### D2. `vol_ratio` 量比（盘中替代计算）

| 项 | 说明 |
|----|------|
| **现状** | 标准量比 = 当前成交量 / 过去5日同时段均值，需要盘中分钟级数据 |
| **替代实现** | 盘后量比 = 今日成交量 / 过去5日平均成交量，可从 daily_cache 取数 |
| **工时** | 0.5 天 |

### D3. `cur_vol` / `in_disk` / `out_disk` 现量/内盘/外盘

| 项 | 说明 |
|----|------|
| **依赖** | L2 逐笔成交数据，mootdx TCP 无此接口 |
| **替代方案** | 无可行替代，保持 `source: 'qmt'` |
| **建议** | 列为 QMT 开通后的验收项 |

### D4. `avg_price` 均价

| 项 | 说明 |
|----|------|
| **替代实现** | 盘后均价 = `amount / vol`（从 daily_cache 的成交额/成交量计算） |
| **工时** | 0.25 天 |

---

## E 类：需 QMT Level-2 行情（~5 天）

> 以下字段需要 QMT 开通后才能真正实现。列在此用于规划。

| 字段 | 说明 | 数据量级 |
|------|------|---------|
| `chg_speed` | 涨速（逐笔价格变化率） | L2 逐笔 |
| `cur_vol` | 现量（最新一笔成交量） | L2 逐笔 |
| `in_disk` / `out_disk` | 内盘/外盘 | L2 逐笔聚合 |
| `vol_ratio` | 量比（实时 5 日均值比较） | L2 分钟级 |
