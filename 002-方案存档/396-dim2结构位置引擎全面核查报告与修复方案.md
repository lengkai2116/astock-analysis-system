## 三、发现详情

### 3.1 错误（1项）

#### F-01：`bsp_detector.detect()` 方法不存在 — 买卖点检测静默失败

**严重级别**：HIGH（功能缺陷）

**位置**：行3943-3946

```python
# dim2_structure_engine.py L3943-3946
bsp_detector = BuySellPointDetector()
bsp_result = bsp_detector.detect(chanlun_result)  # ← BuySellPointDetector 没有 detect 方法
if isinstance(bsp_result, dict):
    buy_sell_points = bsp_result.get('buy_points', []) + bsp_result.get('sell_points', [])
```

**问题**：`BuySellPointDetector` 只有 `find()` 方法（行2205），签名是 `find(strokes, zhongshu_list, divergence, only_last)`，没有 `detect()` 方法。调用 `detect()` 会抛 `AttributeError`，被外层 try/except 静默吞掉。

**影响**：dim2 的 `buy_sell_points` 输出**始终为空列表**，`buy_sell_points_detail` 也为空。dim2的5子维度中"买卖点信号"完全缺失。

**根因**：381号方案P1整合时，`BuySellPointDetector` 的接口从 `detect(result_dict)` 改为 `find(strokes, zhongshu_list, divergence, only_last)`（更细粒度），但调用方 `Dim2StructureEngine.evaluate()` 未同步更新。

### 3.2 HIGH级发现（2项）

#### F-02：`_check_fractal_pair` 末尾不可达代码

**位置**：行1099

```python
def _check_fractal_pair(self, f1, f2, direction):
    if direction == 'up':
        if f2.price <= f1.price: return False
        return True
    else:
        if f1.price <= f2.price: return False
        return True
    return False  # ← 不可达
```

**影响**：无功能影响，但说明原始逻辑被简化后遗留了死代码。

---

#### F-03：`strokes.index()` 在循环中导致 O(n²)

**位置**：行1884、行1941

```python
_prev_down_before_up = next((s for s in reversed(strokes[:strokes.index(last_up)])
                             if s.direction == 'down'), None)
```

**影响**：`list.index()` 是O(n)，在趋势背驰检测中对每对笔调用一次。对120根K线（~60笔）影响约3600次操作，量级可接受，但在高频/大数据场景下会成为瓶颈。

### 3.3 MEDIUM级发现（6项）

#### F-04：`DivergenceDetector` 内部状态泄露

**位置**：行1726-1727、1798、1809等

`self._closes` 和 `self._volumes` 在 `detect()` 中赋值，后续多个 `_calc_stroke_*` 方法依赖这些实例变量。如果调用顺序不正确，`self._closes` 可能为 `None`。当前调用链保证了顺序，但设计上较脆弱。

---

#### F-05：`BiZhongshuFinder.find()` 笔中枢无扩张机制

**位置**：行1679-1693

笔中枢延伸只更新 `end_idx/end_date`，后续笔完全离开区间时直接闭合，不检测扩张。这是设计决策（czsc风格），非bug，但需确认是否符合需求。

---

#### F-06：`_resample_to_weekly/monthly` 假设数据含 `amount` 列

**位置**：行221-224、行238-244

```python
weekly = df.resample('W').agg({
    'open': 'first', 'high': 'max', 'low': 'min', 'close': 'last',
    'vol': 'sum', 'amount': 'sum',  # ← amount 列可能不存在
})
```

**影响**：如果DataFrame不含 `amount` 列，抛 `KeyError`，被 try/except 静默吞掉。多级别联立（日/周/月）在缺列时会静默失败。

---

#### F-07：`_determine_trend` 在笔中枢模式下过度简化

**位置**：行2837-2841

```python
if self.bi_zs_mode:
    if self.strokes:
        return self.strokes[-1].direction  # 最后一笔方向 ≠ 趋势
    return 'unknown'
```

上升趋势中可以有一笔向下的回调，最后一笔方向不能准确代表当前趋势。

#### F-08：买卖点提取使用字符串匹配

**位置**：行3956-3961

```python
bp_str = str(bp)
if '买' in bp_str:
    bp_info['type'] = 'buy'
elif '卖' in bp_str:
```

依赖 `BuySellPoint.__repr__` 输出格式。如果 `__repr__` 格式变化会静默出错。更稳健的方式是直接读取 `bp.type` 属性。

`close = ma_data.get('close', 0)` 在 `if close > 0` 块中使用，但如果 `ma_data` 无 `close` 键，`close=0`，乖离率不会被计算——行为正确但证据可能缺失。

### 3.5 设计决策确认→升级为修复项（2项）

以下两项原被列为"设计决策确认"，经核查历史方案记录和系统架构要求后，均需修正。

#### F-15（原D-01）：分型确认阈值应恢复为0.5%

**严重级别**：MEDIUM

**位置**：行2649

```python
'fractal_threshold_pct': 0,  # 分形确认阈值，0=关闭（对齐 czsc 标准）
```

**历史链条**：

| 方案 | 结论 |
|------|------|
| 285号 P1.1 | 知识库推荐 `threshold_pct=0.5%` 过滤弱势分形 |
| 285号 P0 | 记录默认值从0.5改为0 |
| 362号核查报告 | 明确指出 `fractal_threshold_pct=0` 导致**"噪声分型多"**，建议改回0.5 |
| 当前代码 | 注释写"对齐czsc标准"，但czsc本身有分型过滤，设为0是误解 |

**影响**：设为0等于完全关闭弱势分型过滤→大量噪声分型→笔数量膨胀→中枢位置偏移→缠论分析质量下降。

**修正**：`'fractal_threshold_pct': 0` → `'fractal_threshold_pct': 0.5`

---

#### F-16（原D-02）：`only_last` 快速模式为死代码，应清理

**严重级别**：LOW

**位置**：行2225-2247（`BuySellPointDetector.find` 的 `only_last` 分支）、行2570/2575（`only_judge_last` 属性）、行2712（传参）

**问题**：`only_last=True` 快速模式的设计意图是"大批量场景下只算最后K线的买卖点以节省计算"。但根据系统架构：

- SIG预计算在**日终后到次日开市前**的空闲时间执行
- 全市场股票**逐只全量计算**，不存在"简化预计算"的概念
- `Dim2StructureEngine.evaluate()` 未传入 `only_judge_last` 参数，始终走默认 `False`（全量计算）

因此 `only_last=True` 分支在生产中**永远不会被执行**，是无效代码。

**影响**：无功能影响，但增加代码复杂度和维护成本。

**修正**：删除 `only_last` 参数及相关分支代码（约30行），`BuySellPointDetector.find()` 简化为始终全量计算。

---

### 3.6 遗漏发现（1项）

#### F-14：`TrendStructureDetector.detect()` 缺少 `assumption1/2/3` 字段

**严重级别**：MEDIUM

**位置**：行442（detect返回值） vs 行4144-4146（evaluate读取）

`detect()` 返回 `{signal, strength, detail}`，但 `Dim2StructureEngine.evaluate()` 在行4144-4146读取了不存在的字段：

```python
# 行4144-4146 — 读取的字段在 detect() 返回值中不存在
a1 = trend_structure.get('assumption1', False)
a2 = trend_structure.get('assumption2', False)
a3 = trend_structure.get('assumption3', False)
```

`get()` 默认值为 `False`，所以 evidence 中 `假设1=False，假设2=False，假设3=False` 始终输出，与实际不一致。

**根因**：detect() 内部用局部变量 `trend_break`/`higher_low`/`breakout_high` 表示三个假设，但未写入返回字典。

### 4.5 P2 — 改进 `_determine_trend` 趋势判定（F-07）

**修改**：笔中枢模式下不只看最后一笔方向，综合中枢位置+多笔方向。

```python
if self.bi_zs_mode:
    if self.zhongshu_list and self.strokes:
        zs = self.zhongshu_list[-1]
        last_close = self.klines[-1].close if self.klines else 0
        if last_close > zs.high:
            return 'up'  # 价格在最新中枢上方
        elif last_close < zs.low:
            return 'down'
        # 在中枢内部时看最后3笔方向
        if len(self.strokes) >= 3:
            ups = sum(1 for s in self.strokes[-3:] if s.direction == 'up')
            return 'up' if ups >= 2 else 'down'
    return 'unknown'
```
