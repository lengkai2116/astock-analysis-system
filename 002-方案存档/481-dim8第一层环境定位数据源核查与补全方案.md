## 二、各子项实施明细

### B1｜板块热度读取 bug 根治（先决，1 行 SQL）
**文件**：`app/data/enhanced_cache_manager.py` `get_cached_sector_heat` (:1499-1519)
**改动**：
```python
# 原：SELECT * FROM sector_heat_cache ORDER BY stat_date DESC LIMIT 1
row = self._query_shard('sector_heat_cache',
    "SELECT * FROM sector_heat_cache "
    "WHERE stat_date = (SELECT MAX(stat_date) FROM sector_heat_cache)", [])
```
**影响**：dim1 装配 `data_context['sector_heat']` 恢复 109 行业 → `_sector_position_sentence`（dim8:1109）出「板块定位」句；dim5 情绪段板块热度档位同步恢复。
**验证**：单测——多行业表下 `get_cached_sector_heat()` 返回全部行业且含目标行业；600519 白酒定位句复现。

### B2｜市场状态句数据装配根治（daemon 停态也稳）
**根因**：dim1 `data_context['market_stats']` 读 `pre_feat_cache` 快照，而快照由 daemon 全局 `_market_stats_cache` 写入；daemon 停/重启过即空。
**改动**：`dim1_signal_engine.py` category3 的 market_stats 组读取后，增加**表兜底**——若 `loaded_data['market_stats']` 为空 dict，改为 `dm.cache.get_cached_market_stats()` 直读 `market_stats_cache` 表（该表 daemon 已持久化，实测有 09-21 及历史多行）。
**影响**：`_market_state_sentence`（dim8:1076）恢复「全市场MA20占比/涨停/封板率」广度句；dim5 四象限的 breadth 也受益。
**验证**：单测——daemon 停态下装配 market_stats 非空、广度句复现。

### ① 大盘指数趋势句（接线，`_index_trend_sentence`）
**数据**：`BenchmarkService.get_index_daily(000300.SH/000001.SH)`，取近 1/5/20/60 日，拼一句：
> `大盘：沪深300 4517(当日-0.6%)，近20日-0.8%/近60日-9.3%，60日线下方(偏弱)`

- 判趋势：近60日>0 且站上60日线→偏强；近60日<-5%→偏弱；其间→中性。
- 缺数据降级空串。
**接入**：并入 dim8 summary 前置环境段（`_market_state_sentence` 旁新增，`build_seven_dim_report` 装配）。

### ② 行业完整情况句（接线，`_sector_full_sentence`）
**数据**：`SectorAnalysisService.get_sector_context(ts_code)` 现成（sector_1/5/20d_return、rank、rotation_state、moneyflow）。拼：
> `白酒：近20日-2.2%，行业中游(排名第N)，轮动NEUTRAL，资金净流出`

- rotation_state 中文化：LEADING→领涨/LAGGING→落后/STRENGTHENING→增强/WEAKENING→转弱/NEUTRAL→中性。
- 取代/补充现有 `_sector_position_sentence`（保留前者 heat_level 档位信息，叠加收益/轮动）。
**验证**：600519 白酒收益/轮动/资金句复现。

### ③ 个股行业位置百分位（能力缺口，独立扩产）
**数据**：行业成分股集合（`Stock` 表 `WHERE industry=?`）+ 各成分股 `daily_cache` 近 20 日收益。
**产出**：新增字段（daemon 预计算，独立管道步骤 RAW-2C 写 `industry_position_cache`）：
> `rank_in_industry`：目标股近20日收益在行业全部有效成分股中的名次
> `total_in_industry`：行业有效成分股总数
> `percentile`：`(rank-1)/total`（越小越强）
> `position`：top25%/中上/中下/bottom25% 四档（涨幅前1%→top25%）

**接入**：dim8 环境定位段一句 `白酒板块内近20日涨幅第13/19（前63%），位置中下`。
**实施（已落地，v3.0）**：
- daemon `_precompute_industry_position`（raw-2C 步骤）：app_context 内 DM.get_stock_industry_batch 取行业 → `_ecm.get_cached_daily_batch` 批量取日线 → `_rank_industry_position` 纯计算分组排名（跨行业独立排名）→ `_ecm.cache_industry_position` 独立短连接写盘（DELETE+executemany+commit）。
- ECM `get_industry_position(ts_code)` 按 ts_code 取最新 asof 行 → dim8 `_industry_position_sentence`（挂 summary 前置，紧跟行业完整句后）。
- 单成分行业/缺收益基准 → percentile=None、句降级空串。
**运行态**：缺数据降级空串，不阻塞；计算放 daemon 侧（避免实时逐票查）。daemon 停态探针读表稳定输出。

## 三、平稳运行的工程保障（贯穿全子项）

1. **与 daemon 解耦**：B2 走表兜底、① 走 BenchmarkService 独立查询、② 走 SectorAnalysisService 独立服务、③ 走 industry_position_cache 表——均不依赖 daemon 内存缓存，daemon 停态探针/测试稳定输出。
2. **437「缺则降级」**：每个新句独立 try/空值判断，任一源缺失仅空串，不拖垮整个 summary。
3. **分库路由一致**：B1/B2 已走 `_query_shard` 分库路由（compute_cache.db）；③ `industry_position_cache` 同登 compute_cache.db 路由（426 号 P1-2 三表先例），读写一致分库，避免"总库空壳表"历史陷阱。
4. **幂等**：B1 改读不改写；② 只读服务不改状态；③ 写路径沿用按日替换（DELETE+executemany+commit 一次提交）。
5. **加字段=加行**：① ②③ 作为独立函数挂 summary 前置，不动引擎契约键（前端无破坏）。
