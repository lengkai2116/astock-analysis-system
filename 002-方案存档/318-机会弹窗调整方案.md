# 机会弹窗调整方案（5 项问题核查结论 + 修订计划）

> **背景**：2026-08-07 对机会图谱点击个股后的机会弹窗（`_ui-prototype/opportunity-treemap.html` 的 showDetail / detail-panel）进行了 5 项核查（详见 `001-沟通记录/26-08-07沟通纪要.md` 004）。用户确认核查结果，要求更新方案存档，详细说明问题与解决方案，并制定详细修订计划。**本方案仅存档，不修改任何代码。**

---

## 一、核查结论摘要

机会弹窗（detail-panel，:481-524）当前结构：

```
┌─ detail-header ──────────────────────────────┐
│  d-code / d-name（代码+名称）                 │
│  d-price-row（价格 涨跌 信号强度 ●机会标签 徽标）│ ← 问题①②
│  d-tags（phase 行业 #机会类型）               │ ← 问题③
├─ ★ 交叉验证（d-verdict）─────────────────────┤
├─ 📊 标签摘要（d-tag-summary 四行单值）─────────┤ ← 问题④
├─ 💎 估值定位（d-val-detail：PE/PB/股息率裸数字）│ ← 问题⑤
├─ 🎯 操作建议（d-advice）─────────────────────┤
├─ ⚠️ 风险提示（d-risk）───────────────────────┤
└─ 底部操作栏 ─────────────────────────────────┘
```

弹窗数据来源：
- **初始数据**：`loadMarketData()` 请求 `/treemap?mode=market`（快照表 `treemap_snapshot` 日终数据 + market 模式实时 merge）
- **30s 轮询**（:1764-1787）：仅 `currentMode === 'market'` 时刷新 RAW_STOCKS 的 price/pctChange
- **异步诊断**：`showDetail` 打开后 fetch `/diagnose?ts_code=` 更新 verdict/advice/risk

## 二、问题清单与解决方案

### 问题 ①：价格涨跌数据时效（盘中 vs 日终）

**核查发现**：
1. **盘中链路已通（market 模式）**：后端 `_merge_snapshot_with_realtime`（opportunity_atlas.py:50-63）用 `as_market_snapshot`（daemon 5s 采集实时表）覆盖 price/pct_change，实证当前盘中（10:19）600519 返回 1303.98(-0.35%)、snapshot=True；
2. **缺口**：前端 30s 轮询仅在 market 模式刷新；切到机会/价值地图后弹窗停留在切换前数据，盘中不持续更新；
3. **非交易日/未开盘**：实时表无新数据（cached_at 停更）→ merge 不覆盖 → 自然回落日终快照价，**已符合要求**；
4. **标注缺失**：弹窗未显示数据时效标签（用户无法区分盘中/日终）。

**解决方案**（S1）：
- 将 30s 轮询从 `if (currentMode === 'market')` 改为**始终执行**（三模式共用 RAW_STOCKS 内存数据），弹窗在任何模式下都能跟随盘中刷新；
- 弹窗价格行增加**时效角标**：`data.snapshot === true` 显示 `🕐 盘中`，否则显示 `📅 日终 {snapshot_date}`；
- 后端不变（实时覆盖逻辑已存在）。

**验收**：盘中切到机会/价值地图打开弹窗，30s 内价格自动刷新；非交易时段显示"📅 日终"角标。

### 问题 ②：信号强度右侧颜色标记与内容（不符合最新体系）

**核查发现**：
1. **内容来源**：`● {opportunity_label}`（机会类型中文，如"高股息收益/优质不明"）+ 颜色 `HOLD_COLORS[opportunity_type]`（:532-545，**307 号旧"机会健康度"色板**：绿=关注/黄=观察/橙=高风险/红=回避/灰=信息不足）；右侧徽标 `CONFIRM_BADGE[right_side_confirm]`（:585-590，🔴⏳🟡🟢）；
2. **不符合最新体系（313 号）**：313 号 §五 定版颜色 = **时机信号**（闸门2 右侧确认四档 × 闸门3 L4 共识率细分），色板为 **蓝/黄/灰/棕**（TIMING_COLORS，:549-554，避开 A 股红涨绿跌）；313 号 §7 C6 明确"机会类型退居详情面板、颜色专司时机、分层展示"；
3. **不一致**：地图方块已用 TIMING_COLORS（蓝黄灰棕），弹窗却用 HOLD_COLORS（绿黄橙红）+ 红绿徽标——同页两套色系，违背 313 号设计；
4. **排版**：价格/信号强度/机会标签/徽标挤在同一行（d-price-row），信息过载。

**解决方案**（S2）：
- 弹窗颜色标记**改用 `timingColor(right_side_confirm, consensus_rate)`**（与地图方块同源，蓝/黄/灰/棕 + 共识≥70% 深蓝细分）；
- **另起一行**：价格行保留「价格 + 涨跌幅 + 信号强度」；新增独立行显示「⏱ 时机：●可入场/可轻仓/等待/回避」（用 TIMING_COLORS + 时机语义文案）；
- 机会类型（opportunity_label）保留但改为中性灰色文本、置于时机行之后（313 号 C6：类型=这是什么、时机=现在能不能动，分层展示）；
- 删除 CONFIRM_BADGE 红绿徽标（与 313 号冲突），或改造为 TIMING_COLORS 对应色（🔵可入场/🟡可轻仓/⬜等待/🟫回避）。

**验收**：弹窗时机标记颜色与地图方块一致（蓝黄灰棕），时机信息独立一行，机会类型降为辅助说明。

### 问题 ③：行业名称行（d-tags）英文表述

**核查发现**：
- d-tags 行（:1591-1595）显示三项：`phase`（= main_force_phase **英文原值** building/lifting/washing/distributing 直接透出）、`sector`（行业中文）、`# {opportunity_type}`（**英文枚举**如 quality_unknown/dividend_play）；
- phase 与四行标签"质量"维度重复（同源于 main_force_phase）。

**解决方案**（S3）：
- d-tags 行改为：`{行业中文} · {机会类型中文}`（用 `_tagCn(main_force_phase)` 中文化 + `OPPORTUNITY_PLAIN`/机会类型中文映射）；
- 删除英文 phase 透出（重复信息）与英文 opportunity_type 枚举；
- 建立 `OPPORTUNITY_TYPE_CN` 映射（dividend_play→高股息收益、quality_unknown→优质不明、build_high→建仓在高位…与 OPPORTUNITY_PLAIN 同源），后端已有 opportunity_label 中文可优先复用。

**验收**：弹窗无英文专业术语；行业行显示"食品饮料 · 优质不明"式中文组合。

### 问题 ④：标签摘要四维度信息量不足

**核查发现**：
- 现状：方向/位置/质量/环境四行，每行**仅 1 个单值**（`_tagCn` 单值映射，:1617-1625）；
- **后端已有组合维度未用**：diagnose 接口返回 `tags_summary`（cross_validate.py:721-787）实证组合值：direction="趋势震荡"、position="极度低估"、quality="主力出货, 财务健康"、environment="情绪高潮, 板块前20"——符合 295 号 §6.4「各维度展开 2-3 项」设计；
- 时间标注缺失（313 号 §7 要求"潜力基于快照日期、时机截至实时"）。

**解决方案**（S4）：
- 四行标签摘要改用 **diagnose.tags_summary 组合值**（异步诊断返回后替换），每维度最多展示 2-3 项，逗号分隔；
- 维度前加语义图标（↗方向 / 📍位置 / 🏗质量 / 🌤环境，已有）；
- 弹窗底部或标签区增加**时间标注**：`潜力基于 {snapshot_date} 快照 · 时机截至 {当前时间}`（313 号 C5 要求）；
- 兜底：diagnose 未返回时保留现有单值逻辑。

**验收**：标签摘要每维度 2-3 项组合描述；含时间标注。

### 问题 ⑤：估值定位 PE/PB/股息率展示不直白

**核查发现**：
- 现状：PE 19.9 / PB 6.0 / 股息率 4.03% 三行**裸数字**，无解释（:1628-1635）；
- 用户为非量化分析师（记忆 #522：PE=贵不贵，需直白化）；
- **可用举证字段（真实存在）**：
  - `valuation_level`：600519=extreme_low（极度低估），估值结论已定；
  - **`pe_percentile_5y`=6.8 / `pb_percentile_5y`=3.2**（标签表实证，近 5 年分位）；
  - `valuation_deviation`（+28.8）、`composite_rating`（估值引擎综合评分，600519=1.44）；
  - diagnose 的 `valuation_tracking`（current_level=extreme_low、composite_rating、days_in_position）。

**解决方案**（S5）：
- 估值行改为**结论优先 + 举证**格式：
  - 第一行：`💎 估值结论：极度低估（比近 5 年 93% 时间便宜）`——由 valuation_level + pe_percentile_5y 生成大白话；
  - 第二行举证：`PE 19.9（近5年 7% 分位） · PB 6.0（近5年 3% 分位） · 股息率 4.03%`；
  - 补充一句通俗解释：`PE=价格/年盈利（越低越便宜）`、`PB=价格/净资产（<1 破净=按净资产打折卖）`（记忆 #522 直白化约束）；
- 字段来源：前端 `_raw` 已含 pe/pb/dividend_yield；pe_percentile_5y/pb_percentile_5y 需后端快照 tags dict 补齐（同 317 号 S3 模式）或走 diagnose（valuation_tracking/pe 分位已可读）。

**验收**：估值定位首行给结论+大白话（便宜/贵），次行给 PE/PB/股息率+5年分位举证，附术语通俗解释。

## 四、风险与说明

1. **轮询改造影响**：30s 轮询改全模式刷新会增加非 market 模式的 API 请求频率，但均为内存数据更新、后端有缓存（305 号），性能影响可控；
2. **时机色一致性**：弹窗与地图方块同用 `timingColor()`，需确认 consensus_rate 在前端 stockItem 中完整透出（已透出，:677）；
3. **分位字段来源**：pe_percentile_5y/pb_percentile_5y 在 `opportunity_tags_cache`（5434/5537 只覆盖），若走前端需后端快照 tags dict 补齐（复用 317 号 `_get_latest_tags_for_codes` 模式）；若走 diagnose 则零后端改动但依赖异步返回；
4. **兜底策略**：任何诊断数据未就绪时保留现有展示（单值/裸数字），不阻塞弹窗打开。

## 五、结论

本方案基于 2026-08-07 核查实证（盘中实时链路已验证、313 号时机色体系、diagnose 组合标签、5 年分位数据均真实存在），对弹窗 5 项问题逐一给出解决方案与分阶段修订计划（S1-S6）。核心原则：**直白化（用户非量化分析师）+ 与最新体系对齐（313 号时机色/295 号组合标签）+ 真实数据举证（5年分位）**。**本方案仅为存档，未修改任何代码。**
