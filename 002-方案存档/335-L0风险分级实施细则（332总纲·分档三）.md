# 335 — L0 风险分级实施细则

> **分档定位**：332 号总纲（现状判定引擎统一方案 v3.0）的**分档三**，聚焦总纲 §5.0（L0 风险分级层）的落地细则。
>
> **讨论背景（08-15，沟通纪要 003）**：组1 讨论确认三条方向——①**不新建风险引擎**，L0 直接镶嵌现有 gate（`_evaluate_gate`）+ 仲裁（`arbiter` P0-P7）体系；②**整合现有风险核查能力**（含弃用的选股器链路中仍有价值的部分），清理停用部分；③**可逆风险不硬否决**（对齐知识库五层防护与同类软件）。
>
> **用户最终决策（08-15）**：①选股系统页面**确认弃用**，替换为机会图谱板块——清理选股器 API/集成链路；②**deep（深度高估）不再硬否决**——估值非绝对精准、部分股票存在较大价格突破可能性，实为"高风险机会"，需**高价格风险强提示**而非剔除。
>
> 本方案仅存档细则，不修改任何代码（实施随 332 号 P0/S1/S2）。

## 一、设计原则（用户确认）

1. **零新建**：L0 分级承载于现有 `gate`（cross_validate._evaluate_gate）+ `arbiter`（P0-P7 状态机），不新增风险引擎；
2. **整合优先**：先盘点现有风险能力（gate/仲裁/事件监测/选股器过滤器），能复用的迁移、重复的删除；
3. **可逆不否决**：仅不可逆风险（监管立案/退市/ST）硬否决，其余一律"提示/仓位约束/持有期限制"（知识库五层防护 L1/L2 + 同花顺/东财黄牌做法）；
4. **暂缓不阻塞**：数据缺口（质押率 pledge_stat、真造假识别）列为后续数据源升级项，不阻塞本方案落地。

## 二、L0 分级映射表（镶嵌现有环节）

| 332 L0 分级 | 镶嵌环节 | 现状 | 改动 |
|---|---|---|---|
| **L0a 硬否决**（不可逆，一票剔除） | `gate.hard_risks` + `arbiter` P1 | regulatory（catalyst_event=regulatory）→ event_negative → avoid ✅ 已有 | ①ST 名称检测迁移进 event_monitor（§四）②真造假识别：**暂缓**（fraud_sign 语义已定"经营恶化"归 L0b，非欺诈） |
| **L0b 软约束**（可逆，约束不剔除） | `gate.soft_risks` 系数 + 估值分级 | fina_weak×0.5 / fina_fail×0.5 / distributing×0.7 / low_liquidity×0.7 / valuation moderate×0.5·mild×0.8 ✅ 全部已有 | ①**deep 定位修正**（§三）：硬否决→强提示+仓位压缩 ②系数校准复用 334 号回算机制（§七，后续） |
| **L0c 持有期限制**（快变量） | `arbiter`/`advice_builder` 仓位逻辑（**新增接入点**） | 系统无"已延伸→只持有不开仓"机制 | 接入 334 号信号生命周期"已延伸"阶段（§五） |

**边界澄清（与 gate 关系）**：gate 本就是 L0 的承载——`hard_risks`=L0a、`soft_risks`+估值分级=L0b；无需"移除或降级"去重，直接沿用。剔除比例目标 3-8%（332 §5.0）待 L0a 补入 ST 检测后核查（§七）。

## 三、deep 定位修正（核心决策，用户 08-15 确认）

**决策**：深度高估（valuation=deep，PE 历史分位>90 或 偏离<-20）由"硬否决"改为"**高风险机会强提示**"——保留在图谱与个股页，标注高价格风险，仓位压缩。

**理由**（用户原话直白化）：估值本身非绝对精准，部分股票在深度高估下仍可能出现较大价格突破，实为"高风险机会"而非"否决对象"。

**现状与改动影响面**（代码级核查）：

| 位置 | 现状 | 改动 |
|---|---|---|
| `arbiter.py:209-212`（P2） | deep → `avoid`（max_ratio=0） | **删除 P2 硬否决分支**；deep 不参与状态机否决，正常走 P4-P7 时机判定，state_evidence 追加"深度高估：价格高位风险"提示 |
| `cross_validate.py:1063-1066` | deep → `not_recommended` + max_ratio=0 | 改为：label="深度高估：价格高风险，注意追涨风险" + max_ratio 压缩（如 ×0.3 或上限 0.2，与 L0b 同级） |
| `potential_engine.py:209`（dev>30 → ×0.3 潜力降级） | **保留** | 潜力侧"高风险机会"降级已存在，与强提示方向一致，不动 |
| `tests/test_319_valuation_consistency.py` | deep 断言为否决 | 更新断言：deep → 提示 + 仓位压缩，非否决 |

## 四、ST 检测迁移（选股器 → event_monitor）

**现状**：ST/*ST/退市名称检测在弃用选股器链路的 `chip_pre_filter.FinancialRiskFilter._check_st_status`（L644-658），机会图谱侧 `event_monitor` 已有 `st_warning`/`delist_risk` 事件归 regulatory 的映射，但**无 ST 名称兜底检测**（若事件监测漏检 ST 股，机会图谱不拦截）。

**改动**：将 ST 名称检测逻辑迁移进 `event_monitor`（检测 ST/*ST/含"退"名称 → 归 regulatory 事件），保证 L0a 在机会图谱链路完整生效。

## 五、L0c 持有期限制接入（新增，唯一实质新增）

**输入**：334 号信号注册表信号生命周期——`已延伸`（dist>+12% 或 days>10）。

**规则**（知识库《信号生命周期》"介入贵贱"）：
- 已延伸：**只可持有、不新开仓**——图谱/个股页标注"信号已延伸，追高风险大"；新开仓建议降为 wait/轻仓提示
- 主力出货（distributing）：维持现有 soft_risks ×0.7 + 短期回避提示

**接入点**：`arbiter` 状态机 P4-P7 判定前增加"已延伸"检查（或 advice_builder 仓位逻辑），与 L0b 同级处理。
