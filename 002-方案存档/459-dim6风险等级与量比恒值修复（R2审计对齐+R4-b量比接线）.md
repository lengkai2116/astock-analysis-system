## 二、根因（代码级）

### R2：dim6 两条分支对「事件风险严重度」分级不同步（444-C1 残余）

- **升格分支**（`evaluate`，dim6_risk_engine.py 约 :1217-1220）：
  ```python
  if event_risks and risk_info['level'] not in ('高', '极高'):
      risk_info = {'level': '高', 'light': 'red',
                   'detail': f"事件风险：{event_risks[0]['factor']}"}
  ```
  只要 `event_risks` **非空**（哪怕其中只有 severity='中' 的 `财务关注`/`估值过高`/`主力出货`/`获利盘过高`，它们经 `event_risk_factors_from_tags` 混入）→ 强制 `level='高'`。
- **审计分支**（dim6_risk_engine.py :1355-1357）：
  ```python
  {'name': '无高风险事件', 'satisfied': not any(f.get('severity') in ('极高',) for f in risk_factors), ...}
  ```
  只认 `severity=='极高'`（448 号为造假冒硬否决才升级到「极高」）；普通「高」事件不计入。

→ 非极高事件把 `level` 顶到「高」，而审计只查「极高」 → **level=高 ⟺「无高风险事件」=True 并存**。
448 号只修复了「极高（造假/退市）时不恒真」这一端，**未处理「任意 event_risks 非空即强制升格为高」这条独立于 severity 的分支**——正是 444 §三-C1（risk_level 与 risk_factors 矛盾：risk=高 但风险源含「综合：无显著风险」）在 R2 场景下的残余变体。

### R4-b：pre_feat volume_price 组未接 `_compute_volume_ratio` 真值

- **真生产点在计算层**：`data_daemon._compute_volume_ratio()`（:388，量比=今量/过去5日均量）在计算管道被调用（:2101、:2468），已回写 `daily_basic_cache.volume_ratio`。
- **pre_feat 未消费**：`_raw2_one` 的 volume_price 组（data_daemon.py:3351）：
  ```python
  'volume_ratio': _simple.get('volume_ratio', 1.0),
  ```
  `_simple(_add_vp_simple_tags, :3706)` 只产 `ma_alignment/volume_price_fit/volatility_level/gap_type/breakout_attempts`，**从不产 `volume_ratio`** → `.get('volume_ratio', 1.0)` 恒取默认 1.0。
- **dim3 消费**：`dim3_vp_engine.py:117` `float(tags.get('volume_ratio', 1.0))` → 恒 1.0（444 §4.4 volume_price.volume_ratio 收敛清单 / §4.7 item3 所指）。

## 四、处置方案

### R2：升格与审计分支统一「严重度口径」（对齐，不碰阈值）

**原则（对齐 458 先例）**：不改变任何判定阈值 / 风险源枚举 / 事件识别集合，只消除「升格分支」与「审计分支」对严重度的**口径错位**，使 `level` 与「无高风险事件」audit 自洽。

**改点 1** — 升格分支从「event_risks 非空」收紧为「存在高严重度事件」：
```python
# 改前：if event_risks and risk_info['level'] not in ('高','极高'):
# 改后（已落地）：
_high_evt = any(r.get('severity') in ('高', '极高') for r in event_risks)
if _high_evt and risk_info['level'] not in ('高', '极高'):
    risk_info = {'level': '高', 'light': 'red',
                 'detail': f"事件风险：{event_risks[0]['factor']}"}
```
→ 仅 severity='中' 的事件（财务关注/估值过高/主力出货等）不再把 level 顶成「高」；`event_risk_factors_from_tags` 混入的中档项保持其原 severity，不夸大风险。**实测 000001/600519 risk_level 从「高」回落到「低」。**

**改点 2（已撤回）** — 审计「无高风险事件」门槛与 level 同口径（`not any(severity in ('高','极高'))`）：
> **撤回原因**：与 453 号已拍板语义冲突。`test_453_dim6_st_warning.py:108` 明确断言「普通 ST（severity='高'）→ audit「无高风险事件」应 satisfied=True（仅『极高』*ST/退市整理才不计入）」。audit 只看「极高」是**已拍板设计**（453 分档：*ST/退→极高硬否决，普通 ST→高但非硬否决），非 bug。改点 2 若落地会使普通 ST 的 audit=False，破坏 453 语义。**保持 453 语义，仅改点 1 落地。**

**边界声明**：
- 不破坏 448 号的「极高=造假/退市硬否决」语义（「极高」仍满足审计 False 与 L0a 判定）。
- 不触碰 445 §6.2 dim6 冻结的判定阈值 / 事件识别集合 / rr<1 降级 / 主力出货 / 财务健康 / 情绪联动。
- 回归：448/452/453 + 新增 459 单测全绿，StatusEngine 全链路无回退。

### R4-b：pre_feat volume_price 组接 `daily_basic_cache.volume_ratio` 真值

**原则**：RAW 预计算接线（444 §4.4 统一收敛），不触碰 dim3 判定阈值，只让事实字段 `volume_ratio` 落到真实生产值。

**改点**（data_daemon.py `_raw2_one` volume_price 组 :3345-3351）：
```python
# 从 daily_basic_cache 读取该股票最新 volume_ratio（由 _compute_volume_ratio 回写）
_vol_ratio = _shard_query(...)   # SELECT volume_ratio FROM daily_basic_cache
                                # WHERE ts_code=? AND trade_date=<最新> LIMIT 1
features['volume_price'] = {
    ...
    'volume_ratio': float(_vol_ratio) if _vol_ratio is not None else 1.0,
}
```
（具体取数走 data_daemon 既有的 `_shard_fetchall('daily_basic_cache', ...)` 模式；trade_date 用最新交易日。真实值缺失时保留 1.0 兜底，但不再恒为兜底。）

→ dim3 `tags.get('volume_ratio')` 读到真实量比，量能维度恢复有意义输出。
