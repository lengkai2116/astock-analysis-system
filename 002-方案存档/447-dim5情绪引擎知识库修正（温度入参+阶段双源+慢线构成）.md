# 447 — dim5 情绪引擎知识库修正（B 类第二号）

## 一、问题确认（445 §6.3 dim5，代码级已核）

共 4 项引擎逻辑偏差 + 1 项事实层关联（温度双副本统一）。

### □1. 温度 7 输入仅传 3（50% 权重锁死恒定值）——首要

**现状**（`dim5_emotion_engine.py:499`）：温度函数签名 7 参
```python
calc_emotion_temperature(sentiment_phase, limit_up_count, sealing_rate,
                         sector_rank, volume_price_fit, margin_change_pct, breadth)
```
但 evaluate 内**只传 3 参**：
```python
temperature = calc_emotion_temperature(sentiment_phase=sp, volume_price_fit=vp_fit,
                                       margin_change_pct=margin_change_pct)
```
未传 `limit_up_count/sealing_rate/sector_rank/breadth` 四参，各自走默认值（`TEMP_WEIGHTS` 对应权重 0.15+0.10+0.15+0.10 = **0.50，即 50% 权重被锁死**）：
- `limit_up=0` → 恒 0 分（权重 15%）——涨停家数完全不体现
- `blast_rate=50`（sealing_rate 默认 50）→ 恒中性（权重 10%）
- `sector_heat=` 默认 `sector_rank=None` → 恒中 50（权重 15%）——板块热度不体现
- `breadth=None` → 恒中 50（权重 10%）

**影响**（445 §6.3）：
1. `sector_rank` 第 3 步已拿到（`sector['detail']="板块{industry}(排名{info.get('rank','?')})"`），但温度未复用；
2. `limit_up/sealing_rate/breadth` 需从 data_context / tags 补——数据源可行性未核；
3. BOCIASI 修正后温度 = `0.4*calc + 0.6*bociasi`，虽被四象限分压制，但 50% 权重恒定的 calc 项仍污染最终 `continuous_value`（SIG 情绪灯色的量化输入）。

### □2. 阶段判定双源（阈值 + 枚举值域均不一致）

**源 A——`market_sentiment_service.py:92-108`（六段论，优先）**：
```python
if    limit_up_count < 20 and max_board_height < 3 and sealing_rate < 40: phase='ice'
elif  limit_up_count < 40 and max_board_height <= 2 and sealing_rate < 50: phase='sprout'
elif  limit_up_count >= 40 and limit_up_count <= 80 and max_board_height >= 3 and sealing_rate >= 40: phase='ferment'
elif  limit_up_count > 80 and sealing_rate > 75: phase='climax'
elif  (max_board_height >= 3 and sealing_rate < 50) or (sealing_rate < 40 and limit_up_count < 40): phase='ebb'
elif  limit_up_count >= 20 and limit_up_count <= 60 and max_board_height <= 2: phase='regression'
else: phase='ferment'
```
枚举值域：`ice / sprout / ferment / climax / ebb / regression`（6 值 + 兜底 ferment）。

**源 B——`data_daemon.py:3118-3129`（四级 fallback，仅当源 A 数据不可用时）**：
```python
if   limit_up > 50 and sealing_rate > 75: _sentiment_phase_global = 'climax'
elif (limit_up < 40 and sealing_rate < 40) or limit_down > 20: _sentiment_phase_global = 'ebb'
elif limit_up < 20 and sealing_rate < 40: _sentiment_phase_global = 'ice'
else: _sentiment_phase_global = 'recovery'
```
枚举值域：`climax / ebb / ice / recovery`（含 **recovery**，缺 sprout/regression）。

**矛盾**：
1. **阈值不一致**：climax 门槛 源 A 需 `limit_up>80 且 sealing>75`，源 B 仅 `limit_up>50 且 sealing>75`——同一数据两套临界；
2. **枚举值域不一致**：源 B 的 `recovery` 在源 A 不存在（源 A `PHASE_MAP` 却有 recovery 但六段论不产）；源 A 产 `sprout/regression` 但 dim5 `PHASE_MAP` 已收录（sprout=萌芽/regression=回归），而**源 B 永不产该两项**。若同一天一个维度读到源 A 值、另一维度读源 B 值，`_assess_market_emotion` 对 `recovery` 能命中（PHASE_MAP 有），但语义"复苏"与"回归"易混。
3. `data_daemon:3181` 优先用源 A（`ms.get_sentiment_phase()`），仅异常时回退源 B——但两源阈值口径不同，fallback 路径产出的 phase 与主路径不连续。

### □3. 慢线构成偏离知识库（`bociasi_quadrant.py:88-184`）

**知识库基准**（《BOCIASI-kuaimanxian》）：慢线 4 项 = ERP / 融资余额 / **股债位置差** / **股债收益差**。

**引擎现状**：注释声称"4 个等权指标：ERP分位/融资余额趋势/**股债收益差**/市场估值分位"，但**实际仅 3 项计入 scores**：
1. ERP 分位（`1 - erp_percentile`）
2. 融资余额趋势（`margin_trend`）
3. **PE 分位**（`pe_percentile`）——**这是误加项**，知识库慢线并无 PE 分位
4. **股债位置差 / 股债收益差完全缺失**（注释有、代码无）

**叠加缺陷**：
- `_compute_erp_percentile`（:310-330）：`erp_today = (1 / avg_pe)`——**未减国债利率**（知识库要求 `1/PE - 国债利率`），且用 `avg_pe`（算术平均）而非中位数，与 docstring"1/PE - 国债收益率的历史分位"不符。

**影响**：慢线 score 由 3 项组成（含误加的 PE 分位），缺真正的"股债性价比"两维度 → 四象限 slow 轴语义偏（长线性价比评估失真）→ HH/LL 象限错位风险。

### □4. audit 死条件（`dim5_emotion_engine.py:530`）

```python
{'name': '个股情绪', 'satisfied': stock['emotion'] not in ('极度消极',),
 'actual': stock['emotion'], 'threshold': '非极度消极'},
```
`stock['emotion']` 值域为 `健康 / 关注 / 中性`（`_assess_stock_emotion`，:287-299），**永不产"极度消极"** → `satisfied` 恒 True，是**恒真条件**（audit 假检查）。同 445 §6.3 dim6 的"恒真假检查"同类问题。

### □5. 关联项：温度双副本统一（444 C 类 B1 登记）

- **副本 1**：`dim5_emotion_engine.py:272 calc_emotion_temperature`（内嵌）
- **副本 2**：`app/opportunity_atlas/emotion_temperature.py:calc_emotion_temperature`（独立模块，`data_daemon:3528` RAW 层调用）

当前两副本签名/权重**完全一致**，非运行差异，但属**维护断链风险**：本号改动温度逻辑必须同步两处，否则 RAW 预计算的 `emotion_temperature`（消费方在 dim1 data_context？）与 dim5 实时计算口径分叉 → 444 事实层矛盾。**本号实施温度补入参时一并统一**（确立 emotion_temperature.py 为 SSOT，dim5 改为导入；或明确保留内嵌并同步——见候选方案）。

## 二、候选修正方案（待拍板）

### T1 温度补入参（□1 修复）

**目标**：让 7 输入全部有真实值，消灭 50% 权重锁死。

**数据来源核查**（evaluate 内已可取得）：
| 缺失入参 | 来源 | 可行性 |
|---|---|---|
| `sector_rank` | 第 3 步 `info['rank']`（已拿） | ✅ 直接复用 |
| `limit_up_count` | data_context / tags（全市场涨停家数） | ⚠️ 需确认 data_context 是否含 |
| `sealing_rate` | 同上 | ⚠️ 需确认 |
| `breadth` | data_context（涨跌家数比 / MA20占比） | ⚠️ 需确认 |

**方案 T1a（推荐，若数据齐）**：补全 4 个入参——`sector_rank` 从第 3 步复用，`limit_up/sealing_rate/breadth` 从 data_context 读取；若某项缺 → 该单项走默认值 + audit 标注"温度部分维度无数据"（降级不锁死整体）。
**方案 T1b（保守）**：仅补 `sector_rank`（必可得），limit_up/sealing_rate/breadth 三项暂留默认 + 明示为"温度分辨率不足"的已知限制。

**需要拍板**：limit_up/sealing_rate/breadth 的数据源是否可从 data_context 取（需现场核查 data_context 组成后定）——先核再定，避免方案落空。

### T2 阶段双源统一（□2 修复）

**知识库标准**：《情绪周期六段论》= ice/sprout/ferment/climax/ebb/regression（六段）。`recovery` 是四级 fallback 的自造词，非知识库标准枚举。

**方案 T2a（推荐）**：**废弃源 B 四级 fallback** 的自造值域——data_daemon:3123-3129 改为产出六段论同值域（sprout/regression 补上，删 recovery），阈值与源 A 对齐。即：`recovery` 不再产出，fallback 最低也归 `ferment`（源 A 兜底语义）。这样同一天无论走主路径还是 fallback，枚举值域完全一致，`_assess_market_emotion` 不再出现 `recovery` 分支。
**方案 T2b（中等）**：保留四级，但 data_daemon fallback 阈值与源 A **逐条对齐**（climax 门槛统一 `limit_up>80 且 sealing>75`），recovery 保留但视为"数据不足"降级输出。
**方案 T2c（最小）**：不动 data_daemon，仅把 dim5 `_assess_market_emotion` 的 `recovery` 分支改为明确标注（"数据不足降级"），避免与"复苏"语义混淆。

**影响面**：`recovery` 当前在 dim5 PHASE_MAP 与 data_daemon:3902 `sp_status`（复苏）有定义，若 T2a 废弃需同步清理这两处消费。

### T3 慢线构成补齐（□3 修复）

**方案 T3a（推荐，对齐知识库 4 项）**：慢线改为 4 项 = ERP / 融资余额 / **股债位置差** / **股债收益差**，**移除误加的 PE 分位**。
- 股债位置差：需股息率/指数位置数据（未核来源）；
- 股债收益差：需股息率 - 国债利率（国债利率数据源未核）。
**方案 T3b（降级声明）**：若股债两项数据源不足，**保留 PE 分位但降级**——明确注释"缺股债位置差/收益差，暂以 PE 分位占位（降级）"，避免误当知识库标准项。
**叠加必改项**：`_compute_erp_percentile` 补减国债利率（若无国债数据，至少修正为 `1/PE - 国债利率` 用可用数据，或明示降级）。

**需要拍板**：股债两数据源能否从现有库取（股息率/国债利率表未核），决定走 T3a 还是 T3b。

### T4 audit 死条件清理（□4 修复）

**方案 T4（推荐）**：`个股情绪` 条件改为真实可判——`satisfied: stock['emotion'] in ('健康',)`（健康才 satisfied），threshold='健康'；或将 `_assess_stock_emotion` 值域补入 `极度消极` 分支（volume_price_fit 超阈值背离时产）。**推荐后者**（补分支使 audit 有条件可触发），若过度复杂则取前者（改 threshold）。

### T5 温度双副本统一（□5 关联项，444 C 类 B1）

**方案 T5（推荐）**：确立 **emotion_temperature.py 为 SSOT**——`dim5_emotion_engine.py` 移除内嵌 `calc_emotion_temperature`/`PHASE_BASE_TEMP`/`TEMP_WEIGHTS`，改为 `from app.opportunity_atlas.emotion_temperature import calc_emotion_temperature`。单点改动，与 RAW 层共用一套。
