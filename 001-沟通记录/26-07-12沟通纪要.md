### 004 - 筹码分布图表十字光标联动修复
**用户输入**：筹码分布图表随鼠标移动时价格线和颜色变化正确，但筹码分布柱状图固定不变，应随不同时间点变化。

**AI执行内容**：
- 根因分析：后端 API 不支持按日期查询筹码分布（始终返回最新数据），前端 `_chipCache[tsCode]` 数据不随十字光标日期变化
- 修复后端：`GET /api/v3/chart/chip-distribution/{ts_code}` 新增可选 `?date=YYYY-MM-DD` 参数，`ChipDistributionService` 新增 `end_date` 参数，截取截止日期前的 K 线数据计算筹码分布
- 修复前端：新增 `_datesFull[]` 存储每根 K 线的完整日期，`_currentChipData` 指针跟踪当前显示的筹码数据，`loadChipDistribution(tsCode, dateKey)` 支持按日期加载，`updateCrosshair()` 十字光标移动时自动按日期加载芯片数据
- 缓存策略：`_chipCache` 键改为 `tsCode:YYYY-MM-DD` 格式，避免重复请求同日期数据
- 验证：后端 lint 无新增问题，前端 4 处 `_chipCache[_currentTsCode]` 引用全部替换为 `_currentChipData`

### 005 - 筹码分布修复验证与增强
**用户输入**：筹码分布形状仍然没有任何变化。

**AI执行内容**：
- 排查后端 `get_cached_daily` SQL 查询逻辑：`trade_date` 在 SQLite 中以 "YYYY-MM-DD" TEXT 格式存储，`<=` 字符串比较正确，后端过滤逻辑无问题
- 排查前端日期获取逻辑：发现`_datesFull`依赖`applyRealData()`，夜间数据加载可能不同步。改为优先从`_realKlineData.kline[idx].time`（Unix时间戳）实时计算，兜底使用`_datesFull`
- 排查`loadChipDistribution`：发现当 API 返回空`chip_bins`时代码`throw`异常，`_currentChipData`不会被更新。修改为静默保留旧数据
- 新增筹码面板"筹码数据日"字段（`cd-chip-date`），显示`_currentChipData.trade_date`，用户可直接观察筹码数据是否随光标移动刷新
- **建议用户测试方法**：打开筹码面板，移动鼠标到不同日期，查看"筹码数据日"字段是否变化；如果变化则说明 API 正常但数据近似（120天窗口仅偏移1天），如果不变则说明请求未到达
