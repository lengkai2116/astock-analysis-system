### 001 — 自选监控WebSocket实时数据推送实施

**用户需求：** 全局数据系统已具备盘中数据能力，自选监控需要实现自动推送数据更新的能力

**技术方案：**
- **数据流链**: mootdx TCP (5s采集) → InMemoryStateStore → WsBridge.on_collect_complete() → SocketIO `watchlist` 房间 → 前端自动更新表格
- **后端 WsBridge**：新增 `_watchlist_codes` 集合 + 线程安全管理方法（update/remove/clear）+ `_broadcast_watchlist_quotes()` 推送 `stock:quotes` 事件
- **后端 realtime.py**：`subscribe_watchlist` 处理器增强，将前端订阅的代码注册到 WsBridge
- **前端 watchlist.html**：SocketIO 客户端连接 → 订阅 `subscribe_watchlist` → 监听 `stock:quotes` → 每秒更新价格/涨跌幅/成交量/成交额/最高/最低/开盘/昨收/振幅，3秒渲染节流

**涉及文件：**
- `backend/app/data/ws_bridge.py` — +40行（推送管理+房间推送）
- `backend/app/routes/realtime.py` — 3行（注册自选代码）
- `_ui-prototype/watchlist.html` — +80行（SocketIO客户端+实时更新）

**状态：** ✅ 已完成。盘中数据管道已通路，目前 WebSocket 状态标签从静态 Mock → 真实连接状态指示

### 002 — 自选监控策略评估Bug修复（评分项全显示"—" + 切页面评分丢失）

**问题：**
1. **评分项显示"—"**：`evaluateStock()` 调用 `/strategy/analyze`，该端点返回 `{code:0,...}` 不含 `success` 字段。前端检查 `resp.success` 恒为 false → 走 `fallbackEvaluate` 把评分设成字符串 `'—'`
2. **切页面评分丢失**：评估结果仅存 `stockData` 内存变量，切页面后 `loadWatchlistData()` 从 `/watchlist/quotes` 重新加载（该端点不返回策略评分）→ 评分全部变回 null

**修复：**
- `evaluateStock()` 单只评估改为调用 `/screener/evaluate-batch`（同批量刷新一致的后端链路，返回 `success:true`）
- 抽取 `_applyEvalToStock()` / `_saveEvalToCache()` / `_loadEvalFromCache()` 三函数
- 评估成功后自动写入 `sessionStorage`（key=`wl_eval_{code}`）
- `loadWatchlistData()` 加载 API 数据后用 sessionStorage 中缓存的评分结果覆盖
- 同一 tab session 内切页面/刷新不丢失评分

**涉及文件：**
- `_ui-prototype/watchlist.html` — 约+30行
