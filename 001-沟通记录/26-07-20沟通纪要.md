### 001 - 核查个股策略分析资金流向数据不可用问题

**用户输入：**
请核查一下个股策略分析板块总是提示资金数据不可用且资金流向数据无法正常显示的问题。

**AI执行内容：**

1. **Phase 1 根因调查** — 代码审计 + 数据库检查 + 端点测试
   - 数据库 `moneyflow_cache` 表有 668,651 行数据，覆盖 5,219 只股票，最新数据至 2026-07-17
   - E10 端点 `GET /api/v3/stock/{ts_code}/moneyflow` 直接返回正常
   - E12 端点 `POST /api/v3/strategy/analyze` 返回 `data_availability.moneyflow: False`

2. **Phase 2-3 根因确认：发现 3 个独立问题**

   **根因 #1 — Pandas 兼容性：** `_apply_adjust_factor()` 中 `fillna(method='ffill')` 在 Pandas 2.2+ 中已被移除。导致复权计算失败（caught by try-except），返回未复权数据。日志反复出现 `NDFrame.fillna() got an unexpected keyword argument 'method'`。

   **根因 #2 — 最新日期取错：** `_build_moneyflow_response()` 中 `records[-1]` 取了最旧日期作为 `latest`（records 按降序排列）。`history_5day` 用 `records[:-1]` 取了最近的 4 天，但 `latest` 却是第 5 天即最旧的一条。

   **根因 #3 — 资金流向未独立检测：** `compute_for_stock()` 当日线不足 60 行时立即返回，`moneyflow` 始终设为 `False`，不检查 moneyflow 缓存是否有数据。实际上约 532 只股票只有 9 行日线数据（数据采集尚不完整），但 moneyflow 数据完整。

3. **Phase 4 修复实施（3 处修改）：**

   | 文件 | 修改 | 影响 |
   |------|------|------|
   | `backend/app/data/__init__.py:190` | `fillna(method='ffill')` → `ffill().fillna(1.0)` | 消除 Pandas 2.2+ 兼容错误 |
   | `backend/app/routes/market.py:452,463` | `records[-1]` → `records[0]`, `records[:-1]` → `records[1:]` | E10 `latest` 返回最新日期 |
   | `backend/app/services/signal_computation_service.py:829-845` | 日线不足时独立检测 moneyflow 缓存 | `data_availability.moneyflow` 正确反映实际数据 |

4. **验证结果：**
   - `000001.SZ`: `moneyflow: true`（修复前为 false），E10 返回最新日期 2026-07-17
   - `000002.SZ`: `moneyflow: true`（功能不变）
   - `600519.SH`: `moneyflow: true`（修复前为 false）

**关键结论：** 资金流向数据实际存在于缓存中，问题是策略分析流程中未正确加载和反馈。3 处修复后问题应解决。

### 003 — 修正 P2 根因判断（bvps 并非积分问题）

**用户输入：**
质疑 5000 多 Tushare 积分为何仍无法满足 bvps/pe_ttm 数据需求。

**AI执行内容：**
经重新排查，确认 **bvps 全部缺失不是积分问题，而是代码 bug**：
- Tushare `fina_indicator` API 返回的列名为 `bps`（Book value Per Share）
- 数据库 `fina_indicator_cache` 表字段名为 `bvps`
- `cache_fina_indicator_data()` 的 `_insert_from_df` 按列名匹配合并插入，`bps` ≠ `bvps`，导致所有股票的 `bvps` 均为 NULL
- 同样 `dt_eps` (Tushare) → `eps_diluted` (DB) 也存在同样的映射问题

**pe_ttm 部分缺失**（1,571/5,625 只）是 Tushare 对亏损公司（EPS 为负）不返回 PE 的正常行为，非 bug。

**方案更新**：280 号方案已同步更新，新增 Phase 3 修复项：在 `cache_fina_indicator_data()` 中添加列名映射逻辑。
3. **红线合规审查**：所有问题均不涉及架构红线违规。avg_price 公式修正在调用层，E09 日期修正在调用层，speed/commission 前端渲染修复，volume_ratio 可在计算层自算。
4. **输出方案**：`002-方案存档/280-右侧行情面板数据缺失问题核查与修复方案.md`，含 5 阶段修复优先级和完整的架构合规审查
