**用户输入**：执行止血操作：杀掉孤儿进程、收缩WAL、加单实例检查，注意安全。
**AI执行内容**：

- **止血② 收缩 WAL（86G→0B）**：核心难点是 SQLite 锁——STOP 不释放 fd 锁，checkpoint 始终 busy=1。最终方案：暂停看守(976)→SIGKILL daemon(20083)→SIGTERM 退出 API(4693)→无持有者时 `PRAGMA wal_checkpoint(TRUNCATE)` 返回 0|0|0、WAL 从 86G 收缩到 0B。验证：daily_cache 585.8万行/最新2026-08-05、treemap_snapshot 5560行完整；treemap 接口从 1.14s 提速到 0.36s。

- **进程治理**：清理了操作中产生的临时进程链，最终状态——看守 21175（唯一）+ daemon 21224（唯一，RN）+ API 重启（health/live 200、treemap data_status=complete）。
- **经验教训**：① data_daemon.py 屏蔽 SIGTERM，优雅停止需 kill -KILL；② SQLite STOP 不释放锁，checkpoint 需真正退出所有持有者；③ WAL 86G 中 2200 万帧已合并但文件不截断（API 读锁），需全释放后 TRUNCATE。
